## 2. 已确认的实验判断

### 2.1 底盘与延迟

- 底盘能连续执行平滑速度命令，先前的“一卡一卡”不能简单归因于硬件速度不连续。
- 实车存在命令起效延迟和渐进建立过程，尤其角速度建立较慢；单一纯延迟不能完整描述执行器。
- 持续有效线加速度能力约为 `3.0 m/s²`，不是当前低速 C02 试验的主要限制。
- 当前 legacy `fixed_closed_loop` 使用历史命令作理想前推，没有显式区分 command 与 actual。

## 3. 当前机制判断

当前证据将问题分为三个层次：

1. **运行时与状态结构：** I0、command/actual 分离和 L22 关闭已经用于有效 V2 配对，运行时故障计数为零。因此不能继续把这次负结果简单归因于仍在使用 L22 或故障性硬停车。
2. **连续性修改已进入实物验证：** full-da 软惩罚 smoke 未达当次改善门，后续硬 jerk 约束已实现并在 C03 三个硬约束组中通过核验。该约束限制预测网格的命令加速度变化，不等于真实杯体 jerk 已受控；完整时域 `Delta alpha_cmd` 仍未加入。
3. **预测与真实液体：** 同包幅相、激励和 NOKOV 分析已有后续证据，但结构、驱动及测量链各自的作用仍需核实。C03 内部高度尚无一致收益；命令平滑与软件/运行时通过均不能单独证明 RGB 改善。

6 月仿真有正向模型证据：六组各 9 次，B0/Bslosh 的模型高度 P95 组均值为 `0.594/0.496 mm`。但评价量是 model proxy，不能据此认定当前执行器、I0 与真实液体之间的相位关系已准确。参见 [仿真结果](./实物实验注意事项/对比试验/仿真对比试验/20260627_SPMPC内部消融N9复跑_1mm结果.md) 与 [评价口径](../src/scout_apps/control/spmpc_experiments/config/benchmark/external_slosh_observer_policy.yaml)。

## 4. 当前决策与最小修复

- 不再沿 `O0 + L22` 方向继续微调 `w_slosh`。
- C03 已补录同参数 B0，保留全时域软惩罚，只关闭硬 jerk；后续比较使用相同地图、路径和容器参数，旧 C02/V2 不混入新效果配对。
- 第一阶段保留 `processed-IMU I0 + fail_closed + common_epoch`，只比较完整方法的 jerk 上限，冻结液体权重、执行器和其他共同参数，不同时切换 observer 或增加延迟补偿。
- 用显式执行器模型区分 `v_cmd/omega_cmd` 与 `v_actual/omega_actual`；车体和液体都由 actual 状态驱动，最终 `/cmd_vel` 发布 command 状态。
- 显式执行器模型与 legacy L22 必须互斥。首版固定执行器参数已进入软件 profile，但仍只是主要工作速度附近的候选，必须由实物预测误差和 ABBA 结果验证。
- 第二阶段固定共同 jerk 上限后，再准备 odom 与 IMU 液体初态来源对照；同包双监视器结果只作旁路证据，不能当作已经跑过该闭环对照。

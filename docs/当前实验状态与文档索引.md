## 2. 已确认的实验判断

### 2.1 底盘与延迟

- 底盘能连续执行平滑速度命令，先前的“一卡一卡”不能简单归因于硬件速度不连续。
- 实车存在命令起效延迟和渐进建立过程，尤其角速度建立较慢；单一纯延迟不能完整描述执行器。
- 持续有效线加速度能力约为 `3.0 m/s²`，不是当前低速 C02 试验的主要限制。
- 当前 legacy `fixed_closed_loop` 使用历史命令作理想前推，没有显式区分 command 与 actual。

## 3. 当前机制判断

目前最直接的三个问题是：

1. `O0` 对实际液体状态的描述弱于 processed-IMU `I0`。
2. legacy L22 把命令近似成实际运动并统一前推约 `0.22 s`，不能表达线、角通道不同的延迟和一阶建立过程；其状态时刻语义也需要重新核对。
3. B_slosh 的最终发布命令比 B0 更不连续，同时控制周期存在更明显的发布间隔抖动。这会直接激励真实液体。

ACADOS 本身不是当前首要瓶颈：两包 B_slosh 的求解路径时间均值约 `8.86/9.24 ms`，P95 约 `14.01/14.25 ms`，最大约 `16.72/16.05 ms`，均低于 30 Hz 的 `33.3 ms` 周期。但完整控制周期和命令发布抖动仍需继续处理。

## 4. 当前决策与最小修复

- 不再沿 `O0 + L22` 方向继续微调 `w_slosh`。
- 短期需要可靠运动基线时，继续使用 `B0 + fixed_robot_only`，IMU/RGB 只作旁路证据。
- 新的 SMPCC 主线使用 `processed-IMU I0 + fail_closed + common_epoch`。
- 用显式执行器模型区分 `v_cmd/omega_cmd` 与 `v_actual/omega_actual`；车体和液体都由 actual 状态驱动，最终 `/cmd_vel` 发布 command 状态。
- 显式执行器模型与 legacy L22 必须互斥。首版固定执行器参数已进入软件 profile，但仍只是主要工作速度附近的候选，必须由实物预测误差和 ABBA 结果验证。

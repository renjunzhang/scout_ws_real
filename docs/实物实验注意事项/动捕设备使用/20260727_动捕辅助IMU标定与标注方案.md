# 20260727 动捕辅助 IMU 标定与标注方案

> 文档状态：实物 development / 标定 SOP。  
> 适用对象：Scout、试管、车载 IMU、Nokov/XINGYING 动作捕捉系统，以及当前 S-MPCC 的预测模型 M0/M1 阶段。  
> 安全边界：动捕监控链路仅作为外部真值和离线标注源；不替换 /odom，不接入 planner，也不发布控制用 TF。只有操作者显式运行本方案的 `ARM_MOTION=YES` 序列时，独立脚本才发布 /cmd_vel。
> 本轮范围：只采集地面平面运动的 ax/ay/gz、命令响应和动捕真值，供后续离线滤波；不做完整六轴安装旋转或夹具倾斜。

---

## 1. 目的与当前决策

当前最需要确认的是命令、底盘实际运动、试管刚体激励和 IMU 测量之间的幅值、符号、时间延迟与相位关系，而不是立刻扩大预测窗口 P 或修改控制窗口 C。

动作捕捉可提供独立的车体 6-DoF 位姿参考。结合 IMU、/cmd_vel 和 /odom，可完成以下工作：

1. 标定或核验 IMU 坐标轴相对车体的方向；
2. 标定 IMU 与动捕的时间偏移；
3. 验证 IMU yaw rate、odom yaw rate 和动捕 yaw rate 的幅值/相位；
4. 利用动捕姿态处理 IMU 的重力泄漏，并验证纵向/横向加速度；
5. 把动捕刚体原点、IMU 点和试管中心的杠臂区分开，得到试管位置的刚体激励；
6. 分别估计 cmd_vel 到真实线运动、真实转动的执行延迟，为 M_actuator 提供外部依据。

动作捕捉不能直接观测液体的模态状态 eta_x、eta_y 或液面相位。因此，它不能替代 RGB/LCR；液体模型仍应以经校验的试管激励为输入、以独立 RGB 液面为输出辨识。

## 2. 当前三点 marker 的正确解释

现场当前已贴三枚 marker：

| 标记建议名 | 当前安装位置 | 在本方案中的作用 | 必须确认 |
| --- | --- | --- | --- |
| M0_tube_center | 试管正中心 | 物理上的候选 base_link 原点 / 试管中心参考点 | 与试管、车架和 IMU 均刚性连接；记录 marker 球心到真实试管中心的偏移 |
| M1_lidar_fixed | 雷达附近 | 提供前方参考点，并用于核验雷达安装位置 | 必须贴在不旋转的雷达底座或固定支架上，不能贴在扫描/旋转头上 |
| M2_crossbeam | 横梁 | 与 M0、M1 组成非共线刚体三角形，消除纯点定位歧义 | 横梁不能相对底盘晃动、弯曲或松动 |

三枚不共线 marker 已可建立一个 6-DoF 刚体，因而足以开始第一轮 IMU 标定。它们必须始终属于同一个刚性结构，且在整个运动中不被遮挡。

建议在方便时再加一枚 M3_redundant，贴在车架后侧或另一侧横梁上。第四枚不是第一轮的必要条件，但能在任一 marker 被手、线缆或试管遮挡时保留刚体跟踪，也能帮助发现某一 marker 松动。

### 2.1 M0 位于试管中心，不等于可以发布 base_link

M0 很适合定义为“物理 base_link 候选原点”：后续可令 M0 的球心或经小偏移修正后的试管几何中心对应 p_B = [0, 0, 0]。

但一个 marker 只提供一个点，不提供车体坐标轴。动捕软件输出的刚体原点也可能是 marker 几何中心，而非 M0。因此应保存一个静态外参：

    T_mocap_scout<-B

其中 B 是物理 base_link 参考系，mocap_scout 是动捕软件定义的刚体参考系。若动捕软件支持，推荐将刚体原点设在 M0，并使 x 前、y 左、z 上；若不支持，则离线保存上述静态变换即可。

无论 M0 是否与物理 base_link 重合，ROS 中都只使用隔离的 mocap_scout 或 mocap_world frame。不得由动捕节点发布 map -> base_link、odom -> base_link，也不得把 /mocap/scout_odom remap 成 /odom。

### 2.2 雷达 marker 的边界

M1 可以用于检查雷达参考点相对车体的位置是否与安装记录一致，也可为后续雷达外参复核提供一个已观测的点。

但一枚 marker 只能提供一个点的位置约束，不能单独重新标定雷达完整 6-DoF 外参。完整的 T_B<-L 仍需要至少以下之一：

1. 雷达坐标轴方向有可信的机械/CAD 定义，并结合测量得到的平移；
2. 三个不共线、且均固定在非旋转雷达基座上的可见点；
3. 专门的 LiDAR-target / point-cloud 外参标定流程。

若 M1 当前贴在旋转式 2D 雷达的上盖、扫描头或会随雷达转动的部分，必须先移到固定底座或旁边的刚性支架。旋转 marker 不代表车体刚体，会破坏动捕姿态；也可能干扰雷达扫描。

### 2.3 安装后的最小测量记录

在 marker 粘牢后，用尺或卡尺记录下列量，单位统一为 m，并拍一张俯视和侧视照片留档：

| 量 | 含义 |
| --- | --- |
| p_BM0, p_BM1, p_BM2 | 各 marker 球心相对物理 base_link 的位置 |
| p_BI | IMU 测量中心相对 base_link 的位置 |
| p_BT | 试管中心相对 base_link 的位置 |
| p_BL | 雷达参考点相对 base_link 的位置 |
| R_BI | IMU frame 到车体 frame 的初始安装旋转猜测 |

坐标约定固定为：x 前、y 左、z 上。M1 最好处于 M0 的前方，M2 最好明显位于左侧或右侧；三点不可近似共线。不要只依赖“看起来正”的安装方向。

## 3. 本机已有动捕链路与启动方式

仓库已有独立的 nokov_mocap_monitor 包。它只将 VRPN 数据桥接为 /mocap/* 监控话题，不会改变控制链路。

默认约定：

    Nokov/XINGYING -> VRPN
    -> /vrpn_client_node/Tracker0/pose
    -> /mocap/scout_pose
    -> rosbag / 离线标定

本机此前已使用过该链路时，优先直接按以下命令启动，不需要重做安装或改 planner 配置：

    source /opt/ros/noetic/setup.bash
    source /home/geist/scout_ws/devel/setup.bash

    roslaunch nokov_mocap_monitor nokov_monitor.launch \
      server:=10.1.1.198 \
      vrpn_port:=3883 \
      tracker:=Tracker0

其中 server 和 tracker 必须替换为现场当前 Nokov 主机 IP 与刚体名称，并在启动、录包和序列命令中保持完全一致。本轮实物使用 `Tracker0`：

    /vrpn_client_node/Tracker0/pose

启动后执行只读检查：

    rosrun nokov_mocap_monitor check_nokov_env.sh 10.1.1.198 Tracker0

    rostopic hz /vrpn_client_node/Tracker0/pose
    rostopic hz /mocap/scout_pose
    rostopic echo -n 1 /mocap/scout_pose
    rostopic info /imu/data

通过条件：

1. /vrpn_client_node/Tracker0/pose 与 /mocap/scout_pose 均持续发布；
2. 静止时位置和姿态没有明显跳变，移动底盘时姿态连续变化；
3. 三枚 marker 同时可见，刚体不会在转弯/遮挡时丢失；
4. /mocap/status 为 OK，而非 STALE；
5. Nokov 相关节点不发布 /odom、/cmd_vel 或控制 TF。

若 rospack find nokov_mocap_monitor 失败，才在工作区执行：

    cd /home/geist/scout_ws
    catkin_make --pkg nokov_mocap_monitor
    source devel/setup.bash

### 3.1 当前 bridge 的一个重要限制

/mocap/scout_odom 仅携带 pose，当前 bridge 不填充 twist。不能把其中的 twist 当作动捕速度或加速度真值。

用于 IMU 标定的原始依据应是：

    /vrpn_client_node/Tracker0/pose
    /mocap/scout_pose

离线时以连续的 PoseStamped 时间戳、固定的平滑器和微分方法导出速度、yaw rate、角加速度和线加速度。原始 VRPN pose 和 bridge 后 pose 都应录入 bag，便于追溯时间戳语义。

## 4. 录包：平面序列使用专用 recorder

正式平面序列以 `run_mocap_imu_calibration_sequence.sh` 为主流程：它控制专用 recorder、写 segment/status/timeline、在线检查 IMU/odom/动捕心跳，并在录包后执行完整性检查。通用 full-RGB recorder 仅用于人工运动或另行设计的 RGB 试验，不能通过给本序列设置 `RECORD_RGB=true` 来启用。

建议为每个标定段单独录一个 bag。例如静止零偏段：

    export DATE=20260727
    export RUN_LABEL=MOCAP_IMU_M0_static_60s
    export OUT_DIR=/home/geist/slosh_bags/real/${DATE}_mocap_imu_calib

    RECORD_MOCAP=true \
    MOCAP_TRACKER=Tracker0 \
    RECORD_RGB=false \
    RECORD_SEC=70 \
    RUN_LABEL=$RUN_LABEL \
    NAME=$RUN_LABEL \
    OUT_DIR=$OUT_DIR \
    bash src/scout_apps/control/spmpc_local_planner/scripts/record_spmpc_full_rgb_bag.sh

每次动态标定前只改 RUN_LABEL 和 RECORD_SEC；录制器应先启动，再开始人工/既有安全脚本的运动。建议的 label：

    MOCAP_IMU_M0_static_60s
    MOCAP_IMU_M1_straight_accel_brake_01
    MOCAP_IMU_M1_spin_LR_01
    MOCAP_IMU_M1_scurve_reversal_01

当前仓库另提供两个针对本轮动捕/IMU标定的脚本：

    # 只录制，不控制小车
    MOCAP_TRACKER=Tracker0 RUN_LABEL=spin_ccw_01 \
    bash src/scout_apps/sensors/nokov_mocap_monitor/scripts/record_mocap_imu_spin.sh

    # 小场地平面序列：自动录包并直接发布 /cmd_vel
    ARM_MOTION=YES MOCAP_TRACKER=Tracker0 \
    RUN_LABEL=imu_mocap_planar_r03 CMD_HZ=50 \
    LINEAR_LOW=0.10 LINEAR_NOMINAL=0.15 \
    S_V=0.10 S_OMEGA=0.40 \
    STATIC_PRE_SEC=60 STATIC_POST_SEC=60 \
    bash src/scout_apps/sensors/nokov_mocap_monitor/scripts/run_mocap_imu_calibration_sequence.sh

完整序列采用：

    静止前
      -> 短直线加速/匀速/制动及回程
      -> 原地左右转及直接反转
      -> LR、RL 短 S 弯及回程，各至少 3 次
      -> 静止后

场地受限时不单独跑完整左右圆弧。左右定曲率激励嵌入 LR/RL S 弯：默认 `v=0.10 m/s`、`|omega|=0.40 rad/s`、每腿 1 s，前向命令路程约 0.20 m、半径约 0.25 m，随后按相反命令返回。完整 bag 同时记录 /mocap_imu_calib/segment、/mocap_imu_calib/status 和 ROS/monotonic 双时间 timeline。

RGB/M2 不属于本轮专用序列；若需要，必须另用明确包含相机话题的 recorder 和独立矩阵，不能假定 `RECORD_RGB=true` 对本脚本生效。

脚本结束后会自动生成 `*_validation.json`、`*_bag_info.txt` 和 `*_sha256.txt`。只有 validation 中 `ok=true`、状态为 READY→RUNNING→COMPLETE、无 `.bag.active` 时，才把该 bag 视为正式数据。

    rosbag info <bag_path> | grep -E 'imu|mocap|vrpn|cmd_vel|odom'

至少应看到：

    /imu/data
    /cmd_vel
    /odom
    /vrpn_client_node/Tracker0/pose
    /mocap/scout_pose
    /mocap/status

## 5. 建议采集顺序与人工标注口径

### 5.1 M0：静止段

每次动态试验前后各录至少 60 s 静止段。标注：

    segment_type = static_pre 或 static_post
    valid = true
    motion = no_motion

用途：

1. 估计 gyro 零偏；
2. 记录 IMU 加速度静态偏置与重力方向；
3. 检查动捕 pose jitter、丢帧和时间戳单调性；
4. 检查 marker 粘贴是否存在缓慢滑动。

### 5.2 M1-A：直线阶跃响应与制动

脚本下发 0→恒定速度→0 的低速阶跃，底盘实际响应形成加速和制动；脚本本身不生成显式 ramp。不要把标签解释成预设的匀加速度轨迹。

标注区间：

    straight_low_forward / straight_low_reverse
    straight_nominal_forward / straight_nominal_reverse

主要比较：

    cmd_v -> mocap longitudinal speed
    mocap longitudinal acceleration -> IMU a_x
    odom v -> mocap longitudinal speed

### 5.3 M1-B：原地左/右转

低风险、重复的左转/右转和角速度反向段用于标定 yaw 通道的符号、增益、滤波相位和 IMU 到动捕时延。

标注区间：

    spin_left
    spin_right
    spin_reversal

主要比较：

    IMU omega_z -> mocap omega_z
    odom omega_z -> mocap omega_z
    cmd_omega -> mocap omega_z

### 5.4 M1-C：S 弯中的左右恒曲率段与反转

这组数据对当前晃液问题最有价值。它同时激励：

    a_x
    a_y
    omega_z
    alpha_z

标注区间：

    s_LR_rN_forward / s_LR_rN_return
    s_RL_rN_forward / s_RL_rN_return
    SWITCH|..._reversal

主要比较：

    IMU a_y -> mocap-derived a_y at IMU point
    v * omega -> mocap-derived lateral acceleration at tube point
    cmd_omega -> mocap omega_z

### 5.5 M1-D：完整三维安装旋转（本轮不做）

仅靠地面平面行驶，能核验 yaw、x/y 加速度和时间偏移，但不能可靠辨识完整的 roll/pitch IMU 安装旋转。本轮按当前需求停止在平面数据采集；如未来确有六轴需求，再作为独立夹具试验立项。

若要利用动捕稳健去除重力泄漏，建议在安全支撑下补录多个静止倾斜姿态，或使用刚性夹具让整车/IMU 经历至少三个非共面的已知姿态。禁止在无支撑的倾斜状态下运行车辆。

## 6. 离线处理：从动捕 pose 到 IMU / 试管真值

对每个有效的连续时间段，使用同一个、已记录参数的平滑和微分流程。高阶微分会放大动捕噪声，因此不能把未经平滑的位置二阶差分直接当作加速度真值。

### 6.1 先做坐标与刚体换算

设动捕刚体参考系为 M，物理 base_link 为 B，IMU 测量点为 I，试管中心为 T。

    T_WB(t) = T_WM(t) * T_MB

其中 T_MB 为 marker 构型和实测几何确定的静态外参。若 M0 被设置为刚体原点且轴向与 B 对齐，T_MB 可接近单位变换；否则必须显式保存。

IMU 和试管位于不同点时，必须分别换算。对刚体上固定点 P：

    a_P = a_B + alpha x r_BP + omega x (omega x r_BP)

其中 r_BP 是 B 到 P 的刚体杠臂。应先得到 IMU 点处的动捕导出加速度来验证 IMU，再得到试管中心处的 a_tube 驱动液体模型。不要把 IMU 点的加速度直接冒充为试管中心加速度。

### 6.2 时间对齐分为两类

不要用一个 delay 同时解释全部误差。

| 待估量 | 用途 | 建议数据 |
| --- | --- | --- |
| Delta_t_imu_mocap | 对齐两种测量时间戳 | 原地左右转/反转段的 IMU omega_z 与动捕导出 omega_z |
| Delta_t_cmd_v | 执行器线通道延迟 | cmd_v 与动捕导出线速度/纵向加速度 |
| Delta_t_cmd_omega | 执行器角通道延迟 | cmd_omega 与动捕导出 omega_z |

先估 Delta_t_imu_mocap，之后再估两个 cmd 到真实运动的延迟。历史上角通道延迟量级可能接近液体振荡周期，因此必须用反转段检查相位，不能只比峰值大小。

### 6.3 IMU 校验顺序

1. 静止段：先检查 gyro bias/noise 是否可观测，并记录加速度静态均值；若设备输出被精确钳为零，只能记录“设备零值行为”，不能声称辨识出原始 bias；
2. 左右转：确认 IMU omega_z 与动捕 omega_z 的正负号、峰值、时间偏移；
3. 直线段：比较 IMU a_x 与动捕导出的 IMU 点纵向加速度；
4. S 弯恒曲率段与反转：比较 IMU a_y、odom v*omega、动捕试管点横向加速度的符号、幅值和相位；
5. 在 frame、bias、gravity、杠臂和时间全部通过后，才讨论是否将 IMU a_y 送入 observer。

IMU 的 linear_acceleration 是 specific force，可能包含重力投影、零偏和振动。应使用动捕姿态做坐标旋转和重力处理后再比较；不得直接以 raw IMU a_y 取代未来预测窗口内的 a_y。

当前 WIT `/imu/data` 是 ROS 端未二次滤波的设备解码值，不是串口原始字节。驱动在收到姿态包时取主机 ROS 时间，并合并此前最新的 accel/gyro；该时间戳不等同于硬件采样时刻。后续滤波与时延分析必须保留这一语义。

### 6.4 每个 segment 的建议标注字段

    run_label
    segment_id
    segment_type
    t_start
    t_cmd_change
    t_imu_response
    t_mocap_response
    t_peak
    t_end
    valid
    invalid_reason
    marker_visible
    mocap_drop_or_jump
    imu_vibration_or_bump
    slip_suspected
    axis_sign_ok
    static_bias_ok
    notes

动态段不要仅用一个 peak timestamp 估计延迟；t_cmd_change、首次明显响应、过零点和峰值都应保留。曲率反转段尤其要标注左右切换的命令时刻、IMU 响应时刻和动捕 yaw-rate 过零时刻。

## 7. 雷达外参复核的后续接口

当前 M1_lidar_fixed 的第一用途是成为 Scout 刚体的一部分，并为雷达位置提供一个可追溯的点位核验。建议在本轮标定 metadata 中保存：

    lidar_marker_name = M1_lidar_fixed
    lidar_marker_location = fixed_base_or_bracket
    p_BM1
    p_BL
    R_BL_source = CAD / measured / unknown

可以据此检查雷达原点的平移是否合理，但不能将“一个雷达 marker”写成“已完成雷达 6-DoF 外参重标定”。

若后续确需重标完整雷达外参，应另开任务，冻结雷达 frame 定义、使用非旋转基座上的多点几何或目标板，并单独验证点云/scan 与动捕/车体坐标的一致性。本 IMU 标定数据不应因雷达外参尚未完成而阻塞。

## 8. 通过门槛与下一步

### 8.1 本轮 M0/M1 的最低通过条件

1. 三个 marker 组成的 Scout 刚体在所有标定段连续可见、无明显跳变；
2. marker 所在部件均不相对底盘运动，M1 不在旋转雷达头上；
3. IMU omega_z 与动捕 omega_z 在左/右转中符号一致，且估得的时间偏移在重复段中稳定；
4. 动捕导出的试管横向激励、IMU a_y 和 v*omega 的差异可被 frame、bias、杠臂、滤波或滑移中的某一层解释；
5. cmd 到真实线/角运动的延迟被分通道记录；
6. 所有原始 bag、marker 几何、静态外参、滤波参数和 annotation CSV 一并保存。

### 8.2 不应从本轮数据得出的结论

1. 不能因动捕 pose 平滑就直接认定液体模型正确；
2. 不能把 mocap/scout_odom 的空 twist 当作速度真值；
3. 不能把当前 IMU 瞬时加速度复制进未来 MPC horizon；
4. 不能将动捕 remap 为 /odom 或让 planner 使用其反馈；
5. 不能用单个雷达 marker 宣称完成完整雷达外参标定。

### 8.3 完成本 SOP 后的推进顺序

    marker / 外参冻结
        -> IMU 与动捕时间对齐
        -> M_actuator 与刚体激励验证
        -> 试管激励到 RGB 液面模型验证
        -> 冻结 M-release
        -> 再选择 Ts、P、C 和控制权重

这套顺序保持了当前 S-MPCC 方法分析中的边界：先让模型的物理输入和相位可证，再讨论优化器如何利用它。

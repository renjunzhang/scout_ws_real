## 0. 红线与统一口径

### 0.1 工作区与隔离仿真

```text
Scout workspace: /home/a/scout_ws
isolated sim:    /data/a/scout_sim_replacement
```

- `/home/a/scout_ws` 是代码/配置来源。
- `/data/a/scout_sim_replacement` 是正式仿真环境；不要改地图、world、launch、脚本，除非用户明确授权。
- 正式结果必须 strict fresh-sim：每个 case 单独启动/关闭 ROS/Gazebo，不允许在同一个 Gazebo session 里反复 reset 后当正式数据。
- 不使用 broad `killall` / `pkill`。脚本只能停止自己追踪到的子进程 PID。
- 不使用 `git reset`、`git clean`、`git checkout`、`git push`，除非用户明确要求。
- subagent 不允许控制 Gazebo/ROS 仿真；如使用 subagent，只能用于扫描/聚合/审计，并显式设置 timeout。

### 0.3 FAIL / timeout 规则

- 60s 内未 `GOAL_REACHED`：该 case 记为 FAIL。
- 单 case 外层建议：`timeout --preserve-status --kill-after=60s 15m ...`。
- 同一组连续失败超过 3 次：跳过该组剩余 run，并在 manifest/report 中写明。
- 正式后处理必须检查：
  - `valid_strict_case=true`
  - pre/post ROS/Gazebo reachability 均为 false
  - `goal_reached=true`

### 0.4 delay-phase 口径（2026-07-04 补充）

仿真内部消融 / hard-cap / 外部 baseline 正式对比默认使用：

```bash
DELAY_PHASE_MODE=off
DELAY_PHASE_LINEAR_DELAY_SEC=-1.0
DELAY_PHASE_ANGULAR_DELAY_SEC=-1.0
```

原因：隔离仿真没有实车那类 command/odom 执行延迟。把实车候选 delay（例如 `fixed_closed_loop, 0.08/0.05`）直接开到仿真里，会把 solver input forward-predict 到错误相位，可能反向激励 slosh；它只能作为“delay 归因实验变量”，不能作为仿真正式消融默认项。

已验证的 strict fresh-sim N=1 对照：

```text
# fixed_closed_loop 0.08 / 0.05：B_slosh 被相位补偿打坏
B0      /slosh/height p95=0.742 mm, max=1.555 mm
B_slosh /slosh/height p95=3.309 mm, max=3.934 mm
B_slosh internal /spmpc/slosh_height p95/max=5.395/6.903 mm

# delay off：slosh cost 本身仍能压内部模型 slosh
B0      /slosh/height all p95/max=0.571/1.047 mm, first15 p95=0.533 mm
B_slosh /slosh/height all p95/max=0.571/0.930 mm, first15 p95=0.419 mm
B0      internal /spmpc/slosh_height p95/max=0.737/1.338 mm
B_slosh internal /spmpc/slosh_height p95/max=0.476/1.233 mm
```

结论：仿真里验证“slosh cost 是否有效”时，先用 delay off；若专门研究 delay，则必须同一代码、同一路径成对跑 `delay off` 与候选 delay，并把 `command_intervention`、`solver_input_state`、`raw_state/predicted_state` 一起录入 bag。

实物含义：不要把 `fixed_closed_loop` 当成默认必开项；它是实物 delay 归因变量。实物若要判断是否该开，至少要在同一版代码下跑 `B_slosh_delay_off` 与 `B_slosh_delay_080_050`（必要时再跑旧 `0.15/0.22`），比较模型 slosh peak/p95、`fixed_closed_loop_applied_frac`、`history_complete_frac`、`command_limiter_frac` 与 `published_zero_frac` 后再决定。

### 2.3 更严格的推荐跑法：按 run 拆成 N=1 循环

为了实现“连续失败超过 3 次跳过”与单 case timeout，正式大批量复跑更推荐外层自己循环 `N=1`：

```bash
#!/usr/bin/env bash
set -u -o pipefail

WORKSPACE=/home/a/scout_ws
ROOT=/data/a/scout_sim_replacement
STRICT_WRAPPER=${ROOT}/scripts/run_strict_fresh_fair_comparison_n3.sh
MAP_FILE_FIXED=${ROOT}/maps/proxy_world_manual_saved_20260611_154348.pbstream
CASE_TIMEOUT=${CASE_TIMEOUT:-15m}
RUNS_PER_GROUP=9
FAIL_STREAK_LIMIT=3

run_one() {
  local matrix="$1"
  local run_idx="$2"
  local batch="$(date +%Y%m%d_%H%M%S)_internal_${matrix}_run${run_idx}"
  cd "$WORKSPACE" || return 99
  timeout --preserve-status --kill-after=60s "$CASE_TIMEOUT" env \
    BATCH_STAMP="$batch" \
    N=1 \
    MATRIX="$matrix" \
    MODE=closed_loop \
    RECORD_SEC=60 \
    STRICT_PRE_CONTROL_SETTLE_SEC=30 \
    STRICT_POST_SHUTDOWN_SEC=30 \
    MAP_FILE="$MAP_FILE_FIXED" \
    GOAL_X=5.0 GOAL_Y=0.0 GOAL_YAW=0.0 \
    PATH_TEMPLATE=s_curve PATH_START_HEADING=current \
    PATH_AMPLITUDE_RATIO=0.18 PATH_MIN_AMPLITUDE=0.25 PATH_MAX_AMPLITUDE=1.20 \
    PATH_SIDE=left PATH_SMOOTH_ITERATIONS=3 \
    DELAY_PHASE_MODE=off DELAY_PHASE_LINEAR_DELAY_SEC=-1.0 DELAY_PHASE_ANGULAR_DELAY_SEC=-1.0 \
    "$STRICT_WRAPPER"
}

for matrix in spmpc_B0 spmpc_B_smooth spmpc_B_slosh spmpc_B_ours spmpc_B_slosh_hard spmpc_B_ours_hard; do
  fail_streak=0
  for run_idx in $(seq 1 "$RUNS_PER_GROUP"); do
    if run_one "$matrix" "$run_idx"; then
      fail_streak=0
      echo "[internal_n9] ${matrix} run ${run_idx}: OK"
    else
      fail_streak=$((fail_streak + 1))
      echo "[internal_n9] ${matrix} run ${run_idx}: FAIL fail_streak=${fail_streak}"
      if (( fail_streak > FAIL_STREAK_LIMIT )); then
        echo "[internal_n9] ${matrix}: skip remaining runs"
        break
      fi
    fi
  done
done
```

> 注意：上面是启动模板。正式报告还需要额外汇总每个 run 的 `strict_fresh_manifest.csv`、summary、bag path，生成 master manifest 和统计表。

from pathlib import Path

path = Path(sys.argv[1])

path.write_text(new, encoding='utf-8')

### 4.4 外部 baseline N=9 批量策略

推荐一组一组顺序跑，不并发控制仿真：

```bash
RUNS_PER_ALGO=9
FAIL_STREAK_LIMIT=3

run_algorithm() {
  local algorithm="$1"
  local matrix="$2"
  local extra_name="${3:-}"
  local extra_value="${4:-}"
  local fail_streak=0

  for run_idx in $(seq 1 "$RUNS_PER_ALGO"); do
    if [[ "$algorithm" == "lt_dwa_official" ]]; then
      run_ltdwa_one "$run_idx"
    else
      run_generic_one "$algorithm" "$matrix" "$run_idx" "$extra_name" "$extra_value"
    fi

    rc=$?
    if [[ "$rc" == "0" ]]; then
      fail_streak=0
      echo "[external_n9] ${algorithm} run ${run_idx}: wrapper OK; still check manifest/summary"
    else
      fail_streak=$((fail_streak + 1))
      echo "[external_n9] ${algorithm} run ${run_idx}: FAIL rc=${rc} fail_streak=${fail_streak}"
      if (( fail_streak > FAIL_STREAK_LIMIT )); then
        echo "[external_n9] ${algorithm}: skip remaining runs"
        break
      fi
    fi
  done
}

run_algorithm spmpc_B_ours_hard_1mm spmpc_B_ours_hard
run_algorithm dwa dwa

run_algorithm mpc_local_planner_tuned mpc_local_planner MPC_PLANNER_CONFIG "$MPC_TUNED_CONFIG"
run_algorithm lt_dwa_official lt_dwa_official
```

> 注意：`wrapper OK` 不等于正式成功。正式成功以 manifest + summary 为准：strict valid、pre/post port clean、goal reached。

## 6. 当前推荐结论口径

- 当前推荐 SPMPC hard cap：`slosh_height_max=0.001 m`（1.0mm）。
- `0.85mm` 可行，但 acados transient failure 更多，属于更激进补充。
- 外部 baseline 不使用 slosh feedback，液面只作为外部评价指标；不要把外部 baseline 的液面表现描述成其“主动抑晃”。
- TEB/mpc_local_planner/LT-DWA 到点时间可能更短，但 tracking RMS 和液面指标需按表格综合比较。
- 正式结论必须区分：内部消融、hard-cap 阈值敏感性、外部 baseline 对比，不能混成同一类因果解释。

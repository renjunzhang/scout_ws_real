# SIM-R8 源码隔离仿真实验矩阵与执行方案

日期：2026-08-04

候选协议：`SIM-R8-MECHANISM-40-64-88-v1`（尚未冻结）

当前状态：`DESIGN_ONLY / FORMAL_SIM_NO-GO`

## 结论与适用范围

本方案定义后续要重做的、**源码隔离**的 S-MPCC 仿真矩阵。仿真控制器、液体
plant、构建目录、ROS 节点和运行工具均位于
`src/scout_apps/simulation/` 与
`/data/a/scout_sim_replacement/r8_controller_ws/`，不会加载、构建、修改或启动
`src/scout_apps/control/` 的实物控制器。

本方案选择的目标是“仿真专用、机制验证”的 40 → 64 → 条件性 88，而不是把新
仿真数据冒充实物数据：

- 算法骨架来自实物 S-MPCC 的可审计 fork snapshot，但运行时没有实物源码/二进制
  依赖；
- R8 可在条件满足后支持论文中的仿真机制、鲁棒性和条件迁移证据；
- 它不替代实物实验、不与实物 rows 合并统计，也不能产生 physical-primary 结论；
- 历史 R1–R7/shared-source 结果保留为历史机制证据，**不能**重命名为 R8 或与本
  矩阵混合；
- 2026-08-04 已通过的 H0 live smoke 是 `formal: false` 的 development evidence，
  不占用下列任一 planned row。

`W5_S10` 的实物否证仍有效：它不能被写入任何正式 `Bslosh` identity。当前
`SIM_Bslosh_R1` 也是单独的 sim-only development release，不是本矩阵的
`Bslosh`，不能用其结果填充 40/64/88。

seed bundle；每个 row 仍必须 fresh ROS/Gazebo，不能在同一 Gazebo session reset 后
连续计数。

冻结的 block 数不再是 8，协议 ID、randomization table、master 和分母必须整体改写

## 3. 五个条件的冻结身份

| condition | backend | 身份合同 | 特别禁止项 |
| --- | --- | --- | --- |
| `B0` | online MPCC | 冻结的无 slosh/smooth baseline config | 订阅 plant truth、临场改 limiter/权重 |
| `Bsmooth` | online MPCC | 冻结的 smooth baseline config | 为改善结果临场改 `v_ref`/horizon |
| `SmoothMatch` | online MPCC | 相对 Bsmooth **仅**允许冻结后的一个 `v_ref` 差异 | 同时修改任意权重、observer、delay、solver、约束 |
| `FixedProfile` | frozen profile tracker | H1/C1、L1/C1、H1/C2 各自预生成、hash、只读 replay | case 内重新生成/优化 profile，读取 live liquid state |
| `Bslosh` | online S-MPCC | 新的 R8 source-specific release、完整 effective config 与 observer/delay policy | 使用 W5_S10、SIM_Bslosh_R1、plant hidden state 或未冻结候选 |

所有条件都必须产生 canonical effective-config dump。至少逐字段比较：

```text
w_control, w_smooth, w_alpha, w_du_a, w_du_vs, w_slosh,
v_ref, observer, delay, horizon, solver/backend, limits, safety/intervention
```

`SmoothMatch` 的 diff 只能留下 `v_ref`；任何额外变化为 protocol failure。R8
`Bslosh` 的 observer nominal source、fallback policy、delay semantics、container
model参数和所有 safety layer 都是 method identity 的组成部分。

## 4. 路径、容器与信号语义

### 4.1 H0 与正式 H1/L1

当前 H0 development 场景仅用于环境/可视化/smoke：开阔场地 P2，出生点 `(-4, 0)`，
终点 `(5, 0, 0)`，`/odom` 下 runtime s-curve。它沿用旧场地与终点，但不是 H1/L1。

正式 H1/L1 必须各自冻结 JSON 并经 R8 replay validator 验证：

1. source path hash、rigid transform hash、derived path hash；
2. 弧长、曲率和预定义关键分段保持在容差内；
3. 对 R8 world、robot footprint 和 container 做 fit/clearance audit；
4. case 内只读 replay，禁止以通用 runtime `s_curve` 代替。

H1 应含加速、连续曲率、曲率反转、再加速与终端制动；L1 是独立冻结的低激励任务，
不是 H1 结果不显著后临时选择的路径。

### 4.2 C1/C2

当前仿真 development candidate 为 `C1_37mm_H58_sim.yaml` 与
`C2_95mm_H58_sim.yaml`，其中 C2 直径为 95 mm、高度保持 58 mm。它们尚是
development/unvalidated 配置，不能直接当作 formal C1/C2 manifest。

第一条 formal row 前，必须冻结 geometry、liquid fill/freeboard、density、mounting、
plant/model parameter、initial-state rule 与允许的 C1→C2 transfer diff。S2B 只允许
预注册的 C2 物理变化；weights、solver、observer、delay、path、执行层和分析规则
保持不变。

### 4.3 liquid 信号与 claim

| 通道 | 语义 | 可否作为 physical-primary |
| --- | --- | --- |
| `/slosh/height` | `H_proxy`，仿真 model proxy | 否 |
| `/sim_spmpc/slosh_height` | `H_modal`，controller 内部 modal signal | 否 |
| `/sim_truth/liquid_height` | 仅在独立 plant/fidelity/firewall gate PASS 后的 simulator plant truth | 可作为**仿真 primary**，仍不是 physical-primary |

failure-inclusive 机制结果，不能声称 liquid physical efficacy。

## 6. 每个正式 row 的 strict-fresh 执行合同

```text
验证 immutable row / randomization / config / path / profile / seed hashes
  -> preflight：ROS 与 Gazebo master 均不可达
  -> fresh loopback ROS + fresh Gazebo + R8 environment
  -> 验证 map/world/robot/plant/ROS firewall 与 effective config
  -> 载入 block seed bundle 和只读 assets
  -> 30 s settle
  -> recorder ready，确认 artifact 正在增长
  -> 启动本 row 的 controller/tracker（保持 motion gate）
  -> release frozen path，记录 first effective motion
  -> 最多 60 s 等待精确 GOAL_REACHED
  -> success 或 timeout 均记录 frozen tail
  -> 关闭 recorder，执行 readback/QC
  -> 仅停止本 case 拥有的 PID/process group
  -> 30 s post-shutdown wait
  -> postflight：两 master 均不可达
  -> append-only attempt manifest / dataset index / denominator ledger
```

硬规则：

- 60 s 从 first effective motion 开始计；总 case wall time 可以更长，因为包含启动、
  settle、tail 和 postflight；
- recorder 必须在运动前准备好；success 和 timeout 都保留冻结 tail；
- pre/post 任一 master reachability 为 true，attempt 不具 strict-fresh 资格；
- map、world、path、config、profile、seed、source/build 与 runtime hashes 全部写入
  attempt manifest；
- 不并发争用同一 ROS/Gazebo master；bags/results 只保存在
  `/data/a/scout_sim_replacement`；
- GUI/RViz 仅作为 development visual check，不能改变 formal lifecycle 或证据等级。

## 7. seed、随机化、failure 与固定分母

每个 block 产生一个 seed bundle，并使用独立 sub-seed 或按 simulation-time 索引的
trace 覆盖：initial robot pose、initial liquid state、actuator disturbance、sensor noise、
contact/environment noise、simulator RNG。条件不可通过不同 callback/RNG 消耗改变
同 block 的实际扰动。

冻结三张互相独立的随机表：

```text
SIM-S1_CORE_randomization.csv          # 40 rows
SIM-S2A_SELECTIVITY_randomization.csv  # 24 rows
SIM-S2B_TRANSFER_randomization.csv     # 24 rows
```

每行至少记录 stage、planned_row_id、block_id、order_position、condition_id、path_id、
container_id、seed_bundle_id、planned_block_segment_id 与 randomization hash。S1 为
five-condition randomized complete block；S2A/S2B 各为 three-condition complete block。

| 类别 | 例子 | 能否 retry 覆盖 |
| --- | --- | --- |
| `METHOD_FAILURE` | solver/planner/tracker crash、observer fallback、collision、60 s timeout、method-specific config/CPU/data问题 | 否 |
| `INFRASTRUCTURE_ACQUISITION` | 运动前 ROS/Gazebo/recorder/storage/host 无法取得，且 condition 尚未被执行 | 仅限冻结 classifier + 外部 authorization 后可 retry |
| `PROTOCOL_FAILURE` | hash/row/seed/profile/port/firewall/freshness 不符 | 否；停止并审计 |

所有 stage/condition/contrast 逐项报告：

```text
N_plan
N_attempt
N_method_success / N_plan
N_method_failure / N_plan
N_pair / N_block_plan
```

统计单位永远是 planned row；attempt、ROS message、control cycle、Gazebo step 或 path
point 都不能作为样本。S2A/S2B 的同号 block 也不能跨路径/容器直接配对。

## 8. outcome、stage gate 与报告

如果独立 plant gate PASS，仿真 primary 可预冻结为：

```text
H_plant,p95(first effective motion -> first arrival + frozen tail), lower is better
```

它是 **simulator-primary**，不是 physical-primary。secondary 包括 completion time、
success/failure、tracking、terminal error、collision/safety、runtime、real-time factor、
command intervention 和 plant/modal/proxy mechanism traces。若 plant gate未 PASS，
`H_proxy/H_modal` 只能置于 mechanism 列，不能反向替代 primary。

stage gates：

1. **entry → S1**：所有第 5 节 NO-GO、schema validator、source GO、timing、fresh
   smoke、formal backend 与 randomization 均 PASS。
2. **S1 → S2A**：40 个 planned rows/attempts closure、QC/fidelity/firewall PASS；
   预注册 `Bslosh-Bsmooth`、SmoothMatch completion、FixedProfile、success/tracking/
   runtime 与 leave-one-block-out gates PASS。
3. **S2A → S2B**：S2A 的 24 rows closure 和独立 selectivity report 固化；预注册
   C2 transfer trigger PASS。未触发则停止在 64。

每个 stage 输出 raw per-row table、attempt ledger、fixed-denominator summary、paired
contrast table、QC/failure table、config/source/path/plant hashes 和 analysis report。大 bag
和原始结果留在 `/data/a/scout_sim_replacement`；报告镜像写入：

```text
/data/a/Obsidian/vaults/StudyVault/30-Projects/MPC/
规控一体的实验记录/仿真实验/<R8-release>/
```

repo 中只保存代码、freeze 小型 manifest、validators、测试和 Markdown 报告。

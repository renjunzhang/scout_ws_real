# 20260818 仿真正向但实物未复现的可能原因与解决测量方案

日期：2026-08-18

状态：`DEVELOPMENT_HYPOTHESIS_LEDGER`；基于现有仿真、G3R2 四条实物配对和离线 replay 的分析记录，尚未通过新实物实验验证。

验证状态：`ANALYZED`；本文件没有新增代码运行、仿真或实车数据。

## 1. 当前现象与结论边界

当前证据可概括为：

```text
控制仿真：液体模型指标正向
实物 RGB：未复现正向收益，点估计略微反向
实物内部状态：未显示改善
统计结论：W5_S10 未确认，不能宣称实物中存在稳定反向效应
```

主要数据：

| 证据 | 当前结果 |
| --- | --- |
| 三个控制仿真场景 | 外部模型晃动降低约 `8.3%--13.8%`，内部模态指标降低约 `9.0%--17.6%` |
| 实物 RGB P95 | Bsmooth `0.6863 mm`，W5_S10 `0.6923 mm`，W5 点估计高 `0.0060 mm` |
| 实物 RGB RMS | Bsmooth `0.3407 mm`，W5_S10 `0.3414 mm`，基本持平 |
| 实物 raw-IMU P95 | W5_S10 比 Bsmooth 高 `0.0640 mm` |
| 路径跟踪 | W5_S10 contour P95 高约 `0.01445 m` |
| 数值传播 | OCP 预测与高精度 planned replay 的 RMSE 约 `0.034 mm` |
| 实际输入重放 | 同一液体模型使用未来实际 IMU 输入时，与 RGB 相关性约 `0.71--0.74` |

因此本文件使用“仿真正向、实物未复现”，不使用“实物确定反向”。计划中的 DualSPHysics 全轨迹粒子回放没有执行，现阶段也没有独立高保真粒子仿真结果支持或否定控制器内部模型。

## 2. 可能原因、解决办法与测量方案

### 2.1 高优先级

| 编号 | 可能原因 | 当前依据 | 简单解决方案 | 测量与判定 |
| --- | --- | --- | --- | --- |
| H1 | **规划运动没有被实车准确执行** | actual-IMU replay 仍与 RGB 中等相关，而 planned horizon 随 lead 快速衰减 | 统一 planned/realized 输入语义；记录命令、底盘响应和容器中心实际激励；必要时把执行器延迟或一阶滞后加入预测模型 | 逐周期比较计划与实际的 `a`、`v*omega` 区间 impulse、频谱、相位和 RMSE；按低/高 mismatch 分层检查 first action 与 RGB |
| H2 | **机器人与液体初始状态不在同一物理时刻** | `fixed_robot_only` 使用预测后的机器人状态和当前液体状态；horizon 发布时液体 q0 通常已旧约 `41--57 ms` | 增加共享 `cycle_id`、状态 epoch、solve start/end、horizon available、command publish/effective stamp；将 robot/liquid x0 对齐同一 epoch | 强制检查 `raw selected -> solver input -> solved x0` 接口误差为零、时间单调、两类 x0 epoch 差小于冻结门槛；区分 hindcast 与 causal forecast |
| H3 | **完整 2 s 液体代价使用了低可信远期节点** | 真正可用后约 `0--100 ms` 尚有中等方向信息，`100--333 ms` 衰减，`333 ms` 后不宜作为可靠物理预测 | 保持机器人总 horizon 不变，离线比较液体代价 60 步、前 10 步、前 5 步以及 100 ms 后折扣 | 固定同一 snapshot，测量不同 slosh-horizon 方案下第一条 `a/alpha/v_s`、raw command、预测峰值和 solver status 的变化；只有 first action 对远期节点敏感才修改在线 OCP |
| H4 | **旧配对仍有公共控制权重混杂** | `B_smooth.w_control=0.3`，`B_slosh.w_control=0.1`，旧实验并非只改变 `w_slosh` | 建立同一 10D slosh solver、同一状态输入和全部相同公共权重的 `w_slosh=0/5` 比较，只切换液体代价 | 先做同 snapshot 零/非零权重 replay，再做新 development ABBA；逐项发布 effective config 并要求除 `w_slosh` 外完全相同 |
| H5 | **滚动重规划、限幅和底盘内环破坏远期抵消序列** | MPC 每 33 ms 只执行第一步，后续计划通常不会完整执行；solver 后还有 terminal/shared limits 和底盘速度环 | 记录 solver raw command、各 gate 后命令、实际 odom/IMU 响应；检查减晃是否依赖未执行的未来反向激励 | 统计每层命令改变量、限幅触发率、command-to-motion 延迟和规划序列 adherence；若低 adherence 时收益消失，则优先修执行模型而非加大液体权重 |

### 2.2 中等优先级

| 编号 | 可能原因 | 当前依据 | 简单解决方案 | 测量与判定 |
| --- | --- | --- | --- | --- |
| H6 | **低阶线性液体模型存在 sim-to-real 差距** | 模型只传播主模态，输入主要为 `a` 和 `v*omega`；实物还可能受 jerk、角加速度、振动、侧滑、安装误差和高阶模态影响 | 先用实际 IMU + RGB 离线识别 `omega_n/zeta/kappa/平面旋转/延迟` 候选，训练、验证、测试数据分离；暂不直接重写 ODE | 比较 held-out 数据的幅值、相位、主频、衰减、RMSE 和相关性；actual-input replay 不能稳定复现 RGB 时才升级模型结构 |
| H7 | **observer 没有独立液面反馈，误差会随传播积累** | processed-IMU 是刚体激励输入，不是液面状态测量；当前状态主要由模型传播 | 短期记录 innovation；中期评估带时间戳 RGB 的 output-feedback estimator，并正确处理延迟/OOSM | 检查一拍预测与下一拍估计残差的偏置、白噪性、相位和 reset/fallback 分层；估计器必须在 held-out bag 降低误差后才进入闭环 |
| H8 | **MPC 优化代理与 RGB 评价量不一致** | MPC 惩罚二维 `eta/eta_dot`，实物主要测量单相机可见方向和 P95/RMS；内部模态下降不保证可见投影下降 | 冻结带符号的 RGB `R-L` 投影与独立 calibration/validation；同时保留模态范数、方向和相位 | 报告 `eta_x/eta_y -> signed RGB` 的 held-out gain、intercept、condition number、相关性和相位；禁止只用非负 max/median 指标证明模型正确 |
| H9 | **路径激励和控制差异过小，收益被噪声淹没** | H0、`v_ref=0.20 m/s` 下 RGB P95 多次集中在 `0.68--0.69 mm`；planned control 相对自由衰减的新增预测收益约 `0--5%` | 在安全范围内设计能覆盖主要液体频率、但不进入溢出风险区的开发路径或激励段；先做静态/重复性噪声基线 | 预先冻结最小可检测差异；比较信号幅值、传感器重复性、方向一致性和效应量，避免在测量下限附近继续堆 trial |
| H10 | **求解代价或归一化没有把权重放到真正有效的物理方向** | slosh cost、terminal cost 和真实 RGB 指标不是同一量；现有 aggregate cost breakdown 也不是精确 OCP 目标分解 | 输出精确 per-node slosh cost、terminal contribution 和 first-action sensitivity；检查 `eta` 与 `eta_dot` 权重和参考尺度 | 测量各时段代价质量、梯度/adjoint 或截断消融后的首控制变化；不能仅凭 cost 占比判断哪个节点驱动动作 |

### 2.3 测量与统计层

| 编号 | 可能原因 | 当前依据 | 简单解决方案 | 测量与判定 |
| --- | --- | --- | --- | --- |
| H11 | **单相机 RGB 已处于低幅分辨区** | 两组 P95 差异仅约 `0.006 mm`，远小于当前低幅波动尺度 | 重复静止和已知小幅激励，冻结量化、重复性、漂移和最小可检测差异；保留原生 source stamp 和 signed feature | 若方法差小于预冻结测量分辨率，只能报告“不可分辨”，不能报告正向或反向 |

### 2.4 当前相对不支持的主因

现有证据不支持把 acados 数值积分或求解失败列为首要根因：

- OCP 与高精度 planned replay 的 RMSE 约 `0.034 mm`；
- 四条实物配对没有 solver failure；
- W5 求解时间虽约为 Bsmooth 的四倍，但仍通过实时门槛。

仍应保留 solver status、KKT/残差、bound activity 和首控制重放检查，但优先级低于 H1--H5。

## 3. 备选路线：离线防晃轨迹生成与跟踪

### 3.1 是否需要这条路线

需要保留，但它是 S-MPCC 主线之外的 **Plan B 和诊断对照**，不是直接替代在线局部规划。

B01、B02、B03、B11、C01、C03、C06 等参考工作表明，防晃常被放在完整轨迹、路径时间律、速度/加速度 profile 或 input shaping 阶段，再由在线控制器跟踪预先生成的参考。该路线不依赖每 33 ms 重新预测完整抵消序列，因此可以绕开 H2/H3/H5 中的部分在线状态 epoch、低可信远期预测和滚动重规划问题。但它通常要求路径和环境预先已知，对临时障碍、运行中改道和模型参数变化的适应性弱。

当前仓库已经有这条路线的初版资产：

- `scout_profile_baselines` 提供 Hamaguchi-style two-impulse input-shaped profile 和 Lim-style 离线 heuristic retiming；
- `run_fixed_profile_real_trial.sh` 已提供冻结 path/profile/hash、common tracker 和实物录制入口；
- 两种现有生成器都主要在固定路径上生成或修改速度 profile；Hamaguchi-style 不重新设计路径几何，Lim-style 也不是论文级 full-trajectory OCP。

因此“备选路线已经有执行框架”和“当前 FixedProfile 已经是可靠退路”必须分开。R7 描述性仿真结果为：

| 条件 | Bsmooth：完成时间 / H_proxy peak | FixedProfile：完成时间 / H_proxy peak | 当前判断 |
| --- | --- | --- | --- |
| H1/C1 | `33.0837 s / 1.1229 mm` | `50.8569 s / 1.6234 mm` | FixedProfile 更慢且模型晃动更高 |
| L1/C1 | `31.5309 s / 1.1553 mm` | `45.8952 s / 1.6311 mm` | FixedProfile 跟踪较准，但减晃未成立 |
| H1/C2 | `33.3393 s / 2.9919 mm` | `50.8489 s / 4.6089 mm`，成功 `7/8` | 出现一条 timeout，不能直接进入实物正式比较 |

这些量仍是模型 proxy，不是实物液面真值；它们只能说明当前 FixedProfile 实现不能未经修订就作为成熟 Plan B。

### 3.2 建议的分层方案

| 路线 | 内容 | 定位与放行条件 |
| --- | --- | --- |
| Route-F0：现有 FixedProfile | 保留 Hamaguchi-style 与 Lim-style profile、冻结 CSV 和 common tracker | 仅作传统方法基线、执行链诊断和回归测试；当前结果不支持直接升格为可靠备选 |
| Route-F1：OfflineSloshOCP | 固定路径几何，离线优化时间参数、速度、纵向加速度和转向角加速度 | **优先实现的 Plan B**；先隔离“好的时间律是否足以减晃”，避免路径几何变化引入额外混杂 |
| Route-F2：Path+Timing OCP | 在冻结走廊内联合优化路径几何、曲率和时间参数 | 只有 Route-F1 在弯道受限且证据指向 `v*omega`/曲率激励时才进入；需另建 release |
| Route-H：Hybrid | 以离线防晃轨迹为 nominal reference，在线 S-MPCC 只做有限修正、进度更新和障碍处理 | 后续增强路线；必须单独验证在线修正不会破坏离线设计的相位抵消序列 |

### 3.3 Route-F1 的最小技术定义

第一版不重新选路，只对同一冻结路径进行 **model-based offline retiming**：

1. 复用当前 10D 模型状态 `x=[px,py,theta,v,s,omega,eta_x,eta_x_dot,eta_y,eta_y_dot]` 和控制 `u=[a,alpha,v_s]`，避免为备选路线另造一套不可比较的液体模型。
2. 输入仅允许包括冻结路径、容器/液体参数、统一速度与加速度限制，以及从独立开发数据识别的底盘延迟或一阶执行器模型。
3. 目标同时考虑完成时间、`eta/eta_dot`、`a/alpha` 和控制变化率；约束至少包含 `v/omega/a/alpha`、横向加速度、路径走廊、起终点静止和终点残余晃动。
4. 离线可用 CasADi/IPOPT 等非实时求解器；求解时间不是首要指标，但必须记录 solver status、约束违反、迭代数和 artifact hash。
5. 执行时只读取预生成且冻结的 trajectory/profile，不读取 live RGB、online slosh observer 或当前试验结果重新生成 profile。
6. 保持现有 tracker CSV 作为稳定执行接口；另存 sidecar/report，记录完整 `v/omega/a/alpha`、预测 `eta/eta_dot`、约束余量和生成配置，供 planned-realized 对齐。

Route-F1 的核心假设是：若完整抵消序列在执行前一次性优化并被实车较好复现，减晃收益应比每周期只执行第一步、不断覆盖远期计划更稳定。该假设仍需实物 RGB 验证，不能由离线 OCP cost 或内部 `eta` 自证。

### 3.4 最小比较和测量合同

首轮 development 使用同一冻结路径、容器、初始静置合同、公共底盘限制和预冻结完成时间公平规则，比较：

```text
Bsmooth
现有 FixedProfile（Route-F0）
OfflineSloshOCP（Route-F1）
新的 matched-weight online S-MPCC candidate
```

| 测量层 | 必须记录 | 主要判定 |
| --- | --- | --- |
| 真实液面 | RGB P95、RMS、signed feature、运动后 tail/settling | Route-F1 的改善必须超过预冻结测量分辨率，并在独立 block 中方向一致 |
| 计划与实际激励 | planned/commanded/realized `a`、`v*omega` 的 impulse、RMSE、频谱和相位 | 判断离线抵消序列是否真正执行，以及收益是否随 adherence 提高而出现 |
| 路径与任务 | contour P95/RMSE、完成时间、goal timeout、failure | 防止用极慢运动或更差路径跟踪换取表面减晃 |
| 模型外推 | actual-input replay 对 RGB 的幅值、相位、主频和 held-out 误差 | 判断成功/失败来自轨迹方案，还是来自相同低阶模型的 sim-to-real 偏差 |
| 生成与执行链 | path/profile/config/tracker hash、solver report、限幅触发率和 command delay | 保证每条 trial 执行的是同一冻结 artifact，失败行不得被成功重跑覆盖 |

先做小规模顺序平衡 development block，不把候选筛选数据并入正式确认。只有 Route-F1 在真实 RGB、任务完成和跟踪门同时通过后，才冻结新的 profile release 并设计正式样本量。

### 3.5 结果如何定位根因

| 观察结果 | 更支持的解释 | 下一步 |
| --- | --- | --- |
| Route-F1 实物正向，online S-MPCC 未复现 | H1/H2/H3/H5：在线时间对齐、低可信远期节点、滚动覆盖或执行链破坏抵消序列 | 优先修在线状态 epoch、短期 slosh cost 和 command realization；保留 Route-F1 为可用 Plan B |
| Route-F1 与 online S-MPCC 都未复现 | H6/H8/H11 或共同执行问题：模型、评价投影、测量分辨率或底盘激励语义不正确 | 停止继续加权，先做 actual-input model identification、RGB 台架与执行器辨识 |
| Route-F1 与 online S-MPCC 都正向 | 低阶模型和主要激励语义具备实物有效性 | 比较动态障碍、改道和扰动条件下在线方法的额外价值 |
| Route-F1 只在低 mismatch trial 正向 | planned-realized adherence 是关键中介变量 | 将执行器延迟/内环模型纳入 OCP，并冻结 adherence admission gate |
| Route-F0 失败但 Route-F1 正向 | 简单 input shaping/heuristic retiming 不足，完整动态约束和终端残余条件有必要 | 保留 F0 为 prior-art-inspired baseline，不把失败泛化为所有离线轨迹法无效 |

### 3.6 声明边界

- Route-F1/F2 解决的是已知或冻结路径上的防晃轨迹生成，不等价于动态环境中的在线 local planner。
- 离线方案可以成为实物可用备选和论文 supplementary comparator，但不能反向抹去 S-MPCC 在 online local planning 层的研究问题。
- `Bslosh - OfflineSloshOCP` 是 end-to-end system comparison；单凭该比较不能证明“动态液体记忆在因果上必需”。
- 若 Route-F2 改变路径几何，必须同时报告 route length、曲率分布、最短障碍距离和完成时间，不能把不同几何路径的收益只归因于液体代价。

## 4. 推荐的最小验证顺序

### P0：不启动实车

1. 补齐共享 `cycle_id` 和完整时间合同。
2. 用现有四包完成 planned/realized input、observer、RGB 四层 replay。
3. 建立同一 10D solver 的 matched-weight `w_slosh=0/5` snapshot 消融。
4. 完成 60 步、10 步、5 步和远期折扣的 first-action 消融。

P0 放行条件：能明确回答状态时间是否一致、计划输入实现程度、actual-input 模型误差以及低可信远期节点是否实质改变第一控制动作。

### P1：台架或零运动/小激励验证

1. 复测 RGB 静止噪声、漂移和最小可检测差异。
2. 使用已知平移/偏航小激励验证 IMU、observer、RGB 的幅值和相位。
3. 冻结容器安装、IMU 外参、相机参数和液体初始静置合同。

P1 放行条件：source stamp 健康、observer 无 reset/fallback、held-out RGB 映射达到预冻结误差门槛。

### P2：新的 development 实物配对

1. 不继续旧 G3R2 Row 05/06，也不复用 `W5_S10` 成功名义。
2. 使用同 solver、同状态、同公共权重，只切换预冻结的液体代价方案。
3. 先做两个顺序平衡 ABBA block；逐条执行相机、IMU、跟踪、安全和时间合同 postflight。
4. 只有出现可重复、超过测量分辨率的真实 RGB 改善，才设计正式 Stage I。

## 5. 统计和声明边界

11 类统计/方法偏差已逐项检查。当前主要需要关注：

- `CAUTION`：单次筛选后的均值回归；
- `CAUTION`：多候选选择产生的 look-elsewhere / winner's curse；
- `CAUTION`：复杂 post-hoc 对齐与模型选择中的 garden of forking paths；
- `CAUTION`：相关性和 actual-input oracle replay 不能直接证明在线控制因果收益。

当前没有足够证据支持稳定的 Simpson 反转、生态谬误、Berkson/碰撞器偏差、base-rate neglect、survivorship bias 或 reverse causality；但新实验仍应保留全部失败行、全部候选、预注册分析和 block-level 统计，防止这些偏差进入后续结论。

允许的表述：

> S-MPCC 在当前控制仿真模型中表现出减晃趋势，但该收益没有在现有实物配对中复现；实物点估计略偏向基线，差异处于低幅区，尚不足以证明稳定反向效应。

## 1. 本批实验实际比较了什么

N01、N02、N03 是同一组配置下的三次独立重复，不是三种控制参数：

```text
planner variant             = B0
slosh_enable                = false
solver consumes liquid      = false
robot delay mode            = fixed_robot_only
robot delay                 = 0.15 s linear / 0.22 s angular
v_ref                       = 0.10 m/s
v_safe_max                  = 0.15 m/s
path                        = frozen C02_v2
liquid methods              = O0 / I0 / I1 / L22 parallel shadow
I1 and L22 applied_to_solver= false
```

四路含义：

| 方法 | 状态来源与处理 | 本批用途 |
| --- | --- | --- |
| O0 | odom 液体观察器，不额外传播 | 输入源基线 |
| I0 | processed-IMU 液体观察器，不额外传播 | 当前状态基线 |
| I1 | processed-IMU 状态按实际时间戳短时传播到求解周期目标时刻 | 待验证候选 |
| L22 | 旧命令历史约 `0.22 s` rollout | 预先声明的诊断反例 |

因此四路共享完全相同的实物运动，不会因为某一路估计改变车辆轨迹。这是状态估计的 shadow 比较，不是 slosh 闭环减晃实验。

### 5.3 为什么不能直接选择 L22

L22 的平均 MAE 为 `0.2762 mm`，确实低于 I0 的 `0.3214 mm`，而且三包都更低。但这不构成把旧 `0.22 s` rollout 放入求解器的依据：

1. L22 在方案中预先定义为 legacy 诊断反例，不是候选放行分支；
2. 它的平均相关性 `0.7383` 低于 I0 的 `0.7909`，较低 MAE 与更接近零的幅值偏置有关，并不代表动态状态更正确；
3. N02、N03 的全局最大波峰落在不同事件上，peak-timing 分别可出现秒级乃至几十秒差异，不能解释为真实传感器延迟；
4. RGB `max-LCR` 是非负高度幅值，不能验证 `eta` 的方向、`eta_dot` 的符号或完整四维液体状态；
5. 旧 rollout 使用命令历史近似真实执行激励，已有实物执行链说明命令与实际角速度建立过程并不等价。

L22 的结果只能触发后续模型与执行器诊断，不能推翻当前 `L22 applied_to_solver=false` 的安全边界。

联合脚本状态为 `DEVELOPMENT_ONLY_NOT_RELEASE_EVIDENCE`，因为 runner 从采集时就把这三条标记为 development，不能事后改名为 held-out。即便只看预先冻结的数值门槛，I1 的平均门和方向门也都失败。

## 7. 下一步建议

当前不应直接做“I1 进入 slosh 求解器”的实车闭环。建议顺序：

1. 保留 N01～N03 和当前联合报告，不调整现有结果的 lag、scale、HSV 或标尺；
2. 检查 I0 observer state stamp 是否已经代表接近求解周期的有效时刻，排除重复前推；
3. 定位 23 次 `DYNAMICS_FAILURE` 的具体状态和触发周期；
4. 用同一批 development bag 离线比较更短的候选跨度或不同激励保持方式，但必须明确这些属于调参数据；
5. 冻结新实现和门槛后，另采新的 held-out bag 验证，不能继续复用 N01～N03 放行；
6. 如果选择 I0 作为下一版 slosh 求解器初始状态，也必须建立新的 replay、共同 epoch 合同、专用 runner 和 postflight，不能从本批 B0 shadow 直接跳到实车闭环。

## 9. 声明边界

本批允许的结论：

- 三条 B0 shadow 数据有效，证据链和安全隔离正常；
- 当前条件下 processed-IMU 的 I0 比 odom 的 O0 更接近 RGB 高度代理；
- 当前约 `28 ms` 的 I1 nowcast 没有改善，不能进入求解器；
- L22 虽然 MAE 较低，仍只能作为诊断线索。

本批不允许的结论：

- 不能说 I0 已经是完整四维 slosh 状态的最终真值；
- 不能说液体的物理延迟就是 `0 ms` 或 `28 ms`；
- 不能把全局 peak-timing 差直接解释成传感器延迟；
- 不能声称 I0/I1 改善了路径跟踪或实现了减晃，因为 B0 根本没有消费液体状态；
- 不能把本批 development 数据写成正式 held-out 或论文放行证据。

## 1. 结论

本轮 12 个方向/幅值、每项 2 次，共 `24/24` 条 bag 均完整有效。结果可以概括为：

1. 底盘存在明确的启动滞后和速度渐进建立过程，而且命令越小，响应越慢。它不是一个能覆盖全部低速范围的固定纯延迟。
2. 稳态增益基本接近 `1`。也就是说，给足时间后底盘通常能达到命令幅值；当前主要问题是“开始得晚、逐步建立”，不是“最终速度做不到”。
3. 直线响应的三传感器起效时刻基本一致；转向在 `0.20/0.30 rad/s` 时 NOKOV 与 IMU 也一致。百毫秒级响应不是 bag/header 时间戳伪差。
4. 转向的 odom FOPDT 建立过程明显早于 NOKOV 和 IMU，因此不能只用 odom 标定真实车体转动模型。
5. 现有 legacy `0.15/0.22 s` 在部分工作点与“刚开始动”的时刻接近，但不能表达后续速度建立，也不能作为全速度范围统一的物理纯延迟。
6. 本轮支持后续采用“线速度/角速度分开、随命令幅值变化的执行器模型”。不建议把现有补偿直接替换成另一组单一 delay。

这批数据能说明执行链失配足以成为 SMPCC 跟踪和液体预测误差的重要来源，但还不能单独证明它是液体预测失真的唯一原因。

所有单包报告均具备必需的 NOKOV、IMU、odom 和最终 `/cmd_vel`，制动分析及 FOPDT 可辨识性检查均通过。共同分析配置为：

```text
primary timebase             = rosbag arrival time
command step duration        = 约 4.020 s
command / NOKOV rate median  = 43.96 / 89.98 Hz
IMU / odom rate median       = 50.11 / 50.00 Hz
NOKOV velocity window        = 0.12 s
FOPDT fit window             = 只拟合启动上升段
FOPDT minimum R²             = 0.80
```

下文采用 NOKOV 为主结果，并将同幅值的正反方向、两次重复共 4 条数据取中位数。各指标含义为：

- `onset`：发出阶跃后，首次持续检测到运动的时间；
- `L`：一阶惯性加纯延迟模型拟合出的纯延迟；
- `tau`：运动开始建立后的时间常数；
- `K`：稳态实际速度与命令速度之比；
- `t90`：从发命令到达到本次实测稳态幅值 90% 的总时间；
- `a_eff`：实测速度从 10% 到 90% 的平均斜率，不是电机瞬时极限。

`onset`、`L` 和 `t90` 回答的是不同问题，不能互相替代。尤其在低速死区和非线性较明显时，FOPDT 会把部分缓慢起步等效进 `L`，所以 `L` 可以晚于首次可检测的 `onset`。

## 3. NOKOV 主结果

| 通道与幅值 | onset | FOPDT `L` | `tau` | `K` | 实测 `t90` | `a_eff` | 零命令后运动量 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 线速度 0.05 m/s | 369 ms | 355 ms | 118 ms | 0.984 | 832 ms | 0.084 m/s² | 4.3 mm |
| 线速度 0.10 m/s | 190 ms | 200 ms | 122 ms | 1.012 | 572 ms | 0.227 m/s² | 10.7 mm |
| 线速度 0.15 m/s | 139 ms | 155 ms | 112 ms | 1.018 | 417 ms | 0.475 m/s² | 19.1 mm |
| 角速度 0.10 rad/s | 422 ms | 671 ms | 261 ms | 1.066 | 1136 ms | 0.131 rad/s² | 0.35° |
| 角速度 0.20 rad/s | 217 ms | 445 ms | 163 ms | 1.082 | 863 ms | 0.369 rad/s² | 1.10° |
| 角速度 0.30 rad/s | 167 ms | 330 ms | 119 ms | 1.096 | 669 ms | 0.748 rad/s² | 1.89° |

### 3.1 幅值误差

线速度拟合增益约为 `0.982～1.063`，角速度约为 `1.017～1.098`，均围绕 `1`。因此在本轮 `4 s` 阶跃内，底盘稳态幅值总体能跟上命令。

角速度增益略高于 `1`，但量级只有约 `2%～10%`。相较之下，启动等待和渐进建立达到数百毫秒，是当前更主要的动态误差。

### 3.2 幅值相关性

命令幅值降低后，延迟显著增加：

- 线速度从 `0.15` 降至 `0.05 m/s`，onset 由 `139 ms` 增至 `369 ms`；
- 角速度从 `0.30` 降至 `0.10 rad/s`，onset 由 `167 ms` 增至 `422 ms`；
- 同一角速度范围内，FOPDT `L` 由 `330 ms` 增至 `671 ms`。

这与低速死区、静摩擦和底盘内部速度建立过程一致。仅用一个固定延迟描述整个低速范围，会在不同幅值下产生系统性时间误差。

### 3.3 本轮测到的能力边界

本轮最高只测试到 `0.15 m/s` 和 `0.30 rad/s`。表中的有效加速度随阶跃幅值增大而明显增大，说明它也是工作点相关量，不能把其中最大值直接写成全局硬加速度上限。

最高测试幅值下，NOKOV 中位有效加速度约为：

```text
linear  0.15 m/s step -> 0.475 m/s²
angular 0.30 rad/s step -> 0.748 rad/s²
```

两次重复中有效加速度的中位相对差约 `18.9%`，明显弱于延迟和稳态增益的重复性。因此当前结果适合给模型提供量级和开发候选值，不适合宣称为底盘铭牌极限。

## 4. 三传感器延迟交叉验证

下表每格为 `onset / FOPDT L`，统一使用 rosbag arrival time；直线 IMU 只提供加速度起效时刻，不拟合速度 FOPDT。

| 阶跃幅值 | NOKOV | IMU | odom |
|---|---:|---:|---:|
| 线速度 0.05 m/s | 369 / 355 ms | 357 / — ms | 386 / 370 ms |
| 线速度 0.10 m/s | 190 / 200 ms | 185 / — ms | 209 / 240 ms |
| 线速度 0.15 m/s | 139 / 155 ms | 134 / — ms | 146 / 200 ms |
| 角速度 0.10 rad/s | 422 / 671 ms | 394 / 749 ms | 400 / 400 ms |
| 角速度 0.20 rad/s | 217 / 445 ms | 212 / 459 ms | 212 / 220 ms |
| 角速度 0.30 rad/s | 167 / 330 ms | 158 / 340 ms | 161 / 180 ms |

判断如下：

1. 直线 onset 三路相差通常只有约 `5～20 ms`，支持“真实底盘确实存在幅值相关的启动滞后”。
2. `0.20/0.30 rad/s` 转向时，NOKOV 与 IMU 的 onset、`L` 都接近，说明真实车体转动过程可信。
3. 转向 odom 的 onset 尚且接近，但其 `L` 在 `0.20/0.30 rad/s` 时分别只有约 `220/180 ms`，比 NOKOV 早约 `225/150 ms`。这表示 odom 能较早报告非零轮速，却没有完整反映车体真实角速度的建立过程。
4. `0.10 rad/s` 转向本身最慢且两次重复较弱，三路 FOPDT 差异也更大，不能把这一档单独拿来冻结参数。

### 4.1 不是时间戳造成的假延迟

同一包分别按 bag arrival time 和消息 header time 计算 onset，最大绝对差为：

```text
odom              0.26 ms
IMU gyro          0.45 ms
IMU linear accel  0.25 ms
NOKOV             5.69 ms
```

FOPDT 网格拟合偶尔会因一个采样格产生约 `10～20 ms` 差异，但仍远小于本轮 `139～671 ms` 的主要响应量级。因此不能把本轮百毫秒级结果解释成 rosbag/header 时间戳选择造成的假象。

同时也要保留边界：相对 NOKOV 的数值包含动捕/Wi-Fi/消息链自身的观测时间，本轮测到的是“最终 `/cmd_vel` 发布到被传感器观测到运动”的总执行链，不是驱动器内部的纯电气延迟。

直线前后以及中高幅值左右转的 `L` 和 `K` 没有显示出需要立即建立两套方向模型的强不对称。`0.10 rad/s` 左右差异较明显，但这一档自身重复性最弱，现阶段应先归为低速不确定性，不能凭两次重复认定固定方向偏置。

有效加速度在 `0.15 m/s` 前后和 `0.30 rad/s` 左右存在一定差异；由于该指标重复性较弱且有 NOKOV 跳点干扰，若后续要冻结方向相关的加速度约束，需要增加独立重复。

## 6. 重复性与异常包

NOKOV 两次重复的中位相对差为：

| 指标 | 两次重复中位相对差 |
|---|---:|
| onset | 5.2% |
| FOPDT `L` | 4.8% |
| `tau` | 11.6% |
| `K` | 0.3% |
| `t90` | 10.2% |
| `a_eff` | 18.9% |

延迟和稳态增益适合用于 development 初筛；加速度和低速转向参数仍需更多重复。低速角速度尤其明显：

```text
Row01 左转 0.10 rad/s：两次 L 相差 161 ms
Row02 右转 0.10 rad/s：两次 L 相差 251 ms
```

以下两包的 NOKOV 速度曲线出现孤立尖峰，而 odom 与 IMU 没有同步尖峰，判断为动捕位置跳点，不是底盘真实瞬时加速：

```text
DEV_CHASSIS_STEP_R09_LIN_F_V010_a02
DEV_CHASSIS_STEP_R11_LIN_F_V015_a02
```

其中 R09/a02 的 NOKOV `t90=804 ms`、`a_eff=0.138 m/s²` 明显偏离同 Row 的 a01（`493 ms`、`0.264 m/s²`）。两包的 NOKOV peak/P95 以及建立时间、有效加速度应降权；但 onset 和 FOPDT `L` 仍相对稳定，因此不影响“幅值相关延迟”这一主判断。保留原始异常，不通过事后更改滤波将其隐藏。

另有 R08 后退 `0.05 m/s` 的 a01 中，odom `t90≈2.05 s`，属于低速 odom 阶梯量化影响；同包 NOKOV 与 FOPDT 仍正常，不能用这个单次 odom `t90` 代表底盘能力。

两次重复足够完成本轮快速开发筛查，但不足以给出高置信度正式标定值。若参数进入正式求解器，应冻结实现后另采 held-out 数据，不能把当前 development 包改名作为验证集。

## 7. 对现有 `0.15/0.22 s` 的解释

当前 legacy 补偿配置为线向 `0.15 s`、角向 `0.22 s`。本轮数据显示：

- `0.15 m/s` 时，线速度 onset/`L` 为 `0.139/0.155 s`，确实与 `0.15 s` 接近；
- `0.20 rad/s` 时，角速度 onset 为 `0.217 s`，与 `0.22 s` 接近，但完整拟合仍为 `L=0.445 s、tau=0.163 s`；
- `0.30 rad/s` 时角速度 onset 已降至 `0.167 s`，而 `0.10 rad/s` 时又增至 `0.422 s`；
- 所有工作点都还存在不可忽略的 `tau`，仅平移状态不能表达速度逐步建立。

因此，这两个旧值可继续作为已有跟踪 A/B 支持的工程 baseline，但不能被表述为底盘跨速度范围的固定物理参数。也不能因为本轮得到了一组新的中位数，就立刻把旧值替换成另一个统一 delay。

若建立新执行器模型，至少应满足：

```text
线速度与角速度分通道
delay / tau / gain 分开
参数随命令幅值调度或插值
odom 不单独作为角速度真值
旧 fixed delay 与新模型不得重复补偿
```

## 8. 当前能回答与不能回答的问题

当前已经能回答：

- 最终 `/cmd_vel` 到实车开始运动存在多大延迟；
- 实际线速度和角速度如何逐步建立；
- 在本轮低速范围内，稳态幅值、有效加速度和停车余量大约是多少；
- 延迟如何随命令幅值变化，以及 odom 与真实转动过程的差异。

当前仍不能单独回答：

- solver 内部计划动作是否与最终 `/cmd_vel` 完全一致，因为本测试绕过了 solver；
- 驱动器内部的纯电气延迟，因为传感器观测链仍包含在总时间内；
- 哪一组执行器参数能直接作为最终求解器冻结值，因为每行只有两次 development 重复；
- 执行器失配是否足以单独解释全部液体预测误差，需要将实测响应模型接入离线 replay，并与 RGB/IMU 液体结果继续对照。

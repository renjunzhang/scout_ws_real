旧 G3 release 不放行。其 fixed-closed-loop delay predictor 在四个描述性 block 中都让 W5 的内部预测晃液指标下降，但独立 RGB 只有 Block 02 支持 W5；原始 processed-IMU observer 的方法排序反而更接近 RGB。

## 2. 已核实原因

1. 旧配置声明线/角延迟为 `0.15/0.22 s`，但 predictor 实际统一积分 `max(0.15,0.22)=0.22 s`。
2. cmd 到实际响应不是方法无关的纯延迟：
   - Bsmooth cmd→odom 约为线 `0.20--0.22 s`、角 `0.34--0.35 s`；
   - W5 cmd→odom 约为线 `0.17--0.19 s`、角 `0.22--0.23 s`。
3. raw liquid observer 使用 IMU 实测加速度，delay rollout 随后改用 `delta(cmd_v)/dt` 和 `cmd_v*cmd_omega`，没有建立共同的激励模型。
4. 当前液体 LTI 模型没有旋转一致传播；`SloshDynamics::step()` 接收但忽略 `omega_z`。这仍是后续模型升级项，但本轮不与 delay/权重筛选同时修改。
5. Row 08 的 `/imu/data` bag 本身完整，但 planner 的 subscriber queue 原为 1，漏收一帧后形成 `40.02 ms > 35 ms` 的内部 gap，触发 reset 和 odom fallback。

## 3. G3R 最小 release 决策

为避免同时修改执行器模型、液体模型和权重，G3R 采用最小可证伪方案：

```text
delay_phase_mode             = shadow
closed-loop delay apply      = false
solver robot state           = current TF pose + odom twist
solver liquid state          = current processed-IMU observer
legacy predictor             = diagnostics only
IMU subscriber queue         = 10
observer fallback policy     = fail_closed
odom fallback during motion  = forbidden
```

这不是宣称执行延迟已解决，而是先移除已经被 RGB 否证的闭环状态变换。若 raw-state G3R 仍无正向物理结果，就停止实车重复，返回 actuator/rotation-consistent model 开发。

## 4. G3R 取样规则

初筛仅做五条，每个条件一次：一个 Bsmooth baseline，以及 `W2/W5 × smooth split 0.3/1.0` 四个候选。单条内所有权重冻结；不允许根据前一条 RGB 修改后续条件。

单次结果只用于候选筛选。只有同时满足以下条件才生成 paired-confirmation draft：

- 相对 baseline，RGB P95 至少改善 `0.05 mm`；
- RGB RMS 不恶化；
- raw processed-IMU P95 恶化不超过 `0.05 mm`；
- trial postflight、tracking、runtime、RGB、IMU READY/reset/fallback 全部通过；
- solver input 的 delay compensation applied fraction 不超过 `2%`。

若多个候选同时通过，按预先冻结的 `RGB P95 改善 + 0.5×RGB RMS 改善 + 0.25×max(raw IMU P95 改善, 0)` 排序，只选第一名进入确认。缺包、绑定不一致、bag 哈希不一致或任一 postflight 失败统一记为 `SCREEN_INVALID`，不得误解释成“没有正向候选”。

正向候选随后另建冻结 release，按三组配对进行确认。没有正向候选则停止，不补录、不选择性重跑。

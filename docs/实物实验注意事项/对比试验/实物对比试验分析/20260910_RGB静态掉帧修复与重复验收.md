## 1. 已实现与实测边界

- 驱动按实际选中的 profile 判断物理 sensor；默认 `poll_inactive_sensors=false`，跳过未启用 sensor 的温度读取与通知注册，并在初始化时关闭其 error polling。活动 sensor 的监控保留。原驱动 error polling 开→关→恢复的 60 秒对照中，发布前帧号跳跃分别为 106→51→102 次，支持它参与问题，但该修复单独不足以消除缺帧。
- 有效组合：**RGB `1920×1080@30`，曝光 100、增益 64、白平衡 4600，两种自动模式关闭，global time 保持 true；另开 depth `424×240@6`，emitter=0，stereo error polling=false**。深度图不录制、不参与控制，只作为本次实测有效的采集配置。最后一项显式关闭本次不用于测量的深度模块错误轮询，温度与通知注册仍保留。
- 现有传感器启动脚本新增 depth 尺寸、帧率、emitter 和 inactive polling 参数并打印；`enable_depth` 默认仍为 false，需显式使用下文配置。
- 新增 [静态诊断脚本](../../../../src/scout_apps/control/spmpc_local_planner/scripts/diagnose_spmpc_rgb_recording.py)，支持不写盘、仅 RGB、现有完整白名单三种模式。保留原 100 ms 门，分别核验连续性、时基、锁参；full 同时检查 odom、IMU、scan、Tracker0、TF 的记录覆盖。

设备帧号跳跃时驱动 seq 连续，实时 info/metadata 与 bag 一致，缺口发生在观察到的 ROS 发布之前；不能据此唯一归因于 USB、温度或 SDK。SDK 的 device 级后台校时走硬件查询，关闭 RGB `global_time_enabled` 仅切换输出时间域，本次没有改善，已恢复 true。低带宽 depth 的开/关对照支持该组合有效，尚未证明唯一底层机制。

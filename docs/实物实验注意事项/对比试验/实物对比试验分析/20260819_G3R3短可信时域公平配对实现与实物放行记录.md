## 1. 本轮处理结果

| 旧问题 | 本轮处理 | 当前边界 |
| --- | --- | --- |
| 每 33 ms 重规划覆盖旧 horizon 的后续动作 | 只让 `0--100 ms` 的液体状态代价进入 OCP；逐周期保存上一 horizon 的 `k=1` 与当前 `k=0` 差值，且只比较相邻 `cycle_id` | 没有强制执行完整旧 horizon；是否仍依赖低 adherence 的相位抵消必须由新 bag 量化 |

## 3. 新的逐周期审计

`/spmpc/debug/control_cycle_audit` 为每个控制周期提供唯一 `cycle_id`，并可与 `PreSolveSnapshot`、`PredictedHorizon`、observer selection 联结。主要字段分四层：

```text
raw OCP command
  -> terminal controller command
  -> terminal-spin/tracking safety gate command
  -> shared limiter / published command
```

同一记录还保存：

- robot/liquid 原始 epoch、共同 solver epoch、插值/外推状态；
- solve start/end、horizon available、command publish 时间；
- `u0.a`、`u0.alpha`、计划 `a` 与 `v*omega`；
- 相邻周期 `previous k=1 -> current k=0` 的替换量；
- odom 与 processed-IMU 实际 `a_x/a_y/omega/alpha` 及有效时间戳。

这些字段用于回答“优化器计划了什么、软件实际发布了什么、底盘最终产生了什么激励”，不能把同一周期里较早的 IMU 样本误当成刚发布命令的结果；离线分析必须按显式时间戳估计 command-to-motion delay。

- variant、processed-IMU source、公共权重和 `w_slosh` 身份正确；
- robot/liquid 使用共同 epoch，raw skew 不超过 `80 ms`；
- solver 成功、命令通过安全门且在实车 runner 中确实发布；
- shared limiter 未介入，命令合同无违反；

- 相邻计划比较不跨失败或门禁周期；
- processed-IMU excitation audit 有效；
- bag 不含 `sensor_msgs/Image` 或 `CompressedImage`。

## 7. 六条完成后的唯一决策

先按 block 计算 `Matched5 - Matched0` 的 RGB、跟踪、完成时间和可靠性，再计算：

1. `previous k=1 -> current k=0` adherence；
2. raw OCP 到 published command 的软件干预；
3. published command 到实际 IMU `a`、`v*omega` 的 delay、RMSE、相位和频谱；
4. internal model 与 RGB 的短 lead 一致性。

只有真实 RGB 改善超过冻结测量分辨率、方向跨 block 一致，同时跟踪/安全/执行链门通过，才考虑形成新的正式候选。若 `Matched5` 只在低 mismatch trial 中正向，则下一步是辨识执行器延迟/一阶内环并建立新 release；若 actual-input model 仍不能解释 RGB，则停止加大 `w_slosh`，转向模型/视觉投影辨识。

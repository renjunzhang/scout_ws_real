## 1. 先给结论

本次结果恢复仿真规律的核心原因不是“换了一个新的 delay 数值”，而是：

```text
1. 先做了 B0 fixed-path gate，确认当前实物 tracking baseline 是干净的；
2. 正式三方法比较统一固定在 fixed_closed_loop 0.15 / 0.22 下，只改变 variant；
3. 本次不再混入 hard constraint、delay-off、参数未落地等变量；
4. 当前 slosh soft cost 的 runtime 尺度/诊断口径比 20260702 更接近仿真口径；
5. 指标统计改用 path progress 10%~90% 的 max_10_90，避免起步/终点瞬态污染 peak 判断。
```

因此本次能看到：

```text
B_slosh 的 internal slosh peak / p95 / RMS 明显低于 B0；
B_ours 也低于 B0，同时角速度命令更平滑；
但 B_ours 的晃动抑制不如 B_slosh，说明 smooth priority 在本次口径下更偏“平滑/保守”，不是最强 slosh 抑制。
```

相对地，20260702 的结论是：

```text
B0 的 /spmpc/slosh_height 反而低于 B_slosh / B_ours；
hard 组更差并伴随 ACADOS_SOLVE_FAILED。
```

这批旧结果不应解释为“SPMPC slosh-aware 方法被否定”，更合理的解释是：当时实验口径中还混入了 slosh cost 尺度、hard cap 参数落地、求解失败和相位/模型一致性等问题。

## 2. 相位延迟有没有改变？

严格说：**没有把 delay 数值改成新的值。**

本次三方法正式 smoke 使用的是：

```text
DELAY_PHASE_MODE=fixed_closed_loop
DELAY_PHASE_LINEAR_DELAY_SEC=0.15
DELAY_PHASE_ANGULAR_DELAY_SEC=0.22
```

这和 20260702 成功 B0 的 fixed delay 口径一致。

真正改变的是实验策略：

```text
20260702：虽然 fixed_closed_loop 已启用，但当时还没有先做 B0 gate 来证明该口径是当前最干净 baseline；同时 hard/soft/参数口径问题混在一起。
20260705：先用 B0 gate 验证 fixed_closed_loop 0.15 / 0.22 最干净，再把三方法都固定在同一 delay 口径下比较。
```

本次 B0 gate 的关键结果是：

```text
B0 + fixed_closed_loop 0.15 / 0.22：GOAL_REACHED，projection p95 ≈ 0.0276 m，最干净；
B0 + delay off + 当前保守角向限制：TRACKING_UNSAFE_PROJECTION，失败；
B0 + delay off + 放开角向限制：GOAL_REACHED，但 projection p95 ≈ 0.089 m，不如 fixed 口径干净。
```

所以本次不是重新标定出一个新 delay，而是证明旧成功口径 `0.15 / 0.22` 仍然是当前最干净 baseline。

## 3. 指标口径：peak 只看 path progress 10%~90%

本文件中的 peak 采用：

```text
从 first ACADOS_OK 到 first GOAL_REACHED；
再按 /spmpc/debug/stage0_reference 的 s0 取路径进度 10%~90%；
在该区间内统计 /spmpc/slosh_height 的 max_10_90。
```

这样做的原因：

```text
1. 全程 max 容易被起步瞬态、终点停车、GOAL_REACHED 后残余段影响；
2. path progress 10%~90% 比按时间 10%~90% 更公平，因为不同方法速度不同；
3. 仿真中讨论的“运行过程 peak”更接近路径中段的可重复激励，而不是终端收敛瞬态。
```

## 6. 为什么两次结论不同？

### 6.1 关键差别一：本次先验证了 B0 baseline，旧结果没有把 baseline gate 前置

20260702 的分析记录指出：

```text
fixed_closed_loop phase compensation 已启用，但固定延迟值还未校准；
不能说明 0.15 / 0.22 一定是真实延迟。
```

本次先跑 B0 gate，明确得到：

```text
fixed_closed_loop 0.15 / 0.22 是当前最干净 baseline；
delay off 在当前保守角向限制下会失败；
delay off 即使放开角向限制，tracking 也不如 fixed 口径干净。
```

这让后续三方法比较不再混入“tracking 链路是否干净”的疑问。

### 6.2 关键差别二：本次只改 variant，旧结果里混入了更多问题源

本次正式三包只改变：

```text
planner_variant = B0 / B_slosh / B_ours
```

其他保持一致：

```text
v_ref=0.20
alpha_max=1.2
shared_linear_accel_max=0.6
shared_angular_rate_max=1.2
shared_angular_accel_max=1.2
fixed_closed_loop=0.15/0.22
hard constraint disabled
```

20260702 的记录中还同时涉及：

```text
hard 2.5mm 参数可能没有真正落到 solver；
hard 组大量 ACADOS_SOLVE_FAILED；
slosh/observer 与真实响应存在相位或幅值失配；
eta-dot penalty 尺度与仿真/codegen 口径可能不一致。
```

因此旧结果不是一个干净的“soft slosh 方法失败”实验，而是一个暴露多项工程口径问题的实物包集合。

### 6.3 关键差别三：旧分析记录指出 eta-dot 尺度问题，本次 slosh cost 更接近仿真口径

20260702 记录第 7 节指出过一个重要疑点：

```text
Python/codegen 默认口径：eta_dot_ref = omega_n * eta_ref；
C++ runtime 当时口径：eta_dot_ref = omega_n * h_ref；
而 eta_ref = h_ref / c_h。
```

这个问题会改变 eta-dot penalty 的实际尺度，使实物 runtime 的 slosh cost 与仿真口径不一致。其后果是：

```text
优化器以为自己在压 slosh modal dynamics，
但实际代价尺度可能与仿真不一致，
导致 B_slosh / B_ours 在实物 observer 上没有下降。
```

本次代码和诊断口径已经围绕该问题做了修正/确认，表现为：

```text
B_slosh / B_ours 的 slosh cost monitor 非零；
horizon peak p95 非零；
observer slosh p95 / max_10_90 相比 B0 下降。
```

所以本次更接近仿真中“slosh-aware soft cost 能压低模型晃动”的设定。

### 6.4 关键差别四：本次不跑 hard，避免 infeasible / 参数未落地污染结论

20260702 hard 组用本次口径重算仍然很差：

| hard run | GOAL_REACHED | slosh p95_10_90 | slosh max_10_90 | solve fail |
|---|---:|---:|---:|---:|
| `B_slosh_hard_2p5mm` | `46.72 s` | `2.421 mm` | `7.608 mm` | `64` |
| `B_ours_hard_2p5mm` | `44.83 s` | `1.795 mm` | `8.284 mm` | `57` |

这说明 hard 组主要是在暴露：

```text
hard cap 参数可能没有真正落地；
实际 hard limit 可能仍接近 1mm；
OCP 被压到不可行/难求解边界；
求解失败和命令执行恶化放大了 observer peak。
```

本次先不跑 hard，因此 soft 方法的规律更容易显现。

### 6.5 关键差别五：当前指标解释更严格，不把 B0 horizon=0 当成“B0 没晃动”

`B0` 关闭 slosh cost / horizon slosh prediction，所以：

```text
B0 的 horizon peak p95 = 0
```

这不是说 B0 没有激发液体晃动，而是说 B0 的 solver horizon 不预测/不优化 slosh 项。比较 `B0` 与 slosh-aware 方法时，主指标应该看统一 observer：

```text
/spmpc/slosh_height
```

本次分析明确以 `/spmpc/slosh_height` 的 p95/RMS/max_10_90 为主，不把 horizon=0 误判成 B0 更好。

## 7. 当前可以写进报告的谨慎结论

推荐表达：

```text
20260702 实物包中，B0 的 internal slosh observer 指标低于 B_slosh / B_ours，
但该批数据同时存在 hard 参数落地疑点、hard 求解失败、slosh eta-dot 尺度与仿真口径不一致、以及 phase compensation 仅启用但未通过 B0 gate 验证等问题。
因此该批结果更适合作为工程诊断证据，而不是方法有效性否定证据。

20260705 重新先完成 B0 fixed-path gate，并将三方法统一固定在 fixed_closed_loop 0.15/0.22、相同速度和 shared constraints 下，仅改变 planner variant。
在 path progress 10%~90% 的统计口径下，B_slosh 和 B_ours 的 /spmpc/slosh_height p95、RMS 和 max_10_90 均低于 B0，其中 B_slosh 降幅最大，B_ours 角速度命令最平滑。
这说明在当前更干净的实物 baseline 下，soft slosh-aware 方法恢复了与仿真一致的内部模型晃动降低趋势。
```

## 8. 还不能过度解释的部分

当前仍需注意：

```text
1. 本次三方法目前还是 N=1 smoke，不足以作为最终统计结论；
2. 当前结论限定为 SPMPC internal model evidence，不等于 RGB 真实液面真值；
3. B_ours 虽低于 B0，但不如 B_slosh 低，后续应看 N=3 是否稳定；
4. fixed_closed_loop 0.15/0.22 是当前最干净 baseline，但线速度 delay 离线估计可能更接近 0.18~0.20s，后续可单独做 delay refinement；
5. 不要在当前 N=3 中途改 delay，否则会破坏方法对比口径。
```

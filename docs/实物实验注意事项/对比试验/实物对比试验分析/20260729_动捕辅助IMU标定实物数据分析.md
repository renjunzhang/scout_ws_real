## 1. 核心结论

本轮共冻结三条关键 bag。`r02` 保留低速自动序列、控制命令和分段标签；`remote_r03` 使用硬件遥控形成独立的高幅值验证数据；新录制的 `planar_r03` 由修正后的长驻 publisher 运行，补齐了段长精确、可靠命令边沿和完整 postflight 证据。三者的用途不同，不应只用“`r03`”一个简称。

其中 `r02 + remote_r03` 已足以完成当前 anti-slosh 平面实验需要的以下标定与独立验证：

1. 确认 IMU `omega_z` 与动捕 yaw rate 的正负号一致；
2. 得到 IMU 与动捕的第一版时间对齐；
3. 核验 `omega_z` 的尺度；
4. 发现并量化 `/odom` 角速度相对真实角速度的系统性低报；
5. 对平面 `a_x/a_y` 做符号、时序和杠臂影响的初步核验。

最可靠的 `gyro-z` 稳态拟合为：

```text
omega_mocap = 1.001773 * omega_imu - 0.000297 rad/s

steady-state correlation = 0.999988
steady-state RMSE        = 0.001230 rad/s
effective IMU lag        = about +0.015 s
```

这里正延迟表示：同一真实运动出现在 IMU 输出中的时间比动捕晚。考虑 IMU 只有约 50 Hz，当前延迟不应宣称精确到 5 ms；工程上应记录为：

```text
Delta_t_imu_mocap = +0.015 s, uncertainty about +/-0.020 s
```

本轮同时得到一个对 S-MPCC 更重要的结果：稳态段中动捕与 IMU 基本一致，但 `/odom` 的角速度约比真值低 8.2%；从 odom 换算到动捕真值需要乘约 1.089：

```text
omega_mocap ~= 1.089 * omega_odom - 0.001 rad/s
```

因此，若当前 observer 直接用 `/odom` 的 `omega` 计算 `a_y = v * omega`，横向刚体激励会被系统性低估。`remote_r03` 又得到约 `1.1019` 的 odom-to-mocap 系数，说明低报问题真实存在，但修正量会随速度/滑移变化；不能把 `1.089` 直接冻结成永久常数。

当前不再运行同一版平面脚本，也不再补录硬件遥控 bag。原因不是数据不足，而是 `r02 + r03` 已形成 tuning/validation 分离；继续重复采集不会增加当前目标的关键可观测信息。

如果“标定好 IMU”指完整三轴陀螺仪加三轴加速度计标定，则本轮仍不够，缺少：

- roll/pitch 方向的角速度激励；
- 多个非共面静止重力姿态；
- 可观测原始零偏的 `/imu/data_raw`，或关闭当前角速度零值钳位后的数据；
- 数值化并归档的 `Tracker0 -> base_link -> imu_link -> tube_center` 外参。

因此当前决策是：


### 2.4 当前数据边界

```text
WIT 0x51 signed 16-bit register -> scale conversion -> linear_acceleration
WIT 0x52 signed 16-bit register -> scale conversion -> angular_velocity
WIT 0x53 device Euler angles    -> quaternion       -> orientation
```

ROS 驱动没有对 acceleration 或 angular velocity 再做低通、滑动平均或 Kalman 滤波。因此 `/imu/data` 中的 `ax/ay/gz` 可视作“设备寄存器直接换算值”，可以用于后续离线设计软件滤波器。仍需保留两个边界：

1. 没有单独保存串口原始字节或整数计数；

`/imu/data` 的 orientation、angular velocity 和 linear acceleration covariance 均填 0；这不能解释为“零不确定度”，只能解释为驱动没有提供可信 covariance。

## 4. 静止段与动捕稳定性

为避开标签发布和切换边界，本文选取两个 6 s 内部窗口：

```text
static_pre:   1785303434.0 ~ 1785303440.0
static_post:  1785303994.0 ~ 1785304000.0
```

### 4.1 陀螺仪静止输出

两个窗口中三轴角速度均为：

```text
mean = [0, 0, 0] rad/s
std  = [0, 0, 0] rad/s
```

但这不代表真实 bias 精确为零。非零角速度的最小步进为：

```text
0.001065264436 rad/s
```

三轴都严格落在该步进的整数倍上，静止寄存器值又全部为 0。ROS 驱动代码本身没有显式零值钳位，因此置零更可能来自 WIT 设备输出或设备内部处理。当前只能说“设备输出层的有效静止偏置小于约一个 LSB”，不能从这条 `/imu/data` 反推出更细的传感器原始 gyro bias。

### 4.2 加速度静止输出

| 窗口 | ax mean/std | ay mean/std | az mean/std | 单位 |
| --- | ---: | ---: | ---: | --- |
| pre | 0.201915 / 0.002912 | 0.009380 / 0.002860 | 9.835451 / 0.003178 | m/s² |
| post | 0.152584 / 0.003171 | 0.019983 / 0.002808 | 9.836040 / 0.002957 | m/s² |

pre/post 的 raw `ax/ay` 变化不能直接叫作 bias drift，因为车体 roll/pitch 也发生了小变化。若仅用 IMU 自己输出的 roll/pitch 做重力投影，得到的剩余均值为：

```text
pre:  [0.120493, 0.000537, 0.029144] m/s^2
post: [0.120558, 0.000367, 0.029462] m/s^2
mean: [0.120526, 0.000452, 0.029303] m/s^2
```

这说明 IMU 内部姿态和加速度在两个静止窗口中自洽，尤其 `x` 方向存在约 `+0.1205 m/s²` 的稳定剩余项。但该计算用到了同一 IMU 的姿态解算，存在循环依赖，不能替代动捕多姿态重力标定。

### 4.3 动捕静止噪声

## 5. `gyro-z` 与时间对齐结果

### 5.1 处理口径

本文使用：

1. `/imu/data.header.stamp`；
2. `/vrpn_client_node/Tracker0/pose.header.stamp`；
3. 对动捕 quaternion 提取 yaw 并 unwrap；
4. 用中心 `+/-0.10 s` 差分得到 yaw rate；
5. 再做中心 0.07 s 平滑；
6. 在实际角速度命令窗口及边沿附近搜索 `-0.30 ~ +0.30 s` 的 IMU 时间偏移；
7. 稳态尺度只在持续至少 2 s 的实际非零 `/cmd_vel.angular.z` 平台内部计算。

中心滤波不会引入单向群延迟；所有滤波窗口均围绕同一时间戳。

### 5.2 全局时延和动态一致性

使用 0.20 s 总差分窗时：

```text
best effective lag = +0.015 s
dynamic correlation = 0.996314
dynamic affine fit:
  omega_mocap = 0.994382 * omega_imu + 0.000018 rad/s
dynamic corrected RMSE = 0.020620 rad/s
dynamic MAE            = 0.012419 rad/s
```

动态 RMSE 主要集中在加减速和反转边沿，并受 IMU 内部滤波与动捕差分窗影响，因此尺度结论应优先看稳态平台，而不是用边沿 RMSE 反推 gyro scale。

更改动捕差分半窗后的最优时延为：

| 半窗 | 最优 IMU lag |
| ---: | ---: |
| 0.06 s | +0.015 s |
| 0.10 s | +0.015 s |
| 0.15 s | +0.015 s |
| 0.20 s | +0.005 s |

各逻辑运动段单独拟合的最优值位于 `-0.005 ~ +0.025 s`。所以当前最合理的发布口径是约 `+15 ms`，不应再追求低于一个 20 ms IMU 周期的伪精度。

### 5.3 稳态平台尺度

17 个持续至少 2 s 的正负角速度平台得到：

```text
omega_mocap = 1.001773 * omega_imu - 0.000297
correlation = 0.999988
RMSE        = 0.001230 rad/s
```

截距小于一个 IMU 角速度 LSB，因此当前没有证据支持额外写入非零 `gyro-z` bias。建议的第一版离线修正是：

```text
omega_z_calibrated = 1.0018 * omega_z_imu - 0.00030 rad/s
```

但在线使用前应保留可关闭开关，并用独立 bag 复核；当前尺度误差本来就只有约 0.18%。

典型平台中位数：

| cmd omega | IMU omega | mocap omega | odom omega | 单位 |
| ---: | ---: | ---: | ---: | --- |
| +0.20 | +0.213 ~ +0.216 | +0.211 ~ +0.217 | +0.198 ~ +0.201 | rad/s |
| -0.20 | -0.214 ~ -0.217 | -0.215 ~ -0.218 | -0.198 | rad/s |
| +0.25 | +0.270 | +0.268 ~ +0.271 | +0.248 ~ +0.249 | rad/s |
| -0.25 | -0.270 ~ -0.271 | -0.270 ~ -0.272 | -0.248 ~ -0.249 | rad/s |

IMU 与动捕共同说明真实车体角速度比 `/odom` 大约高 8.9%，等价于 `/odom` 比真实值低约 8.2%。这不是 IMU 自己的尺度异常。

### 5.4 IMU orientation 的辅助核验

从 pre 到 post 的净 yaw 变化：

```text
IMU orientation:  -11.7499 deg
mocap:            -11.9954 deg
difference:        +0.2455 deg
```

两者绝对 yaw 存在约 7.5 deg 的常量偏移。该偏移可能同时包含磁航向零点与安装朝向，不能仅凭本轮平面数据将它全部写成 `R_base_imu` 安装 yaw。

## 6. `/odom` 角速度与 S-MPCC 模型输入

同一批 17 个稳态平台上：

```text
omega_odom = 0.919993 * omega_imu + 0.000629 rad/s
omega_mocap ~= 1.089 * omega_odom - 0.001 rad/s
```

这意味着当前采用 odom-driven 状态构造时：

```text
a_y_model = v_odom * omega_odom
```

仅由 `omega` 低报就可能少约 8.2%。如果 `v_odom` 也有尺度误差，乘积误差还会继续变化。

当前可先离线重算两套输入，其中 B 只代表 `r02` 工况的 development 对照：

```text
A. 原始：        a_y = v_odom * omega_odom
B. development： a_y = v_odom * (1.089 * omega_odom - 0.001)
```

比较它们对现有 slosh observer、预测相位和 RGB 真值的影响。`remote_r03` 已独立确认 odom 低报，但得到约 `1.1019` 而非 `1.089`，所以问题已复核、单一常数尚未冻结；不直接修改正式在线 `/odom` 或底盘驱动参数。

## 7. `Tracker0` 能否先作为平面 base_link

在三段原地旋转中，用模型

```text
p_tracker(t) = p_pivot + R(yaw(t)) * r_pivot_to_tracker
```

拟合瞬时旋转中心，得到：

| 段 | Tracker0 到拟合旋转中心的 XY 半径 | 位置拟合 RMSE |
| --- | ---: | ---: |
| CCW hold | 9.0 mm | 1.30 mm |
| CW hold | 1.5 mm | 1.10 mm |
| direct reversal | 4.1 mm | 3.06 mm |

考虑轮胎滑移、地面不平和短弧拟合条件，这支持以下有限结论：

> `Tracker0` 的输出原点在 XY 上已接近小车原地旋转中心，可作为本轮平面 base_link 候选，误差量级约 1 cm 内。

但它还不能证明：

- `Tracker0` 的 z 与 ROS `base_link` 高度一致；
- 刚体 x/y 轴已与车辆 x 前、y 左严格对齐；
- `Tracker0 -> base_link` 的完整 6-DoF 外参已经冻结；
- 雷达圆盖中心的一枚 marker 已完成雷达 6-DoF 外参标定。

后续仍需把三枚 marker 球心、IMU 测量中心、试管中心和雷达参考点的相对坐标以米为单位写入标定文件。

## 8. 平面加速度能用到什么程度

### 8.1 原始激励范围

```text
ax: -2.268 ~ +2.632 m/s^2
ay: -2.091 ~ +2.254 m/s^2
az: +8.680 ~ +11.197 m/s^2
gz: -0.289 ~ +0.288 rad/s
```

其中加速度极值包含底盘振动、起停冲击和高频噪声，不能直接当作低频刚体加速度尺度。

### 8.2 初步动捕对比

仅作 development 诊断时，本文暂时假设：

```text
Tracker0 origin ~= base_link origin in XY
Tracker0 axes    ~= base_link axes
base_link -> imu_link translation = [0.100, -0.045] m
```

将该杠臂随动捕 yaw 旋转后，对 IMU 点位置使用相同的中心三阶多项式滤波，并将动捕二阶导数转回车体系。0.51 s 窗口下得到：

```text
ax correlation: 0.947
ay correlation: 0.827
```

如果不加入 `[0.100, -0.045] m` 杠臂，`ay` 相关系数只约 0.506，说明角加速度乘杠臂项在这组反转实验中不可忽略。

但把滤波总窗从 0.51 s 改到 1.21 s 后，尺度拟合会明显变化：

```text
mocap ax / IMU ax scale: about 0.66 ~ 0.73
mocap ay / IMU ay scale: about 0.50 ~ 0.60
```

该敏感性说明当前不能把上述值当作 accelerometer scale factor。主要限制是：

1. 短直线实际只有 0.75–0.80 s；
2. S 弯两侧严重不等时，横向激励不对称；
3. 动捕位置二阶微分对滤波窗口敏感；
4. `Tracker0 -> base_link -> imu_link` 外参仍是名义值；
5. 没有多姿态重力数据分离 bias、scale、安装倾角与交叉轴误差；
6. 车体振动在 IMU 上的局部幅值不会完整出现在低通后的动捕刚体位置中。

因此本轮 `ax/ay` 可用于：

- 确认主要轴符号；
- 标注起停和曲率反转的响应时序；
- 验证杠臂修正是必要的；
- 为下一轮滤波频带和实验幅值设计提供依据。

不能用于直接冻结完整 accelerometer scale matrix。

## 13. 当前 `base_link`、IMU 与雷达外参审计

> 本节记录 2026-07-29 现场运行时的只读审计结果。审计过程中没有修改 launch、TF、ROS 参数或外参文件。

### 13.1 ROS `base_link` 的当前语义

当前 `/odom.child_frame_id` 为 `base_link`，底盘节点持续发布 `odom -> base_link`。Scout 描述文件中前后轮和左右轮关于 `base_link` 对称，因此当前 ROS 语义下：

```text
base_link x: 车辆前方
base_link y: 车辆左方
base_link z: 车辆上方
base_link XY origin: 轮距/轴距意义上的车体运动中心候选
```

`odom -> base_link` 的数值是车辆在任意 odom 原点下的动态位姿，不是传感器外参；重启、里程计复位或轮胎滑移都会改变它，不能拿来定义 marker 的静态安装位置。

### 13.2 `Tracker0` 能否代表平面 `base_link`

在 `remote_r03` 中，用近直线稳态样本从动捕速度方向估计车体前向，得到：

```text
yaw_base - yaw_Tracker0 = -2.267 deg
sample residual std      =  0.630 deg
sample count             = 1574
```

在三段原地转中拟合瞬时旋转中心，`base yaw center -> Tracker0 origin` 的半径分别约：

```text
5.0 mm
7.4 mm
11.9 mm
```

位置拟合 RMSE 为约 `2.6~4.4 mm`；轮胎滑移造成各段结果变化。因此本轮可记录一个仅用于平面 development 的暂定关系：

```text
Tracker0 -> base_link, planar provisional:
  x ≈ +0.006 m
  y ≈ +0.004 m
  yaw ≈ -2.27 deg
  z = unknown
  XY uncertainty order ≈ 0.01 m
```

该平移方向以 Tracker0 坐标轴表达，是三个旋转中心拟合的量级估计，不是正式 hand-eye calibration。它还依赖一个现场条件：Nokov 中 `Tracker0` 的刚体输出原点确实设置在 M0 试管中心 marker；如果软件使用三点几何中心或其他自定义刚体原点，上式描述的是 Tracker0 刚体原点，而不是 M0 球心。

当前结论：

```text
Tracker0 作为平面 base_link proxy: PROVISIONAL PASS
Tracker0 与 base_link 完整 6-DoF 外参: NOT FROZEN
```

试管中心 marker 与 ROS `base_link` 的高度差不能由平面运动辨识，必须实测。

## 14. IMU 作为液体模型输入的最终判定

### 14.1 数据质量结论

从 `r02/r03` 可确认：

```text
IMU continuity:                 PASS, about 50 Hz
non-finite / timestamp regress: 0 / 0
static accel noise std:         about 0.003 m/s^2 per axis
gyro-z time/scale validation:   PASS across two bags
ax mocap correlation:           up to about 0.91
ay mocap correlation:           up to about 0.83
```

因此，数据质量足以支持从 IMU 构造“已经发生的试管刚体激励”候选。这里通过的是数据充分性，不是当前在线输入链 readiness；重力、杠臂、因果滤波和 held-out 幅相验证尚未冻结。该结论不等于允许把 `/imu/data.linear_acceleration` 原样直接送进模型。

### 14.2 当前代码实际使用什么输入

截至本次审计：

1. `slosh_monitor_node` 从 odom 构造：

   ```text
   ax = (v[k] - v[k-1]) / dt
   ay = v * omega
   alpha = (omega[k] - omega[k-1]) / dt
   ```

   再使用 `accel_filter_alpha=0.3` 的 EMA。

2. `scout_local_planner/SloshFeedback` 已有 IMU 接口，但默认：

   ```text
   use_imu_lateral_accel = false
   use_imu_yaw_rate      = true
   use_imu_alpha_z       = false
   imu_filter_alpha      = 0.3
   ```

   IMU 路径只读取 raw `linear_acceleration.y` 和 `angular_velocity.z`。`ay` 仅经过一次启动静止 bias、scale 和 EMA；没有姿态重力补偿，也没有 IMU 点到试管中心的杠臂换算。`ax` 仍来自 odom 差分。

3. 当前 SPMPC observer/predictor 仍主要使用 odom 的 `dv/dt` 与 `v*omega`。未来 horizon 内的液体输入由预测运动状态/控制产生，不消费未来 IMU。

所以当前不能仅将 `use_imu_lateral_accel=true` 打开后就把结果称为物理正确的试管横向加速度。

### 14.3 为什么 raw `ay` 不能直接使用

`remote_r03` 的两个静止窗口中：

```text
pre raw ay mean  = +0.02805 m/s^2
post raw ay mean = -0.03038 m/s^2
difference       = -0.05843 m/s^2
```

该变化主要来自停车姿态/重力投影，而不是液体真实横向激励。当前代码只在启动时估一次 bias；若使用 pre bias，post 会留下约 `-0.058 m/s²` 的虚假恒定输入，使液体模型产生不存在的平衡偏移。

此外，IMU 位于试管中心之外。角加速度和向心加速度在反转时不可忽略；`r02` 中加入名义 `[0.100, -0.045] m` 杠臂后，`ay` 与动捕的相关系数从约 `0.506` 提升到约 `0.827`。

### 14.4 正确的平面输入处理链

```text
/imu/data 原始设备解码值
  -> 保留 header.stamp
  -> IMU/动捕有效时差建模（约 15 ms）
  -> 坐标轴和静态 scale/offset
  -> roll/pitch 重力投影补偿
  -> 因果滤波，并显式记录群延迟
  -> IMU 点到 tube_center 的刚体杠臂换算
  -> a_tube_x / a_tube_y
  -> 液体状态 observer 的当前/历史输入
```

离线配对约定：

```text
IMU sample stamped t_imu <-> mocap truth near t_imu - 0.015 s
```

`gyro-z` development 候选：

```text
omega_z_cal = 1.001773 * omega_z_imu - 0.000297 rad/s
```

若 `r_IT` 表示 IMU 点到试管中心的杠臂，并将所有量表达在同一车体系：

```text
a_T = a_I + alpha x r_IT + omega x (omega x r_IT)
```

平面展开：

```text
a_Tx = a_Ix - alpha_z * r_y - omega_z^2 * r_x
a_Ty = a_Iy + alpha_z * r_x - omega_z^2 * r_y
```

若暂取 `tube_center = base_link` 且使用当前名义 IMU 平移，则：

```text
r_IT ~= [-0.100, +0.045, z_T-z_I] m
```

未知 z 在纯平面 yaw 杠臂项中不进入 XY 展开式，但 roll/pitch 和真实安装旋转仍会影响重力补偿。

### 14.5 滤波器不能只看“是否平滑”

当前默认 EMA：

```text
y[k] = 0.3*x[k] + 0.7*y[k-1]
```

在 `fs=50 Hz`、`f=5 Hz` 附近，其理论幅值增益约 `0.50`，相位约 `-43.5 deg`。也就是说，如果当前液体主模态约在 5 Hz，直接沿用 `alpha=0.3` 可能把关键激励减半并显著移相。

候选滤波器必须在 `r02` 选择、`remote_r03` 验证，并同时报告：

```text
static noise RMS reduction
0~model-band amplitude error
group delay / zero-crossing delay
mocap-referenced RMSE
peak and impulse behavior
```

离线零相位 `filtfilt` 只能制作参考标签，不能代表在线因果滤波。

单位为 `m/s^2` 和 `rad/s`。`ax/ay/az` 的静止噪声约 `0.003 m/s^2`，适合作为软件滤波器的噪声基线。pre/post 均值差同时含有停车姿态和重力投影差异，不能直接命名为 accelerometer bias drift。

两个正式静止窗内的 `gz` 共 5811 条，全部精确为 0；运动中的最小非零量化步进约为 `0.0010653 rad/s`。因此：

```text
运动段 gz 动态响应: PASS
静止亚 LSB gyro bias 可观测性: FAIL / 设备输出层置零
```

这是本 bag 最重要的数据边界，不是录制故障。它不影响平面动态响应、命令时序和后续因果滤波设计，但禁止用这条 `/imu/data` 声称已估计出亚 LSB 原始陀螺零偏。

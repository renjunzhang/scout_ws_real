# 20260731 G2S 重标尺与 IMU/odom 输入源三包预分析

## 1. 结论

基于 `u01/u02/u03` 三条同轨迹 Bsmooth G2S raw-RGB bag 的重新离线视觉结果，`processed_imu` observer 相对 odom observer 在三条 trial 上均更接近 RGB：

- 三条 motion-window 平均 MAE：odom `0.3656 mm`，processed IMU `0.2392 mm`；
- processed IMU 相对改善 `34.56%`；
- 单条改善分别为 `38.28% / 30.38% / 34.40%`，方向为 `3/3` 一致；
- 两种 observer 的时间覆盖率均为 `100%`，差异不是缺样造成的；
- processed IMU 与 RGB 的相关性在三条上也均高于 odom。

因此当前开发结论是：**后续 S-MPCC 内部模型输入优先选择 `processed_imu`**。

该结论仍是三条数据的 development 决策，不能替代预注册 G2S 的正式四条决策。操作员已经明确停止 G2S、不补 `u04`，因此本批冻结结论是：**允许 processed-IMU 进入 G2C development，但不得写成正式四条 G2S PASS，也不得据此放行 G3 或 40/64/88。**

## 7. 解释与限制

1. 两种模型相对 RGB 仍总体偏高，不能把“IMU 更接近”理解成模型已经完成绝对标定。
2. u02 中 processed IMU 的单次模型峰值不一定低于 odom，但它在整个 motion window 的 MAE、RMSE 和相关性更好；本结论是“时序整体更贴近 RGB”，不是“每个峰值都更小”。
3. 当前 RGB 峰值只有约毫米量级，应继续使用同一分辨率、曝光、容器几何和冻结 YAML，不能在后续 trial 中临时换阈值。
4. 正式协议仍需要 u04、正式 postflight、相同代码 revision 和相同 source/config hash；本批已由操作员停止，所以正式 gate 保持未完成，而不是用三包结果补写 PASS。
5. 当前 G2S runner 的历史默认标定不影响已停止的本批；若未来新开 G2S batch，必须重新预注册并显式冻结 v2 或更新后的标定，不能把本次 post-hoc relabel 当作原在线标量已经通过。

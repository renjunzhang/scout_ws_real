# 2026-09-17 B0 与加防晃液面高度对比

**已有录像数据中，这次“B0 框架 + 防晃”虽然成功到点，整段估算晃动却高于 B0。**
最大峰值出现在末段高速后急减速附近，不能用到点成功代表防晃效果通过。
本轮只分析已有 bag、绘图，没有追加仿真或调参。

> 后续已按用户要求补跑 B0 N40，见[统一 40 步后的对照](20260917_B0统一40步后的防晃对照.md)。相同 N 后峰值为 15.01 / 15.68 mm，仅差约 4.5%；下文保留此前 N60/N40 的原始对比，不再用其 2.84 倍差距直接评价防晃代价。

## 数据与计算口径

| 项目 | B0，无防晃 | B0 框架 + 防晃 |
|---|---|---|
| 录像目录 | `20260917_b0_video/case` | `20260917_raw_slosh_n40_video/capture/case` |
| 代码记录 | `75125f5f` | `03f1e345` |
| 预测步数 / 控制频率 | N60 / 30 Hz | N40 / 30 Hz |
| 求解器液体模型 / 权重 | 关闭 / 0 | 开启 / 5 |
| 参考 | 原始 S 路线 + cruise | 相同 |
| 到点时间（本次统一口径） | 26.964 s | 26.825 s |

两目录均位于 `/data/a/scout_sim_replacement/results/`。
使用同一任务及执行器适配脚本；`slosh`、`slosh_observer`、`execution_model`、`terminal`
参数完全一致。两个 commit 间控制器包内的源文件差异只有未被本次直接使用的原 Full profile，
但归档生成求解器的预测步数不同，不能视为严格的单变量对照。

**B0 不加液体代价，不代表没有液体高度数据。** 两次都运行独立于代价开关的 odom 液体观测器。
本次统一读取 `/spmpc/debug/slosh_observer_odom` 的有效消息，液体模型版本均为 1，
来源均为 odom；以状态时间戳去重、对齐任务下发时间。
高度采用 `modal_height_m × 1000`，单位 mm，逐样本核对满足：

```text
h_modal = height_coeff × sqrt(eta_x² + eta_y²)
height_coeff = 1.8179308248624537
```

两次均关闭抛物面附加项，`total_height_m == modal_height_m`，观测器没有重置。
该量是根据实际运动估算的模态液面扰动幅值，**不是独立液位传感器或流体仿真的实测液面**，
也不是 OCP 预测时域里的最大液面高度。

统计窗口为任务路径消息的 header 时间至首次 `GOAL_REACHED` 消息的 bag 时间。
只统计各自运输过程，不混入启动前静置、到点后停车或长时间超时静置。
两次有效高度样本分别为 1348 / 1341 个，约 50 Hz，曲线未经平滑。

- B0 最大峰值前出现动力学检查拒绝、停车 jerk 历史拒绝和预算停车。
  峰值时观测器输入的纵向加速度约 `-1.28 m/s²`。
- 加防晃的最大峰值前，速度接近 `0.8 m/s`；约 22.324～22.543 s 出现
  `STOP_ACTUAL_MOTION_BOUND_VIOLATION` / `STOP_JERK_HISTORY_INFEASIBLE`，随后速度陡降。
  22.573 s 高度达到 15.683 mm，模型输入纵向加速度约 `-3.35 m/s²`。
  这说明大峰值与末段急减速及停车干预对应，不能解释为正常跟踪段防晃代价单独导致。

即使单看前 15 s，加防晃的峰值 / P95 / RMS 也为 5.507 / 0.817 / 0.552 mm，
B0 为 4.904 / 0.796 / 0.487 mm，没有出现可据此宣称的整体降低。
前 15 s 只是补充时间窗，两车行驶进度并不完全相同，不把它当作严格配对的路径阶段。

## 判断与后续范围

当前证据支持“能沿 S 路线完成运输”，**不支持“当前这次已经比 B0 更防晃”**。
眼下应优先解决末段速度抬升及停车干预造成的急减速，单纯继续增加防晃权重没有验证依据。

## 约束核对与急减速链条补充

用户追问两次是否约束不同。重新对比完整 live_params 和所有实际执行 RTI 的快照后确认：
两次运动边界相同，实际速度范围 `[-0.002, 0.8] m/s`、角速度范围 `±1.2 rad/s`，
命令加速度 `±0.6 m/s²`、命令角加速度 `±1.2 rad/s²`、命令 jerk 上限 `1.0 m/s³`，
每拍加速度变化上限 `0.0333333333 m/s²`。区域、终点、时效和执行器参数也一致，
两次都关闭液体硬约束；加防晃采用软代价，不保证液面不超过某个上限。

不同的是预测时域：B0 为 `60 × 1/30 ≈ 2 s`，加防晃为 `40 × 1/30 ≈ 1.33 s`。
这是配置差异，不能把它说成加防晃时放宽了运动约束；其独立影响尚未隔离。

本次已进一步核实急减速的直接指令证据：任务 22.288 s、周期 692 正常发布
`0.78756 m/s`；22.322 s、周期 693 出现 `STOP_ACTUAL_MOTION_BOUND_VIOLATION`，
**未进入 OCP 求解，直接发布 0**，之后连续多个拒绝周期继续发 0。
ROS 失败分支调用 `publishZeroCommand()`，并非执行正常 OCP 的平滑减速序列。
因此求解中的命令加速度/jerk 限制不能保证失败分支切零时的实际减速度；
同一阶惯性执行器收到速度阶跃后，模型输入在液面峰值时达到约 `-3.35 m/s²`。
约 22.32 s 的这个直接触发事件是停车运动边界检查拒绝，不是该周期计算超时。

另外，`v_ref=0.25` 和末端 `0.18` 减速包络在此模式中用于速度参考，并非硬速度上限，
所以优化仍可能在末端升到接近 `0.8 m/s`。当前防晃软代价没有阻止这一速度轨迹，
随后失败分支的突变停车又激起更大的估算液面峰值。
应先处理末段速度抬升与拒绝后的减速衔接，再固定相同 N 比较防晃收益；
这不意味着应删除运动边界检查。本轮只核对已有数据与代码，未改逻辑或再跑仿真。

补充证据：同一对比目录下 `constraint_and_stop_audit.json`。

## 1. 编译与测试

本机为 ROS Noetic / Python 3.8.10 / CMake 3.16.3，CasADi 3.7.2；acados 为
`v0.5.4-7-gdc6668f85`。依次重新生成 B0/slosh 求解器，并整体生成 ROS 消息、编译节点。

本轮修复四处移植问题：

1. legacy direct-omega 后端的局部 `fitReferencePolynomials` 与新共享函数发生重载歧义；
   局部函数改名，保留该历史后端原有计算。
2. 四个没有自带 `main` 的 catkin 测试显式链接 `gtest_main`。
3. CTest 3.16 不支持 `--test-dir`，原脚本会显示 `No tests were found` 而退出成功；
   改为进入实际构建目录再执行 CTest。
4. 上层任务的字典合并使用 Python 3.8 可用的写法。

| 检查 | 结果 |
| --- | --- |
| ROS1 节点及消息编译 | 通过，真实 B0/slosh acados 后端启用 |
| ROS gtest | 21 个程序、236 个独立 testcase，0 失败 |
| native 真实 acados CTest | 19/19 程序通过 |
| 计划/后缀/快照/旋转液体/预测高度/录制合同 Python 检查 | 44/44 通过 |

`catkin_test_results` 打印的 472 是 XML 层级累计数；逐个 `<testcase>` 核对为 236，
不把两者当成两批测试。pytest 仅安装到本批 `/tmp/.../test_deps`，未改系统 Python。

原工作区存在不同 catkin 工具的构建标记，本轮使用独立构建前缀：

## 2. Gazebo 集成诊断

入口为 [`scripts/run_trajectory_gazebo_smoke.py`](../../../../../scripts/run_trajectory_gazebo_smoke.py)，
复用隔离环境的 `launch_proxy_sim_localization_env.sh`，另外启动当前分支的
`trajectory_mpcc.launch`。未修改外部 world、地图、launch 或脚本。

- 地图显式使用 `proxy_world_manual_saved_20260611_154348.pbstream`。
- 独立端口为 ROS 11892 / Gazebo 11926；逐 case 全新启动，前后均核对为空。
- 预等待 30 s，录包先于任务发布，观察最多 60 s 仿真时间，退出后等待 30 s。
- S 路线沿用 amplitude ratio 0.18、0.25～1.20 m、left、3 次平滑，map 终点 `(5,0,0)`。
- 路线从本批初始 map 位姿约 `(0.0197,-0.0093,0.00144)` 冻结，118 点，长 5.8092 m。
  Gazebo world 出生点 `(-4,0)` 与 map 原点不能直接混用。
- 开发任务 deadline 45 s，上层 transport duration 40 s，停车评价尾窗 5 s。
  这些是本批开发条件，未冻结为正式效果比较协议。
- 仿真专用覆盖将 `frames/robot_base` 设为真实 `/odom.child_frame_id=base_footprint`。
  保留生产默认 30 Hz、最多 5 次 RTI、`max_prediction_defect=1e-4` 和发布时效门。

**执行模型存在已知失配。** 当前生成模型固定 5/10 拍延迟并使用实车 FOPDT 参数；
现有 Gazebo 是直接平面速度插件加限加速 guard。本批显式记录
`actuator_plant_matches_controller=false`，所有运行 `formal=false`。
这批结果用于接口与在线执行诊断，不能报告为公平防晃性能对比。

初次冻结区域沿用了 TF `map<-odom` 对 world 边界的映射，未证明该 odom 原点等于
Gazebo world；该矩形只保留作本批模型/启动诊断条件，不能作为已验收的场地走廊。
最终入口改为静止时配对 `/gazebo/model_states` 的 world 位姿与 map TF，显式记录
world-to-map 变换；此项尚未重新跑运输用例。后续新批次必须重新冻结任务、区域和计划。

### 最终两例的失败证据

| 指标 | B0：raw_r03 | Full：full_r02 |
| --- | ---: | ---: |
| `PREDICTION_DYNAMICS_VIOLATION` 求解次数 | 2 | 11 |
| 完成的 RTI 次数 | 每拍 1 次 | 8 拍 1 次、3 拍 2 次 |
| 动力学最大余差范围 | 0.02209～0.02582 | 0.0004935～0.007117 |
| 当前接纳阈值 | 0.0001 | 0.0001 |
| 后续预算耗尽接管停车 | 1 次 | 1 次 |
| 非零 `/cmd_vel` 消息 | 0 | 0 |
| 最终任务状态 | TASK_DEADLINE_MISSED | TASK_DEADLINE_MISSED |

上述误差是完整 24/28 维状态分量的最大绝对动力学缺陷，不是单一位置误差或液面高度。
失败发生在尚未发出非零命令时，不能将其归因为车辆已经受到执行器模型失配影响。
Full 前一例还记录了状态外推范围失败；全部状态计数保留在 JSON 中。

全观察窗的周期耗时包含大量静止停车周期，不能用它的低 P95 宣称有效跟踪达到 30 Hz。
没有成功运输，因此也没有本批可用的 IMU 高度收益、停车残余或运输效率比较结论。

使用本机新构建的 `geometry_trial`，同一冻结 S 任务与上层计划，固定 5 次 RTI、没有在线
时间预算；沿用 native 的显式配置与理想液体状态反馈。它不是 ROS 配置的逐叶复现，也不是
独立液体 plant。

| 指标 | raw / B0 | planned_slosh / Full |
| --- | ---: | ---: |
| 完成 | 否 | 是 |
| 完成时间 | — | 9.733 s |
| 失败 | 43 s，TASK_GOAL_CONSTRAINT_VIOLATION | 无 |
| 最后位置误差 | 0.000433 m | 0.01106 m |
| 最后朝向误差 | 0.62490 rad | 0.07711 rad |

下层闭环改变运动后，计划峰值不能代替实际闭环评价。

Full 在充分迭代的模型内完成任务，但在线周期预算下尚未启动成功。B0 的末端朝向失败仍需
单独处理。两者耗时不匹配且 B0 未完成，表中峰值只作失败诊断，不参与防晃收益统计。

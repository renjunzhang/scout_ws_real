# 2026-09-17 Full 预算恢复单次验证

**预算不足后永久不再求解的问题已修复，但 Full 仍未跑通。**
本次 127 次预算拒绝之后都再次执行了 RTI，成功接纳 163 次 OCP 命令；
频繁预算短缺和结果过期导致反复停车，最终任务超时。

## 本次修改

- 预算不足使用独立的临时停车状态；当前停车尾段安全、实测速度低于停车门限、命令及 FIFO 清零后允许重试。
- 重试从一次新的 RTI 耗时测量开始，避免旧耗时尖峰永久阻止求解；过期预算仍不启动 RTI，后续迭代和最终命令发布继续检查时效。
- 数值求解失败、终点停车和区域安全停车仍保持原有锁存；任务时钟、历史、动力学、停车尾段检查保留。
- 给开发验证入口增加可选 `--identified-actuator`：仅在本次独立环境中停止原速度 guard，由工作区节点按相同 delay/tau/gain 输出到原平面驱动，输出频率 120 Hz。外部地图、world、launch 和脚本未修改。

代码提交：`aead0eaa`。原来的 30 Hz、60 步、任务、计划及 6 ms 发布预留不变，
未重新生成求解器，也未扫参数或重跑 B0；只执行一次 Full。
`delay_phase` 保持关闭。

## 验证结果

ROS 节点增量编译通过；`test_solver_failure_stop`、`test_terminal_controller`、
`test_control_cycle_contract`、`test_replay_diagnostics` 四组针对性测试通过。
执行器节点的延迟阶跃、命令切换及超时响应三项解析测试通过。

cycle 23 预算拒绝，24 恢复 RTI；cycle 27 预算拒绝，33 再次接纳 OCP。
127 次恢复的首次耗时估计均为零，确认走到了新的重新测量分支。
后段 cycle 1327 出现一次真实 `ACADOS_SOLVE_FAILED_4`，按原策略锁存停车；
同一周期发布状态为 `COMMAND_RESULT_EXPIRED`，不能只查最终状态而漏掉求解失败。

按实际命令发布时间独立计算解析 FOPDT 响应，与带时间戳 odom 比较，线速度误差
P95 为 0.000117 m/s、最大 0.000829 m/s。参数核对相同，原驱动发布者已被唯一的
适配节点替代；这次低速记录支持执行器适配生效。角向激励很小，不能据此声称
全工况模型一致；ROS 传输及 120 Hz 保持误差仍在，未引入独立液体真值模型。

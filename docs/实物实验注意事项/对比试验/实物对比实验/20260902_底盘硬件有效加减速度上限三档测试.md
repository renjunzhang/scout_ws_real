# 底盘硬件有效加减速度上限三档测试

> 日期：2026-09-02
>
> 协议：`MOCAP_HARDWARE_ACCEL_LIMIT_V2`
>
> 性质：三档各一包的 development 硬件能力测试，不启动 MPC、路径跟踪、slosh 或相机

## 1. 要回答的问题

直接向最终 `/cmd_vel` 依次发送三档线速度阶跃/短脉冲，让底盘驱动器自行给出当前条件下能够实现的加速和制动过程，并由 NOKOV、IMU、odom 交叉测量。

本测试得到的是：

```text
当前高速挡 + 当前电量 + 当前负载 + 当前地面
0.8、1.5 和 3.0 m/s 三档命令激励下的底盘与驱动器整体有效加减速度
```

它不是电机堵转转矩对应的理论极限，也不能代表所有电量、地面和负载。对 SMPCC 来说，整车实际可执行能力比脱离驱动器的电机理论值更有意义。

## 2. 为什么用速度阶跃

测试脚本不人为指定加速度，而是直接制造速度误差。底盘内部速度控制器会按自身允许的过程加速；实际速度曲线的斜率就是需要测量的能力。

冻结为三档，每档只录一包，必须按顺序执行：

```text
H01：零速 3.0 s -> 0.8 m/s 保持 2.0 s -> 零速记录 4.0 s
H02：零速 3.0 s -> 1.5 m/s 保持 2.0 s -> 零速记录 4.0 s
H03：零速 3.0 s -> 3.0 m/s 仅保持 1.0 s -> 零速记录 4.0 s
```

H01 是安全基准；H02 检查更大的速度误差是否还能提高实际加速度；H03 是满量程短脉冲，只用于激发最大加速度，**不要求车辆达到 3.0 m/s**。三档非零命令阶段按“命令速度×时长”计算的保守位移上界分别为 `1.6 m`、`3.0 m`、`3.0 m`，其后仍需制动空间。

当前场地约 `7.5 m`，建议 H01、H02、H03 的正前方连续净空分别不少于 `4 m`、`6 m`、`7 m`。每包结束后必须停车、回到同一起点并确认制动正常。只有 H01、H02 的结果和人工观察均正常，才允许 H03；H03 不是额定极速或持续高速测试。

判断是否接近上限时，比较三档的 NOKOV/odom 有效加速度和加速度 P95：如果提高命令档位后实测加速度不再明显提高，说明当前底盘与驱动器已经进入有效饱和区。不要用单点噪声峰值判断上限。

## 3. 自动录制与分析

录制话题：

```text
/cmd_vel
/mocap_hardware_accel_limit/cmd_vel_stamped
/vrpn_client_node/Tracker0/pose
/imu/data
/odom
/scout_status
```

结束后复用冻结的速度阶跃分析，自动输出：

- NOKOV 和 odom 的速度、加速度及启动上升段拟合图；
- IMU 前向加速度图；
- 加速与制动的起效时间；
- `10%～90%` 有效加速度和 `90%～10%` 有效减速度；
- 平滑加速度曲线的 P95、峰值；
- 零命令后的制动时间、停车距离和横向偏移。

判断硬件有效能力时，以三路一致的加速度平台或高分位范围为主。NOKOV 二阶差分的单点峰值容易放大噪声，不能把一个最高尖峰直接写成硬件上限。

## 4. 运行前条件

- Scout 挡位开关确认在高速挡；
- 电量和负载具有代表性，并记录测试时状态；
- 车辆朝向场地长边；H01/H02/H03 分别确认至少 `4/6/7 m` 正前方连续净空；
- 遥控器急停在手，出现方向错误、异常加速或传感器故障立即停车；
- 底盘驱动、NOKOV、`/imu/data`、`/odom` 正常；
- 停止 MPC 和 ROS 遥控节点，确保没有其他节点发布 `/cmd_vel`。

如果手持遥控器本身通过 ROS 持续发布 `/cmd_vel`，它会与测试命令冲突，脚本将拒绝启动。安全遥控必须能够在底盘硬件层覆盖或急停，而不是与测试脚本并行争用同一 ROS 话题。

## 5. 执行命令

先校验 H01，不动车：

```bash
cd /home/geist/scout_ws

ATTEMPT=01 \
HARDWARE_TEST_ID=H01 \
bash src/scout_apps/control/spmpc_local_planner/scripts/run_spmpc_mocap_hardware_accel_limit_trial.sh
```

确认校验输出中的速度、时长、目录和场地条件后，正式执行 H01：

```bash
cd /home/geist/scout_ws

ATTEMPT=01 \
HARDWARE_TEST_ID=H01 \
VALIDATE_ONLY=false \
ARM_MOTION=YES \
CONFIRM_TEST_SETUP=YES \
bash src/scout_apps/control/spmpc_local_planner/scripts/run_spmpc_mocap_hardware_accel_limit_trial.sh
```

H01 正常结束并回到起点后，把 `HARDWARE_TEST_ID` 改成 `H02`；H02 正常结束并确认制动距离安全后，再改成 `H03`。其余命令不变。不要一次启动三包，也不要跳过前一档直接跑 H03。

这是突加速测试：敲下回车前急停必须已经在手，人员不得位于车辆前方。脚本异常退出或按 `Ctrl+C` 时会立即重复发布零速度，但不能替代硬件急停。

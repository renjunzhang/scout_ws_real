## 1. 总体策略

实验按同一冻结 release 分阶段采集：

| 阶段 | 预注册正式矩阵 | 累计矩阵单元 | 主要目的 | 决策 |
| --- | --- | ---: | --- | --- |
| 阶段 0：参数与工具冻结 | C1、独立 H0 pilot 路径，B0、B_smooth、`w_slosh=1/2/5` 各 3 次；随后执行 Smooth-match pilot、视觉/同步和 replay smoke | **0** | 无 RGB 地完成模型侧权重筛选，并冻结全部正式执行条件 | 全部冻结门槛通过后才允许开始正式 40 次 |
| 阶段 I：核心机制包 | 高风险路径、名义容器三方法 24 次；等完成时间 16 次 | **40** | 检查真实液面是否改善，并排除普通平滑和整体减速解释 | 40 次通过阶段门槛后才扩展 |
| 阶段 II-A：双路径扩展 | 名义容器、低风险路径三方法 24 次 | **64** | 检查效果是否只存在于高风险 S 弯 | 阶段 I 通过后执行 |
| 阶段 II-B：跨容器扩展 | 已预先冻结的第二容器、高风险路径三方法 24 次 | **88** | 检查只更新容器模型参数、不重调权重时的有限迁移 | 阶段 I 通过后执行；C2 本身必须在首条正式 trial 前冻结 |

权重 pilot、开发 smoke、相机标定、路径冻结、Smooth-match 调速 pilot、C2 选型和 replay 工具验证均不计入 40/88 次。

这里的 40、64 和 88 表示预注册正式矩阵单元，不是机器人现场的全部运动次数。pilot、smoke、每日 sentinel、与方法无关的采集故障补采均单独计数并完整报告。

40、64 和 88 次只是同一冻结 release 的阶段性证据包，不是调参或升级方法的节点。首条正式 trial 前必须一次性冻结 `FREEZE_ID` 所绑定的软件 revision、液体动力学与状态传播、代价结构与权重、三方法差异、H0/H1/L1、C1/C2 参数、执行限制、视觉/同步配置、随机表和分析规则。C2 的正式 24 次可以留到阶段 II-B 采集，但不得根据前 40/64 次结果重新选容器或修改参数。

若最终停在 40 或 64 个正式矩阵单元，摘要、贡献、RQ、结果表和结论必须同步删除或降级尚未获得支持的跨路径或跨容器主张。

旧 0705/0706 的 N=3 数据只作为 development-only/pilot，不并入新的正式 `n=8`。

## 4. 权威跟踪路径

### 4.1 正式路径冻结原则

历史脚本采用“固定终点、每次从当前起点重新生成路径”。该方式适合调试，但不同 run 的几何路径会随起点误差改变，不适合新的正式 paired comparison。

正式实验改为：

1. 在地面起点位置和航向标记处生成候选路径；
2. 验收路径长度、曲率、起终点和安全走廊；
3. 保存权威 JSON、路径图、曲率图和 SHA-256；
4. 正式 run 使用 `fixed_global_path_runner.py --mode replay` 发布同一 JSON；
5. replay 前执行 `0.05 m/0.10 rad` 起点门控；
6. bag 中继续记录实际 `/scout/global_path_fixed`，分析时核对其 hash/几何是否与权威文件一致。

建议 freeze artifact 目录：

```text
docs/实物实验注意事项/对比试验/实物对比实验/freeze/
├── freeze_manifest.template.yaml   # 协议冻结模板，不代表执行已 GO
├── freeze_manifest.yaml            # 全部门槛通过后才生成的只读执行 manifest
├── paths/
│   ├── H0_weight_pilot.json          # 本协议唯一的参数 pilot 路径
│   ├── H1_P2_s_curve.json
│   ├── H1_P2_s_curve_geometry.csv
│   ├── L1_gentle.json
│   └── L1_gentle_geometry.csv
├── configs/
├── randomization/
└── calibration/
```

正式 runner 在采集前必须支持 replay 已冻结路径；不得在正式 run 中静默退回 template regeneration。

权重 pilot 固定只使用不进入正式主表的 `H0_weight_pilot`，不得在同一批次切换到 H1。H0 必须与 H1 使用相同 S-curve 激励家族和曲率符号反转结构；两者的长度、最大绝对曲率、曲率变化率和积分绝对曲率在查看 pilot 排序前统一计算并归档，由路径 smoke 确认 H0 能激发同一类机制且仍满足安全走廊。现场工作文件固定为 `/home/geist/fixed_paths/real/<DATE>_spmpc_parameter_pilot/H0_weight_pilot.json`；验收后把只读副本、几何统计和 SHA-256 归档到上述仓库 `freeze/paths/`。

### 4.2 高风险路径 `H1`

沿用已在实物上验证的 P2 fixed S-curve 作为候选：

| 字段 | 候选冻结值 |
| --- | --- |
| 路径 ID | `H1_P2_s_curve` |
| frame | `map` |
| 起点 | 现场地面起点标记的 map 位姿，待冻结 |
| 终点 | `x=-5.424, y=-4.736`；yaw 只作记录，不由模板几何强制 |
| template | `s_curve` |
| start heading | `current`，生成时车体必须对齐起点航向标记 |
| amplitude ratio | `0.18` |
| min/max amplitude | `0.25/1.20 m` |
| side | `left` |
| smoothing | Chaikin `3` 次 |
| spacing | `0.05 m` |

该路径用于全部 40 次核心机制包和 C2 跨容器扩展。

路径区段在查看正式 RGB 结果前，根据冻结路径的曲率图确定：

| 区段 | 物理含义 | 初始建议边界；最终以曲率图冻结 |
| --- | --- | --- |
| `Z1` | 起步直线加速 | `σ≈0–0.15` |
| `Z2` | 第一持续曲率转弯 | `σ≈0.15–0.40` |
| `Z3` | S 弯曲率符号反转 | `σ≈0.40–0.65` |
| `Z4` | 退出转弯并重新加速 | `σ≈0.65–0.85` |
| `Z5` | 终点减速、制动和到达后观察 | `σ≈0.85–1.00`，另加到达后 `5 s` |

最终区段边界只能根据路径几何和控制逻辑调整，不能根据哪一段 RGB 差异最大来选择。

### 4.3 低风险路径 `L1`

完整 88 次方案增加一条低风险路径：

| 字段 | 设计 |
| --- | --- |
| 路径 ID | `L1_gentle` |
| 起终点 | 与 `H1` 使用相同起点标记和终点，控制总位移和 terminal 条件 |
| 候选模板 | `straight`；若当前起点航向与终点弦线不完全一致，生成器的 cubic blend 形成缓慢转向 |
| spacing | `0.05 m` |
| 目标特征 | 无曲率符号反转；最大曲率和曲率变化率显著低于 `H1` |
| 用途 | 检查 S-MPCC 在简单路径上是否造成不必要的时间或跟踪损失 |

`L1` 必须和 `H1` 一样保存权威 JSON、曲率统计和 hash。若 `straight` 候选仍出现过大初始弯折，应移动终点或调整起点航向标记后重新冻结，而不是在正式数据中临时换路径。

### 5.1 权重 pilot 中唯一允许变化的参数

P3B 只允许改变 `B_slosh` 的 `w_slosh`。下面内容在整个参数 pilot 中保持一致：

```text
v_ref=0.20
v_max=0.8
omega_max=1.2
a_max=0.6
alpha_max=1.2
horizon=60
dt=0.0333333333
rho_eta_dot=0.3
delay=fixed_closed_loop 0.15/0.22
terminal/gate/limiter/fallback 相同
C1、液深、安装和冻结路径相同
RealSense 随基础栈保持启动；RECORD_RGB=false，不启动在线视觉液面节点
standalone /slosh/* monitor 全 15 次强制启动、使用同一配置 hash，并在每个 trial 前 reset
```

P3A 必须在查看 P3B 候选排序前，为 P4 输出 B_smooth 的数值安全速度上下限。本文不预填或推断上下限；endpoint 候选、每个 endpoint 的固定重复数和验收门槛必须先写入 manifest 草案。两个 endpoint 均使用 P4 将采用的冻结 `H1 + C1`、B_smooth 配置、起点/静稳规则和公共执行链；每个 endpoint 的全部预注册重复都必须同时通过 success、tracking、solver、solve-time、fallback、执行干预、安全和数据完整性门槛。上下限必须是实际完成 endpoint smoke 的速度，且满足下限严格小于上限；不得越过实测 endpoint 外推。

P3A 通过后，以下字段必须写入只读 manifest；任一字段为空时 P4 保持 NO-GO：


endpoint 的方法无关采集故障只能按第 12 节使用 `r02`；solver、tracking、fallback、安全、超时或其他性能失败不得补跑成通过，并使 P3A/P4 及正式采集保持 NO-GO。P3A 的 endpoint 尝试单独报告，不改变 P3 的 15、P4 的 12 或正式 40/64/88 个矩阵单元。

### 5.3 权重选择规则

B0 和 B_smooth 已关闭控制器液体状态，因此缺失或恒为零的控制器内部 `/spmpc/slosh_height`、`H_modal` 或 horizon 不能用于估计 `delta_model`。P3B 的 15 个矩阵单元必须从第一条起统一启动同一个方法无关 standalone `/slosh/*` monitor，使用同一模型参数、配置 hash、topic/单位和窗口，并在每个 trial 前成功调用 reset；任一矩阵单元在第 12 节允许的同 segment `r02` 处理后仍缺少 monitor、reset 证据或配置一致性时，本轮权重冻结 NO-GO。

在查看候选排序前，先冻结 tracking、完成时间、实时性和执行层干预阈值，并用 B0/B_smooth 各 3 次的 standalone monitor 重复性冻结模型侧实用等价容差。对每个预注册高度指标 `q∈{peak,RMS,post-arrival RMS}`，固定计算：

```text
delta_repeat,q = max(
  max_b(q_standalone(B0,b))      - min_b(q_standalone(B0,b)),
  max_b(q_standalone(Bsmooth,b)) - min_b(q_standalone(Bsmooth,b))
)

delta_model,q = delta_repeat,q
```

如果在 P3 开始前已经预注册独立 noise/repeatability smoke 作为补充来源，则其数据、指标、窗口、估计脚本和组合规则必须预先写入 manifest，统一采用 `delta_model,q=max(delta_repeat,q,delta_noise,q)`；否则 manifest 固定 `independent_noise_smoke_enabled=false`。不得在看到候选排序后临场选择 standalone 重复性或独立 smoke 中更有利的来源。standalone proxy 与 S-MPCC 在线高度指标之间的单位换算和尺度映射也必须在排序前冻结并归档。

S-MPCC 候选的模型响应和机制排序仍使用其自身在线 `/spmpc/slosh_height`、完整预测 horizon、第一控制动作以及 block-paired 指标；standalone monitor 提供方法无关的重复性底噪和全 15 次一致性旁证，不以 B0/B_smooth 的缺失/零控制器信号替代。随后按四层决策：

1. **准入：** success、tracking、solve time/solve-budget overrun、observed inter-arrival gap proxy、fallback、执行层和数据完整性全部合格；
2. **机制：** Z2/Z3 中完整 horizon、optimized first action 或局部速度/激励分配发生稳定变化，不能只是全程统一降速；
3. **模型响应：** block-paired 内部 `H_modal`/horizon peak、RMS 和 post-arrival RMS 改善方向稳定，不由单个 trial 独占；
4. **最小拐点：** 相邻候选在对应指标 `q` 上的额外模型侧收益低于冻结的 `delta_model,q` 时选择较小权重；更大权重只有在提供明确额外收益且不恶化任务/执行指标时才能入选。

不得只看 cost breakdown 或单次最小值选权重；必须同时检查内部高度时序、完整预测 horizon、第一控制动作、tracking、完成时间和执行层干预。该步骤得到的是 `model-side frozen weight`，不是对真实液面高度改善的独立物理证明。

本协议不使用候选权重之间的 RGB 排名选择 `w_slosh`。P0/P8 的 RGB 数据只用于冻结视觉链、同步、噪声、clipping 和路径激励准入，不得据此重新排列候选权重。P3 得到的是 `model-side frozen weight`；正式 RGB 是独立物理验证，不能在正式结果产生后反向调权。

### 5.4 Smooth-match 固定 12 个矩阵单元 pilot

P4 在最终 `w_slosh` 冻结后执行，只使用完成时间，不录制或查看 RGB。先利用 P3 三个 block 中 B_smooth 与最终 S-MPCC 候选的完成时间，按预先冻结的规则计算中心值：

```text
r   = median_b(T_Bsmooth,b / T_Bslosh-final,b)
v_c = round_to_0.005(0.20 * r)
M-  = v_c - 0.01 m/s
M0  = v_c
M+  = v_c + 0.01 m/s
```

三个候选必须互不相同并全部位于 manifest 已冻结的闭区间 `[methods.smooth_match_safe_v_ref_min, methods.smooth_match_safe_v_ref_max]`（单位 m/s）；不满足时 P4 NO-GO，不得现场裁剪候选。P4 使用已经冻结的 H1、C1、最终 S-MPCC 和全部公共控制条件，固定 12 个 pilot 矩阵单元：

| P4 block | 顺序 |
| ---: | --- |
| 01 | S-MPCC → M- → M0 → M+ |
| 02 | M0 → S-MPCC → M+ → M- |
| 03 | M+ → M0 → M- → S-MPCC |

每个条件出现 3 次且占据 3 个不同位置。所有 bag 使用 `PF_SM_H1_C1_<METHOD>_b<BB>_r01`，不进入正式 `n=8`。对每个候选计算

```text
R_j = median_b(T_j,b / T_S-MPCC,b)
e_j = abs(R_j - 1)
```

一次性选择规则：S-MPCC 和候选必须 `3/3` 完成且通过 tracking、solver、fallback 和数据完整性门槛；在合格候选中选择 `e_j` 最小者，精确并列时依次选择 M0、M-、M+；只有 `e_j≤5%` 才冻结为 Smooth-match。若无候选通过，正式 40 次保持 NO-GO，不得追加候选或性能重复；方法无关采集故障仅按下段和第 12 节处理。需要另建新版 P4 协议时，旧 12 个矩阵单元及其全部物理尝试永久保留为 development pilot。

P3/P4 只允许对与方法无关的采集故障使用 `r02`，原尝试和原因必须保留并单独计入物理尝试总数。性能、solver、tracking、fallback、timeout、方法相关命令异常或 safety failure 均不得补成成功，并直接使本轮 P3/P4 参数冻结及正式采集保持 NO-GO。`r02` 必须在原 pilot block 的同一 `block_segment_id` 和冻结环境阈值内完成才保留配对资格；跨时段只能标记为 split-block，不能用于模型侧配对选权或 Smooth-match 主匹配。若因此不足 3 个完整配对 block，不得通过追加零散重复凑满；只有另建并预注册新版 pilot 协议后才能重新开始。

1. 核对 block、方法、路径 hash、配置 hash 和 Git revision；
2. 检查容器、液深、中心安装、相机固定和安全空间；
3. 机器人回到起点门控范围；
4. 机器人和容器停止后等待 manifest 中冻结的固定静置时间 `T_SETTLE`；可选叠加 monitor-only `/slosh/height` 门，但它不是 K6 的 `H_vis`；

6. replay 权威路径，启动随机表指定的方法；
7. 完成路径或记录方法失败；
8. 到达/停止后继续记录 `5 s`；
9. 保存 run metadata、异常说明和结束时电池/环境记录；
10. 快速检查数据完整性，但不查看方法间正式 RGB 排名后改变后续顺序。

`H_vis` 不作为在线控制信号，也不是 recorder 直接保存的正式话题。每次 trial 后由冻结脚本从 raw RGB 离线导出，并回查运动前连续 `2 s` 是否低于冻结静止阈值、30 帧零点是否全部早于 `t_move`；不通过时标记为预先定义的 visual-start QC failure，不得把不满足静稳条件的曲线当作有效液面比较。

## 7. 40 次完成后的扩展门槛

只有下面条件共同满足，才扩展到 64/88 次：

| Gate | 检查内容 | 通过原则 |
| --- | --- | --- |
| G1 协议完整性 | 40 个正式矩阵单元及其全部物理尝试、冻结顺序、配置/path hash、失败和补采记录 | 无未解释配置漂移；旧 pilot 未混入；split-block 已单独标记 |
| G2 视觉有效性 | RGB 有效率、同步、静止噪声、缺帧和 ROI | 不存在方法相关的系统缺失；高风险路径信号明显高于噪声 |
| G3 执行一致性 | raw/post-gate/published command 和 `r_int` | 执行层未长期覆盖 OCP 差异；阈值在看结果前冻结 |
| G4 RQ1 核心方向 | B_slosh − B_smooth、B_slosh − B0 的 block-paired `H_vis,p95` | `H_vis` 越低越好，预期差值为负；方向与主张一致且不由单个 block 独占，同时报告区间和 leave-one-block-out |
| G5 RQ2 减速排除 | E3 完整配对 block 中 Smooth-match 与 B_slosh 的完成时间和 RGB | `R=median_b(T_SmoothMatch,b/T_S-MPCC,b)` 满足 `abs(R-1)≤5%`，且 S-MPCC 的液面收益仍有一致方向 |
| G6 任务与实时性 | success、tracking、solve time/overrun、observed inter-arrival gap proxy、fallback | 无不可接受的方法特异失败；30 Hz 下 solve-time p95 应优先低于 `33.33 ms`，超限必须先诊断；不把 bag 到达间隔写成严格 deadline miss |
| G7 RQ4 工具 | 四相位和 actual/zero replay | actual 可复现在线求解；完整 horizon 和 trial-level 汇总可生成 |

`n=8` 不等于自动“显著”。如果效应方向不稳定、RGB 接近噪声、Smooth-match 未匹配或执行层污染严重，应停在 40 次进行诊断，而不是通过增加第二路径或第二容器掩盖核心问题。

### 9.1 第二容器 `C2` 的选择与冻结

`C2` 的正式物理试次安排在阶段 II-B，但 C2 不是在 40 次结果后再选择的自适应条件。其容器实物、几何、液深、freeboard、液体、派生模态参数、安装方式和视觉采样能力必须在第一条正式 trial 前完成选择、验收并写入同一 `FREEZE_ID`；阶段 II-B 只执行已冻结的 C2，不重新选型、不调权。

| 项目 | 规则 |
| --- | --- |
| 几何差异 | 改变半径和/或液深，使第一模态频率相对 C1 改变约 `15%–20%` 或更多 |
| 视觉准入 | 计算 `N_frame/cycle = f_cam/f1`；30 Hz 相机下优先选择更低或适中的 `f1`，避免每周期采样过少 |
| 安装 | 与 C1 一样位于车体旋转中心 |
| 液体 | 同类型、同染料浓度；按统一 freeboard fraction `λ_H` 冻结液位 |
| 允许更新 | `ω1,c`、`c_h,c`、`η_ref,c`、`ηdot_ref,c` |
| 禁止更新 | MPCC 权重、阻尼比、horizon、solver、运动约束、路径、共享执行层 |

最终表中填写：容器内半径、液深、freeboard、液体质量、`f1`、每周期相机帧数和派生模型参数。

## 11. 正式录制矩阵与录制方法

### 11.1 一个 trial 对应一个独立 bag

正式实验不允许把多个方法或多个 block 连续录进同一个 bag。每个表格单元中的一次 trial 必须产生独立的 `.bag` 和完整 sidecar，并使用第 6.3 节的唯一 `RUN_LABEL`。

建议统一目录：

```text
${HOME}/slosh_bags/real/<DATE>_spmpc_formal/
├── S1/E2/H1_C1/<METHOD>/
├── S1/E3/H1_C1/<METHOD>/
├── S2A/E1/L1_C1/<METHOD>/
└── S2B/E2/H1_C2/<METHOD>/
```

录制矩阵如下：

| 阶段/组 | 路径 | 容器 | 方法及 recorder `VARIANT` | Block | bag 数 | `RUN_LABEL` 模式 |
| --- | --- | --- | --- | ---: | ---: | --- |
| S1/E2 | H1 | C1 | B0→`B0`、B_smooth→`B_smooth`、B_slosh→`B_slosh` | 01–08 | 24 | `S1_E2_H1_C1_<METHOD>_b<BB>_r01` |
| S1/E3 | H1 | C1 | Smooth-match→`B_smooth` 加冻结 `v_ref`；S-MPCC→`B_slosh` | 01–08 | 16 | `S1_E3_H1_C1_<METHOD>_b<BB>_r01` |
| S2A/E1 | L1 | C1 | `B0`、`B_smooth`、`B_slosh` | 01–08 | 24 | `S2A_E1_L1_C1_<METHOD>_b<BB>_r01` |
| S2B/E2 | H1 | C2 | `B0`、`B_smooth`、`B_slosh`，统一切换冻结 C2 配置 | 01–08 | 24 | `S2B_E2_H1_C2_<METHOD>_b<BB>_r01` |

其中 `<METHOD>` 只使用 `B0`、`Bsmooth`、`Bslosh`、`SmoothMatch`。`r02` 及以上只用于第 12 节允许的采集故障补采，原始失败 bag 和说明必须保留。

### 11.2 冻结的 recorder 设置

正式录制统一调用：

```text
src/scout_apps/control/spmpc_local_planner/scripts/record_spmpc_full_rgb_bag.sh
```

它只订阅和保存数据，不发送目标、不发布速度、不负责启动 planner。正式设置为：

| 设置 | 正式值 | 说明 |
| --- | --- | --- |
| `RECORD_RGB` | `true` | 原始 RGB 是物理液面 primary outcome 的真源 |
| `RECORD_CAMERA_COMPRESSED` | `false` | 避免压缩伪影进入液面真值 |
| `RECORD_DEPTH` | `false` | 当前主分析不使用深度，降低写盘压力 |
| `RECORD_SCAN` | `true` | 保存现场环境和定位故障证据 |
| `RECORD_STANDALONE_SLOSH` | `true` | 记录统一的 monitor-only `/slosh/*`；monitor 必须另行启动并在每次运动前 reset |
| `RECORD_ONLINE_LIQUID` | `false` | 在线 proxy 不进入控制或 primary outcome；需要调试时另开 pilot |
| `RECORD_ALL_EXISTING_TOPICS` | `false` | 使用确定性 whitelist，避免不同 run 的 topic 集随现场节点漂移 |
| `RECORD_TOPIC_INFO` | `true` | 保存 publisher/subscriber/type sidecar |
| `ROSBAG_BUFFER_SIZE_MB` | `4096` | RGB 正式录制的候选 buffer；现场机内存不足时必须在正式开始前统一冻结新值 |
| `RECORD_SEC` | `90` 或人工提前停止 | 给最长 60 s 运动、planner 启动/检查、运动前预录和到达后 5 s 留出余量；不得在到达瞬间停止 |
| `NAME` | 等于 `RUN_LABEL` | 确保 bag 与全部 sidecar 同名 |

P3 参数冻结 pilot 中 RealSense 随基础栈保持启动，但输出到独立的 `*_spmpc_parameter_pilot` 根目录，并固定 `RECORD_RGB=false`、`RECORD_DEPTH=false`、`RECORD_ONLINE_LIQUID=false`。全部 15 个矩阵单元保留 odom、TF、路径、命令、solver、机器人预测 horizon 和 standalone `/slosh/*`；只有 W1/W2/W5 额外强制保留实际在线 `/spmpc/slosh_height`、slosh state 和带液体状态的完整预测 horizon，B0/B_smooth 不得将这些缺失信号填零。standalone monitor 在全部 15 个矩阵单元中为强制项：必须使用同一配置 hash，在每个 trial 前 reset，并把 reset 成功状态、topic/单位和配置写入 sidecar。planner 启动参数、recorder metadata、run-env sidecar 和 effective config 必须同时记录候选 `W_SLOSH`；字段不一致的物理尝试不得用于权重选择，且对应矩阵单元在允许的同 segment `r02` 后仍无合格数据时，本轮参数冻结保持 NO-GO。

正式路径必须从冻结 JSON replay。`run_spmpc_real_fixed_path_trial.sh` 已支持 `PILOT_MODE=true + PATH_SOURCE_MODE=replay`，推荐作为 P3 一键入口，并默认使用 `0.08 m / 0.15 rad` 的 pilot 起点门控；每条 PF 命令必须先 `unset MATRIX_PRESET` 并显式填写 `PILOT_METHOD=B0|Bsmooth|W1|W2|W5`，禁止旧 `0706` preset 和隐式 `B_ours` 默认进入本矩阵。正式 40/88 次仍使用配套启动文档的多终端流程和冻结的更严格门控。`run_continuous_real.sh` 仍按当前起点重新生成路径，只用于 smoke。

当前 recorder 已把 `/spmpc/debug/warm_start` 和 `/spmpc/debug/warm_start_status` 加入白名单，但尚未完成独立 bag smoke 和 `used_fallback` 场景验收，因此该 recorder gate 仍为 NO-GO；不能只凭代码白名单或 `warm_start_head` 认定完整 fallback 证据已经可用。actual/zero 正式 replay 工具也尚未实现，仍须单独补齐并验收。当前也没有带 source timestamp、expected/current timer time 和 sequence 的正式 timing topic：solve-budget overrun 固定由 `solver_time_ms>33.33 ms` 推导；`/spmpc/debug/command_intervention` 的 bag 时间戳只计算 `observed command-intervention inter-arrival gap rate`，可能同时包含 recorder/传输丢样，不能称严格 control-cycle deadline miss。gap 阈值、窗口和分母必须在 P3 排序前冻结。

### 11.3 每次 run 必须记录的证据

| 层次 | 必须记录 |
| --- | --- |
| 路径 | 权威 path ID/hash、`/scout/global_path_fixed`、`s`、`σ`、曲率和 Z1–Z5 |
| 机器人 | `x,y,theta,v,omega`、contour/lag error、到达和失败状态 |
| OCP 输入 | 实际 solver robot state、传播液体状态、`s_min`、有效 `v_ref` |
| OCP 输出 | 第一 `a,alpha,v_s`、solver status、solve time、完整配置诊断 |
| 执行层 | raw solver command、post-gate command、published command、limiter/fallback 标志 |
| 液体模型 | `eta_x,eta_x_dot,eta_y,eta_y_dot`；`/spmpc/slosh_height` 为 mm，预测 horizon 的 `h_modal` 为 m |
| 物理液面 | bag 保存原始 RGB、camera_info；冻结脚本离线导出 `H_vis`、clipping、缺帧、30 帧零点和同步质量派生产物 |
| 平台 | `FREEZE_ID`、freeze manifest/hash、Git revision、配置 hash、节点/话题快照、电池、温湿度、操作员说明 |
| Replay | pre-solve solver/warm-start/previous-solution 快照和完整预测 horizon |

当前代码已提供并由正式 S-MPCC recorder 显式录制：

- `/spmpc/debug/predicted_horizon`：完整 61 状态、60 控制预测时域；
- `/spmpc/debug/pre_solve_snapshot`：solve 前 robot/slosh 输入、参考曲线、有效 `v_ref`、边界、61 阶段参数、上一解和完整原始变量初值。

这两个接口当前由论文主线 `continuous_mpcc_acados` 完整填充。pre-solve 消息明确标记 `primal_guess_only=true`，尚不包含对偶变量和 acados 内部 SQP memory。因此 K3 的 actual/zero replay 在进入正式分析前必须先通过冻结的复现门槛：actual 分支复现在线 solver status、第一控制量和 raw command；不能仅因快照已经录下就认定 exact replay 成立。若 actual 分支超过容差，先补充求解器内部状态，再开展 zero 或 phase-flip 分叉。

### 11.4 录制生命周期

每次 trial 严格按下面顺序执行：

1. 根据随机表填写 `FREEZE_ID`、`RUN_LABEL`、方法、block、路径、容器和输出目录；
2. 核对只读 freeze manifest、冻结路径 JSON 和配置的 SHA-256，并把 hash 写入本次外部 sidecar；
3. 启动或核对 standalone slosh monitor，调用 `/slosh/reset`；
4. 启动 frozen-path replay，但停在 `--manual-start` 的 Enter 门；
5. 启动 recorder，使节点启动、首个求解周期和全部运动前静止段进入 bag；
6. 启动指定 planner；在尚未发布路径时核对 backend、variant、公共约束、诊断话题和唯一 `/cmd_vel` publisher；
7. 固定 `T_SETTLE`、运动前原始 RGB 帧数和可选 monitor 门均满足后，在 replay 终端按 Enter；起点位置/航向门控通过后开始发布路径和运动；
8. 到达、方法失败或安全终止后继续录制 5 s；
9. 先安全停止 recorder 使 bag 正常闭合，再停止 planner 和 path replay；
10. 立即核对 bag、recorded-topics sidecar、路径/config hash、关键 replay 话题和异常记录。

不得在同一 planner 进程中连续切换方法录制多个 trial。每次 trial 都重新启动 planner，使内部历史解、上一控制、delay 状态和 terminal 状态从统一初始条件开始。

论文 primary outcome 固定为首次有效运动到统一到达时刻的全运动窗口 RGB p95：

```text
H_vis,p95(full motion)
```

同时报告：10%–90% 路径进度 RGB p95、full-motion RGB RMS、到达后 5 s RMS、completion time、path error p95、success/failure、运动激励、执行层干预和实时性。

一次完整 trial 才是统计样本；RGB 帧、控制周期和路径采样点不能当作独立样本。

## 12. 失败、补采与数据使用规则

允许排除并在相同 block 补采的情况仅限与方法无关的采集故障：

- 相机或 rosbag 从未启动；
- 视频不可恢复损坏；
- 运动前静止段未获得 30 个有效 RGB 帧，或离线 visual-start QC 未通过冻结静稳规则；
- 正式开始前发布了错误路径或错误配置；
- 与方法无关的现场人员/障碍侵入。

上述故障的 `r02` 只有在原 `block_segment_id` 的连续实验时段内完成，且冻结的照明、电池、环境、路径、配置和起点/静稳门槛仍通过时，才能替代该矩阵单元的无效采集并保留配对资格；原 bag、故障原因和全部 sidecar 不得删除，`r02` 不产生新的正式矩阵单元。若只能跨时段补采，必须建立新的 `block_segment_id` 并标记 `split_block=true`；该有效尝试仍进入透明的完成率/敏感性汇总，但不能与另一 segment 的 trial 组成主分析配对。

以下情况保留为方法失败，不得删除后补一个“成功 run”替换：

- solver failure 或 timeout；
- tracking failure；
- safety termination；
- fallback；
- 方法相关的命令异常；
- 未在最长时间内到达。

所有有效方法尝试进入 success rate 分母。某个方法失败后仍按预注册顺序完成同一 block 的其他方法，不丢弃整个 block。配对资格按 contrast 分别判断：对应两方法必须都完成、视觉质量有效、共享同一 `block_id` 和同一 `block_segment_id`；同一 segment 内合规的 `r02` 可以替代无效采集，跨 segment 不配对，不插补缺失值，也不从其他 block 借用 trial。`split_block=true` 不自动删除完全位于同一 segment 内的 pair，但所有跨中断 pair 均不合格。

E2-C1 分别报告 `n_pair(Bslosh,B0)/8` 和 `n_pair(Bslosh,Bsmooth)/8`，E3 报告 `n_pair(Bslosh,SmoothMatch)/8`；E1-C1 和 E2-C2 也分别报告各自的 `n_pair(Bslosh,B0)/8` 与 `n_pair(Bslosh,Bsmooth)/8`。G5 的完成时间配对比值和 RGB 比较必须使用同一组 E3 完整 pair，不能以两方法各自的边际中位数或不同 block 子集替代。各方法同时报告“完成数/正式矩阵单元数”和全部额外物理尝试；所有已完成 trial 的非配对描述只作为敏感性结果，不能替代预注册配对分析。

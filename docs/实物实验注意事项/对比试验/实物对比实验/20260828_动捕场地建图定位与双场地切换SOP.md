## 1. 不可突破的边界

- Cartographer 独占动态 `map -> odom`；不得再启动静态 `map -> odom` publisher；
- 底盘继续提供 `odom -> base_link`，S-MPCC 继续使用 `/odom` 和 `map -> odom -> base_link`；
- NOKOV 只发布隔离的 `/mocap/*` 监测数据；不得把动捕 pose remap 为 `/odom`，也不得向控制链发布 `map/odom/base_link` TF；
- Cartographer 的 `map` 原点和 NOKOV 的 `mocap_world` 原点不必重合。二者只在离线分析中用冻结外参比较，不为“看起来对齐”而临场修改控制 TF；
- 小场地地图必须使用新名字，例如 `map_carto_20260828_mocap_exec_v1`；不得覆盖或复用大场地 `map_carto_20260629_R0`；
- 任何地图冻结、静止定位验收和静止 smoke 都要求 `/cmd_vel` 没有 publisher；
- 建图资产、执行链资产和 G3R3 资产分目录保存，不跨场地混用。

正确 TF 所有权是：

```text
Cartographer localization: map -> odom
Scout odometry:            odom -> base_link
NOKOV monitor:             mocap_world -> mocap_scout（可选，仅监测）
```

不存在控制用途的 `map <-> mocap_world` edge。

## 4. 现场完整顺序

```text
无地图的 mocap/odom/IMU 静止 smoke
→ 建立唯一命名的小场地 Cartographer 地图
→ 停止 teleop，冻结 pbstream/PGM/YAML 与 SHA
→ 用绝对 pbstream + 预期 SHA 重启纯定位
→ 静止定位验收
→ 探索并冻结紧凑 S 路径
→ 正式静止 timing smoke
→ 执行链 R01--R05
→ 执行链决策门
→ 合格时停止小场地栈，用旧大场地地图/SHA/H0 重启 G3R3
```

### 4.1 先连接 NOKOV

按现有 NOKOV Wi-Fi 说明启动 VRPN client 和隔离 monitor，确认：

```bash
rostopic echo -n 1 /vrpn_client_node/Tracker0/pose
rostopic hz /vrpn_client_node/Tracker0/pose
rostopic echo -n 1 /mocap/status
```

`/mocap/status` 必须以 `OK` 开头并包含 `tracker=Tracker0`。monitor 默认不得发布控制 TF。

### 4.2 做一次无地图静止 smoke

终端 A 启动 CAN、底盘、雷达、IMU 和 RealSense，但不启动定位或建图：

```bash
cd /home/geist/scout_ws
source /tmp/mocap_field_mapping.env

START_REALSENSE=true \
  bash src/scout_apps/control/scout_local_planner/scripts/launch_real_sensors_no_localization.sh
```

机器人完全静止、teleop/planner 均未启动时，在另一终端执行：

```bash
cd /home/geist/scout_ws
source /tmp/mocap_field_mapping.env

NAME=MOCAP_NO_MAP_STATIC_$(date +%H%M%S) SMOKE_SEC=15 \
  bash src/scout_apps/control/spmpc_local_planner/scripts/record_spmpc_mocap_static_smoke.sh
```

基础栈会同时检查 RealSense，但 smoke recorder 不录图像；这一步的数据判定仍只回答 VRPN、odom、IMU 的时间与静止质量是否基本可用。没有 `/map` 时不得生成路径或开始 S-MPCC 运动。

### 4.3 建立小场地地图

保持终端 A 的底盘/雷达/IMU 栈运行。在新终端按“主工作空间后、Cartographer 后”的顺序 source：

```bash
cd /home/geist/scout_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash
export CATKIN_SETUP_UTIL_ARGS=--extend
source src/scout_apps/sensors/cartographer_ws/install_isolated/setup.bash

roslaunch nanoscan3_mapping scout_nanoscan3_cartographer.launch \
  scan_topic:=/scan_front \
  odom_topic:=/odom \
  occupancy_grid_resolution:=0.02 \
  use_rviz:=true \
  respawn:=false
```

建图过程中才启动低速 teleop。以低速闭环覆盖可行驶区域，至少形成一次可识别的回环；避免长时间原地自旋、轮胎打滑、Marker 遮挡和贴墙。RViz 中确认地图不重影、墙体闭合且 `map -> odom -> base_link` 连续。

建图 launch 已移除静态 `map -> odom`，该 edge 只由 Cartographer 动态发布。若 `rosrun tf tf_monitor map odom` 显示多个 authority，停止并排查，不能冻结。

### 4.4 停止 teleop 并冻结地图

先完全退出 teleop，保持机器人静止，再做只读 dry-run：

```bash
cd /home/geist/scout_ws
source /tmp/mocap_field_mapping.env

VALIDATE_ONLY=true \
  bash src/scout_apps/control/spmpc_local_planner/scripts/freeze_spmpc_mocap_field_map.sh
```

核对输出 stem 后，显式授权一次冻结：

```bash
ARM_MAP_FREEZE=YES \
  bash src/scout_apps/control/spmpc_local_planner/scripts/freeze_spmpc_mocap_field_map.sh
```

脚本会：

1. 拒绝任何已经存在的目标文件；
2. 拒绝 `/cmd_vel` publisher；
3. 检查 `/scan_front`、`/odom`、`/map`、原始动捕和 `/mocap/status`；
4. 调用 `/finish_trajectory` 与 `/write_state`，并要求两者 `status.code == 0`；
5. 用 `cartographer_pbstream_to_ros_map` 导出同 stem 的 PGM/YAML；
6. 校验 YAML image、resolution/origin/threshold、PGM 头与三个文件的 SHA；
7. 生成可直接 `source` 的 `${MAP_ID}_freeze.env`。

任何步骤失败都保留已有的响应、日志和部分输出；不要删除或覆盖，应改新 `MAP_ID` 重新建图。

### 4.5 用冻结地图重启纯定位

冻结完成后停止建图 launch 和终端 A 的传感器栈，打开新终端：

```bash
cd /home/geist/scout_ws
source /tmp/mocap_field_mapping.env
source "${MAP_STEM}_freeze.env"

LOG_DIR=/tmp/mocap_localization_$(date +%Y%m%d_%H%M%S) \
START_LOCALIZATION=true START_REALSENSE=true \
  bash src/scout_apps/control/scout_local_planner/scripts/launch_real_sensors_stack.sh
```

显式 `LOCALIZATION_MAP_FILE` 会自动把 `/map` 和 `map -> base_link` 等待升级为致命门；地图文件缺失、SHA 不符、map topic 或 TF 超时都会终止整套启动。日志目录中的 `localization_map_identity.env` 保存实际加载路径、预期/实际 SHA 和 frame。

不要在建图进程仍运行时同时启动定位；两者会争用 `cartographer_node` 名称和 `map -> odom`。

### 4.6 完成静止定位验收

保持机器人、容器和 Marker 完全静止，且不要启动 teleop/planner：

```bash
cd /home/geist/scout_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash
source /tmp/mocap_field_mapping.env
source "${MAP_STEM}_freeze.env"

mkdir -p "${LOCALIZATION_REPORT_DIR}"
REPORT="${LOCALIZATION_REPORT_DIR}/${MAP_ID}_static_$(date +%H%M%S).json"

python3 src/scout_apps/control/spmpc_local_planner/scripts/analysis/validate_mocap_field_localization.py \
  "${MAP_STEM}" \
  --expected-pbstream-sha256 "${MAP_PBSTREAM_SHA256}" \
  --expected-yaml-sha256 "${MAP_YAML_SHA256}" \
  --expected-pgm-sha256 "${MAP_PGM_SHA256}" \
  --expected-resolution "${MAP_RESOLUTION}" \
  --mocap-tracker "${MOCAP_TRACKER}" \
  --duration-sec "${LOCALIZATION_STATIC_SEC}" \
  --min-scan-rate-hz "${MIN_SCAN_RATE_HZ}" \
  --max-scan-gap-sec "${MAX_SCAN_GAP_SEC}" \
  --min-odom-rate-hz "${MIN_ODOM_RATE_HZ}" \
  --max-odom-gap-sec "${MAX_ODOM_GAP_SEC}" \
  --min-imu-rate-hz "${MIN_IMU_RATE_HZ}" \
  --max-imu-gap-sec "${MAX_IMU_GAP_SEC}" \
  --min-mocap-rate-hz "${MIN_MOCAP_RATE_HZ}" \
  --max-mocap-gap-sec "${MAX_MOCAP_GAP_SEC}" \
  --max-tf-position-p95-m "${MAX_TF_POSITION_P95_M}" \
  --max-tf-yaw-p95-rad "${MAX_TF_YAW_P95_RAD}" \
  --max-mocap-position-p95-m "${MAX_MOCAP_POSITION_P95_M}" \
  --max-mocap-yaw-p95-rad "${MAX_MOCAP_YAW_P95_RAD}" \
  --report "${REPORT}"
```

只有 JSON 中顶层 `"pass": true` 才通过。它同时验证：

- 磁盘上的 pbstream/YAML/PGM 与冻结 SHA；
- `/cartographer_node/frozen_map_file` 和 `frozen_map_expected_sha256` 确实对应本次小场地图；
- `/map` frame、resolution、尺寸与数据长度；
- `/scan_front`、`/odom`、`/imu/data`、原始动捕的频率、断帧和 header 单调性；
- `map -> base_link` 可用率、时间新鲜度和静止抖动；
- odom/动捕静止位姿和 odom 速度；
- 全程无 `/cmd_vel` publisher，且 `/mocap/status` 始终为当前 Tracker 的 `OK`。

现场地面或传感器频率确需修改阈值时，必须在第一条正式 smoke 前统一修改 `/tmp/mocap_field_mapping.env` 并保留原失败报告，不能逐次放宽到 PASS。

### 4.7 探索并冻结 S 路径，再做正式静止 smoke

静止定位验收通过后，先生成候选紧凑 S 路径并做一条明确标记为 `PATH_SELECTION` 的低速探索。确认全程在地图/动捕有效区域内、停止距离充足且左右转均安全后，才把候选路径、几何报告和 SHA 转为正式冻结输入；探索 bag 不计入 R01--R05。探索失败时保留候选资产并使用新文件名生成下一候选，禁止覆盖。

专用探索入口先 dry-run，再由操作者显式授权；默认 `0.10 m/s`，脚本硬限制不超过 `0.15 m/s`：

```bash
source /tmp/mocap_field_mapping.env
source "${MAP_STEM}_freeze.env"
source /tmp/mocap_execution_chain.env

SELECTION_ID=C01 V_REF=0.10 VALIDATE_ONLY=true \
  bash src/scout_apps/control/spmpc_local_planner/scripts/run_spmpc_mocap_path_selection_trial.sh

SELECTION_ID=C01 V_REF=0.10 ARM_MOTION=YES \
  bash src/scout_apps/control/spmpc_local_planner/scripts/run_spmpc_mocap_path_selection_trial.sh
```

它会再次核对候选路径 SHA、小场地地图三件套、运行时 Cartographer map 参数、关键 topic、动捕状态和 `/cmd_vel` publisher，并自动执行 motion bag postflight。输出明确写入 `formal_trial_consumed=false`。

地图、定位、路径、variant、速度、载荷和阈值全部冻结后，才执行协议中的正式 timing smoke：

```bash
SMOKE_SEC=15 \
  bash src/scout_apps/control/spmpc_local_planner/scripts/record_spmpc_mocap_static_smoke.sh
```

正式 smoke PASS 后，依次完成 `R01 -> R05`。建图、定位验收和 `PATH_SELECTION` 数据均不计入执行链正式 trial。

## 5. 从执行链切回 G3R3

### 5.1 先过决策门

| 执行链结果 | 是否直接做原 G3R3 | 动作 |
| --- | --- | --- |
| 定位/时序合格，未发现稳定的实质执行延迟 | 是 | 保持 G3R3 release、runner、H0 和六条顺序不变 |
| 发现跨 trial/held-out 稳定的实质延迟 | 否 | 若要把执行器模型接入控制，建立新代码 release、协议 ID 和数据集；不得静默修改 G3R3 |
| 定位、NOKOV 时间或辨识结论不确定 | 否 | 先重复建图/静止验收或执行链 trial，不把不确定参数带到大场地 |

“实质延迟”是否成立以执行链方案的预声明门和 held-out 结果为准，不由一条互相关峰值决定。

## 6. 故障处理

| 现象 | 处理 |
| --- | --- |
| `/map` 有消息但 TF 跳变 | 检查是否仍有第二个 `map -> odom` authority；停止，不冻结 |
| 地图 SHA 不符 | 停止；确认路径和 freeze.env，不能用实际 SHA 覆盖预期值来强行启动 |
| 地图 YAML 指向其他 PGM | 资产组无效；重新导出到唯一 stem |
| freeze 服务退出码为 0 但 `status.code != 0` | 冻结失败；保留响应文件，使用新 MAP_ID 重建 |
| 静止验收发现 `/cmd_vel` publisher | 停止 planner/teleop，再用新报告名重做 |
| TF age/抖动不合格 | 查 Cartographer 匹配、雷达 TF、odom 和场地特征；不生成路径 |
| 动捕 OK 但与地图坐标不同 | 正常；保持两套 frame 隔离，只冻结离线外参 |
| 切回大场地后仍显示小地图 | 整套进程未完全停止或环境变量残留；全部停止，在全新终端重启 |

## 2. 总实验矩阵

### A. 内部消融

| 字段 | 内容 |
|---|---|
| 场景 | 固定中等风险 S-curve 路径 |
| 方法 | `B0`, `B_smooth`, `B_slosh`, `B_ours` |
| 重复数 | 已有 clean N=3 可先写论文；条件允许再补到 N=5 |
| 主要问题 | 效果是否来自液体动态记忆增强 MPCC，而不是单纯平滑 |
| 主指标 | RGB 液面 peak/p95/RMS，任务时间，跟踪误差，cmd 平滑性，求解时间 |
| 论文作用 | 主方法贡献 1 的核心实物证据 |

推荐交错顺序：

```text
Round 1: B0 -> B_smooth -> B_slosh -> B_ours
Round 2: B_ours -> B_slosh -> B_smooth -> B0
Round 3: B_smooth -> B0 -> B_ours -> B_slosh
Round 4/5: 若补 N=5，继续交错，不连续跑同一方法
```

判读重点：

```text
B_ours vs B_smooth：证明 slosh-aware prediction 超过 smooth-only。
B_slosh vs B0：证明显式 slosh soft cost 有独立作用。
B_ours vs B_slosh：证明 smooth shaping 对实物执行仍必要。
B_smooth vs B0：说明普通平滑本身的贡献。
```

### B. Governor 消融

| 字段 | 内容 |
|---|---|
| 场景 | 同一 fixed S-curve，但使用较高名义 `v_ref`，使 governor 有机会激活 |
| 方法 | `B_ours`, `B_ours_gov` |
| 可选方法 | `B_ours_uniform_slow` |
| 重复数 | 每方法 N=3 起，推荐 N=5 |
| 主要问题 | finite-horizon predictive reference adaptation 是否能在相同名义参考下进一步压低晃液风险 |
| 主指标 | RGB 液面指标，任务时间，`beta_raw`, `beta_filtered`, `v_ref_governed`, saturated rate |
| 论文作用 | 主方法贡献 2 的核心实物证据 |

推荐先从下面两档中选一档：

```text
温和 stress: V_REF=0.25
明显 stress: V_REF=0.30
```

如果 `B_ours_gov` 在 `V_REF=0.25` 基本不激活，不要硬做 N=5；先升到 `V_REF=0.30` 做 N=1 smoke，确认：

```text
1. governor active fraction > 0；
2. beta_filtered 有明显低于 1.0 的区间；
3. 仍能 GOAL_REACHED；
4. 没有 safety gate / limiter 频繁污染。
```

推荐交错顺序：

```text
Round 1: B_ours -> B_ours_gov
Round 2: B_ours_gov -> B_ours
Round 3: B_ours -> B_ours_gov
Round 4/5: 继续交错
```

如果 governor-on 显著变慢，建议补：

```text
B_ours_uniform_slow
```

其固定速度取 `B_ours_gov` 的平均有效速度或使完成时间接近 `B_ours_gov`。该组用于排除“只是整体变慢所以液面变小”的解释。

### C. 外部局部规划器 baseline

| 字段 | 内容 |
|---|---|
| 场景 | 与 A 组相同 fixed S-curve |
| 方法 | `B_ours` 或 `B_ours_gov` vs 稳定可跑的 `LT-DWA` / `TEB` / `mpc_local_planner` |
| 重复数 | 每方法 N=3 起，稳定后可 N=5 |
| 主要问题 | 普通 local planner 不传播液体状态时是否足够 |
| 主指标 | 成功率，任务时间，RGB 液面指标，跟踪误差，cmd 平滑性 |
| 论文作用 | 普通 local planner 对照，不是主贡献唯一支柱 |

执行原则：

```text
1. 只选 1 个最稳定 baseline 进入正文主表；
2. 第 2 个 baseline 只作为 appendix 或补充；
3. 每个外部 baseline 必须先 shadow，再 actuated N=1 smoke，再 formal N=3；
4. 任一时刻只允许一个 /cmd_vel publisher；
5. 不使用 slosh feedback，不接 RGB 闭环。
```

TEB 当前状态：

```text
0706 记录显示 TEB 能接入 fixed path，但仍存在速度慢、摆头、参数未 freeze 的问题。
因此 TEB 不能直接进入 formal 表。必须先调到 stable smoke。
```

TEB 或其他外部 baseline 进入 formal N=3 的门槛：

```text
GOAL_REACHED；
无明显左右摆头或急停；
goal time 不超过 B_ours 的 1.3~1.5 倍；
tracking p95 在 0.10~0.30 m 内；
/cmd_vel 无旧 publisher 污染；
RGB / odom / path / cmd 记录完整。
```

### D. 模型--外部液面保真度诊断

| 字段 | 内容 |

## 5. 公平性参数设置

实物实验中，公平性优先级高于“临时把某个方法调得好看”。进入 formal run 前必须冻结参数；formal 过程中除本组定义的自变量外，不允许按方法单独调参。

### 5.1 全局公平性原则

所有进入同一张结果表的 run 必须满足：

```text
同一 fixed path / goal；
同一容器、液位、载荷固定方式；
同一 RGB 相机位置、曝光、ROI 和光照条件；
同一定位栈、地图、TF、底盘模式；
同一 delay compensation 设置；
同一 shared velocity / acceleration / angular limits；
同一 hard constraint 开关；
同一 recorder topic 集合；
同一 clean-run 判定标准；
同一统计窗口和后处理脚本。
```

现场不允许的做法：

```text
某个方法晃得大就单独降 v_ref；
某个方法跟踪差就单独放宽 goal tolerance；
某个方法摆头就单独降低 omega_max；
某个方法失败后只重跑成功样本，不记录失败；
把调参 smoke bag 混入 formal 统计；
按 RGB 结果反复调参后继续宣称是盲测/公平对比。
```

如果确实需要调整参数，必须：

```text
1. 终止当前 formal 矩阵；
2. 记录旧矩阵作废原因；
3. 重新冻结新参数；
4. 所有方法按新参数重新交错执行。
```

### 5.2 A 组内部消融公平性

A 组唯一允许变化的是方法 variant 本身：

| 方法 | 允许变化 |
|---|---|
| `B0` | 无 slosh cost，无 enhanced smooth priority |
| `B_smooth` | 只开启 enhanced smooth priority |
| `B_slosh` | 只开启 slosh model / cost |
| `B_ours` | 同时开启 slosh model / cost 和 enhanced smooth priority |

A 组必须固定：

```text
nominal v_ref；
v_max / omega_max；
linear accel limit / angular accel limit；
delay compensation；
goal tolerance；
hard constraint disabled；
slosh governor disabled；
RGB 只离线评价，不进闭环。
```

注意：如果 `B_ours` 或 `B_slosh` 因 slosh cost 自己生成更慢速度，这是方法结果；但不能人为给 `B0` 或 `B_smooth` 单独降低速度来追平液面，也不能人为给 `B_ours` 单独放宽速度限制。

### 5.3 B 组 Governor 消融公平性

B 组唯一允许变化的是 governor 开关：

| 方法 | 允许变化 |
|---|---|
| `B_ours` | governor disabled |
| `B_ours_gov` | governor enabled |
| `B_ours_uniform_slow` | 可选 time-matched 控制组，必须单独标注 |

B 组必须固定：

```text
同一 nominal v_ref；
同一 B_ours variant；
同一 slosh cost / smooth weights；
同一 path / delay / limits / hard constraint disabled；
同一 governor 参数，除 enable 外不按 run 调整；
同一 RGB 离线评价口径。
```

`B_ours_gov` 的 `v_ref_governed` 变小是 governor 的方法输出，不算不公平。相反，`B_ours` 不能为了对齐结果而手动降速；如果需要排除“整体变慢”解释，另开 `B_ours_uniform_slow`，并在表中明确它是 time-matched control，不和 governor off/on 混成同一自变量。

formal 前必须先做 N=1 governor activation smoke：

```text
active fraction > 0；
beta_filtered 有低于 1.0 的区间；
saturated rate 不长期为 1；
governed_v_ref 不超过 nominal_v_ref；
仍能 GOAL_REACHED；
后级 safety / limiter 不频繁改写输出。
```

### 5.4 C 组外部 baseline 公平性

外部 baseline 与 SPMPC 的接口不同，不要求内部参数完全同构，但必须固定 common limits，并报告实际执行速度和时间。

C 组必须固定：

```text
同一 fixed path / goal；
同一 max_v / max_w / accel limits；
同一 goal tolerance；
同一 timeout；
同一 RGB 和 tracking 后处理；
同一 success / invalid 判定；
不使用 slosh model、slosh observer、RGB 液面反馈。
```

外部 baseline 参数必须先通过 shadow 和 N=1 smoke 调稳，然后 freeze。freeze 后进入 formal N=3/N=5，不能边跑 formal 边继续调 TEB/DWA 参数。

外部 baseline 表必须同时报告：

```text
success rate；
goal time；
actual cmd_v mean/p95；
actual cmd_omega p95；
tracking p95；
RGB H_vis peak/p95/RMS。
```

这样可以避免“某个外部 planner 只是更慢所以液面更小”或“某个 planner 贴线差但晃动低”的误读。

### 5.5 D 组保真度诊断公平性

D 组不额外跑控制实验，只复用 A/B/C 的 clean rosbag。不得因为某个 run 的模型--RGB 相关性差就剔除该 run；剔除只能基于第 7 节的 run 有效性标准。

D 组必须明确区分：

```text
H_model：内部模型代理量；
H_vis：RGB 外部液面观测；
二者不是同一个物理测量源；
H_model 不能替代 H_vis 作为真实液面主结论。
```

## 7. Run 有效性判定

### 7.1 Clean paper sample

进入主统计的 run 必须满足：

```text
GOAL_REACHED；
无人工接管；
无 E-stop；
无明显定位跳变；
无旧 /cmd_vel publisher；
RGB 覆盖 first OK -> first GOAL_REACHED，并保留 post-goal 残余段；
zero_due_to_tracking_safety = 0；
delay_compensation_applied_frac 接近 1.0；
effective_config 与本组口径一致；
关键 topic 样本充足；
```

### 7.2 记录但不进主统计

下面情况保留 bag 和日志，但不混入 clean 主表：

```text
人工接管；
急停；
TF / odom / map 明显异常；
RGB 画面丢失或 ROI 不可用；
外部 baseline 未到点；
TEB / DWA 调参过程；
后级 limiter / safety gate 长时间介入；
容器液位或相机姿态发生改变。
```

失败 run 不删除。失败本身可用于 appendix 或工程诊断，但正文主结果表只统计 clean sample。

## 8. 现场执行 SOP

每个 run 前：

```text
1. 确认 /cmd_vel 无旧 publisher；
2. 回起点标记；
3. 对齐 heading；
4. 液体静稳 60-90s；
5. 确认 RGB 画面、ROI、光照正常；
6. 确认 /odom, /tf, /map, fixed path, goal 正常；
7. recorder 先启动，再启动 planner；
8. E-stop / 遥控急停就位。
```

每个 run 后：

```text
1. 确认 /cmd_vel 已归零；
2. 记录 run label、方法、参数、是否 clean；
3. 记录现场备注：摆头、切弯、液体初始状态、光照变化；
4. 不要立即下一包，先让液体静稳；
5. 若出现异常，先排查再继续，不要带病跑完整矩阵。
```

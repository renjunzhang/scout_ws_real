# 底盘速度连续性快速测试

> 日期：2026-09-02
>
> 协议：`MOCAP_VELOCITY_CONTINUITY_V1`
>
> 性质：development 快速诊断，不启动 MPC、路径跟踪或 slosh 控制

## 1. 目的

直接向最终 `/cmd_vel` 发布连续变化的线速度，检查小车本身是否会出现：

- 速度突跳或突然掉速；
- 加速过程中反复加速、减速；
- 恒速阶段明显抖动；
- 命令连续但实际运动“一卡一卡”。

本测试只测底盘执行性能，用来区分“底盘不能连续执行”和“SMPCC 自己给出的速度命令不连续”。

## 2. 只录两包

不做多幅值矩阵，不做前后、左右和多次重复。先只录下面两包：

| 顺序 | 模式 | 速度形状 | 最高速度 | 单次预计位移 |
|---:|---|---|---:|---:|
| 1 | `trapezoidal_velocity` | 匀加速 → 恒速 → 匀减速，即梯形速度 | 0.80 m/s | 约 4.00 m |
| 2 | `linear_accel` | 加速度从 0 线性增加，速度边沿为二次曲线 | 0.80 m/s | 约 4.00 m |

`constant_accel` 是 `trapezoidal_velocity` 的兼容别名，物理上是同一条曲线，不要把两者各录一次。

共同时间流程：

```text
静止 3 s
连续加速 3 s
恒速 2 s
连续减速 3 s
静止 3 s
```

底盘高速模式的额定最大速度为 `3.0 m/s`，但它不是本次无路径、无避障直线测试的目标速度。按当前轮廓直接测试 `3.0 m/s`，单包理论位移约 `15 m`，不适合当前动捕场地。

当前直线场地约 `7.5 m`。综合场地余量与底盘 `3.0 m/s` 额定上限，本次将默认目标和脚本速度硬上限都冻结为 `0.80 m/s`，并额外禁止理论行程超过 `5.0 m`。默认梯形速度的加速度幅值约为 `0.267 m/s²`；`linear_accel` 在边沿末端的最大加速度约为 `0.533 m/s²`。这能测试高速模式下有意义的连续性，同时不做危险的额定极速冲刺。

## 3. 自动录制内容

脚本自动录制：

```text
/cmd_vel
/mocap_velocity_continuity/cmd_vel_stamped
/vrpn_client_node/Tracker0/pose
/imu/data
/odom
/scout_status
```

其中带时间戳的命令副本用于精确还原发布曲线；分析还会核对它与最终 `/cmd_vel` 是否一致。

本测试不录相机，不需要 Realsense，不消费 IMU 液体状态，也不启动 solver。

## 4. 自动输出的 5 张图

每包只保留 5 张核心图：

```text
linear_mocap_velocity.png             # 发布速度与 NOKOV 实际速度
linear_mocap_acceleration.png         # 发布加速度与 NOKOV 推导加速度
linear_mocap_delta_velocity_20ms.png  # 每 20 ms 的速度变化，最直接看突跳/掉速
linear_odom_velocity.png              # odom 速度交叉检查
linear_imu_acceleration.png           # IMU 前向加速度交叉检查
```

图中不把 NOKOV、odom、IMU 全揉在一起。NOKOV 是主结果，odom 和 IMU 只用于判断异常是否来自单一传感器。

## 5. 自动计算的连续性指标

主要看：

- 恒速阶段速度标准差和 P95 波动；
- 实际速度相对连续命令的误差；
- 每 `20 ms` 的 `Δv` P95 和最大值；
- 加速阶段显著掉速次数；
- 加速度正负反复翻转次数；
- 梯形速度边沿的一次拟合质量，或 `linear_accel` 边沿的二次拟合质量；
- NOKOV、odom 的有效对齐延迟。

其中“有效对齐延迟”只用于把两条曲线对齐后计算连续性残差，不替代已经完成的速度阶跃 FOPDT 延迟辨识。

脚本终端的 `PASS` 只表示 bag 完整、命令副本一致且分析成功，不代表小车连续性自动合格。连续性好坏要根据两包的 NOKOV 主指标和曲线作结论。

## 6. 脚本

```text
src/scout_apps/control/spmpc_local_planner/scripts/run_spmpc_mocap_velocity_continuity_trial.sh
```

脚本默认只做参数校验，不动车；拒绝覆盖已有输出，并会检查：

- `/use_sim_time=false`；
- NOKOV、IMU、odom 均在线；
- 底盘驱动订阅 `/cmd_vel`；
- 没有 MPC、遥控等其他节点正在发布 `/cmd_vel`；
- 车辆在正式曲线开始前保持静止；
- 中断或异常退出时强制发布零速。

## 7. 执行命令

先校验梯形速度，不动车：

```bash
cd /home/geist/scout_ws

PROFILE=trapezoidal_velocity \
ATTEMPT=01 \
bash src/scout_apps/control/spmpc_local_planner/scripts/run_spmpc_mocap_velocity_continuity_trial.sh
```

确认正前方至少有 `5.0 m` 连续净空、车辆朝向与长边平行、急停在手后，正式录制梯形速度：

```bash
cd /home/geist/scout_ws

PROFILE=trapezoidal_velocity \
ATTEMPT=01 \
VALIDATE_ONLY=false \
ARM_MOTION=YES \
bash src/scout_apps/control/spmpc_local_planner/scripts/run_spmpc_mocap_velocity_continuity_trial.sh
```

第一包结束并检查终端 `PASS` 后，将车移回安全位置，再录 `linear_accel`：

```bash
cd /home/geist/scout_ws

PROFILE=linear_accel \
ATTEMPT=01 \
VALIDATE_ONLY=false \
ARM_MOTION=YES \
bash src/scout_apps/control/spmpc_local_planner/scripts/run_spmpc_mocap_velocity_continuity_trial.sh
```

只需要这两包。除非某包传感器异常或结果互相矛盾，否则暂不增加重复。

## 9. 结果怎么判断

- `/cmd_vel` 连续，NOKOV 和 odom 都出现同一位置的掉速：优先判断为底盘执行不连续；
- `/cmd_vel` 连续，只有 NOKOV 尖峰而 odom、IMU 无同步变化：优先判断为动捕跳点；
- 梯形速度正常，但 `linear_accel` 出现反复掉速：说明底盘对随时间变化的加速度跟随较弱；
- 两包都连续，而此前 Bslosh 仍“一卡一卡”：说明卡顿主要来自 solver 生成的命令，而不是底盘在平滑命令下自行顿挫。

该命令不发布速度、不录 bag，只检查路径、标定、hash 和 runner 环境。

第 3 条：

```bash

```

第 4 条：

```bash
ARM_MOTION=YES CONFIRM_RGB_GEOMETRY=YES G2S_ROW=04 \
bash /home/geist/scout_ws/src/scout_apps/control/spmpc_local_planner/scripts/run_spmpc_g2s_h0s_source_selection_trial.sh
```

每次只执行一条，**不要用 `for` 循环连续跑**。两条之间必须：

1. 确认脚本已发零速并退出；
2. 小车回到相同起点并对齐；
3. 确认相机和容器没有移动；
4. 等待液体完全静稳；
5. 再执行下一条。

实车命令会自动完成：

```text
启动在线 RGB 标量
→ 开始录包
→ 启动 Bsmooth 和 odom/processed-IMU 双 observer
→ 等待 processed-IMU READY
→ replay H0s 并发布 /cmd_vel
→ 路径结束后发布零速度
→ 关闭本条 trial 的节点
→ 自动执行 postflight
```

脚本会自动停车，但现场仍必须保持急停可用。

## 三、4 条都 PASS 后执行分析

```bash
bash /home/geist/scout_ws/src/scout_apps/control/spmpc_local_planner/scripts/analyze_spmpc_g2s_source_selection.sh
```

该命令只读分析 4 条 bag，比较 odom observer 和 processed-IMU observer 与在线 RGB 标量的一致性。结果将决定后续 `Bslosh` 的唯一输入源。

分析完成后就停止实验；不得继续执行 W2/W5、G3 或正式 Stage I。

## 四、整个 40/64/88 矩阵的命令状态

| 阶段 | 计划数量 | 条件 | 当前命令状态 |
| --- | ---: | --- | --- |
| G2S | 4 条 development | `Bsmooth`，同 trial 记录 odom/IMU/RGB | **上述命令可执行** |
| G2C | `2 × n_cand` | W2 对 W5 | NO-GO；等 G2S 冻结输入源 |
| G3 | 默认候选 8 条 | `Bsmooth` 对最终 `Bslosh` | NO-GO；等 G2C 冻结权重 |
| Stage I | 40 条 | `C1 + H1`，8 block × 5 条件 | NO-GO |
| Stage II-A | 新增 24 条 | `C1 + L1`，8 block × 3 条件 | Stage I PASS 后才能执行 |
| Stage II-B | 条件性新增 24 条 | `C2 + H1`，8 block × 3 条件 | Stage II-A trigger PASS 后才能执行 |

Stage I 的五个条件是 `B0`、`Bsmooth`、`SmoothMatch`、`FixedProfile`、`Bslosh`。Stage II-A/B 只保留 `Bsmooth`、`FixedProfile`、`Bslosh`。每个 block 必须按冻结随机表执行，不得由操作员自行排序。

当前不给 G2C/G3/Stage I/II 伪造一行命令，因为以下内容尚未冻结：

- odom/processed-IMU 唯一输入源；
- W2/W5 唯一 `Bslosh` 权重；
- 五条件/三条件随机表；
- FixedProfile 实车 runner 与冻结 profile；
- `freeze_manifest.yaml` 的 `status=GO` 和唯一 `FREEZE_ID`。

这些条件满足后，再为各阶段提供与 G2S 同样的单条 trial wrapper，而不是现场手工组合 `roslaunch` 和 `rosbag record`。

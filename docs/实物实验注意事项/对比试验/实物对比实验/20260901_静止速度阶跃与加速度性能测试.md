# 静止速度阶跃与底盘执行器辨识

> 当前协议：`MOCAP_VELOCITY_STEP_V2`
>
> 性质：底盘执行器 development 辨识，不启动 MPC、路径跟踪或 slosh 控制

## 1. 目的

车辆静止时直接向最终 `/cmd_vel` 发布单轴速度阶跃，辨识：

- 线速度通道：运动起效延迟、速度建立时间、稳态增益、有效加减速度、制动时间、制动距离和侧向偏移；
- 角速度通道：转动起效延迟、角速度建立时间、稳态增益、有效角加减速度、停转时间和零指令后的残余转角；
- 多个幅值下参数是否稳定，以及前后、左右是否存在不对称。

最终要为显式执行器模型提供：

```text
delay_v / delay_omega
tau_v / tau_omega
gain_v / gain_omega
a / alpha 的低速安全工作范围
```

jerk 上限不能只由单次速度阶跃决定，后续还要结合命令连续性与闭环安全门单独冻结。

本测试测量的是“最终命令发布到观测到实车运动”的执行链，不包含 solver 计算时间。相对 NOKOV 得到的延迟仍包含 NOKOV/Wi-Fi/时间戳链自身的延迟，因此必须同时用 IMU 和 odom 交叉检查，不能把任一传感器的单个数直接称为电机纯延迟。

## 2. 传感器口径

- NOKOV 是线速度、角速度和位姿结果的主传感器；
- odom 独立给出线速度和角速度，用于交叉检查；
- 转向时，IMU gyro-z 独立给出角速度、起效时刻和角加速度；
- 直线时，IMU 只用配置的车体前向轴做“加速度何时出现”的辅助检查，不直接作为稳态速度或 FOPDT 增益真值；
- IMU 原始线加速度含重力、安装倾斜和静态偏置，绘图会减去静止偏置，但不把它替代 NOKOV 主结果。
- NOKOV 的线速度/角速度由位置/航向在默认 `0.12 s` 窗口内作零相位局部直线斜率得到，不使用会放大低速量化噪声的单帧差分。窗口会写入 JSON，延迟结论必须与原始 IMU/odom 交叉检查。

没有 NOKOV 时不允许使用本协议标定 MPC 执行器参数。

## 6. 自动计算内容

每个传感器分别报告：

- `onset`：命令改变后，响应连续越过静止噪声阈值的首个时刻；
- `t10/t50/t90`：达到本次实测稳态幅值 10%/50%/90% 的时间；
- `a_eff/decel_eff`：速度 10%～90% 上升和 90%～10% 下降的平均斜率；
- 平滑加速度曲线的上升段 P95/Peak 和制动段 P95/Peak；
- 制动起效时间、停止时间，以及直线制动距离或转向残余角度；
- bag arrival time 与各消息 header time 两套结果。

每个速度传感器还会自动拟合：

```text
y(s) / u(s) = K * exp(-L*s) / (tau*s + 1)
```

其中：

- `L`：FOPDT 纯延迟候选；
- `tau`：速度渐进建立的时间常数；
- `K`：命令到实测稳态速度的增益；
- `R²/RMSE`：拟合质量。

FOPDT 只拟合“零命令→固定速度”的启动上升段，不把回零后的停车段混入同一个一阶模型。原因是底盘启动和刹停动力学可以明显不对称；刹停延迟和减速能力由上述独立刹停指标描述。

拟合还要通过可辨识性门槛：默认 `R² >= 0.80`，且近优参数不得碰到搜索边界。未通过时仍保留原始拟合供诊断，但会明确标成 `diagnostic only`，不进入矩阵的正式 `L/tau/K` 汇总。

`onset` 与拟合 `L` 必须同时保留。`t90` 包含纯等待和渐进建立，不能整体写成纯延迟。加速度曲线采用固定窗口的零相位局部斜率，只用于离线能力分析；窗口会写入 JSON，不用单点数值微分的噪声峰值冒充底盘能力。

## 7. 使用方法

先确认底盘驱动、NOKOV、`/imu/data` 和 `/odom` 正常，并停止 MPC 和遥控节点。runner 会拒绝已有 `/cmd_vel` 发布者、NOKOV/IMU/odom 缺失、仿真时间以及输出覆盖。

只检查第一行合同，不动车：

```bash
cd /home/geist/scout_ws

MATRIX_ROW=01 \
ATTEMPT=01 \
DATA_SPLIT=development \
bash src/scout_apps/control/spmpc_local_planner/scripts/run_spmpc_mocap_velocity_step_matrix_trial.sh
```

确认转动净空和急停后，实测第一行：

```bash
cd /home/geist/scout_ws

MATRIX_ROW=01 \
ATTEMPT=01 \
DATA_SPLIT=development \
VALIDATE_ONLY=false \
ARM_MOTION=YES \
bash src/scout_apps/control/spmpc_local_planner/scripts/run_spmpc_mocap_velocity_step_matrix_trial.sh
```

结束后检查终端 `PASS`、JSON 和分离图，再人工启动 Row02。不得在一个命令里循环执行 Row01～Row12。

开发集建议每行重复 5 次，只修改 `ATTEMPT=01..05`。当前先全部标记为 `development`；validation/final-test 必须使用后来单独冻结且未参与调参的新包，不能把看过的 development 包改名冒充。

## 9. 实物安全与可比性

- 地面、轮胎状态、负载和电池状态尽量保持一致，负载应与后续 MPC 实验一致；
- 车辆每次启动前必须完全静止；同幅值反方向运行前也要等待底盘和液体稳定；
- 默认最大直线行程约 `0.6 m`，还需额外预留制动距离；
- 最高角速度行约转动 `1.2 rad`，必须检查车体、线缆和周围设备净空；
- 急停保持在手，任何异常加速、方向错误、NOKOV 丢失或底盘故障立即停止；
- 本协议得到的是低速工作区参数。若以后扩大速度范围，必须另建更高风险协议，不能直接修改本矩阵上限。

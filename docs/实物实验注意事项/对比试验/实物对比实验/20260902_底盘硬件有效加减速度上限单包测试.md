# 底盘硬件有效加减速度上限单包测试

> 日期：2026-09-02
>
> 协议：`MOCAP_HARDWARE_ACCEL_LIMIT_V1`
>
> 性质：一次性 development 硬件能力测试，不启动 MPC、路径跟踪、slosh 或相机

## 1. 要回答的问题

直接向最终 `/cmd_vel` 发送一次足够大的线速度阶跃，让底盘驱动器自行给出它在当前条件下能够实现的最快加速和制动过程，并由 NOKOV、IMU、odom 交叉测量。

本测试得到的是：

```text
当前高速挡 + 当前电量 + 当前负载 + 当前地面
从 0 到 0.8 m/s 工作区内的底盘与驱动器整体有效加减速度上限
```

它不是电机堵转转矩对应的理论极限，也不能代表所有电量、地面和负载。对 SMPCC 来说，整车实际可执行能力比脱离驱动器的电机理论值更有意义。

## 2. 为什么用速度阶跃

测试脚本不人为指定加速度，而是直接把速度命令从 `0` 跳到 `0.8 m/s`。只要这个速度误差足够大，底盘内部速度控制器就会按自身允许的最快过程加速；实际速度曲线的斜率就是需要测量的能力。

冻结流程只有一包：

```text
零速度 3.0 s
0 -> 0.8 m/s 速度阶跃并保持 2.5 s
0.8 -> 0 m/s 速度阶跃
零速度继续记录 4.0 s
```

非零命令阶段的理论位移上界为 `0.8×2.5=2.0 m`，还需要给制动和人工处置留出空间。当前约 `7.5 m` 场地要求正前方至少 `4.0 m` 连续净空。

不直接阶跃到高速挡额定 `3.0 m/s`。测量最大加速度不要求达到额定最高速度，而当前场地也不适合做 `3.0 m/s` 冲刺。

## 3. 自动录制与分析

录制话题：

```text
/cmd_vel
/mocap_hardware_accel_limit/cmd_vel_stamped
/vrpn_client_node/Tracker0/pose
/imu/data
/odom
/scout_status
```

结束后复用冻结的速度阶跃分析，自动输出：

- NOKOV 和 odom 的速度、加速度及启动上升段拟合图；
- IMU 前向加速度图；
- 加速与制动的起效时间；
- `10%～90%` 有效加速度和 `90%～10%` 有效减速度；
- 平滑加速度曲线的 P95、峰值；
- 零命令后的制动时间、停车距离和横向偏移。

判断硬件有效能力时，以三路一致的加速度平台或高分位范围为主。NOKOV 二阶差分的单点峰值容易放大噪声，不能把一个最高尖峰直接写成硬件上限。

## 4. 运行前条件

- Scout 挡位开关确认在高速挡；
- 电量和负载具有代表性，并记录测试时状态；
- 车辆朝向场地长边，正前方至少 `4.0 m` 无人员和障碍物；
- 遥控器急停在手，出现方向错误、异常加速或传感器故障立即停车；
- 底盘驱动、NOKOV、`/imu/data`、`/odom` 正常；
- 停止 MPC 和 ROS 遥控节点，确保没有其他节点发布 `/cmd_vel`。

如果手持遥控器本身通过 ROS 持续发布 `/cmd_vel`，它会与测试命令冲突，脚本将拒绝启动。安全遥控必须能够在底盘硬件层覆盖或急停，而不是与测试脚本并行争用同一 ROS 话题。

## 5. 执行命令

先做校验，不动车：

```bash
cd /home/geist/scout_ws

ATTEMPT=01 \
bash src/scout_apps/control/spmpc_local_planner/scripts/run_spmpc_mocap_hardware_accel_limit_trial.sh
```

确认校验输出中的速度、时长、目录和场地条件后，正式执行一次：

```bash
cd /home/geist/scout_ws

ATTEMPT=01 \
VALIDATE_ONLY=false \
ARM_MOTION=YES \
CONFIRM_TEST_SETUP=YES \
bash src/scout_apps/control/spmpc_local_planner/scripts/run_spmpc_mocap_hardware_accel_limit_trial.sh
```

这是突加速测试：敲下回车前急停必须已经在手，人员不得位于车辆前方。脚本异常退出或按 `Ctrl+C` 时会立即重复发布零速度，但不能替代硬件急停。

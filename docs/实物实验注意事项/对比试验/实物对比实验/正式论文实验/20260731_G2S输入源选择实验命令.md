
每条都是：


- runner 环境和所有必要文件。

dry-run 不通过时不得增加 `ARM_MOTION=YES`。

## 6. 单条 trial 的自动行为

```text
检查路径/RGB/IMU 冻结证据
→ 检查 1920×1080 RGB 输入与手动曝光
→ 启动在线 RGB 标量节点（publish_debug=false）
→ 等待 zero_locked + valid + status=OK
→ 启动 recorder
→ 启动 Bsmooth 和 odom/processed-IMU 双 observer
→ 保持小车静止，等待 processed-IMU READY
→ replay H0s 并发布 /cmd_vel
→ 路径/录制边界结束
→ 发布零速度并停止 trial 节点
→ 自动执行 G2S postflight
```

正常结束会自动停车。`Ctrl+C`、runner 失败或中途异常时也有零速清理逻辑，但实车现场仍必须保持急停可用。

默认 bag：

```text
/home/geist/slosh_bags/real/20260731_spmpc_g2s_source_selection/H0s_Bsmooth/DEV_G2S_H0s_C1_Bsmooth_u<ROW>_a01.bag
```

## 7. 每条结束后

只有脚本退出码为 0，且输出明确包含 postflight `PASS` 时，才允许进入下一条。

两条之间：

```text
确认零速并退出
→ 保留本条 bag/postflight/log
→ 小车回到相同起点
→ 重新对齐
→ 等待液体完全静稳
→ 执行下一个 G2S_ROW
```

失败 bag 和日志不得删除。不得因方法效果不好而重跑换成成功样本；只有被冻结 verifier 判定为方法无关 acquisition failure 时，才能另行授权 `G2S_ATTEMPT=02`。

## 8. 步骤 4：4 条全部 PASS 后分析

```bash
G2S_DATE=20260731 \
bash /home/geist/scout_ws/src/scout_apps/control/spmpc_local_planner/scripts/analyze_spmpc_g2s_source_selection.sh
```

分析脚本会按 trial 比较两路 observer 与在线 RGB 标量的一致性。processed-IMU 只在同时满足以下条件时才被选中：

1. 聚合改善至少 `10%`；
2. 至少 `3/4` trial 改善方向一致；
3. 结果不由单条 trial 独占；
4. READY 和 RGB 覆盖率不劣化。

若改善相当、方向冲突、覆盖率劣化或证据不确定，默认保留 odom。

## 9. 分析后的停止点

生成 G2S source-selection report 后立即停止。当前不允许直接执行：

- W2/W5 G2C；
- G3 RGB efficacy；
- Stage I 40 条；
- Stage II-A/B。

若保留 odom，下一步是在 odom source release 下准备 G2C。若选中 processed-IMU，则必须先完成与该决策绑定的 source-specific method release、延迟/状态年龄处理和无命令回放验证，才能进入 G2C。

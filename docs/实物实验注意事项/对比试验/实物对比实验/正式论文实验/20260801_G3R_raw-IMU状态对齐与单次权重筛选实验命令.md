## 6. 自动检查和停止规则

每条脚本自动检查：

- effective weights 与冻结矩阵完全一致；
- `delay_phase_mode_code=2`，delay compensation applied fraction `<=2%`；
- record-to-motion `<=23 s`、首次到达 `<=42 s`，并完整保留到达后 5 s RGB tail；
- raw/predicted/SolverInput 状态诊断非空，SolverInput source code 的 processed-IMU 覆盖率 `>=98%`；
- W2/W5 确实消费 processed-IMU；Bsmooth 只记录 observer；
- IMU READY `>=98%`，无 reset、fallback；
- `GOAL_REACHED`、tracking、runtime、RGB/tail、image-free 全部通过。

Row 05 后自动生成：

```text
/home/geist/slosh_bags/real/20260801_spmpc_g3r_raw_imu_weight_screen/H0/G3R_WEIGHT_SCREEN_REPORT.json
/home/geist/slosh_bags/real/20260801_spmpc_g3r_raw_imu_weight_screen/H0/G3R_WEIGHT_SCREEN_METRICS.csv
```

若有正向候选，还会生成：

```text
G3R_CONFIRMATION_PLAN.draft.json
```

此时先停止实车。必须将所选候选和三组配对顺序冻结到新 release，才能继续确认采集。若 `NO_PROMOTION`，本轮立即停止，不重复任何条件。

单次筛选的正向门槛为：相对 Row 01，RGB P95 至少改善 `0.05 mm`、RGB RMS 不恶化、raw processed-IMU P95 恶化不超过 `0.05 mm`。若多个候选同时为正，冻结排序分数为：

```text
RGB_P95改善 + 0.5×RGB_RMS改善 + 0.25×max(raw_IMU_P95改善, 0)
```

`SCREEN_INVALID` 表示数据完整性、绑定或 postflight 有问题，不等于 `NO_PROMOTION`；遇到它应停止并分析故障，不能选择性补录。

# 实物对比试验启动指南（无经验地图版）

> 目标：给实物 Scout 固定路径对比试验一套可执行的多终端启动顺序。本文只覆盖 **fixed-path 实物对比**，不启动经验地图 / Map-vref / R0-R2 profile lookup。
>
> 实物端命令默认工作区为 `/home/geist/scout_ws`；如果在开发机检查命令，把路径替换为 `/home/a/scout_ws`。

---

## 0. 本轮到底要启动哪些

实物对比不是一个总 launch，而是按下面模块逐个启动：

| 顺序 | 模块 | 作用 | 是否所有方法共用 |
|---:|---|---|---|
| 1 | 传感器/定位/底盘栈 | base、CAN、LiDAR、Cartographer localization、IMU、RealSense | 是 |
| 2 | 相机固定参数 | 固定 RGB exposure/gain/white balance，避免组间光照漂移 | 是 |
| 3 | 在线 RGB 液面观察 | 现场看 `/liquid/height`、debug image、zero 是否正常 | 是；只作现场观察 |
| 4 | standalone slosh monitor | 统一评价 proxy，记录 `/slosh/*` | 是；外部 baseline 不允许用作控制输入 |
| 5 | 固定路径/目标发布 | 发布同一条 `/scout/global_path_fixed` 和 `/scout/goal` | 是 |
| 6 | 全量 RGB rosbag recorder | 正式证据链，保留 RGB、odom、cmd、planner debug | 是；必须先于 planner 启动 |
| 7 | SPMPC variants | `B0`、`B_slosh`、`B_ours`、可选 hard-cap | SPMPC 内部消融 |
| 8 | LT-DWA official wrapper | 先 shadow，再 bounded `/cmd_vel` | 外部 online baseline |
| 9 | Hamaguchi / Lim profile baseline | 离线 profile baseline + common tracker | 补充液体抑晃 baseline |
| 10 | DWA / TEB / mpc_local_planner tuned | 先 N=1 smoke，再决定是否进正式表 | 外部 nav-core baseline |

本轮**不启动**：经验地图、Map-vref runtime lookup、profile lookup、地形条件晃液经验地图采集。

统一关闭口径：

```bash
rosparam set /spmpc_local_planner/map_vref/runtime_v_ref_enable false
rosparam set /spmpc_local_planner/map_vref/profile_enable false
```

普通 `B_ours` 的期望状态是：`/spmpc/debug/map_vref_status = VARIANT_FALLBACK`，而不是 `PROFILE_LOOKUP` / `RUNTIME_OVERRIDE`。

## 1. 实物安全红线

1. 任一时刻只允许一个 planner 有效发布 `/cmd_vel`。
2. 每个 actuated run 前必须检查：
   ```bash
   rostopic info /cmd_vel
   ```
   确认没有旧 planner publisher 残留。
3. 第一轮一律 shadow：把 `CMD_TOPIC=/spmpc_shadow_cmd_vel` 或保持 `publish_cmd_vel:=false`，只看 topic、TF、path、status、raw command。
4. 只有现场急停/遥控/安全员就位后，才把 `CMD_TOPIC=/cmd_vel` 或 `publish_cmd_vel:=true`。
5. 60s 内未到点算 FAIL；明显离轨、原地转圈、朝人/障碍物运动，立即急停并计入失败/NO-GO。
6. 外部 baseline（LT-DWA、DWA、TEB、mpc_local_planner、Ham/Lim）不得订阅 `/slosh/*`、`/liquid/*` 或 RGB 液面结果作为在线控制输入。
7. 失败 run 不能删除；bag/log 保留，进入 success/failure 统计或标注 invalid。

### 7.2 正式 fixed-path 对比：S-curve 模板

终端 A 先启动 path generator 等待目标：

```bash
PATH_FILE=${PATH_DIR}/fixed_s_curve_compare.json

rosrun scout_local_planner template_fixed_path_generator.py \
  --template s_curve \
  --goal-topic ${GOAL_TOPIC} \
  --output-topic ${REF_TOPIC} \
  --path-file "${PATH_FILE}" \
  --start-heading current \
  --spacing 0.05 \
  --amplitude-ratio 0.18 \
  --min-amplitude 0.25 \
  --max-amplitude 1.20 \
  --side left \
  --smooth-iterations 3 \
  --publish-count 0
```

终端 B 发布固定终点（坐标必须根据现场安全路径替换）：

```bash
rosrun scout_local_planner send_fixed_goal.py \
  --goal-topic ${GOAL_TOPIC} \
  --frame map \
  --x <goal_x> \
  --y <goal_y> \
  --yaw <goal_yaw> \
  --repeat-count 5 \
  --repeat-rate 5
```

RViz 人工确认：路径不穿墙、不贴墙、不穿人、不贴障碍物；确认后才进入 planner smoke。

## 9. SPMPC 启动模板

### 9.0 相位延迟显示/补偿开关

SPMPC 的相位延迟没有单独的“显示开关”参数，统一由 `delay_phase_mode` 控制：

| `delay_phase_mode` | 是否显示/记录诊断 | 是否预测执行状态 | 是否真正补偿控制 |
|---|---:|---:|---:|
| `off` | 否 | 否 | 否 |
| `monitor` | 是，只看 odom/cmd 时序 | 否 | 否 |
| `shadow` | 是，显示预测/对齐情况 | 是 | 否 |
| `fixed_closed_loop` | 是 | 是 | 是，guard 通过才改 `SolverInput` |

只想现场观察相位延迟、不影响控制时，用：

```bash
delay_phase_mode:=shadow \
delay_phase_linear_delay_sec:=0.15 \
delay_phase_angular_delay_sec:=0.22
```

只看 odom/cmd 时序时，用：

```bash
delay_phase_mode:=monitor
```

真正实物补偿时才用：

```bash
delay_phase_mode:=fixed_closed_loop \
delay_phase_linear_delay_sec:=0.15 \
delay_phase_angular_delay_sec:=0.22
```

必录/必看 topic：

```text
/spmpc/debug/delay_phase
/spmpc/debug/odom_timing
/spmpc/debug/execution_state
/spmpc/debug/execution_alignment_status
/spmpc/debug/delay_compensation
```

`/spmpc/debug/delay_compensation` 数组含义：

```text
mode_code, closed_loop_enabled, linear_delay_ms, angular_delay_ms, shadow_valid, status_code
```

判读口径：

```text
closed_loop_enabled=1：补偿实际参与控制；
shadow_valid=1 且 closed_loop_enabled=0：预测有效，但只是 shadow/或 guard 未通过；
mode_code=3：fixed_closed_loop 模式。
```

## 13. 推荐实验顺序

### 13.1 上车当天 smoke 顺序

```text
1. 传感器/定位/相机/RGB/recorder 链路空跑检查。
2. fixed straight path：B0 shadow。
3. fixed straight path：B0 低速 actuated，v_ref=0.20，60s 内到点。
4. fixed straight path：B_ours fixed_closed_loop 低速 actuated。
5. S-curve：B0/B_ours N=1 smoke。
6. LT-DWA official wrapper shadow。
7. LT-DWA official wrapper bounded actuated smoke。
8. Hamaguchi / Lim shadow -> actuated smoke。
9. DWA/TEB/mpc_local_planner tuned N=1 smoke。
```

### 13.2 正式 N=3 交错顺序

不要一个算法连续跑完三次。推荐：

```text
Round 1: B0 -> B_ours -> LT-DWA -> Hamaguchi -> Lim
Round 2: Lim -> Hamaguchi -> LT-DWA -> B_ours -> B0
Round 3: LT-DWA -> B0 -> Lim -> B_ours -> Hamaguchi
```

如果 DWA/TEB/mpc_local_planner 也进入正式表：

```text
Round 1: B0 -> B_ours -> LT-DWA -> DWA -> TEB -> mpc_local_planner -> Hamaguchi -> Lim
Round 2: Lim -> Hamaguchi -> mpc_local_planner -> TEB -> DWA -> LT-DWA -> B_ours -> B0
Round 3: LT-DWA -> B0 -> TEB -> Hamaguchi -> B_ours -> DWA -> Lim -> mpc_local_planner
```

每个 run 之间：

```text
停 planner -> 发 /cmd_vel zero -> 停 bag -> 回起点 -> 等液体静稳 60~90s -> 查 /cmd_vel publisher -> 开下一轮 recorder -> 开 planner
```

## 14. 每个 run 的现场 gate

起步前必须逐项确认：

```bash
rostopic info /cmd_vel
rostopic echo -n 1 /odom
rostopic echo -n 1 /map
rostopic echo -n 1 /scan_front
rostopic echo -n 1 /camera/color/image_raw
rostopic echo -n 1 ${REF_TOPIC}
rostopic echo -n 1 ${GOAL_TOPIC}
```

人工确认：

```text
E-stop / 遥控急停就位: yes/no
/cmd_vel 无旧 publisher: yes/no
RGB online zero locked: yes/no
bag recorder 已启动: yes/no
RViz path/goal/定位正常: yes/no
机器人周围安全: yes/no
液体已静稳 60~90s: yes/no
```

停止条件：

```text
明显离开 fixed path；
原地转圈或小 linear.x + 大 angular.z 持续约 2s；
60s 未到点或 progress 长时间不增长；
/odom、TF、/map、/scan_front 异常；
容器松动、液体溅出风险；
SPMPC 出现 TRACKING_UNSAFE_PROJECTION / SPIN_FAIL / ACADOS_SOLVE_FAILED；
LT-DWA bridge diagnostics 长时间异常或 final command 不合理；
现场人员认为不安全。
```

## 16. 后处理口径

正式比较至少同时报告：

```text
success / failure / invalid count
first-goal time / duration
tracking RMS / p95 / max / final error
RGB max-LCR peak / p95 / RMS / AUC
/slosh/height peak / p95（proxy）
cmd_v、cmd_omega、dv/dt、domega/dt
SPMPC delay closed_loop_enabled_frac
LT-DWA guard_applied rate / latency
```

液面结论优先写成：

```text
在同等完成率、同等 tracking 或同等速度附近，B_ours 的 RGB 液面风险更低。
```

不能只用 raw peak 下结论；慢方法天然晃得少，必须同时看时间、速度和 tracking。

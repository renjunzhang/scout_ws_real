# SPMPC 论文对比实验设计建议

> 本文是论文对比实验的 canonical 设计文档。
> `20260603_SPMPC连续MPCC实物对比实验SOP.md` 只作为执行 SOP；`20260602_实物端代码拉取与子模块注意事项.md` 只作为部署/移植说明。

## 0. 总口径：不是重选 baseline，而是建立证据链

最终实验不要把所有方法混在一张表里，而是做到：

```text
一组实验只回答一个问题。
```

论文主线要证明：

```text
1. slosh model / slosh monitor 和真实液面响应有基本对应关系。
2. fixed-path 临界场景中，slosh-aware horizon cost 有因果贡献。
3. 相比 TEB / DWA / mpc_local_planner 等非液体感知 baseline，B_ours 不是自研框架内部自嗨。
4. P2P、扰动、容器/液位迁移只做补充，证明可用性和泛化性。
```

不要现在引入 EXACT-MPPI、Nav2 MPPI、learning planner 或复杂动态障碍 planner。它们会把主线带偏。当前主线是：

```text
液体运输任务风险感知的 continuous MPCC local planner。
```

## 2. Main Experiment 2：Fixed-path critical scenario internal ablation

这是最核心的主实验。目的：在容易激发晃液的 fixed-path 临界场景中，证明 slosh-aware horizon cost 的因果贡献。

### 主消融方法

| 方法 | 定位 | slosh state/cost | smooth | 说明 |
|---|---|---|---|---|
| `B0` | internal non-slosh MPCC baseline | 否 | 否 | 只能称为内部 non-slosh MPCC baseline，不等同于 de Groot 2025 / mpc_planner 完整复现 |
| `B_smooth` | smooth-only baseline | 否 | 是 | 回答“只靠平滑控制能不能降晃” |
| `B_slosh` | slosh-only ablation | 是 | 否 | 回答 slosh-aware 模型/代价是否有效 |
| `B_ours` | final method | 是 | 是 | 完整方法 |
| `B_accel` | optional supplemental | 否 | 弱 | 无 slosh state，只加强瞬时加速度正则，用来回答“是不是只是加速度小” |

`B_accel` 不进入默认主矩阵，除非最终论文叙事需要。它必须满足：

```text
不传播 slosh modal state
不用 eta / eta_dot cost
不读取 /slosh/*
不把 slosh height 用进控制、调参或轨迹优化
```

### 临界路径建议

优先构造容易激发晃液的 fixed path：

```text
S-curve
连续左右转
急停接转弯
U-turn
短距离 fixed-path + terminal stop
```

> 路径设计提醒：让急转 / S 弯**避开起点、前面留一段直线引导段**，使起步加速激励与过弯激励在时间/弧长上分开。
> 否则（如当前 `P2_s_curve` 急转压在前 30%、与起步重叠）过弯抑晃会被起步 lurch 淹没，"仅 S 弯段"指标也会失效（见 §7 去前 2s 口径）。

### 难度 sweep

可以系统调这些变量：

```text
v_ref 增大
转弯半径 R 减小
曲率 kappa 增大
终点停车距离缩短
液体填充高度变化
容器尺寸变化
```

更机器人化的解释：

```text
lateral excitation ≈ v^2 * kappa
longitudinal excitation ≈ a
```

理想现象：

```text
低难度：大家都能完成，晃液差距不大
中难度：B_slosh / B_ours 开始降低液面峰值
高难度：B0 / B_smooth 晃液明显，B_ours 保持更低风险
```

## 3. Main Experiment 3：Fixed-path external planner comparison

目的：证明不是自研框架内部自嗨。

### 方法

| 方法 | 定位 |
|---|---|
| `B0` | external 表里的 SPMPC non-slosh anchor，说明不是 continuous MPCC 本身带来的全部收益 |
| `B_ours` | 我们完整方法 |
| `TEB` | 传统优化式局部规划 baseline |
| `DWA` | 传统速度采样局部规划 baseline |
| `mpc_local_planner` | 权威 optimization baseline；跑稳后进正式表，否则 diagnostic |

### 公平性要求

```text
同一起点或可解释的小范围定位误差
同一目标
同一地图
同一 fixed path 或同一 global path
同一 v_max / omega_max
同一 acc limits（线加速度 0.6；角加速度 1.2 rad/s²：SPMPC 在 OCP 内约束 |ω̇|<=alpha_max，TEB/DWA 用 acc_lim_theta）
同一 footprint
同一 goal tolerance 与成功判定阈值（统一 0.20 m：SPMPC terminal/goal_tolerance、TEB/DWA xy_goal_tolerance、指标 success 距离阈值都用 0.20）
同一 controller frequency 或记录实际频率
同一统计窗口
同一 RGB 后处理脚本和阈值
所有失败 run 记录并进入统计
TEB/DWA/mpc_local_planner 未加入 slosh model
SPMPC warm-start 只用在线可获得信息
```

## 5. TEB / DWA / mpc_local_planner 公平性处理

TEB / DWA 不能直接拿默认参数就说它们差。正式实验前按固定流程：

```text
1. 先调到能稳定完成 fixed-path / P2P 任务。
2. 再在统一或可比的速度、角速度、线加速度、角加速度限制下调平滑性。
3. 不允许为某一个 run 单独调参。
4. 所有正式 run 使用冻结后的固定参数。
5. 所有失败 run 必须记录并进入统计，不能删失败样本。
```

允许的普通保守调参：

```text
降低最大速度和最大角速度
限制线加速度和角加速度
提高轨迹/速度平滑性
减少急转、急停和终点震荡
```

禁止：

```text
不给 TEB / DWA / mpc_local_planner 加 slosh dynamics
不给它们加液体高度代价、eta/eta_dot 代价或 slosh-aware optimization
不把 /slosh/* 作为控制反馈、调参输入或轨迹选择依据
不把魔改后的 slosh-aware TEB/DWA 当作标准 TEB/DWA baseline
```

论文表述建议：

```text
TEB and DWA were first tuned to reliably complete the task under comparable physical constraints. Their smoothness-related parameters were then tuned conservatively. All baseline parameters were frozen before formal evaluation and were not adjusted per run. They do not use the proposed slosh dynamics or slosh-aware cost.
```

## 6. `/slosh/*` 数值监控口径

可以在所有方法中运行 `slosh_models` standalone monitor，用来统一记录模型预测液面高度和液体状态。

口径必须写清楚：

```text
/slosh/* 是评价信号，不是 baseline 控制信号。
```

允许：

```text
用同一个 slosh monitor 对所有方法记录 slosh height / eta / eta_dot。
```

不允许：

```text
让 TEB / DWA / mpc_local_planner 根据 slosh height 改速度、改轨迹、改 cost 或调参。
```

当前 standalone monitor 接口：

```text
输入：/odom，/cmd_vel 仅 debug
输出：/slosh/height，单位 m
输出：/slosh/state，[x_m, vx_mps, y_m, vy_mps]
输出：/slosh/debug，记录 dt、速度、加速度估计、height、计数器
reset：/slosh/reset
```

注意：

```text
/slosh/height 使用 SI 单位 m，指标脚本会统一换算成 mm。
/spmpc/slosh_height 是 SPMPC 内部 debug，单位 mm。
```

fixed-path suite 中显式打开：

```bash
SLOSH_MONITOR_ENABLE=true
```

## 7. 指标建议

主体段统计窗口（两端都要裁）：

```text
pre_terminal_phase = 1          # 去掉终点停车段
且 t > t_move_start + 2.0 s      # 去掉起步从静止猛冲的 lurch
```

> 为什么去前 2s：实测 slosh peak 主要由起步加速 lurch(t≈1s)贡献，不是过弯
> （B_ours 全程 36mm → 去前 2s 12mm）。不裁起步会把"谁起步猛"误读成"谁晃"，
> 五个变体会挤在一起分不开（见 20260606 / 20260607 仿真记录）。t_move_start 取
> odom 速度首次 > 0.05 m/s 的时刻；统一起步 ramp 或路径加直线引导段亦可，本口径统一用"去前 2s"。

主体段报告：

```text
success rate / failure count
tracking error RMS / p95
slosh height peak / p95          # 窗口 = pre_terminal 且去起步前 2s
eta_dot peak / RMS
cmd_v / cmd_omega smoothness
odom ax / ay p95
solver time
```

不要只比 raw slosh peak（慢 = 天然少晃，会把"谁慢"当成"谁懂液体"）。主结论用同工作点对比：

```text
slosh–速度 / slosh–tracking / slosh–完成时间 的 Pareto
报告"同等速度或同等 tracking 下 B_ours 的 slosh 更低"
```

terminal 停车段单独报告：

```text
stop distance
final speed / final omega
stable stop bool
terminal slosh peak
cmd_v jump / deceleration
```

视觉真值报告：

```text
RGB max-LCR peak / p95 / RMSE / AUC
统一 ROI / HSV / calibration / 后处理脚本
```

## 8. 推荐论文表格组织

不要一张表塞全部方法。

```text
Table 1: slosh model validation
  modal predictor / standalone monitor vs visual height / acceleration proxy

Table 2: fixed-path critical ablation
  B0 / B_smooth / B_slosh / B_ours
  optional supplementary: B_accel

Table 3: fixed-path external baseline
  B0 / B_ours / TEB / DWA / mpc_local_planner if stable

Supplementary Table A: P2P navigation
  B0 / B_ours / TEB / DWA

Supplementary Table B: robustness / transfer
  selected perturbations and fill/container parameters

Supplementary Table C: engineering ablation
  primitive / anti / continuous MPCC, warm-start, terminal policy
```

结论口径：

```text
fixed-path 内部消融证明方法组成；
fixed-path 外部 baseline 证明相对普通局部规划器/优化式规划器的优势；
slosh model validation 证明评价/预测模块与真实液面有对应；
P2P、robustness、transfer 作为补充，不抢主线。
```

## 9. 仿真实施命令

所有 bag/log/统计结果放 `/data/a`。

### 9.1 fixed-path 仿真启动原则

不要在同一个 Gazebo session 里连续用 `/gazebo/set_model_state` reset 后跑多个方法。这样容易残留定位、odom、TF、costmap 或 planner 内部状态。

正式或半正式对比建议：

```text
一个方法 / 一组方法跑完 -> 关仿真 -> 重新 fresh 启动仿真 -> 再跑下一个方法。
```

仿真启动后先等约 30s，让定位/TF/costmap 稳定，再发布 `/scout/global_path_fixed`：

```bash
PRE_PATH_WAIT_SEC=30
```

### 9.2 启动 fixed-path 对齐仿真

终端 1：

```bash
source /opt/ros/noetic/setup.bash
source /home/a/scout_ws/devel/setup.bash
cd /home/a/scout_ws

SIM_ENV=open \
USE_RVIZ=true \
SPAWN_X=3.4484412831971465 \
SPAWN_Y=0.2053595972008268 \
SPAWN_Z=0.1 \
SPAWN_YAW=-3.0815575130115853 \
rosrun scout_local_planner launch_sim_nav_stack.sh
```

这里 `USE_RVIZ=true` 会打开 Gazebo GUI；如果设成 `false`，通常是后台 `gzserver`，不一定弹窗口。

终端 2：确认 ready：

```bash
source /opt/ros/noetic/setup.bash
source /home/a/scout_ws/devel/setup.bash

rostopic echo -n 1 /odom
rostopic echo -n 1 /gazebo/model_states
rostopic echo -n 1 /map
```

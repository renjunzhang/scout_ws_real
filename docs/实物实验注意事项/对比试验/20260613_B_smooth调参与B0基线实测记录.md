## 实验目的

## B_smooth 调参历程（全部失败）

B_smooth 的 `smooth_priority_enable: true`（variants.yaml 中 w_smooth=1.0）与 S 曲线路径跟踪存在根本矛盾：smooth cost 压制频繁小角度换向，导致 OCP 在弯道处做出少而大的急转，触发 UNSAFE_PROJECTION 或终点振荡。

### 原因分析

```text
1. smooth_priority_enable=true 在 OCP 目标中增加 smooth cost（w_smooth=1.0），
   与 S 曲线需要频繁方向调整的本质矛盾。
2. B0（smooth_priority_enable=false）前天 20260611 同路径同终点轻松通过，
   今天 v_ref=0.65 再次通过，验证了 B_smooth 的失败不是路径或定位问题。
3. 降低 v_ref 到 0.50 勉强可到点，但伴有 TERMINAL_SPIN_FAIL 或 CAPTURE_STOP，
   无法形成与 B_ours 公平对比的稳定基线。
```

## 结论与下一步

```text
1. B_smooth 在当前 S 曲线路径上无法形成稳定基线——五组参数无一通过（无 UNSAFE、无 SPIN_FAIL、有 GOAL_REACHED）。
2. B0 已验证可行，v_ref=0.65 下输出限幅器施加额外安全层。
3. 下一轮：取消 B_smooth，直接用 B0 作为 tracking 基线，B_ours 作为 slosh-aware 候选，
   做 B0 vs B_ours 的 N=1 smoke 对比。
4. B_ours 参数使用 relaxed 首轮值：w_slosh=2, w_alpha=0.5, w_du=0.1, v_ref=0.65，
   只比 B0 多 slosh state + slosh cost + smooth_priority（B_ours 的 smooth_priority_enable=true, w_smooth=1.0）。
5. 若 B_ours 也因 smooth_priority 失败，需评估是否先关闭 smooth_priority，
   只保留 slosh state + slosh cost 进行更干净的消融。
```

```text

  processed-IMU I0 是当前唯一接受的液体输入方向
```

因此这一步不解锁 Stage 3，也不将开发集的候选小数写成实车标定。

## 2. 依赖边界

```text
identity.py
   +-- contract_source.py (Stage 0 原始字节 authority)
   |          |
   |          +-- Stage 3A manifest（保持原有 blocked/prohibited 语义）
   |
   +-- stage1_evidence.py
              |
              +-- development-only blocked reference
```

关键隔离：

- `stage1_evidence.py` 不导入 `layout.py` 或 `manifest.py`；
- Stage 3A 不读取 development evidence，不因其存在而改变 gate；
- development loader 只能返回 `stage1_freeze_allowed=false` 和 `stage3_codegen_allowed=false`；
- 未提供 freezer、production layout constructor、artifact SHA 或 `lmax_frozen` 布尔逃生口。

未来正式 `stage1_contract_v1` 必须由独立 freezer 消费通过门禁的原始 bag、report、分析器和分区身份；不会在当前 development loader 上增加一个 `frozen=true` 参数。

## 4. Fail-closed 行为

以下任一情况都拒绝：

- registry 原始字节、Stage 0 原始字节或两份源文档变化；
- JSON 重复 key、非有限数、未知字段或非小写 SHA-256；
- source path 越出仓库或不是普通文件；
- bag trial ID/SHA 重复、来源角色错配或伪称已在本机验证原始字节；
- 把 development 条目填入 validation/final-test；
- 改开 Stage 1 freeze/Stage 3 codegen gate；
- 将 I1/L22 接入 solver，将 legacy 有效窗口改名为 FOPDT 参数，或将候选状态改为 frozen；
- 删除、替换或重排必需的未冻结 authority 列表。

## 6. 正式 Stage 1 开放条件

下一个可生成 production authority 的阶段必须另行完成：

1. 安全地完成直线起停、前后向、左右转和正负换向的专用辨识重复；
2. 冻结互斥 development/validation/final-test 路径、原始字节 SHA、motion window、分析器与阈值；
3. 在未参与拟合的数据上通过线角分通道 fidelity gate；
4. 确认拟合参数近优区不触及搜索边界，再以开发集与物理裕量独立冻结 codegen `L_max`；
5. 独立 freezer 生成带完整证据链的 `stage1_contract_v1`。

只有该正式合同可被未来 production layout constructor 消费。

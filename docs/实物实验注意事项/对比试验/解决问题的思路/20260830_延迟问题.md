## 4. 最终命令到实际运动的同包模型

### 4.1 模型含义

本次用最终 `/cmd_vel` 的 bag 到达时间作输入，在同一 bag 内对齐 NOKOV、odom 和 raw IMU。拟合模型为“一段纯等待 + 一阶逐渐建立”：

```text
dy_real/dt = (K * u_cmd(t-L) - y_real) / tau
```

- `L`：曲线开始受命令影响前的纯时移；
- `tau`：开始响应后建立快慢；
- `K`：长期幅值比例；
- `t90 = L + 2.303*tau`：模型达到最终变化量 90% 的时间。

`t90` 不是纯延迟，尤其不能把角向约 `1.5～1.6 s` 直接写入 `angular_delay_sec`。

### 4.2 三包结果

| 响应链 | `L` | `tau` | `K` | R² | 模型 `t90` |
|---|---:|---:|---:|---:|---:|
| cmd v → NOKOV v | `80 ms` | `79～93 ms` | `1.045～1.051` | `0.935～0.941` | `0.262～0.293 s` |
| cmd v → odom v | `110～120 ms` | `100～118 ms` | `0.999～1.005` | `0.969～0.970` | `0.341～0.381 s` |
| cmd omega → NOKOV omega | `40～80 ms` | `625～677 ms` | `0.987～0.993` | `0.913～0.919` | `1.520～1.629 s` |
| cmd omega → odom omega | `40 ms` | `533 ms` | `0.937～0.941` | `0.952～0.954` | `1.268 s` |
| cmd omega → IMU gyro-z | `60～90 ms` | `625～677 ms` | `0.976～0.983` | `0.856～0.868` | `1.530～1.639 s` |

三种反馈给出相同方向：线速度约几百毫秒基本跟上，角速度要一秒以上才基本建立。NOKOV、odom 和 IMU 的具体 `L` 相差几十毫秒，既包含传感器时间差，也受滤波和 `L/tau` 耦合影响，不能任选一列当“真实底盘死时间”。

### 4.3 起步和停车的同级阈值检查

下表不是阶跃模型的 `t10/t50/t90`，而是当前实际斜坡命令与响应经过相同速度级别的时差：

| 事件 | NOKOV 10%/50%/90% 同级时差 | odom 10%/50%/90% 同级时差 |
|---|---:|---:|

起步明显比停车慢，说明单一线性模型还没有表达静摩擦、驱动死区或加减速不对称。当前路径的角命令主要是长斜坡，缺少清晰、可重复的正负阶跃；半幅 crossing 可以说明转向慢，但不能可靠冻结角向纯延迟。

## 5. NOKOV、IMU 和 odom 的时间关系

### 5.1 数学边界

定义：

```text
t_cmd    最终 /cmd_vel 发布
t_phys   真实刚体开始响应
t_nokov  Ubuntu 端 NOKOV 曲线看到响应
t_imu    /imu/data 曲线看到响应

d_act = t_phys  - t_cmd
d_N   = t_nokov - t_phys
d_I   = t_imu   - t_phys

L_cmd_nokov = d_act + d_N
L_cmd_imu   = d_act + d_I
Delta_N_I   = t_nokov - t_imu = d_N - d_I
```

现有软件 bag 只能观察组合量，不能唯一拆出 `d_act`、`d_N` 和 `d_I`。若要得到 NOKOV 的绝对曝光—解算—传输延迟，仍需要硬件触发或统一硬件时钟。

### 5.2 D02～D04 同包 NOKOV/IMU 结果

符号约定：负值表示 NOKOV 更早。

| bag | NOKOV 相对 raw IMU | 峰值相关系数 | 搜索边界 |
|---|---:|---:|---|
| `D02` | `-20 ms` | `0.963` | 否 |
| `D03` | `-10 ms` | `0.964` | 否 |
| `D04` | `-20 ms` | `0.966` | 否 |

bag time 与 header time 口径结论一致。独立 N02～N04 手推/转动试验此前得到 `-15 ms`，局部范围 `-15～-10 ms`。两组方向一致，但 raw IMU 约 `20 ms/样本`，所以正式口径仍是：**NOKOV 与 raw IMU 在 `±20 ms` 内基本同步，NOKOV 通常早约一个样本。**

这足以说明：NOKOV/IMU 之间的相对时差远小于角速度约 `0.6 s` 的建立过程，不是转弯慢的主体。

### 5.3 processed-IMU 时间戳审计

三包逐条审计结果完全一致：


## 8. 对 slosh 预测的影响

OCP 中液体受到的主要平面激励为：

```text
ax = a
ay = v * omega
```

实车执行链则表现为：

```text
计划 a/alpha
  → 每 33 ms 可能被下一次重规划覆盖
  → 最终 /cmd_vel
  → 纯时移 + 线/角不同的建立过程
  → 实际 v/omega/a/v*omega
  → 低阻尼液体的历史响应
```

当前 `ExecutionStatePredictor` 用命令历史作 ZOH 传播，并没有显式表达本次看到的分通道一阶建立动态。`fixed_robot_only` 在 B0 中只替换车体状态，不滚动液体状态，所以本次成功证明的是“车体时间对齐有帮助”，不是“fixed_closed_loop 的液体 rollout 已经正确”。

此外，前一周期远期 `a/alpha` 约有 `8～9%` 符号翻转，进一步说明 planned-input 与 realized-input 会随 lead 增大而分离。要把这条机制升级成 slosh 因果证据，仍需在同一条有效 slosh+RGB bag 上，从同一 `q0` 分别使用 planned input 和实际 IMU/odom input 回放，并在 held-out RGB 上比较误差。

因此当前可以写：执行延迟和慢角响应足以成为液体预测快速失真的重要机制；不能写：它已经被证明是液体误差的唯一根因。

## 9. 当前补偿决策

### 9.1 现在保持不变

```text
delay_phase_linear_delay_sec  = 0.15 s
delay_phase_angular_delay_sec = 0.22 s
```

理由：

1. 这是当前唯一经过直接 B0 实物 A/B 支持的在线窗口；
2. 它更像同时吸收底盘、odom 状态起点和信号带宽的“有效窗口”，不是纯硬件死时间；
3. 同包 FOPDT 虽然预测更好，但精确 `L/tau` 尚不可辨识；
4. 在线 predictor 目前也没有一阶执行器状态，直接把 `tau` 塞进纯延迟参数在数学上是错误的。

### 9.2 明确禁止的改法

- 不把 NOKOV/IMU 的 `10～20 ms` 相对时差加到 `0.15/0.22 s` 上；
- 不从 `0.15/0.22 s` 中直接减去 processed-IMU 的 `15 ms`；
- 不把线向最佳 `L=80 ms` 直接改成 `linear_delay_sec=0.08`；
- 不把角向 `t90≈1.5～1.6 s` 改成 `angular_delay_sec`；
- 不在 `/cmd_vel` 出口偷偷增加另一套延迟或限幅；
- 不让 B0 与 slosh 使用不同的基础车体执行模型，否则实验失去公平性。

### 9.3 可保留的离线描述模型

若只用于研究型离线 replay，可把三包 NOKOV 中位模型写成：

```text
linear:  L≈0.080 s, tau≈0.086 s, K≈1.050
angular: L≈0.070 s, tau≈0.677 s, K≈0.990
```

必须同时附带本文件的宽近优范围和 `INCONCLUSIVE` 标签，不能把这些小数当作已冻结实车标定。

## 10. 下一次专用辨识 bag 应解决什么

下一次不要再只依赖路径跟踪中的内生命令。应在安全速度和足够空旷场地内，单独设计可重复激励：

1. 线速度分别做起步、稳态、停车，至少重复 5 次；
2. 角速度做正向、负向和正负换向，给足稳定平台时间；
3. 线/角通道尽量分开激励，再补一组组合运动；
4. 同时录制最终 `/cmd_vel`、odom、raw IMU、NOKOV pose、底盘状态和全部时间戳；
5. 预先冻结命令波形、阈值、平滑窗和拟合区间，不看结果后再挑参数；
6. 用一部分重复拟合，保留独立重复作真正 held-out；
7. 若要拆出 NOKOV 绝对延迟，另加硬件触发或统一硬件时钟。

在此之前无需再次做危险的高速度路径试验，也无需修改在线补偿。

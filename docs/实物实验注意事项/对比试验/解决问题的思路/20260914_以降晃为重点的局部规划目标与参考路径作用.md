# 以降晃为重点的局部规划：目标与参考路径作用

> **2026-09-14 用户已确认方向：本方法定位为局部规划器，重点是在完成导航任务的前提下降晃。参考路径提供路线和进度引导，跟踪误差不作为主要成绩。** 本文的目标结构改造先形成具体方案，再落实代码；用户随后单独授权的四子步积分修正已实施、生成 solver 并编译，见第4节。尚未启动实车。
> 核对HEAD：`diag/lt-dwa-collision-tracking @ e91512e`。工作区四子步RK4修正已完成软件验证，实车收益待验证（见第4节）；局部规划目标新结构尚未实施。已有当日分析/交接/方案及代码修改保留，本次仅更新本文。

## 1. 今天结果带来的认识

`w_contour=0.5` 的 Full/Smooth 两包质量均 PASS。Full 全任务 IMU/odom slosh RMS 分别高18.6%/15.8%，到达后5秒残余分别低39.8%/22.4%；Full路径误差较小，耗时近似相同。完整证据和全部尝试见[当日分析第9节](../实物对比试验分析/20260914_C03当前版本J0.6_Full与Smooth修改前基线分析.md)。

这次降低的是**跟踪误差的权重**，没有要求实际误差增大。两组共同采用0.5，Full另有液体代价，其优化动作仍可能恰好更贴近路径；单凭这一对不能说明降低权重使跟踪变好，也不能证明tracking是降晃未改善的唯一原因。报告中的路径误差是定位快照到固定路径折线的几何距离，并非OCP相对虚拟进度点的contour/lag原始分项。

新的方向不是让Full故意偏离路径，也不是继续追求更小跟踪误差，而是**让规划器可以在明确的可行空间内，为降晃选择合适的局部轨迹、转弯方式和速度安排**。小范围速度/jerk/tracking权重试验没有建立重复的全任务收益，结束这轮扫描，转入目标结构与规划自由度的方案设计。

## 2. 用户确认的目标关系

| 层次 | 作用与要求 |
|---|---|
| 基本可行要求 | 轨迹无碰撞、满足车体和执行器运动边界，并能完成到达目标的任务。有限时域内的可行性与整个任务完成须分别设计、验证。 |
| 主要优化目标 | 减小液体激励与晃动，同时处理运动过程和真正终点的减速、停车及残余。不能用通用平滑指标替代slosh收益。 |
| 任务效率 | 保留适当进度与效率要求，报告耗时、路径长度等取舍；不能以停滞、无限降速或无意义绕行获得低slosh。效率边界尚未选定。 |
| 参考路径 | 提供导航方向、通道选择和进度关联；允许在可行区域内调整几何轨迹和速度。是否保留弱几何正则及其形式，留到具体方案确定。 |
| 跟踪误差 | 作为偏离程度的诊断量，不按“谁更贴线”评定局部规划器优劣；允许偏离也不等于允许越出可行区域。 |

“降晃优先”目前是方法目标，**不能只凭权重数字较大就宣称已实现优先级**。后续需明确目标的归一化、效率取舍及约束关系，并验证液体状态/预测是否实际改变轨迹选择。液体高度上限是否启用、软硬形式及不可行处理仍待设计；当前Full未启用液面硬约束，内部模型满足上限也不等于真实液面保证。

## 3. 当前已有能力与具体方案要补的内容

当前主线并非完全没有轨迹或速度自由度：[OCP模型](../../../../src/scout_apps/control/spmpc_local_planner/scripts/acados/spmpc_acados_model.py)已有车体位置、姿态、实际速度等状态，控制为`a_cmd/alpha_cmd/v_s`，通过车体和显式执行器动力学联合优化局部运动与进度。固定参考路径并不是强制机器人每拍位于曲线上的等式约束，`v_ref`也不是强制恒速。

但当前C03仍围绕固定参考曲线设置contour/lag、速度/anti-creep及progress目标。液体代价已生效，只将`w_contour`减半没有重新定义可活动空间、导航要求及降晃与效率的关系。当前后端的障碍OCP项尚未接入，[能力检查](../../../../src/scout_apps/control/spmpc_local_planner/src/ros/spmpc_local_planner_ros.cpp)会拒绝`obstacle_enable=true`；不能把已有状态变量或松弛跟踪误差视为已经具备完整避障规划能力。

下一份具体改造方案需要回答：

1. **轨迹可以在哪里变化？** 明确局部可行区域或通行走廊的来源、边界、车体尺寸与余量，以及参考路径如何保持路线关联。走廊是候选表达方式，宽度、生成方法和节点间碰撞检查尚未确定。
2. **哪些要求是边界，哪些是取舍？** 分开定义避碰/运动可行性、任务进度、终点要求、液体目标和参考路径正则；检查现有速度与低速惩罚是否与降晃所需的减速冲突，不直接把所有tracking权重置零。
3. **液体如何影响轨迹选择？** 保持IMU观测初态、执行器前推和未来OCP的信息流清楚；在相同车体/液体初态和可行区域下比较Full/Smooth的候选轨迹、速度、实际发布命令及液体响应，而非只看加权cost占比。
4. **模型与执行是否支持这一选择？** 在一致作用点、坐标和时间基准上检查预测激励与实际激励，区分任务内动作和停车阶段；沿用已有安装偏移/旋转耦合、执行器与停车分析，不把未验证缺项当作唯一根因。

无碰撞是方法的基本要求；当前仅确认设计方向，真实障碍物实验没有因此自动提前。可先在明确边界的无障碍区域验证轨迹选择与降晃关系，再按实现能力讨论障碍场景。无需等唯一根因查清才设计候选，但不能用同一个模型中预测更小的高度自证实物改善。

## 4. 六点排查：从液体项接入到实际决策

**排查主线更新为：液体目标怎样改变动作 → 模型是否准确预测动作效果 → 动作是否带来实际降晃收益。** 液体代价生效已核实，暂不重复排查“只加状态、没加目标”。已录C03基线和最新预测/积分诊断分别见[当日分析第5～6、10～11节](../实物对比试验分析/20260914_C03当前版本J0.6_Full与Smooth修改前基线分析.md)；旧包负结果与新积分版本的软件结果分开解释。

| 排查点 | 当前判断与下一步 |
|---|---|
| 状态是否进入cost/constraint | 已确认液体代价进入实际OCP，基线四包精确cost重建通过；不是只有液体状态的被动预测。仍需验证它是否改变动作。 |
| 约束/代价是否起作用 | 当前Full未启用液面硬约束，不能用“未碰到上限”解释收益不足；液体二次代价没有必须超限才生效的门槛。 |
| 实际代价数量级 | 基线液体项与tracking同量级，未见数量级淹没。在线统计仍需修正anti-creep漏项、曲率速度参考及阶段/终端缩放，分项之和应等于实际目标。 |
| 跟踪与速度要求是否压缩选择空间 | 小跟踪误差不能证明tracking过强；要一起检查contour/lag、速度跟踪、anti-creep和progress，判断扩大转弯半径或提前减速的代价。 |
| 工况激励是否足够 | 保留为一般检查项；当前已有Full全任务指标变差的结果，优先解释动作为什么没有产生预期收益，不先提速制造差异。 |
| 预测时域是否足够 | 当前已有2秒、60步；已确认区间内部积分偏粗，先修数值精度，再按需要评估时域，不混淆二者。 |

**约束不激活，不等于液体目标不起作用；cost数值大，也不等于决策影响大。** 优化器比较候选动作带来的$\Delta J$，应在相同初态、环境和其他设置下检查速度、转向时机与局部轨迹的变化。“相同增广模型下液体目标开/关”检查目标作用；“保留液体目标、观测初态/零初态”检查状态反馈作用，两者不同，NoState仍后置。

### 4.1 接续四步

1. **先修积分精度（软件已完成，实车待验证）。** Full/Smooth每个33.3 ms区间共用4个RK4子步；30 Hz、2秒时域、物理参数和权重不变，控制量与延迟队列头在区间内固定，FIFO和加速度记忆每周期只更新一次。自定义`DISCRETE`需修改离散表达式并重新生成solver，不能只调ERK积分选项。当前实现、双solver生成、编译和软件检查已完成；简化自由衰减算例两秒振幅包络误差由约−36.6%降至+0.0074%，独立复算一致。这是数值精度证据，不能换算成实车收益或已解释的预测偏差占比；证据见当日分析第11节。
2. **再查预测收益为何未兑现。** 统一初态、时间、坐标及液体作用点，按下表分离原计划变化、执行器激励误差和液体数值传播误差。旧版五个Full已见初态接近、远期高度明显低估；随后闭环包含反复重规划，不能全部归为液体物理模型错误。IMU高度仍是实测加速度驱动的模型指标，不是液面真值。

| 重放比较 | 要回答的问题 |
|---|---|
| 原计划／实际发布命令（同初态、同模型重放） | 后续重规划和命令处理是否改变了原计划的消晃动作？ |
| 实际命令重放的加速度／IMU加速度 | 同样的命令是否产生了执行器模型预期的激励？ |
| 同一激励下的OCP／监视器传播 | 积分修正后，液体传播是否一致？ |

3. **然后设计局部规划目标。** 修准代价统计，共同明确可行区域、车体尺寸/余量、允许减速的效率预算和防停滞要求，据此调整速度跟踪、anti-creep与progress，并检查虚拟进度与位置的一致性。若需要主动偏好缓弯，可另选曲率正则，先处理低速时的定义，并由Full/Smooth共用；具体公式和权重尚未确定。由于$a_y\approx v^2\kappa$，减速和减小曲率都可能有效，Full不必更偏离参考路径。
4. **液面硬约束单独验证。** 积分修正后固定场景和其他参数，依据预测峰值与可行性逐步收紧上限，观察动作变化、约束激活及求解状态，并明确不可行处理和延迟段不可避免超限的处理方式。模型内满足上限不等于真实液面保证。

安装偏移、旋转耦合继续分版本安排。提速、收紧高度上限、降低tracking权重应拆成独立开发对照，每次只改变一个因素；目标结构版本按“明确方案 → 修改OCP并生成solver → 离线闭环验证 → 短smoke → 同版本新包配对”推进，不把各版本收益混在一起。

## 5. 后续验证与已有文档的衔接

接续顺序以第4节为准：先核对积分修正版本的运行质量及预测/执行差异，再落实目标、约束、可行空间和版本边界的具体方案。目标结构实施后做离线闭环验证，检查轨迹自由度、液体项的决策作用、约束满足及求解/执行稳定性。复用已有MPCC、显式执行器、时间对齐、监视器、录制与离线工具，不预设重写整个规划器。

进入实物时，Full/Smooth共享相同环境、可行区域、导航目标、运动边界和非液体任务要求，避免只给Full额外空间。保留现有IMU主评价与odom并列参考，主要比较全任务slosh RMS，同时报告峰值、中段、停车后残余、任务完成、耗时、路径长度和运行质量；跟踪误差明确作为诊断项。若新增边界/碰撞或效率有效性条件，须在新包前明确并冻结，不能录后调整。选定候选后再用新的两对包复验，模型、滤波、统计窗口或协议改变时重新冻结。

本文更新的是**当前要讨论的局部规划目标结构**；停止单纯围绕tracking权重继续筛选，先明确轨迹选择的可行空间与目标关系。与[9月12日联合避障备忘](20260912_避障与防晃联合局部规划后续思路.md)共享方法定位，但没有授权立即启动避障实物实验。[cost/参考/时域排查](20260912_C03后续_cost参考跟踪与预测时域排查思路.md)和[模型一致性、液面约束与停车分版本安排](20260913_模型一致性液面约束与停车处理分版本验证安排.md)保留为技术参考，其实施顺序需在新方案中统一。

目标结构当前只记录方案，具体数值、数学优先级、走廊实现及新实验协议尚未确定；第4节四子步修正已有软件测试，不代表目标结构已实现或实物正向。RGB/NoState后置，NOKOV仅作辅助运动记录，不恢复NOKOV液体模型、自转或5Hz标定支线。

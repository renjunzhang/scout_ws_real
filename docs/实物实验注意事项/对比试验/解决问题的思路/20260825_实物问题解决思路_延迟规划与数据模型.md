# 实物问题解决思路：延迟、液面规划与数据模型

日期：2026-08-25

状态：阶段性思路记录，后续根据实验结果逐步细化。

## 总体思路

当前按以下顺序解决问题：

> 先快速排查延迟问题，再推进“考虑液面晃动的规划 + MPCC”两层方案；如果仍没有明显进展，再转向基于数据的模型，并优先用于轨迹生成。

## 1. 尽快进行敏捷测试，排查延迟问题

首先设计一个规模小、准备快、能够重复的敏捷测试，重点检查：

- 控制器计划的动作与最终发布命令是否一致；
- 机器人收到命令后，实际速度和转动经过多长时间才开始响应；
- 实际运动相对计划动作是否存在明显的幅值误差和相位滞后；
- 这些差异是否足以解释液体预测随时间迅速失真。

这一步的目的不是立即证明减晃有效，而是尽快判断当前主要问题是否来自命令延迟和底盘执行。如果延迟问题明确，就优先补充或修正车体、执行器模型，再进行后续控制实验。

### 1.1 2026-08-31 阶段性回答

以 3 包有效 `fixed_robot_only` 实物数据为主，当前可以简要回答为：

| 问题 | 当前回答 | 主要数据 |
|---|---|---|
| 控制器计划的动作与最终发布命令是否一致 | **当前周期立即执行的第一个命令一致**，未被后续限幅器改写；但规划中更远的动作会在约 `33 ms` 后被下一次规划重写，不保证原样执行。 | 正常跟踪段 `solver_cmd = published_cmd = /cmd_vel`，线、角命令差的 P95 和最大值均为 `0`；远期加速度的符号翻转率约 `8%～9%`。 |
| 收到命令后多久开始响应 | 底盘不是立即跟上，而是“短暂等待后逐渐建立速度”。 | `/cmd_vel` 到 NOKOV：线速度纯等待约 `80 ms`，再经 `79～93 ms` 逐渐建立；角速度纯等待约 `40～80 ms`，但建立过程长达 `625～677 ms`。 |
| 实际运动是否有明显幅值误差和相位滞后 | **长期幅值误差不大，但过程中的滞后明显，尤其是转向。** | NOKOV 线速度幅值比约 `1.045～1.051`，角速度约 `0.987～0.993`；模型达到 90% 变化量约需线向 `0.262～0.293 s`、角向 `1.520～1.629 s`。 |
| 这些差异是否足以解释液体预测快速失真 | **足以成为重要原因，但尚未证明是唯一原因。** 规划动作会被频繁改写，实车又会延迟且缓慢地执行，因此液体模型使用的未来激励与真实激励会逐渐分离。 | 同一路径下 `shadow` 未到终点，3 次 `fixed_robot_only` 均到达终点；但本轮 B0 关闭了 slosh，还需要同一初始液体状态下的计划输入/实际输入回放和 RGB 对照来完成直接验证。 |

注：上述延迟数字是“等待 + 逐渐响应”的闭环拟合结果，不能把角向 `1.5～1.6 s` 直接当成纯延迟补偿值。当前仍保留经实物 A/B 支持的线/角 `0.15/0.22 s` 补偿基线。详细证据见 [20260830_延迟问题.md](./20260830_延迟问题.md)。

## 2. 采用“液面规划 + MPCC”两层方案

在排查执行延迟后，进一步让液面晃动同时进入规划层和控制层：

- **规划层：** 在生成路径、速度或时间安排时考虑液面晃动，尽量得到容易执行、晃动较小的整体运动方案；
- **MPCC 层：** 在机器人实际运行过程中跟踪规划结果，并根据当前状态进行局部修正，同时继续考虑液面变化。

最终目标是形成“上层规划整体减少液体激励、下层 MPCC 保证跟踪和实时修正”的两层结构，避免只依赖每个控制周期内较远期、容易被重新规划覆盖的减晃动作。

## 3. 必要时转向基于数据的模型

如果完成延迟排查和两层规划控制后，实物结果仍没有明显进展，则考虑使用实物数据建立模型。

基于数据的模型首先用于**轨迹生成**：根据已有的命令、实际运动和液面测量数据，寻找更可能减小液面晃动的路径或速度安排。这样可以先离线检查模型是否能产生可重复、可执行的轨迹，再决定是否将其进一步用于在线预测或控制。

## 推进顺序

1. **近期：** 完成延迟敏捷测试，确认“计划动作—发布命令—实际运动”的主要误差；
2. **中期：** 建立考虑液面晃动的规划层，并与 MPCC 组成两层方案；
3. **后备：** 当前两条路线仍无进展时，建立数据驱动模型，并先用于离线轨迹生成。

三条路线按证据依次推进，不在同一轮实验中同时修改延迟模型、规划结构和数据模型，避免实验结果无法解释。

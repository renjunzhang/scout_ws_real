## 3. 本阶段冻结的语义

Stage 0 只冻结不会依赖辨识结果的结构合同：

1. `ML-01`～`ML-16` 全部存在且顺序固定。
2. B0/Bslosh 共用完整模型和执行链，只允许 `condition` 与 `liquid_objective_scale=0/1` 不同。
3. steady clock 生成绝对 `1/30 s` 网格，边界使用 `round_nearest(k*1e9/30)`，不累计截断、不跳拍。
4. model clock 只通过冻结 clock anchor 映射，不允许与 steady time 隐式混用。
5. stage state 是 `T_k^-` 的 pre-issue state：

   ```text
   x = robot/progress(6) + publisher(4) + delay taps + liquid(4)
   NX = 14 + D_v + D_omega
   u  = [j_issue_v, j_issue_omega, v_s]
   NU = 3
   ```

6. `issue_map(x0,u0)` 只从权威 publisher state 和 jerk 生成本拍命令，不接受 measured velocity 输入。
7. delay 维度、三槽 execution 参数布局和 `NP_exec` 公式固定，但 `L_max` 数值未冻结。
8. `N=60`、`dt=1/30 s`、right-endpoint liquid running、`x_K` boundary、tail/terminal liquid cost 为零。
9. `1 <= K_liquid < N`；development 首候选为 `8/10`，validation 对照为 `3/5/8/10`。
10. proposal 不是事实；只有 final publish 成功后才能提交 history、publisher state、delay generation、warm start 和 `s_commit`。

上述合同在 ROS-free 头文件中形成窄类型和纯数学接口，尚未接入生产节点。

## 4. 验证协议冻结

机器合同同时冻结 development/validation/final-test 的互斥规则、final-test 一次性解封规则、执行器 fidelity 指标、逐未来 bin 液体 skill、工程门、B0 门和 Bslosh 正式符号约定。

当前三个数据分区都为空。这是有意的 fail-closed 状态：没有专用 bag 与 SHA-256 前，不得把旧路径跟踪 bag 自动分配为新模型的 validation/final-test。

第一版门保持方案原值，包括：

- 线/角分别裁决，final-test median RMSE 相对最佳旧模型不高于 `0.90`，每条不高于 `1.05`；
- onset error 不超过一个 nominal step，`t90` 相对误差不超过 `15%`；
- 液体未来 bin 为 `0/100/167/267/333 ms`，只用随后真实 emitted command；
- target solver P95 `<25 ms`；
- B0 `|Δv| P95 <= 0.005 m/s`、强翻转为零、各通道饱和率不高于 `5%`；
- `Delta = metric(B0)-metric(Bslosh)`，正值才表示改善。

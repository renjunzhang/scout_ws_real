## 1. 已确定的方向

先做一个小改动，再用三组实物开发对比验证：

1. 保留现有执行器模型、速度接口、液体状态和虚拟进度优化，在已有完整时域 `Δa_cmd` 软惩罚上增加硬约束，暂不重构成 jerk 控制。
2. 首轮候选只改变这一项；速度设置、`w_slosh`、其他权重及执行器参数保持冻结，先完成离线验证和低速 smoke。
3. 观察是否形成提前减速、过弯调速、出弯再加速；若没有，再单独检查 anti-creep 是否使局部减速代价过高。
4. 通过开发门后录 RGB，先比较 Smooth-only、NoState、完整 S-MPCC；加入“完整方法去 jerk”可单独评价新增硬约束的贡献。

**命令变平滑只是中间结果。三组用统一监视器计算内部液体高度作为模型指标，同时结合 RGB 液面晃动、完成时间和跟踪误差判断；论文关注液体预测与历史状态记忆是否带来额外收益。**

## 2. 已确认事实与尚未证明的机制

- `064e5e6` 已实现完整时域 `Δa_cmd` 软惩罚及加速度记忆状态。上述 SHA 的已提交基线尚无本次硬约束；9 月 7 日工作区实现了可开关的约束。显式执行器 B0/Bslosh 状态维度仍为 24/28，控制仍为 `[a_cmd, alpha_cmd, v_s]`。
- 2026-09-06 的 full-da smoke 运行链正常，但相邻输出差分 P95、转弯约 5 Hz 幅值只下降 `33.8% / 42.3%`，未达到当次各下降 `50%` 的门。该包无 RGB、无新 B0 配对；这证明当时的软惩罚版本平滑改善不足，不能证明真实降晃改善或恶化。
- 同包振荡主要已存在于预测计划内部。69 个快照的特定去频带扰动降低了平滑代价，却全部提高液体 running 代价和总目标；这只说明当前模型对该扰动的偏好，不证明原动作对实物有效。
- 现有 matched-processing 诊断发现模型与 I0 的约 5 Hz 激励幅相存在明显差距；独立 NOKOV 分析也报告车体振动。结构、驱动及测量链各自的作用仍需核实，不能把硬约束当作已解决根因。
- 既有 9 月 3 日有效 RGB 配对中，Bslosh 比同设置 B0 更差，已停止继续该批配对。新候选不继承实物有效性，也不续补旧批次。

当前机制假设是：模型可能利用了实物难以按预测准确兑现的快速动作。硬约束会限制这类动作，但也可能限制有用的补偿；是否有净收益需要实物证据。anti-creep 只是后续单变量检查对象，尚不是已确认原因。

历史结果见 [Block 1 及 full-da 分析第 11、12 节](../实物对比试验分析/20260903_I0显式执行器OCP_B0_Bslosh_Block1分析.md)；原实现主线见 [I0 与显式执行器 OCP 最小修复方案](20260903_I0与显式执行器OCP最小修复方案.md)。

## 3. 最小方法改动及边界

利用已有记忆状态，在所有控制 stage（当前 `N=60`）加入：

$$
a_{\mathrm{mem},k+1}=a_{\mathrm{cmd},k},\qquad
|a_{\mathrm{cmd},k}-a_{\mathrm{mem},k}|
\le j_{\max}\Delta t,\quad k=0,\ldots,N-1.
$$

- 保留原有软惩罚。代码默认 `jerk_max=1.0 m/s³`，但硬约束默认关闭；该数值仅是离线开发候选，实物上限尚未选定。
- 第 0 拍的 `a_mem` 使用实际最终发布命令历史，沿用当前重建语义；不能只接上一轮求解器的原始输出。
- 平滑基线、NoState、完整方法使用同一上限、同一控制周期和共同动作边界；“完整方法去 jerk”只关闭新增硬约束，保留软惩罚。外部对比方法不要求全部改造，其比较属于端到端系统评价。此处约束限制预测网格上的命令加速度差分，不等于已经约束了真实杯体 jerk；需另审计实际发布时间和 IMU 激励。
- 保留 fail_closed、common_epoch 和原有停车保护。安全干预后继续使用真实发布历史；不得伪造记忆状态、绕过停车或用事后夹紧掩盖不可行。
- 第一轮不同时调整 anti-creep、液体权重或执行器参数。是否出现有用的局部调速是观察结果，不是硬约束必然带来的行为。

注意版本混杂：9 月 6 日历史 bag 使用旧容器参数；当前配置已由 `d0c98a0` 修正为内半径 `0.01725 m`、液深 `0.053 m`，名义频率约 `5.15 Hz`。新候选与其对照须使用相同的冻结容器参数；回放旧 bag 使用其快照。不能把跨版本变化全部归因于新增硬约束。

## 4. 三组开发对比的准确含义

| 组别            | 送入 OCP 的液体初态                      | 未来液体预测与代价                                     | 要回答的问题                             |
| --------------- | ---------------------------------------- | ------------------------------------------------------ | ---------------------------------------- |
| Smooth-only     | 不参与液体优化                           | 液体代价关闭，只保留共同运动平滑设置                   | 通用平滑能做到什么程度？                 |
| NoState         | 每轮设为`[0, 0, 0, 0]`                 | 保留液体动力学、未来传播、running 和 terminal 液体代价 | 从零初态预测新动作引发的晃动，有何效果？ |
| 完整 S-MPCC     | 当前 I0 驱动并传播得到的内部液体模型状态 | 与 NoState 相同                                        | 保留此前累积的状态记忆是否进一步有益？   |
| 完整方法去 jerk | 与完整 S-MPCC 相同                       | 与完整 S-MPCC 相同，仅关闭新增变化率硬约束             | 新增硬约束带来多少改善？                 |

**NoState 不是 B0 加监控。** B0 的监控只计算和记录，不影响优化；NoState 的未来液体预测会进入优化代价并改变动作。它每轮只假设“此刻没有残余晃动”，不是让整个预测时域的液体状态一直为零。

NoState 的实现定义是：在完成共同时间对齐及前推后，仅将送入 OCP 的四个液体初态置零。车体状态、执行器状态、FIFO、命令记忆和共同保护不置零；后台 I0 可以继续传播和记录，不能把监控状态清零冒充实物已静止。完整 S-MPCC 的初态仍是内部模型状态，不是真实液体相位的直接测量。

NoState 与完整 S-MPCC 除液体初态输入规则外，模型、权重、约束、求解与执行配置保持相同。三组使用共同非液体设置；“`w_slosh` 保持不变”指两组液体方法使用同一冻结正权重，Smooth-only 的液体权重为零。本轮不同时为各组单独调平滑权重。

同一版代码和三个 launch 入口现已支持这些功能组合；以 `B_slosh` 为共同非液体配置来源，通过显式开关构造各组，避免切换到不同权重的现有 variant。开关组合与日志见第 7 节；新增 `run_spmpc_ablation_smoke.sh` 开发入口复用旧 smoke 引擎支持四组单包采集，旧冻结入口和正式 RGB/ABBA 协议仍保持各自语义。

### 4.1 统一液体监视器与时间对齐（本次讨论补充）

三组采用相同的独立液体监视器：输入各自实物试验的 processed-IMU 激励，使用相同容器参数、坐标/作用点、滤波、初态准入和传播规则，整段持续计算 `H_monitor = c_h * sqrt(eta_x² + eta_y²)`，比较其 P95、RMS。这里“独立”指评价状态与 OCP 输入修改解耦，不表示它是独立于模型的物理测量。NoState 仅清零送入 OCP 的初态，不能清零评价监视器；也不能拿被清零的 `H_ocp,0` 和完整方法的监视器高度比较。

用户特别强调：**监视器必须注意时间对齐。** 后续实现和分析统一遵守：

1. **按测量时间推进。** 当前 processed-IMU 定义 `measurement_stamp = source_stamp - sensor_delay`；I0 优先把该时间用作 `state_stamp`，并用接受的 `sample_dt_sec` 做变步长精确 ZOH。监视器沿用并核验这套输入区间语义，不使用 bag 接收时间、回调时刻或固定 30 Hz 求解周期替代传感器间隔。源码有退回 `source_stamp` 的兼容分支，评价数据若走到该分支须标记，不能静默与正常时间口径混合。
2. **状态时刻与传播区间一致。** 核对实际接受的相邻样本间隔、累计传播时间和输出 `state_stamp`，记录重复、乱序、丢样、重置及有效区间。缺失段不能填零，也不能漏掉时间间隔却继续把状态标成最新时刻；处理规则三组一致。
3. **滤波延迟与传感器延迟分开。** 当前另有 `accel_effective_stamp`、`gyro_effective_stamp`、`alpha_effective_stamp`；它们描述不同分量的名义滤波延迟。不可把这些分量强行当成同一物理时刻，也不可在已有补偿后再统一减一次延迟。模型激励与 processed-IMU 对比优先复用既有“模型侧套用同一处理链、按 measurement_stamp 比较”的口径；这不自动证明真实物理相位已标定。
4. **跨信号使用对应的绝对时刻。** OCP 第 `k` 步按实际初态 epoch 的 `t0 + k*dt` 对应监视器状态；最终命令按实际发布时间，RGB 按采集/曝光时间及独立核验的时钟偏移对齐。监视器不额外加减执行器延迟来追齐命令，控制器的 common-epoch 前推状态也不冒充原始监视器测量时刻。
5. **统一窗口和补偿规则。** 三组预先冻结共同的起动/到达事件定义、重采样、有效覆盖及时间偏移处理。RGB 对齐使用独立标定或预先冻结的规则，不逐包寻找“最像模型”的平移量。不确定的时延做统一敏感性分析，报告范围；`common_epoch` 通过不等于物理相位正确。约 5 Hz 下，20 ms 就对应约 36° 相位差。

监视器模型高度与 RGB 分别报告：前者评价实测运动在统一液体模型下的响应，后者评价真实液面。两者都有误差，不能因 RGB 有测量误差就把内部模型高度当作液面真值。上述内容是监视器的待落实合同，本次没有实现新监视器或完成新的时间标定。

核对入口：[IMU 时间戳构造](../../../../src/scout_apps/control/spmpc_local_planner/src/estimation/processed_imu_pipeline.cpp)、[I0 变步长传播与状态时间戳](../../../../src/scout_apps/control/spmpc_local_planner/src/estimation/slosh_observer_bank.cpp)、[既有激励一致性分析第 12.6 节](../实物对比试验分析/20260903_I0显式执行器OCP_B0_Bslosh_Block1分析.md)。

## 5. 验证顺序与决策

| 阶段              | 检查内容                                                                               | 进入下一阶段的条件                                       |
| ----------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 离线              | 原配置复现；新约束全时域及第 0 拍是否生效；可行性、求解时间、速度/动作边界及预测跟踪   | 候选满足预先确定的门；单拍区间非空不等于全时域或闭环可行 |
| 低速 smoke        | 运行链、停车保护、发布历史；命令差分与约 5 Hz 能量；IMU 激励；实际局部调速、跟踪及耗时 | 运行与动作指标通过；无 RGB 时只判运行和平滑，不判降晃    |
| 三组 RGB 开发对比 | 共同路径、容器、速度及动作边界，预先固定批次数和随机顺序，统一起始静置条件             | 联合评估液面、耗时、跟踪和成功率，保留全部失败与负结果   |

实物采集前补齐 `j_max`、候选配置 hash、开发批次数、有效性/停止阈值和输出目录。保留原有停止规则；新门须预先定义，不能在看到结果后为通过而放宽。至少记录完整 horizon、送入 OCP 的初态、最终发布命令、I0/IMU、里程计、求解状态与干预标志；RGB 阶段增加带时间戳的液面原始证据。

模型指标使用统一运动窗口的 `H_monitor` P95、RMS；实物效果评价使用 RGB 液面 P95，并同时报告 RGB RMS、完成时间、跟踪误差和失败。两类指标分别解释，本次不改正式协议的主终点。机制图使用实测运动重建的 `t(s_proj)`、速度和激励；OCP 的 `s_ocp` 不当作实际执行进度。

- 命令平滑而 IMU 仍有强约 5 Hz 振荡：优先受控固定命令回放，核对执行/车体动态及测量链，不仅继续加平滑。
- 完整 S-MPCC 改善 RGB，且任务代价可接受：再准备等耗时 Smooth-match 和 Fixed-profile 对比。
- 完整 S-MPCC 未显示超越 NoState 的可靠收益：不能主张历史液体状态记忆具有额外实物价值，也不能仅凭不显著就断言两者等效。
- 开发三组通过不等于论文正式验证通过；本次没有决定替换正式 B0 或更改正式样本量、随机表与推断规则。

## 7. 2026-09-07 显式开关实现记录

启动参数为 `slosh_enable`（默认 `inherit`）、`zero_liquid_initial_state`（默认 false）、`jerk_limit_enable`（默认 false）和 `jerk_max`（默认 1.0）。液体预测开关覆盖所选 variant 的 `slosh_enable`；其余读取自节点私有命名空间 `ablation/*`。试验中不热切换。组合方式：

| 内部条件        | slosh_enable         | zero_liquid_initial_state | jerk_limit_enable |
| --------------- | -------------------- | ------------------------- | ----------------- |
| 平滑基线        | false，液体权重设 0  | false                     | true              |
| NoState         | true，相同正液体权重 | true                      | true              |
| 完整方法        | true，相同正液体权重 | false                     | true              |
| 完整方法去 jerk | true，相同正液体权重 | false                     | false             |

- 生成器为两种模型增加同一条线性混合约束 `C*x + D*u = a_cmd - a_cmd_memory`，覆盖 stage 0..59。运行时设置 `±jerk_max*dt`；关闭时设为 `±1e15`。状态和参数维度不变，已重新生成两种求解器，之后切换参数无需重复 codegen。
- NoState 在求解器内部复制已对齐/前推的输入，只将副本的四个液体初态置零；warm start 与 OCP 初态采用同一副本。调用者状态、后台 I0、时间戳、执行器和命令历史保留。整个未来液体 horizon 和 running/terminal 代价继续存在。
- 第 0 拍使用真实发布历史。求解失败不夹紧历史；成功结果额外检查全时域相邻命令差分，超过约束上限加 `1e-6 m/s²` 数值容差时返回失败，不发布该候选动作。
- `effective_config` 在原字段后追加开关和上限；`PreSolveSnapshot`、`PredictedHorizon` 更新为 schema 5。快照同时保存实际 OCP 的 `eta_*` 和修改前的 `observed_eta_*`，以及开关、`jerk_max`、实际 `delta_a_max`。不能只按 variant 名字识别组别。

## 1. 实施边界

本子阶段新增 ROS-free 的 `ActuatorDiscreteModel`，把已冻结的 pre-issue 单拍语义组装为一个完整、固定容量、失败原子的离散 map。它复用：

- Stage 0 的 jerk 到 `q_issue/a_issue` 代数映射；
- Stage 2c 的分通道延迟 schedule、三槽并集和 one-hot target selector；
- Stage 2d 的解析 FOPDT、actual 中点位姿与 actual 节点激励 RK4 物理核。

它不读写 `PublishedCommandHistory`，不调用只能在真实 `kPublished` receipt 后执行的 `advanceAfterPublished()`，不接 known-prefix、progress projector、ROS 或 acados。

Stage 1 仍为：

```text
BLOCKED_PENDING_DEDICATED_IDENTIFICATION_EVIDENCE
```

因此当前模板宽度、delay、tau、gain 与液体参数只出现在合成测试中，没有写入正式 preset，也没有生成 Stage 3 artifact。

## 2. pre-issue 状态与固定顺序

输入状态是发布边界 `T_i^-` 的：

```text
physical       = pose + actual + liquid
progress       = s
publisher      = q_prev_v/q_prev_omega/a_prev/alpha_prev
delay older    = 两通道各自的固定容量 older taps
```

单拍严格按以下顺序执行：

```text
1. issueCommand(publisher, jerk, dt)
2. Q(0)=q_issue，Q(1)=q_prev，Q(r>=2)=older[r-2]
3. 用启动时冻结的三槽 selector 选择每段线/角 target
4. PiecewiseZohPlantIntegrator 传播 pose/actual/liquid
5. 按每个物理子段累加 s += delta*v_s
6. stage 末更新 publisher state，最后 shift older queue
```

selector 永远在 shift 前读取 pre-issue 历史。因此对整数延迟 `M*dt`，本边界的 `q_issue` 在 `T_i+M*dt` 之前不能影响 target、actual、pose 或 liquid；当 `M=1` 时，改变本拍 jerk 不会经由命令导数泄漏到本拍物理传播。

`NQ=1/2/4` 及线角不同宽度都由模板类型显式实例化；`older` 容量仍严格为 `max(0,NQ-2)`。

## 3. 虚拟进度语义

均匀 OCP stage 内有当前决策变量 `v_s`，因此完整 map 按子段时长传播：

```text
s_next = s + sum(delta_r * v_s)
```

`v_s` 必须有限且非负；负值或非有限值 fail closed。这不改变 known-prefix 的边界：历史 emitted 事件不包含权威 `v_s`，后续 `KnownPrefixPropagator` 仍只传播 physical/publisher/queue，不能调用本 map 猜测历史 `s`。

## 4. 失败原子性

`step()` 是无异常运行时边界。它先在局部 `Result` 中完成 issue、selector、物理传播、progress 与 shift，只在全部有限且合法后一次赋给调用方 output。以下任一失败都保留 output 的原始比特语义：

- 非有限初态或历史 tap；
- 负/非有限控制；
- issue map 溢出；
- selector/tap 非法；
- 物理传播的中间量或结果非有限；
- progress 累加溢出。

`trySelectDelayTarget()` 为 release/prefix 可复用的无异常选择边界；selector 不是有限 one-hot 或任一 tap 非有限时返回 `false`，不改写 target。

## 5. 独立 complete-map golden

合成 fixture 使用 `dt=1 s`、线/角 delay 分别为 `0.5/0.25 s`、`NQ_v=NQ_omega=4`，得到三段：

```text
duration       = [0.25, 0.25, 0.50]
linear target  = [1.0, 1.0, 5.0]
angular target = [-1.0, -0.5, -0.5]
```

测试中的最终 pose/actual/liquid 是由实现外独立计算并硬编码的 golden，同时核对：

```text
s_next                    = 10.7
publisher_next            = (5.0,-0.5,6.0,0.5)
linear_older_next         = [1.0,3.0]
angular_older_next        = [-1.0,2.0]
```

额外测试覆盖零延迟当拍 issue、一拍整数延迟无泄漏、连续两拍 shift、线角不同 `NQ`，以及所有主要失败路径不改写 sentinel output。

这些测试只证明 C++ 合成离散顺序，不证明实车 fidelity。Python/CasADi 同公式 parity 必须等 Stage 1 冻结实际维度后才能进入 Stage 3。

## 1. 目标和证据边界

本子阶段只把 Stage 0 已冻结的状态、控制和 execution parameter prefix 公式变成一份可测试的纯 Python 布局合同。它用于提前发现 `D/R/NQ/NX/NU/NP_exec`、名称和 offset 漂移，不导入 CasADi/acados/ROS，不生成 solver、header 或动态库。

Stage 1 仍缺少专用辨识数据划分、gate hash 和正式 `L_max`。因此这里的 `0.10/0.14 s` 只用于覆盖整数/非整数维度公式，既不是候选 preset，也不能进入生产配置或 manifest。

## 2. 单向模块边界

```text
contract_source.py       layout.py
        \                   /
         \                 /
          ---- manifest.py
```

- `contract_source.py` 只读取 Stage 0 机器合同，以 pinned SHA-256 `2a9b1fdd91a474af5894a23b9cb882a94580204ea76cea1fc95ec13ce80508bd` 校验其完整原始字节，并证明 `Stage 1=BLOCKED`、`Stage 3=PROHIBITED`、两个 `L_max` 与 dataset gate 仍为 unfrozen。相同字段但重新编码或改写过的 JSON 也不能取得 authority。
- `layout.py` 只展开结构公式。唯一 purpose 是 `STAGE3A_SYNTHETIC_NO_ARTIFACT`；不存在 `lmax_frozen=True`、`synthetic=True` 两个可组合布尔门，也不存在调用者自报“已冻结”的生产入口。
- `manifest.py` 只生成 `LAYOUT_ONLY_STAGE3A` 身份文档。builder 不接受调用者手工构造的 reference，只接受 Stage 0 文件路径并在内部读取 pinned bytes；它没有 `GENERATED` 状态，不接收 artifact SHA、生成命令或 toolchain 元数据，任何新增 artifact 字段都会被严格 schema 拒绝。

该依赖方向使布局公式不依赖身份、文件系统或生成器，Stage 0 读取也不依赖布局。只有最外层 scaffold manifest 同时消费两者。

## 3. 当前冻结范围

当前布局文档显式标记 scope：

```text
STATE_CONTROL_AND_EXECUTION_PARAMETER_PREFIX_ONLY
```

它覆盖：

- pre-issue state 顺序与 `NX=14+D_v+D_omega`；
- `u=[j_issue_v,j_issue_omega,v_s]` 与 `NU=3`；
- `R_c=ceil(L_max,c/dt)`、`D_c=max(0,R_c-1)`、`NQ_c=R_c+1`；
- 三槽 execution prefix 的完整展开顺序、selector offset 和 `NP_exec=7+3*(NQ_v+NQ_omega)`；
- Stage 0 的 `N=60`、`dt=1/30 s`、model/discretization/cost schema 名称。

它故意不声明完整 `NP`。manifest 内持续列出生成 artifact 前尚缺的合同：Stage 1 冻结 authority、生产资源预算、完整 parameter layout、cost expression、constraints、solver options、solver library 和 legacy generator 清退。仅有 `NP_exec` 时不得把 execution prefix 冒充完整 `p[k]`；旧 generator/CMake 的移除必须等唯一替代链通过后按计划单独提交，不能在 scaffold 阶段制造不可运行的半迁移状态。

`4096 retained commands/channel` 只是防止恶意 synthetic 输入导致无界 Python 展开的脚手架资源 guard。该值进入 layout identity，并明确列在 `production_resource_budget` 缺口之前；它不是 C++/目标机资源合同，也不能替代 `<25 ms P95` 性能门。

## 4. Fail-closed 行为

以下情况全部拒绝：

- purpose 不是强类型 `STAGE3A_SYNTHETIC_NO_ARTIFACT`；
- scenario ID 非法，`L_max/dt/N` 非有限、越界或不是冻结网格；
- Stage 0 文件重复 key、Stage 1/3 gate 被改开，或 `L_max`/dataset gate 不再标记 unfrozen；
- 布局维度、名称、offset、selector、scope、资源 guard 或缺口列表被篡改；
- scaffold manifest 添加 runtime schedule、generation 或 artifact 字段；
- source contract、layout identity 或 SHA-256 不一致。

## 5. 验证和后续开放条件

新增 14 项 Python 合同测试，覆盖整数/分数/零上界、浮点边界两侧、状态/控制/参数顺序、不可变 builder 输出、单一 purpose、资源 guard、Stage 0 原始 SHA、gate 漂移、manifest 篡改和 canonical JSON。

正式 Stage 3 仍未开放。下一步必须按顺序完成：

1. Stage 1 产出带 dataset partition/gate hash、正式参数和 `L_max` 的强类型冻结合同；
2. 新建只消费该合同的 production layout constructor，不扩展本 synthetic purpose；
3. 冻结完整 `p[k]`（含 reference/slosh/cost coefficients）、cost、constraints 和 solver options；
4. 生成真实 solver library/header 后，从实际文件计算 SHA，再建立最终 codegen manifest 和 C++ 启动 hash gate。

在上述四项完成前，当前 scaffold 不能接入 generator 或生产启动路径。

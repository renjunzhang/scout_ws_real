# 液体模型一致性 V1：实现与离线验证

日期：2026-09-13。基线提交：`9abdea6c6f76d0387c0d3909b92627f32866d47d`。本版为工作区代码改造，未提交、未推送、未运行机器人。

本版只统一液体模型、激励时间和传播方式。代价统计、anti-creep、液面恢复松弛和任务终点处理继续分版本推进；不能把本版数值一致性解释为实测降晃有效。

## 1. 固定假设和接口

- 按用户确认，容器中心与 `base_link` 重合，容器轴与 base 轴一致；容器安装偏移为 `(0,0)`。
- 保留当前 IMU 标定：IMU→容器杆臂 `(-0.100,+0.045)` m、安装 yaw、陀螺仪标度和零偏处理、去重力及滤波参数。只补偿一次杆臂，IMU 加速度不再叠加 `v*omega`。
- 小幅、水平圆柱容器、单模态、相对容器阻尼。状态 `[eta_x,eta_x_dot,eta_y,eta_y_dot]` 是容器轴下的模态位移及相对导数，单位 m、m/s。
- `h_modal = c_h*hypot(eta_x,eta_y)`。现有可选 parabola 高度 proxy 保留，单独于模态高度和求解器模态约束。
- 保持 30 Hz、60 阶段、约 2 秒；模型版本 `liquid_model_version=1`，历史数据缺少该字段时按版本 0 处理。

令 `J=[[0,-1],[1,0]]`，共享方程为：

```text
q_ddot = -2*zeta*omega_n*q_dot - omega_n^2*q - a_C
         - 2*omega_actual*J*q_dot - alpha_actual*J*q + omega_actual^2*q
```

当前模态质量位移约定 `kappa_x=kappa_y=1`。`omega_n`、阻尼、`c_h` 继续由现有 `LiquidSloshModel` 物理参数计算；C++ OCP 包装层注入相同参数，不为观察器和求解器单独调参。

## 2. 共源代码与三条链

规划器相对路径均位于 `src/scout_apps/control/spmpc_local_planner/`：

| 位置 | 作用 |
|---|---|
| `scripts/acados/slosh_kernel.py` | 纯液体 CasADi RHS 与 RK4；不接触执行器、命令或队列 |
| `scripts/acados/actual_motion_kernel.py` | 组合执行器、车体与液体 RHS；生成 C 与 OCP 使用同一组合 |
| `scripts/acados/model_contract.py` | 模型版本、RK4 子步数/步长上限、CasADi 生成版本的共同定义 |
| `scripts/acados/generate_slosh_kernel.py` | 生成 `src/dynamics/generated/` 中纳入版本管理的 C 核与契约头 |
| `include/spmpc_local_planner/dynamics/slosh_types.h` | 独立液体状态、容器激励和系数类型；无机器人/ROS 依赖 |
| `src/dynamics/slosh_dynamics.cpp` | 只负责液体配置、高度和给定容器激励的受检传播；无机器人/执行器依赖 |
| `src/dynamics/actual_motion_propagator.cpp` | 联合传播实际执行器响应、车体和液体；不选择历史命令或移动 FIFO |
| `scripts/acados/spmpc_acados_model.py` | OCP 直接组合共享 RHS；保留 command/actual 分离和 5/10 拍延迟队列 |

| `src/ros/execution_state_predictor.cpp` | 已发布命令历史经执行器模型前推，联合传播车体和液体 |
| `src/warm_start/explicit_actuator_warm_start.cpp` | 由候选控制生成最终实际运动热启动；负责命令限幅/FIFO 更新并重算最终诊断 |
| `src/solvers/continuous_mpcc_solver_acados.cpp` | 选择 flatness/历史/保守种子，调用独立热启动模块，再交给 acados |
| `scripts/analysis/rotating_liquid_replay.py` | 无 ROS 离线激励/OCP 重放入口，保留真实初态、延迟队列与每阶段参数 |

预测端在每个 RK4 求值点计算 `a_actual=(gain_v*v_delayed-v_actual)/tau_v`、`alpha_actual=(gain_omega*omega_delayed-omega_actual)/tau_omega`，再用 `a_C=[a_actual,v_actual*omega_actual]` 驱动液体。`alpha_cmd` 只更新命令状态和队列。

OCP 每阶段 4 个 RK4 子步。测量/前推每段使用至少 4 子步，并限制子步不超过 1/120 秒；前推和 nowcast 仍按其各自的分段上限取激励。同初态、激励、区间及分段时 C++ 与符号传播一致；不同分段有相应的 RK4 截断误差。

历史 direct-omega/primitive 后端未完成完整旋转与实际执行器适配，因此本版 ROS 节点要求 `continuous_mpcc_acados + explicit_actuator`。旧后端代码保留，不作为本版运行配置。

## 3. IMU 对齐与诊断

共同有效时刻为 `source_stamp - sensor_delay - max(accel,gyro,alpha phase delay)`。默认相对 source 延后约 30.001 ms，较旧 measurement 时刻更早 15.001 ms。

先将每个滤波通道按其自己的有效时刻插值到该共同时间，再做 IMU→容器杆臂修正。缓冲区最多 512 个样本，无前后包围样本时保持 warmup/invalid，禁止外推；时间回退、重置和间断清空缓冲区。有效 excitation 的四个时间字段相等，实际数值也已经插值。原始滤波诊断字段仍是最新滤波输出，不代表对齐后的输入。

**固定相位延迟只是现有标定频带内的近似。** 本版没有建立宽频精确群延迟，也没有重新识别 IMU 外参或执行器参数。odom 的 `dv/dt, v*omega, domega/dt` 继续假设 twist 作用点与坐标是 base；没有新增侧滑观测。

`SloshObserverDebug` schema 升为 3；`PreSolveSnapshot`、`PredictedHorizon` 升为 6，三者增加 `liquid_model_version`。ROS1 消息 MD5 随之改变，节点和订阅/录包端需重建消息。模型契约头会使旧求解器生成物在编译时显式失败，必须重新生成 B0 和 slosh。

历史 G3/G4 重放和 C03 V2 评价入口拒绝版本 1 数据。V2 不能生成新模型的评价锁；以后冻结新协议时需纳入符号源、生成 C、消息定义、参数、构建库和评价器指纹。

## 4. 生成、检查与重放

生成环境固定为 **CasADi 3.7.2 + acados v0.5.4**。C++ 运行只依赖生成 C，不需要 Python/CasADi。完整 acados 生成物仍在原有忽略目录 `generated/acados/`，不手改生成物。

在规划器包目录下，用准备好的独立 Python 环境执行：

```bash
python -m pip install -r scripts/acados/requirements.txt
python scripts/acados/generate_slosh_kernel.py
python scripts/acados/generate_spmpc_acados.py --model b0 --check
python scripts/acados/generate_spmpc_acados.py --model slosh --check
# ACADOS_SOURCE_DIR、PYTHONPATH、动态库路径应指向已安装的 acados v0.5.4。
python scripts/acados/generate_spmpc_acados.py --model b0
python scripts/acados/generate_spmpc_acados.py --model slosh
python -m pytest -q scripts/tests/test_rotating_slosh_kernel.py scripts/tests/test_explicit_actuator_model.py scripts/tests/test_horizon_future_alignment.py scripts/tests/test_internal_slosh_freeze.py scripts/tests/test_internal_slosh_metrics.py
```

观察器重放使用 `horizon_liquid_replay.ModalParameters(..., liquid_model_version=1)`，每个 `ObserverInputSample` 必须携带实际 `omega,alpha`；版本 0 保留旧精确 ZOH，版本 1 调用共享旋转核。

OCP 重放可运行 `python scripts/analysis/rotating_liquid_replay.py input.json output.json`。输入 JSON 必须包含 `liquid_model_version=1`、完整 `x0`（24/28 个状态）、`controls`（N×3）和 `stage_parameters`（N 或 N+1 行）。字段顺序与 snapshot 一致；`x0` 应取实际 OCP 初态，控制应取对应候选序列，不能用只有 `a/alpha` 的历史即时执行重放代替。输出是动力学传播，不是重新求解或实测激励重建。

## 6. 本次结构整理及主线保护

整理基线是本次开始前的 **V1 工作区**，不是旧提交 `9abdea6` 的无旋转动力学。没有更改 V1 方程、积分规则、物理/执行器参数、代价、约束、jerk、命令发布或终点状态机，没有 commit/push。

依赖方向为：纯液体状态/激励 → 液体传播；执行器/车体 + 液体 → 联合传播；命令历史前推与最终热启动 → 联合传播。I0/odom/nowcast 直接向液体模块传入已对齐的容器激励。C++ 两种传播共享私有 `integration_policy.h`；生成物只通过生成脚本产生，支持后端的判断集中在 `solver_factory.h`。

统一受检接口：

```cpp
// 给定容器激励；失败返回 false，next 等于输入 state。
bool SloshDynamics::stepWithDt(const SloshState& state,
    const ContainerExcitation& excitation, double dt, SloshState& next) const;

// 固定延迟命令段内的联合传播；失败时两个输入/输出状态均保持原值。
bool propagateActualMotion(RobotState& robot, SloshState& liquid,
    const DelayedActuatorCommand& delayed, const ActuatorModelParams& actuator,
    const SloshDynamics& liquid_model, double dt);
```

已删除会在失败时悄悄返回原状态的 `step()`。观察器、nowcast、前推、热启动、历史采样后端和风险监视器均检查返回值。风险传播失败记录 `DYNAMICS_FAILED`，不报告可行、不推进 beta 滤波记忆；ROS 沿用原有 governor 无效输出的处理方式。历史前推传播失败记录 `DYNAMICS_FAILURE`。这些是明确的异常路径修正，不把失败解释为液体静止。

主线 flatness 和保守种子只生成几何/候选控制，随后与历史种子共用一次最终实际传播。最终状态序列完整成功后才替换候选；按最终序列重算 `max_v/max_omega/max_a/max_lateral_acc/max_slosh_height_pred/reference_fit_error/bound_violation_count`，保留种子来源标记。`bound_violation_count` 现在表示最终状态/控制的边界违反数量，不再混入几何构造时的限幅次数；最终参考误差只作诊断，不新增拒绝热启动的门槛。独立 flatness 工具的可选液体传播接口仍保留。

# 轨迹层与 MPCC 协同：代码修改方案

日期：2026-09-15。分支：`feat/spmpc-liquid-control`，基线 `f00ed4f`，核心实现来自 `ac18949`、`ba4a9c2`。状态：**供复盘的开发方案，新增模块、接口与剩余段检查尚未实现**。论文机制、适配边界和完整题录见[框架思路](20260915_轨迹层与MPCC协同框架思路.md)第 1.2、7 节。本轮只整理文档，未改控制代码或运行实验。

实施主线：**先定义完整任务优化 → 验证上层收益空间 → 接入按进度变化的全时域参考 → 从预测末端检查剩余运动 → 分因素评价。** 剩余段检查先离线运行；进入在线目标、约束或命令接纳之前，需要额外的机制与开销验证。

## 1. 当前已经有的基础与缺口

| 模块 | 已核对的当前代码 | 本轮处理 |
|---|---|---|
| 物理模型 | `scripts/acados/slosh_kernel.py`、`actual_motion_kernel.py`、`model_contract.py`，以及 `src/dynamics/` 的生成核和实际运动传播 | 复用旋转液体定义、command/actual 区分和四子步 RK4，规划层不另写一套方程 |
| 路径几何 | `include/spmpc_local_planner/reference/` 和 `src/reference/` 下的 `reference_path`、`reference_spline`、`progress_projector` | 保留路径输入；补齐轨迹参考所需的速度、时间与区域信息，检查拟合有效域和进度投影 |
| 求解接口 | `include/spmpc_local_planner/core/types.h` 的 `SolverInput` 只有当前 `v_ref_current` 等字段 | 增加完整轨迹参考上下文，保留原模式作为对照 |
| acados 包装层 | `src/solvers/continuous_mpcc_solver_acados.cpp` 把同一个巡航基准 `V_REF` 写入各阶段，代价内已有曲率限速与可选停车减速，几何采用局部三次拟合 | 抽取逐阶段参考装配，接入上层全程速度剖面，不只修改当前一个巡航速度值 |

| 代价核验 | `OcpCostEvaluator`、`generate_cost_kernel.py` | 新增项继续共源生成，分项之和与 solver 目标一致 |
| 终点与发布 | `SpmpcProblem`、`TaskStopManager`、`CommandHistoryBuffer`、ROS 发布链 | 复用真实终点协调和最终命令历史；轨迹层不直接发布 `/cmd_vel` |
| 剩余任务指导 | 当前有真实终点停车协调，没有本文所需的全程计划后缀评价接口 | 从预测末端完整状态评价候选剩余运动；不能把 `TaskStopManager` 等同于短时域末端的剩余可行性证明 |

以上相对路径均以 `src/scout_apps/control/spmpc_local_planner/` 为根。当前状态维度 B0/slosh 为 24/28，参数为 34/46，控制为 `[a_cmd, alpha_cmd, v_s]`；液体版本 1、代价版本 2，snapshot/horizon schema 7。新增参数和消息必须同步生成契约，不沿用其他分支旧维度。

已知首要工程问题是静止微负实际速度与预测非负边界的冲突；低速执行器、静止判定及 ROS1 整链也未验收。具体证据见[现状文档第 6 节](../../../../src/scout_apps/control/spmpc_local_planner/代码改进方向与现状.md)。这不阻止先设计离线规划，但不能把未解决的执行问题算成新方法失败或绕过它进入实车。

## 2. 先确定优化问题，再确定接口

### 2.1 论文启发对应哪些改动

| 现有不足 | 参考机制 | 本轮设计动作 |
|---|---|---|
| 原计划在在线调整后可能失效 | R08 的在线进度决策；R13/R19 的剩余可完成性 | 保留唯一进度，重新传播液体；增加候选剩余段评价 |
| 各目标相互牵制 | D19/D20 的 contour、lag、区域分工；R15 的二次目标 | 分开参考、目标和边界；记录有效参考与各项真实代价 |
| 先有模块清单，后有优化问题 | R32 的完整任务 OCP；C06 的联合参考接口 | 先固定已知量、变量、目标、初终条件及评价窗口，再选参数化 |
| 难以定位收益 | C11 的同平滑代价消融；R08 的 MPC/MPCC 比较 | 保留四组，增加同计划固定时序/在线进度对照；剩余段指导另作单因素比较 |

论文提供机制与结构参考，不直接给出当前 24/28 维系统的实现或参数。特别是 C06 的液体位移测量与独立平面加速度输入、R13/R15 的标量速度状态、R19 的历史成功后缀假设，均需适配。

### 2.2 首版上层问题合同

以下是待复盘的首版定义，不是已冻结实验协议。

| 项目 | 首版建议 |
|---|---|
| 已知量 | 路径及其坐标/弧长定义、完整初态、待执行命令、实际运动/液体参数、运动与活动区域边界、共同到达期限、停车窗口 |
| 动力学 | 用当前共源核传播 command/actual、FIFO、加速度记忆和液体状态；几何与 Scout 非完整运动相容 |
| 决策 | 全程可执行命令及由其得到的实际运动；先给定名义时长，速度节点、命令序列或进度 jerk 作为候选参数化比较 |
| 目标 | 模型防晃安排考虑全程液体响应、停车残余和运动代价；普通平滑安排保留共同运动目标，明确关闭哪些液体项 |
| 约束 | 完整动力学、真实初态、速度/角速度/加速度/jerk、路径或区域要求、目标位姿、共同期限；液体目标、恢复预算和已知物理边界分别记录 |
| 终点 | 几何到达、车体停稳、命令/FIFO/加速度记忆释放和液体稳定分别检查；不能只以 `s` 到终点或液体位移过零作为完成 |
| 评价 | 相同事件定义下的全程晃动、峰值、耗时、停车残余与所有失败；固定停车窗口，独立评价模型/液面数据另列 |

用 `z` 表示完整增广状态、`c` 表示可执行控制参数，首版按固定执行网格建立 `z[k+1] = F(z[k], c[k], dt)`。沿用 30 Hz 时，改变名义运输时长应通过规划步数或外层候选处理，不能随意缩放 `dt` 而保留原 FIFO 拍数，导致物理延迟同时改变。离线优化的网格、执行网格和积分子步分别记录。

候选目标可先写成 `w_H * J_full_liquid + w_R * J_stop_residual + w_U * J_motion`：前两项分别覆盖完整任务及固定停车窗口的液体响应、停车后的残余能量；运动项采用明确归一化的命令与变化量。初版各项的具体形式、归一化、权重与液体约束开关需在 P1 数值比较前写入配置。该目标是我们的适配，不冒称 R32 的原式或严格时间最优。

先找得到可执行、按时完成的普通平滑计划，再评估防晃增量。固定参考几何时，明确名义贴合方式及允许的实际跟踪误差；不得通过理想平面加速度、瞬时切换车速、重置状态或事后限幅生成看似可行的计划。R32 的进度 jerk 与当前命令加速度变化上限不是同一个量。

### 2.3 下层目标与剩余任务的责任

- **参考**：全时域提供随预测进度变化的运动参考；上层液体序列用于名义诊断，不赋给在线初态。
- **目标**：contour 调节横向偏离，lag 维护实际位置与进度的对应；实际/虚拟速度、anti-creep 和 progress 的语义共同核对。区域边界与速度上限单独作为约束。
- **进度连续性**：当前 `v_s` 是控制，`w_du_vs` 只对首阶段前次控制做平滑；R08 的进度加速度方案需单独评估。若增加进度记忆/变化率约束或改变状态布局，应作为独立行为改动，不能在接参考时隐式引入。
- **剩余任务**：首阶段只评价预测末端接候选后缀的结果；只有其进入目标、约束或明确的候选选择后，才可能影响动作。单个巡航参考、progress 奖励和当前真实终点停车模块不能替代这部分。

以下是拟新增路径，不表示文件已存在；目录均相对规划器包根目录。

| 拟新增位置 | 单一职责 |
|---|---|
| `include/spmpc_local_planner/reference/trajectory_plan.h` | 定义计划身份、名义样本、运动限制、任务时限和区域关联；不依赖 ROS 消息 |
| `include/spmpc_local_planner/reference/trajectory_reference.h` 与 `src/reference/trajectory_reference.cpp` | 检查和采样计划，提供按弧长查询的速度/时间/名义运动；处理端点、越界和版本不匹配 |
| `include/spmpc_local_planner/reference/horizon_reference_builder.h` 与 `src/reference/horizon_reference_builder.cpp` | 将当前状态、同一进度和名义计划装配成 N+1 个阶段参考，隔离求解器包装层中的装配逻辑 |
| `scripts/planning/trajectory_rollout.py` | 调用当前共源动力学，传播完整 command/actual、FIFO、jerk 记忆和液体状态，供离线优化及核验 |
| `scripts/planning/generate_slosh_trajectory.py` | 按第 2 节问题生成全程安排，导出计划与模型内可行性报告；报告不是独立对象的效果验证 |

| `scripts/analysis/analyze_trajectory_mpcc.py` | 对齐名义计划、返回预测与实际执行，评价动作变化、任务完成和晃动；不参与控制 |

纯数据、参考、物理、求解和分析模块分开。ROS 层只负责配置、消息接入和调用；不把新规划器写入 `spmpc_local_planner_ros.cpp`，不为本轮强制重构全部历史模块。

## 4. 两层接口与参考语义

建议首版计划由 JSON 元数据和逐样本表组成，字段至少包含：

- 路径身份、坐标系、模型/参数/计划版本，弧长单位和任务时间起点。
- 名义 `t,s,x,y,yaw`，预测实际 `v,omega`，名义发布命令及其初始待执行历史；命令与实际运动分列。
- 名义液体预测、速度/加速度/jerk 等运动限制，到达要求和固定停车评价窗口。
- 活动区域的关联信息、计划适用范围、求解及可行性检查结果。
- 规划目标/归一化、参考模式、任务与停车事件定义、移动/停等/停车阶段身份；固定时序和在线进度对照使用同一计划身份。

完整 rollout 状态和配置作为复现产物保存。计划中的液体序列只作参考和机制诊断，在线初态仍取当前估计与真实命令历史。

**建议在线以弧长关联参考，只维护现有 `s,v_s` 进度。** 上层给出名义速度剖面及时间安排；下层允许偏离名义时序，同时记录剩余期限。偏离路径时实际车速不必等于虚拟进度速度，两者关系要由运动与路径关联共同约束。名义时钟只是参考信息，不增加第二套独立优化进度。

阶段参考应随预测进度变化。首版可围绕热启动进度构造局部速度剖面表达式，作为阶段参数传入，并保留对优化变量 `s` 的依赖；不能把整窗都取成当前点速度。插值形式、有效区间及越区间后的重新装配须在接口实现时确定并测试。最终有效参考同时用于对应的速度、低速惩罚和诊断；终点减速与现有曲率限速只组合一次。

弧长查询只负责移动段。停等时同一个 `s` 对应多个时间，液体仍继续演化，因此计划还要保存阶段身份和阶段内时间，不能用任意一次相同进度样本恢复液体状态。任务时钟在跨周期查询时持续推进，不因落后或重新装配而重置到名义时刻。

| 模式 | 查询及控制语义 | 用途 |
|---|---|---|
| 原巡航模式 | 当前巡航值、已有曲率限速与停车处理 | feat 行为回归；模式关闭后与本次改动前一致 |
| 固定时序参考 | 按共同任务起点后的实际经过时间读取完整参考，不随误差平移/拉伸时钟 | 同计划时序对照；不称 C06 直接复现 |
| 在线进度参考 | 根据当前/预测唯一进度关联名义运动，并重新预测实际运动与液体 | 两层协同候选；保留期限和阶段处理 |

固定时序与在线进度的参考/进度项差异属于被比较机制，应逐项记录；其余模型、预测时域、信息来源、液体设置、运动边界及停车窗口保持一致。固定时序版不另加一套暗中追赶或重置时钟的恢复逻辑。

原有巡航参考模式（含已有曲率限速与停车处理）继续显式保留作对照；请求轨迹模式后，计划缺失或身份不符应明确报错，不能悄悄退回原模式并仍记为轨迹层运行。

### 4.1 候选剩余段评价接口

首版为纯数值接口，先不接入命令发布或 ROS 循环。建议输入/输出合同如下：

| 输入或输出 | 必需内容 |
|---|---|
| 预测末端 | solver 返回的完整状态、预测有效时刻、来源周期、模型/参数身份；包括位姿、actual/command、两通道 FIFO、加速度记忆、液体位移/速度、进度 |
| 候选后缀 | 同一计划的阶段/样本身份、接续规则、名义后续命令；任何过渡/跟踪控制都显式记录 |
| 任务合同 | 共同起点事件和到达期限、路径/区域、运动/液体边界、停车策略与固定评价窗口 |
| 报告 | 候选是否通过、违反的边界和位置、预计到达/停稳/稳定时刻、液体峰值/残余、检查耗时、模型与候选身份 |
| 状态语义 | `CANDIDATE_PASS`、`CANDIDATE_FAIL`、`NOT_EVALUATED`；失败不提升为全局无解，未算完不能算通过 |

从预测末端直接重放候选命令，保留衔接误差并核验运动、几何、FIFO 与 jerk；不能把位姿投影到计划、重置液体或清零待执行命令。若直接后缀无法接上，可另外生成可执行的过渡候选，仍从同一完整状态验证。

候选通过仅说明该模型下存在这一条经检查的后续运动；节点检查需另做细化传播核验，实物与鲁棒效果仍需独立证据。所有候选失败只说明本次搜索没有找到后续。首版报告保持诊断身份；检查预算不足返回未评价，不追加隐藏的速度改写。

如果后续要加入 `J_tail` 或终端可接续约束，需另外设计其关于优化变量的表达、导数/近似及有效域，接入共源代价/约束生成和 solver 核验，并验证最优动作确实变化。离线后缀检查器不能未经开销与执行契约验证直接塞进 30 Hz 发布链。

## 5. 分阶段实施与验收

### P0：确认开发基础与最小问题

先复盘第 2 节的优化问题、参考/任务时钟、目标与终点事件，形成配置草案。核对当前生成 solver 与源码身份，复用 V1/V2–V4 的模型和代价检查。针对微负实际速度，分别复现噪声、偏置与真实回退的情形，设计实际状态允许域和命令约束；保留真实 x0，不靠裁零掩盖不可行。

低速执行器与静止阈值用现有数据核对；统一模型重放 Smooth-only，按同有效时刻比较实际/预测容器激励。杯沿余量、液量/安装与恢复预算单独校准。离线规划设计可先推进，ROS1 构建、配置/无速度发布检查和执行链验收须在新实车前完成。

输出：可复现的小问题、基本运动/停车行为及已知限制。ROS1 集成前先做不依赖 ROS 的数值检查；不把 ROS2 环境当作 ROS1 构建环境。

### P1：离线规划的收益空间

按第 2 节完整问题先固定参考几何。少量速度节点可作为一个参数化候选，但须检查其是否能表达所需连续动作并形成可执行计划；与命令序列或进度 jerk 参数化的取舍由小问题决定。调用当前完整执行链 rollout，覆盖加减速、转向、待执行历史和液体响应；不能只算 `v²κ` 或事后限幅。

用相同路径、初态、运动限制和运输时间要求比较普通平滑安排与模型防晃安排，评价全过程及停车尾段。名义规划可以预测完整未来动作，但不得使用未知未来扰动。

输出：计划文件、可行性与时间报告、完整预测曲线。先查能否执行与按时到达，再判断降晃潜力；求解失败保留，不能以失败轨迹较短导致的低 RMS 当作收益。

验收至少包含名义初态/命令的共源传播一致性、不同积分细化下的边界核验、真实目标与停车尾段，以及相同耗时条件下普通/防晃计划的对照。高精度重放验证数值可行性，不作为独立实物效果证据。

### P2：接通全时域参考

实现 `TrajectoryReference`、`HorizonReferenceBuilder`，扩展 `SolverInput`；在 `SpmpcProblem` 中保存计划身份与任务状态，在 acados 包装层装配全部阶段参考。同步符号参数、生成 C、C++ 参数索引和消息版本，并重新生成 solver。

先用普通平滑计划验证接口，再接入防晃计划；这一阶段不同时改变活动区域、液体权重和停车策略。按第 4 节明确两种参考模式，采用同一模型估计重新传播，不追踪旧名义液体相位。全时域进度平滑若需改状态或约束，另作可关闭的独立变更。

输出：前方速度安排确实进入预测窗口的证据；名义命令、solver 首拍和最终发布命令能逐拍追溯。关闭新参考模式时，行为应与当前 feat 基线一致。

### P3：从预测末端检查候选剩余运动

先实现第 4.1 节离线评价，复用 P1 rollout；输入来自 P2 的真实 solver 预测末端。构造位置/速度相近但液体速度方向或 FIFO 不同的候选，检查它们能否产生不同的剩余晃动、耗时与可行性判断。加入期限不足、后缀衔接失败、停等、无候选及计算未完成等情况。

输出：可追溯的末端状态、候选后缀和检查报告。先观察该信息能否识别局部低晃动却不利于后续停车的动作。全部检查只诊断时，不报告控制收益。

若证据支持，再单独定义进入在线目标/约束的版本：明确近似误差、代码生成、开销上限和失败语义，并做相同初态下有/无该项的动作对照。增加终端代价需通过真实 solver 总价核验；增加接续约束需验证该约束与真正可执行后缀的关系。未经这一步，不声称已解决在线剩余可行性问题。

### P4：分别释放速度和几何调整空间

- **速度对照：** 固定区域及路径项，只改变速度/低速/进度目标的组织，让提前减速不被原恒速要求抵消；与共同到达期限、剩余运动可行性一起设计。
- **几何对照：** 固定其他速度/任务设置，定义允许活动的区域及车体边界，调整 contour 等横向正则；lag 的进度一致性作用单独保留和检验。若两组实际速度也变了，记录差异，不把结果称为纯几何贡献。先在明确的无障碍区域检查，再组合两类改动。

`corridor_width` 的归一化作用与真正区域约束分开命名。新增区域约束需要覆盖车体及节点间运动，局部几何拟合和投影跳变也需检查。Full/Smooth 共享区域与任务条件。

同初态下分别观察最优轨迹、速度、转向时机、各项代价变化及约束接近情况，区分“不愿调整”和“无法调整”。不能仅看代价占比或地图上的贴线程度。

输出：有无调整空间及液体目标如何影响动作的对照报告。到达期限的具体可行性近似、区域宽度和权重仍需由这些结果确定，不能预设放宽就一定有效。

### P5：独立闭环与实物

按框架第 5 节执行“普通/防晃计划 × 在线液体目标开/关”四组，四组共用同一进度模式。具体 profile 列清液体代价、硬约束、恢复、停车和后缀指导开关，避免在标为关闭的组里通过其他入口用液体评分选动作。固定时序/在线进度另用同一防晃计划对照；若 P3 的信息进入控制，再增加同条件有/无剩余段指导对照。旧论文笔记 B/D 编号不直接沿用。

独立仿真覆盖名义执行、短时限速、初始位姿偏差和模型失配；主实验只给控制器实际可获得的信息。未知液体初态/直接液体扰动与可从实际运动更新的激励误差分开评价；真值状态只能用于标明身份的上限研究或独立评价。用于规划的同一模型只能先做流程回归，效果确认另用独立对象。

适配 diag 最近的预测/命令/观测诊断和实验入口，核对新模型与消息身份。完成 ROS1 整链验证后，选定候选做短实车检查及新的配对复验。记录全程晃动、峰值、耗时、到达、残余和全部失败；固定停车窗口，以独立液面数据确认实物效果。

R36 风格整形/滤波参照先限于经过可执行性验证的任务，计入延迟与全部实际耗时。受扰恢复能力优化、高维终端集合、额外监督器及动态避障，在基本两层收益明确后再研究；论文的存在不替代这些机制的本项目验证。

## 7. 必须覆盖的验证与待定项

| 验证对象 | 要区分的行为 |
|---|---|
| 计划与任务身份 | 错模型、单位、路径、阶段或过期计划明确失败；请求轨迹模式后不静默退回巡航 |
| 完整 rollout | 同初态/历史/命令下共享传播一致；缩放运输时长不改变物理延迟；包含制动和停车尾段 |
| 全时域参考 | 前方减速进入 N+1 参考；改变优化进度确实改变参考；局部表达式越区间、端点和停等被明确处理 |
| 两种时序模式 | 固定时序时钟不被重置；在线模式只有一个进度；改变时序后液体重新传播 |
| 目标/约束 | contour 与 lag 的作用分开；速度与 anti-creep 使用一致参考；所有新增代价与 solver 总价一致 |
| 剩余段检查 | 不投影末端、不清历史；液体相位/FIFO 差异能改变结果；候选失败与未评价不误报全局无解或通过 |
| 剩余段进入控制 | 独立开关、优化表达与适用域明确；观察动作和结果变化，计入完整运行耗时 |
| 回归与独立评价 | 模式关闭回到 feat 基线；区域/投影与实际任务停车验证；同模型检查与独立对象效果分开 |

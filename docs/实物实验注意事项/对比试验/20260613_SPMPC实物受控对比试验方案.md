# 20260613 SPMPC 实物受控对比试验方案：B0 锚点 + B_slosh/B_ours 弱 smooth 复测

> 适用状态：20260613 实物回传 bag 已显示 `B0(v_ref=0.65)` 可完成同一路径，而 `B_smooth` 多组与今日 `B_ours` 均未形成稳定通过；本版不再把 `B_smooth` 作为正式实物 A baseline 死磕，改为先用 B0 锚定 tracking，再用 `B_slosh` / 弱 smooth `B_ours` 拆分 slosh-aware 与 smooth/control 权重影响。
>
> 参考操作命令：`docs/实物实验注意事项/代码移植/20260611_SPMPC实物Smoke_P2P到固定路径步骤.md`；今日实测记录：`docs/实物实验注意事项/对比试验/20260613_B_smooth调参与B0基线实测记录.md`
>
> 本文不是“直接正式大矩阵放行”，而是实物受控复测 SOP：每个 run 仍从低风险 N=1 closed-loop smoke 开始；只有 B0、B_slosh、弱 smooth B_ours 均安全且数据完整后，才考虑 N=3 或外部 planner 对比。

## 0. 本轮核心问题

本版实物复测只回答两个递进问题：

```text
1. 在同一实物 Scout、同一路径、同一输出安全层下，slosh-aware 本身（B_slosh）是否仍能稳定完成 P2 S 曲线？
2. 若 B_slosh 稳定，弱 smooth 的 B_ours 是否能在不牺牲 tracking 的前提下恢复降晃收益？
```

今日实测已经给出约束：`B0(v_ref=0.65)` 可过，`B_smooth` 多组失败，今日 `B_ours` 也跑不了；因此第一轮不再做 `B_smooth` vs `B_ours` 正式 A/B，而是先拆因子：

```text
Z: B0,       V_REF=0.65, w_alpha=fallback, output angular limiter on, 基础 tracking/第一弯锚点
S: B_slosh,  V_REF=0.50 -> 0.65, W_SLOSH=2, w_alpha=0.1, w_du_a=w_du_vs=0.1, 验证 slosh-aware 本体
S_ext:       仅当 S(w_slosh=2) 通过后，再扩展 W_SLOSH=10 -> 20；不把强 slosh cost 作为实物首跑
O: B_ours,   V_REF=0.50 -> 0.65, W_SLOSH=1/2, w_alpha=0.1, w_du_a=w_du_vs=0.05, 验证弱 smooth 候选
C: 可选扩展：只有 O 通过后，才逐步把 w_alpha 提到 0.2/0.3 或把 W_SLOSH 提到 5；不再把 w_alpha=0.5/2 作为第一轮实物参数
```

推荐优先级：

```text
先 Z(B0) N=1 smoke，确认基础 tracking/第一弯仍可过
再 S0/S1(B_slosh, w_slosh=2) N=1 smoke，证明 slosh-aware 本体不是失败来源
若 S1 通过且现场状态稳定，再扩展 S2/S3(B_slosh, w_slosh=10/20)，验证 slosh cost 收益上限
再 O0/O1/O2(B_ours weak smooth) N=1 smoke，逐步恢复 slosh 权重和速度
只有 S/O 全部安全且数据完整，才考虑 N=3；B_smooth 暂停作为正式实物 baseline，仅保留为诊断/仿真消融
```

## 1. 安全红线

必须满足：

```text
1. 现场至少一人专门盯车，手边有硬件 E-stop / 遥控急停。
2. 本轮不做 shadow，因此每个 run 前必须更严格确认 `/cmd_vel` 没有旧 planner publisher，且 RViz/path/goal/定位都正常。
3. 每个 run 先启动 RGB 在线监控并等待 zero locked，再开 recorder，最后启动 planner。
4. N=1 smoke 只验证安全与数据链路，不作为正式对比结论。
5. 不改地图、TF、定位、URDF、雷达、底盘模型来“修”实验结果。
6. 不使用 broad killall / pkill；只 Ctrl-C 当前终端或硬件急停。
7. 失败 bag、异常 log、急停记录都保留，不删除失败数据。
8. 任何人主观认为不安全，立即停。
```

立即停机条件：

```text
1. 明显原地转圈或小 linear.x + 大 angular.z 持续约 2s。
2. 明显离开固定路径或朝障碍物/人运动。
3. /spmpc/status 出现 TRACKING_UNSAFE_PROJECTION / TRACKING_SPIN_FAIL / TERMINAL_SPIN_FAIL。
4. /spmpc/status 出现 ACADOS_NOT_IMPLEMENTED / ACADOS_NOT_CREATED / ACADOS_SOLVE_FAILED_*。
5. /spmpc/debug/cmd_vel_output 显示 limiter 长时间持续大幅介入，且现场运动异常。
6. /odom、TF、/map、/scan_front 明显异常。
7. 前方有人、障碍、空间不足，或液体容器固定异常。
```

停机顺序：

```text
1. 优先硬件 E-stop / 遥控急停。
2. Ctrl-C 停当前 planner roslaunch。
3. 连续发 /cmd_vel zero。
4. Ctrl-C 停 rosbag。
5. 保存 bag、log、path JSON、现场记录。
```

zero 命令：

```bash
for i in 1 2 3 4 5; do
  rostopic pub -1 /cmd_vel geometry_msgs/Twist \
    "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"
  sleep 0.1
done
```

### 3.1 在线液面监控 / 现场快检

本节只用于 **实物现场在线观察和快速判定链路是否正常**；正式主表仍以后续 bag 图像离线复算的 RGB max-LCR 为准。

启动传感器栈和 RealSense RGB 后，先启动 RGB-only 在线监控：

```bash
source /opt/ros/noetic/setup.bash
source /home/geist/scout_ws/devel/setup.bash
cd /home/geist/scout_ws

DATE=$(date +%Y%m%d)

roslaunch realsense_liquid_measurement online_liquid_monitor_combined.launch \
  calibration:=/home/geist/slosh_bags/real/${DATE}_calib/red_3ruler.yaml \
  image_topic:=/camera/color/image_raw \
  process_every:=1 \
  height_bias_mm:=0.0 \
  hue1_low:=0 hue1_high:=11 \
  hue2_low:=173 hue2_high:=179 \
  sat_min:=80 val_min:=162
```

该 launch 只启动 RGB 在线液面链路：

```text
/camera/color/image_raw
  -> online_liquid_height_node.py
  -> /liquid/height, /liquid/height_lcr, /liquid/height_median, /liquid/debug_image
  -> liquid_experiment_monitor.py dashboard
```

它 **不启动** 独立 `/slosh/height` 模型，也不把模型曲线当真实液面。dashboard 右侧 Height Trend 只看 RGB max-LCR / L / C / R。

启动 planner 前必须做在线液面 quick check：

```bash
rostopic echo -n 1 /liquid/height
rostopic echo -n 1 /liquid/height_lcr
rostopic hz /liquid/height
rostopic echo -n 1 /liquid/debug_image/header
```

现场步骤：

```text
1. 车辆和液体保持静止。
2. 等 online_liquid_height 日志出现 zero locked，或 dashboard 静止曲线接近 0 mm。
3. 如静止偏置明显，先不要开 planner；保持静止后重置在线零点：
   rosservice call /online_liquid_height/reset_zero
4. dashboard 点 START，开始本 run 的现场 session。
5. 开 recorder，再开 planner。
6. run 结束后先停 planner / 发 zero，再停 recorder；dashboard 点 STOP，可选 EXPORT 保存现场快检 CSV/SVG。
```

在线输出语义：

```text
/liquid/height：RGB max-LCR 在线高度，带在线 zero/bias 修正，只作现场快检。
/liquid/height_lcr：[left, center, right] 三标尺在线高度，用于检查某一标尺是否跑偏。
/liquid/height_median：三标尺 median 质检量。
/liquid/debug_image：红色液体 ROI / top boundary overlay，用于检查 HSV/ROI/标尺是否匹配。
```

若 bag 已经记录 `/liquid/height` 和 `/liquid/height_lcr`，现场可快速导出在线数据作排障：

```bash
python3 src/scout_apps/sensors/realsense_liquid_measurement/scripts/export_liquid_variation_from_bags.py \
  /home/geist/slosh_bags/real/${DATE}_spmpc_ab_compare \
  --recursive \
  --source online \
  --out-dir /home/geist/slosh_bags/real/${DATE}_spmpc_ab_compare/liquid_online_export
```

注意：`--source online` 只导出当时在线节点发布的数据，适合现场快速检查；正式论文/对比结论仍用第 7 节的 `--source rgb` 从 bag 图像离线复算。

### 5.3 实物调参建议与停止条件

```text
已知现场现象：按 alpha_max=8.0、shared_angular_accel_max=3.0 后，B0(v_ref=0.65) 可完成同一路径；B_smooth 五组未形成稳定通过；今日 B_ours 也跑不了。
bag 判读：desired_omega≈limited_omega，limiter 介入比例很低，B0 同 limiter 可过；因此主要矛盾不是 output limiter，也不支持 horizon/current-state rollout 是一阶主因，而是 smooth/control 权重在实物 S 曲线闭环中让第一弯/终点修正过慢或不稳定。
slosh-aware 判读：20260611 实物 B_slosh/B_ours 均通过，且今天 B_smooth 不含 slosh-aware 也失败；因此 slosh-aware 本身不是当前第一嫌疑，需用 B_slosh 先单独复核。
20260614 隔离仿真补充：B_slosh 在 real-like 参数口径下扫 w_slosh=0/1/2/5/10/20 全部 strict fresh-sim 到点；N=1 中 w=20 的 core p95/rms 与 cmd abs(domega/dt) 最低，w=10 的 core raw peak 最低。但实物首轮仍从 w=2 开始，w=10/20 只作为 w=2 通过后的收益扩展。
```

调参顺序：

```text
1. 固定 Z_B0_v065_alim 作为 tracking anchor；B0 不安全时不测 S/O。
2. 先跑 S0/S1，即 B_slosh w_slosh=2：若 S1 能过，说明 slosh state + 温和 slosh cost 本身不是失败来源。
3. S1 通过后，优先扩展 S2/S3：B_slosh w_slosh=10 -> 20；每次只加一个权重，若 S2 tracking/终端/RGB 任一异常，则不跑 S3。
4. S2/S3 的目的只是评估 slosh-only 收益上限：只有 completion 与 tracking 安全成立后，才比较 RGB core p95/rms；不能用离轨换低液面。
5. 再跑 O0/O1/O2：B_ours 从 v_ref=0.50、w_slosh=1、w_alpha=0.1、w_du=0.05 开始，先保 tracking，再逐步恢复 w_slosh 和 v_ref。
6. 只有 O2 稳定后，才逐步加 smooth 到 w_alpha=0.2/0.3 或把 B_ours 的 w_slosh 提到 5；不要直接回到 w_alpha=0.5/2、w_slosh=10。
7. 若 S0/S1/S2/S3 过而 O0/O1/O2 不过，优先怀疑 B_ours 继承的 smooth/control envelope；下一步应新建/调整 B_ours_weak（降低 w_control/w_smooth），而不是继续只扫 w_slosh。
8. B_smooth 暂停作为正式实物 baseline；若要保留，只能作为 A_diag 诊断，不进入论文主 A/B 结论。
9. 不优先改 horizon / next-state rollout：B0 已通过同一路径同速度同 limiter，当前证据不支持 rollout 是主因。
```

和 20260611 记录、仿真记录的区别：

```text
20260611 P2 成功记录使用的是默认速度/默认权重：B0、B_slosh、B_ours 均 alpha_max=8.0，未显式 v_ref=0.65、w_alpha=2、w_slosh=10，也未显式打开本轮 output angular limiter。
B_smooth 在 strict fresh-sim 中通过过，但找到的通过记录不是今日实物精确同参：仿真多为默认速度或 v_ref=0.70、alpha_max=1.2，未找到 v_ref=0.65 + alpha_max=8.0 + w_alpha=0.5/2 + w_du=0.1 + output limiter on 的 strict fresh-sim 通过证据。
因此 20260611 证明“默认口径 slosh-aware 可过”，仿真证明“B_smooth 变体在理想闭环下可过”，但都不能直接证明“今日高速实物 + strong/medium smooth envelope 可过”。
```

## 6. 执行顺序

### 6.1 第一轮只做 N=1 smoke，不做正式 N=3

```text
直接 closed-loop Smoke N=1（本轮不做 shadow）:
  Z(B0)
    -> 立刻检查 tracking/第一弯/bag/RGB/export/cmd diagnostics
  S0(B_slosh v0.50 ws2 wa0.1 du0.1)
    -> 低速预热；若现场希望直接按目标速度验证，也可在 B0 稳定后跳到 S1
  S1(B_slosh v0.65 ws2 wa0.1 du0.1)
    -> 核心门槛：S1 安全通过，才说明 slosh-aware 温和权重可上实物
  S2(B_slosh v0.65 ws10 wa0.1 du0.1)
    -> 只在 S1 安全、bag/RGB/cmd diagnostics 完整后扩展
  S3(B_slosh v0.65 ws20 wa0.1 du0.1)
    -> 只在 S2 安全后扩展；S2 有异常则不跑 S3
  O0(B_ours v0.50 ws1 wa0.1 du0.05)
    -> S1 至少安全后才跑；若当天优先做 slosh-only 收益，则放在 S2/S3 后
  O1(B_ours v0.50 ws2 wa0.1 du0.05)
    -> O0 安全后才跑
  O2(B_ours v0.65 ws2 wa0.1 du0.05)
    -> O1 安全后才跑
```

N=1 smoke 通过标准：

```text
1. 机器人全程可控，无明显离轨/转圈/朝障碍物运动。
2. bag 中有 /camera/color/image_raw、/cmd_vel、/odom、/spmpc/debug/cmd_vel_output。
3. 尽量包含 /spmpc/debug/projector、/spmpc/debug/first_shot_summary、/spmpc/debug/warm_start_head、/spmpc/debug/stage0_reference。

5. output limiter 没有长时间持续大幅替 planner 修正。
6. 到点或安全停止后能按流程 zero、停 planner、停 recorder。
```

### 6.2 可选扩展与 N=3 条件

```text
S1(w_slosh=2) N=1 安全且数据完整后，才考虑 S2/S3(w_slosh=10/20)。
若 S2 稳定：可跑 S3；若 S2 有 tracking/终端/RGB/limiter 异常，停止 B_slosh 强权重扩展。
```

## 10. 测后分析口径

主真值：**离线 RGB max-LCR 液面高度**。

辅助指标：

```text
/liquid/height, /liquid/height_lcr：在线 RGB 观测，只作现场快检；正式主表仍用 bag 图像离线复算。
/slosh/height：外部 standalone slosh monitor / evaluation-only 模型 proxy，只作趋势辅助。
/spmpc/slosh_height：SPMPC 内部模型 proxy，只作解释，不当真实液面高度。
/spmpc/debug/cmd_vel_output：证明输出限幅前后差异，不可忽略。
```

B0 判定口径：B0 只用于确认同一路径、同一 `alpha_max=8.0` 与同一输出安全层下的基础 tracking/第一弯行为；若 B0 在 20% 左右触发 `TRACKING_UNSAFE_PROJECTION` 或第一弯明显不可控，先停止 S/O，回到 `cmd_vel_output`、`projector`、`warm_start_head`、`first_shot_summary` 和路径投影诊断。

第一轮 S/O 判定表：

| 指标 | 优先级 | 解释 |
|---|---:|---|
| completion / progress / terminal status | 高 | 第一优先，先证明 tracking 安全可完成。 |
| `/spmpc/debug/cmd_vel_output` desired vs limited | 高 | 继续验证是否不是 output limiter 卡住。 |
| `/cmd_vel` 与 `/odom` yaw rate | 高 | 区分 planner 输出、底盘响应和终端振荡。 |
| tracking error / progress_s / projector | 高 | 避免用明显离轨换低晃动；若触发 unsafe，必须看 projector。 |
| RGB core 10%-90% p95/rms | 中高 | 只有完成且 tracking 安全后，才进入降晃判定。 |
| RGB core 10%-90% peak | 中 | peak 要结合起步/终端/遮挡异常解释，不能单点决定。 |
| cmd abs(dω/dt) p95/max | 中 | 检查是否因弱 smooth 产生不可解释尖峰。 |

可以写成有效的条件：

```text
B_slosh：先证明 slosh state + 温和 slosh cost(w=2) 在今日速度/安全层下能稳定完成；若 w=2 失败，不上 B_ours，也不扩展 w=10/20。
B_slosh 权重扩展：只有 w=2 通过后才跑 w=10/20；结论优先看 completion/tracking，其次才看 RGB core p95/rms 是否下降。
B_ours_weak：只有在 S1 稳定后才判断其 RGB core p95/rms 是否相对 B_slosh 或 B0 改善；若 tracking 不稳，不能声称降晃有效。
```

如果结果是：

```text
B_slosh w=2 过、B_slosh w=10/20 也过 -> slosh-aware 本体和较强 slosh cost 均可实物闭环，再比较 RGB core p95/rms 选最稳权重。
B_slosh w=2 过、B_slosh w=10 或 w=20 不过 -> slosh-aware 本体不是锅，但强 slosh cost 会破坏实物闭环，实物后续退回 w=2。
B_slosh 过、B_ours_weak 不过 -> slosh-aware 不是锅，优先怀疑 B_ours 的 smooth/control envelope，需要 B_ours_weak 配置或代码层降 w_control/w_smooth。
B_slosh w=2 不过 -> 先降速/降 w_slosh，暂不上 B_ours，也不跑 w=10/20。
B_ours_weak 只在 /spmpc/slosh_height 上更好，但 RGB 不好 -> 不能声称实物降晃有效。
B_ours_weak RGB p95/rms 更好，但 peak 个别 run 异常 -> 保留证据，分析是否为起步/终端/视觉异常。
```

## 11. 何时扩展到 TEB/DWA

只有满足下面条件，才进入外部 planner 对比：

```text
1. SPMPC 内部复测至少 Z/S1/O2 N=1 全部安全；若要写正式结论，S/O 至少 N=3 全部安全。
2. B_ours_weak 相比 B_slosh 或 B0 在 RGB p95/rms 或 core peak 上有可写的实物证据，且 tracking 不恶化。
3. real costmap for TEB/DWA 已现场复核，不直接套 sim costmap。
4. TEB/DWA 是否需要 shadow 另开外部 planner SOP 决定；不要混入本文 SPMPC 内部复测。
5. 对比表明确 common-limit 或 tuned-limit；不能混口径。
```

外部对比公平性原则：

```text
如果 SPMPC 使用 output angular limiter，TEB/DWA 要么也经过同一安全 envelope，
要么报告中明确写：SPMPC 是“带输出安全层”的实物候选，TEB/DWA 是各自原生输出，不能把结论写成纯 OCP 本体对比。
```

建议外部对比另开文档/另开批次，不混入第一轮 SPMPC 内部复测。

```text
7. S2/S3 完成或当天决定暂不扩展后，按 O0 -> O1 -> O2 逐步恢复 B_ours：先低速低 slosh，再加 w_slosh=2，最后恢复 v_ref=0.65。
8. O2 通过后，才考虑 O3/O4/O5 或 N=3；若 O2 不过，优先做 B_ours_weak / w_control / w_smooth 诊断，不继续盲扫 w_slosh。
9. 当天不做 TEB/DWA，除非 S/O 结论非常稳定且 baseline real costmap 已单独复核；更推荐另开批次/另开文档。
```

# 20260613 SPMPC 实物受控对比试验方案：直接 N=1 smoke，先内部 A/B，再扩展 TEB/DWA

> 适用状态：隔离仿真 `w_alpha + output angular limiter` N=3/N=5 已通过；本轮按用户要求 **不做 shadow**，直接从低风险 N=1 closed-loop smoke 开始。只有确认传感器、定位、TF、`/cmd_vel` 通路、急停、RGB 三标尺和录包正常后，才进入本文。
>
> 参考操作命令：`docs/实物实验注意事项/代码移植/20260611_SPMPC实物Smoke_P2P到固定路径步骤.md`
>
> 本文不是“直接正式大矩阵放行”，而是实物受控对比 SOP：先用 B0 N=1 smoke 确认基础 tracking/第一弯可过，再用 N=1 smoke 验证 A/B 安全和数据链路，随后做 SPMPC 内部 `B_smooth` vs `B_ours` N=3 A/B；只有内部证据成立后再考虑外部 planner 对比。

---

## 0. 本轮核心问题

本轮实物对比只回答一个核心问题：

```text
在同一实物 Scout、同一路径、同一起点、同一速度/加速度/角加速度约束、同一 RGB 液面真值口径下，
B_ours 的 slosh-aware 项是否比 smooth-only baseline 更稳定地降低真实液面晃动？
```

第一轮不急着证明 TEB/DWA 对比；先加 B0 做基础 tracking 诊断，再用**放宽后的 smooth/slosh 权重**做 SPMPC 内部 A/B：

```text
Z: B0,       V_REF=0.65, w_alpha=fallback, output angular limiter on, 基础 tracking/第一弯诊断
A: B_smooth, V_REF=0.65, w_alpha=0.5, w_du_a=w_du_vs=0.1, output angular limiter on, relaxed smooth-only baseline
B: B_ours,   V_REF=0.65, W_SLOSH=2, w_alpha=0.5, w_du_a=w_du_vs=0.1, output angular limiter on, relaxed slosh-aware 候选
C: 可选调参扩展：A/B 成对改成 w_alpha=0.3，或在同一 smooth envelope 下把 B_ours W_SLOSH 提到 5；不再把 v_ref=0.70 作为第一轮候选
```

推荐优先级：

```text
先 Z(B0) N=1 smoke，确认基础 tracking/第一弯可过
再 A_relaxed / B_relaxed 两组 N=1 smoke
通过后 A/B 两组 N=3；B0 是否追加 N=3 只作为 tracking 诊断，不作为降晃主结论
如果 A/B 任一组仍第一弯失败，先按第 5.3 节放宽/降速，不进入正式 N=3
```

## 1. 安全红线

必须满足：

```text
1. 现场至少一人专门盯车，手边有硬件 E-stop / 遥控急停。
2. 本轮不做 shadow，因此每个 run 前必须更严格确认 `/cmd_vel` 没有旧 planner publisher，且 RViz/path/goal/定位都正常。
3. 每个 run 先启动 RGB 在线监控并等待 zero locked，再开 recorder，最后启动 planner。
4. N=1 smoke 只验证安全与数据链路，不作为正式 A/B 结论。
5. 不改地图、TF、定位、URDF、雷达、底盘模型来“修”实验结果。
6. 不使用 broad killall / pkill；只 Ctrl-C 当前终端或硬件急停。
7. 失败 bag、异常 log、急停记录都保留，不删除失败数据。
8. 任何人主观认为不安全，立即停。
```

立即停机条件：

```text
1. 明显原地转圈或小 linear.x + 大 angular.z 持续约 2s。
2. 明显离开固定路径或朝障碍物/人运动。
3. /spmpc/status 出现 TRACKING_UNSAFE_PROJECTION / TRACKING_SPIN_FAIL / TERMINAL_SPIN_FAIL。
4. /spmpc/status 出现 ACADOS_NOT_IMPLEMENTED / ACADOS_NOT_CREATED / ACADOS_SOLVE_FAILED_*。
5. /spmpc/debug/cmd_vel_output 显示 limiter 长时间持续大幅介入，且现场运动异常。
6. /odom、TF、/map、/scan_front 明显异常。
7. 前方有人、障碍、空间不足，或液体容器固定异常。
```

停机顺序：

```text
1. 优先硬件 E-stop / 遥控急停。
2. Ctrl-C 停当前 planner roslaunch。
3. 连续发 /cmd_vel zero。
4. Ctrl-C 停 rosbag。
5. 保存 bag、log、path JSON、现场记录。
```

zero 命令：

```bash
for i in 1 2 3 4 5; do
  rostopic pub -1 /cmd_vel geometry_msgs/Twist \
    "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"
  sleep 0.1
done
```

### 3.1 在线液面监控 / 现场快检

本节只用于 **实物现场在线观察和快速判定链路是否正常**；正式 A/B 主表仍以后续 bag 图像离线复算的 RGB max-LCR 为准。

启动传感器栈和 RealSense RGB 后，先启动 RGB-only 在线监控：

```bash
source /opt/ros/noetic/setup.bash
source /home/geist/scout_ws/devel/setup.bash
cd /home/geist/scout_ws

DATE=$(date +%Y%m%d)

roslaunch realsense_liquid_measurement online_liquid_monitor_combined.launch \
  calibration:=/home/geist/slosh_bags/real/${DATE}_calib/red_3ruler.yaml \
  image_topic:=/camera/color/image_raw \
  process_every:=1 \
  height_bias_mm:=0.0 \
  hue1_low:=0 hue1_high:=11 \
  hue2_low:=173 hue2_high:=179 \
  sat_min:=80 val_min:=162
```

该 launch 只启动 RGB 在线液面链路：

```text
/camera/color/image_raw
  -> online_liquid_height_node.py
  -> /liquid/height, /liquid/height_lcr, /liquid/height_median, /liquid/debug_image
  -> liquid_experiment_monitor.py dashboard
```

它 **不启动** 独立 `/slosh/height` 模型，也不把模型曲线当真实液面。dashboard 右侧 Height Trend 只看 RGB max-LCR / L / C / R。

启动 planner 前必须做在线液面 quick check：

```bash
rostopic echo -n 1 /liquid/height
rostopic echo -n 1 /liquid/height_lcr
rostopic hz /liquid/height
rostopic echo -n 1 /liquid/debug_image/header
```

现场步骤：

```text
1. 车辆和液体保持静止。
2. 等 online_liquid_height 日志出现 zero locked，或 dashboard 静止曲线接近 0 mm。
3. 如静止偏置明显，先不要开 planner；保持静止后重置在线零点：
   rosservice call /online_liquid_height/reset_zero
4. dashboard 点 START，开始本 run 的现场 session。
5. 开 recorder，再开 planner。
6. run 结束后先停 planner / 发 zero，再停 recorder；dashboard 点 STOP，可选 EXPORT 保存现场快检 CSV/SVG。
```

在线输出语义：

```text
/liquid/height：RGB max-LCR 在线高度，带在线 zero/bias 修正，只作现场快检。
/liquid/height_lcr：[left, center, right] 三标尺在线高度，用于检查某一标尺是否跑偏。
/liquid/height_median：三标尺 median 质检量。
/liquid/debug_image：红色液体 ROI / top boundary overlay，用于检查 HSV/ROI/标尺是否匹配。
```

若 bag 已经记录 `/liquid/height` 和 `/liquid/height_lcr`，现场可快速导出在线数据作排障：

```bash
python3 src/scout_apps/sensors/realsense_liquid_measurement/scripts/export_liquid_variation_from_bags.py \
  /home/geist/slosh_bags/real/${DATE}_spmpc_ab_compare \
  --recursive \
  --source online \
  --out-dir /home/geist/slosh_bags/real/${DATE}_spmpc_ab_compare/liquid_online_export
```

注意：`--source online` 只导出当时在线节点发布的数据，适合现场快速检查；正式论文/对比结论仍用第 7 节的 `--source rgb` 从 bag 图像离线复算。

## 5. 对比矩阵

### 5.1 第一轮最小 A/B（放宽版）

| label | variant | v_ref | w_slosh | w_alpha | w_du_a/w_du_vs | output angular limiter | 用途 |
|---|---|---:|---:|---:|---:|---|---|
| `Z_B0_v065_alim` | `B0` | 0.65 | N/A | fallback | fallback | on | 基础 tracking/第一弯诊断 |
| `A_Bsmooth_v065_wa05_du01_alim` | `B_smooth` | 0.65 | N/A | 0.5 | 0.1 / 0.1 | on | 放宽 smooth-only baseline，和 B 共享同一 smooth envelope |
| `B_Bours_v065_ws2_wa05_du01_alim` | `B_ours` | 0.65 | 2 | 0.5 | 0.1 / 0.1 | on | 只比 A 多 slosh-aware 项，保持公平 |

### 5.2 可选调参候选（只在 5.1 安全后加测）

| label | variant | v_ref | w_slosh | w_alpha | w_du_a/w_du_vs | output angular limiter | 用途 |
|---|---|---:|---:|---:|---:|---|---|
| `A0_Bsmooth_v065_wa03_du01_alim` | `B_smooth` | 0.65 | N/A | 0.3 | 0.1 / 0.1 | on | 若 A/B 的 0.5 仍太保守，成对降 smooth |
| `B0_Bours_v065_ws2_wa03_du01_alim` | `B_ours` | 0.65 | 2 | 0.3 | 0.1 / 0.1 | on | 与 A0 成对，保持同一 smooth envelope |
| `B2_Bours_v065_ws5_wa05_du01_alim` | `B_ours` | 0.65 | 5 | 0.5 | 0.1 / 0.1 | on | 更接近 20260611 默认 slosh 权重；需和 A 使用同一 smooth envelope 对比 |
| `D_pair_v050_wa05_du01_alim` | `B_smooth`/`B_ours` | 0.50 | 0 / 5 | 0.5 | 0.1 / 0.1 | on | 若 0.65 下任一组仍不稳，成对降速诊断 |

统一 limiter 参数：

```text
shared_angular_limit_enable=true
shared_angular_rate_max=1.2
shared_angular_accel_max=3.0
shared_angular_accel_max_dt=0.2
alpha_max=8.0
```

说明：

```text
B0 的 w_alpha / w_du_a / w_du_vs 不覆盖时沿用 variant 的 w_smooth fallback，用于检查基础 tracking 与旧代码口径。
w_du_a=-1.0 / w_du_vs=-1.0 表示沿用 variant 的 w_smooth fallback；对 B_smooth/B_ours 来说 fallback=1.0，实物第一弯可能过保守。
本版对 B_smooth/B_ours 显式设 w_du_a=w_du_vs=0.1，避免速度/路径进度第一帧连续性过强导致入弯修正太慢。
输出 angular limiter 是实物安全/诊断层，不应写成 OCP 本体贡献。
```

### 5.3 实物调参建议与停止条件

```text
已知现场现象：按 alpha_max=8.0、shared_angular_accel_max=3.0 后，B0(v_ref=0.65) 可过第一弯；但 B_smooth(w_alpha=2,w_du=fallback=1.0) 与 B_ours(w_slosh=10,w_alpha=2,w_du=fallback=1.0) 不安全。
判读：路径/定位/底盘通道基本可行，主要矛盾是 smooth/slosh 权重在 v_ref=0.65 下过强，第一弯需要的 omega/速度修正被压慢。
```

调参顺序：

```text
1. 固定 Z_B0_v065_alim 作为 tracking baseline；B0 不安全时不测 A/B。
2. 公平原则：A/B 主对比必须共用同一 v_ref、alpha_max、output limiter、w_alpha、w_du_a、w_du_vs；只允许 B_ours 相比 B_smooth 多 slosh-aware 项/权重。
3. 第一轮主对比用 A_Bsmooth_v065_wa05_du01_alim vs B_Bours_v065_ws2_wa05_du01_alim。
4. 如果 A/B 的 w_alpha=0.5 仍显得过保守或第一弯修正慢，成对退到 A0/B0 的 w_alpha=0.3,w_du=0.1，而不是只放宽某一组。
5. 如果 ws2 的 B_ours 稳定，再在同一 smooth envelope 下试 B2_Bours_v065_ws5_wa05_du01_alim；此时仍要保留对应 B_smooth(A) 作为同 envelope baseline。
6. 不再把 w_alpha=2,w_du=fallback=1.0,w_slosh=10 作为实物第一轮 smoke 参数；这些只保留为后续离线/仿真或低速诊断。
7. 若同 envelope 下 A/B 在 0.65 仍不稳，优先成对降 v_ref=0.50，而不是继续加大 smooth/slosh 权重。
```

和 20260611 记录的区别：

```text
20260611 P2 成功记录使用的是默认速度/默认权重：B0、B_slosh、B_ours 均 alpha_max=8.0，未显式 v_ref=0.65、w_alpha=2、w_slosh=10，也未显式打开本轮 output angular limiter。
因此 20260611 证明“默认低速 B_slosh/B_ours 能过”，不能直接证明“v_ref=0.65 + 强 smooth/slosh 权重能过”。
本轮若要做高速实物 A/B，必须先找到能稳定过第一弯的 relaxed smooth/slosh envelope，再谈 RGB 降晃。
```

## 6. 执行顺序

### 6.1 如果只做 B0 + A/B

```text
直接 closed-loop Smoke N=1（本轮不做 shadow）:
  Z(B0) -> 立刻检查 tracking/第一弯/bag/RGB/export/cmd diagnostics -> A -> 立刻检查 -> B

如果 Z/A/B 的 N=1 都安全且数据完整，再做 A/B N=3:
  Round 1: A -> B
  Round 2: B -> A
  Round 3: A -> B

B0 是否追加重复 run 只作为 tracking 诊断；主降晃结论仍看 A/B。
若时间允许，A/B N=4 更平衡：
  Round 4: B -> A
```

N=1 smoke 通过标准：

```text
1. 机器人全程可控，无明显离轨/转圈/朝障碍物运动。
2. bag 中有 /camera/color/image_raw、/cmd_vel、/odom、/spmpc/debug/cmd_vel_output。
3. 单 run 能导出 liquid_variation_summary.csv，valid_samples 正常。
4. output limiter 没有长时间持续大幅替 planner 修正。
5. 到点或安全停止后能按流程 zero、停 planner、停 recorder。
```

### 6.2 如果加入可选调参候选

```text
先 Z(B0) 与 A/B relaxed N=1 smoke 通过。
如果 B_ours ws2 稳定，再单独加 B2(ws5) N=1 smoke。
如果 A/B relaxed 仍不安全，按第 5.3 节成对降 smooth 或降 v_ref；不要只放宽某一组。
全部安全后才考虑 N=3：
  主表优先 A <-> B 成对交替
  B2 只作为 slosh 权重诊断，不直接替代主 A/B
```

B2 是调参候选，不参与第一轮最低风险 smoke 的必要项。Z(B0) 或 A/B 任一组 N=1 失败、第一弯明显不可控或数据链路不完整，则不跑 B2。

每个 run 之间：

```text
1. Ctrl-C 停 planner。
2. 发 /cmd_vel zero。
3. 停 rosbag。
4. 把车回到同一起点地面标记。
5. 等液体静稳，建议 60~90s。
6. 确认 /cmd_vel 无旧 publisher。
7. 再开始下一个 run。
```

## 10. 测后分析口径

主真值：**离线 RGB max-LCR 液面高度**。

辅助指标：

```text
/liquid/height, /liquid/height_lcr：在线 RGB 观测，只作现场快检；正式主表仍用 bag 图像离线复算。
/slosh/height：外部 standalone slosh monitor / evaluation-only 模型 proxy，只作趋势辅助。
/spmpc/slosh_height：SPMPC 内部模型 proxy，只作解释，不当真实液面高度。
/spmpc/debug/cmd_vel_output：证明输出限幅前后差异，不可忽略。
```

B0 判定口径：B0 只用于确认同一路径、同一 `alpha_max=8.0` 与同一输出安全层下的基础 tracking/第一弯行为；若 B0 在 20% 左右触发 `TRACKING_UNSAFE_PROJECTION` 或第一弯明显不可控，先停止 A/B，回到 `cmd_vel_output`、`warm_start_head`、`first_shot_summary` 和路径投影诊断。

第一轮 A/B 判定表：

| 指标 | 优先级 | 解释 |
|---|---:|---|
| RGB core 10%-90% p95/rms | 高 | 第一优先，用于判断行进段抑晃是否稳定。 |
| RGB core 10%-90% peak | 中高 | peak 要结合起步/终端/遮挡异常解释，不能单点决定。 |
| tracking error p95/rms | 高 | 避免用明显离轨换低晃动。 |
| `/cmd_vel |domega/dt|` p95/max | 高 | 检查输出安全层是否生效，不能出现不可解释尖峰。 |
| completion / first goal time | 中 | 速度收益要服从安全和抑晃。 |
| limiter activation rate | 中 | 短时介入可接受，长时间高比例介入说明 OCP/参数仍需改。 |

可以写成有效的条件：

```text
B_ours 相比 B_smooth：
1. RGB core p95 或 rms 稳定下降；
2. tracking 不明显变差；
3. completion 不失败；
4. /cmd_vel |domega/dt| 没有反向恶化；
5. limiter 不是长时间持续大幅替 planner 修正。
```

如果结果是：

```text
B_ours 只在 /spmpc/slosh_height 上更好，但 RGB 不好 -> 不能声称实物降晃有效。
B_ours RGB p95/rms 更好，但 peak 个别 run 异常 -> 保留证据，分析是否为起步/终端/视觉异常。
B_ours RGB 不优于 B_smooth -> 不继续扩展 TEB/DWA，回到参数/模型分析。
```

## 11. 何时扩展到 TEB/DWA

只有满足下面条件，才进入外部 planner 对比：

```text
1. SPMPC A/B 至少 N=3 全部安全。
2. B_ours 相比 B_smooth 在 RGB p95/rms 或 core peak 上有可写的实物证据。
3. real costmap for TEB/DWA 已现场复核，不直接套 sim costmap。
4. TEB/DWA 是否需要 shadow 另开外部 planner SOP 决定；不要混入本文 SPMPC 内部 A/B。
5. 对比表明确 common-limit 或 tuned-limit；不能混口径。
```

外部对比公平性原则：

```text
如果 SPMPC 使用 output angular limiter，TEB/DWA 要么也经过同一安全 envelope，
要么报告中明确写：SPMPC 是“带输出安全层”的实物候选，TEB/DWA 是各自原生输出，不能把结论写成纯 OCP 本体对比。
```

建议外部对比另开文档/另开批次，不混入第一轮 SPMPC 内部 A/B。

## 12. 最小可执行计划

如果当天时间有限，只做这一版：

```text
0. 启动传感器/定位/RGB，确认链路正常；确认急停人员就位。
1. 生成 P2 s_curve，发送固定目标；人工检查 RViz/path/goal。
2. 先开 recorder，再直接做 Z_B0_v065_alim closed-loop N=1 smoke，重点看第一弯、tracking safety 与 desired/limited cmd。
3. 停 planner、zero、停 recorder，立刻检查 bag 与 RGB export；B0 不安全或数据不完整则停止排障。
4. B0 通过后，做 A_Bsmooth_v065_wa05_du01_alim closed-loop N=1 smoke。
5. A 通过后，再直接做 B_Bours_v065_ws2_wa05_du01_alim closed-loop N=1 smoke。
6. A/B 两者都安全且数据完整，则按 A/B/B/A/A/B 或 A/B/B/A 做到 N=3/N=4。
7. 如果还有时间，B2_Bours_v065_ws5_wa05_du01_alim 只先做 N=1 smoke；若 0.65 仍不稳，再按第 5.3 节成对降到 v_ref=0.50。
8. 当天不做 TEB/DWA，除非 A/B 结论非常稳定且 baseline real costmap 已单独复核；更推荐另开批次/另开文档。
```

最小结论句模板：

```text
在同一 P2 s_curve 实物路径、同一输出角加速度安全层、同一 relaxed smooth envelope 下，B0(v_ref=0.65) 先作为基础 tracking/第一弯诊断；若 B0 与 A/B smoke 均安全，进一步判断 B_ours(v_ref=0.65,w_slosh=2,w_alpha=0.5,w_du=0.1)
相对 B_smooth(v_ref=0.65,w_alpha=0.5,w_du=0.1) 是否降低 RGB 液面 core p95/rms；若降低且 tracking/cmd 不恶化，
则 slosh-aware 项获得第一轮实物证据；否则不扩展外部 planner 对比，回到参数/模型分析。
```

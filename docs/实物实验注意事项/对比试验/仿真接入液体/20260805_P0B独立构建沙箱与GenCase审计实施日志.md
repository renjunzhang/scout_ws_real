### 9.3 对 `-accel tcg` 的修正

把 TCG 固定写成“更安全”并不严谨：

- 优点：不向 QEMU 开放 `/dev/kvm`，去掉 KVM 内核接口这一层；
- 缺点：所有客体指令进入 QEMU TCG 翻译器，扩大用户态 CPU 模拟代码的可达面，并显著
  降低构建性能；
- 对本项目而言，GenCase 首先只是可信 guest 内的非特权进程，主要隔离来自 guest OS、
  最小虚拟设备和 QEMU 自身 sandbox，而不是单独来自 TCG/KVM 选择。

建议把准入写成：首个极小 CLI smoke 可选择 TCG 作为独立风险实验；正式 CPU build 在
`+esm3`、`-nodefaults`、QEMU sandbox 和最小设备策略通过后使用 KVM。不能声称 TCG
天然优于 KVM。

### 20.3 namespace、QMP 和一次性语义

未来 launcher 不执行 `/usr/bin/unshare`，而是自有 child syscall：父进程先绑定
PID/starttime/PGID 并持有 pidfd，第一次 ACK 才允许创建 userns；child 清空 supplementary
groups，使用 `1000 -> 1000` UID/GID 映射，再创建 netns、确认只有 DOWN 且无地址/路由/
INET socket 的 loopback、丢弃全部 capability/bounding/ambient set，并重新绑定 PDEATHSIG。
父进程核验全部证据后关闭 namespace FD，第二次 ACK 才允许 exact FD exec。

QMP 只允许：

```text
qmp_capabilities
query-kvm      -> enabled=false, present=true
query-block    -> []
query-status   -> running=false, singlestep=false, status=prelaunch
quit
```

QEMU 4.2 文档说明 `quit` reply 不保证送达，所以完整写入 exact quit 后，clean EOF + direct
child exit 0 可以 PASS；如收到 event，只允许 quit 后的 exact `SHUTDOWN`，其
`guest=false/reason=host-qmp-quit`。QMP transcript 有严格 UTF-8/JSON duplicate-key/
NaN/帧数/单帧/总字节/deadline 限制。greeting 后再次核验 namespace、零 groups/caps、
`NoNewPrivs=1`、`Seccomp=2` 和无 KVM/TUN/Vhost/DRI/VFIO/USB/block/socket/host-path FD。

未来任何 live 尝试都先在锁内、fork 之前用 O_EXCL 创建并 fsync 固定 attempt marker；失败、
超时或断电也永久消耗本次 admission，不提供 reset/delete/retry。marker 提交时的
`NOT_CREATED/NOT_EXECUTED` 只描述提交瞬间，不能证明后续没有尝试。PASS receipt 发布后还要
O_NOFOLLOW 重新读取，验证 regular/nlink/owner/mode/size、schema、自哈希、当前资产、marker、
A/B/C、namespace、QMP wire/output 和 effect 语义，才允许 gate 返回 PASS。
父进程在一次性运行作用域内固定并最终恢复 `umask=0027`，确保 marker `0600`、receipt
`0640` 不会因调用者的更严格 umask 在成功后才发生模式复验失败。

# 地形条件晃液经验地图：最终版方案

**英文名称：** Terrain-Conditioned Slosh Experience Map  
**备选名称：** Payload-Aware Slosh Risk Map  
**适用系统：** Scout Mini + `spmpc_local_planner` + 固定全局路径液体运输  
**版本：** Final v1.2（仿真 smoke 与 R0 方案状态同步）
**日期：** 2026-06-21
**状态更新：** 2026-06-22：方案主线未变，已完成 S0/S1/S2 仿真软件链路 smoke 与 R0 实物探索采集方案；下一步进入 R0 实物采集，不进入 R1 冻结或 R2 盲测。

---

## 0. 执行摘要

本文提出一个与 SPMPC 解耦的**空间经验扩展层**：将历史通行中的 RGB 液面真值、IMU 冲击、机器人位姿、通过速度、方向、入射角和 slosh model 残差，组织为可复用的**地形事件经验数据库**；再将这些经验投影到当前地图，并沿当前全局路径导出风险剖面 \(R(s)\) 和条件化参考速度 \(v_{\mathrm{ref,map}}(s)\)。

第一阶段不修改 acados OCP，也不把在线 RGB 反馈进闭环。运行时只读取已经冻结的风险资产，通过轻量 Map-vref 接口调节 SPMPC 的参考速度；后续 R1/R2 前可再拆成独立适配器：

\[
v_{\mathrm{ref,map}}(s)
=
\min\!\left(
v_{\mathrm{ref,base}}(s),
v_{\mathrm{safe}}(s)
\right)
\]

该量在第一阶段是**地图条件参考速度**，不是严格硬速度约束。若后续需要对所有 planner 强制相同上界，可增加独立的 `MapGate`。

当前代码状态需要明确：第一阶段的最小只读 Map-vref 接口已经在 `spmpc_local_planner` 侧打通。现有实现可从 ROS 参数 runtime override 或 profile CSV 查得 `v_ref_current`，并注入 acados 已有的 `V_REF` stage parameter；`variant_.v_ref` 仍保留为 base/fallback。该实现不改变 OCP 状态维度、动力学模型或 codegen，符合本方案“先 Map-vref、后 Map-OCP”的落地顺序。

本方案的核心不是“把 RGB 峰值画在地图上”，而是：

1. 将门槛、接缝等建模为**物理地形事件**；
2. 考虑液体响应滞后，将后续液面响应归因给事件；
3. 根据速度、方向、入射角、payload 和事件前液体状态估计条件风险；
4. 强制执行 `build → validate → freeze → use → evaluate`，杜绝测试数据泄漏；
5. 用 `uniform_slow` 基线排除“地图版只是整体变慢”的解释。

当前论文落地顺序明确为：

```text
先仿真/人工 risk zone 跑通软件链路
  -> 再实物采集 RGB/IMU/odom/cmd/path
  -> 离线构图并冻结 profile
  -> 最后做冻结盲测对比
```

仿真阶段不要求得到真实 RGB 结论，只负责证明 Map-vref 接口、录包、metrics 和控制行为能闭环；实物阶段才负责构建真正用于论文主结果的 terrain-conditioned slosh experience map。

# 1. 研究动机与问题定义

## 1.1 当前 SPMPC 的能力边界

当前 SPMPC 已显式考虑：

- 平面线加速度 \(a\)；
- 横向运动激励 \(v\omega\)；
- 二阶液体模态状态 \(\eta,\dot{\eta}\)；
- fixed global path 下的 tracking、progress、smooth 与 slosh cost。

但实验室跨室运行时，门槛和接缝会引入当前平面模型没有完整描述的因素：

- 垂向冲击；
- pitch / roll；
- 重力在容器坐标系内的水平投影变化；
- 轮胎—地面接触振动；
- 底盘结构与容器支架振动；
- 定位误差和重复通行差异。

Di Leva 等的实验模型研究表明，液体高度估计在考虑平面运动之外还可扩展到垂向加速度，说明门槛场景中的垂向激励确实值得单独处理 [11]。

## 1.2 目标

对固定物理环境中的门槛、接缝等重复地形事件，学习：

\[
R_e
=
R_e
\left(
v,\ d,\ \phi,\ \chi_{\mathrm{pre}},\ p
\right)
\]

其中：

- \(v\)：通过速度；
- \(d\)：通行方向；
- \(\phi\)：相对门槛法向的入射角；
- \(\chi_{\mathrm{pre}}\)：进入事件前的液体状态或视觉代理；
- \(p\)：payload 配置，包括容器、水位、液体、安装和相机标定。

最终沿路径生成：

\[
R(s),\quad
C(s),\quad
v_{\mathrm{safe}}(s)
\]

用于 SPMPC 的空间条件速度调度。

# 3. 模块化与解耦原则

## 3.1 包级解耦

建议新增独立 ROS 包：

```text
spmpc_terrain_slosh_map
```

禁止将以下逻辑塞入 `continuous_mpcc_solver_acados.cpp`：

- RGB 处理；
- bag 时间同步；
- 门槛事件检测；
- 风险地图构建；
- train / validation / test 管理；
- 地图版本注册；
- 经验数据库更新。

`spmpc_local_planner` 只消费标准化的路径风险 profile，不依赖 RGB、IMU 建图实现。

## 3.2 职责边界

| 包 / 层 | 允许职责 | 禁止职责 |
|---|---|---|
| `spmpc_terrain_slosh_map` | 离线构图、冻结地图、导出 profile | 直接发布 `/cmd_vel` |
| `spmpc_local_planner` | 消费 profile、求解 OCP、输出控制 | 训练或更新风险地图 |
| `spmpc_experiments` | 编排、录包、指标和报告 | 实现地图算法主体 |
| RGB pipeline | 提供视觉液面标签 | 在测试 run 中在线改变 planner |
| external slosh monitor | 统一评价和辅助解释 | 在测试时反馈给 planner |

# 4. Method

## 4.1 三层风险资产

### A. Slosh Experience Database

长期保存与具体 SLAM 地图无关的物理事件经验：

\[
\mathcal D
=
\left\{
e_i,\ p_i,\ z_i,\ y_i,\ c_i
\right\}_{i=1}^{N}
\]

其中：

- \(e_i\)：地形事件 ID；
- \(p_i\)：payload ID；
- \(z_i\)：条件变量；
- \(y_i\)：RGB / IMU / residual 响应；
- \(c_i\)：数据质量与置信度。

### B. Map Risk Projection

把物理事件从 canonical frame 投影到当前 `map_id`：

```text
physical event
→ canonical pose
→ current map transform
→ event polygon / PRE / EVENT / POST zones
```

### C. Path Risk Profile

沿当前全局路径 \(\mathbf r(s)\) 采样：

\[
R(s)
=
R_{\mathrm{map}}
\left(
\mathbf r(s)
\right)
\]

输出：

```text
s
risk
confidence
zone
event_id
v_safe
v_ref_map
```

换路径只重新导出 profile；同一物理环境重新 SLAM 只重新配准和投影，不重新采集全部 RGB 数据。

---

## 4.2 数据时间同步

将 RGB 时间轴作为主时间轴，配对：

\[
H_{\mathrm{vis}}(t_i),\
H_{\mathrm{model}}(t_i),\
\mathbf p(t_i),\
\mathbf f_{\mathrm{imu}}(t_i),\
v(t_i),\
\omega(t_i)
\]

若最近邻或插值间隔满足：

\[
\Delta t_{\mathrm{gap}} > 0.15\ \mathrm{s}
\]

则丢弃该样本。

所有同步参数、时间偏移和丢弃比例写入 `sync_report.yaml`。

---

## 4.3 事件定义与局部坐标系

每个门槛或接缝建立事件局部坐标系 \(\mathcal F_e\)：

- \(x_e\)：门槛法向；
- \(y_e\)：沿门槛方向；
- 原点：门槛几何中心；
- \(\phi\)：机器人速度方向相对 \(x_e\) 的夹角。

事件 registry 至少保存：

```yaml
event_id:
type:
canonical_pose_xy_yaw:
polygon:
height_m:
width_m:
edge_shape:
normal_yaw:
pre_zone_length:
post_zone_length:
registration_uncertainty:
```

---

## 4.4 门槛事件检测

第一版采用“已知几何 + IMU”联合检测：

\[
\mathrm{event}
=
\mathrm{inside\_polygon}
\land
\left(
|a_z| > \tau_a
\ \lor\
|j_z| > \tau_j
\ \lor\
|\dot{\theta}_{\mathrm{pitch}}| > \tau_p
\right)
\]

得到冲击时刻 \(t_e\)。

若几何触发与 IMU 峰值相差过大，则标记：

```text
EVENT_ALIGNMENT_UNCERTAIN
```

---

## 4.5 事件前液体状态筛选

液体有记忆。相同门槛和速度下，不同初始残振会得到不同结果。因此每个事件保存：

\[
\chi_{\mathrm{pre}}
=
\left[
H_{\mathrm{vis,pre,p95}},
H_{\mathrm{model,pre,p95}},
\eta_x,\dot{\eta}_x,\eta_y,\dot{\eta}_y
\right]
\]

第一版可设置静稳筛选条件：

\[
H_{\mathrm{vis,pre,p95}} < H_{\mathrm{pre,max}}
\]

并要求事件前速度和角速度在规定窗口内稳定。

不满足时：

```text
PRE_SLOSH_NOT_SETTLED
```

该样本可进入探索分析，但不能和静稳样本混合估计正式风险。这里的“筛选”只是论文数据分组规则，不是复杂工程 gate。

---

## 4.6 响应窗口与液体记忆归因

门槛冲击发生后，RGB 液面峰值通常滞后出现，因此不能把峰值直接写到峰值时刻的机器人位置。

第一版采用事件响应窗口：

\[
\mathcal W_e
=
[t_e,\ t_e + T_r]
\]

在该窗口内计算：

\[
H_{e,\mathrm{peak}}
=
\max_{t\in\mathcal W_e} H_{\mathrm{vis}}(t)
\]

\[
H_{e,\mathrm{p95}}
=
Q_{0.95}
\left(
H_{\mathrm{vis}}(t),\ t\in\mathcal W_e
\right)
\]

\[
H_{e,\mathrm{rms}}
=
\sqrt{
\frac{1}{|\mathcal W_e|}
\int_{\mathcal W_e} H_{\mathrm{vis}}^2(t)\,dt
}
\]

并估计门槛后 settling time：

\[
T_{\mathrm{settle}}
=
\min
\left\{
\tau:
H_{\mathrm{vis}}(t)
<
H_{\mathrm{settle}}
,\ \forall t\ge t_e+\tau
\right\}
\]

第二版可通过 IMU 冲击和 RGB 液面互相关估计时延，再使用滞后核归因。

---

## 4.7 模型残差层

对 slosh model 做训练集标定：

\[
\widetilde H_{\mathrm{model}}(t)
=
k_{\mathrm{cal}} H_{\mathrm{model}}(t)
\]

其中 \(k_{\mathrm{cal}}\) 只能由 train / validation 数据确定。

定义正残差：

\[
H_{\mathrm{res}}(t)
=
\max
\left(
0,\
H_{\mathrm{vis}}(t)
-
\widetilde H_{\mathrm{model}}(t)
\right)
\]

含义是：

```text
真实视觉液面中未被当前平面 slosh model 解释的部分
```

该残差可能来自地形冲击、垂向激励、pitch/roll、结构振动或模型误差。因此正式表述应为：

> spatially repeatable unmodeled slosh risk

而不是直接宣称全部 residual 都是地形真值。

---

## 4.8 条件风险估计

事件条件向量：

\[
z_e
=
[
v_e,\ d_e,\ \phi_e,\ \chi_{\mathrm{pre}},\ p_e
]
\]

第一版使用可解释的分箱统计，不使用复杂神经网络：

```text
speed_bin × direction × approach_angle_bin × payload_id
```

对每个 bin 估计：

\[
\widehat Q_{0.95}(H_{\mathrm{vis}}\mid z)
\]

和不确定性：

\[
\sigma_H(z)
\]

定义风险上置信界：

\[
R_e(z)
=
\widehat Q_{0.95}(H_{\mathrm{vis}}\mid z)
+
\beta \sigma_H(z)
\]

置信度由样本数、方差、同步质量、事件定位误差和 RGB 有效帧比例共同确定。

低置信度区域不自动认为安全。

---

## 4.9 RGB、残差、IMU 与仿真先验的融合

建议保留独立 layer：

```text
R_rgb
R_res
R_imu
R_sim
confidence
sample_count
```

在各 layer 完成独立验证前，不强制融合为单一数值。

需要融合时：

\[
R_{\mathrm{fused}}
=
\frac{
\sum_j w_j C_j R_j
}{
\sum_j w_j C_j + \epsilon
}
\]

其中：

- \(R_j\)：第 \(j\) 类风险；
- \(C_j\)：该风险的置信度；
- \(w_j\)：只由 validation 数据确定的固定权重。

实物 RGB 风险应具有最高优先级；仿真只作为未覆盖区域的弱先验。

---

## 4.10 PRE / EVENT / POST 风险投影

每个事件投影为三段：

1. **PRE：** 提前减速区；
2. **EVENT：** 实际冲击区；
3. **POST：** 残振恢复区。

提前减速距离满足：

\[
d_{\mathrm{pre}}
\ge
\frac{
v_{\mathrm{base}}^2
-
v_{\mathrm{cross}}^2
}{
2a_{\mathrm{dec}}
}
\]

恢复区长度可取：

\[
d_{\mathrm{post}}
=
v_{\mathrm{cross}} T_{\mathrm{settle}}
\]

并根据定位和事件配准不确定性膨胀事件区域。

---

## 4.11 从风险估计安全通过速度

对每个条件 bin，定义目标液面阈值 \(H_{\mathrm{target}}\)。

选择满足上置信界要求的最大速度：

\[
v_{\mathrm{safe}}
=
\max_v
\left\{
v:
\widehat Q_{0.95}(H\mid v,d,\phi,p)
+
\beta\sigma_H
\le
H_{\mathrm{target}}
\right\}
\]

若样本不足：

```text
使用相邻 bin 的保守下界；
或使用仿真 / 几何先验；
或标记 UNKNOWN 并降到默认保守速度。
```

---

## 4.12 路径风险剖面

沿路径采样得到：

\[
R(s),\quad C(s),\quad v_{\mathrm{safe}}(s)
\]

建议 CSV：

```csv
s_m,x_map,y_map,event_id,zone,
risk_rgb_p95_mm_ucb,risk_residual_p95_mm_ucb,risk_imu,confidence,
v_ref_base_mps,v_safe_mps,v_ref_map_mps,
unknown_flag,quality_flag
```

字段口径：`risk_rgb_p95_mm_ucb` 和 `risk_residual_p95_mm_ucb` 单位为 mm；`risk_imu` 是归一化冲击风险；`unknown_flag=true` 表示低样本或低置信区域，不得默认安全；`v_ref_map_mps` 是冻结后实际提供给 Map-vref adapter 的参考速度。

风险剖面必须附带：

```text
map_id
path_id
path_hash
payload_id
risk_map_hash
source_commit
freeze_time
```

---

## 4.13 第一阶段控制接入：Map-vref

第一阶段只调整参考速度：

\[
v_{\mathrm{ref,map}}(s)
=
\min
\left(
v_{\mathrm{ref,base}}(s),
v_{\mathrm{safe}}(s)
\right)
\]

随后执行与老速度 profile 一致的前向 / 后向加减速约束和平滑，避免风险边界产生阶跃。

重要边界：

> `v_ref_map` 是 OCP 的参考速度，不是严格硬上界。

必须同时记录：

```text
v_ref_base
v_ref_map
cmd_v
odom_v
event crossing speed
reference exceedance ratio
```

## 4.14 可选通用 MapGate

为了验证地图先验是否对所有 local planner 都有帮助，可增加独立 `MapGate`：

\[
v_{\mathrm{cmd,post}}
\le
v_{\mathrm{safe}}(s)
\]

该 gate 可用于：

```text
DWA + MapGate
TEB + MapGate
SPMPC + MapGate
```

它属于统一执行安全层，不属于 SPMPC OCP 贡献。

只有在 Map-vref 被证明有效后，按顺序推进：

### Map-w

\[
w_{\mathrm{slosh},k}
=
w_0
\left(
1+\lambda_w R_k
\right)
\]

### Map-hcap

\[
h_{\max,k}
=
\frac{
h_0
}{
1+\lambda_h R_k
}
\]

使用 nonlinear soft constraint + slack，不建议无 slack 的纯硬约束。

### Map-OCP

将：

```text
v_ref,k
w_slosh,k
h_max,k
terrain risk
```

作为 shooting-stage parameter 进入 acados。

# 5. 仿真到实物的推进方式

## 5.1 仿真作用

仿真用于：

- 验证时间同步和事件检测；
- 验证风险资产的构建、冻结和导出；
- 调试门槛几何、方向和风险区；
- 获得低置信度空间的弱先验；
- 验证 Map-vref 不破坏到点和 tracking。

仿真 slosh model 不能同时作为控制器内部模型、构图标签和最终评价真值。

## 5.2 门槛仿真搭建

必须建立真实碰撞几何，而不是只在 2D costmap 上画高代价带。

优先校准：

- 门槛高度、宽度、边缘形状；
- 轮径、轮胎接触和摩擦；
- 底盘质量与惯量；
- 接触刚度和阻尼；
- 容器安装高度；
- 仿真 IMU 的 \(a_z\)、pitch、roll 峰值与双峰间隔。

## 5.3 实物主标签

实物构图主标签：

```text
offline RGB max-LCR
```

在线 `/liquid/height` 只用于 preliminary 检查。

模型 proxy 和 IMU 是辅助 layer，不替代 RGB。

# 9. 实验设计

## 9.1 最小闭环方法矩阵

| 方法 | 目的 |
|---|---|
| `B_ours` | 无地图基础方法 |
| `B_ours_uniform_slow` | 排除“地图只是整体变慢” |
| `B_ours_map_vref` | 最小地图闭环 |
| `B_smooth_map_vref` | 区分地图先验与在线 slosh state |
| `B_ours_oracle_vref` | 只作理论上界，不进主结论 |

## 9.2 门槛条件矩阵

```text
2 个方向
× 3～4 个速度 bin
× 2 个入射角 bin
× 固定 payload
× 每条件 N≥5
```

正式关键条件建议 N≥10。

## 9.3 主要指标

### 液面

- RGB peak；
- RGB p95；
- RGB RMS；
- RGB AUC；
- event-window peak / p95；
- post-threshold settling time。

### 导航与公平性

- success rate；
- first goal time；
- mean velocity；
- completion-time ratio；
- tracking RMS / max；
- crossing speed。

### 控制安全

- \(|dv/dt|\) p95 / max；
- \(|d\omega/dt|\) p95 / max；
- vref exceedance ratio；
- MapGate clamp ratio。

### 地图质量

- 跨 run 热点位置误差；
- 风险与测试 RGB p95 的秩相关；
- high-risk event AUROC；
- calibration curve；
- sample count 与 confidence coverage。

## 9.4 主验证问题

1. 地图热点是否在同一物理门槛位置跨 run 重复？
2. `map_vref` 是否在相近完成时间下降低 RGB peak / p95？
3. `map_vref` 是否优于 `uniform_slow`？
4. 风险是否依赖速度、方向和入射角？
5. residual layer 是否比 raw RGB map 更能定位模型未解释区域？
6. 地图是否能在冻结后泛化到新 test run？

# 10. 论文版最小推进路线

本文目标是形成可发表的实验贡献，不追求完整工程产品化。因此不采用繁琐 gate 流程，只保留“先仿真跑通、再实物采集、最后冻结盲测”的三步证据链：

| 步骤 | 任务 | 交付物 | 论文中要证明的点 |
|---|---|---|---|
| Step 1：仿真先行 / 人工 risk zone smoke | 打通 `risk profile -> Map-vref -> SPMPC` 软件链路，先不用真实 RGB 构图 | 人工 risk zone profile、map-vref smoke bag、速度曲线、v_ref/cmd_v/odom_v 对齐图 | Map-vref 接口有效；风险区能局部降速；不破坏到点、tracking 和控制平滑性 |
| Step 2：实物采集、构图与冻结 | 对一个门槛/接缝采集 RGB+IMU+odom+cmd+path，离线构建并冻结单环境单 payload 风险 profile | event DB、frozen profile、hash/meta、sync_report、quality_report | 热点位置可重复，风险随速度/方向有解释性；test 未参与构图 |
| Step 3：冻结盲测对比 | 跑 `B_ours` / `B_ours_uniform_slow` / `B_ours_map_vref` | 三组 test bags、RGB 指标表、控制指标表 | Map-vref 在相近完成时间下降低 RGB peak/p95/settling，并优于整体降速解释 |

可选扩展：只有上述三步形成清晰正结果后，才考虑 `B_smooth_map_vref`、多门槛、多 payload、Map-w / Map-hcap / Map-OCP。论文第一版不需要把这些做成工程 gate。

# 11. 失败模式与规避

| 风险 | 后果 | 规避 |
|---|---|---|
| 将 RGB 峰值写到峰值位置 | 热点偏到门槛后方 | 事件窗口 + 滞后归因 |
| 忽略进入门槛前残振 | 条件风险方差过大 | 静稳筛选或 \(\chi_{\mathrm{pre}}\) 条件化 |
| 将 `v_ref_map` 当硬 cap | 实际速度可能超出 | 明确软参考；记录 exceedance |
| 地图版整体更慢 | 贡献不清 | time-matched uniform-slow |
| test RGB 更新地图 | 数据泄漏 | build/freeze/use/evaluate 分离 |
| 换 payload 继续用旧图 | 风险量级失效 | `payload_id` 强制隔离 |
| 仿真模型自证 | 结论循环 | RGB truth / 独立 monitor 优先 |
| 直接上 h hard bound | OCP infeasible | 先 Map-vref，再 slack soft bound |
| 低样本格被认为安全 | 不安全泛化 | confidence/UCB 和 UNKNOWN 策略 |
| 地图配准误差 | PRE/EVENT 区错位 | canonical frame + uncertainty inflation |

# 12. 预期论文贡献

该模块可以形成以下扩展贡献：

1. **任务相关 terrain interaction mapping：** 将液体负载的 RGB 晃动响应作为地形交互反馈，而非只使用坡度或粗糙度。
2. **事件级晃液经验资产：** 将门槛经验与具体 SLAM 地图、具体路径解耦。
3. **液体记忆感知归因：** 使用事件响应窗口和事件前状态，避免直接把滞后峰值绑定到错误位置。
4. **在线状态记忆 + 离线空间记忆：**
   - \(\eta,\dot{\eta}\) 表示液体当前如何晃；
   - Slosh Experience Map 表示前方地形以前如何激发晃动。
5. **公平闭环验证：** 通过冻结地图、time-matched uniform-slow 和 RGB test truth，验证空间自适应而非单纯降速。

# 13. 论文表述边界

可以声称：

> 历史 RGB / IMU 交互经验可用于构建与 payload 条件相关的地形事件风险，并为 fixed-path SPMPC 生成空间条件速度先验。

暂不声称：

- residual 全部等价于地形真值；
- 当前模块已经实现完整 terrain-aware route planning；
- 仿真地图可以直接替代实物 RGB；
- Map-vref 是 OCP 内硬速度约束；
- 地图在新 payload、新楼层或任意环境中无需重标定。

# 15. 最终实施建议

近期只实现以下最小闭环：

```text
一个实验室环境
+ 一个门槛
+ 一个固定 payload
+ 事件级经验数据库
+ frozen path risk profile
+ Map-vref
+ B_ours / uniform_slow / map_vref 三组对比
```

成功标准：

```text
1. frozen map 在 test run 中只读；
2. 门槛热点跨 run 空间重复；
3. map_vref 与 uniform_slow 完成时间接近；
4. map_vref 的 RGB peak / p95 / settling time 更低；
5. tracking 和 |dv/dt|、|dω/dt| 不恶化；
6. 所有资产具备 map/path/payload/hash 可追溯性。
```

在该闭环被证明有效之前，不进入完整二维在线学习、Map-hcap 或 Map-OCP。

# 16. 工程实现细节补充（v1.1）

本节补充“如果真的采用该方案，第一版应该怎么落地”。核心原则是：**仿真先打通软件链路，实物采集 RGB/IMU/位姿构图，冻结后盲测评价；第一阶段只做 Map-vref，不做在线 RGB 闭环，也不改 acados 动力学模型和状态维度。**

## 16.1 数据集口径：不一定是神经网络，但必须防泄漏

本方案中的 “train / validation / test” 更准确可写为：

| 英文口径 | 中文口径 | 用途 | 是否允许改风险资产 |
|---|---|---|---:|
| train / build | 构图集 | 构建事件经验库、估计风险统计 | 是 |
| validation / check | 校验集 | 选择响应窗口、bin、UCB 系数、PRE/POST 长度、UNKNOWN 策略 | 是，但必须在 freeze 前完成 |
| test / blind evaluation | 冻结盲测集 | 只评价 frozen map + Map-vref 是否有效 | 否 |

最低要求：

```text
构图/校验数据 ≠ 正式评价数据
冻结后的 test RGB 只进入 metrics/report，不得更新 risk map、v_safe profile 或 planner 参数。
```

推荐生命周期：

```text
Build → Validate → Freeze → Use → Evaluate
构图 → 校验 → 冻结 → 使用 → 评价
```

## 16.2 仿真到实物推进顺序

执行顺序固定为：**先仿真跑通接口与实验脚本，再实物采集 RGB/IMU/位姿数据**。原因是实物采集成本高，且一旦发现 Map-vref 接口、录包 topic、progress 对齐或 metrics 有问题，实物数据会难以复用。

仿真环境按隔离 SOP 执行，默认使用：

```text
/data/a/scout_sim_replacement
```

固定路径、可视化诊断和 SPMPC smoke 必须显式指定已确认地图：

```bash
MAP_FILE=/data/a/scout_sim_replacement/maps/proxy_world_manual_saved_20260611_154348.pbstream
```

推荐顺序是先启动“仿真 + Cartographer 定位 + RViz”，确认 `/map`、`/scan_front`、RobotModel、TF 对齐后，再 attach SPMPC。终点必须在 RViz 中确认位于已建图空地，不要放在墙边、角落、未知区域或障碍物附近；若地图、激光、TF 未对齐，本次 smoke 不作为有效结果。

```text
S0 仿真/人工 profile：验证软件链路                         [2026-06-22 已完成]
S1 仿真 PRE/EVENT/POST：验证事件区、PRE/POST 与 metrics    [2026-06-22 已完成]
S2 仿真 + /slosh/height：补齐评价侧 slosh_proxy 记录       [2026-06-22 已完成]
R0 实物探索采集：验证真实热点是否存在且重复                 [下一步]
R1 构图/校验/冻结：生成 frozen profile                     [未开始]
R2 冻结盲测对比：形成论文主结果                            [未开始]
```

### S0：人工 risk zone 仿真 smoke

先不建真实门槛模型，只人工构造一个 profile，例如：

```text
s = 2.0~2.6 m
zone = EVENT
v_ref_base = 0.25 m/s
v_safe = 0.12 m/s
v_ref_map = min(v_ref_base, v_safe)
```

验证目标：

```text
1. risk profile 可加载；
2. path_hash / map_id / payload_id 可校验；
3. Map-vref adapter 能输出 v_ref_current 或 v_ref_k；
4. SPMPC 能消费该参考速度；
5. cmd_v / odom_v 在风险区前下降，通过后恢复；
```

## 16.4 SPMPC runtime v_ref 接口

当前 `spmpc_local_planner` 的第一版接口已经完成最小落地：主线 acados solver 仍把同一个 `V_REF` 写入所有 shooting stage，但该 `V_REF` 可由 `SolverInput::v_ref_current` 在每个控制周期覆盖；若没有 runtime/profile 输入，则回退到 variant 中的 `v_ref`。

### A. 最小实现：per-cycle scalar `v_ref_current`

```text
当前 progress s0 或 [s0, s0 + lookahead_s]
  -> 查询 profile CSV（S0/S1 为人工 profile；R1 后为 frozen profile）
  -> v_ref_map_mps / v_safe_mps
  -> v_ref_current
  -> 当前控制周期所有 shooting stages 共用 V_REF
```

当前已实现参数口径：

```yaml
map_vref:
  runtime_v_ref_enable: false   # 手动标量 override，用于 smoke/debug
  runtime_v_ref: -1.0
  profile_enable: false         # 只读 CSV profile lookup
  profile_path: ""              # 支持 s_m/progress_s_m 与 v_ref_map_mps/v_safe_mps 等列名
  profile_lookahead_s: 0.0
```

后续如果拆出独立 `spmpc_terrain_slosh_map` 包，可再升级为 topic/msg 模式：

```yaml
map_vref:
  enable: false
  mode: scalar_current
  source: topic            # topic | csv_file
  topic: /terrain_slosh_map/v_ref_current
  stale_timeout_sec: 0.5
  fallback_to_variant_v_ref: true
  min_v_ref_mps: 0.05
  max_v_ref_mps: 0.8
  slew_rate_limit_mps2: 0.6
  lookahead_s: 0.60
```

当前完成情况：

```text
已完成：VariantConfig/variant_.v_ref 保留为 base/fallback。
已完成：SolverInput 增加 has_v_ref_current、v_ref_current、v_ref_status。
已完成：SpmpcLocalPlannerROS 支持 runtime scalar override 与 CSV profile lookup。
已完成：ContinuousMpccSolverAcados 与 legacy backend 使用 input.v_ref_current 覆盖 variant_.v_ref。
已完成：DiagnosticsPublisher 发布 /spmpc/debug/v_ref_current 与 /spmpc/debug/map_vref_status。
未做：独立 topic subscriber、stale timeout、stage-wise v_ref_k；这些留到 R1/R2 前视需要升级。
```

### B. 完整实现：stage-wise `v_ref_k`

```text
stage k -> s_k -> v_ref_map(s_k) -> p_k[V_REF]
```

优点是 horizon 内能提前看到 PRE zone；缺点是需要修改 solver 参数填充逻辑、warm start/debug/metrics。建议在 scalar_current smoke 通过后再做。

# 置信度门控、相位漏斗约束的残差式 S-MPCC 方案

日期：2026-08-18

英文名称：**Confidence-Gated Phase-Funnel Residual S-MPCC**

文档状态：`RESEARCH_PROPOSAL`。本文给出可实现、可消融和可形成论文方法章节的候选方案；尚未完成代码实现、漏斗计算、闭环仿真或实物验证，因此不得把本文中的预期性质写成已证实结论。

2026-08-19 实施约束：本方案在控制机理上比继续使用 full-horizon liquid cost 或继续增大 `w_slosh` 更针对当前实物断点，但只有在 `actual-input replay` 仍能解释真实 RGB、且 `OfflineSloshOCP` 先证明完整抵消序列在实物有效时，才允许进入 residual/tube 实现。当前 [G3R3 短可信时域公平配对实物验证](../对比试验/实物对比实验/20260819_G3R3短可信时域公平配对实物验证方案.md)只负责产生这一决策所需的证据，不得与本方案未来的新 release 混用。

## 1. 方案结论

建议将下一阶段的论文主线定义为：

> 将离线优化得到的完整防晃抵消序列转换为随轨迹相位变化的可恢复漏斗；在线 MPCC 围绕该序列优化残差，只在经过数据验证的可信短时域内传播液体状态，同时保留较长的机器人和障碍预测时域。在线局部绕障造成的液体幅值与相位偏差必须在可信时域末端重新进入可恢复漏斗，否则控制器转入减速、恢复或安全停车。

该方案不是“离线轨迹规划 + 在线 MPC”的模块拼接。论文级方法对象由以下三个相互约束的部分组成：

1. **Phase-indexed recoverability funnel**：把离线 nominal 的完整相位抵消能力转换成在线可用的终端可恢复集合。
2. **Confidence-gated trusted slosh horizon**：液体预测时域随 observer、执行器和模型可信度变化，不再默认完整 `2 s` 液体预测都有效。
3. **Residual local replanning**：在线 MPCC 优化 `u = ū(τ) + δu`，在局部避障和保持离线防晃序列之间建立可观测的“相位债务—恢复”关系。

上面是论文目标版本，不是第一版一次性实现清单。最小可行版本固定 `N_s=3`（`0--100 ms`），先完成 Scout 执行链辨识、OfflineSloshOCP、residual control 和 empirical recoverability tube；逐周期自适应 confidence horizon 最后加入。这样才能分别判断收益来自执行模型、完整 nominal、phase tube 还是 confidence gate。

当前论文库足以支持这是一个明确的候选研究缺口，但不能据此宣称“世界首次”。正式形成 novelty claim 前仍需补充截至投稿日期的外部系统检索。

## 3. 为什么该方案针对当前实物问题

当前证据是“控制仿真正向，但实物 RGB 未复现”，而不是已经证明实物稳定反向。现有诊断进一步显示：

- 真正可用后的 planned liquid prediction 约在 `0--100 ms` 尚有方向信息；
- `100--333 ms` 相关性明显衰减；
- `333 ms` 后不宜继续作为强物理预测；
- 每 `33 ms` 只执行 MPC 第一拍，后续抵消动作会被下一轮重新规划覆盖；
- planned、commanded 与 realized 激励之间可能存在延迟、限幅和底盘内环失配；
- 当前 FixedProfile 只是传统方法框架和诊断基线，现有 R7 描述性仿真结果没有显示成熟的减晃能力。

本方案分别对应这些问题：

| 当前问题                      | 方法响应                                                                             |
| ----------------------------- | ------------------------------------------------------------------------------------ |
| 远期液体节点低可信            | 将机器人/障碍 horizon 与液体可信 horizon 分离                                        |
| 滚动重规划覆盖后续抵消动作    | 使用 phase funnel 保留“仍可恢复”的跨周期条件                                       |
| 离线轨迹无法在线避障          | 只优化 nominal 周围的 residual，并允许虚拟相位时钟调整                               |
| 理想计划输入与实车激励不一致  | 在 OCP 中加入执行器/realization state，液体由 realized excitation 驱动               |
| observer 新鲜度和模型误差变化 | 由 lead、age、innovation、realization 和 parameter confidence 决定液体时域及风险余量 |

是否进入本方案必须按 G3R3 的失败类型判断：

| G3R3 或前置结果 | 对本方案的含义 |
| --- | --- |
| planned-input 预测差，但 actual-input replay 能在 held-out bag 解释 RGB | 可以进入 Scout 执行链辨识和 OfflineSloshOCP，方向成立 |
| Matched0/Matched5 的 first action 几乎没有可执行差异 | 先检查动作敏感度；当前结果不可判定，不足以支持直接换架构 |
| actual-input replay 仍不能解释 RGB | 暂停本方案，先修液体模型、坐标、observer、RGB 投影或时间对齐 |
| OfflineSloshOCP 在 matched-task 实物比较中正向，而滚动在线 MPC 不正向 | 最支持 phase-tube residual 路线，说明完整抵消序列可能被滚动覆盖或实现失配破坏 |
| OfflineSloshOCP 也不优于 Bsmooth | 不构造 funnel；nominal 抵消序列本身没有实物依据 |

最理想的进入证据链为：

```text
actual-input liquid model 在 held-out bag 有效
→ 含冻结 Scout 执行模型的 OfflineSloshOCP 实物有效
→ 完整离线抵消序列有效，但滚动在线 MPC 未复现
→ phase-tube residual S-MPCC 具有明确物理动机
```

## 5. 离线阶段：从防晃 nominal 到相位漏斗

### 5.1 OfflineSloshOCP

第一版不重新选择全局路径几何，只在冻结路径或走廊内完成 model-based retiming。复用当前 10D 状态和控制语义：

\[
x=
[p_x,p_y,\theta,v,s,\omega,
\eta_x,\dot\eta_x,\eta_y,\dot\eta_y]^\mathsf T,
\qquad
u=[a,\alpha,v_s]^\mathsf T.
\]

上述 10D 只作为机器人—液体核心语义。P1 的 realization model 接入后，优化状态必须显式增广，而不能仍把理想 `v/omega` 当成实车状态。最小连续语义为：

\[
\dot v_{\mathrm{cmd}}=a_{\mathrm{cmd}},\qquad
\dot\omega_{\mathrm{cmd}}=\alpha_{\mathrm{cmd}},
\]

再由执行器状态产生 `v_r/omega_r`。机器人位姿和液体激励使用 realized state，代价/限制同时约束 commanded 与 realized state。带纯延迟时还需要离散 delay buffer、Padé 状态或经 held-out 选择的等价实现，因此最终维数由 P1 冻结模型决定，不能继续把目标方法称为严格 10D solver。

离线 OCP 同时考虑：

- 完成时间或进度；
- `η/η_dot` 的运行期能量与终端残余；
- `a/α`、控制变化率和横向激励；
- `v/ω/a/α`、路径走廊和任务时间公平约束；
- 从独立数据识别并在 held-out bag 验证的 `v_cmd/omega_cmd → v_r/omega_r` 执行模型；
- 起点和终点的机器人/液体状态合同。

输出冻结 artifact：

\[
\bar x(\tau),\qquad
\bar u(\tau),\qquad
\bar z(\tau),
\]

并保存 path/profile/model/config hash、求解状态、约束余量和完整 predicted trajectory。这里 `τ` 是 nominal 的虚拟时间或相位坐标。

### 5.2 液体能量—相位向量

定义二维主模态的归一化相位向量：

\[
z=
[\omega_n\eta_x,\dot\eta_x,
 \omega_n\eta_y,\dot\eta_y]^\mathsf T,
\qquad
E_{\mathrm{slosh}}=\frac12 z^\mathsf Tz.
\]

与只惩罚 `η²` 或单一非负液面峰值不同，`z` 同时保留幅值和速度符号。它在相平面中的位置表示当前振荡相位，因此能够区分“幅值相近但下一步应加速抵消”与“幅值相近但下一步应减速抵消”的状态。

### 5.3 相位索引的可恢复漏斗

漏斗不能只由液体误差决定。相同的 `z-z̄(τ)` 下，不同底盘速度、角速度或执行器内部状态可能具有完全不同的剩余控制能力。第一版至少使用增广误差：

\[
e=
[e_v,e_\omega,e_{\mathrm{act}}^\mathsf T,
(z-\bar z(\tau))^\mathsf T]^\mathsf T,
\]

其中 `e_act` 表示由 held-out 辨识选中的执行器/延迟状态。若局部绕行、横向偏差或进度债务会显著改变后续可执行控制集合，则继续加入 `e_y,e_theta,e_s` 或等价的 phase/progress error；是否加入由恢复率和 false-safe 消融决定，不能为了降维事后删除关键状态。

沿 nominal 对增广动力学进行线性化：

\[
e_{k+1}=A_ke_k+B_k\delta u_k+G_kw_k,
\]

其中 `w_k` 覆盖预冻结范围内的参数偏差、实现误差和外部扰动。以终端低残余集合为起点，反向计算：

\[
\mathcal F(\tau)=
\left\{e:
e^\mathsf TP(\tau)e\le \rho(\tau)
\right\}.
\]

该集合的目标语义是：如果可信时域末端的液体、底盘和执行器联合误差仍位于 `F(τ)` 内，则存在满足速度、加速度、执行器和 residual authority 限制的后续动作，使系统能够重新接回 nominal 的抵消尾段并回到终端低残余集合。只检查 `e_z` 会产生“液体看似在集合内，但当前 `v/omega` 和执行器状态已无法完成剩余抵消动作”的 false-safe。

第一版优先用预注册参数范围内的密集 Monte Carlo/rollout 构造 **empirical recoverability tube**，并冻结集合内恢复率、集合外失败率、false-safe rate 和 coverage。若在线约束仍采用 `P(τ),rho(τ)`，必须从训练 rollout 拟合保守内椭球，再在完整 held-out rollout 上验证 false-safe；若椭球近似不充分，应改用多面体或其他可审计集合表示。只有后续使用 TVLQR、tube MPC、LMI 或近似 backward reachable set 给出明确计算和保证后，才允许称为形式化 phase funnel 或 invariant/reachable funnel。

## 6. 在线阶段：置信度门控的残差式 local MPCC

### 6.1 虚拟相位对齐

在线根据机器人路径进度和带符号液体相位，将当前状态锚定到 nominal 的 `τ_t`。优化中允许：

\[
\tau_{k+1}=\tau_k+\Delta t\,\nu_k,
\]

其中 `ν=1` 表示按 nominal 时间运行，`ν<1` 表示减速或等待，`ν>1` 表示在放行范围内加快 nominal。应惩罚 `ν-1` 及其变化率，防止控制器通过不受约束的时间扭曲虚假满足漏斗。

相位对齐不能只使用几何最近点。连续转弯或在线绕障后，机器人可能位于相近路径进度，但液体处于不同振荡相位；对齐目标至少需要同时考虑进度、机器人状态和 `z-z̄(τ)`。

### 6.2 Residual control

控制命令写成：

\[
u_k^{\mathrm{cmd}}=\bar u(\tau_k)+\delta u_k.
\]

其中 nominal 提供完整防晃抵消骨架，`δu` 只承担：

- 局部静态或动态障碍绕行；
- 实际路径和速度误差修正；
- observer 检测到的液体相位偏差恢复；
- 执行器/环境扰动补偿。

`δu` 的幅值、变化率和累计激励均应受约束。否则 nominal 只会成为弱 reference，在线优化仍可能重新退化为从零规划的 full-horizon S-MPCC。

### 6.3 置信度门控的液体时域

实现分为两个独立 release：

1. **固定短时域 MVP**：先冻结 `N_s=3`，即 `0--100 ms`，confidence 只做 shadow 记录，不改变 OCP 时域；
2. **自适应时域扩展**：只有固定时域 residual/tube 已在仿真和实物 development 正向，且 held-out 数据证明预测可信长度确实随状态变化时，才启用运行时 confidence gate。

这样可避免第一版出现 `3 → 6 → 3 → 10` 的逐周期跳变、OCP 目标/终端集合不连续和动作抖动，也能把 phase tube、执行模型与 confidence 的增益分别消融。`N_s=3` 是当前 development release 的冻结值，不声称它是跨平台通用常数。

目标版本将机器人/障碍预测长度 `N_r` 与液体可信预测长度 `N_s(t)` 分离。定义：

\[
c_{k|t}=
r_k^{\mathrm{lead}}
c_t^{\mathrm{age}}
c_t^{\mathrm{innovation}}
c_t^{\mathrm{realization}}
c_t^{\mathrm{parameter}},
\]

其中：

- `r_lead`：由 held-out 数据得到的预测误差—lead-time reliability profile；
- `c_age`：当前液体状态和机器人状态的时间新鲜度；
- `c_innovation`：observer innovation 或 normalized innovation consistency；
- `c_realization`：最近窗口 planned/commanded/realized 激励的一致程度；
- `c_parameter`：液位、固有频率、阻尼和安装外参的不确定度。

可信液体时域定义为：

\[
N_s(t)=\max\{k\le N_r:c_{k|t}\ge c_{\min}\}.
\]

`r_lead`、各 confidence 映射和 `c_min` 必须在独立 development 数据上冻结。`r_lead` 必须对 lead 单调不增，confidence 标定数据不得参与方法 confirmation。

第一版自适应扩展只允许离散集合：

```text
N_s(t) ∈ {3, 6, 10}
```

切换必须使用不同的进入/退出阈值 `c_up > c_down`、最小驻留周期 `T_dwell`，并限制每次最多升降一个档位。所有档位变化、触发 confidence 分量和 terminal tube 身份都写入 cycle audit。若这些约束仍产生明显控制不连续，则保留固定 `N_s=3`，不为了方法完整性强行启用自适应时域。

### 6.4 在线 OCP

目标版本的一个最小目标函数为：

\[
\begin{aligned}
J={}&J_{\mathrm{MPCC}}
+\sum_{k=0}^{N_r-1}\|\delta u_k\|_R^2
+\sum_{k=0}^{N_r-1}\|\delta u_k-\delta u_{k-1}\|_{R_\Delta}^2\\
&+\sum_{k=0}^{N_s(t)}
c_{k|t}\|z_k-\bar z(\tau_k)\|_Q^2
+w_\nu\sum_k(\nu_k-1)^2
+w_\phi\epsilon_\phi^2.
\end{aligned}
\]

机器人和障碍仍在完整 `N_r` 上预测，液体只传播到 `N_s(t)`。固定短时域 MVP 令 `N_s(t)=3`，并使用预冻结的固定 stage weight；不得把尚未标定的 runtime confidence 乘入代价。在液体可信时域末端施加增广 tube 约束：

\[
e^\mathsf TP(\tau)e
+\beta\,\mathrm{tr}(P(\tau)\Sigma_e)
\le
\rho(\tau)+\epsilon_\phi.
\]

该约束不是要求液体在每次短时域末端立即归零，而是要求液体、底盘和执行器联合状态回到“后续仍可恢复”的集合。`Σ_e` 占用联合不确定性余量；confidence 越低，允许控制器依赖的状态空间越小。`ε_φ` 是有记录、受惩罚且有硬上限的软 slack，用于避免障碍冲突时制造不可审计的求解失败；持续依赖 slack 必须触发降级，不能被平均 cost 掩盖。

### 6.5 Realization-aware liquid excitation

Scout 最终接收的是 `/cmd_vel` 的速度和角速度命令，因此液体不能由理想 `a/alpha` 或一个未经验证的“加速度到加速度”一阶滞后直接驱动。最小候选执行模型应先建在 `v/omega` 层：

\[
\dot v_{\mathrm{cmd}}=a_{\mathrm{cmd}},\qquad
\dot\omega_{\mathrm{cmd}}=\alpha_{\mathrm{cmd}},
\]

\[
\tau_v\dot v_r+v_r
=\mathcal S_v\!\left(v_{\mathrm{cmd}}(t-d_v)\right),
\]

\[
\tau_\omega\dot\omega_r+\omega_r
=\mathcal S_\omega\!\left(\omega_{\mathrm{cmd}}(t-d_\omega)\right),
\]

其中 `d_v,d_omega,tau_v,tau_omega` 由独立数据辨识，`S_v/S_omega` 只在 held-out 残差证明存在饱和、速率限制或死区时加入。还必须与纯延迟、离散 ARX/状态空间等同等或更简单候选比较；第一阶模型不是预设真值。

容器参考点的名义刚体激励为：

\[
a_x^C=\dot v_r,\qquad
a_y^C=v_r\omega_r.
\]

实物辨识必须把以下三层分开：

1. **底盘/驱动器动态**：用 published `v_cmd/omega_cmd` 对 realized `v_r/omega_r` 辨识物理延迟、时间常数、gain 和非线性；
2. **processed-IMU 测量链**：单独估计滤波群延迟、时间戳延迟和带宽，不能把它们吸收到 Scout 物理时间常数；
3. **IMU 到容器参考点**：使用冻结外参和刚体加速度关系处理坐标旋转、重力补偿、`dot(omega) × r` 与 `omega × (omega × r)` 杠杆臂项，最终得到容器中心激励。

训练/验证必须按完整 trial 或 block 划分；禁止把同一条轨迹相邻 sample 随机拆分后声称 held-out。若 G3R3 的重复 S 路径对参数缺少持续激励，应另录预注册的安全辨识轨迹。最终 OCP 和 OfflineSloshOCP 使用同一冻结 realization model；`actual-input replay` 则绕过该模型，直接使用时间对齐后的实测容器中心激励，以独立检验液体动力学。另设 `identified-actuator replay` 用冻结执行模型生成激励，两种 replay 不得混名。planned、solver raw、各级 gate 后 command、realized `v/omega`、container-center excitation 和 processed IMU 均须分层记录。

## 7. 安全优先级和降级逻辑

推荐的约束优先级是：

1. 碰撞和平台硬安全约束；
2. 速度、加速度、转速、执行器和通信约束；
3. recoverability tube/funnel 约束；
4. 进度、时间最优和 nominal adherence。

固定 `N_s=3` 的 MVP 中，confidence 只 shadow 记录，不得触发时域切换或改变控制；降级由 tube margin、`ε_φ`、求解状态和 obstacle maneuver 决定。只有 P5 放行后的独立 release 才允许 confidence 参与下列降级逻辑。

当 confidence 过低、tube slack 超过阈值或 obstacle maneuver 超出 residual authority 时：

1. 限制 `δu` 和 `ν` 的可用范围；
2. 进入 slosh-safe slowdown；
3. 必要时执行带液体状态的 controlled stop；
4. 静止或恢复后重新锚定 nominal phase；
5. 对需要大拓扑改道的场景触发 global replan 和新的 offline/local retiming。

这套逻辑不能宣称在任意障碍、任意感知误差和任意 NLP infeasibility 下提供无条件安全保证。大幅临时改道可能离开预计算 funnel 的有效走廊，是方法的明确适用边界。

## 8. 可以形成的论文贡献

在实现和实物证据成立后，贡献可写为：

1. 提出一种 phase-funnel residual MPCC，将离线防晃 nominal 转换为相位索引的可恢复集合，使标准 WMR 能在局部在线改道时显式管理液体相位债务。
2. 在 P5 独立消融成立后，提出数据标定的 confidence-gated trusted slosh horizon，使 liquid prediction horizon 与 robot/obstacle horizon 解耦，避免低可信远期液体节点持续驱动第一控制动作。
3. 建立 realization-aware 的载液移动机器人闭环实现和评价合同，同时审计 planned、commanded、realized excitation、真实液面、路径任务和求解实时性。

第二条只有 confidence 相对固定 `N_s=3` 显示独立收益时才能保留；否则论文方法应收缩为 fixed-horizon phase-tube residual MPCC。第三条只有在完整实物实验和统计合同通过后才能作为论文贡献。目前三条均只可写成计划设计。

建议避免的声明：

- 首次将液体模型加入 MPC；
- 首次在线预测液体状态；
- 首次生成防晃轨迹；
- phase funnel 等价于无条件防洒保证；
- 内部 `η/η_dot` 或 OCP cost 下降等价于真实 RGB 液面下降。

## 9. 对比、消融和测量合同

### 9.1 主对比

| 条件                                  | 用途                                         |
| ------------------------------------- | -------------------------------------------- |
| `Bsmooth`                           | ordinary smooth MPCC，同层无液体 baseline    |
| Hamaguchi-style FixedProfile          | 传统 input shaping / fixed-profile baseline  |
| `OfflineSloshOCP`                   | 检验完整离线抵消序列是否在实物有效           |
| 当前 full-horizon S-MPCC              | 检验“完整远期 node-wise liquid cost”的效果 |
| Proposed Phase-Funnel Residual S-MPCC | 完整方法                                     |

所有在线 MPC 条件必须复用同一 solver state、公共权重、速度/加速度限制、路径和状态输入，只切换预注册的方法组件。

### 9.2 必要消融

消融按模块加入顺序执行，不从完整方法一次删多个模块：

1. `Bsmooth` 与加入冻结 realization model 的 `OfflineSloshOCP`：先证明完整 nominal 有实物基础；
2. 固定 `N_s=3` 的 residual controller，有/无 offline nominal；
3. 固定 `N_s=3` 的 residual controller，有/无 empirical recoverability tube；
4. tube 只含 `e_z` 与包含 `e_v/e_omega/e_act/e_z` 的增广 tube：量化 false-safe；
5. 使用理想执行与使用冻结 realization model；
6. 固定 `nu=1` 与允许受限 virtual phase adaptation；
7. 固定 `N_s=3` 与带滞回/驻留时间的 `N_s ∈ {3,6,10}`；
8. 有/无 uncertainty margin，以及 terminal mean-only 版本。

旧 full-horizon S-MPCC 可作为历史机制对照，但不能替代上述逐级消融。只有前一级通过放行门才实现后一级，避免完整方法失败时无法定位原因。

### 9.3 场景

- 无障碍冻结路径，用于检查纯防晃收益；
- 临时静态障碍局部绕行，用于检查 nominal cancellation 是否被破坏；
- 动态障碍减速/恢复，用于检查 phase debt；
- 不同液位或固有频率偏差；
- 人为增加 command delay 或限幅；
- 带少量初始晃动启动；
- 超出 residual authority 的大幅改道，用于验证 fallback 而不是证明 efficacy。

### 9.4 必须记录的指标

| 层       | 指标                                                                               |
| -------- | ---------------------------------------------------------------------------------- |
| 真实液面 | RGB P95、RMS、signed feature、phase、motion 后 tail/settling                       |
| 内部液体 | `η/η_dot`、energy、tube margin、phase slack、confidence 和 `N_s(t)` |
| 激励实现 | planned/solver raw/commanded/realized `v/omega/a_x/a_y` 的 delay、gain、impulse、频谱、相位和 RMSE |
| 模型辨识 | `d_v/d_omega/tau_v/tau_omega`、参数区间、held-out error、残差白化、跨 block 稳定性和杠杆臂修正 |
| 路径任务 | contour P95/RMSE、完成时间、最短障碍距离、timeout、failure                         |
| 实时性   | solver median/P95/P99、deadline miss、fallback、bound activity                     |
| 统计     | block-level paired effect、区间、顺序效应、失败行和缺失原因                        |

RGB calibration、confidence 标定和候选选择数据不得进入正式 confirmation。完整 trial 或 ABBA block 是统计单位，不能把重叠 MPC cycle 当作独立样本。

## 10. 分阶段实现路线与放行门

### P0：完成 G3R3 决策证据

- 保持当前 `G3R3_short_horizon_matched_v1` 的 6 条顺序和配置不变；
- 使用共享 `cycle_id`、共同 state epoch 和完整 command audit；
- 检查 Matched0/Matched5 的 first-action separation，防止把“控制作用太弱”误判为模型失败；
- 完成 planned-input 与 actual-input replay，并冻结 RGB 最小可检测差异。

放行条件：数据有效，能解释状态时间、first action、实际激励和 RGB 的因果顺序。若 actual-input replay 在 held-out bag 仍无效，本方案停止在 P0。

### P1：辨识 Scout 执行链

- 从 `/cmd_vel` 的 `v_cmd/omega_cmd` 到 realized `v_r/omega_r` 比较纯延迟、一阶加纯延迟及必要的非线性候选；
- 分离底盘动态、processed-IMU 滤波/时间戳延迟和 IMU 杠杆臂；
- 按完整 block 划分 training/validation，检查参数稳定性和 excitation rank；
- 数据不可辨识时，另建短小、安全、预注册的执行链辨识试验。

放行条件：最简单充分模型在 held-out bag 达到预冻结 delay/gain/RMSE/phase 门，参数跨 block 稳定，并能生成容器中心 realized excitation。未通过时不能把一个事后拟合的一阶模型写入 OCP。

### P2：实现并验证 OfflineSloshOCP

- 第一版不改变全局路径几何，只优化冻结路径上的时间律和控制；
- 加入 P1 冻结的 realization model、终端液体残余和公共硬限制；
- 与 Bsmooth 和现有 FixedProfile 做 matched-task 仿真与小规模实物 development；
- 明确约束完成时间，禁止仅靠整体减速获得液面收益。

放行条件：`OfflineSloshOCP` 在真实 RGB 上的改善超过预冻结测量分辨率，在独立 block 中方向一致，同时完成时间、路径误差和安全门通过。若不优于 Bsmooth，本方案停止在 P2，不构造 tube。

### P3：固定短时域 residual S-MPCC

- 加入 `u=ū(τ)+δu` 和受限 virtual phase state；
- 固定 `N_s=3`，confidence 只 shadow 记录；
- 使用 P1 的 realization model 和 P2 的冻结 nominal；
- 先不施加 recoverability tube，验证 residual authority、局部绕行、实时性和 phase alignment。

放行条件：相对直接跟踪 OfflineSloshOCP，residual controller 能处理预注册的小幅局部偏差/障碍且不破坏无障碍 RGB、tracking 和完成时间；raw command、realized excitation 和 phase debt 可审计。

### P4：构造并接入 empirical recoverability tube

- 对增广误差 `e=[e_v,e_omega,e_act,e_z,...]` 做 Monte Carlo/rollout；
- 预先冻结参数扰动、初始相位扰动、执行偏差和 residual authority；
- 验证集合内恢复率、集合外失败率、coverage 和 false-safe；
- 接入 terminal tube constraint、slack 硬上限、降级和 re-anchor 状态机。

放行条件：增广 tube 相对 `e_z`-only tube 明显降低 false-safe，在线求解满足实时门，且不依赖持续 slack。第一版统一称 empirical recoverability tube。

### P5：加入 confidence-gated horizon

- 先离线冻结 lead reliability 和 age/innovation/realization/parameter confidence；
- 只允许 `N_s ∈ {3,6,10}`，加入滞回、最小驻留周期和逐档切换；
- 先 shadow 决策，再在独立 release 中影响 OCP；
- 与固定 `N_s=3` 做独立消融。

放行条件：数据证明可信时域确实随状态变化，自适应版本相对固定时域有独立收益，并且没有目标跳变、动作抖动、deadline miss 或 calibration leakage。否则固定 `N_s=3` 保留为最终版本。

### P6：实物 development 与正式确认

- 每一级先做顺序平衡的小规模 development，参数冻结后建立新 release；
- 重新进行正式 paired/ABBA confirmation，不复用 G3R3 或模块选择数据；
- 无障碍固定路径先验证纯 efficacy；
- 静态/动态障碍、参数扰动和超 residual authority 场景作为独立扩展，不与无障碍主结论混池。

## 11. Go/No-Go 判据

以下任一情况成立时，应暂停该主线而不是继续增加权重或模块：

1. G3R3 两条件的 first action 没有可执行分离，却在未补 sensitivity 证据前直接把无 RGB 差异解释为架构失败；
2. actual-input replay 在 held-out bag 中不能稳定复现 RGB 的幅值、主频和相位；
3. `v/omega` 执行模型只在训练轨迹拟合良好，参数跨 block 不稳定或 excitation 不足；
4. `OfflineSloshOCP` 在 matched-task 实物比较中仍不能优于 Bsmooth；
5. empirical tube 只能通过事后选择参数得到较高 coverage，或 `e_z`-only 集合存在不可接受的 false-safe；
6. proposed 方法的收益只来自明显更慢的完成时间，或主要结果小于冻结的 RGB 最小可检测差异；
7. tube constraint 大量依赖 slack，或导致 solver P99 超过控制周期；
8. 固定 `N_s=3` 已足够，而自适应 confidence 没有独立收益或引入动作跳变；
9. 删除 confidence/tube/realization model 后结果不变，无法支持对应的机制性贡献。

如果 `OfflineSloshOCP` 正向而在线方法未复现，优先支持“滚动重规划、状态时间或实现失配破坏抵消序列”；如果二者都不正向，应回到液体模型、RGB 映射和执行器辨识，不应继续扩展 phase-funnel 控制器。

## 12. 预期论文题目和研究问题

候选题目：

> **Confidence-Gated Phase-Funnel Residual MPCC for Online Liquid-Carrying Mobile Robots**

该题目只在 P5 证明自适应 confidence 相对固定 `N_s=3` 有独立贡献时成立。若最终保留固定短时域和 empirical tube，应相应收缩题目，例如：

> **Phase-Tube Residual MPCC with Realization-Aware Short-Horizon Slosh Prediction for Liquid-Carrying Mobile Robots**

候选研究问题：

> Does confidence-gated, phase-funnel residual MPCC preserve the recoverability of an offline anti-slosh cancellation sequence during online local obstacle avoidance, and reduce real liquid response relative to smooth-only MPCC, offline profiles, and conventional full-horizon S-MPCC under matched task constraints?

这一路线的核心创新不是“预测更多液体节点”，而是只在证据支持的范围内使用预测，并通过相位可恢复集合把短时反馈和完整离线抵消序列连接起来。

# 8 月 14 日阶段工作汇报：GPU 液体仿真阶段总结与实物实验续接

## 一、本阶段总体进展

8 月 11 日的上一版汇报中，液体仿真仍主要依赖单线程 CPU，约 8 秒的仿真仍未完全稳定。本阶段已将工作向前推进到：

1. 完成 RTX 5080 对应的 GPU 程序构建、检查和短时间运行测试；
2. 通过两次独立计算、中间结果续算、CPU/GPU 结果对照和三类简单运动，完成液体单独开发验证；
3. 从已经完成的 88 条 Gazebo 机器人仿真实验中，只读选取 1 条基准运动记录，并完成轨迹提取和坐标转换；
4. 完善 GPU 全轨迹液体回放、资源监控和输出检查工具，同时搭建后续结果分析流程；
5. 重画考虑液体晃动的模型预测路径控制方法（S-MPCC）闭环核心架构图并接入论文，但论文整体仍有较多内容需要集中修改。

当前最重要的结论是：**运动记录的只读封存和轨迹转换已经完成，但真实 GPU 全轨迹液体回放尚未开始。考虑到计算和首次分析仍需较长时间，现阶段决定暂停这条独立粒子仿真路线。下周不是重新开始实物实验，而是接着解决放假前已经暴露的问题，继续实物开发和验证。**

## 二、液体仿真已完成的关键结果

### 2.1 RTX 5080 GPU 程序和液体单独验证已通过

GPU 程序已经完成构建和运行前检查。1 秒短时间测试正常结束，9,078 个粒子全部保留，没有粒子丢失。

早期仅缩小时间步的方案仍有 9/17 项稳定性指标超限，因此没有采用。随后在保持其他主要设置不变的情况下调整人工黏性，完成了：

- 两次独立冷启动和延长沉降；
- 中间保存结果续算及重复性检查；
- CPU/GPU 逐粒子位置、速度和密度对照；
- 零运动回放、2 mm/1 Hz 平移和 2°/1 Hz 偏航三类合成运动。

最终将约 45.05 秒时的计算状态确定为稳定起点。三类简单运动共输出 143 帧，始终保持 9,078 个粒子且没有粒子丢失。液体仿真由上一版汇报中的“静水仍未稳定”，推进到“固定软件和参数下的液体单独开发验证通过”。

### 2.2 单条既有小车仿真记录已完成只读封存

本轮没有扫描或回放全部 88 条既有数据，只处理了高激励路径、第一种容器条件下的一条平滑控制基准记录。

该记录使用机器人系统的录制文件（ROS Bag）保存，已经通过文件身份、信号类型、时间范围和源文件前后一致性检查。封存过程没有运行液体计算，没有使用 GPU，也没有读取其他控制方法的配对记录。

### 2.3 轨迹转换和交接验证已完成

轨迹转换程序已将这条记录中的里程计运动转换为液体计算程序所需的相对位姿轨迹。主要结果为：

| 项目             |       结果 |
| ---------------- | ---------: |
| 记录运动时长     |    49.38 s |
| 原始运动采样     |     989 个 |
| 液体计算轨迹行   |     990 行 |
| 插值与转换检查点 |   3,953 个 |
| 相对起点最大位移 | 约 8.824 m |
| 轨迹数值质检     |       通过 |

该结果证明“既有小车仿真运动→独立液体计算轨迹”的转换链路可用，但它本身还不是液体回放结果。

## 三、GPU 全轨迹回放和结果分析的当前状态

### 3.1 已完成的工具和检查流程

为真实 GPU 全轨迹回放，已补齐以下内容：

- 含移动容器和随动液面探针的 GPU 构建与运行前检查流程；
- 一次性运行授权、计算资源监控、GPU 驱动错误检查和异常记录保留；
- 粒子是否齐全、是否出现无效数值、容器是否按轨迹运动以及文件是否完整的检查；
- 16 个圆周液面探针的原始数据保留、归一化和时间网格核对；
- 回放完成后对液面幅值、频率、衰减、相位、相关性和误差进行分析的工具。

### 3.2 尚未完成的实际运行

目前只完成了程序、检查规则和运行准备，专用 GPU 程序尚未生成最终运行结果，全轨迹回放也尚未启动。因此，当前不能把“回放工具已经准备好”表述成“已经完成小车轨迹的液体回放”，也还没有可供分析的液面时序、对比图或动画。

### 3.3 预计计算时间和暂停决定

单条基准运动包含 49.38 秒实际运动和 1 秒收尾，液体仿真总时长约 50.38 秒。根据同类 GPU 运行的实测速度，纯计算预计需要约 65—70 分钟，最长运行时间设为 90 分钟。首次还要完成专用程序构建、结果检查、分析和出图，整体按半天到一天安排更稳妥。若再增加一条控制方法作为配对，两条记录的纯计算时间合计约 2.2 小时。

按上一阶段的单线程 CPU 速度粗略外推，同一条 50 秒轨迹约需 14—15 小时，因此 GPU 已经把单条代表性验证缩短到可以接受的范围。但如果扩展到全部 88 条记录，仅纯计算就约需 95—103 小时，还不包括检查和分析，不适合作为大批量实验工具。

**简单结论：虽然 GPU 已明显缩短单条计算时间，但首次完整计算、检查和分析仍需半天到一天，也无法经济地扩展为大批量验证。因此，本阶段到此暂停独立粒子仿真，不再执行原计划的全轨迹回放，也不增加第二条对比记录。现有程序、配置和结果全部保留，今后只有在论文审稿或模型验证确有必要时，才考虑恢复少量代表性计算。**

### 4.2 方法核心思想

> **S-MPCC 不只规划机器人怎么沿路径走，还在每次优化中预测这段运动会怎样晃动液体，并据此选择下一步动作。**

下周将围绕这句话重新检查方法章、架构图、摘要和结论，使整篇论文由同一个核心思想贯穿，而不是堆叠公式、模块和实验流程。

### 4.3 下周集中修改内容

下周安排一个连续时段集中修改论文，重点完成以下事项：

1. **增加机器人本体形象。** 在系统总览图和核心架构图中加入移动机器人、容器和开口液体的具象图形或实物照片，使读者能直接看懂研究对象及信号来源。
2. **把方法解释得更具体。** 将公式中的车体运动、路径推进、液体位移和液体速度与机器人实际动作一一对应，并用一次控制循环说明“输入什么、预测什么、最后执行什么”。

5. **暂不把粒子仿真写成论文证据。** 由于全轨迹回放已经暂停，论文中不能把尚未产生的结果表述为模型可靠性验证。若以后确有必要恢复少量计算，再比较内部液体模型与粒子仿真的响应方向、峰值、主频和衰减趋势，并根据实际结果决定是否加入论文。
6. **统一全文表达。** 让标题、摘要、方法图、实验问题和结论共同回答“为什么要在路径优化时预测液体响应，以及这样做带来了什么”。

## 五、当前限制和结论边界

1. 当前通过的是固定软件和数值参数下的开发验证，不是实物保真或正式实验结论。
2. 本轮选定的运动来自 Gazebo 小车仿真，不是实物小车采集数据。
3. 当前只处理了一条平滑控制基准记录，还没有回放启用液体晃动代价的控制方法，因此不能比较两种方法的独立液体响应。
4. 粒子仿真本身也是数值模型。即使后续与控制器内部液体模型一致，也只能说明两种模型在规定条件下相互支持，不能单独证明真实液体中的准确性。
5. 当前实物侧只有经质量筛选的单相机可见液面投影，可用于开发性比较，但还不是完整二维液面真值，且在当前低幅区的分辨能力有限，因此不能发布实物保真结论。
6. 8 月 11 日汇报中四路 VL6180X PCB 液面测量尚不稳定的结论未发生变化，本阶段也没有新的实物测量通过证据。

## 六、下一阶段安排

### 6.1 放假前实物实验的停点和问题

下周的工作是继续放假前的实物实验。此前已经完成候选筛选和两组有效配对，不是从零开始。当前停点和问题为：

1. **当前液体状态已经送入求解器。** 每次实际求解时，惯性测量单元（IMU）驱动的液体状态都会写入求解器当前状态，因此问题不是“状态没有传进去”或简单的接口赋值错误。
2. **候选方法没有复现液面改善。** 原计划进行 6 条配对实验，完成前 4 条后，两个完整配对均没有显示候选方法的相机液面优势，继续最后 2 条也不可能通过原定方向门槛，因此停止采集，候选方法没有进入正式论文实验。
3. **实物运行中的当前内部状态没有复现仿真优势。** 两个配对中，平滑基线的求解前当前晃动指标平均约为 1.070 mm，候选方法约为 1.176 mm，候选方法反而高约 0.106 mm。这个指标是实物小车实际运动后形成的当前状态，不是优化器计划的未来液体响应；平滑基线也只记录它，并不在优化中使用它。
4. **此前控制仿真支持方法机制，但仅限仿真模型。** 在已经完成的三个仿真场景中，启用液体晃动代价的方法相对平滑基线都降低了模型晃动量：外部模型指标降低约 8.3%—13.8%，控制器内部模态指标降低约 9.0%—17.6%。因此，准确结论是“仿真模型内支持、实物配对未复现”，而不是“方法在所有证据中都无效”。这组仿真同时出现完成时间更长、路径跟踪误差更大的代价，也不能替代真实液面验证；本周暂停的独立粒子仿真尚未产生结果，与这组已有控制仿真不是一回事。
5. **完整预测序列已有记录，并已做事后对齐。** 两条候选方法记录分别包含 1,052 和 1,049 个有效预测序列；每次求解保存 61 个状态节点，覆盖未来 2 s。与原生相机时间戳事后对齐后，预测在真正可用后的 0—100 ms 内保留中等方向信息，100—333 ms 明显衰减，333 ms 后不宜视为可靠物理预测，500 ms 后没有稳定线性预测信息。因此，完整 2 s 预测并未得到实物支持。
6. **现有分解更指向“计划运动没有按预测实现”。** 求解器预测与高精度数值重放之间的均方根误差约为 0.034 mm，说明数值积分不是主要问题；若事后使用未来实际 IMU 输入，同一液体模型与相机仍保持约 0.71—0.74 的相关性。相反，规划输入相对无输入自然衰减的新增预测收益仅约 0%—5%，100 ms 后部分区间还略差。当前更可能的主要矛盾是规划的未来运动与实际闭环运动不一致，而不是液体二阶模型方向完全错误。
7. **现有预测分析仍是描述性证据。** 记录中没有贯通状态、求解结果和首个控制动作的共享周期编号；预测消息时间也是求解后的发布时间，不是权威预测起点。因此可以判断衰减趋势，但还不能把上述时间范围冻结为论文中的正式有效预测时域。
8. **采集和跟踪曾分别出现问题。** 一次实验发生相机源时间戳不稳定，受控重录后通过；另一候选实验超过路径跟踪门槛，按方法失败保留，未选择性重录。
9. **模型和比较条件仍有混杂。** IMU 驱动的状态主要由模型传播，没有真实液面修正；此前两种方法的公共控制权重也没有完全一致，不能把负结果唯一归因于液体代价本身。
10. **相机处在低幅测量区间。** 当前两种方法的液面差异很小，接近相机标量的量化和重复性范围，因此后续必须保留带方向的原始液面特征并严格处理相机时间戳，不能只比较一个非负峰值。

详细依据已保存在项目实验记录中，包括正式论文实物实验记录、放假前四条配对停止分析、液体状态一致性解决方案、未来液面预测事后分析和控制仿真机制结果。

### 6.2 下周实物实验续接安排

1. **暂停并封存独立粒子仿真。** 保留现有程序、配置、轨迹转换结果和阶段回执，不再继续构建或执行全轨迹回放。
2. **从放假前的问题继续。** 不重复已经完成且有效的四条配对，先检查相机时间戳、液面原始数据、IMU 状态、控制配置和安全链路。
3. **重新做公平的单因素比较。** 两种方法使用相同的求解器、状态输入和公共控制权重，只切换是否启用液体晃动代价，避免把其他权重差异误认为液体模型效果。
4. **补齐预测序列的时间合同。** 现有记录已经保存完整预测序列，不需要从零增加这一类消息。下一步应增加共享控制周期编号、权威预测起点、求解完成时间和首个控制动作时间，再与原生相机时间戳、IMU 和机器人实际运动严格对齐。
5. **检查远期低可信节点是否影响当前动作。** 对同一批求解状态做预测时域截短或远期折扣对比；若 100—333 ms 以后的低可信节点明显改变第一个控制动作，优先缩短或降低远期液体代价，而不是继续增大液体权重。
6. **先做开发性配对，再决定是否进入正式实验。** 只有相机时间同步、路径跟踪和数据完整性全部通过，并出现可重复的真实液面改善，才冻结方法并继续正式论文实验；若仍无改善，则转而修改运动执行模型、液体参数或采用更保守的平滑控制方案。
7. **集中修改论文。** 下周另安排一个连续时段，先确定一句话核心思想，再补机器人本体图、具象解释、内容删减和术语清理；粒子仿真不作为当前论文证据。

## 七、本次汇报结论

近几天的主要进展，是将独立液体仿真从“CPU 下可重复但未稳定”推进到“RTX 5080 GPU 下完成固定参数的液体单独开发验证”，并已完成一条既有小车仿真运动的只读封存和轨迹转换。单条完整回放的 GPU 纯计算预计约需 65—70 分钟，首次从程序构建到结果分析按半天到一天安排。

考虑到单条完整流程仍需半天到一天，批量计算仅纯计算就可能超过 95 小时，相对于当前项目需求耗时过长。因此，本阶段在这里结束并暂时放弃继续开展独立粒子仿真，不执行原计划的全轨迹回放，也不再扩展更多条件。现有程序、配置和结果保留，当前不能据此给出模型可靠性、控制方法减晃效果或实物保真的结论。

下周工作主线是继续放假前的实物开发实验，而不是重新开始。此前控制仿真在三个场景中都显示启用液体代价后模型晃动量下降，说明方法机制在仿真模型内得到支持；但放假前的实物配对没有复现相机液面优势，实物运行中的当前内部状态也没有显示改善，因此候选方法尚不能进入正式论文实验。已有预测序列事后分析进一步表明，求解器在约 0—100 ms 内保留中等方向信息，之后快速衰减，完整 2 s 预测没有得到实物支持；现有证据更指向规划运动与实际闭环运动不一致，而不是液体模型方向完全错误。下一步应补齐权威周期和时间记录，在公共权重一致的新开发性配对中复核，并检查是否需要缩短或折扣远期液体代价。只有出现可重复的真实液面收益后，才继续正式实验。论文另安排一个连续时段集中修改，重点凝练核心思想、增加机器人形象和具象说明，并删减冗余内容；尚未完成的粒子仿真不作为论文证据。

# 20260602 SPMPC 连续优化求解器升级判断

## 当前结论

当前阶段**不需要马上引入 acados**。

更准确的定位是：

```text
acados 是后续把 SPMPC 升级为连续优化 OCP/NMPC 时的候选后端，
不是当前 primitive-based SPMPC 实车验证阶段的必需依赖。
```

当前 solver 口径应写成：

```text
motion-primitive rollout selection
运动基元库 rollout 后按 cost 择优
```

不要写成 `rollout sampling` 或 `sampling-based SPMPC`，避免被误读成 MPPI 或随机采样方法。

## 当前优先级

先保持现有 primitive-based SPMPC，完成实车 fixed-path smoke 和主窗口指标验证：

```text
1. slosh state 是否稳定继承；
2. slosh cost 是否真实改变 cmd_v / cmd_omega；
3. anti-slosh primitives 是否降低 model/RGB peak 或 p95；
4. B0 / B_slosh / B_smooth / B_ours_anti 是否有可解释差异；
5. terminal 和主 tracking window 是否分开统计；
6. 外部 baseline 是否在同一输入输出接口下公平可跑。
```

这些问题没有实车闭环数据前，不建议引入 acados。否则结果异常时很难判断问题来自：

```text
slosh model
cost 权重
primitive 表达能力
acados infeasible
warm start
离散化/线性化
实车延迟
```

## 什么时候升级连续优化 solver

满足下面条件时，再考虑新增 `ContinuousOcpSolver`：

```text
1. 实车证明 slosh cost 有用，但 primitive 候选空间限制了效果；
2. B_slosh_anti / B_ours_anti 仍不能稳定降低 RGB/model 指标；
3. 诊断显示需要连续优化 u_0 ... u_{N-1} 的时序，而不是只在运动基元库中选；
4. 当前 primitive solver 的 best candidate 经常受限于候选模板，而不是 cost 方向错误；
5. fixed-path 实验链路、视觉指标和 baseline 录包已经稳定。
```

升级后问题形式为：

```text
minimize over X = {x_0 ... x_N}, U = {u_0 ... u_{N-1}}

subject to:
  robot dynamics
  slosh modal dynamics
  velocity / acceleration / yaw-rate bounds
  corridor constraints
  terminal constraints
```

## OSQP 与 acados 的取舍

### SQP + OSQP

适合：

```text
线性化动力学
sequential convexification
QP 子问题
工程可控、依赖轻、调试透明
```

优点：

```text
ROS1 接入简单
调试成本较低
和已有 QP/MPC 经验更接近
```

### acados

适合：

```text
完整 nonlinear OCP / NMPC
SQP / SQP-RTI
codegen solver
```

优点：

```text
更正统
连续优化整条 horizon
论文方法表述更硬
```

代价：

```text
依赖更重
接入和构建复杂
warm start / infeasible 处理更麻烦
实车调参风险更高
```

## 推荐路线

```text
阶段 1:
  保持 motion-primitive SPMPC
  跑实车 fixed-path smoke
  锁定 B0 / B_slosh / B_smooth / B_ours_anti 的差异

阶段 2:
  如果实车效果足够明显
  当前 solver 作为工程原型结果
  文中谨慎表述为 primitive-based integrated SPMPC prototype

阶段 3:
  如果效果受 primitive 表达力限制
  新增 ContinuousOcpSolver
  先比较 SQP-OSQP 和 acados 的工程可行性

阶段 4:
  连续优化 solver 稳定后
  再把论文主方法升级为完整 continuous OCP/NMPC SPMPC
```

一句话结论：

```text
现在先跑 primitive-based SPMPC 的实车证据；
只有当数据证明运动基元库表达能力不足时，再引入连续优化 solver；
acados 是候选后端，不是当前必需品。
```

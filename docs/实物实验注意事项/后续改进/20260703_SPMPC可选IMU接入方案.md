# 20260703 SPMPC 可选 IMU 接入方案

## 1. 背景

当前 `spmpc_local_planner` 没有直接使用 IMU：ROS 节点只订阅 odom、reference path 和可选 costmap；`RobotState::omega` 来自 `/odom.twist.twist.angular.z`；slosh observer 用 odom 线速度差分得到 `ax`、用 `v * omega` 得到 `ay`；delay predictor 使用历史已发布 `/cmd_vel` 前向积分。

2026-07-02 实物 bag 显示，`B_slosh / B_ours` 的实物表现可能受到角速度/相位误差影响，尤其 fixed closed-loop delay compensation 中角速度相位过补偿会直接影响 slosh-aware MPC 的初始状态与晃动预测。因此下一步可以低风险地把 IMU 作为可选观测源接入，先改善 yaw-rate 与 slosh observer 诊断，不默认改变既有行为。

本方案目标不是用 IMU 全面替代 odom，而是分阶段、可回退地使用 IMU yaw-rate，并在充分验证后再评估 IMU lateral acceleration。

## 2. 总体原则

1. 默认行为保持不变，IMU 全部为可选增强。
2. 先做 IMU 观测和诊断，再逐步让它影响控制输入。
3. 第一优先级使用 IMU yaw-rate，不优先使用 IMU linear acceleration。
4. delay predictor 第一版保持 command-history-based rollout，不直接吃 IMU acceleration。
5. 所有 IMU 使用都必须有 freshness、finite、range check 和 fallback 诊断。

## 3. 推荐分阶段实现

### Phase 0：只接入 IMU 诊断，不影响控制

新增 IMU subscriber 和 IMU 状态缓存，但不改变控制行为：

- 不改 `robotStateFromLatest()`；
- 不改 `updateSloshObserverFromOdom()`；
- 不改 `ExecutionStatePredictor`；
- 不改 solver input。

建议新增配置，默认关闭：

```yaml
imu:
  enable: false
  topic: /imu/data
  timeout_sec: 0.10
  use_for_raw_omega: false
  use_for_slosh_omega: false
  use_for_slosh_ay: false
  omega_lowpass_alpha: 0.4
  accel_lowpass_alpha: 0.2
  ay_bias_estimation_enable: true
  ay_bias_stationary_v_thresh: 0.03
  ay_bias_stationary_omega_thresh: 0.05
  ay_bias_min_samples: 50
  max_abs_omega: 4.0
  max_abs_ay: 8.0
```

建议新增诊断 topic：

```text
/spmpc/debug/imu_state
```

至少发布：

```text
imu_age_ms
omega_z_raw
omega_z_filtered
linear_accel_y_raw
linear_accel_y_filtered
linear_accel_y_bias
bias_ready
fresh
fallback_reason_code
```

这一阶段的目的：先用旧 bag/新短 bag 判断 IMU 本身是否稳定、是否比 odom omega 更贴近实际转向响应。

### Phase 1：可选用 IMU yaw-rate 作为 raw robot omega

保持现有位姿和速度口径：

- `x / y / yaw`：继续按当前逻辑，`use_tf_pose=true` 时来自 TF，否则来自 odom pose；
- `v`：继续来自 `/odom.twist.twist.linear.x`；
- `omega`：可选来自 IMU `angular_velocity.z`。

启用条件：

```text
imu/enable == true
imu/use_for_raw_omega == true
IMU fresh
omega_z finite
abs(omega_z) <= imu/max_abs_omega
```

任一条件不满足时回退：

```text
omega = /odom.twist.twist.angular.z
```

建议 source code：

```text
0 = odom
1 = imu
2 = fallback_to_odom
```

这一阶段会真正影响 solver input，但只改角速度初值，不改速度、不改位置、不积分 IMU。

### Phase 2：可选用 IMU yaw-rate 改善 slosh observer

当前 slosh observer 的输入为：

```text
ax = odom dv/dt
omega = odom omega
ay = v * omega
```

建议改成可选输入选择：

```text
ax = odom dv/dt
omega_used = imu omega_z, fallback odom omega
ay = v * omega_used
```

这一阶段仍不直接使用 IMU `linear_acceleration.y`，避免偏置、安装方向、重力耦合和振动噪声直接污染 slosh observer。

建议新增诊断 topic：

```text
/spmpc/debug/slosh_observer_input
```

至少发布：

```text
dt_ms
ax_used
ay_used
omega_used
omega_source_code
ay_source_code
imu_age_ms
fallback_active
```

这一阶段的主要目标是改善 slosh observer 的横向激励相位，尤其转弯段 `ay = v * omega` 的相位。

### Phase 3：最后再评估 IMU lateral acceleration

`imu/use_for_slosh_ay` 继续默认关闭。只有在 bag 证明 IMU `linear_acceleration.y` 的 frame、符号、偏置、噪声可靠后，才允许：

```text
ay = filtered_imu_accel_y - ay_bias
```

bias 估计只在近静止条件下更新，例如：

```text
abs(v) < imu/ay_bias_stationary_v_thresh
abs(omega) < imu/ay_bias_stationary_omega_thresh
```

当 IMU ay 不可用、bias 未 ready 或数据超限时，必须回退：

```text
ay = v * omega_used
```

## 4. delay predictor 边界

第一版不建议让 `ExecutionStatePredictor` 直接使用 IMU acceleration。

推荐保持当前边界：

```text
raw state / raw slosh observer 可以被 IMU 改善；
delay predictor rollout 继续使用历史已发布 /cmd_vel。
```

原因：

1. predictor 的职责是从当前观测状态出发，用 command history 前推 delay window；
2. IMU 是当前观测，不是未来 delay window 内的执行输入；
3. 直接把 IMU acceleration 塞入 predictor rollout，会混淆“观测修正”和“输入传播”；
4. 保持 command-history-based rollout 更利于解释 fixed closed-loop delay compensation 的效果。

因此第一版中 IMU 只通过更好的 raw `omega` 和更好的 raw `current_slosh_` 间接改善 predictor 起点。

覆盖：

4. `use_for_slosh_omega=false` 时 observer 仍用 odom omega；
5. `use_for_slosh_omega=true` 时 observer 用 IMU omega，且 `ay = v * omega_imu`；

同时扩展：

```text
test/test_execution_state_predictor.cpp
```

明确锁住设计边界：IMU 不直接改变 predictor rollout，只改变 raw 初始状态。

### 6.2 bag 回放验证

1. `imu/enable=false`：行为必须与当前 baseline 一致；
2. `imu/enable=true` 但所有 use flags 为 false：只多 diagnostics，不改变 raw/solver input；
3. 只开 `use_for_raw_omega`：检查 raw omega source、IMU-vs-odom 差异和 cmd/predicted/raw omega 对齐；

5. 最后小心测试 `use_for_slosh_ay`。

## 7. 实物验证判据

默认配置下：

- planner 行为必须完全保持不变；
- IMU topic 丢失、stale、异常值时不得进入 `WAITING_FOR_IMU`，只回退 odom；
- fallback 原因必须写入 diagnostics。

开启 `use_for_raw_omega` 后：

- bag 中 raw omega source 应明确为 IMU；
- `/spmpc/debug/cmd_odom_alignment` 中 raw/predicted omega 差异应更可解释；
- terminal spin / tracking spin 诊断不应更差。

开启 `use_for_slosh_omega` 后：

- `/spmpc/debug/slosh_observer_input` 应显示 `omega_source=imu`；
- `ay` 应为 `v * omega_imu`；
- slosh observer 相位不应明显恶化；
- solver 成功率不应下降。

开启 `use_for_slosh_ay` 后：

- bias 未 ready 时必须回退；
- 静止段 corrected `ay` 应接近 0；
- 转弯段 IMU ay 与 `v * omega` 的符号和量级应合理；
- 若噪声显著增加，应继续默认关闭该功能。

## 8. 当前推荐结论

短期最推荐的落地顺序是：

```text
1. IMU subscriber + /spmpc/debug/imu_state，只诊断，不控制
2. raw omega 可选使用 IMU yaw-rate
3. slosh observer omega 可选使用 IMU yaw-rate，ay = v * omega_imu
4. 最后再评估 IMU linear_acceleration.y - bias
```

不推荐第一轮做：

```text
1. 用 IMU 替代 v
2. 用 IMU acceleration 直接驱动 delay predictor rollout
3. 复杂融合器/Kalman/姿态补偿大改
4. 大幅修改既有 diagnostics 数组布局导致历史分析脚本失效
```

本方案的核心是：**先让 IMU 成为可观测、可回退、可解释的 yaw-rate source，再逐步用于 slosh observer；不要一次性把 IMU 引入所有状态与预测链路。**

# 容器安装偏移与液体作用点加速度统一改造方案

> 状态：**讨论稿，未实施**。2026-09-11，静态核对 `/home/geist/scout_ws`，分支 `diag/lt-dwa-collision-tracking @ 9d31ff6`。按用户要求调用 `memory-writer`，先写方案，再讨论具体落实；本次仅记录方案及[交接入口](../../Claude/对话交接文档-时间-简介/2026-09-10_SPMPC实物降晃与来源对照交接.md)，不改运行代码、配置或生成物，不启动 ROS/实车，不重分析历史 bag。
> 现有未提交 NOKOV 自转工具及根目录 `VALIDATE_ONLY=false`、`bash` 保留。本方案不恢复 NOKOV/5 Hz 标定支线，不把瞬时旋转中心测量作为前置。

## 1. 结论与当前事实

建议将各条液体链的输入统一为**容器中心所受的平面惯性加速度，以 `base_link` 轴表达**。容器安装位置是相对 `base_link` 的固定几何量；补偿作用于加速度输入，不给液面高度加固定偏差，也不把漂移的瞬时旋转中心当作安装基准。

**当前不能认定“缺少非零容器偏移”就是已有负结果的根因。** 用户给出的安装判断是容器中心与 `base_link` 基本重合；若该判断成立，未来预测的容器平移补偿为零，现有参考点激励在这一项上无需改变。IMU 自身安装偏移仍需补偿。优先核实 IMU 原点、轴向及容器位置，不能用有利的 slosh 排名反推一个“有效偏移”。

| 项目 | 当前证据 / 状态 |
|---|---|
| IMU → 液体目标点补偿 | [处理链][imu]已经实现 `ax−alpha*ry−omega²*rx`、`ay+alpha*rx−omega²*ry`，在去重力、偏置处理、坐标旋转及滤波后执行 |
| `base_link → IMU` | [IMU 启动配置][imu-tf]和 [URDF][urdf]名义平移为 `(0.100, -0.045)` m；代码存在不等于实物已精确测量/标定 |
| IMU → 目标点 | [common.yaml][common]为 `(-0.100, +0.045)` m，安装 yaw 为名义 `0`；当前注释及诊断使用 `base/ICR proxy`、`liquid_observer_target_icr_proxy`，没有证明其物理位置就是容器中心 |
| `base_link → 容器` | 用户安装判断：暂按 `(0,0)` m；尚无本轮实测外参记录 |
| odom 液体监视器 | [ROS 入口][ros]使用 `Δv/Δt`、`v*omega`，同时计算 `Δomega/Δt`，尚未加入容器偏移项 |
| 执行器前推 | [ExecutionStatePredictor][prefix]按预测实际速度变化与中点 `v*omega` 推进液体，尚未加入容器偏移项 |
| OCP 未来预测 | [CasADi 模型][ocp]已有 `a_actual`、`alpha_actual`，液体 RHS 使用 `a_actual` 与 `v_actual*omega_actual`；未接入容器几何参数 |
| 热启动 | [ACADOS 包装层][solver]的实际执行器热启动推进和 [flatness 热启动][warm]也调用液体模型，不能只改 OCP 后遗漏这些输入 |
| 液体时间前推及物理核 | [LiquidStateNowcaster][nowcast]直接消费 `MotionExcitation`；[SloshDynamics][dynamics]直接积分传入的 `ax/ay`，不应在其内部再次做几何补偿 |

以上为源码核对；未证明新的几何参数、完整物理预测或实物收益。用户提供的“世界坐标二阶差分、零偏移、两段换算等价均通过”作为讨论依据保留，本轮未取得其可追溯测试产物；落实时仍需纳入仓库回归。

## 2. 数学和坐标约定

记 `B` 为 `base_link` 原点，`C` 为容器中心，`r_BC=(r_x,r_y)` 为 **B 指向 C** 的固定向量，以车体轴表达；x 向前、y 向左、z 向上，逆时针 yaw 为正。参考点加速度指世界惯性加速度转到车体轴后的分量，不是未经处理的 IMU 比力，也不只是旋转坐标中速度分量的导数。

由 `p_C=p_B+Rr_BC`，对世界位置求二阶导数并转回车体系，有

$$
a_C^B=a_B^B+\alpha\times r_{BC}+\omega\times(\omega\times r_{BC}),
$$

因此在平面运动下

$$
\begin{aligned}
a_{C,x}&=a_{B,x}-\alpha r_y-\omega^2r_x,\\
a_{C,y}&=a_{B,y}+\alpha r_x-\omega^2r_y.
\end{aligned}
$$

`B` 可以平移和转弯，不要求它是旋转中心。当前无侧滑预测模型给出

$$
a_{B,x}=\dot v_{\rm actual},\qquad a_{B,y}=v_{\rm actual}\omega_{\rm actual}.
$$

代入后得到用户提出的容器激励，再输入原液体方程：

$$
\ddot\eta_i+2\zeta\omega_n\dot\eta_i+\omega_n^2\eta_i=-\kappa_i a_{C,i}.
$$

`v*omega` 已包含 B 点随车转弯的横向加速度。r=0 时，即使 B 不在瞬时旋转中心，也不能再人为附加一遍该项。

数学依据：[刚体平面运动学](https://mechref.engr.illinois.edu/dyn/rkg.html)。作用点平移公式不依赖无侧滑假设；无侧滑是当前计算 `a_B` 的模型假设。真实侧滑、roll/pitch、容器相对车体的姿态差、旋转坐标下液体模态耦合等不由本次二维平移补偿解决。本方案保留既有线性/平面液体近似、模态到高度映射及 `use_parabola_term` 配置；不将几何修正宣称为完整液体动力学证明。

## 3. 参数设计：两个安装向量，一个派生值

统一以 `base_link` 为安装基准：

$$
r_{IC}=r_{BC}-r_{BI}.
$$

这里三个向量均以 **base 轴**表达；`r_IC` 的下标表示向量起终点，不表示改用 IMU 轴。若加速度还在 IMU 轴，必须先完成轴向旋转，不能直接用 base 轴偏移补偿。

建议新增统一几何配置，命名待落实时确定，例如：

```yaml
# 拟新增接口，不是当前可直接使用的配置。
liquid_geometry:
  base_to_container_x_m: 0.0
  base_to_container_y_m: 0.0
  base_to_imu_x_m: 0.100
  base_to_imu_y_m: -0.045
```

加载后只派生一次 IMU→容器 `(-0.100,+0.045)`，传给 IMU 处理链；容器偏移 `(0,0)` 传给 odom、执行器前推、OCP 与热启动。安装 yaw 继续走现有 `imu_to_base_yaw_rad`，不能把平移与轴向校正合并。

最小迁移原则：

- 配置入口只维护 B→C、B→IMU 两个独立向量；旧 `lever_arm_imu_to_target_*` 仅作历史兼容输入，不再提供第三套独立可调偏移。新旧参数同时出现时验证派生值一致；不一致则明确报错，不能静默覆盖。
- 旧配置没有新几何字段时保留既有数值行为，标明旧目标点语义/未核实状态；启用新非零容器偏移必须使用完整新配置。迁移默认配置时同步去掉重复的旧输入。
- 核对实物上 `base_link` 的固定安装基准、IMU 感测原点及轴向、容器中心的水平位置；普通相对位置测量可以作为初始证据，记录来源和误差范围，不要求先做自转中心拟合。
- 核对 odom twist 的实际参考点和轴系确实对应 B；仅改 `frame_id` 不能完成速度参考点变换。静态 TF/URDF 与数值配置做一致性核对，首版不引入运行中自动查 TF、自动覆盖参数或动态标定。
- 参数只在启动时冻结，打印两个向量及派生值。拟在录制入口暴露容器/IMU 的 x、y 参数，但这些是安装量，不作为按每包效果扫描的控制权重。

## 4. 最小代码改造范围（均待实施）

### 4.1 在激励生成处换算，液体核只消费结果

建议提供无 ROS 依赖的纯数值接口 `accelerationAtContainer(ax, ay, omega, alpha, rx, ry)`。调用者负责数据有效性、同轴及时间语义；输出是容器点加速度。

| 位置 | 应做的改动 / 补偿次数 |
|---|---|
| `ProcessedImuPipeline` | 复用现有公式，改由统一配置派生 r_IC；必要时收拢到 C++ helper。去重力、bias、滤波及符号不顺手重写。只补偿一次 |
| odom 激励生成 | 在 ROS 入口生成 `MotionExcitation` 前，以 r_BC 换算 `Δv/Δt, v*omega, omega, Δomega/Δt`；observer bank直接消费结果 |
| `LiquidStateNowcaster` | 输入已是容器激励，不再加偏移；保持当前零阶保持、时戳和有效性检查 |
| `ExecutionStatePredictor` | 对显式执行器积分小步计算实际 `a`、实际 `alpha`，用同一步中点 `v/omega` 与 r_BC 换算，再调用 `step/stepWithDt` |
| OCP `rhs(z)` | 使用该 RK4 子步的 `a_actual, alpha_actual, z[v], z[omega]` 计算 a_C；不能用控制输入 `a_cmd/alpha_cmd` 替代实际响应，也不能只在 stage 起点补偿一次 |
| 热启动 / 重建液体轨迹 | 主线实际执行器 rollout 同步使用实际角加速度；普通 flatness/备用种子中凡保留液体推进的路径也核对，避免初猜与未来模型作用点不同 |
| `SloshDynamics` / `LiquidSloshModel` | 输入契约说明“加速度已在容器点”；保持液体物理核及高度输出不做第二次安装修正 |

Python/CasADi 不能直接用只支持 `double` 的 C++ helper构造符号图。建议保留一份极短的等价符号表达，通过跨语言数值测试固定符号/约定；不为两行公式建立代码生成框架。

首版覆盖当前 `continuous_mpcc_acados + explicit_actuator` 实物主线。其他 solver、旧 delay/rollout、risk governor等若尚未适配，非零容器偏移下明确拒绝不受支持的组合；零偏移保持历史兼容。不要静默让某条可执行路径仍消费 B 点激励，也不借此恢复旧诊断支线或同步改造仿真副本。

### 4.2 OCP 参数、生成物和 C++ 包装保持一致

建议仅在**主线 slosh 参数向量末尾**追加 `container_offset_x_m/y_m`，不重排现有索引，不把几何量优化成状态/控制量。当前 NX 为无液体24、带液体28，本改造不增加状态维数；时域、执行器队列、jerk 约束及权重不变。

同步修改 `spmpc_acados_model.py` 的主线参数名/索引、生成器默认参数、C++ `enum Param`/`parameterNames`/参数填充及静态断言，检查 cost 模块的索引假设。不要向 legacy 与主线共享的 extra 列表盲目插值，避免误改旧 solver ABI。

重新生成并编译受影响的 `spmpc_slosh` 求解器和 planner，生成物不手改。若无液体参数前缀保持不变，`spmpc_b0` 不必因几何参数单独改变数学模型，但必须通过与 Smooth 的构建/运行契约回归。未知/不匹配的生成物版本不能带入实车。

### 4.3 明确点语义和时间近似

当前 [MotionExcitation][excitation] 注释允许来源各自的参考点，IMU debug仍写 `ICR proxy`。新模式应将两条监视器统一标为容器中心，以 `base_link` 轴表达；坐标轴 frame 与加速度作用点是两个概念，不能只改标签而未改变数值。

复用既有 `SloshObserverDebug`、`effective_config`、pre-solve 参数快照和 prereg，记录几何输入、派生 r_IC、参考点及补偿后激励。必要时补充补偿前后差值；不新增第三个液体监视器。消息/契约发生变化时同步版本与验收工具。

**同一时刻是物理公式的前提，现有离散估计仍含近似。** 当前 IMU 的 accel/gyro/alpha 标注相位延迟分别为6.834/5.020/15.001ms；odom 的速度差分代表一个采样区间，前推也用区间实际速度变化。提取 helper不等于这些量已精确同时。首版保留现有滤波/时序设计以支持数值回归，明确记录有效时间及近似，不把“共用消息/epoch”写成所有信号相位已校准。若偏移项对 alpha 噪声/时差敏感，单列后续问题，不在本改造中同时调滤波或延迟来制造改善。

## 5. 落实顺序与验收

先讨论参数和兼容策略，再实施以下三步；**本轮没有执行这些代码改造或测试**：

1. **配置与纯函数。** 核实安装基准，补统一配置、派生值、点语义与纯函数；零偏移/名义 IMU 参数时保持当前数值行为。
2. **一次接齐主线。** IMU/odom、nowcast输入契约、执行器前推、OCP及实际使用的热启动一起完成；生成 solver、编译、同步诊断与录制参数。不能只让监视器换点而预测仍在旧点。
3. **软件门通过后再由用户实车。** 先确认小范围运动下的输入/有效性，再按新的冻结评价链录制 Full/Smooth；不自动运行、扫参或回放发令。

必要测试优先复用现有 `test_processed_imu_pipeline.cpp`、执行器模型/nowcast/observer/热启动测试，以及刚完成的内部指标和评价锁测试：

| 测试 | 验收含义 |
|---|---|
| 独立世界轨迹二阶差分 | B同时平移、变速旋转，验证解析补偿的符号和数值；差分步长收敛，不用调用同一helper的结果自证 |
| 零偏移 / 纯平移 | r_BC=0 恢复原未来激励；omega=alpha=0时任意平移偏移不改变加速度；容器r=0并不清零 IMU lever arm |
| 匀速转动 / 起停转动 | 验证 `−omega²r` 和 `alpha×r` 两项，分别覆盖x/y偏移、正负角速度/角加速度 |
| B→IMU→C 等价 | 使用同一时刻、同一轴系的合成运动，两段换算等价于直接B→C；另测重复补偿会被发现 |
| C++ / CasADi / 执行器链一致 | 同一合成实际状态下的 a_C相符；含非零安装偏移和 `alpha_actual != alpha_cmd`，检查 RK4每个子步。离散积分方法不同采用误差/收敛判据，不要求不同积分器逐位一致 |
| 默认回归与错误配置 | 默认几何下状态/代价/jerk行为与旧代码一致（按数值容差）；缺字段、非有限值、新旧偏移冲突、未适配 backend 明确失败 |
| 记录与冻结 | 两组相同几何参数被写入报告和评价锁；参数/模型改变后旧锁拒绝通过；Full和Smooth保持共同jerk/速度/非液体权重 |

合成测试中的非零偏移只是验证工具，不是实物安装值。软件测试证明实现符合公式和接口契约；不能证明安装精确、未来液体预测准确或已经降晃。

## 6. 与当前实验的关系及待讨论决策

当前[Full/Smooth 实验入口与命令][experiment]已经在 `9d31ff6` 实现并通过75项软件测试；这些测试不代表本改造已经实现或验证。本次只写讨论稿，因此现有录制路线和参数保持原状。

若后续实施本方案，液体输入/模型与评价链可能变化，须建立新的候选和冻结版本；不能在四包复验中途更换参数/代码，也不能把新旧监视器结果直接混合。即使r_BC=0、数值理论等价，当前锁包含代码/库SHA，更新后也应重新冻结。Full与Smooth均使用相同实物几何和监视器模型，RGB、NoState后置，NOKOV仅保留辅助运动记录。

建议先按以下讨论基线推进：**B→容器暂为0、IMU安装值先核实、统一配置自动派生IMU→容器、主线各处一次接齐、保留液体核和现有滤波。** 落实前只需明确安装测量值/不确定度、新旧参数兼容方式，以及与当前实验批次的切换时点；不需要先寻找唯一负结果根因或漂移旋转中心。

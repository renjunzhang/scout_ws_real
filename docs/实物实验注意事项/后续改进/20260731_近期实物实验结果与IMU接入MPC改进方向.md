# 近期实物实验结果与 IMU 接入 MPC 改进方向

> 整理日期：2026-07-31
> 文档性质：近期开发实验小结。当前结果用于分析和后续改进，还不能作为正式 S-MPCC 实物结论。

## 1. 这几天主要完成的工作

1. 检查了 S-MPCC 的液体模型传播、延迟预测以及预测窗口设置，进一步明确了预测模型 `M`、预测窗口 `P` 和控制窗口 `C` 的关系。
2. 完成了动捕辅助的 IMU 平面标定、录包和数据检查，并修正了录包环境与文件名问题。
3. 在规划器中加入了“处理后 IMU”管线和独立液体观测器，包括去重力、静止偏置估计、滤波、陀螺仪修正、杠臂补偿和时间戳保护。
4. 设计并初步测试了一块直径为 95 mm 的圆形 PCB，使用 4 个 VL6180X 传感器按十字方向布置，用来尝试从四个方向测量液面变化。

## 2. 目前得到的实验结果

### 2.1 IMU 与动捕标定

平面旋转实验中，IMU 的 `z` 轴角速度与动捕结果基本一致：

```text
omega_mocap ≈ 1.001773 × omega_imu - 0.000297 rad/s
```

IMU 相对动捕的有效延迟约为 `0.015 s`，考虑 50 Hz 采样率后，不确定度约为 `±0.020 s`。这说明 IMU 的角速度可以经过修正后使用，但不能把时间延迟当成完全精确的固定值。

实验还发现，里程计给出的角速度比动捕低约 8%～10%。因此，当前如果只用 `/odom` 的 `v·omega` 估计横向激励，可能会低估试管实际受到的横向加速度。

原始 IMU 加速度仍然不能直接送入液体模型。它还受到重力投影、零偏、振动、安装方向、安装位置和滤波延迟的影响。目前合理的做法是先使用处理后的 IMU，并保持可诊断、可回退。

### 2.2 对预测模型 M 的认识

小车与试管是刚性连接，液体对整车动力学的反作用很小，所以预测模型可以分成单向连接的两部分：

```text
小车/执行器模型 → 试管刚体加速度 → 液体模型
```

液体不需要反过来推动小车，但预测出的液体晃动要进入 MPC 代价函数，从而影响小车下一步的控制选择。

IMU 主要测量的是小车和试管当前受到的真实激励，不是液体高度或液体状态。未来预测窗口里的加速度也不能使用“未来 IMU”，仍然要由小车和执行器模型根据候选控制量算出来。因此，正确的接入方式是：

- 当前液体状态更新使用处理后的 IMU；
- 未来液体状态仍由小车模型和液体模型向前预测；
- RGB 液面结果继续作为独立评价依据。

当前代码中的 IMU 观测器仍处于默认关闭的影子模式，只发布诊断，不进入求解器，也不会影响 `/cmd_vel`。所以目前完成的是安全接入基础，还没有完成“IMU 闭环参与 MPC”的实物验证。

### 2.3 当前预测窗口

当前配置为：

```text
控制频率：30 Hz
采样时间：1/30 s
预测窗口 P：60 步
控制窗口 C：60 步
总预测时间：2.0 s
```

每次求解虽然只执行第一步控制，然后马上重新规划，但这不代表控制窗口只有 1 步。当前 60 个预测阶段都有独立控制量，所以基本相当于 `C=P=60`。

2 秒能够覆盖多次名义液体振荡，可以继续作为起点。不过当前液体模态约为 5 Hz，30 Hz 下每个周期只有约 6 个采样点；再加上执行延迟和模型相位误差，现在还不能说明 60 步就是最优值。应先把模型 `M` 验证清楚，再比较 `P` 和 `C`。

### 2.4 四路 VL6180X PCB

四传感器十字布局能够同时观察四个方向，结构上比较直观，也便于后续做方向比较。但液体透明，VL6180X 的光可能穿过液体，或者被试管壁、液面和底部多次反射，初步测量容易跳动，精度还不够稳定。

因此，这块 PCB 暂时只能作为辅助探索，不能替代 RGB，也不适合马上作为 MPC 的液体状态输入。后续可以少量检查遮光、安装角度、容器壁反射、单传感器标定和滤波效果；如果仍然不稳定，就不在这条路线投入过多时间。

## 3. 为什么下一步重点应放在 IMU 接入 MPC

目前最关键的问题不是“有没有更多液面传感器”，而是 MPC 使用的激励是否接近小车真实运动。动捕实验已经说明 `/odom` 的角速度存在系统误差，命令到真实运动之间也有延迟。如果激励的幅值或相位不对，液体模型即使数学上稳定，预测出的晃动峰值和时刻仍可能是错的；单纯调大液体权重或加长预测窗口解决不了这个问题。

处理后 IMU 更接近试管实际受到的刚体激励，因此值得优先验证。但接入时必须保留两个边界：IMU 不能直接测出液体状态，也不能代替未来模型预测。它首先应该用于修正当前观测器，再经过独立实验确认后，才允许进入 MPC 的当前状态输入。

## 4. 后期改进方向

建议按下面顺序推进：

1. **先做离线验证。** 使用已经保留的动捕/IMU 数据，比较“odom 驱动观测器”和“处理后 IMU 驱动观测器”的激励幅值、相位以及多步液体预测。标定数据和验证数据要分开。
2. **进行实车影子测试。** 打开 IMU shadow，只记录两个观测器和 RGB，不改变求解器输入与控制命令，重点检查偏置建立、掉帧、时间戳、滤波延迟和回退逻辑。
3. **受保护地接入 MPC。** 影子结果通过后，允许处理后 IMU 更新当前液体观测状态；未来 60 步仍使用执行器、小车和液体模型预测。IMU 失效或数据过期时必须自动退回 odom 观测器。
4. **分阶段做闭环实验。** 固定路径、速度上限、权重和 `P=C=60`，先做单次低速测试，再做重复试验。使用 RGB 的峰值、p95、峰值时刻和残余振荡作为外部指标，同时检查跟踪误差、求解失败、控制平滑性和安全回退。
5. **最后再调整 P 和 C。** 当 IMU 接入后的模型幅值和相位通过验证后，再比较不同预测时长、采样率或积分子步。这样才能判断结果变化究竟来自模型改进，还是来自窗口参数。
6. **PCB 保持低优先级。** 只做少量台架改进和可重复性检查，不影响当前 IMU 接入 MPC 的主线进度。

## 5. 当前结论

近期工作已经完成了 IMU 标定、处理管线和双观测器的基础建设，也找到了 odom 可能低估真实横向激励的问题。下一阶段的核心任务是先证明“处理后 IMU 能让当前液体状态和激励估计更准确”，再安全地让它参与 MPC。

在这一步完成以前，保持 `P=C=60、预测 2 s` 不变更有利于排除干扰。四路 VL6180X PCB 作为辅助方案保留，但不作为近期主要改进方向。正式 S-MPCC 实物实验目前仍应保持谨慎放行。

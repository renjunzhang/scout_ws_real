## 1. 本阶段解决的问题

旧合同把 deadline、solver failure、输入短暂 stale 和 publish jitter 都处理成一拍零命令。这样虽然容易 fail closed，却会在 30 Hz 发布边界制造命令和 acceleration 跳变，放大实物顿挫。

本阶段只实现两块独立、ROS-free 的发布内核：

1. `JerkLimitedFallbackPolicy`：从最后一条真实发布的 `q_prev/a_prev` 生成下一拍平滑停车命令；
2. `PublishedCommandHistory` 事实顺序修正：已经发布的 late nominal 必须先进入权威历史，再由 `publish_late` 通知下一拍降级。

尚未实现 `ReleaseCoordinator`、ROS publisher adapter、运行态 re-arm、trial invalidation 或诊断消息接线。因此本阶段不能解释为“实车节点已经启用平滑 fallback”。

## 2. 发布原因不再混淆瞬态降级与硬停

`EmissionReason` 分为：

- nominal：`kNominal`；
- warm-up：`kWarmupZero`；
- 平滑降级：`kDeadlineFallback`、`kSolverFailureFallback`、`kPublishTimingFallback`、`kInputStaleFallback`；
- 硬停：`kHardSafetyStop`、`kClockFaultStop`。

历史数值 `2–5` 曾表示旧的一拍零命令或 safety override，现故意留空。clock-fault 的零语义保留数值 `6`，新 hard stop/fallback 使用 `7–11`，避免旧的纯数值 audit/event 被新版二进制误解释成新裁决。

history 只验证并记录 publisher 边界事实：平滑 fallback 保存真实 `q/a`；warm-up 和 hard stop 要求 `q=0,a=0`。jerk 可恢复性由 policy 保证，不在 history 中复制第二套控制算法。

## 3. 固定 30 Hz jerk-limited 停车

policy 不接受调用方传入的任意 `dt`，固定使用主线 release grid 的：

```text
h = 1/30 s
```

每个通道独立使用与主线 `issueCommand()` 相同的 constant-jerk 端点语义：

```text
a1 = a0 + j*h
q1 = q0 + 0.5*h*(a0+a1)
```

`a1` 是下一 publisher state 的权威端点 acceleration，不是 `(q1-q0)/h`。policy 同时约束：

```text
|q1| <= q_max
|a1| <= a_max
|a1-a0| <= jerk_max*h
q1 不穿过零
```

当 `a0` 与 `q0` 同向时，有限 jerk 不可能让 command 立即下降。policy 先以最大许可 jerk 消除向外 acceleration，此间 command 允许出现物理上不可避免的小幅增加；当 acceleration 已进入制动方向后，command 幅值保持单调下降。

## 4. 离散可恢复域

只检查下一拍不越零还不够：靠近零点时可能留下 `q=0,a!=0`，下一拍将无法同时保持零和满足 jerk 上界。policy 因此为候选端点 acceleration 计算后续以最大 jerk 收回到零所需的完整离散停车距离，并只选择仍在可恢复域内的值。

若最强制动不可行、较弱制动可行，policy 用固定 64 次二分找到安全侧最强候选，并向安全侧保留若干可表示 double 间隔；过程不分配内存、不持锁、工作量有界。负停车裕量一律拒绝，不使用对称 epsilon 放行。为避免安全偏置留下无限衰减的亚 ULP 尾巴，仅当 command 与 acceleration 都进入明确的 `32*epsilon*scale` 正残差范围、且最后一次 jerk 仍合法时规范化为精确零；该规范化绝不把负裕量改判为成功。只有：

```text
q == 0 && a == 0
```

才返回 `stopped=true`。

以下状态明确返回 `kUnrecoverablePublisherState`，output 保持不变：

- `q=0,a!=0`；
- 剩余 command 距离不足以在 jerk 界内收回 acceleration；
- command 上界、acceleration 上界、jerk 上界和不反向约束无共同可行解。

release owner 后续必须把 unrecoverable 归类为 hard stop，不能发布一个违反合同的值再标成 smooth fallback。对应的 solver 阶段还应加入 fallback viability 约束，降低 nominal 状态落出该可恢复域的概率。

## 5. late publish 的事实顺序

publish timing 只有在 publisher 调用发生后才能最终确定。此前 history 对超出 `epsilon_pub` 的 nominal receipt 返回 `kLateNominal`、锁存 fault，导致已经发生的命令没有进入权威历史。

现在顺序固定为：

```text
publish(exact q)
-> commit exact q/a/reason/actual stamp
-> event.publish_late = true
-> 下一 release cycle 进入 kPublishTimingFallback
```

late 仍使 formal trial 无效，但证据资格不能反向删除物理事实。planned `T_k^model` 仍是 delay tap 时刻，actual stamp 只作因果和 jitter 审计。

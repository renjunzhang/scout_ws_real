## 1. 本阶段解决的问题

Stage 3-D2b 已经把固定容量、完整参数布局和每拍 runtime parameter
snapshot 收敛为唯一输入，但还缺少能独立检查后续符号图的数值真值。

本阶段新增四个互相窄依赖的 ROS-free、CasADi-free 模块：

1. `discrete_dynamics.py`：单拍 actuator-aware 离散 map；
2. `reference_oracle.py`：归一化局部三次参考及 MPCC tracking error；
3. `cost_oracle.py`：普通 stage 与 terminal 的可重建分项代价；
4. `constraints_oracle.py`：显式开发约束的结构与 residual 顺序。

这些模块是 D2d CasADi 图的独立数值 oracle，不生成 symbolic graph、acados
OCP、C 源码、动态库、header 或 artifact manifest。

## 2. 单拍离散 map

唯一入口为：

```python
evaluate_discrete_map(
    capacity,
    development_layout,
    state,
    control,
    stage_parameters,
)
```

flat `x/u/p` 是有意的边界，对应后续 `f_discrete(x,u,p)`；字段语义仍只由
`DevelopmentLayout` 和 `SolverParameterLayout` 的 typed name/offset 提供，模块内
没有第二份数字 offset。

执行顺序固定为：

```text
pre-issue x_k
  -> issue q_issue/a_issue
  -> Q(0)=issued, Q(1)=q_prev, Q(r>=2)=older[r-2]
  -> 读取 D2b 已编译的三槽 duration/selector
  -> 每槽解析 FOPDT + 中点 pose + actual 激励液体 RK4
  -> s += sum(delta_r*v_s)
  -> publisher state 更新为 issued
  -> older 使用旧 q_prev shift
  -> x_{k+1}
```

map 不从 delay 重新计算 `m/beta/schedule`，也不从 runtime snapshot 反解来源
身份。snapshot/hash 与 schedule 的一致性属于调用层审计；纯 map 只表达
`x/u/p -> x_plus` 数学关系。

测试覆盖零延迟、整数延迟、分数延迟、最大容量延迟以及固定种子的 64 组随机
双通道 delay。D2b 的 `NQ_v=13/NQ_omega=25` 数值结果与独立 Stage 2 Python
oracle 对齐；已有 Stage 2 C++ golden 继续提供既有执行核回归。当前不能把这
表述为“同一 D2b case 已有直接 C++ consumer parity”，该直接跨语言 fixture
仍可在后续补充。

## 3. Reference oracle

reference 只读取完整 stage 参数中的 normalized cubic：

```text
xi = (s-ref_s_origin)/ref_s_scale
x_ref = cx0+cx1*xi+cx2*xi^2+cx3*xi^3
y_ref = cy0+cy1*xi+cy2*xi^2+cy3*xi^3

dx_ref/ds = (cx1+2*cx2*xi+3*cx3*xi^2)/ref_s_scale
dy_ref/ds = (cy1+2*cy2*xi+3*cy3*xi^2)/ref_s_scale
psi_ref = atan2(dy_ref/ds, dx_ref/ds)
```

`ref_speed` 是逐 stage 的独立参数，不是几何系数。`xi` 只接受闭区间
`[0,1]`；域外、非正 scale、退化切向、负速度参考和非有限输入全部拒绝，不做
clamp 或静默外推。contour/lag 符号与 D2a 冻结的主线 MPCC 合同一致。

## 4. Stage 与 terminal 代价

普通 shooting stage 的数值结果显式拆成：

```text
robot_running_cost
liquid_running_cost
liquid_boundary_cost
total_cost
```

唯一求值关系为：

```text
J_stage(x_k,u_k,p_k)
  = J_robot_and_command(x_k,u_k,issue_k)/N
  + liquid_run_coeff[k] * Lq(x_{k+1}, r_dot)
  + liquid_boundary_coeff[k] * E_boundary(x_k, ratio=1)

x_{k+1} = evaluate_discrete_map(x_k,u_k,p_k)
```

因此：

- robot/command 项只除一次 `N`；
- liquid running 使用同一个 map 的预测右端，不再除 `N`、不乘 `dt`；
- boundary 使用 shooting state `x_K`，模态速度比例固定为 `1`，不复用
  running `r_dot`；
- stage oracle 不允许调用方注入无来源的缓存 map；
- terminal 入口只接收 `x_N/p_N`，不接受 `u_N`，只计算四项机器人 terminal
  cost，全局液体 terminal 恒为零。

B0/Bslosh 使用同一 map、reference 和 robot cost。两臂数值差异仍只能来自
`liquid_run_coeff/liquid_boundary_coeff`。

## 5. Constraints 结构与数值成熟度

本阶段冻结约束的形状，不冻结生产数值。`ConstraintBounds` 的七个上限必须由
调用方逐项显式提供且为严格正有限 float：

```text
q_issue_v_max
q_issue_omega_max
a_issue_max
alpha_issue_max
jerk_v_max
jerk_omega_max
v_s_max
```

数值状态固定标记为：

```text
EXPLICIT_CALLER_SUPPLIED/DEV_UNVALIDATED
```

约束 oracle 输出 14 个有序 residual，每个均使用 `residual <= 0` 的可行约定：

```text
q_issue_v lower/upper
q_issue_omega lower/upper
a_issue lower/upper
alpha_issue lower/upper
j_issue_v lower/upper
j_issue_omega lower/upper
v_s lower/upper
```

双边约束被显式展开，不使用 `abs()` 非光滑代理。`v_s` 下界固定为零，上界
显式提供。B0/Bslosh 都没有 condition-dependent liquid hard constraint。

这里没有从 legacy YAML 复制任何默认值，也不要求先读取 bag 才能建立开发图。
后续 development artifact 必须记录实际采用的显式 bounds 和
`DEV_UNVALIDATED` 身份；production promotion 才要求用正式证据冻结和验证数值。

## 6. 失败与权限边界

四个 oracle 均要求有限、精确 typed 的 tuple/dataclass/layout 输入。非法宽度、
非有限中间量、无效 reference 域、错误 one-hot、非正动力学参数、非正归一化、
负权重或 residual 溢出都会显式失败。

明确不属于 D2c 的职责：

- 不读取 bag、RGB、ROS、TF 或 Stage 1 production gate；
- 不选择 production `delay/tau/gain`、权重或 constraint 数值；
- 不创建 CasADi graph 或伪造 dependency object；
- 不生成、命名或晋级任何 solver artifact；
- 不实现 acados wrapper、warm start、release coordinator 或 publisher。

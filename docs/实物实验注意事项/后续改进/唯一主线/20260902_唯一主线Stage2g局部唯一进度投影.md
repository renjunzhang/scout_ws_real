## 1. 实施边界

本子阶段新增固定容量、无动态分配的 `ReferenceProgressProjector`。它只读取 Stage 2f 在 `T_k^-` 得到的 pose、同一周期冻结的路径 snapshot，以及一个经过发布边界提交的进度权威，在局部进度窗内重建 OCP 的 `s(T_k)`。

它不：

- 读取 actual velocity、历史命令、旧未来 `v_s` 或 shifted warm start；
- 修改路径、重采样路径或进行全局最近点 fallback；
- 在人工搜索窗边界把 pose 静默 clamp 到 `s_commit` 或 forward upper；
- 接 ROS、solver、warm-start rollout 或 acados；
- 生成或冻结任何 Stage 1 执行器辨识参数。

Stage 1 仍为：

```text
BLOCKED_PENDING_DEDICATED_IDENTIFICATION_EVIDENCE
```

因此本阶段只完成数据结构、因果/几何合同与合成测试。正式路径的 start interval、forward/contour/heading guard 和 ambiguity tolerance 仍须进入后续 effective config/hash 并在使用前冻结。

## 2. 两种显式进度权威

投影没有“缺字段时默认从零开始”的入口，只接受以下两种权威之一。

### 2.1 预冻结首周期锚点

`FrozenStartProgressAnchor` 绑定：

```text
source = FrozenStartInterval
path_id / path_hash / reset_epoch
完整 target CycleRequest
history_generation
```

目标 cycle、steady/model release、path/reset 和非零 history generation 必须逐项相等。搜索窗只能是配置中预冻结的 `[start_s_min,start_s_max]`。锚点不能跨 cycle 复用；其一次性消费由后续 `PlanningCoordinator` 负责。

### 2.2 上一拍 nominal live release 提交

`NominalProgressCommit` 绑定：

```text
source = NominalLiveRelease
s_commit
完整上一拍 CycleRequest
path_id / path_hash / reset_epoch
release_generation / history_generation
```

只有实际发布值与 proposal 完全一致的 nominal live release 才能产生这种提交。projector 要求：

- commit cycle 恰好是 target cycle 的前一拍；
- 两个 cycle 的 steady/model 时间差都精确等于绝对 30 Hz release grid 的 cycle offset 差；
- `release_generation == history_generation == expected_history_generation` 且非零；
- path ID/hash/reset epoch 与本周期冻结 snapshot 完全相同。

proposal、dry-run、deadline zero、hard-safety 改写和 solver 成功本身都不能伪造此权威。生产中只有 `ReleaseCoordinator` 能创建它。

## 3. 唯一局部搜索窗

nominal 窗口严格为：

```text
I_k = [s_commit,
       min(s_path_end,
           s_commit + v_progress_bound*(T_k-T_commit) + forward_guard)]
```

时间差使用 checked `int64 ns` 相减；时间回退、差值溢出或任一浮点中间量非有限均失败。`s_commit` 必须已经位于同一条路径内，不能先 clamp 再搜索。

路径 snapshot 是固定容量有序 polyline，携带 `path_id/path_hash/reset_epoch`、有限顶点、累计弧长和显式 `s_path_end`。projector 验证：

- 顶点数在容量内，坐标/累计弧长有限且不回退；
- 非退化线段的几何长度与累计弧长增量一致；
- 重复零长度顶点不产生候选，全退化路径失败；
- `s_path_end` 与末顶点累计弧长一致。

snapshot 构建 adapter 负责按冻结的几何顺序和 metadata 计算 `path_hash`；projector 只做非零 hash 与 expected/authority/snapshot 三方相等检查，不在控制周期内重新计算 SHA-256，也不修复或替换 snapshot。Stage 4 接入时必须把该构建器收成唯一入口，不能让调用方给改变后的几何复用旧 hash。

只遍历与 `I_k` 相交的线段。每段先在完整线段上求正交投影，再检查原始进度是否位于人工窗口：低于 lower 返回 backward/start-window failure，高于 upper 返回 forward/start-window failure，禁止把它夹到人工边界。仅对浮点运算造成、且不超过显式 progress/numeric tolerance 的边界亚误差归一到等号边界；测试同时证明超过容差的 pose 不会被接受。只有真实路径首尾端点允许标准 endpoint projection，而且仍必须通过距离和航向 guard；沿端点切线离得很远也会失败。

## 4. contour、heading 与歧义

每个候选同时派生：

```text
s / projected point / path tangent
Euclidean distance
signed contour error
wrapped heading error in [-pi,pi]
```

线段内部用 `abs(signed contour error)` 检查 contour guard；当最近点是 polyline endpoint 时改用 Euclidean distance，防止远处切线延长线被误认为零横向误差。heading error 用 `atan2(sin(delta),cos(delta))` 归一化。

歧义容差的单位是米，比较候选到 pose 的 Euclidean distance，而不是平方距离：

- 不同进度分支的距离差不超过 `ambiguity_tolerance` 时返回 ambiguity；
- 距离差明确超过容差时选择更近的局部分支；
- 共享顶点产生的相同 `s`、相同投影位置候选按 `progress_equivalence_tolerance` 合并，再按最小 heading error、距离和 segment index 稳定选择；该容差必须严格小于 `minimum_segment_length`，且两个 segment 之间只能经过同一位置/进度的重复顶点；
- 仅 `s` 接近但投影位置不同的自交候选不能合并。

该规则避免全局最近点跳支，同时不把折线离散产生的明显更远 endpoint 候选误报为常态歧义。

## 5. 失败原子性与后续边界

两种 `project*()` 入口都只在局部临时对象中计算。identity、authority、generation、time、path、window、guard、数值或 ambiguity 任一失败时，调用方 output sentinel 保持不变。

成功输出携带本次实际 `s`、搜索上下界、投影点/切向、距离、signed contour、heading error、选中线段、候选数、path identity、authority cycle 和 history generation。后续 Stage 4 必须用该值覆盖 `x0.s`；不得把 shifted warm-start 的旧 `s` 写回，也不得因投影失败继续 solve。

本阶段不打开 Stage 3。正式 codegen 仍必须等待 Stage 1 的专用辨识数据、范围冻结和独立 validation/final-test 证据。

## 6. 合成验证

ROS-free 单元测试覆盖：

- 直线 window golden、上下界包含与人工边界不 clamp；
- 真实路径端点、contour/heading guard 和角度 wrap；
- 首周期 frozen anchor、nominal cycle/双时钟/generation/path/reset 权威；
- 折线共享顶点、重复零长度顶点与确定性 tie-break；
- 自交路径的局部 branch、near-equal ambiguity 与明显择近；
- 非法配置、非法路径、NaN/Inf、时间/进度溢出；
- 所有失败路径的 output 原子性。

当前执行容器只有 ROS 2 Jazzy/colcon，没有 ROS 1 `catkin_make` 或 catkin CMake package，因此新增 `catkin_add_gtest` 目标已接线但无法在该容器运行 catkin 集成命令。standalone 测试使用与包相同的 C++14 header 和 gtest 源直接编译；后续进入 ROS 1 构建环境时仍须补跑该目标。

## 7. 模块边界收口

后续主线审查在不改变上述投影语义的前提下，把原先集中在 projector 头文件中的稳定类型拆成三层：

```text
domain/physical_state.h
  -> 定义 pose/actual/liquid physical vocabulary 及其 finite invariant

reference/reference_path_snapshot.h
  -> 只定义 path identity、vertex 和固定容量 snapshot

reference/reference_progress_contract.h
  -> 只定义 projector config、两种 authority、status 和 result

reference/reference_progress_projector.h
  -> 只保留 release/window 校验和局部几何算法
```

因此参考投影不再为了一个 `PlanarPoseState` 依赖整个 plant integrator，plant integrator 也不再拥有跨模块共享的 physical state 类型。`FrozenStartProgressAnchor` 的完整周期字段明确命名为 `target_cycle`，`NominalProgressCommit` 的完整已发布周期字段明确命名为 `release_cycle`，避免两个权威入口都暴露含义不清的 `cycle`。

该拆分没有增加兼容入口、运行时分支或第二套类型；旧聚合定义已从原头文件删除。四个边界头文件均通过独立严格 C++14 自包含编译，直接受影响的 plant/discrete-map/known-prefix/projector 39 项及 Stage 2 全部 104 项回归通过；projector 另在 `-O0/-O1/-O2/-O3` 与 ASan/UBSan 下通过。

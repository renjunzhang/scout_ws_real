## 1. 实施边界

本子阶段新增 ROS-free 的 `PiecewiseZohPlantIntegrator`，把一个已经选定常值 target 的物理子段按唯一顺序传播：

```text
解析 FOPDT actual
-> actual 子段中点位姿
-> 使用解析 actual 节点激励的固定 RK4 液体模态
```

它不维护命令历史、不计算 issue map、不推进 delay queue、不传播虚拟进度 `s`，也不接 known-prefix、progress projector、ROS 或 acados。Stage 2e 才把 Stage 2c 的 selector/queue、Stage 0 的 issue map 与本数值核组装为完整 pre-issue 离散 map。

Stage 1 仍为：

```text
BLOCKED_PENDING_DEDICATED_IDENTIFICATION_EVIDENCE
```

因此本阶段只使用测试内合成的 `tau/gain/omega_n/zeta/kappa`，没有写入正式执行器 preset，没有冻结最终 state/parameter 维度，也没有打开 Stage 3 codegen 门禁。

## 2. 强类型物理状态

`PhysicalPlantState` 只包含：

```text
pose:   x, y, heading
actual: linear_velocity, angular_velocity
liquid: eta_x, eta_x_dot, eta_y, eta_y_dot
```

这里刻意没有 `s`。历史命令中不存在权威 `v_s`，后续 `KnownPrefixPropagator` 只能调用该物理核；均匀 OCP stage 的 `s_next=s+dt*v_s` 由完整离散 map 单独处理。

## 3. 常值目标子段

对每个 `ZohTargetSegment{delta,q_target_v,q_target_omega}`，线角 actual 使用 Stage 2c 同一解析 FOPDT：

```text
actual_c(t) = exp(-t/tau_c)*actual_c(0)
            + (1-exp(-t/tau_c))*gain_c*q_target_c
```

位姿只使用 `t=delta/2` 的解析 actual：

```text
theta_next = theta + delta*omega_actual_mid
theta_mid  = theta + 0.5*delta*omega_actual_mid
x_next     = x + delta*v_actual_mid*cos(theta_mid)
y_next     = y + delta*v_actual_mid*sin(theta_mid)
```

不使用 raw command、`a_issue/alpha_issue` 或 measured velocity 代替 actual。

## 4. 液体 RK4

液体连续模态只消费 actual 激励：

```text
a_x(t) = (gain_v*q_target_v-v_actual(t))/tau_v
a_y(t) = v_actual(t)*omega_actual(t)

eta_x_ddot = -2*zeta*omega_n*eta_x_dot
             -omega_n^2*eta_x-kappa_x*a_x(t)
eta_y_ddot = -2*zeta*omega_n*eta_y_dot
             -omega_n^2*eta_y-kappa_y*a_y(t)
```

固定 RK4 的四个节点分别在 `0,delta/2,delta/2,delta` 重新解析计算 actual，不能把 target、命令加速度或子段平均 actual 当成四个节点的共同激励。`delta=0` 是严格 identity。

启动参数强校验要求：

```text
tau_v/tau_omega > 0
gain_v/gain_omega > 0
omega_n > 0
zeta >= 0
kappa_x/kappa_y > 0
全部有限，派生 damping/stiffness 也必须有限
```

## 5. 固定容量分段与失败语义

`propagatePiecewise()` 接受编译期固定长度数组。active 子段必须从 slot 0 连续排列，零时长 unused slot 只能尾随；所有 duration 必须非负、有限，并在冻结容差内合计为调用方声明的总时长。

运行时接口返回强类型状态码。初态、target、duration 或任一中间 actual/RK4/pose 结果非法时立即失败，调用方 output 完全不变；不会留下“actual 已更新但 liquid 未更新”的半提交状态。

## 6. 合成测试

11 项 ROS-free 测试覆盖：

- 非法执行器/液体参数和派生系数溢出；
- 零时长严格 identity；
- 解析 FOPDT 的 end/midpoint 与中点位姿 golden；
- 无阻尼自由模态的 RK4 四阶多项式 golden；
- RK4 在四节点采样解析纵向 actual 加速度；
- 横向激励严格使用 `v_actual*omega_actual`；
- 改变 liquid 初态不反向影响 pose/actual；
- 1/2/3 active slot 的物理时间顺序；
- duration gap、总和错误、NaN target；
- 非有限初态、有限输入中间溢出及后续子段失败时 output 原子不变。

这些测试只证明离散公式和失败边界，不证明实车执行器或液体 fidelity。Python/CasADi 同公式 golden、正式参数和 final-test 仍属于后续门禁。

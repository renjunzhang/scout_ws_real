# 近期实物实验进展与 IMU-MPC 后续改进

> 整理日期：2026-08-04
> 文档性质：近期 development 实物实验与离线诊断小结，不构成正式 S-MPCC 实物结论。
> 证据范围：基于上一份小结所在提交 `01700fd` 之后至 `73495b0`（2026-08-02）的已提交 Git 历史及其冻结产物；不包含当前工作区尚未提交的仿真开发内容。

## 1. 术语说明

- **`processed_imu`：处理后的 IMU 输入。** 它不是直接使用原始加速度计数值，而是经过去重力、静止偏置估计、滤波、陀螺仪修正、杠臂补偿和时间戳保护后的刚体激励估计。本阶段比较的是它和仅由轮式里程计 `/odom` 推出的激励，目的是给液体模型选择更可信的当前输入。
- **observer：液体状态估计器。** 它根据 IMU 或 odom 推断“此刻液体大致怎么晃”，并不是直接测得液面高度的传感器；RGB 才是本阶段用于独立核对它的外部测量。
- **G2S：第二阶段的“输入源选择”实验。** `S` 表示 source selection。它在相同 Bsmooth 小车运动上，同时离线比较“odom 驱动的 observer”和“processed-IMU 驱动的 observer”谁更接近独立 RGB 液面测量；它不是两种控制器之间的优劣比较。
- **G2C：G2S 之后的候选权重比较实验。** 在确定优先使用 processed-IMU 后，原计划用 W2 和 W5 做 ABBA 比较，检查不同液体晃动权重的安全性、跟踪和求解行为。它仍是 development 入口，不是正式结果；本文只记录它被准备和门禁保护，并不把它当作已经取得的疗效证据。
- **G3 与 G3R：更靠后的“是否真的降低液面晃动”验证及其整改版。** G3 原本尝试用在线 RGB 检验候选控制器的实物效果；G3R 是发现旧 G3 的延迟状态口径有问题后，先收缩状态处理、再重新筛选候选的整改路线。
- **G3R2：旧 G3 问题后的第二版整改实验批次。** 旧 G3 暴露出“用于求解的延迟传播液体状态”与独立 RGB 的方法排序不一致。G3R2 因而先保留最新实测的液体状态，再以最小改动筛选和确认候选权重；它是 development 诊断批次，不是正式论文实验。
- **`fixed_robot_only`：只补偿小车、不滚动液体的延迟口径。** 控制器可按固定延迟处理小车的位置/速度等机器人状态，但液体状态仍采用当前 processed-IMU observer 的最新估计，不能再用历史控制命令把液体状态向前“滚动”一段时间。这样可避免把尚未验证的液体延迟模型混入本轮权重比较。
- **`W5_S10`：本轮待验证的一个控制器参数组合。** `W5` 表示液体晃动代价权重 `w_slosh=5.0`；`S10` 表示平滑相关权重 `w_smooth`、`w_alpha`、`w_du_a`、`w_du_vs` 均取 `1.0`。它与基线 `Bsmooth` 的主要差别是加入了较强的液体晃动代价，并不是一个已经证明有效的新算法。
- **`Bsmooth`：本轮安全对照组。** 它不加入液体晃动代价（`w_slosh=0`），但保留相同的平滑相关权重。所有“Bsmooth − W5 为正”都表示 W5 的 RGB 液面指标更低、更好。
- **ABBA 配对确认：抵消顺序和环境漂移的重复比较。** 一个 block 按“Bsmooth→W5”运行，下一 block 反转为“W5→Bsmooth”。候选必须在预先冻结的多个 block 中持续胜出，单次看起来较好的结果不能直接放行。
- **H0：本轮使用的固定开发路径。** 结论只适用于这条路径、当前速度和容器条件，不能自然外推到其他轨迹或正式实验矩阵。
- **solver stage 0：一次 MPC 求解的当前起点。** 它约束的是“现在的液体状态”，不是未来预测节点；确认 observer 写入 stage 0 只说明当前起点接通，不能证明后续 2 s 的预测正确。
- **正式 Stage I：候选通过 development 配对确认后才可进入的正式实物证据阶段。** 当前 G2S、G3R2 都停留在 development，不能计入正式 40/64/88 实物实验矩阵。

## 2. 当前的问题

当前的核心问题已经不是“IMU 有没有接进 MPC”，而是“接入后的 MPC 能否正确判断未来液体会怎样晃，并据此带来真实收益”。具体有四层：

1. **当前状态较可信，但未来预测不够可信。** `processed_imu` 比 odom 更接近 RGB，且它已经写入 solver 的当前起点；但这只能说明“现在的液体状态”较合理，不能证明后续 2 s horizon 的预测正确。
2. **预测与实物的对应在远期变弱。** 按真正可用后的时间来衡量，planned horizon 与 RGB 的对应性约 `100 ms` 后开始明显衰减，`333 ms` 后不宜作为可靠物理预测。因此，当前的远期 slosh cost 可能在优化低可信信息。
3. **当前控制权重没有带来可重复的实物收益。** `W5_S10` 在有效 ABBA 配对中没有比 `Bsmooth` 降低 RGB 液面指标，同时增加了部分跟踪误差和求解时间。这说明“给液体晃动更大权重”在当前模型和状态口径下没有得到实物支持。
4. **根因仍未分清。** 现在还不能确定主要是时间对齐、计划运动与实际运动不一致、液体模型参数、输入定义，还是 RGB 与液体状态的映射造成了上述失配。没有分清以前，继续调大 `w_slosh`、重录有利 trial 或加入 hard cap 都不能解决问题。

因此，当前应先用离线 replay 将“时间语义—计划/实际输入—observer—RGB”逐层拆开验证，再建立新的 development release；正式 Stage I 和 40/64/88 仍保持 NO-GO。

## 3. 已完成的工作

### 3.1 G2S：先为液体模型选择更可信的当前输入

完成了 G2S 三条 raw-RGB development bag 的重标尺、视觉复核和 observer 对齐分析。相对 odom observer，`processed_imu` observer 的 motion-window RGB 对齐 MAE 从 `0.3656 mm` 降至 `0.2392 mm`，平均改善 `34.56%`；三条 trial 的方向均一致，且两种 observer 的时间覆盖率均为 `100%`。

因此，后续 S-MPCC development 的内部液体模型输入优先采用 `processed_imu`。同时已补齐 source selector、诊断消息、录包与分析器，以及 G2C 的 fail-closed 入口。

但原预注册 G2S 的第四条没有采集，本批也没有完整正式 postflight。因此它只能支持 `processed_imu` 进入 G2C development，不能写成正式 G2S PASS，更不能据此放行 G3 或正式 40/64/88 实物实验。

### 3.2 旧 G3 暴露了“内部预测好看、外部液面不支持”的问题

对旧 G3 八包的只读复算表明，旧的 liquid delay rollout 使内部 predicted-slosh 指标持续偏向 W5，但独立 RGB 的方法排序并不支持这一结论。严格排除相机时间戳失败和 IMU reset/fallback 后，仅有 6 条数据具备完整资格；两个严格有效配对的 RGB 平均结果也不支持旧 W5。

因此，旧的闭环液体延迟传播不再作为放行依据。后续 G3R/G3R2 采用最小可证伪方案：

- solver 的液体初始状态使用当前的 processed-IMU observer；
- 机器人状态只进行 robot-only 延迟处理或影子诊断；
- 不再把 liquid delay rollout 当作已验证的物理状态变换；
- IMU 运动期间 fallback 采用 fail-closed 策略。

这一步不是宣称执行延迟已经解决，而是先移除已经被独立 RGB 否证的状态处理方式，避免同时混入执行器模型、液体模型和权重变化。

### 3.3 G3R2：在不滚动液体状态的前提下筛选和确认候选

本阶段补齐了只补偿小车延迟的 smoke、四候选单次筛选、相机时间戳失败证据及受控重试、方法失败后的继续规则，以及候选的 ABBA 配对确认协议。单次筛选选择 `W5_S10` 进入配对确认，但最终结果未能复现该单次正向信号。

已完成的两个完整 ABBA block 共四条数据均通过 postflight：RGB motion+tail 有效率、processed-IMU READY/source coverage、robot delay applied fraction、tracking 和 solver runtime 均满足单条门槛，未出现 reset、fallback、求解失败或录包损坏。

然而，冻结主指标的结果为：

```text
RGB P95 改善（Bsmooth - W5）平均值 = -0.0060 mm
RGB 正向 block                         = 0 / 2
冻结要求                               = 至少 2 / 3 个正向 block
```

剩余一个 block 即使正向也无法达到原冻结方向门槛，故该批以 `FUTILITY_STOP_NO_CONFIRMATION` 停止。它不是采集质量失败，而是一个透明记录的 development futility stop：`W5_S10` 不进入正式 Stage I，不能作为有效 anti-slosh 方法，也不得把 4/6 条数据包装为完成的正式三配对实验。

## 4. 对 IMU、observer 与 solver 的新认识

后续的逐预测步 horizon 对齐与 replay 诊断确认：在 G3R2 的 W5 求解中，selector 时刻最新合格的 processed-IMU observer snapshot 已写入 solver stage 0，并由 `lbx = ubx = x0` 固定。当前问题因此不能简单归为“IMU observer 没有送入 solver”的接线错误。

同时，诊断也明确了该链路尚不能支持完整 2 s horizon 的物理有效性声明：

- 接近起点的部分 horizon node 仍可能对应已发生状态，不能直接当作 forecast；
- 以真正可用后的 causal lead 衡量，planned horizon 与 native RGB 的对应性在约 `100 ms` 后明显衰减，`333 ms` 后不宜视为可靠物理预测；
- actual-IMU retrospective replay 与 RGB 仍保持中等稳定对应，说明液体 ODE 的软件实现和 observer 时间步进没有发现明显接线错误；主要矛盾更接近 planned future motion 与实际闭环 future motion 的失配。

因此，当前证据既不支持重写液体 ODE，也不支持周期性用 observer 覆盖 future horizon nodes。应优先审计时间语义、计划/实际输入差异以及远期低可信节点对首控制量的影响。

## 5. 当前允许与不允许的结论

允许的结论：

- `processed_imu` 在当前三条 G2S development 数据中比 odom 更贴近 RGB；
- G3R2 的 observer 到 solver stage-0 接入链已完成并可审计；
- 当前 `W5_S10` 的配对 confirmation 没有显示可重复的 RGB 液面收益；
- 当前完整 2 s horizon 尚未得到实物预测 fidelity 的验证。

不允许的结论：

- 不能把 G2S 三条数据称为正式输入源选择 PASS；
- 不能把 W5_S10 的单次筛选正向当成论文实物 efficacy；
- 不能据此否定 processed-IMU 的工程可用性；
- 不能因 observer 已写入 stage 0，就推断未来液体预测已正确；
- 不能开始正式 Stage I、40/64/88，或直接进入 hard-cap 实车试验。

## 6. 下一步改进方向

建议按以下顺序继续：

1. **冻结统一时间合同。** 为 selector、solver、horizon、RGB 和命令链增加可审计的 cycle/time 语义，严格区分 hindcast 与真正 forecast。
2. **分层做离线 replay。** 分别量化 OCP 数值层、planned/realized input 层、observer 实现层和 RGB 物理层误差，避免只比较三个 P95 标量。
3. **先验证模型与测量映射。** 使用独立 calibration/validation/test bag，检查幅值、相位、gain 与 held-out RGB 预测；在此之前不继续提高 `w_slosh`。
4. **把总预测 horizon 与液体代价 horizon 分开验证。** 暂不因为液体远期预测变弱就直接缩短 `P=C=60` 的 2 s MPC 总 horizon，以免同时改变小车跟踪、速度规划和终端行为。先在不发 `/cmd_vel` 的离线 replay 中，预冻结比较“液体代价使用完整 60 步”“只使用前 10 步（约 333 ms）”“只使用前 5 步（约 167 ms）”以及“约 100 ms 后逐步折扣”对第一条控制命令的影响。只有确认低可信远期节点实质驱动了第一条控制命令，才在新的 development release 中缩短或折扣**液体代价**的有效作用区；`100/333 ms` 目前只是诊断候选，不是可直接写入控制器的正式常数。
5. **再建立新 development release。** 只有时间、输入、预测 fidelity 与 matched-weight 因果隔离均通过后，才重新预注册实物配对实验；新的数据不得重解释为当前 W5_S10 的证据。
6. **约束按风险层逐步推进。** 先做可审计的 soft constraint/slack 和 fallback，再考虑不确定性 tightening；在 false-safe 和 constraint-relevant peak 未独立验证前，不启用无 slack 的 hard cap。

## 7. 当前结论

1. **输入源的当前选择是 processed-IMU。** 在现有三条 development 数据中，它比 odom 更接近 RGB，因此后续开发应优先沿用它；但三条数据不是正式四条输入源选择实验，不能把这个工程选择包装为正式实物结论。
2. **当前液体状态已能进入 MPC，但未来液体预测还没有通过实物验证。** observer 的最新状态确实写入每次求解的起点；这解决了“当前状态有没有接通”的问题。它不等于控制器已经能正确预知未来 2 s 的液面变化，现有证据反而显示远期预测可信度不足。
3. **当前 W5_S10 配置不应继续用于实物 efficacy 尝试。** 它在有效的 ABBA 配对中没有比 Bsmooth 降低 RGB 液面指标，还牺牲了一部分路径跟踪并增加了求解时间。这个配置不应重录、挑选有利 trial 或修改阈值后重新解释。
4. **正式实物实验仍是 NO-GO。** 现阶段不能进入正式 Stage I、40/64/88，也不应直接加入无 slack 的液面 hard cap；这些动作都需要新的、预冻结的 development evidence 作为前提。
5. **下一轮工作的核心不是继续调大权重。** 应先把时间语义、计划输入与实际输入的差异、RGB 物理映射和有效预测时域说明白；通过后再建立新的 release 和新的配对实验，而不是把当前失败批次续写成新方法的证据。

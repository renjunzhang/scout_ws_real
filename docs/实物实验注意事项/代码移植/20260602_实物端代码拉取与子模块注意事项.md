## 2. 实物端标准拉取命令

在实物机执行：

> **注意**：`git submodule update --init --recursive` 会初始化全部子模块，其中 `mpc_planner`、`control_box_rst`、`mpc_local_planner` 包含非 catkin 构建类型，会导致后续 `catkin_make` 失败（§5.10）。
> SPMPC 主线只需要 `navigation` 子模块；外部 baseline 额外需要 `mpc_local_planner`（走 isolated 构建）。
> 首次配置建议只初始化需要的子模块：

```bash
source /opt/ros/noetic/setup.bash
cd /home/geist/scout_ws

git fetch origin
git checkout experiment/georef-mpc-hybrid
git pull --ff-only

git submodule sync --recursive
# SPMPC 主线：只初始化 navigation
git submodule update --init src/scout_apps/control/navigation
```

检查子模块指针：

```bash
git submodule status --recursive
```

应该能看到：

```text
3885d64... src/scout_apps/control/mpc_local_planner
58976e6... src/scout_apps/control/navigation
```

如果显示前面有 `-`，表示子模块还没初始化；重新执行：

```bash
git submodule update --init --recursive
```

如果显示前面有 `+`，表示子模块 checkout 的 commit 和主仓库记录不一致；重新执行：

```bash
git submodule sync --recursive
git submodule update --init --recursive
```

### 2.1 `git pull` 不会带来的本地产物

下面这些文件**不会**通过 `git pull` 出现在实物机，必须本地重新生成或安装：

```text
src/scout_apps/control/spmpc_local_planner/generated/acados/spmpc_b0/
src/scout_apps/control/spmpc_local_planner/generated/acados/spmpc_slosh/
src/scout_apps/control/spmpc_local_planner/generated/acados/spmpc_b0_direct_omega_legacy/
src/scout_apps/control/spmpc_local_planner/generated/acados/spmpc_slosh_direct_omega/
```

原因：acados 生成的 C 求解器包含大量 `.c/.h/.o/.so` 构建产物，已按工程规则忽略，不提交到 git。

因此实物机拉完代码后，如果要跑 `continuous_mpcc_acados`，必须执行 §3.1 的 `generate_spmpc_acados.py --model b0/slosh`。
如果要跑 RouteB 诊断后端 `continuous_mpcc_direct_omega_legacy`，还要生成 `b0_direct_omega_legacy`；`slosh_direct_omega` 目前有生成/链接入口，但 formal 使用前仍需单独验证。
如果只跑 `solver_backend:=primitive`，不需要这些 generated 文件。

### 3.1 acados 连续 MPCC 求解器安装（alpha-state 主线 / RouteB 诊断后端）

> 跑 `solver_backend:=continuous_mpcc_acados`（alpha-state 连续 MPCC 主线）或 `solver_backend:=continuous_mpcc_direct_omega_legacy`（RouteB/direct-omega 诊断后端）时需要。
> 只跑 primitive 后端的话**不需要 acados**，跳过本节。
> 以下步骤在 Ubuntu 20.04 (focal) + ROS Noetic + Python 3.8 实测通过（2026-06-03）；RouteB direct-omega 生成入口在 2026-06-08 后加入。

**隔离原则（务必遵守，避免污染现有环境）：**

```text
C 库      -> ~/acados           （独立 .so，运行时 C++ 靠 LD_LIBRARY_PATH，不碰系统）
Python 接口-> ~/acados_venv      （专用 venv，绝不动 ~/.local 的 casadi）
```

实物机的 `ferrari_oracle.py` 等脚本依赖 `~/.local` 的 casadi 3.7.2；
**不要用 `pip install --user acados`**，否则可能改写 casadi 版本、波及 scout 分析脚本。

**步骤：**

```bash
# (1) 系统依赖
sudo apt-get install -y build-essential cmake git python3-venv python3-dev

# (2) 源码 + 子模块
git clone https://github.com/acados/acados.git ~/acados
cd ~/acados && git submodule update --init --recursive

# (3) 编译 C 库（CPU，无显卡；X64_AUTOMATIC 自动选最快 BLASFEO 内核）
mkdir -p build && cd build
cmake -DACADOS_WITH_HPIPM=ON -DACADOS_INSTALL_DIR=$HOME/acados \
      -DBLASFEO_TARGET=X64_AUTOMATIC ..
make install -j$(nproc)
# 产物校验: ls ~/acados/lib/libacados.so  ~/acados/lib/libhpipm.so

# (4) 环境变量（写入 ~/.bashrc 并 source）
# ⚠️ 必须写在 ~/.bashrc 的交互式守卫之前，否则非交互 shell（roslaunch 子进程）读不到（§5.12）
sed -i '1i export ACADOS_SOURCE_DIR=$HOME/acados\nexport LD_LIBRARY_PATH=$HOME/acados/lib:$LD_LIBRARY_PATH\n' ~/.bashrc
source ~/.bashrc

# (5) 隔离 venv 装 Python 接口（用源码自带版本，匹配 C 库；勿用 PyPI 的 pip install acados）
python3 -m venv ~/acados_venv
source ~/acados_venv/bin/activate
pip install --upgrade pip
pip install -e ~/acados/interfaces/acados_template pyyaml
deactivate
```

**focal 专属坑 —— t_renderer 模板渲染器（必踩）：**

acados 首次 codegen 需要 `t_renderer`。官方预编译二进制针对 GLIBC≥2.32，
**focal 只有 GLIBC 2.31，直接用会报 `version GLIBC_2.32 not found`**。
必须从子模块源码自编：

```bash
# 子模块自带 tera_renderer 源码，但依赖 pest≥2.8.6，要求 rustc≥1.83；
# apt 的 cargo(1.75) 太旧，用 rustup 装最新 stable（装到 ~/.cargo，用户级隔离）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y --profile minimal
source ~/.cargo/env

cd ~/acados/interfaces/acados_template/tera_renderer
cargo build --release
cp target/release/t_renderer ~/acados/bin/t_renderer   # 覆盖不兼容的预编译版
```

**(6) 生成求解器并验证：**

```bash
export ACADOS_SOURCE_DIR=$HOME/acados
export LD_LIBRARY_PATH=$HOME/acados/lib:$LD_LIBRARY_PATH
source ~/acados_venv/bin/activate
cd ~/scout_ws/src/scout_apps/control/spmpc_local_planner/scripts/acados

# alpha-state 主线
python generate_spmpc_acados.py --model b0      # -> generated/acados/spmpc_b0/libacados_ocp_solver_spmpc_b0.so
python generate_spmpc_acados.py --model slosh   # -> generated/acados/spmpc_slosh/...

# RouteB/direct-omega 诊断后端（需要跑 continuous_mpcc_direct_omega_legacy 时再生成）
python generate_spmpc_acados.py --model b0_direct_omega_legacy
python generate_spmpc_acados.py --model slosh_direct_omega   # formal 使用前仍需单独验证
deactivate
```

看到 `[ok] acados 求解器 ... 已生成` 即成功。
（不装 acados 时可 `python3 generate_spmpc_acados.py --model b0 --check` 仅校验 CasADi 模型；也可对 `slosh` / `b0_direct_omega_legacy` / `slosh_direct_omega` 执行 `--check`。）

生成后再回到工作区重编 `spmpc_local_planner`，让 CMake 把 generated solver 链接进去：

```bash
deactivate 2>/dev/null || true
source /opt/ros/noetic/setup.bash
source ~/.bashrc
cd ~/scout_ws
catkin_make --pkg spmpc_local_planner --force-cmake
source ~/scout_ws/devel/setup.bash
```

如果跳过这一步，节点可能仍按 stub 编译，运行时 `/spmpc/status` 会报 `ACADOS_NOT_IMPLEMENTED`。

**隔离验证（确认没污染）：**

```bash
python3 -c "import casadi; print(casadi.__file__)"          # 应仍是 ~/.local 的 3.7.2
python3 -c "import acados_template" 2>&1 | grep -q "No module" && echo "系统未泄漏 acados_template(正确)"
```

**版本备忘（实测组合）：** acados v0.5.4 / acados_template 0.5.1 / casadi 3.7.2 /
rustc 1.96(rustup) / t_renderer 自编 / GLIBC 2.31。

```text
liquid_experiment_monitor.py  纯订阅前端, 只显示 RGB overlay、液面曲线、SPMPC 状态, 不发控制命令
```

依赖：

```bash
sudo apt-get install -y python3-matplotlib python3-opencv ros-noetic-cv-bridge
catkin_make --pkg realsense_liquid_measurement
source ~/scout_ws/devel/setup.bash
```

```bash
roslaunch realsense_liquid_measurement online_liquid_height.launch \
  calibration:=/home/geist/slosh_bags/real/<DATE>_calib/red_3ruler.yaml \
  image_topic:=/camera/color/image_raw \
```


### 3.4 Nokov 动捕监控端（只做监控/真值，不接规划闭环）

Nokov/XINGYING 动捕在当前实物实验中只作为**外部轨迹监控与 rosbag 真值记录**，不替换 `/odom`，不作为 `spmpc_local_planner` 输入，不发布 `/cmd_vel`，默认不发布 TF，也不发布 `map -> base_link` 或 `odom -> base_link`。

底层接入按 Nokov PDF 的 ROS1/VRPN 流程：

```text
XINGYING/Nokov 开启 VRPN
  -> 工控机 ros-noetic-vrpn-client-ros
  -> /vrpn_client_node/<Tracker>/pose
  -> nokov_mocap_monitor 封装为 /mocap/* 监控话题
```

#### 3.4.1 工控机一次性系统依赖

首次在工控机上使用 Nokov 前安装：

```bash
source /opt/ros/noetic/setup.bash
sudo apt-get update
sudo apt-get install -y ros-noetic-vrpn-client-ros

rospack find vrpn_client_ros
```

`vrpn_client_ros` 作为系统依赖，不作为子模块放进仓库；本仓库只保存监控端 launch/config/script。

#### 3.4.3 XINGYING/Nokov 侧约定

建议现场固定：

```text
XINGYING/Nokov 主机 IP: 10.1.1.198
工控机有线网口 IP:       10.1.1.196/24
VRPN 端口:                3883（常用默认值；以 XINGYING 实际配置为准）
刚体类型:                 刚体
刚体名:                   Scout

```

`3883` 是 VRPN 常用默认端口，不是协议上不可改变的固定值。如果 XINGYING/VRPN 广播配置里改过端口，ROS 端必须使用同一个端口；仓库封装 launch 用 `vrpn_port:=<端口>` 覆盖。

#### 3.4.6 与规划控制链路的隔离检查

Nokov 监控端启动后，必须确认它没有接入控制：

```bash
rostopic info /odom
rostopic info /cmd_vel
rosnode info /mocap_pose_monitor
rosnode info /spmpc_local_planner
```

期望：

```text
/mocap_pose_monitor 只订阅 /vrpn_client_node/Scout/pose；
/mocap_pose_monitor 只发布 /mocap/*；
spmpc_local_planner 不订阅 /mocap/scout_odom；
Nokov 相关节点不发布 /odom；
Nokov 相关节点不发布 /cmd_vel；
默认没有动捕 TF；显式 publish_tf:=true 时也只能是 mocap_world -> mocap_scout。
```

启动 SPMPC 时不要加：

```bash
odom_topic:=/mocap/scout_odom
```

也不要把任何 YAML 改成：

```yaml
topics:
  odom: /mocap/scout_odom
```

### 5.9 实物端路径 JSON 和开发机不完全一致

当前实物连续 MPCC SOP 不是严格复用同一个 JSON 路径文件。实物上每次按同一地面起点、同一目标点、同一 `P2_s_curve` 模板参数，从当前车位姿生成模板路径。

公平性口径写在 `docs/实物实验注意事项/对比试验/20260603_SPMPC连续MPCC实物对比实验SOP.md`：

```text
同一地面起点标记 + 同一目标点 + 同一 P2_s_curve 模板参数 + 同一相机/HSV/标尺标定。
```

### 5.10 catkin_make 报 "non-catkin packages" 错误

`git submodule update --init --recursive`（§2）会把所有子模块都拉下来，但当前工作区里有三个子模块是**不应该全量初始化**的：

```text

src/scout_apps/control/control_box_rst  ← build_type: cmake
```

```text

a non-homogeneous workspace without isolation.
```

**处理（两种方案）：**

方案 A —— 只初始化需要的子模块（SPMPC 主线只需要 `navigation`）：

```bash
git submodule sync --recursive
git submodule update --init src/scout_apps/control/navigation
```

方案 B —— 全量 init 后再 deinit 不需要的：

```bash
git submodule update --init --recursive
git submodule deinit -f src/mpc_planner
git submodule deinit -f src/scout_apps/control/control_box_rst
git submodule deinit -f src/scout_apps/control/mpc_local_planner
```

验证 catkin_make 配置无报错：

```bash
rm -rf build devel
catkin_make --pkg spmpc_local_planner
```

如果还要跑 mpc_local_planner 外部 baseline，走 §4 的 `catkin_make_isolated` 单独构建，不要让它进入主 `catkin_make`。

### 5.12 acados 环境变量在 ~/.bashrc 中的位置（非交互式 shell 问题）

实物机标准 Ubuntu 20.04 的 `~/.bashrc` 顶部有一个交互式守卫：

```bash
case $- in
    *i*) ;;
      *) return;;
esac
```

如果 `export ACADOS_SOURCE_DIR=...` 和 `export LD_LIBRARY_PATH=...` 写在守卫**之后**，`roslaunch` 子进程（非交互式 shell）执行 `source ~/.bashrc` 时会在守卫处直接 `return`，不会读到 acados 变量。C++ 节点将找不到 `libacados.so`、`libhpipm.so`。

**正确做法**：把 acados 环境变量写在 `~/.bashrc` 的交互式守卫**之前**：

```bash
# ~/.bashrc 文件开头（守卫之前）
export ACADOS_SOURCE_DIR=$HOME/acados
export LD_LIBRARY_PATH=$HOME/acados/lib:$LD_LIBRARY_PATH

# 以下是原有的交互式守卫
case $- in
    *i*) ;;
      *) return;;
esac
```

验证非交互式 shell 能读到变量：

```bash
bash --norc --noprofile -c 'source ~/.bashrc; echo $ACADOS_SOURCE_DIR'
# 应输出 /home/geist/acados
```

### 5.13 acados 求解器生成后 model 文件更新导致 static_assert 编译失败

§3.1(6) 生成求解器后，如果后续 `git pull` 更新了 Python 模型文件（`scripts/acados/spmpc_acados_model.py`）中的参数数量，而 `generated/acados/` 目录里的旧求解器未被清理/未重新生成，再次 `catkin_make --force-cmake` 时会触发 C++ 编译期 static_assert：

```bash
catkin_make --pkg spmpc_local_planner --force-cmake
source ~/scout_ws/devel/setup.bash
```

```bash
grep 'SPMPC_B0_NP\b' src/scout_apps/control/spmpc_local_planner/generated/acados/spmpc_b0/acados_solver_spmpc_b0.h
```

```text
3. 不要把 alpha-state 的 alpha_max=1.2 结果和 RouteB alpha_max=3.5 结果混成同一张 common-limit 主表。
```

### 7.7 常见状态码

| status | 含义 | 处理 |
|---|---|---|
| `ACADOS_NOT_IMPLEMENTED` | 编译成 stub，没链接真实 acados 后端 | 检查 `ACADOS_SOURCE_DIR`、generated solver、`--force-cmake` |
| `ACADOS_NOT_CREATED` | generated solver 参与编译但 capsule 创建失败 | 检查 `.so`、`LD_LIBRARY_PATH`、codegen 版本 |
| `ACADOS_SOLVE_FAILED_*` | alpha-state 后端求解失败 | 检查起点、goal、路径、约束、权重、`alpha_max` 是否过紧 |
| `ACADOS_DIRECT_OMEGA_SOLVE_FAILED_*` | RouteB/direct-omega 后端求解失败 | 检查 direct-omega generated solver、路径曲率、输出 `alpha_max` rate clamp 是否过紧 |
| `WAITING_FOR_ODOM` | 无 `/odom` | 检查底盘/定位栈 |
| `WAITING_FOR_REFERENCE_PATH` | 无参考路径 | 检查 goal 与 path generator |
| `WAITING_FOR_TF_POSE` | TF 不通 | 检查 `map <- base_link` 或配置的 reference frame |

### 9.7 立即停机条件

出现任一情况，立即硬件急停或 Ctrl-C 停 planner，再发 zero：

```text
1. 启动后原地明显转圈。
2. 没有跟上 /scout/global_path_fixed，明显离轨。
3. /spmpc/status = TRACKING_UNSAFE_PROJECTION。
4. /spmpc/status = TRACKING_SPIN_FAIL。
5. /spmpc/status = TERMINAL_SPIN_FAIL。
6. /spmpc/status = ACADOS_NOT_IMPLEMENTED 或 ACADOS_NOT_CREATED。
7. /spmpc/start_lock/mode = UNSAFE_PROJECTION_DISTANCE 持续出现。
8. /cmd_vel 中 |angular.z| > 0.5rad/s 持续约 2s，且 linear.x 很小。
9. 任何人主观认为不安全。
```

停机顺序：

```text
1. 优先硬件 E-stop / 遥控急停。
2. Ctrl-C 停 roslaunch spmpc_local_planner。
3. 连续发几次 /cmd_vel zero。
4. 停 rosbag。
5. 保存 bag、planner log、path JSON，不要删除失败数据。
```

zero 命令：

```bash
for i in 1 2 3 4 5; do
  rostopic pub -1 /cmd_vel geometry_msgs/Twist \
    "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"
  sleep 0.1
done
```

### 9.8 记录口径

operator override bag 的结论只能这样写：

```text
类别：operator override closed-loop smoke
技术 Gate 结论：仍沿用仿真 Gate 的 NO-GO，除非后续 strict fresh-sim/current-pose Gate 和实物复核都通过。
用途：只用于判断实物链路是否复现 startup spin / unsafe projection / solver failure。
```

不要把“现场安全措施做得好、实物没有撞东西”写成 SPMPC 主线技术通过。技术通过仍需至少满足：

```text
1. fresh-sim/current-pose strict Gate 不再触发 TRACKING_UNSAFE_PROJECTION。
2. bag 复核无持续启动转圈、无明显离轨。
3. terminal reached 使用真实欧氏终点距离，不是 projected remaining_s false-PASS。
4. 实物闭环 bag 中无 tracking_safety / terminal_spin_fail 触发。
5. 多次独立样本一致，不是单次偶然。
```

# 20260602 实物端代码拉取与子模块注意事项

本文记录开发机代码同步到实物机的标准流程，适用于当前 `experiment/georef-mpc-hybrid` 分支下的 SPMPC 规控一体主线和外部 baseline 对比实验。

## 1. 当前远端状态

主仓库：

```text
https://github.com/renjunzhang/scout_ws_real.git
branch: experiment/georef-mpc-hybrid
```

当前对比实验用到的子模块中，有两个不是直接使用官方上游：

```text
src/scout_apps/control/navigation
  url: https://github.com/renjunzhang/navigation.git
  branch/commit: noetic-devel / 58976e6

src/scout_apps/control/mpc_local_planner
  url: https://github.com/renjunzhang/scout_ws_real.git
  branch/commit: submodule/mpc_local_planner / 3885d64
```

原因：

```text
navigation 官方 ros-planning/navigation 已归档只读；
mpc_local_planner 官方 rst-tu-dortmund/mpc_local_planner 没有 push 权限；
所以这两个子模块 patch 已推到可访问远端，保证实物机可以 submodule update。
```

## 2. 实物端标准拉取命令

在实物机执行：

```bash
source /opt/ros/noetic/setup.bash
cd /home/geist/scout_ws

git fetch origin
git checkout experiment/georef-mpc-hybrid
git pull --ff-only

git submodule sync --recursive
git submodule update --init --recursive
```

检查子模块指针：

```bash
git submodule status --recursive
```

应该能看到：

```text
3885d64... src/scout_apps/control/mpc_local_planner
58976e6... src/scout_apps/control/navigation
```

如果显示前面有 `-`，表示子模块还没初始化；重新执行：

```bash
git submodule update --init --recursive
```

如果显示前面有 `+`，表示子模块 checkout 的 commit 和主仓库记录不一致；重新执行：

```bash
git submodule sync --recursive
git submodule update --init --recursive
```

### 2.1 `git pull` 不会带来的本地产物

下面这些文件**不会**通过 `git pull` 出现在实物机，必须本地重新生成或安装：

```text
src/scout_apps/control/spmpc_local_planner/generated/acados/spmpc_b0/
src/scout_apps/control/spmpc_local_planner/generated/acados/spmpc_slosh/
```

原因：acados 生成的 C 求解器包含大量 `.c/.h/.o/.so` 构建产物，已按工程规则忽略，不提交到 git。

因此实物机拉完代码后，如果要跑 `continuous_mpcc_acados`，必须执行 §3.1 的 `generate_spmpc_acados.py --model b0/slosh`。
如果只跑 `solver_backend:=primitive`，不需要这些 generated 文件。

### 3.1 acados 连续 MPCC 求解器安装（continuous_mpcc_acados 后端）

> 仅在跑 `solver_backend:=continuous_mpcc_acados`（连续 MPCC 主方法）时需要。
> 只跑 primitive 后端的话**不需要 acados**，跳过本节。
> 以下步骤在 Ubuntu 20.04 (focal) + ROS Noetic + Python 3.8 实测通过（2026-06-03）。

**隔离原则（务必遵守，避免污染现有环境）：**

```text
C 库      -> ~/acados           （独立 .so，运行时 C++ 靠 LD_LIBRARY_PATH，不碰系统）
Python 接口-> ~/acados_venv      （专用 venv，绝不动 ~/.local 的 casadi）
```

实物机的 `ferrari_oracle.py` 等脚本依赖 `~/.local` 的 casadi 3.7.2；
**不要用 `pip install --user acados`**，否则可能改写 casadi 版本、波及 scout 分析脚本。

**步骤：**

```bash
# (1) 系统依赖
sudo apt-get install -y build-essential cmake git python3-venv python3-dev

# (2) 源码 + 子模块
git clone https://github.com/acados/acados.git ~/acados
cd ~/acados && git submodule update --init --recursive

# (3) 编译 C 库（CPU，无显卡；X64_AUTOMATIC 自动选最快 BLASFEO 内核）
mkdir -p build && cd build
cmake -DACADOS_WITH_HPIPM=ON -DACADOS_INSTALL_DIR=$HOME/acados \
      -DBLASFEO_TARGET=X64_AUTOMATIC ..
make install -j$(nproc)
# 产物校验: ls ~/acados/lib/libacados.so  ~/acados/lib/libhpipm.so

# (4) 环境变量（写入 ~/.bashrc 并 source）
echo 'export ACADOS_SOURCE_DIR=$HOME/acados'                    >> ~/.bashrc
echo 'export LD_LIBRARY_PATH=$HOME/acados/lib:$LD_LIBRARY_PATH' >> ~/.bashrc
source ~/.bashrc

# (5) 隔离 venv 装 Python 接口（用源码自带版本，匹配 C 库；勿用 PyPI 的 pip install acados）
python3 -m venv ~/acados_venv
source ~/acados_venv/bin/activate
pip install --upgrade pip
pip install -e ~/acados/interfaces/acados_template pyyaml
deactivate
```

**focal 专属坑 —— t_renderer 模板渲染器（必踩）：**

acados 首次 codegen 需要 `t_renderer`。官方预编译二进制针对 GLIBC≥2.32，
**focal 只有 GLIBC 2.31，直接用会报 `version GLIBC_2.32 not found`**。
必须从子模块源码自编：

```bash
# 子模块自带 tera_renderer 源码，但依赖 pest≥2.8.6，要求 rustc≥1.83；
# apt 的 cargo(1.75) 太旧，用 rustup 装最新 stable（装到 ~/.cargo，用户级隔离）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y --profile minimal
source ~/.cargo/env

cd ~/acados/interfaces/acados_template/tera_renderer
cargo build --release
cp target/release/t_renderer ~/acados/bin/t_renderer   # 覆盖不兼容的预编译版
```

**(6) 生成求解器并验证：**

```bash
export ACADOS_SOURCE_DIR=$HOME/acados
export LD_LIBRARY_PATH=$HOME/acados/lib:$LD_LIBRARY_PATH
source ~/acados_venv/bin/activate
cd ~/scout_ws/src/scout_apps/control/spmpc_local_planner/scripts/acados

python generate_spmpc_acados.py --model b0      # -> generated/acados/spmpc_b0/libacados_ocp_solver_spmpc_b0.so
python generate_spmpc_acados.py --model slosh   # -> generated/acados/spmpc_slosh/...
deactivate
```

看到 `[ok] acados 求解器 ... 已生成` 即成功。
（不装 acados 时可 `python3 generate_spmpc_acados.py --model b0 --check` 仅校验 CasADi 模型。）

生成后再回到工作区重编 `spmpc_local_planner`，让 CMake 把 generated solver 链接进去：

```bash
deactivate 2>/dev/null || true
source /opt/ros/noetic/setup.bash
source ~/.bashrc
cd ~/scout_ws
catkin_make --pkg spmpc_local_planner --force-cmake
source ~/scout_ws/devel/setup.bash
```

如果跳过这一步，节点可能仍按 stub 编译，运行时 `/spmpc/status` 会报 `ACADOS_NOT_IMPLEMENTED`。

**隔离验证（确认没污染）：**

```bash
python3 -c "import casadi; print(casadi.__file__)"          # 应仍是 ~/.local 的 3.7.2
python3 -c "import acados_template" 2>&1 | grep -q "No module" && echo "系统未泄漏 acados_template(正确)"
```

**版本备忘（实测组合）：** acados v0.5.4 / acados_template 0.5.1 / casadi 3.7.2 /
rustc 1.96(rustup) / t_renderer 自编 / GLIBC 2.31。

### 3.3 RGB 在线识别与现场前端

RGB 在线识别不是控制闭环的必要输入，但实物实验推荐开启，便于现场检查液面是否被正确识别。它与相机驱动、控制器完全隔离：

```text
online_liquid_height_node.py  订阅 /camera/color/image_raw, 发布 /liquid/height、/liquid/height_lcr、/liquid/debug_image
liquid_experiment_monitor.py  纯订阅前端, 只显示 RGB overlay、液面曲线、SPMPC 状态, 不发控制命令
```

依赖：

```bash
sudo apt-get install -y python3-matplotlib python3-opencv ros-noetic-cv-bridge
catkin_make --pkg realsense_liquid_measurement
source ~/scout_ws/devel/setup.bash
```

使用方式（传感器栈和 RealSense 已启动后）：

```bash
roslaunch realsense_liquid_measurement online_liquid_height.launch \
  calibration:=/home/geist/slosh_bags/real/<DATE>_calib/red_3ruler.yaml \
  image_topic:=/camera/color/image_raw \
  process_every:=1 \
  publish_debug:=true

roslaunch realsense_liquid_measurement liquid_monitor.launch
```

注意：

```text
1. `liquid_monitor.launch` 需要图形桌面/DISPLAY；纯 SSH 无图形环境时不要开它。
2. 只需要录包或离线分析时，可以不开前端，只开 online_liquid_height 或直接录 /camera/color/image_raw。
3. 如果没有 /liquid/debug_image，检查 online launch 是否设置了 publish_debug:=true。
```

## 5. 常见问题

### 5.1 git pull 后子模块仍然指向官方上游

执行：

```bash
git submodule sync --recursive
git submodule update --init --recursive
```

然后检查：

```bash
git config -f .gitmodules --get-regexp '^submodule\..*\.url'
```

应包含：

```text
https://github.com/renjunzhang/navigation.git
https://github.com/renjunzhang/scout_ws_real.git
```

### 5.2 mpc_local_planner 找不到插件

通常是没有 source isolated install：

```bash
source /home/geist/scout_ws/install_isolated_mpc/setup.bash
source /home/geist/scout_ws/devel/setup.bash
```

重新检查：

```bash
rospack find mpc_local_planner
rospack plugins --attrib=plugin nav_core | grep mpc_local_planner
```

### 5.3 实物机只跑 SPMPC，不跑外部 baseline

可以暂时不构建 isolated `mpc_local_planner`。只需要：

```bash
catkin_make --pkg spmpc_local_planner spmpc_experiments
source /home/geist/scout_ws/devel/setup.bash
```

### 5.4 `/spmpc/status = ACADOS_NOT_IMPLEMENTED`

含义：当前 `spmpc_local_planner` 编译时没有找到 generated acados solver，使用了占位 stub。

处理：

```bash
source ~/.bashrc
source ~/acados_venv/bin/activate
cd ~/scout_ws/src/scout_apps/control/spmpc_local_planner/scripts/acados
python generate_spmpc_acados.py --model b0
python generate_spmpc_acados.py --model slosh
deactivate

cd ~/scout_ws
catkin_make --pkg spmpc_local_planner --force-cmake
source ~/scout_ws/devel/setup.bash
```

### 5.5 `/spmpc/status = ACADOS_NOT_CREATED`

含义：generated solver 已参与编译，但运行时创建失败。常见原因是 `.so` 版本、环境变量或旧 generated 目录不匹配。

处理顺序：

```bash
source ~/.bashrc
echo "$ACADOS_SOURCE_DIR"
echo "$LD_LIBRARY_PATH" | grep acados
ls ~/acados/lib/libacados.so

# 重新生成两套 solver，再强制重编
source ~/acados_venv/bin/activate
cd ~/scout_ws/src/scout_apps/control/spmpc_local_planner/scripts/acados
python generate_spmpc_acados.py --model b0
python generate_spmpc_acados.py --model slosh
deactivate

cd ~/scout_ws
catkin_make --pkg spmpc_local_planner --force-cmake
```

### 5.6 RGB 在线节点找不到脚本或没有 `/liquid/*`

先确认包已构建并 source：

```bash
catkin_make --pkg realsense_liquid_measurement
source ~/scout_ws/devel/setup.bash
rospack find realsense_liquid_measurement
roslaunch --nodes realsense_liquid_measurement online_liquid_height.launch
```

如果有 `/liquid/height` 但没有 `/liquid/debug_image`，启动时加：

```bash
publish_debug:=true
```

### 5.7 工作区有本地修改导致 pull 失败

先查看：

```bash
git status --short
```

如果只是实物端临时日志或无关文件，不要直接 `git reset --hard`。先确认文件是否需要保留，再决定移动备份或手动处理。

### 5.8 实物端路径 JSON 和开发机不完全一致

当前实物连续 MPCC SOP 不是严格复用同一个 JSON 路径文件。实物上每次按同一地面起点、同一目标点、同一 `P2_s_curve` 模板参数，从当前车位姿生成模板路径。

这不是代码没拉全，也不是启动错误。原因是实物回位存在厘米级误差，强行 replay 同一个 JSON 路径反而会引入起点校验失败和不公平初始横向误差。

公平性口径写在 `docs/重要文档/20260603_SPMPC连续MPCC实物对比实验SOP.md`：

```text
同一地面起点标记 + 同一目标点 + 同一 P2_s_curve 模板参数 + 同一相机/HSV/标尺标定。
```

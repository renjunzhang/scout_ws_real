# 20260713 多算法编译隔离与 Overlay 使用注意事项

> 适用工作区：Scout 实物工控机 `/home/geist/scout_ws`
>
> 涉及算法：SPMPC、TEB、`mpc_local_planner`、LT-DWA、DWA 等 ROS1 控制/规划包
>
> 目的：避免不同构建工具、CMake whitelist 和运行时 overlay 造成“编译了错误的包”或
> “运行时加载了另一份插件”。

## 0. 结论

这些算法的源码和构建产物不会必然互相覆盖，但当前工作区并不是完全独立的四套环境。
需要同时管理三个边界：

```text
源码依赖：mpc_local_planner 直接依赖 control_box_rst 和 teb_local_planner；
构建缓存：SPMPC、主 TEB、LT-DWA wrapper 共用主 build/ 和 devel/；
运行环境：source install_isolated_mpc 后，MPC overlay 中的 TEB 会覆盖主 devel 中的 TEB。
```

固定原则：

```text
SPMPC / 主 TEB / DWA / LT-DWA wrapper：使用主 build/、devel/；
mpc_local_planner：只使用 build_isolated_mpc/devel_isolated_mpc/install_isolated_mpc；
TEB 正式实验终端：不要 source install_isolated_mpc；
MPC 终端：最后 source install_isolated_mpc；
每次主工作区 catkin_make 都显式给出 whitelist，不依赖上一次 CMake 缓存；
不要同时启动两个写入同一 build/ 或 devel/ 的编译进程。
```

## 1. 当前实物端构建拓扑

### 1.1 主 catkin 工作区

主工作区由 `catkin_make` 管理：

```text
/home/geist/scout_ws/build
/home/geist/scout_ws/devel
```

当前已存在的代表性产物：

```text
devel/lib/libspmpc_local_planner.so
devel/lib/libteb_local_planner.so
devel/lib/lt_dwa_official_wrapper/lt_dwa_worker
devel/lib/lt_dwa_official_wrapper/lt_dwa_scout_bridge
```

SPMPC、主工作区 TEB、DWA、LT-DWA wrapper 及其 Scout 侧依赖共享这组构建目录。
不同包通常不会互相覆盖文件，但它们共享顶层 `build/CMakeCache.txt`，因此 whitelist 和
CMake 开关会延续到下一次主工作区编译。

截至 2026-07-13 检查时，主缓存包含：

```text
CATKIN_WHITELIST_PACKAGES=
  slosh_models;
  spmpc_local_planner;
  spmpc_experiments;
  baseline_local_planner_runner;
  scout_profile_baselines

LT_DWA_WRAPPER_ENABLE_OFFICIAL_CORE=ON
CMAKE_BUILD_TYPE=Release
```

因此直接运行不带参数的 `catkin_make`，不能理解为“自动全量重编所有算法”；它可能继续
沿用上一次 whitelist。

### 1.2 MPC isolated 工作区

`mpc_local_planner` 由 `catkin_make_isolated` 管理：

```text
/home/geist/scout_ws/build_isolated_mpc
/home/geist/scout_ws/devel_isolated_mpc
/home/geist/scout_ws/install_isolated_mpc
```

2026-07-13 实物端已经完成 isolated 构建，代表性产物为：

```text
install_isolated_mpc/lib/libmpc_local_planner.so
install_isolated_mpc/lib/libmpc_local_planner_utils.so
install_isolated_mpc/lib/libmpc_local_planner_optimal_control.so
install_isolated_mpc/lib/libteb_local_planner.so
```

MPC 构建没有覆盖主 `devel/`，但它确实又编译了一份 TEB。原因是
`mpc_local_planner/package.xml` 和 CMake 配置把 `teb_local_planner` 声明为直接依赖。

### 1.3 各算法之间的实际关系

| 算法 | 构建位置 | 是否会连带其他算法 | 主要风险 |
|---|---|---|---|
| SPMPC | 主 `build/`、`devel/` | 会构建 `slosh_models` 等直接依赖 | whitelist 缓存导致漏编包 |
| TEB | 主 `devel/`；MPC overlay 中还有一份 | MPC isolated 构建会连带 TEB | source 顺序决定加载哪一份 |
| `mpc_local_planner` | `*_isolated_mpc` | `control_box_rst`、MBF、消息包、TEB | 不能混入普通全量 `catkin_make` |
| LT-DWA wrapper | 主 `build/`、`devel/` | vendor deps、worker、bridge | whitelist 和 official-core 开关写入主缓存 |
| DWA | 主 `build/`、`devel/` | navigation 相关依赖 | 与其他主包共享构建缓存 |

## 2. 为什么普通全量 `catkin_make` 可能失败

`control_box_rst` 的 package build type 是：

```text
cmake
```

它不是普通 catkin 包。初始化 `control_box_rst` 和 `mpc_local_planner` 子模块后，如果清空
whitelist 并尝试让普通 `catkin_make` 处理整个 `src/`，可能遇到：

```text
This workspace contains non-catkin packages in it,
and catkin cannot build a non-homogeneous workspace without isolation.
```

处理原则：

```text
不要删除现有主 build/、devel/ 来“修复”MPC；
主工作区继续使用显式 whitelist；
MPC 与 control_box_rst 继续使用独立 catkin_make_isolated；
不要执行无选择的全量 git submodule update --init --recursive。
```

## 3. 推荐的编译边界

### 3.1 SPMPC 主线

SPMPC 使用主工作区。每次编译显式给出本轮包集合，例如当前实物端主线集合：

```bash
source /opt/ros/noetic/setup.bash
cd /home/geist/scout_ws

catkin_make \
  -DCATKIN_WHITELIST_PACKAGES="slosh_models;spmpc_local_planner;spmpc_experiments;baseline_local_planner_runner;scout_profile_baselines" \
  -DCMAKE_BUILD_TYPE=Release
```

不要假定此前运行过 LT-DWA 或 TEB 编译后，再执行无参数 `catkin_make` 就会自动恢复到
SPMPC 包集合。

### 3.2 主工作区 TEB / DWA

TEB 和 DWA 仍放在主 `devel/`。编译时应显式切换 whitelist 到本轮真正需要的包，并把
runner、实验入口等同轮需要的包一起列入。

完成后必须检查目标库时间和路径，不能只看 `rospack find`：

```bash
test -r /home/geist/scout_ws/devel/lib/libteb_local_planner.so
rospack find teb_local_planner
rospack plugins --attrib=plugin nav_core | grep teb_local_planner
```

`rospack find` 能找到源码目录不等于共享库已经成功重编。

### 3.3 MPC local planner

MPC 只使用已经验证过的 isolated 命令：

```bash
source /opt/ros/noetic/setup.bash
source /home/geist/scout_ws/devel/setup.bash
cd /home/geist/scout_ws

catkin_make_isolated --install --force-cmake \
  --only-pkg-with-deps mpc_local_planner \
  --install-space install_isolated_mpc \
  --devel devel_isolated_mpc \
  --build build_isolated_mpc
```

该命令会处理：

```text
control_box_rst；
MBF 相关依赖；
mpc_local_planner_msgs；
teb_local_planner；
mpc_local_planner。
```

这是依赖闭包的正常结果，不代表 TEB 主工作区产物被覆盖。

### 3.4 LT-DWA official wrapper

LT-DWA official 源码保持在 `third_party/LT_DWA`，不能复制或链接进 catkin `src/`，因为
上游含 `local_planner`、`navigation` 等通用包名，可能与当前工作区发生名称冲突。

wrapper 使用显式 whitelist：

```bash
source /opt/ros/noetic/setup.bash
cd /home/geist/scout_ws

catkin_make \
  -DCATKIN_WHITELIST_PACKAGES="obstacle_msgs;local_map_generation;lt_dwa_official_wrapper" \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DLT_DWA_WRAPPER_ENABLE_OFFICIAL_CORE=ON
```

执行该命令后，主 `build/CMakeCache.txt` 会保留 LT-DWA whitelist。下一次编译 SPMPC 或
TEB 时必须再次显式传入对应 whitelist。

## 4. 运行时 source 隔离

### 4.1 SPMPC、主 TEB 和 DWA

新终端只 source ROS 和主工作区：

```bash
source /opt/ros/noetic/setup.bash
source /home/geist/scout_ws/devel/setup.bash
```

TEB 正式实验终端不要继续 source：

```text
/home/geist/scout_ws/install_isolated_mpc/setup.bash
```

否则 `rospack find teb_local_planner` 会从主源码路径切换为：

```text
/home/geist/scout_ws/install_isolated_mpc/share/teb_local_planner
```

实际加载的 `libteb_local_planner.so` 也会优先来自 MPC overlay。

### 4.2 MPC local planner

MPC 终端按以下顺序 source，isolated overlay 最后：

```bash
source /opt/ros/noetic/setup.bash
source /home/geist/scout_ws/devel/setup.bash
source /home/geist/scout_ws/install_isolated_mpc/setup.bash
```

检查：

```bash
rospack find baseline_local_planner_runner
rospack find spmpc_experiments
rospack find mpc_local_planner
rospack plugins --attrib=plugin nav_core | grep mpc_local_planner

MPC_LIB=/home/geist/scout_ws/install_isolated_mpc/lib/libmpc_local_planner.so
test -r "$MPC_LIB"
ldd "$MPC_LIB" | grep 'not found' || true
```

### 4.3 LT-DWA

LT-DWA 使用主 `devel/`，并额外把 official runtime 配置包放在 ROS 包搜索路径最前面：

```bash
source /opt/ros/noetic/setup.bash
source /home/geist/scout_ws/devel/setup.bash

export SCOUT_WS_ROOT=/home/geist/scout_ws
export ROS_PACKAGE_PATH=$SCOUT_WS_ROOT/tools/lt_dwa/local_planner_runtime:$ROS_PACKAGE_PATH
```

不要把这个 `ROS_PACKAGE_PATH` 修改长期写入所有算法共用的终端环境；LT-DWA 测试使用独立
新终端。

## 5. 什么时候必须重编

| 变更内容 | 至少需要重编 |
|---|---|
| `spmpc_local_planner`、`slosh_models` 源码 | 主 SPMPC whitelist |
| 主 `teb_local_planner` 源码或配置生成文件 | 主 TEB 构建 |
| `control_box_rst` 或 MPC 子模块 commit | 完整 MPC isolated 构建 |
| MPC 依赖的 `teb_local_planner` 源码 | MPC isolated 构建；若还跑主 TEB，也重编主 TEB |
| `baseline_local_planner_runner` | 主工作区 runner；不需要重编 MPC 插件本体 |
| LT-DWA wrapper/vendor deps | LT-DWA whitelist 构建 |
| 仅 YAML/launch 参数 | 通常不需要 C++ 重编，但要重新 source/launch 并保存参数证据 |

如果公共消息定义、ABI、编译器选项或系统库发生变化，不要只重编最末端插件，应从对应
依赖链重新构建。

## 6. 编译和运行前检查清单

### 6.1 编译前

```bash
cd /home/geist/scout_ws
git status --short --branch
ps -ef | grep -E '[c]atkin_make|[m]ake|[n]inja'
grep -E '^(CATKIN_WHITELIST_PACKAGES|LT_DWA_WRAPPER_ENABLE_OFFICIAL_CORE):' \
  build/CMakeCache.txt 2>/dev/null || true
```

确认：

```text
知道本轮要写入主 build/devel 还是 *_isolated_mpc；
没有另一个编译进程写入同一目录；
明确本轮 whitelist；
没有准备删除现场已有 build/devel；
现场未提交源码已经记录并保留。
```

### 6.2 运行前

```bash
echo "$CMAKE_PREFIX_PATH" | tr ':' '\n' | head -n 10
echo "$ROS_PACKAGE_PATH" | tr ':' '\n' | head -n 10
rospack find <目标包>
```

插件算法还必须检查：

```bash
rospack plugins --attrib=plugin nav_core | grep '<目标插件包>'
find /home/geist/scout_ws/devel /home/geist/scout_ws/install_isolated_mpc \
  -name 'lib<目标插件>.so' -print 2>/dev/null
```

一句话判断：

```text
rospack 能看到源码，只说明包路径可见；
共享库存在、ldd 完整、plugin XML 可见，才说明插件具备加载条件；
最终加载哪一份库，由当前终端的 overlay 顺序决定。
```

## RGB 液面分析（去起终点段）

指标口径按 `docs/重要文档/红色液体视觉验证固定流程.md` §5：

```text
h_max_lcr_raw(t) = max(h_left, h_center, h_right)
h_max_lcr_smooth(t) = rolling_median(h_max_lcr_raw, window=5)
H_vis(t) = abs(h_max_lcr_smooth(t))
```

`red_liquid_infer_from_bag.py` 的 `h_mm_smooth_corr` 是 median-LCR 质检链路；主表使用上面的 max-LCR smooth 后处理结果。RGB 推断命令：

```bash

  --calibration <RUN_SPECIFIC_CALIB.yaml> \
  --out-dir <OUT_DIR> \
  --topic /camera/color/image_raw \
```

### C. SPMPC slosh model peak 对比

SPMPC bags 中有两类模型侧输出：

- `/spmpc/slosh_height`：当前模型液面高度，已按 `diagnostics_publisher.cpp` 转成 mm 发布。
- `/spmpc/slosh_horizon_summary`：预测 horizon summary，字段为 `h_peak_pred_mm,h_p95_pred_mm,eta_x_peak,eta_y_peak,eta_dot_norm_peak,peak_k`。

输出归档：

```text
/data/a/slosh_bags/real/20260611_spmpc_mainline_smoke/analysis_exclude_start_end_20260612/spmpc_slosh_model_peak_metrics.csv
/data/a/slosh_bags/real/20260611_spmpc_mainline_smoke/analysis_exclude_start_end_20260612/spmpc_slosh_model_peak_metrics.json
```

统一 `progress 10%→90%` 窗口下，模型侧结果如下：

| variant | model topic / metric | peak | p95 | rms | 判读 |
|---|---|---:|---:|---:|---|
| **B0** | `/spmpc/slosh_height` current | 1.91 mm | **1.10 mm** | 0.57 mm | 当前模型高度最低 |
| **B_slosh** | `/spmpc/slosh_height` current | 4.54 mm | **2.85 mm** | 1.54 mm | 最高 |
| **B_ours** | `/spmpc/slosh_height` current | 2.82 mm | **1.60 mm** | 0.72 mm | 明显低于 B_slosh |
| **B0** | horizon `h_peak_pred_mm` | 0.00 mm | 0.00 mm | 0.00 mm | B0 该字段全程为 0，不用于解释真实/当前液面 |
| **B_slosh** | horizon `h_peak_pred_mm` | 4.54 mm | **2.95 mm** | 1.71 mm | 预测峰值最高 |
| **B_ours** | horizon `h_peak_pred_mm` | 2.82 mm | **1.83 mm** | 0.92 mm | 预测峰值低于 B_slosh |

结论：

```text
1. 若看 /spmpc/slosh_height 当前模型高度，排序与 RGB 真值一致：B0 最低，B_slosh 最高，B_ours 明显低于 B_slosh。
2. 若看 horizon h_peak_pred_mm，B_slosh > B_ours 的结论仍一致；但 B0 的 horizon 字段全程为 0，与 /spmpc/slosh_height 不一致，说明该字段不能用于 B0 物理液面比较。
3. progress 10%→90% 下，B_ours 相比 B_slosh：RGB max-LCR p95 下降约 55%，/spmpc/slosh_height p95 下降约 44%，horizon h_peak_pred p95 下降约 38%。方向一致，但幅值不完全相同。
4. TEB/DWA 本批没有可比的 SPMPC slosh model topic；本批也没有有效外部 /slosh/height，因此 slosh model peak 对比仅限 SPMPC 三组内部，不能拿 /spmpc/slosh_height 与 TEB RGB 直接混比。
```

因此，本批实物数据中，“smooth priority 让 B_ours 相比 B_slosh 降低液面”的结论在 RGB 真值和 SPMPC 模型侧输出上方向一致；但论文主结论仍以 RGB 离线真值为准，模型侧只作为机制解释和辅证。

## DWA 未通过（待后续排查，公平参数已回齐）

症状：`DWA planner failed to produce path` 持续刷屏。源码语义上，这通常表示 DWA 已有 robot pose 和 transformed local plan，但 `findBestPath()` 中所有采样候选轨迹被代价函数/碰撞检查淘汰，不等价于“没有收到路径”。

### 公平 common-limit 参数

`config/dwa_planner_real.yaml` 已按 strict sim/common-limit 回齐普通运动学限制：

```yaml
DWAPlannerROS:
  max_vel_x: 0.8
  max_vel_theta: 1.2
  acc_lim_x: 0.6
  acc_lim_theta: 1.2
```

这四项对应 SPMPC / strict 仿真 common-limit 的 `0.8 / 1.2 / 0.6 / 1.2`。此前实车草案中的 `acc_lim_x=0.8`、`acc_lim_theta=2.0` 属于更激进 tuning，不能混入公平对比主结果。

### 实车启动时必须显式覆盖

`nav_core_runner.launch` 默认插件是 TEB，默认 costmap 是 sim 版；DWA 实车排障时必须显式传入 real config：

```bash
roslaunch baseline_local_planner_runner nav_core_runner.launch \
  plugin_type:=dwa_local_planner/DWAPlannerROS \
  plugin_name:=DWAPlannerROS \
  reference_path_topic:=/scout/global_path_fixed \
  cmd_vel_topic:=/cmd_vel \
  base_frame:=base_link \
  plan_target_frame:=map \
  costmap_config:=$(rospack find baseline_local_planner_runner)/config/local_costmap_real.yaml \
  planner_config:=$(rospack find baseline_local_planner_runner)/config/dwa_planner_real.yaml \
  status_topic:=/baseline/dwa/status \
  global_plan_topic:=/baseline/dwa/global_plan
```

### 排障方向（不能直接算公平结果）

- 先确认 `planner_config`、`costmap_config`、`base_frame=base_link`、`plugin_name=DWAPlannerROS` 都已实际加载。
- 打开 `publish_cost_grid_pc: true` 或 RViz 观察 local costmap，判断是否激光/膨胀层导致所有候选轨迹碰撞。
- 若仍失败，可单独开 tuned-diagnostic 改 `path_distance_bias / goal_distance_bias / occdist_scale / sim_time / vx_samples / vtheta_samples / prune_plan`，但这些属于 DWA 工程排障，不进入 common-limit 公平主表。
- `map`/`odom` 口径切换、`base_link`/`base_footprint` 切换也只作为诊断变量记录，不能与 common-limit 主结果混表。

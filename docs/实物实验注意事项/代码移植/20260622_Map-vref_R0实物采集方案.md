# 20260622 Map-vref / 地形条件晃液经验地图 R0 实物采集方案

这份文档记录 **R0 实物探索采集** 的现场执行方案。它承接仿真 S0/S1/S2 smoke：

```text
S0：profile CSV -> v_ref_current -> SPMPC -> cmd_vel/odom 软件链路通过
S1：PRE/EVENT/POST profile window 与 event metrics 链路通过
S2：/slosh/height 评价侧记录与 slosh_proxy metrics 链路通过
```

但 R0 不是冻结盲测，也不是论文正式主结果。R0 的目的只是采集真实 RGB/IMU/odom/cmd/path 数据，确认真实液面热点是否存在、是否重复、是否能离线构图。

2026-06-28 建议顺序：


## 0.1 阶段边界

当前允许进入：

```text
R0：实物探索采集 / 数据链路验证
```

当前还不进入：

```text
R1：离线构图、校验、冻结 profile
R2：冻结 profile blind test / 论文正式对比
```

R0 的成功标准不是“Map-vref 有效果”，而是：

```text
1. 机器人安全到点，不撞墙、不洒液、不失控。
2. bag 能回放。
3. RGB 能离线标注 max-LCR。
4. /odom、/tf、/cmd_vel、fixed path/progress 能和 RGB 对齐。
5. 同一路线重复采集中，真实晃液热点有可检查的重复性。
```

## 1. 关键原则

### 1.1 R0 不使用测试数据反向调控制

R0 可以记录：

```text
RGB video / camera_info
/odom
/tf
/cmd_vel
/scout/global_path_fixed
/spmpc/status
/spmpc/debug/progress_s
/spmpc/debug/v_ref_current
/spmpc/debug/map_vref_status
/spmpc/debug/delay_phase      # P0/P1-shadow 诊断，不改变控制
/spmpc/debug/execution_state  # raw/predicted execution state 诊断
/spmpc/debug/odom_timing
/imu 或 /container_imu
/slosh/height                 # 只作模型辅助评价
/spmpc/slosh_height           # 只作 SPMPC 内部诊断
/liquid/height                # 在线 RGB 调试，可录但不是冻结真值
```

R0 不允许：

```text
1. 用本轮 RGB 在线改 v_ref。
2. 用本轮 RGB 在线改 profile。
3. 用本轮 RGB 改 SPMPC 权重、速度上限、command gate 或路径。
4. 把 /slosh/height 当实物液面真值。
5. 把 /liquid/height 在线结果当正式论文真值。
```

正式实物液面真值口径：

```text
RGB bag/video -> offline max-LCR 后处理
```

### 1.2 R0 第一批建议不启用真实 Map-vref

为了避免数据采集阶段自反馈，第一批 R0 建议使用稳定基线控制：

```text
planner_variant=B_ours
map_vref/profile_enable=false
map_vref/runtime_v_ref_enable=false
```

P0/P1 延迟相位诊断可以打开，因为 `delay_phase_mode=shadow` 只发布诊断，不替换 `SolverInput`，也不做闭环补偿：

```text
delay_phase_mode=shadow
delay_phase_linear_delay_sec=0.15
delay_phase_angular_delay_sec=0.22
closed_loop_delay_compensation=false   # 当前实现中固定为 false
```

可选第二批再跑均匀慢速对照：

```text
B_ours_uniform_slow
```

但不要在 R0 中用同批 RGB 生成 profile 后马上闭环验证；这会污染后续冻结盲测。R0 的 profile 只能进入后续 R1 离线构图 / 冻结流程，不能当天反向调参后再把同批数据当盲测。

## 2. R0 最小采集矩阵

第一天只做小批次，优先保证数据质量。推荐把“录包链路”和“自动控制效果”分开验收。

| 批次 | 路线 | 控制 | repeats | 目的 | 是否进入正式统计 |
|---|---|---|---:|---|---|
| R0-Pre | 原地 / 手推短段 | 不启动 SPMPC 自动控制 | 1 | 验证 RGB、TF、odom、/cmd_vel publisher、录包脚本、metadata | 否 |
| R0-A | 空旷安全固定路线 | `B_ours` 保守速度，Map-vref off，delay_phase shadow on | 3 | 验证 RGB/odom/cmd/path/progress 同步，检查真实热点是否重复 | R0 数据集 |
| R0-QC | 离线 quick check | 不新增 run | 1 | 回放 bag，检查 RGB 可见、progress_s 有效、cmd/odom 可对齐 | gate |
| R0-B | 同一路线 | `B_ours_uniform_slow` 可选 | 3 | 判断“全程慢速”对真实液面是否明显改变 | R0 数据集 |
| R0-C | 门槛/接缝/地砖缝路线 | `B_ours` 保守速度，Map-vref off，delay_phase shadow on | 3 | 探索地形事件区是否产生稳定热点 | R0 数据集 |

如果 R0-A 的 RGB 看不清、时间戳不同步、progress_s 缺失、cmd/odom 延迟无法分析、或机器人不稳定，不进入 R0-B/R0-C，也不进入正式内部消融矩阵。

## 3. 现场安全顺序

必须按顺序执行：

```text
1. 空车 / 无液体：检查底盘、遥控、急停、/cmd_vel 无旧 publisher。
2. 有容器少量液体：低速手动或低速自动，确认不洒、不晃出、不遮挡相机。
3. 固定相机：确认 RGB 能看清红色液面、三标尺或容器边界。
4. 在线监控只作现场观察：确认 /liquid/height 或 debug_image 工作。
5. 短路线录包 smoke：只验证 bag 和同步，不追求实验效果。
6. R0-A N=3：固定路线、固定 payload、固定相机参数。
7. 离线检查：确认 RGB max-LCR 能标注后，再扩展 R0-B/R0-C。
```

现场硬停止条件：

```text
1. 车体明显偏离路线或靠近障碍。
2. TF / odom / map / scan 异常。
3. /cmd_vel 有多个 planner publisher。
4. 液体明显要溢出。
5. 相机画面丢失或液面不可见。
6. 人工观察认为不安全。
```

## 12. R0 到 R1 的进入条件

只有满足以下条件，才进入 R1 构图/冻结：

```text
1. 至少一条路线 N=3 bag 全部可回放。
2. RGB offline max-LCR 全部可提取，缺失段可解释。
3. /odom、/cmd_vel、/tf、path/progress 与 RGB 可对齐。
4. delay_phase / cmd->odom 延迟诊断可解释，没有明显时间戳错位。
5. 热点区间在重复 run 中大致稳定。
6. metadata 足够描述 payload、相机、路径、地形事件。
```

R1 的输出才是：

```text
frozen risk/profile CSV
profile hash
path hash
map_id / path_id / payload_id
freeze note
```

R2 才能用 frozen profile 做 blind test。R0 数据本身不能同时当构图集又当盲测集。

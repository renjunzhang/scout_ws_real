## 1. 结论

本次 run 应固化为：

```text
RouteB direct-omega legacy backend + B0 的成功到点基线，
同时提供 B0 在起步入弯高曲率段激起较高 slosh proxy 的基线。
```

不要把文件名中的 `alpha8` 解读为 alpha-state 主线结论。

原因：本次实际 backend 是 `continuous_mpcc_direct_omega_legacy`，其 OCP 控制量是直接 `omega`，不是 alpha-state 主线的 `alpha = omega_dot`。

```text
RouteB direct-omega:
  u = [a, omega, v_s]

  u = [a, alpha, v_s]
```

因此，本次 run 不能用于说明 `SPMPC_ALPHA_MAX=8.0` 是否解决 alpha-state creep。这里的 `alpha_max` 最多只影响 direct-omega 后端的出口角速度 rate limiter，不进入 OCP 模型本身；且首帧没有上一周期控制量，`cmd_omega` 可以直接到 `omega_max`。

### 5.2 当前判断

这不是简单 topic 丢包或 height 计算跳变。原因：

```text
slosh_height 与 eta_norm 几乎完全一致。
```

用整条 bag 拟合：

| 检查项 | 值 |
|---|---:|
| fitted scale | `1820.7 mm / eta` |
| R2 | `0.99999` |
| horizon summary max | `0` |

这与代码路径一致：`/spmpc/slosh_height` 是由当前 observer state 计算的瞬时 proxy，核心是 `height_coeff * ||eta||`，向心抛物项很小。

单帧近零基本对应 `eta_norm` 本身接近零，而不是 height topic 单独异常。其时间间隔约 `0.10 s` 量级，和当前一阶模态频率约 `4.97 Hz` 的半周期接近。因此它更像是高频模态状态的瞬时过零，而不是 bag 解析错误。

### 5.3 但它仍不能直接当“真实液面晃动”

虽然这不像数据管线故障，但它说明：

```text
/spmpc/slosh_height 是瞬时 modal proxy，
不是视觉测得的液面 envelope / peak-to-peak 真值。
```

如果论文中要写“真实晃动”或与 RGB 对齐，应至少补做：

```text
1. 下一次打开 slosh monitor，记录 /slosh/eta 和 /slosh/eta_dot；
2. 与 /spmpc/debug/slosh_state 对齐，确认两个 observer 口径是否一致；
3. 对 RGB / liquid height 使用同一时间窗口的 p95 / max / envelope，而不是逐帧瞬时零点；
4. 必要时单独导出 eta_norm 和 height_mm 曲线，标注 modal zero-crossing。
```

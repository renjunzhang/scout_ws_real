# 20260615 RGB 与 slosh model 保真度实物验证实验方案

> 目标：专门录制一批用于验证 **RGB 液面真值** 与 **slosh model proxy** 之间保真度的实物 bag。
>
> 参考启动流程：`docs/实物实验注意事项/对比试验/20260613_SPMPC实物受控对比试验方案.md`
>
> 本文不是新的控制性能大矩阵，也不是 TEB/DWA 外部 planner 对比。第一目标是得到同步可靠、视觉幅值足够、模型 topic 连续的 RGB-vs-model 数据。

---

## 0. 本轮只回答的问题

本轮实物 bag 只回答下面几个保真度问题：

```text
1. /slosh/height 或 /spmpc/slosh_height 与 RGB max-LCR 液面真值是否同相、同趋势？
2. 模型高度是偏保守、偏低估，还是只在趋势上可信？
3. 在有效视觉晃动幅值 >5 mm 时，gamma_model%、RMSE、p95/peak 误差是否稳定？
4. /slosh/* observer 是否仍在 TRACKING -> REACHED 后停摆？如果停摆，gap 从哪里开始？
```

不回答的问题：

```text
1. 不把 /slosh/height 当真实液面。
2. 不用这批数据直接声称 SPMPC 已经实物最优。
3. 不把 output angular limiter 写成 OCP 贡献。
4. 不把仿真第 12/14 页权重结论直接迁移成实物最优权重。
5. 不在本批次混入 TEB/DWA，外部 planner 对比另开方案。
```

## 1. 核心口径

### 1.1 RGB 视觉真值

正式保真度分析以后处理 RGB 图像为准，在线 `/liquid/*` 只用于现场 quick check。

建议同时输出两套视觉序列：

```text
H_vis_max_lcr(t) = |max(h_left, h_center, h_right) - h0|
H_vis_median(t)  = |median(h_left, h_center, h_right) - h0|
```

其中：

```text
h0 = 每个 bag 前 30 帧静止 RGB 图像估计的零点
smooth = rolling median, window=5
```

主结论优先用：

```text
RGB max-LCR
```

备份/和旧保真度文档对齐时再给：

```text
RGB median-LCR
```

### 1.2 模型侧 proxy

至少保留两条模型曲线：

```text
H_model_standalone(t) = |/slosh/height|
H_model_spmpc(t)      = |/spmpc/slosh_height|
```

分析时将模型曲线线性插值到 RGB 时间戳：

```text
H_model_rgb_time(t_rgb) = interp(t_rgb, t_model, H_model)
```

### 1.3 指标

主指标：

```text
gamma_model% = 100 * integral(H_model - H_vis) dt / (integral(H_model) dt + eps)
```

解释：

```text
gamma > 0: 模型偏保守 / 高估
gamma ≈ 0: 模型绝对幅值接近 RGB
gamma < 0: 模型低估真实液面运动
```

辅助指标：

```text
RMSE
corr
model_peak - visual_peak
model_p95  - visual_p95
model_rms  - visual_rms
pair_dt_p95
/slosh/* gap_start_time
```

最低可接受同步质量：

```text
pair_dt_p95 <= 80 ms
```

推荐目标信号强度：

```text
RGB visual peak >= 5 mm
最好 ay_p95 > 0.5 m/s^2
```

如果 visual peak 仍低于 2 mm，本批次只能写“趋势参考”，不适合支撑强保真度结论。

## 2. 安全红线

必须满足：

```text
1. 现场至少一人专门盯车，手边有硬件 E-stop / 遥控急停。
2. 本文命令中的 planner launch 会发布真实 /cmd_vel；没有现场安全确认时不要执行。
3. 先开 recorder，再开 planner；到点后继续录 20-30s 残振段，再停 recorder。
4. 每个 run 前确认 /cmd_vel 没有旧 planner publisher。
5. 不改地图、TF、定位、URDF、雷达、底盘模型来“修”实验结果。
6. 不使用 broad killall / pkill；只 Ctrl-C 当前终端或硬件急停。
7. 失败 bag、异常 log、急停记录都保留，不删除失败数据。
8. 任何人主观认为不安全，立即停。
```

立即停机条件：

```text
1. 明显原地转圈或小 linear.x + 大 angular.z 持续约 2s。
2. 明显离开固定路径或朝障碍物/人运动。
3. /spmpc/status 出现 TRACKING_UNSAFE_PROJECTION / TRACKING_SPIN_FAIL / TERMINAL_SPIN_FAIL。
4. /spmpc/status 出现 ACADOS_NOT_IMPLEMENTED / ACADOS_NOT_CREATED / ACADOS_SOLVE_FAILED_*。
5. /odom、TF、/map、/scan_front 明显异常。
6. /camera/color/image_raw、/liquid/debug_image 中液面 ROI 明显失效。
7. /slosh/height 或 /spmpc/slosh_height 在运动段完全没有数据。
8. 前方有人、障碍、空间不足，或液体容器固定异常。
```

停机顺序：

```text
1. 优先硬件 E-stop / 遥控急停。
2. Ctrl-C 停当前 planner roslaunch。
3. 连续发 /cmd_vel zero。
4. 保持 recorder 再录 5-10s，确认残振/zero，然后 Ctrl-C 停 rosbag。
5. 保存 bag、log、path JSON、现场记录。
```

zero 命令：

```bash
for i in 1 2 3 4 5; do
  rostopic pub -1 /cmd_vel geometry_msgs/Twist \
    "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"
  sleep 0.1
done
```

## 3. 推荐 bag 矩阵

### 3.0 先 probe、再正式录制

本轮按“**先验证能不能跟轨迹，再录正式保真度矩阵**”执行：

```text
F0_static_calib_30s
  -> F_probe_B0_scurve_run01
  -> F_probe_Bslosh_w2_scurve_run01
  -> 若 B0 和 w2 都安全跑通，再进入正式 B0 N=3 + B_slosh_w5 N=3
```

probe 也建议开 `record_spmpc_full_rgb_bag.sh` 录包，但它们默认标记为 **probe/诊断包**，不计入正式 N=3 主表。这样如果 B0 或 `w_slosh=2` 跟不上轨迹，可以直接用 bag 回看 `/cmd_vel`、`/odom`、`/spmpc/status`、`/slosh/height` 与 RGB，而不是只靠现场主观判断。

如果某个 probe 从 20s 静止预录、运动段、到点后残振记录到 quick check 全部满足正式标准，且现场记录明确同意，也可以把它升级为正式 `run01`；更保守的做法是 probe 通过后重新录正式 `run01-run03`。

### 3.1 第 0 阶段：标定与安全 probe

| 顺序 | run name | planner / 动作 | 用途 | 是否进正式 N=3 主表 |
|---:|---|---|---|---|
| 0 | `F0_static_calib_30s` | 不开 planner，静止 30s | 当天 ROI/HSV/h0/相机零点检查 | 否，作为标定/质检 |
| 1 | `F_probe_B0_scurve_run01` | `B0` | 已有实物成功锚点；确认今日路径、定位、底盘、recorder、RGB 和模型 topic 正常 | 默认否，可合格后升级 |
| 2 | `F_probe_Bslosh_w2_scurve_run01` | `B_slosh`, `w_slosh=2` | 低权重 slosh-aware 安全门槛；确认不会明显跟不上轨迹 | 默认否，可合格后升级 |

通过标准：

```text
1. tracking 可控，无明显离轨/转圈/朝障碍物运动。
2. /camera/color/image_raw、/camera/color/camera_info、/cmd_vel、/odom、/slosh/height、/spmpc/slosh_height 都有数据。
3. /spmpc/status 不出现 TRACKING_UNSAFE_PROJECTION / SPIN_FAIL / ACADOS_SOLVE_FAILED_*。
4. 到点或安全停车后仍保留 20-30s 残振记录。
5. RGB peak 最好 >=5mm；若 <2mm，即使跑通也不适合作强保真度主证据。
```

若 `F_probe_B0` 不安全：停止全部 B_slosh，先排查定位、路径、底盘、cmd、RGB/recorder。若 `F_probe_B0` 安全但 `F_probe_Bslosh_w2` 不安全：不进入 `w5/w10`，先降速或降 slosh 权重诊断。

### 3.2 最小正式主批次：7 个 bag

只有 `F_probe_B0` 和 `F_probe_Bslosh_w2` 都通过后，才进入正式录制：

| 顺序 | run name | planner / 动作 | N | 用途 |
|---:|---|---|---:|---|
| 0 | `F0_static_calib_30s` | 不开 planner，静止 30s | 1 | 当天 ROI/HSV/h0/相机零点检查 |
| 1 | `F1_B0_scurve_x5_run01` | `B0` | 1 | 无 slosh cost 的高晃动锚点 |
| 2 | `F1_B0_scurve_x5_run02` | `B0` | 1 | baseline 重复性 |
| 3 | `F1_B0_scurve_x5_run03` | `B0` | 1 | baseline 重复性 |
| 4 | `F2_Bslosh_w5_scurve_x5_run01` | `B_slosh`, `w_slosh=5` | 1 | 标准 B_slosh 模型/视觉对齐 |
| 5 | `F2_Bslosh_w5_scurve_x5_run02` | `B_slosh`, `w_slosh=5` | 1 | 重复性 |
| 6 | `F2_Bslosh_w5_scurve_x5_run03` | `B_slosh`, `w_slosh=5` | 1 | 重复性 |

说明：

```text
B0 用作无 slosh cost 的高晃动锚点。
B_slosh_w5 对应当前 PPT 第 12 页标准 B_slosh 权重。
这批的目的不是证明 w5 实物最优，而是验证同一路径下 RGB 与模型 proxy 的保真度。
正式主表必须先满足 completion/tracking，再比较 RGB 与模型保真度；不能用跟不上轨迹换低液面曲线。
```

### 3.3 完整扩展批次：11 个 bag

在最小主批次通过且现场时间允许时，追加：

| run name | planner / 动作 | N | 用途 |
|---|---|---:|---|
| `F3_Bslosh_w10_scurve_x5_run01` | `B_slosh`, `w_slosh=10` | 1 | 较强 slosh cost 下模型/RGB 是否仍同趋势 |
| `F3_Bslosh_w10_scurve_x5_run02` | `B_slosh`, `w_slosh=10` | 1 | 重复性 |
| `F4_straight_accel_brake_run01` | 直线加速-减速-停，低风险执行 | 1 | 主要激励 `a_x`，补充纵向模型保真度 |
| `F4_straight_accel_brake_run02` | 直线加速-减速-停，低风险执行 | 1 | 重复性 |

`F3` 只在 `B_slosh_w5` 至少 1 包安全且数据完整后追加；`F4` 不建议和主 S 曲线混在同一结论里，它是补充验证 `a_x` 激励的专门 bag。若没有单独的安全 SOP，当天可跳过。

### 3.4 第一包门槛

`F_probe_B0_scurve_run01` 录完后先做 quick check，再决定是否继续：

| 结果 | 决策 |
|---|---|
| `B0` tracking 安全、`RGB peak >= 5 mm` 且 `pair_dt_p95 <= 80 ms` | 进入 `F_probe_Bslosh_w2`；w2 也通过后录正式 B0/B_slosh_w5 N=3 |
| `B0` tracking 安全但 `RGB peak 2-5 mm` | 可以继续 w2 probe，但结论写成中等幅值；建议追加更强但安全激励 |
| `B0` tracking 安全但 `RGB peak < 2 mm` | 暂停正式矩阵，先增强激励或调整方案；否则会重复旧数据“信号太小”的问题 |
| `B0` 跟不上轨迹/离轨/转圈 | 不测 B_slosh，先排查路径、定位、底盘响应、cmd 与 projector |
| `B0` 安全但 `B_slosh_w2` 跟不上轨迹 | 不进入 `w5/w10`；先降速、降权重或检查 slosh-aware 闭环配置 |
| RGB 缺帧、ROI 失效、`/slosh/*` 运动段无数据 | 先修数据链路，不继续录正式 bag |

## 4. 每个 bag 的时间结构

每个 run 固定为：

```text
0-20s: 静止段，用于每包 h0 / RGB 零点 / IMU bias
20s-运动结束: 执行固定路径或指定激励
到点/停车后 20-30s: 残振段，用于检查液面衰减与 /slosh/* observer 是否停摆
```

注意：

```text
recorder 必须早于 planner 启动。
planner 到 REACHED 后不要立刻停 recorder。
如果 /slosh/* 在 TRACKING -> REACHED 后停摆，记录 gap start，并在 fidelity 分析窗口中截断到 gap 前。
```

每个 run 之间：

```text
1. Ctrl-C 停 planner。
2. 发 /cmd_vel zero。
3. recorder 继续录 5-10s 后再停。
4. 把车回到同一起点地面标记。
5. 等液体静稳，建议 60-90s。
6. 确认 /cmd_vel 无旧 publisher。
7. 再开始下一包。
```

## 6. 启动流程

以下命令参考 20260613 实物受控对比 SOP。除 recorder 和检查命令外，planner launch 会发布真实 `/cmd_vel`，必须在现场安全确认后执行。

### 6.1 通用环境变量

```bash
source /opt/ros/noetic/setup.bash
source /home/geist/scout_ws/devel/setup.bash
cd /home/geist/scout_ws

DATE=$(date +%Y%m%d)
OUT_DIR=/home/geist/slosh_bags/real/${DATE}_rgb_model_fidelity
PATH_DIR=/home/geist/fixed_paths/real/${DATE}
CALIB=/home/geist/slosh_bags/real/${DATE}_calib/red_3ruler.yaml
GOAL_TOPIC=/scout/goal
REF_TOPIC=/scout/global_path_fixed
PATH_FILE=${PATH_DIR}/P2_s_curve_rgb_model_fidelity.json

mkdir -p "$OUT_DIR" "$PATH_DIR"
```

### 6.2 启动传感器、定位、底盘链路

按现场已有流程启动 Scout、RealSense、定位/map、RViz。进入闭环前必须检查：

```bash
rostopic echo -n 1 /odom
rostopic echo -n 1 /map
rostopic echo -n 1 /scan_front
rostopic echo -n 1 /camera/color/image_raw
rostopic echo -n 1 /camera/color/camera_info
rostopic hz /odom
rostopic info /cmd_vel
```

`/cmd_vel` 若已有旧 planner publisher，停止，不进入实验。

### 6.3 启动在线 RGB 液面监控

在线监控只用于现场 quick check；正式真值以后处理 RGB 复算为准。

```bash
roslaunch realsense_liquid_measurement online_liquid_monitor_combined.launch \
  calibration:=${CALIB} \
  image_topic:=/camera/color/image_raw \
  process_every:=1 \
  height_bias_mm:=0.0 \
  hue1_low:=0 hue1_high:=11 \
  hue2_low:=173 hue2_high:=179 \
  sat_min:=80 val_min:=162
```

启动 planner 前 quick check：

```bash
rostopic echo -n 1 /liquid/height
rostopic echo -n 1 /liquid/height_lcr
rostopic hz /liquid/height
rostopic echo -n 1 /liquid/debug_image/header
```

现场步骤：

```text
1. 车辆和液体保持静止。
2. 等 online_liquid_height 日志出现 zero locked，或 dashboard 静止曲线接近 0 mm。
3. 如静止偏置明显，先不要开 planner；保持静止后重置在线零点：
   rosservice call /online_liquid_height/reset_zero
4. dashboard 点 START，开始本 run 的现场 session。
5. 开 recorder，再开 planner。
```

### 6.4 启动 standalone slosh monitor

这一步用于保留 `/slosh/height` 作为外部模型 proxy。它不是 RGB 真值。

```bash
roslaunch slosh_models slosh_monitor.launch \
  odom_topic:=/odom \
  cmd_vel_topic:=/cmd_vel \
  subscribe_cmd_vel_debug:=true \
  output_namespace:=/slosh
```

检查：

```bash
rostopic echo -n 1 /slosh/height
rostopic echo -n 1 /slosh/state
rostopic hz /slosh/height
```

若 planner 未启动前 `/slosh/height` 很小或接近 0 是正常的；若运动段完全没有数据，则该 bag 不能作为主保真度数据。

### 6.5 生成并确认 P2 S 曲线固定路径

沿用实物 P2 固定终点：

```text
x   = 7.164488315582275
y   = 9.307367324829102
yaw = 1.0808
```

生成 P2 S 曲线：

```bash
rosrun scout_local_planner template_fixed_path_generator.py \
  --template s_curve \
  --goal-topic "${GOAL_TOPIC}" \
  --output-topic "${REF_TOPIC}" \
  --path-file "${PATH_FILE}" \
  --start-heading current \
  --spacing 0.05 \
  --amplitude-ratio 0.18 \
  --min-amplitude 0.25 \
  --max-amplitude 1.20 \
  --publish-count 0 \
  >"${OUT_DIR}/p2_s_curve_path_generator.log" 2>&1
```

发送同一终点：

```bash
rosrun scout_local_planner send_fixed_goal.py \
  --goal-topic /scout/goal \
  --x 7.164488315582275 \
  --y 9.307367324829102 \
  --yaw 1.0808 \
  --repeat-count 1 \
  --repeat-rate 1
```

确认 path：

```bash
rostopic echo -n 1 /scout/global_path_fixed/header
rostopic echo -n 1 /scout/global_path_fixed/poses
```

人工看 RViz：如果路径穿障碍、太贴边、起点不贴当前车位姿，停止，不启动 planner。

```bash
RUN_LABEL=F0_static_calib_30s

RECORD_SCAN=false \
```

### 7.3 必须录到的 topic

核心 topic 缺一类就不要作为主保真度 bag：


## 9. 每包录完立刻 quick check

### 9.1 topic 完整性

至少确认 bag 中有：

```text
/camera/color/image_raw
/camera/color/camera_info

/spmpc/slosh_height
/odom
/cmd_vel
/tf
/tf_static
```

缺 `/camera/color/image_raw` 或 `/camera/color/camera_info`：该包不能做 RGB 真值。

缺 `/slosh/height` 和 `/spmpc/slosh_height`：该包不能做 RGB-vs-model 保真度。

### 9.2 时间同步

可用已有脚本检查 `/slosh/height` 与 RGB 时间戳：

```bash
python3 src/scout_apps/control/scout_local_planner/scripts/analysis/check_time_sync.py \
  ${OUT_DIR}/F1_B0_scurve_x5_run01.bag \
  --height-topic /slosh/height \
  --image-topic /camera/color/image_raw \
  --tol-ms 80 \
  --csv ${OUT_DIR}/F1_B0_scurve_x5_run01_sync.csv
```

目标：

```text
pair_dt_p95 <= 80 ms
```

如果 p95 明显超过 80-100 ms，优先考虑降低记录负载，例如下一包关闭 depth、确认磁盘写入、必要时 RECORD_SCAN=false。

### 9.3 RGB 幅值

每包录完建议立即导出一次 RGB 液面曲线：

```bash
python3 src/scout_apps/sensors/realsense_liquid_measurement/scripts/export_liquid_variation_from_bags.py \
  ${OUT_DIR}/F1_B0_scurve_x5_run01.bag \
  --source rgb \
  --calibration ${CALIB} \
  --topic /camera/color/image_raw \
  --out-dir ${OUT_DIR}/F1_B0_scurve_x5_run01_liquid_variation \
  --zero-correction-frames 30 \
  --smooth-frames 5 \
  --debug-every 30 \
  --hue1-low 0 --hue1-high 11 \
  --hue2-low 173 --hue2-high 179 \
  --sat-min 80 --val-min 162
```

看：

```text
liquid_variation_summary.csv
liquid_variation_timeseries.csv
liquid_variation_runs.png
```

现场门槛：

```text
visual peak >= 5 mm: 继续主矩阵
visual peak 2-5 mm: 可继续但结论降级
visual peak < 2 mm: 暂停，先增强激励或调整方案
```

### 9.4 observer gap

每包记录：

```text
1. /spmpc/status 中 TRACKING -> REACHED 的时间。
2. /slosh/height 最后一个有效样本时间。
3. /spmpc/slosh_height 最后一个有效样本时间。
4. REACHED 后是否仍有 20-30s RGB 残振段。
```

如果 `/slosh/*` 在 `REACHED` 后停摆，分析窗口截断到 gap 前；不要把 gap 后 RGB 残振和空模型曲线硬对齐。

## 11. 测后分析口径

每个有效 bag 至少输出：

```text
bag_name
variant / w_slosh
valid_rgb: yes/no
valid_model: yes/no
pair_dt_p95_ms
visual_peak_mm
visual_p95_mm
visual_rms_mm
model_peak_mm
model_p95_mm
model_rms_mm
gamma_model_percent
rmse_mm
corr
model_peak - visual_peak
model_p95 - visual_p95
model_rms - visual_rms
observer_gap_start_s
analysis_window_s
```

结论写法边界：

```text
可以写：/slosh/height 与 RGB max-LCR 在主要激励段同趋势，但绝对幅值存在高估/低估。
可以写：在本批 >5mm 视觉晃动包中，gamma_model% 为正/负，说明模型偏保守/偏低估。
可以写：若 REACHED 后 /slosh/* 停摆，保真度窗口截断到 gap start，残振段仅作为 observer 连续性问题记录。

不能写：/slosh/height 是真实液面。
不能写：某个 w_slosh 是实物最终最优。
不能写：在线 /liquid/height 直接等同正式真值；正式真值以后处理 RGB max-LCR 为准。
不能写：output angular limiter 是 OCP 贡献。
```

## 12. 最小可执行计划

如果当天时间紧，只执行“probe 通过后再正式录制”的版本：

```text
0. 启动传感器/定位/RGB/standalone slosh monitor，确认急停人员就位。
1. 录 F0_static_calib_30s。
2. 生成 P2 s_curve，发送固定目标，人工检查 RViz/path/goal。
3. 开 recorder，静止 20s，跑 F_probe_B0_scurve_run01。
4. 到点/停车后继续录 20-30s，停 planner、zero、停 recorder。
5. 立刻检查 B0 是否跟得上轨迹、RGB peak、pair_dt_p95、/slosh gap。
6. B0 不安全或数据不完整：停止，不测 B_slosh，先排查路径/定位/底盘/recorder。
7. B0 安全后，开 recorder，静止 20s，跑 F_probe_Bslosh_w2_scurve_run01。
8. w2 不安全或跟不上轨迹：停止，不跑 w5/w10；先降速、降权重或诊断 slosh-aware 闭环配置。
9. B0 与 w2 都安全后，正式录 F1_B0_scurve_x5_run01-run03。
10. 再正式录 F2_Bslosh_w5_scurve_x5_run01-run03。
11. 若 w5 至少 1 包安全且数据完整，再考虑 F3_Bslosh_w10_run01-run02。
12. 当天不做 TEB/DWA，不做 B_ours/B_smooth，除非另开控制性能 SOP。
```

最小结论句模板：

```text
本批实物保真度验证在同一 P2 s_curve、同一 RGB 标定与同一输出安全层下，同时记录 RGB 原始图像、standalone /slosh/height、SPMPC /spmpc/slosh_height、cmd/odom/IMU。正式真值以后处理 RGB max-LCR 为准，模型曲线插值到 RGB 时间戳计算 gamma/RMSE/corr。若 observer 在 REACHED 后停摆，则保真度窗口截断到 gap start；残振段用于记录 observer 连续性问题。
```

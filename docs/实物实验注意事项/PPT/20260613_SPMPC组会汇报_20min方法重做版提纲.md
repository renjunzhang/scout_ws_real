## 0. 本版核心口径

本版 PPT 收成一条主线：

> 本工作不是单独做 slosh model，也不是单独调 tracking controller，而是把有记忆的液体二阶动力学作为增广状态嵌入 continuous MPCC，使 local planner 在 horizon 内联合优化路径进度、车辆控制和液体晃动风险。

具体口径：

- 旧主线：`src/scout_apps/control/scout_local_planner` 是 **fixed-path tracking MPC 纯控制器层 baseline**，只作为演进来源和 baseline，不再占用多页展开。
- 当前主线：`src/scout_apps/control/spmpc_local_planner` 是 **slosh-aware continuous MPCC 规控一体 local planner**。
- 系统层级：SPMPC 与 TEB/DWA 在 ROS navigation stack 中同属 **local planner 层**；SPMPC 不是 global planner，也不是底盘低层 controller。
- 路径边界：SPMPC 接收 global/fixed reference path，并在局部 horizon 内优化；它不负责生成任意全局路径，也不保证任意给定路径都可跟踪，只能处理满足曲率、动力学、投影、避障和终端条件的可行参考路径。
- 数学重点：晃液是有记忆的二阶 ODE；增广 `eta/eta_dot` 后满足 Markov 形式，可进入 MPC/MPCC horizon 预测；slosh-aware cost 与 smooth-only 不等价。
- 仿真主证据：**`B0 vs B_slosh`**，证明 slosh-aware cost 的基础贡献；`B_smooth_only vs B_ours_w10` 只作为机制补充，用于说明 slosh-aware 不等价于 smooth-only，不作为仿真主打或实物迁移主证据。
- 补充证据：`B_slosh ws0/ws2/ws10/ws20` 复核 real-like envelope 下的可运行性、非单调性和实物候选排序。
- `B_ours` 定位：作为 slosh-aware 基础上的工程候选和 smooth/control 正则扩展；在 2×2 消融中只用于辅助回答“slosh cost 是否仍能在 smooth priority 之外带来增益”。
- 输出限幅：`output angular limiter` 是发布层 wrapper/safety layer，记录 desired vs limited，不是 OCP 本体贡献。
- 模型保真度：仿真 `/slosh/height` 是 proxy；实物正式效果仍以后续离线 RGB max-LCR 为准。

## 2. Slide 2：问题定义

核心讲法：

```text
普通移动机器人 local planner 只需要在局部避障和到点之间折中；液体运输还多了一个有记忆的内部动态状态。
如果 planner 不预测液体残振，只追踪路径或只平滑命令，可能在第一弯、终端减速或连续换向时激发液面峰值。
```

推荐三点：

1. 任务：移动 Scout 搬运开口容器液体，要求到点且降低晃液。
2. 难点：液体响应依赖历史加速度和相位，不是当前速度/加速度的静态函数。
3. 方法需求：local planner 需要在 horizon 内联合考虑路径进度、车辆控制和液体状态。

## 3. Slide 3：方法贡献概览

建议写成 3 个 contribution：

```text
1. Slosh dynamics augmentation
   将二维晃液二阶 ODE 的 eta/eta_dot 增广进 SPMPC 状态，使液体响应可在 horizon 内预测。

2. Slosh-aware continuous MPCC local planner
   在 local planner 层联合优化路径进度 s、控制 u=[a, alpha, v_s]、tracking/progress/smooth/slosh-aware cost。

3. Controlled validation pipeline
   用 strict fresh-sim 和实物 RGB max-LCR 建立验证链：先证明 slosh cost 的仿真 proxy 贡献，再通过实物 B0 -> B_slosh -> weak B_ours 拆因子迁移。
```

## 4. Slide 4：系统层级与方法演进

本页用于同时回答两个容易被问到的问题：

```text
1. SPMPC 和 TEB/DWA 是不是同一层？
2. SPMPC 相比旧 fixed-path tracking MPC 到底升级在哪里？
```

### 4.1 系统层级：SPMPC 与 TEB/DWA 同属 local planner

| 模块 / 方法 | 系统层级 | 主要输入 | 内部决策 / 优化对象 | 主要输出 | PPT 口径 |
|---|---|---|---|---|---|
| Global planner / fixed path source | 全局路径 / 参考路径层 | map、goal、固定路径模板 | 生成全局或固定参考路径 | `/scout/global_path_fixed` / global path | 给 local planner 提供参考，不直接做局部避障/控制 |
| DWA | local planner 层 | global path、costmap、odom | 速度采样与打分 | `/cmd_vel` | external local planner baseline；不含 slosh model |
| TEB | local planner 层 | global path、costmap、odom | elastic-band 轨迹优化 | `/cmd_vel` | external local planner baseline；优化型但不含 slosh model |
| SPMPC / continuous MPCC | local planner 层 / 规控一体局部规划器 | fixed/global path、costmap、odom、slosh state | 联合优化路径进度 `s`、局部轨迹、车辆控制 `u=[a, alpha, v_s]` 与预测晃液状态 | `/cmd_vel` + horizon/debug prediction | 与 TEB/DWA 同层，但内部是 slosh-aware 规控一体 OCP |
| B0 / B_slosh / B_ours | SPMPC 内部变体 | 同 SPMPC | 切换是否启用 slosh-aware cost、smooth/control 正则 | 同 SPMPC | 用于 SPMPC 内部消融；不是新的系统层级 |
| output angular limiter | local planner 输出 wrapper / safety layer | SPMPC desired `/cmd_vel` | 发布前 rate/accel envelope 与诊断记录 | limited `/cmd_vel`、`/spmpc/debug/cmd_vel_output` | 安全层，不是 OCP 本体贡献，不改变 SPMPC 的 local planner 层级 |
| Chassis driver / low-level controller | 底盘执行层 | `/cmd_vel` | 电机/底盘执行控制 | 车体运动、odom | 不属于 planner，对所有 local planner 一视同仁 |

一句话讲法：

```text
SPMPC 与 TEB/DWA 在 ROS navigation stack 中同属 local planner 层，接口上都是接收路径/地图/状态并输出 /cmd_vel；不同的是 SPMPC 在 local planner 内部用 continuous MPCC 联合优化路径进度、车辆控制和晃液预测状态，因此是 slosh-aware 的规控一体 local planner。
```

路径能力边界：

```text
SPMPC 不是 global planner；它可沿给定且局部可行的 global/fixed reference path 做规控一体优化，但不保证任意全局路径都可跟踪。
```

### 4.2 方法演进：旧 tracking MPC 只是 baseline / evolution source

| 维度 | fixed-path tracking MPC / `scout_local_planner` | SPMPC / `spmpc_local_planner` |
|---|---|---|
| 系统定位 | fixed-path tracking controller baseline | slosh-aware continuous MPCC local planner |
| 路径进度 | 外部给定或按参考点推进 | OCP 内优化 `s` / `v_s` |
| 控制量 | 主要服务路径跟踪 | `a, alpha, v_s` 联合优化 |
| 液体状态 | 后处理/弱耦合解释 | `eta/eta_dot` 增广进入预测状态 |
| 方法目标 | tracking error 小 | progress + tracking + slosh + smooth + safety |

讲法：

```text
旧 scout_local_planner 只作为 fixed-path tracking baseline 和演进来源；SPMPC 的升级点不是简单换 solver，而是把路径进度和晃液状态一起放进 local planner 的 horizon 优化中。
```

## 5. Slides 5-10：方法本体讲法

### Slide 5：SPMPC 系统架构

建议图上分 4 层：

```text
Inputs:
  fixed/global path, odom/TF, costmap, slosh state/observer

SPMPC OCP:
  continuous_mpcc_acados
  states: vehicle + progress + slosh
  costs: tracking + progress + smooth + slosh-aware

Output wrapper:
  desired cmd -> output angular limiter -> /cmd_vel
  diagnostics: desired/limited, progress, horizon, solver status

Baselines:
  TEB/DWA external local planner, not inside SPMPC OCP
```

### Slide 6：SPMPC 状态、控制与 continuous MPCC

```text
x = [p_x, p_y, theta, v, s, omega, eta_x, eta_x_dot, eta_y, eta_y_dot]^T
u = [a, alpha, v_s]^T
```

重点：

- `s` / `v_s` 使其不是纯 tracking controller；它在局部 horizon 内优化路径进度。
- `eta_x/eta_y` 及其速度使 slosh response 成为预测状态。
- `continuous_mpcc_acados` 是当前主 backend。

### Slide 7：Slosh 二阶 ODE

连续模型：

```text
eta_ddot_x + 2*zeta*omega_n*eta_dot_x + omega_n^2*eta_x = -a_x
eta_ddot_y + 2*zeta*omega_n*eta_dot_y + omega_n^2*eta_y = -a_y
```

核心句：

```text
当前液面 != f(当前加速度)
液体有内部状态和残振记忆，必须预测 eta/eta_dot 的演化。
```

### Slide 8：Markov 增广与离散化

```text
x_slosh = [eta_x, eta_x_dot, eta_y, eta_y_dot]^T
x_dot = A_c x + B_c u
x_{k+1} = A_d x_k + B_d u_k
A_d = exp(A_c T_s)
```

讲法：

```text
只用车辆状态时，对晃液问题不是 Markov；加入 eta/eta_dot 后，可以写成 s_{k+1}=f(s_k,u_k)，因此能进入 MPC/MPCC horizon。
```

### Slide 9：SPMPC 联合 OCP

代价口径：

```text
J = J_tracking + J_progress + J_smooth/control + J_slosh + terminal/constraint terms
```

强调：

- `J_slosh` 直接作用于预测的 slosh state / height proxy。
- `J_smooth/control` 是工程正则，不等价于 slosh-aware。
- 输出 limiter 不放进 OCP 主体，只是发布层 safety envelope。

### Slide 10：为什么 slosh-aware 不等于 smooth-only

模态响应可以写成卷积形式：

```text
x_k = A_d^k x_0 + sum(A_d^{k-1-j} B_d u_j)
```

结论：

```text
液面响应依赖整段控制序列、残振状态和相位。两条控制序列即使有相同的平滑度或加速度范数，也可能产生不同液面峰值。
```

可以说：

> 在稳定二阶模态模型下，slosh-aware 代价直接约束预测液面响应；smooth-only 只是间接减少激励。

不能说：

> 已证明当前非凸实时 OCP 全局最优，或已用模型 proxy 证明实物真实降晃。

## 7. Slide 12：加入 slosh-aware cost 后，B_slosh 的 core p95/rms 低于 B0

标题建议直接写结论：

```text
加入 slosh-aware cost 后，B_slosh 的 core p95/rms 低于 B0
```

主视觉建议做成两组柱状图：

| metric | `B0` | `B_slosh` | change |
|---|---:|---:|---:|
| core p95 mm | 0.542 | **0.434** | -19.9% |
| core rms mm | 0.334 | **0.290** | -13.2% |
| core peak mm | 1.405 | 1.338 | -4.8% |

旁注小表：

| case | 作用 | N/pass | first goal mean s | cmd abs(dω/dt) p95/max |
|---|---|---:|---:|---:|
| `B0` | tracking baseline | 3/3 | 15.204 | 0.620 / 5.103 |
| `B_slosh` | slosh state + slosh cost | 3/3 | 15.617 | 0.594 / 4.251 |

讲法：

```text
B_slosh 的 p95/rms 有明确下降；peak 仅小幅下降，因此不夸大 peak 抑制。
二者均 3/3 strict valid 且 3/3 goal reached。
```

结论句：

> 在相同 tracking 任务下，加入 slosh-aware 分支后，仿真 `/slosh/height` core p95/rms 低于 B0，说明 slosh-aware cost 在模型 proxy 中有基础贡献。

边界：

```text
这页证明的是 slosh-aware cost 的仿真 proxy 贡献，不直接等价于实物 RGB 真值。
```

## 8. Slide 13：机制补充：slosh-aware 不等价于 smooth-only

标题建议：

```text
机制补充：slosh-aware 不等价于 smooth-only
```

主视觉：

| | no slosh cost | slosh-aware cost |
|---|---|---|
| no smooth priority | `B0` | `B_slosh` |
| smooth priority | `B_smooth_only` | `B_ours` / `B_ours_w10` |

这页回答听众可能追问的关键问题：

```text
液面降低是不是只是因为命令变平滑？
```

可用数值：

| 对比 | N/pass | core p95/rms mm | 讲法 |
|---|---:|---:|---|
| `B_smooth_only` | 3/3 | 0.477 / 0.267 | smooth-only 可通过 |
| `B_ours_w10` | 3/3 | 0.365 / 0.253 | 同 smooth priority 下 slosh cost 进一步降低 p95/rms |

解释：

```text
B0 -> B_slosh:
  Primary evidence：slosh cost 基础贡献，是仿真主打证据。

B_smooth_only -> B_ours_w10:
  Mechanism check：在相同 smooth priority 下，slosh cost 仍有额外收益，说明 slosh-aware 不等价于 smooth-only；但不作为仿真主打或实物迁移主证据。

B_slosh -> B_ours:
  观察 smooth/control regularization 的工程影响；B_ours 只作为工程候选，不声称实物已最优。
```

边界：

```text
2×2 只作为机制补充证据；实物 B_smooth/B_ours 当天失败说明 smooth/control envelope 还需要单独拆因子迁移，不能把 B_ours 直接写成实物主结论。
```

## 11. Slide 16：工程安全与 Sim-to-real 边界

标题建议：

```text
仿真候选不能直接等价于实物参数，需拆因子迁移
```

工程安全证据：

| `Bours_v070_ws10_wa2_alim` | 5/5 | 0.868 / 0.516 | **0.902 / 1.239** | 更快，但液面 rms 略高 |

当前实物观察：

```text
20260613 实物：
- B0(v_ref=0.65, alpha_max=8.0, output limiter on) 可完成同一路径；
- B_smooth 多组失败；
- B_ours 当天也失败；
- bag 诊断显示 desired_omega≈limited_omega，limiter 介入比例低，所以主因不是 output limiter；
- 当前优先怀疑 B_smooth/B_ours 共同的 smooth/control envelope，而不是 slosh-aware 本体。
```

实物路线：

```text
B0 tracking anchor
  -> B_slosh w_slosh=2
  -> 若 w=2 通过，再扩展 B_slosh w_slosh=10
  -> 若 w=10 也安全，再扩展 B_slosh w_slosh=20
  -> 再进入 B_ours weak smooth
```

Claim boundary：

| 可以 claim | 不能 claim |
|---|---|
| SPMPC 是 local planner 层的 slosh-aware continuous MPCC | SPMPC 是 global planner，能规划任意全局路径 |
| Slosh ODE 增广后可进入 MPC/MPCC horizon 预测 | 当前非凸实时 OCP 被证明全局最优 |
| B0 vs B_slosh 仿真支持 slosh-aware cost 有 proxy 贡献 | 仿真 proxy 等价于实物 RGB 真值 |
| B_smooth_only vs B_ours_w10 可作为机制补充，说明 slosh-aware 不等价于 smooth-only | 已证明所有 real-world 场景都能降低真实液面，或把 B_ours 当作实物主结论 |
| TEB/DWA 是同层 external baselines，不含 slosh model | 已经公平实物击败 TEB/DWA |
| output limiter 提升发布层安全和诊断 | limiter 是 OCP 本体贡献 |
| 实物下一步需 B0 -> B_slosh -> weak B_ours 拆因子 | 直接把仿真最优 B_ours 权重搬到实物即可 |

结尾一句：

> 仿真证明机制与候选，实物验证真实 RGB 效果；当前最稳路线是先证明 slosh-aware 本体可实物闭环，再逐步恢复 strong slosh cost 与 weak smooth B_ours。

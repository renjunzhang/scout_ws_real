# 2026-03-07 修改方案

## 1. 当前代码状态

基于当前工作区代码，`scout_local_planner` 与 `slosh_models` 已具备以下能力：

- 已完成液体晃动状态注入：`x0` 中包含 `[ETA_X, ETA_X_DOT, ETA_Y, ETA_Y_DOT]`
- 已完成晃动软代价接入：`Q_slosh_eta` 已进入 `cost_function.cpp`
- 已完成 `ay = v * omega` 的一阶线性化补项
- 已发布调试话题：
  - `/slosh/state`
  - `/slosh/height`
  - `/slosh/ax_est`
  - `/slosh/ay_est`
  - `/slosh/alpha_est`
  - `/mpc/solve_ms`
  - `/mpc/status_val`

但当前仍存在几个关键缺口：

- 目前主要还是 **soft cost 被动抑制**，`slosh_height_max` 还没有真正进入 QP 约束
- 执行端仍存在 **模型外隐藏滤波**（`publishCmdVel()` 内 EMA），会带来预测-执行不一致
- 目前还没有 **预测峰值监测**，无法直接判断“优化器自己预测会不会爆峰”
- `PathHandler` 尚未做 slosh-aware 速度治理，当前主要靠 MPC 后端压制晃动
- `LiquidSloshModel` 尚无 `setState()`，`readFromAugmentedState()` 仍未闭环

---

## 2. 本轮修改原则

本轮不继续把主要精力放在单纯调 `Q_slosh` 上，而按下面顺序推进：

1. 先固定实验口径
2. 先去掉/固定模型外隐藏动态
3. 再增加预测峰值监测
4. 再把液面峰值代理约束逐步接入 QP
5. 最后再把反激励前移到速度规划层

原因：

- 当前 bag 结果已经说明 `Q_slosh` 有削峰趋势，但效果仍混杂了执行滤波、路径差异、实验口径不统一等因素
- 如果不先统一实验口径和预测-执行一致性，后续约束和速度治理的收益很难被清晰验证

#### 额外发现：当前“终点不收敛”的直接原因

结合 bag 末端状态分析：

- 末端 `mpc_status` 一直停留在 `TRACKING`
- 末端 `cmd_vel` 已降到约 `3e-4 m/s`
- 将 `odom` 通过 `map->odom` TF 还原到 `map` 后，最终仍有：
  - 距离误差约 `0.26 m`
  - 航向误差约 `0.116 rad`
- 当前 `goal_tolerance = 0.1 m`
- 当前 `yaw_tolerance = 0.1 rad`

这说明问题不是“求解失败”，而是：

- `PathHandler::getReferencePoints()` 的末端停车速度主要按 **路径弧长剩余 `remain_s`** 收缩
- `PathHandler::isGoalReached()` 则按 **欧氏 goal 距离 + 末端切线 yaw** 判定
- 当 `s_global_` 已接近路径末端、但车体仍横向偏离 goal 时，`v_ref` 会过早掉到接近 `0`
- 于是出现：
  - 状态仍是 `TRACKING`
  - 但速度已几乎为零
  - 最终“停在 goal 外侧而不收敛”

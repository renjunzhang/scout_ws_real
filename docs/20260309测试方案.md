# 20260309 实物测试方案

## 1. 目标

本轮测试只解决一个问题：

- 实物路径跟踪过程中出现的“左摇右晃 / 来回摆头”

当前判断的优先级如下：

1. 执行端 EMA 滤波导致预测-执行不一致
2. `Q_ec / Q_etheta` 与 `R_omega / R_domega` 不匹配，转向修正过猛
3. `lookahead_distance` 偏小，四轮差速底盘对近端误差过敏
4. 定位 yaw 抖动或 TF 轻微抖动
5. Frenet 小角度近似是放大因素，但不是第一主因

本轮测试按这个顺序验证，不同时改很多项。

---

## 2. 测试原则

- 固定起点和终点
- 每次只改 1 组参数
- 每组至少跑 2 次
- 先关掉 anti-slosh，先把基础跟踪调顺
- 每次都记录 bag，便于对比

---

## 3. 基础观测话题

至少同时观察：

```bash
rostopic echo /mpc_status
rostopic echo /mpc/status_val
rostopic echo /cmd_vel
```

建议在 RViz 同时看：

- `/scout/global_path`
- `/local_path`

如果怀疑定位抖动，再额外看：

```bash
rostopic echo /odom
rosrun tf tf_echo map base_link
```

---

## 4. 静止定位测试：先确认定位本身是否抖动

在不上 goal、不让机器人移动的情况下，先静止观察 `20~30s`。

### 4.1 观察命令

```bash
rostopic echo /odom
rosrun tf tf_echo map base_link
```

### 4.2 观察点

- 机器人静止时，`map -> base_link` 的 yaw 是否仍明显跳动
- `/odom` 的角速度和姿态是否存在高频变化

### 4.3 判定

如果静止状态下 yaw 自己就在抖：

- 后续动态测试会被定位噪声污染
- 此时不要急着改 MPC 参数，应先排查定位链路

如果静止状态下 TF 基本稳定，再进入下一步动态测试。

---

## 5. 基线测试：先排除 EMA 相位滞后

### 5.1 启动命令

使用实验 launch，但把 anti-slosh 关掉，并关闭执行端额外 EMA：

```bash
roslaunch scout_local_planner slosh_experiment.launch \
  Q_slosh:=0 \
  enable_slosh_box_constraint:=false \
  slosh_speed_governor_enable:=false \
  filter_alpha_v:=1.0 \
  filter_alpha_omega:=1.0 \
  filter_kappa_boost:=0.0
```

### 5.2 观察点

- `/cmd_vel.angular.z` 是否仍明显正负来回切换
- `/local_path` 是否仍左右摆着贴路径
- `/mpc/status_val` 是否稳定为 `1`

### 5.3 判定

如果关闭 EMA 后，左右摆明显减轻，则说明：

- 当前主因之一就是执行端 EMA 滤波引入的相位滞后

此时后续基础跟踪调参都应优先在“关闭 EMA”的条件下进行。

---

## 6. 第二轮：先调转向平滑性

如果第 5 步后仍然有明显摆头，先只调整角速度相关权重和前视距离。

### 6.1 当前实物参数

```yaml
Q_ec: 30.0
Q_etheta: 12.5
R_omega: 1.0
R_domega: 3.0
lookahead_distance: 0.5
omega_max: 1.0
```

### 6.2 第一组建议参数（先只改平滑相关）

```yaml
R_omega: 2.0
R_domega: 5.0
lookahead_distance: 0.6
```

### 6.3 目的

- 增大角速度和角速度变化代价
- 适当看远一点，减少对近端误差的过敏修正

### 6.4 判定

如果这组参数后：

- `/cmd_vel.angular.z` 振幅明显减小
- 方向修正更像小幅连续微调
- 路径仍能贴住全局路径

则说明主因偏向“转向平滑性不足”，先不要改结构。

---

## 7. 第三轮：再调跟踪权重

如果第 6 步后仍有明显摆头，再调整路径跟踪权重。

### 7.1 第二组建议参数

```yaml
Q_ec: 20.0
Q_etheta: 8.0
```

### 7.2 目的

- 降低“立刻贴回路径”的冲动
- 避免为了快速消除横向误差而持续过修正

### 7.3 判定

如果这组参数后：

- 摆头继续减轻
- `/local_path` 仍能贴住 `/scout/global_path`

则说明主因偏向“跟踪权重过于激进”。

---

## 8. 第四轮：检查是否是定位抖动

如果关闭 EMA 且调完参数后，仍然左右摆动明显，再检查定位。

### 8.1 观察项

- `map -> base_link` 的 yaw 是否高频抖动
- 机器人静止时，`odom` 和 `tf` 的 yaw 是否仍在跳
- 摆动时 `/cmd_vel.angular.z` 的方向变化是否和定位 yaw 抖动同步

### 8.2 判定

如果定位 yaw 本身高频抖动，则：

- MPC 看到的 `e_theta` 会来回跳
- 左右摆动不一定是控制参数本身的问题

这时应先处理定位质量，再继续调跟踪参数。

---

## 9. 第五轮：再考虑模型项

只有在下面三项都做过之后，才考虑模型问题：

1. EMA 已关闭
2. 平滑参数已调过
3. 定位抖动已排除
4. 跟踪权重已调过

这时如果仍明显摆头，再重点看：

- `e_theta` 峰值是否经常大于 `0.15 ~ 0.2 rad`
- 是否在大误差修正时才出现显著振荡

如果是，则说明：

- Frenet 小角度近似可能已经开始明显影响行为

但这不是当前第一刀要改的内容。

---

## 11. 当前推荐执行顺序

### 第一步

先做静止定位测试：

```bash
rostopic echo /odom
rosrun tf tf_echo map base_link
```

### 第二步

先跑“EMA 全关”的基线：

```bash
roslaunch scout_local_planner slosh_experiment.launch \
  Q_slosh:=0 \
  enable_slosh_box_constraint:=false \
  slosh_speed_governor_enable:=false \
  filter_alpha_v:=1.0 \
  filter_alpha_omega:=1.0 \
  filter_kappa_boost:=0.0
```

### 第三步

若仍摆头，再改：

```yaml
R_omega: 2.0
R_domega: 5.0
lookahead_distance: 0.6
```

### 第四步

若仍摆头，再改：

```yaml
Q_ec: 20.0
Q_etheta: 8.0
```

### 第五步

若仍明显摆动，再查定位 yaw 抖动。

### 第六步

只有前面三步都确认后，才考虑是否需要改 Frenet 运动模型。

---

## 12. 本轮测试结论输出格式

每轮测试后统一记录：

- 启动命令
- 修改的参数
- 是否仍有左摇右晃
- `/cmd_vel.angular.z` 是否明显改善
- `/mpc/status_val` 是否稳定
- 是否顺利到达终点
- `TF/定位是否稳定：稳定 / 轻微抖动 / 明显抖动`
- 主观结论：更好 / 无明显变化 / 更差

这样后续比较不会混乱。

## 1. 当前目标、论文问题与写作定位

### 1.1 用户已明确的方向

1. **主比较是普通 B0 与我们的完整双层防晃 MPCC。** 两者输入同一个 S 形参考路径，在同一物理区域、起终条件和运动约束下完成运输。
2. 原路径提供引导与进度坐标；允许在共同区域内优化实际几何和速度。跟踪误差不是主要成绩，完成任务、空间可行性和运输效率仍需核验。
3. 当前开发阶段先比较 solver 预测高度，以及 IMU 实测运动驱动 slosh model 得到的高度。
4. **用户随后明确：最终论文肯定包含 RGB，只是目前尚未完成。** 最终实物防晃结论应由校准后的 RGB 液面测量支撑，预测与 IMU 重建保留为机制解释和模型诊断。
5. 先建立条件清楚的理论与名义模型依据，再验证闭环仿真和实物；不能提前填写收益比例。

本文提出的五组主表、两层因子消融、外部方法选型、指标主次、重复次数和扩展场景均为**实施建议**，尚未形成冻结协议。不得把旧草稿的 40/64/88 次矩阵或旧速度配置自动移植过来。

### 1.2 论文的中心问题

> 在运输效率和运动空间受限时，全任务防晃规划与基于当前液体状态估计的在线 MPCC 调整，能否共同降低连续转弯和停车过程中的液面响应？收益来自哪些机制，在执行偏差下能保留多少？

建议题名：**面向移动机器人液体运输的两层防晃轨迹规划与模型预测轮廓控制**。

英文候选：*Hierarchical Slosh-Aware Trajectory Planning and Model Predictive Contouring Control for Mobile Liquid Transport*。

正文逻辑应为：液体存在振荡记忆 → 相邻转弯及制动激励会相互影响 → 上层考虑全程 → 下层处理当前状态和执行偏差 → 用相近效率下的实际液面结果检验收益。给定几何参考和滚动执行第一步都是问题设定，本身不决定创新强弱。

## 3. 方法章节建议结构

方法章建议由六个小节构成。每节写清“解决什么问题、输入输出、数学定义、实现对应”，避免按 ROS 文件或调参经历组织正文。

### 3.1 Task Definition and Hierarchical Architecture：任务与两层结构

需要定义：原始参考路径 $r(s)$、有序允许运动区域、起终状态、运输时长/期限、停车评价窗口、运动限制和液体参数。上层输入至少包括有序路点、区域、完整初态、目标姿态、时间要求、执行器/液体参数及目标权重。

区分三种对象：

| 对象 | 本文含义 |
| --- | --- |
| 原始几何路径 | 无须预先附带完整时间律；提供路线身份、引导和进度坐标 |
| 上层名义计划 | 整段任务的时间索引状态/控制序列，包括几何、速度、液体和停车过程 |
| 下层预测与实际输出 | 每周期优化短时域状态轨迹和控制序列，经执行流程输出当前速度命令 |

当前“全局层”指看完整任务的离线层；不表示已做地图拓扑搜索，也不表示得到全局最优解。当前运输时长为给定量，不应写成自由终止时间最优方法。参考是弱引导且区域内允许改几何，标题和问题定义不能继续暗示严格沿唯一曲线运动。

架构图应显示：任务输入 → 离线计划 → 在线参考构造 → MPCC → 最终命令 → 实车；运动测量 → 状态构造 → MPCC。RGB 为评价支路。除非后续实际实现，不画“实车反馈自动更新上层剩余计划”的箭头。

### 3.2 Unified Robot–Actuator–Liquid Model：统一动力学

用分块状态表示车辆、虚拟进度、命令速度、执行器/FIFO、加速度记忆和四维液体模态。状态索引与完整参数表可放补充材料。当前已核对显式执行器版本的 B0/slosh 状态维数为 24/28，不能继续使用旧草稿的 6/10 维模型代表全部实现。

下层优化控制量应与源码语义一致：

$$
u=[a_{\mathrm{cmd}},\alpha_{\mathrm{cmd}},v_s]^\top,
\qquad \dot v_{\mathrm{cmd}}=a_{\mathrm{cmd}},\quad
\dot\omega_{\mathrm{cmd}}=\alpha_{\mathrm{cmd}},\quad \dot s=v_s.
$$

实际速度经 FIFO 和执行器响应形成，不能直接把命令加速度当作容器实际加速度。统一模型可概括为 $z_{k+1}=F_{\Delta t}(z_k,u_k;\vartheta)$；需说明离散积分、队列更新和初态构造，参数来源单独报告。

以随容器旋转的模态坐标 $q=[\eta_x,\eta_y]^\top$ 为例，当前低阶旋转模型的核心形式为：

$$
\ddot q=-2\zeta\omega_n\dot q-\omega_n^2q-a_C
-2\omega J\dot q-\alpha Jq+\omega^2q,
\qquad J=\begin{bmatrix}0&-1\\1&0\end{bmatrix}.
$$

这里 $\omega,\alpha$ 为实际旋转运动，$a_C$ 为容器作用点的平面加速度；外参和偏置换算需明确，不能重复叠加旋转激励。说明与文献模型的近似关系，不把该形式包装成原创物理模型。

模态高度采用：

$$
H_{\mathrm{modal}}=c_h\sqrt{\eta_x^2+\eta_y^2}.
$$

它是模型输出。IMU 测量运动后传播得到的模态状态仍是估计，不是直接观测到液体位移和带符号相位。参数辨识、传感校准与初始化规则应能复现；当前支持 odom/processed-IMU 来源，不应在正式配置未定前写死其中一个。最终 RGB 评价不自动意味着 RGB 进入控制反馈。

### 3.3 Full-Task Slosh-Aware Planning：上层全任务规划

写清决策变量、共同动力学、空间区域、运动限制、目标到达和停车尾段；上层同时选择可执行几何、速度分配及激励时序。正文用结构式表达目标，完整归一化系数列到附表：

$$
\min_{Z,U}\quad J_{\mathrm{guide}}+J_{\mathrm{geometry}}+
J_{\mathrm{control}}+J_{\mathrm{liquid}}+V_{\mathrm{terminal}}.
$$

解释每项的物理作用，尤其液体位移、模态速度和停车残余。固定运输时长、deadline 与 stop window 分别定义，不把它们混为实际到达时间。当前液体硬约束是可选条件；若最终实验使用，需给出准确开关、阈值、软化方式和约束核验范围。

输出包括完整状态/控制样本、时间、阶段、原路线与区域身份。求解后重新传播检查可行性；IPOPT 报告成功只表示数值求解状态，不能直接写成全局最优或连续时间无溢出证明。

### 3.4 Online Slosh-Aware MPCC：下层在线优化

先给出一个控制周期的因果顺序：对齐当前车辆、液体估计和命令历史 → 投影得到进度 → 构造参考及约束 → 滚动优化 → 检查与发布 → 记录实际反馈。

解释 contour/lag、速度/进度速度、几何平滑、控制变化、液体模态及终端项。当前下层也允许调整局部几何和速度，不能简写成固定轨迹跟踪器。实际进度/到达时间通过共同测量规则获取，不能把 OCP 虚拟进度当成执行真值。

输出应分为内部预测状态/控制序列、首步候选命令、最终发布命令。描述首步加速度如何经命令状态形成线速度/角速度输出；旧稿直接由测得速度加 $a\Delta t$ 的表达需按最终实现重写。发布后的限幅、停车接管与失败处理只有实装并验证后才能写成完整执行机制。

### 3.5 Inter-Layer Coordination and Scope of Analysis：两层接口与分析

已核对基线中的上层提供几何、速度/进度参考、任务时间/目标信息和计划 warm start；下层从当前状态重新预测液体。给出 reference 的时间/进度对应关系，并说明平台停住或进度平台段如何选参考。共同模型与完整 warm start 不等于强制跟踪上层液体相位。

至少讨论一个核心限制：液体有时间记忆，下层即使处于同一几何位置，也可能具有不同的液体状态；按进度采样上层计划不自动保持其原时间响应。

理论部分分清三个层次：

- **设计依据：** 液体响应依赖初态和激励历史，解释全程规划与在线状态修正的动机。
- **条件性名义结论：** 在相同初态、固定时长、可行集、非液体目标和全局最优条件下，增加选定液体指标的正权重可推出该指标不劣。详见[已有验证思路第 3 节](../../实物实验注意事项/对比试验/解决问题的思路/20260916_B0与双层防晃MPCC从仿真到实物的验证思路.md)。这不是当前局部求解和闭环实车已经满足的定理，也不足以单独作为核心理论创新。
- **待实现/待证明的机制：** B0 候选非劣接受、预测末端与剩余计划接续、在线剩余任务更新。没有实现和证明时，放讨论或后续工作，不混入当前算法流程。

若将来宣称全程性能保持，应明确候选可表示性、共同约束、终端接续条件、数值误差及扰动假设；单次预测代价下降不自动推出闭环全任务或 RGB 指标改善。

### 3.6 Numerical Implementation and Execution：求解与实现

正文交代离线/在线求解器、采样周期、预测时域、积分、warm start、计算预算和失败行为；完整版本、参数和数据格式放附录或补充材料。

分开报告离线规划耗时、在线求解耗时和整控制周期耗时。候选 30 Hz 是目标配置，只有实测周期、超期率及失败记录支持时才写满足实时运行要求。执行器响应延迟与求解后命令变旧是不同问题，不能用前者的建模代替后者的时效核验。

## 4. 试验章节的问题与顺序

建议按以下问题组织，避免仅按“仿真/实物/算法名”罗列结果：

| 问题 | 主要对照与证据 | 能支持的结论 |
| --- | --- | --- |
| RQ1：完整方法是否有效？ | B0 对 Full；最终以 RGB 全程响应、残余、耗时与完成率为主 | 报告条件下完整方法的实物效果 |
| RQ2：收益是否超出平滑、减速和已有防晃方法？ | 平滑/耗时匹配对照、离线防晃方法、液体感知跟踪 MPC | 限定到被比较方法的增量价值 |
| RQ3：两层各起什么作用？ | 同框架两层液体项消融；轨迹、激励、液体状态和命令变化 | 机制贡献；额外分析后才谈交互作用 |
| RQ4：执行偏差与计算限制下是否成立？ | 失配/噪声仿真、预先确定的扩展工况、最终命令及周期统计 | 已测试范围内的可执行性和适用边界 |

章节顺序建议为：平台/任务/配置 → 对照方法与公平条件 → 测量和统计 → 仿真机制与失配 → RGB 实物主比较 → 关键消融/扩展 → 运行代价与局限。RGB 尚未完成时只写协议与待填结果，不用模型曲线代替实物结论。

## 5. 主对照与外部算法安排

### 5.1 建议五组主比较

| 组别 | 定义 | 当前定位 |
| --- | --- | --- |
| B0 | 原始 S 路径进入普通 MPCC，不使用上层防晃计划或液体决策；保留正确公共动力学和约束 | 用户指定主基线，对应当前 raw_mpcc |
| Smooth/time-matched MPCC | 无液体项，在开发集合理调整平滑权重与参考速度，使耗时接近 Full | 排除通用平滑和减速解释；不是独立外部算法 |
| Offline anti-sloshing + tracker | 文献方法移植的离线防晃轨迹，加公开说明的液体关闭跟踪器 | 外部防晃规划候选，优先对照 Ferrari 类方法 |
| Slosh-aware tracking MPC | 跟踪预先冻结的可执行时间轨迹，含液体模型和代价，不优化虚拟路径进度 | 外部防晃控制候选，可参考 Prabakaran；待实现核验 |
| Full | 全任务防晃规划＋在线液体感知 MPCC | 对应当前 planned_slosh；性能待验证 |

B0 与 Full 为主比较，其余比较的主次和检验顺序在正式协议中预先确定。B0 已有的公共平滑项不必清零；Smooth 组是透明调参对照，不能故意弱化 B0 再制造收益。

### 5.2 外部算法的选择与身份

1. **Ferrari 类离线优化。** 原文分别研究固定路径时序优化与路径/时序联合优化。必须说明选用哪个版本、移植到 Scout 的运动约束、液体模型、目标和跟踪接口。原文时间最优与本方法固定时长目标不同，应通过开发阶段预设的时间/阈值设置比较液面—耗时关系。修改原目标后只能称适配版本，不能冒称原算法复现。
2. **Prabakaran-inspired 液体感知跟踪 MPC。** 原文是不同运动平台上的模型/Kalman-MPC 跟踪，不能直接假设 Scout 能独立控制两个平移加速度。适配时明确非完整运动、参考时间律和可取得的状态信息；未实现原观测器时如实说明。仓库[已有方案](../../实物实验注意事项/后续改进/20260703_Prabakaran启发的晃液感知MPC跟踪baseline.md)是候选文档，不是已运行算法。
3. **Hamaguchi/ZV 类输入整形。** 作为低计算量补充，已有[profile 实现入口](../../../src/scout_apps/control/scout_profile_baselines/README.md)可供核对。现有 Hamaguchi-style 只保留部分整形/限速思想，Lim-style 是启发式重定时；均不能标为原论文忠实复现。运输时长必须包含整形增加的延迟。
4. **TEB、LT-DWA、普通外部 MPC。** 选少量通用方法作导航/执行能力补充即可，避免用大量不含液体的基线替代直接防晃近邻。已有[runner](../../../src/scout_apps/control/baseline_local_planner_runner/README.md)和[算法索引](../../../src/scout_apps/control/spmpc_experiments/README_compare_algorithms.md)仅证明有资产，仍需按新任务核验版本、输出链和评价口径。

**内部与外部不能重复计数：** 自己的上层计划配液体关闭下层属于上层消融；换一个作者名字不会成为独立外部方法。给外部跟踪 MPC 喂同一份自己的上层计划，可以形成受控的跟踪器比较，但应与完整系统的端到端比较分开说明。选择外部算法应在正式结果前确定，不因其表现好而移出主表。

## 6. 两层消融如何设计

建议优先在仿真做同框架 $2\times2$ 液体项消融：

| 记号 | 上层液体项 | 下层液体项 | 解释 |
| --- | --- | --- | --- |
| A00 | 关 | 关 | 两层几何/速度框架本身的效果 |
| A10 | 开 | 关 | 上层液体规划贡献 |
| A01 | 关 | 开 | 在液体关闭上层计划上加入下层液体决策 |
| A11 | 开 | 开 | 完整方法 |

四组保留相同的非液体目标、区域、任务、动力学和运动约束，仅切换预先定义的液体项。关闭上层液体项要重新生成计划，不能仅删除导出文件的液体曲线。若启用硬液面约束，应明确它属于该液体开关，或另外进行约束消融，避免权重关闭而约束仍在决策。

当前 planned_mpcc/planned_slosh 在同一液体感知上层计划下，接近 A10/A11 这一对。A00/A01 需要液体关闭上层计划及匹配下层配置；现有 raw/geometry/planned 四个 profile 不能直接充当这套因子实验。

**A00 不等于 B0：** A00 仍有上层几何/速度优化，B0 没有该上层。主比较与因子消融回答不同问题。直接移除上层、只保留下层 slosh 的比较也可补做，但应作为架构消融单列。

若要写“两层有协同增益”，不能仅凭 A11 最低：需报告预先指定的层间对比，以及交互量（例如某一共同指标的 $Y_{11}-Y_{10}-Y_{01}+Y_{00}$）及不确定性。若只支持一层主要贡献，应按结果收缩措辞。第一轮实物可以先 B0/Full，再完成论文所需的关键消融。

## 7. 三条测量链、指标与公平性

### 7.1 三条链分别承担什么角色

| 数据链 | 定义 | 论文角色 |
| --- | --- | --- |
| 预测高度 | solver 预测实际运动经液体模型得到 $H_{\mathrm{pred}}(t_j+\tau\mid t_j)$ | 计划机理与预测诊断 |
| IMU 重建高度 | 实测运动经标定、重力/外参处理和连续液体传播得到 $H_{\mathrm{IMU}}(t)$ | 当前阶段评价；最终解释执行响应和模型偏差 |
| RGB 液面测量 | 校准图像后得到预先定义的液面高度指标 $H_{\mathrm{RGB}}(t)$ | 最终实物效果的主要独立测量依据 |

RGB 使用哪一侧/几个视角、相对静液面位移还是液面幅差、像素到长度换算、可见区域与缺帧规则均需明确。单视角可见液面与模型径向最大模态高度不必是同一量；定量误差比较前先建立匹配的观测映射，不能只因单位都是 mm 就逐点相减。

已核对基线中的 B0 solver 液体高度字段为占位零，不能作为零晃动结果。需要统一旁路模型，用 B0 的预测实际运动和可追溯液体初态生成预测高度；旁路评价不得改变 B0 命令。不同外部算法未提供液体预测时，主表仍可统一比较 RGB/IMU，不能为凑齐预测表虚构其内部状态。

预测误差按固定提前量和真实状态 epoch 对齐；$\tau=0$ 可能只是同一观察器初值，不构成预测验证。预测与未来 IMU/RGB 的差异还含后续重规划和执行变化。模型/IMU 共享模型的吻合也不能替代独立 RGB 验证。

### 7.2 指标与分析建议

- 最终主效果指标建议为全运输窗口的 RGB 高度 RMS；当前开发阶段采用 IMU 重建 RMS。主指标和高度定义需在正式采集前确定。
- 补充全程峰值/P95、停车后固定窗口的 RMS/峰值，必要时报告阈值超限时间。停车窗口可从已有建议的 5 s 起评估，但尚未冻结。
- 同时报告实际运输时间、完成率、目标误差、区域/运动约束违反、最终命令干预、整周期耗时和超期率。几何路径长度/曲率用于解释收益来源。
- 运输窗口包括起步和制动；用共同位置、朝向、实际速度和命令队列规则定义到站。不能只保留路径中段或首次进入目标圈前的样本。
- 报告每趟/每区组的配对差、相对改善和置信区间；B0 接近零时优先绝对差。正式检验与多重比较规则随比较主次预先定义。
- 全部尝试及失败必须进入记录；若连续液面统计仅限成功配对，明确其条件性并同时报告完成率。无效测量、重置和丢帧不能补成零液面收益。

### 7.3 公平条件

主任务给相同参考和物理区域，允许各算法按自身能力选择运动；任务级比较只能先说明整体收益。另在共同可执行几何上做专项比较，区分几何自由度与速度/液体控制作用；不能一边允许 Full 切角、一边把对手更严格的曲线限制隐去后宣称纯液体模型优势。

相同 deadline 不等于相同实际耗时。调参阶段为方法生成几个预设工作点，报告高度—实际时间权衡，且冻结耗时匹配容差。不能事后拉伸时间轴、删掉不匹配运行，或让某组独自违反运动限制来“匹配”。

统一平台、容器/液量、载荷、起终状态、区域、测量处理与合理调参预算；每种方法的内部模型及适配差异单独披露。防晃外部 MPC 应获得同等质量且因果可取得的状态信息；普通导航算法保留原生无液体决策。旧文档“所有外部算法禁止液体反馈”的规则只对应其当时定义的液体无关基线，不适用于新提出的防晃 MPC 类比较。

外部方法的原始与最终命令均应保存，共同平台约束与算法原生限制分别交代。后级限幅如果频繁改变某组输出，应把其影响纳入解释，不能直接把部署层的效果归于优化器。

## 8. 从仿真到实物的执行安排

| 阶段 | 任务 | 产出及用途 |
| --- | --- | --- |
| P0：任务/模型核对 | 固定 S 路径、区域、起终条件；核对完整初态、模型、B0 旁路评价和时间轴 | 保证后续比较确实回答同一任务 |
| P1：名义模型潜力 | 充分求解预算下做 B0/Full 和两层消融 | 找到可重复的收益及失效条件；未降晃时先解释目标/可行空间 |
| P2：现实闭环仿真 | 加入有限计算预算、部署状态链及两类外部防晃方法；再加入执行器/液体参数失配、测量噪声和时间抖动 | 检查收益是否进入实际运动；扰动范围优先来自测量，探索值单列 |
| P3：低速集成及 RGB 预试验 | 完成最终执行版本核验、RGB 标定/同步；少量平衡区组核对指标和重复性 | 开发数据，不能同时作为正式无偏效果数据 |
| P4：正式实物主场景 | 冻结版本、方法、工作点和分析规则；同一 S 场景做主比较与关键消融 | RGB、IMU、预测、运动和运行时间的可追溯配对证据 |
| P5：预设扩展 | 少量不同弯道尺度、运输时间或液量条件，按预先选择的方法子集执行 | 检查适用范围；不要求首次就铺满所有组合 |

名义仿真可以作为模型内潜力验证；部署型闭环仿真不能仅给 Full 真实液体状态或未来扰动。采用相同控制/对象模型只验证一致性，应另有失配条件。完全相同的确定性仿真重复运行不是独立样本。

实物采用随机或平衡区组，每个区组内完成相应方法；两组开发对照可用平衡 ABBA，多组正式试验按其实际随机化设计分析。统一回起点和液体初态恢复规则。预试验可先规划每条件 3–5 个完整区组估计变异，但不据此承诺功效；正式数量由最低有意义 RGB 改善、配对变异、精度要求及失败/测量损失估算确定。

外部算法先按统一任务完成与实现正确性标准验证，再进入正式比较；性能较差的有效实现和正式失败不能事后删除。有限资源时先完成 B0/Full、关键消融和一个可靠的离线防晃对手，再补液体感知跟踪 MPC；主张范围随实际完成内容调整。

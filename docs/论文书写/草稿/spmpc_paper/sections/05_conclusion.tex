\section{Conclusion and Limitations}

This paper formulates \SMPCC{}, an online receding-horizon local motion planner and controller for transporting an open liquid container along a prescribed geometrically feasible reference path. The method augments an acceleration-level path-progress \MPCC{} model with the first lateral liquid mode in two orthogonal directions. The modal state is propagated from odometry-driven excitation and retained as liquid dynamic memory, allowing the current displacement, velocity, and phase to influence future motion selection. The controller applies the first optimized base action and repeats the coupled prediction at the next cycle.

The evaluation is organized around four questions: whether explicit liquid dynamics improve measured free-surface response relative to matched Baseline and Smooth-only \MPCC{} variants, whether the benefit remains under completion-time matching, whether geometry-based model reparameterization transfers across containers without weight retuning, and whether liquid phase and the propagated runtime state change future plans and optimized first actions within the real-time deadline. Formal conclusions will be based on randomized blocks, trial-level calibrated RGB measurements, paired effect estimates, controlled longitudinal and lateral phase studies, actual/zero replay cloned from identical pre-solve snapshots, command-chain intervention records, success and failure records, and solve-time distributions. Archived three-trial results remain development evidence and do not contribute to the formal sample size.

The scope is deliberately limited. The current OCP assumes that a geometrically feasible reference path is supplied and does not include global route selection, occupancy-grid collision constraints, or dynamic-obstacle prediction. The liquid model is low order, is not corrected by measured free-surface feedback, and does not provide a formal spill-free guarantee. The container is assumed to be mounted at the base rotation center. The reference governor and modal hard cap are optional extensions and are disabled in the core comparison. Delay prediction, terminal handling, command gating, rate limiting, and fallback logic belong to the shared deployment layer; raw solver, post-gate, and published commands must therefore be logged separately before optimizer-level effects are inferred from physical execution.

Accordingly, the supported claim is restricted to the performance of \SMPCC{} relative to matched slosh-agnostic and smooth-only \MPCC{} variants under the reported paths, containers, sensing protocol, and execution configuration. Broader comparisons with liquid-aware profile methods or external online planners may be added only under a separately frozen and reproducible protocol.

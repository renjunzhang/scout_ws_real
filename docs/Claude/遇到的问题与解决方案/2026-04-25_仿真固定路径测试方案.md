# 2026-04-25 仿真固定路径测试方案

## 问题

实物 32 个 bag 使用 `docs/重要文档/20260423有效性验证方案.md` 中的固定路径方案：

- `P0_straight`
- `P1_single_turn`
- `P2_s_curve`
- `P3_mixed`

问题是这些生成轨迹和固定路径重放脚本能否直接迁移到当前 Gazebo 仿真中，用于验证 anti-slosh MPC 代码改动。

## 结论

可以用。

原因：

- `template_fixed_path_generator.py` 只依赖 ROS topic 和 TF，不依赖实物底盘硬件。
- `fixed_global_path_runner.py` 只负责保存/重放 `nav_msgs/Path`，也不绑定实物。
- 当前仿真链已经提供 `/odom`、`/tf`、`/imu/data`、`/scout/global_path_fixed`、`/cmd_vel` 这些 MPC 需要的接口。

需要调整的地方：

- 路径文件不要再写 `/home/geist/fixed_paths/`，仿真统一放到 `/data/a/fixed_paths/sim/`。
- RViz `2D Nav Goal` 的发布话题要和脚本一致。推荐用 `/scout/goal`；如果 RViz 实际发 `/move_base_simple/goal`，就把脚本参数改成 `--goal-topic /move_base_simple/goal`。
- 当前 `open_walled.world` 是 12 m x 12 m，墙在 `x/y = +/-6 m`，生成路径时终点要留 0.5 m 以上安全边界。
- 仿真没有真实液面视觉，主指标只能用 `/slosh/height`、`/slosh/height_pred_max`、轨迹和 MPC 状态；不能替代实物红色视觉结论。

## 测试目标

第一轮仿真不追求完全复刻实物液面视觉，只做三件事：

1. 验证固定路径生成/重放链路在仿真中可用。
2. 验证 `Q_slosh`、`risk_scheduler`、`Q_slosh_eta_dot` 对 `/slosh/height` 的影响方向。
3. 在实物前用低成本 bag 排查 MPC 结构、TF、路径、终点恢复和求解失败问题。

## 启动仿真

终端 1：启动开阔场地仿真导航骨架。

```bash
source /home/a/scout_ws/devel/setup.bash
SIM_ENV=open USE_RVIZ=true \
SPAWN_X=-4.5 SPAWN_Y=0.0 SPAWN_Z=0.1 SPAWN_YAW=0.0 \
rosrun scout_local_planner launch_sim_nav_stack.sh
```

说明：

- `SPAWN_X=-4.5` 是为了在 12 m 场地里留出更长路径长度。
- 如果定位不稳定，可以先用 `SPAWN_X=0.0` 跑短路径 smoke test。
- 一键脚本定位模式下默认 `ENABLE_ODOM_TF_BRIDGE=false`，不要手动打开，避免和 Cartographer localization 重复发布 `odom -> base_footprint`。
- `SIM_ENV=open` 启动后会自动执行定位刷新动作：前进 3s、顺时针转 1s、逆时针转 1s；`maze/custom` 不受影响，仍使用原来的后退刷新动作。
- 等终端出现 `Simulation navigation stack started.` 后，再采集固定路径或启动录包脚本。

```bash

rosrun tf tf_echo map base_link
```

## 采集并保存固定路径

先创建目录：

```bash
mkdir -p /data/a/fixed_paths/sim
```

采集路径时，在 RViz 里用 `2D Nav Goal` 点终点。建议终点不要贴墙。

注意：

- `template_fixed_path_generator.py` 用于第一次“生成 + 保存”路径。
- open 场景会先执行定位刷新动作，所以固定路径应在刷新动作完成、定位稳定后采集。
- 仿真固定路径采集推荐加 `--start-heading current`，让路径第一个点的朝向等于当前车头方向，避免起步时大航向误差。
- 使用 `--start-heading current` 时，RViz 终点必须点在当前车头前方；如果点到车后方，脚本会拒绝生成。
- 它也会临时发布一次 `/scout/global_path_fixed`，方便立即预览路径是否合理。
- 正式对比实验不要反复用它发布路径，因为它每次依赖当前车位姿和点击终点。
- 正式实验统一用后面的 `fixed_global_path_runner.py --mode replay` 发布已保存 JSON。

如果 RViz 的目标话题是 `/scout/goal`，使用以下命令。

### P0_straight

```bash
rosrun scout_local_planner template_fixed_path_generator.py \
  --template straight \
  --start-heading current \
  --goal-topic /scout/goal \
  --output-topic /scout/global_path_fixed \
  --path-file /data/a/fixed_paths/sim/P0_straight.json
```

建议终点：点在当前车头前方 7~9 m，尽量保持同一条直线，且离墙至少 0.5 m。

### P1_single_turn

```bash
rosrun scout_local_planner template_fixed_path_generator.py \
  --template single_turn \
  --start-heading current \
  --goal-topic /scout/goal \
  --output-topic /scout/global_path_fixed \
  --path-file /data/a/fixed_paths/sim/P1_single_turn.json
```

建议终点：点在当前车头前方偏左或偏右 6~8 m，保证单弯激励明显但不贴墙。

### P2_s_curve

```bash
rosrun scout_local_planner template_fixed_path_generator.py \
  --template s_curve \
  --start-heading current \
  --goal-topic /scout/goal \
  --output-topic /scout/global_path_fixed \
  --path-file /data/a/fixed_paths/sim/P2_s_curve.json
```

建议终点：点在当前车头前方 7~9 m，横向偏移不宜过大，路径中间会自动生成 S 弯。

## 发布/重放固定路径

正式实验不再重新点终点，直接重放同一条 JSON。

以 `P2_s_curve` 为例：

```bash
rosrun scout_local_planner fixed_global_path_runner.py \
  --mode replay \
  --path-file /data/a/fixed_paths/sim/P2_s_curve.json \
  --output-topic /scout/global_path_fixed \
  --skip-start-wait \
  --publish-once-keepalive
```

如果只是手动检查起点门控是否满足，可以临时运行：

```bash
rosrun scout_local_planner fixed_global_path_runner.py \
  --mode replay \
  --path-file /data/a/fixed_paths/sim/P2_s_curve.json \
  --output-topic /scout/global_path_fixed \
  --manual-start \
  --start-pos-tol 0.10 --start-yaw-tol 0.15
```

仿真正式录包不建议再做起点门控。固定路径已经从定位刷新后的当前位姿采集，重复“去起点”会把导航误差和姿态误差混入 anti-slosh 对比。

## 录包

仿真 bag 建议放：

```bash
mkdir -p /data/a/slosh_bags/sim/20260425
```

推荐使用单次 trial wrapper。它会按顺序完成：

1. 等待仿真/定位稳定。
2. 启动 rosbag 录制。
3. 发布指定固定路径 JSON。
4. 启动指定 MPC 条件。
5. 按 `Ctrl+C` 停止本次 trial 并关闭相关进程。

脚本默认只发布一次 latched 固定路径，并保持路径发布者存活，不会 2 Hz 重复发布。这样可避免 `PathHandler` 在终点附近反复收到“新路径”，导致 `REACHED` 状态被重复刷新。

脚本默认 `APPROACH_START_ENABLE=false`，即不再自动去固定路径起点。固定路径应从 open 场景定位刷新后的当前位姿采集，避免“去起点”的导航误差混入正式实验。

脚本不覆盖 `vehicle/*` 或 `path_handler/*` 控制参数。速度、加速度、曲率限速等 MPC 行为必须只通过 `config/mpc_params_sim.yaml` 显式修改，避免 wrapper 悄悄改变实验口径。

示例：录一包 `P2_s_curve + FAS_Q5_DOT + run01`。

```bash
source /home/a/scout_ws/devel/setup.bash
PATH_ID=P2_s_curve CONDITION=FAS_Q5_DOT RUN_ID=01 \
START_DELAY=30 APPROACH_START_ENABLE=false \
rosrun scout_local_planner run_sim_fixed_path_bag.sh
```

常用单包录制命令：

```bash
# NOM
PATH_ID=P2_s_curve CONDITION=NOM RUN_ID=01 \
START_DELAY=30 APPROACH_START_ENABLE=false \
rosrun scout_local_planner run_sim_fixed_path_bag.sh

# FAS_Q5
PATH_ID=P2_s_curve CONDITION=FAS_Q5 RUN_ID=01 \
START_DELAY=30 APPROACH_START_ENABLE=false \
rosrun scout_local_planner run_sim_fixed_path_bag.sh

# FAS_Q5_DOT
PATH_ID=P2_s_curve CONDITION=FAS_Q5_DOT RUN_ID=01 \
START_DELAY=30 APPROACH_START_ENABLE=false \
rosrun scout_local_planner run_sim_fixed_path_bag.sh

# FAS_Q10
PATH_ID=P2_s_curve CONDITION=FAS_Q10 RUN_ID=01 \
START_DELAY=30 APPROACH_START_ENABLE=false \
rosrun scout_local_planner run_sim_fixed_path_bag.sh
```

换路径时只改 `PATH_ID`：

```bash
PATH_ID=P0_straight   # 长直线 sanity check
PATH_ID=P1_single_turn
PATH_ID=P2_s_curve
PATH_ID=P3_mixed
```

常用切换参数：

```bash
PATH_ID=P2_s_curve      # P0_straight / P1_single_turn / P2_s_curve / P3_mixed
CONDITION=FAS_Q5_DOT    # NOM / FAS_Q5 / FAS_Q5_DOT / FAS_Q10 / PROP_Q5 / ISR
RUN_ID=01
START_DELAY=30          # 已经等待过则设为 0
RECORD_DURATION=0       # 0 表示手动 Ctrl+C；非 0 表示自动录固定秒数
PATH_PUBLISH_ONCE_KEEPALIVE=true  # 默认 true，避免固定路径重复触发新路径
APPROACH_START_ENABLE=false       # 默认 false；固定路径应从定位刷新后的当前位姿采集
```

脚本默认路径和 bag 目录：

```bash
FIXED_PATH_DIR=/data/a/fixed_paths/sim
BAG_DIR=/data/a/slosh_bags/sim/$(date +%Y%m%d)
```

如果需要手动使用底层录包脚本：

```bash
SLOSH_BAG_MODE=sim \
SLOSH_BAG_DIR=/data/a/slosh_bags/sim/20260425 \
rosrun scout_local_planner record_slosh_experiment.sh 5 P2_s_curve_FAS_Q5_DOT_run01
```

底层脚本会生成 `slosh_Q5_时间戳_P2_s_curve_FAS_Q5_DOT_run01.bag`。主推荐仍是 `run_sim_fixed_path_bag.sh`，因为它的 bag 命名直接包含路径、条件和 run 编号。

命名必须包含：

```text
YYYYMMDD_<路径>_<条件>_run<编号>.bag
```

示例：

```text

20260425_P2_s_curve_FAS_Q5_run01.bag
```

## 离线分析

每个 bag 先做 smoke：

```bash
python3 src/scout_apps/control/scout_local_planner/scripts/analyze_day3_abc_smoke.py <bag>
python3 src/scout_apps/control/scout_local_planner/scripts/diagnose_real_tuning.py <bag> --brief
```

重点比较：

- `/slosh/height peak`
- `/slosh/height p95`
- `/slosh/height RMS`
- `/slosh/height_pred_max`
- `/mpc/status_val success_ratio`
- `/mpc/solve_ms p95`
- `task_time`
- `cmd_vel.linear.x` 分布
- `cmd_vel.angular.z` 分布

仿真结论口径：

- 如果 `FAS_Q5_DOT` 相比 `FAS_Q5` 降低 `/slosh/height p95/RMS`，且 `solve_ms/status_val/task_time` 不明显变差，则 `Q_slosh_eta_dot` 值得进入实物小样本验证。
- 如果 `FAS_Q5_DOT` 只降低 peak，但 p95/RMS 不降，需要查看是否只是终点/某段速度变慢造成。
- 如果 `/slosh/height` 降低但轨迹严重变差，说明 dot cost 过强或权重尺度不合适。
- 如果三组差异很小，说明当前 slosh 模型对路径激励不敏感，应先加大路径激励或检查 `v*omega / omega_est_used / ay_est`，不要直接否定结构改动。

## 已知限制

- 仿真没有红色液体视觉，不能验证真实液面，只能验证模型内 `/slosh/height`。
- 当前 Gazebo skid-steer 自转有轻微抖动，不建议用长时间原地自转路径作为主实验。
- 当前 `open_walled.world` 场地大小有限，实物 10~15 m 路径在仿真中可能需要缩放；结论应看相对趋势，不直接等价到实物幅值。
- `PROP_Q5` 仍依赖 scheduler 与 IMU/odom 不确定性通道，建议等 `Q_slosh_eta_dot` 单变量验证后再加入。

## 问题描述

当前 IMU ay 标定只完成了**零偏（bias）在线估计**，缺少**比例系数（scale）**的离线标定。

两个未处理的物理误差来源：

| 误差来源 | 量级估计 | 影响 |
|---|---|---|
| 重力分量（车体俯仰 θ 时：g·sinθ） | 地面平坦时 < 0.1 m/s²，可忽略 | 较小 |
| 杠杆臂效应（IMU 离旋转中心 ~11cm）：ay_extra = ω²·r_x | 以 ω=0.5 rad/s 算：0.25²×0.10=0.025 m/s² | 中等，转弯时叠加 |

综合表现：`imu_ay_filtered` 的幅值与 `v·ω` 不完全匹配，导致 u_k 估计在常规工况下虚高，进而干扰 risk_scheduler 行为（见 `2026-04-19_仿真PROP比FAS晃动更大问题.md`）。

## 标定流程

### 第一步：录标定 bag

机器人接好 IMU，启动底盘和 IMU，运行标准动作序列：

```bash
# 终端 1：底盘 + IMU
roslaunch scout_bringup scout_mini_robot_base.launch
roslaunch scout_bringup scout_imu.launch

# 终端 2：录包
cd $(rospack find scout_local_planner)
./scripts/record_slosh_experiment.sh 0 imu_calib

# 终端 3：标准动作序列（静止5s → 左弧线5s → 静止3s → 右弧线5s → 静止5s）
python3 scripts/run_imu_stage2_sequence.py
```

动作参数建议：
- linear = 0.30 m/s，omega = ±0.40 rad/s（比原来 0.30 稍大，提高激励）
- 左右各跑 5 秒以上

### 第二步：运行标定脚本

```bash
cd $(rospack find scout_local_planner)
python3 scripts/calibrate_imu_ay.py \
    /path/to/slosh_Q0_XXXXXXXX_imu_calib.bag \
    --output imu_ay_calibration.yaml \
    --plot
```

输出：
- `imu_ay_calibration.yaml`：包含 `slosh_estimator/imu_ay_scale`
- `imu_ay_calibration_plot.png`：可视化验证图

### 第三步：将 scale 写入 launch 参数

```bash
# 查看标定结果
cat imu_ay_calibration.yaml
```

将 scale 值传给 launch：

```bash
roslaunch scout_local_planner slosh_experiment.launch \
  slosh_use_imu_lateral_accel:=false \    # lateral_accel 仍默认关闭
  slosh_use_imu_yaw_rate:=true \
  slosh_imu_ay_scale:=<标定值>            # 仅影响 u_k 计算精度
```

或直接加入 `mpc_params.yaml` 的 `slosh_estimator` 段：

```yaml
slosh_estimator:
  imu_ay_scale: 0.xxxx
```

## 判断标准

标定脚本输出以下诊断量：

| 指标 | 合格 | 说明 |
|---|---|---|
| `scale` ∈ [0.8, 1.2] | 可接受 | 偏离 > 20% 建议检查安装 |
| `corr(ay_calib, v·ω)` > 0.7 | 可接受 | < 0.5 说明有严重干扰 |
| 残差 RMS < 0.15 m/s² | 可接受 | 相对 a_uncert_max=0.5 < 30% |

---

## 预期影响

- `lateral_accel` 仍保持 `false`，scale 只影响 `imu_ay_unbiased_` 计算
- `u_k = |imu_ay_unbiased - v·ω| / a_uncert_max` 因此更准确
- risk_scheduler 的 fallback 触发更合理，rho_k 在正常工况下降低

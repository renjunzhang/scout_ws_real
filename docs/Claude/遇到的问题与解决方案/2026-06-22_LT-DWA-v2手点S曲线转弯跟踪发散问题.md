## 2. 现象

人工在 RViz 中点终点后，生成的全局层 S 曲线是合理发布的，LT-DWA-v2 也开始跟踪。

但是视觉观察到：

```text
实际轨迹在转弯处没有紧跟全局层，存在明显切弯/过冲。
```

最终状态不是成功到达，而是触发安全发散：

```text
status = TRACKING_DIVERGED
```

bag 中最后状态近似为：

```text
TRACKING_DIVERGED expanded=0 valid=0 goal_dist≈3.26 goal_yaw_err≈2.08
```

说明当前 safety gate 起作用了：发散后没有继续危险前进，而是进入 NO-GO 停止状态。

## 4. 全局路径几何分析

生成路径：

```text
frame = map
poses = 162
length ≈ 8.04 m
start ≈ (-0.010, 0.010)
end ≈ (6.980, 0.018)
```

路径曲率统计：

```text
curvature median ≈ 0.085 1/m
curvature p90    ≈ 1.285 1/m
curvature p95    ≈ 1.568 1/m
curvature max    ≈ 2.718 1/m
```

如果按不同速度通过这条曲线，理论所需角速度约为：

| 速度 | p95 曲率所需角速度 | 最大曲率所需角速度 |
|---:|---:|---:|
| `0.2 m/s` | `0.31 rad/s` | `0.54 rad/s` |
| `0.3 m/s` | `0.47 rad/s` | `0.82 rad/s` |
| `0.4 m/s` | `0.63 rad/s` | `1.09 rad/s` |
| `0.5 m/s` | `0.78 rad/s` | `1.36 rad/s` |
| `0.6 m/s` | `0.94 rad/s` | `1.63 rad/s` |

因此，这条 S 曲线在局部最大曲率处确实偏急：如果车以 `0.5 m/s` 以上强行贴最大曲率走，会接近或超过 `omega_max_radps=1.2`。

但本次实际失败发生时，车辆并没有以那么高速度贴最大曲率通过。

## 6. 是否是角速度上限导致？

当前证据判断：**不是主要由 `omega_max_radps=1.2` 硬上限导致。**

理由：

bag 中命令角速度和实际角速度都没有接近 `1.2 rad/s`：

```text
cmd_w mean_abs ≈ 0.217 rad/s
cmd_w p95_abs  ≈ 0.45 rad/s
cmd_w max_abs  ≈ 0.54 rad/s
cmd_w >= 1.14 rad/s 的比例 = 0

odom_w mean_abs ≈ 0.217 rad/s
odom_w p95_abs  ≈ 0.45 rad/s
odom_w max_abs  ≈ 0.54 rad/s
odom_w >= 1.14 rad/s 的比例 = 0
```

根据当前匹配进度和实际速度估计，active tracking 阶段的路径曲率所需角速度：

```text
omega_required p95 ≈ 0.45 rad/s
omega_required max ≈ 0.53 rad/s
```

与实际命令/odom 角速度基本同量级，并远低于 `1.2 rad/s`。

因此，如果问题是角速度硬限制，应该看到：

```text
cmd_w 长时间贴近 ±1.2 rad/s
```

或者：

```text
cmd_w 已经很大，但 odom_w 明显跟不上
```

但这次两者都没有出现。

## 7. 更可能的问题判断

当前更可能的问题是：

```text
LT-DWA-v2 的 scoring / local target / lateral recovery 仍然不够成熟。
它在 S 弯中允许候选轨迹切弯或过冲，并且在横向误差变大后没有足够强地选择“减速 + 大角速度回正”的恢复动作。
```

具体表现：

1. 第一段左弯后 lateral error 已经能放大到接近 `0.7 ~ 1.0 m`。
2. 中段又向另一侧过冲，出现负 lateral error。
3. planner 没有使用更大的角速度主动贴回路径；最大命令角速度仅约 `0.54 rad/s`。
4. progress 仍继续推进，说明“偏着走也获得 progress”的风险仍在。
5. 最终横向误差超过 `1.50 m`，被 safety gate 正确判为 `TRACKING_DIVERGED`。

这更像是局部规划策略/评分结构问题，而不是底盘动力学硬限制。

## 8. 需要请教老师的问题

可以把问题概括成：

```text
我现在有一个独立实现的 LT-DWA-v2，本质是 DWA 工程框架 + 长视域候选轨迹搜索/评分。
它在直线和部分路径上可以闭环推进，但在手点生成的 S 曲线转弯处出现切弯/过冲，最终 lateral error 超过 1.5 m 触发 tracking diverged。
从 bag 看，角速度上限 1.2 rad/s 没有打满，cmd_w/odom_w 最大只有约 0.54 rad/s，所以问题不像是底盘角速度限制，而像是候选轨迹评分和局部目标选择没有足够约束曲线跟踪。
```

建议重点请教：

1. **DWA 类局部规划器在全局路径 S 弯处，如何设计 path-distance / goal-distance / heading / progress 的权重关系，避免切弯？**
2. **长视域候选搜索中，progress reward 是否应该在 lateral error 较大时强衰减甚至禁止？**
3. **是否应该在评分中显式引入 path curvature / curvature matching / required omega matching，而不是只看 lateral distance 和 heading error？**
4. **横向误差变大后，是应该让 planner 自然评分恢复，还是应增加一个 recovery mode，例如减速、提高角速度采样、临时压制 progress reward？**
5. **当前 lookahead_distance=0.35m、max_progress_advance_per_step=0.20m 是否过于局部，导致目标点在弯道中抖动或错配？还是仍然偏大，导致切弯？**
6. **DWA 工程结构中，局部路径裁剪/rolling window/progress matching 是否比当前实现更关键？LT-DWA-v2 是否应该加入更明确的 local plan window 而不是直接在整条 fixed path 上 bounded projection？**
7. **当候选轨迹偏离全局路径但短期 progress 更大时，应该如何让 scoring 更鲁棒地区分“有效进展”和“切弯假进展”？**

## 9. 当前不能直接进入正式主表的原因

虽然之前有一次 strict fresh-sim 单例通过：

```text
success=1
GOAL_REACHED
stable_stop_bool=1
```

但本次人工监督可视化暴露出：

```text
LT-DWA-v2 对新生成 S 曲线的弯道跟踪仍不稳定。
```

因此当前结论应保持为：

```text
LT-DWA-v2 可以作为 experimental / conditional baseline 继续诊断；
不能因为一次 strict smoke 通过就进入正式主表；
需要先解决弯道跟踪、切弯和 lateral recovery 问题。
```

## 10. 下一步候选修复方向

暂不建议第一刀放宽 `omega_max_radps`。

更建议优先做小范围 LT-DWA-v2-only patch：

1. 在大 lateral error 时进一步压制 progress reward。
2. 在 lateral error 超过 `tracking_slowdown_lateral_m` 后更强降低 forward velocity。
3. 增强 lateral recovery：鼓励朝路径法向/路径切向一致的角速度，而不是只靠 heading cost 间接体现。
4. 增加切弯惩罚：候选轨迹如果 progress 增加但 lateral error 同时扩大，应加重惩罚。
5. 分析是否需要 DWA-style local plan window / path pruning，而不是仅靠全局 path bounded projection。
6. 后续再考虑 curvature-aware scoring 或 curvature-aware speed cap。

安全边界：

```text
不要修改 ROS DWA。
不要修改 third_party/LT_DWA。
不要修改实物 launch 默认行为。
不要修改底盘实际控制入口。
不要修改 /cmd_vel 生产链路。
不要修改 SPMPC OCP 参数输入链路。
slosh monitor 输出仍只作为评价/监控，不得被 planner、profile generator、command gate、OCP 或 /cmd_vel 链路消费。
```

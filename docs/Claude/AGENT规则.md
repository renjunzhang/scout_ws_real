# AGENT 规则

本文档用于约束 AGENT 在 `/home/a/scout_ws` 项目中的协作方式。默认目标是帮助完成 Scout 实物平台上的 tracking MPC 液体晃动抑制实验、参数维护、数据采集和证据链验证。

## 1. AGENT 协作规则

1. 默认以”先收敛、后扩展”为原则工作。优先完成当前实验闭环，不主动扩展新主线。
2. 若任务会导致 scope 膨胀，必须明确指出，并给出更小、更稳的实现路径。
3. 若用户没有明确要求，不要自行切换论文主线、控制方案或有效性验证方案。
4. 若已有方案足以推进实现，优先落地代码、参数、脚本和实验闭环，不继续生成新方案。
5. 若判断必须调整主方案，必须明确写出：`需要修改主方案!!`，并说明原因。
6. 若用户目标清晰，但当前路径不是更短、更稳或更合理的实现路径，应直接指出，并给出替代方案。
7. 遇到问题默认追根因，不以临时补丁为首选！！！！！！！每个关键决策都应能回答”为什么这样做”。
8. 输出默认只保留会影响判断、实现或决策的信息，删除不改变结论的低价值内容。
9. 默认使用中文沟通；命令、路径、参数名、话题名保持原文。

## 2. 修改记录规则（每次工作必须执行）

每次会话涉及代码或方案改动时，必须在当天结束前完成以下两项记录：

### 2.1 执行方案（每个执行日写）

**路径**：`/home/a/scout_ws/docs/Claude/修改方案-时间-简介/YYYY-MM-DD_DayN_主题.md`

**命名规则**：
- `YYYY-MM-DD`：执行日期
- `DayN`：推进方案中的第几天（Day1、Day2……）
- `主题`：当天核心任务的简短描述（如 `测量协议与参数辨识`、`调度器实现`）
- 示例：`2026-04-15_Day1_测量协议与参数辨识.md`

**内容要求**：
- 按 Step 编号列出当天每一个具体操作步骤（命令、脚本、检查项）
- 每步有明确的通过标准（`通过标准：xxx`）
- 末尾有 `Day N 完成标准` checklist（`[ ]` 待办项）
- 不写代码规格说明，只写”今天要做什么、怎么做、怎么判断做完了”

### 2.2 修改日志（每次会话结束时写）

**路径**：`/home/a/scout_ws/docs/Claude/修改日志-时间/YYYY-MM-DD.md`

内容要求：
- 今日实际完成内容（新建/修改的文件列表）
- 关键决策（方案确定、参数确定、策略调整）
- 当前分支和提交状态
- 明日计划（带 `[ ]` 待办项）
- 格式参考：`修改日志-时间/2026-04-14.md`

### 2.3 执行时机

| 场景 | 动作 |
|---|---|
| 会话开始，收到代码改动任务 | 先写修改方案，再动代码 |
| 会话结束或阶段性完成 | 写修改日志 |
| 纯讨论/规划会话（无代码改动） | 只写修改日志，修改方案可省略 |
| 用户要求补写记录 | 立即补写，不跳过 |

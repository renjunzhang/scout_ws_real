## 1. 设计目标

把 L2 已抽出来的 G 层从"分文件 + 串联"升级到"接口最小化 + 真正解耦"，
让 S 层（OSCRS selector）对 G 内部一无所知。

```text
当前 (L2)：       目标 (L3+)：

raw path           raw path
  ↓                  ↓
G(base, specs,      G : Generator (registry-resolved)
  min_seg,            ↓ list[Candidate]
  sanitize_fn)      S : Selector
  ↓                   ↓
S consumes        S 完全不知道 G 是 GeoRef / B-spline / timing
list[(name,
      points)]
+ S 持有 specs
+ S 持有 sanitize
+ S 用 index 排序
+ S 持有 max_candidate_level
```

## 2. 当前 L2 残留的 4 处耦合（必须全部破除）

### 2.1 `candidate_specs` 形态 GeoRef-specific

**当前 (`anti_slosh_path_post_processor.py:184`)：**

```python
self.candidate_specs = [
    ("original", 0, 0.0, 0.0),                 # iters/gain/drift 是 GeoRef-specific
    ("mild",   18, 0.35, 0.08),
    ...
]
# S 层把 specs 直接喂给 G：
candidates = generate_georef_candidates(base, self.candidate_specs, ...)
```

**目标：S 层不持有 spec。** spec 是 G 的私有配置，由 G 自己从 yaml 读取。

```python
# S 层只调用：
candidates = self.generator.generate(base)   # 无 spec 参数
```

### 2.2 `sanitize_fn` 反向注入

**当前：** G 层调用 S 层定义的 `sanitize_points`（依赖反转规避循环 import）。

**目标：** `sanitize_points` 移到共享工具模块 `path_utils.py`，G 与 S 都从这里 import；
G 与 S 之间不再有任何函数引用。

### 2.3 `max_candidate_level` gate 写在 S 层但语义属 G 层

**当前 (`anti_slosh_path_post_processor.py:534`)：**

```python
if self.candidate_levels.get(name, 0) > self.candidate_levels[self.max_candidate_level]:
    reject_reasons.append(f"level:{name}>{self.max_candidate_level}")
```

**问题：** "level" 是 GeoRef smoothing 强度的概念，但 gate 在 S 的 `evaluate_candidate` 里。
B-spline / timing generator 来了之后这个 gate 失去意义。

**目标：** G 在 `generate(base)` 内部自己 cap 候选集；S 看到的就是已经被 cap 住的列表。
S 的 `evaluate_candidate` 不再有 level gate。

### 2.4 `index` 顺序依赖

**当前：** S 用 `enumerate(candidates)` 的 index 当 candidate 标识，候选间同分时取最先出现者。

**目标：** S 用 `Candidate.name` 当唯一标识；同分 tie-break 改为按 name 字典序，与 G 顺序解耦。
G 的返回顺序退化为单纯的"按生成顺序"信息（用作诊断 log，不参与决策）。

## 3. 目标架构

### 3.1 数据结构

```python
# oscrs/candidate_generators/base.py
from dataclasses import dataclass, field
from typing import Mapping

@dataclass(frozen=True)
class Candidate:
    name: str                              # 唯一标识，S 用此 tie-break
    points: tuple[tuple[float, float], ...]   # 二维路径点（map frame）
    metadata: Mapping[str, object] = field(default_factory=dict)
    # metadata 对 S 不透明，仅用于 candidate_report 诊断
    # 例如 GeoRef 写 {"smoothing_iters": 18, "gain": 0.35, "level": 1}
    # 例如 B-spline 写 {"control_points": [...], "degree": 3}
```

### 3.2 Generator 接口

```python
# oscrs/candidate_generators/base.py
from abc import ABC, abstractmethod

class CandidateGenerator(ABC):
    name: str                 # registry key（class attribute）
    paper_label: str          # 论文里出现的名字（class attribute）

    @abstractmethod
    def configure(self, params: dict) -> None:
        """从 yaml params dict 读取配置。在 ROS 节点 init 时调一次。"""

    @abstractmethod
    def generate(self, base: tuple[tuple[float, float], ...]) -> tuple[Candidate, ...]:
        """对 base 路径生成候选集合。

        契约：
          1. 返回元组（不可变），允许空元组（极端 fail-soft 场景）；
          2. Candidate.name 在返回集合内唯一；
          3. 至少包含一个名为 'original' 的候选（含义 = 不修改 base，
             用于 OSCRS fb=1 fallback 语义）；如果 generator 不能产 original
             则需在 configure 阶段抛错；
          4. 任何过滤（如 max_candidate_level）必须在 generator 内部完成；
          5. 不调用 S 层任何函数；不订阅 ROS topic；不发 ROS 消息。
        """
```

### 3.3 Registry

```python
# oscrs/candidate_generators/registry.py
_REGISTRY: dict[str, type[CandidateGenerator]] = {}

def register(cls):
    _REGISTRY[cls.name] = cls
    return cls

def build(name: str, params: dict) -> CandidateGenerator:
    if name not in _REGISTRY:
        raise KeyError(f"unknown generator: {name}; available={list(_REGISTRY)}")
    g = _REGISTRY[name]()
    g.configure(params)
    return g
```

各 generator 模块 import 时 `@register` 装饰自己；ROS 节点 init 一次性
`import oscrs.candidate_generators.georef_smoothing  # noqa: F401`
触发注册，再用 `build()` 拿实例。

### 3.4 选择器（S 层）

```python
# oscrs/selector.py
class OscrsSelector:
    """slosh-constrained candidate selector (S)"""

    def __init__(self, params: dict): ...
    def evaluate(self, base, candidates: tuple[Candidate, ...]) -> tuple[OscrsRow, ...]:
        # collision gate / forward v rollout / slosh ODE rollout / hard gate
        # tie-break by Candidate.name 字典序，不用 index
    def select(self, rows) -> Candidate: ...
    def safety_alarm(self, rows, geometry_best, published) -> str | None: ...
```

S 不 import G 的任何具体子类，只看 `Candidate` 数据。

### 3.5 ROS 节点（thin adapter）

```python
# scripts/anti_slosh_path_post_processor.py  (重构后 ~ 80 行)
class AntiSloshPathNode:
    def __init__(self):
        gen_type = rospy.get_param("~candidate_generator/type")
        gen_params = rospy.get_param("~candidate_generator/params", {})
        sel_params = rospy.get_param("~selector", {})
        self.generator = build(gen_type, gen_params)
        self.selector = OscrsSelector(sel_params)
        self.pub_path = ...
        self.pub_report = ...
        rospy.Subscriber("/scout/global_path", NavPath, self.path_callback)

    def path_callback(self, msg):
        base = points_from_path(msg)
        candidates = self.generator.generate(base)         # G
        rows = self.selector.evaluate(base, candidates)    # S
        best = self.selector.select(rows)
        self.pub_path.publish(...)
        self.pub_report.publish(...)
```

post_processor 退化为 ROS subscribe/call/publish 适配层，
不持有候选 specs、不持有 selector 内部逻辑、不持有 sanitize_points。

### 4.2 ROS / catkin / PYTHONPATH 注意事项

```text
1. scripts/oscrs/ 是 Python package，需要 __init__.py；
2. ROS rosrun 默认把 scripts/ 加入 sys.path，但子目录不会被自动识别为可 import 包；
   → setup.py (catkin_python_setup) 中显式声明 packages=['oscrs', 'oscrs.candidate_generators']
   → CMakeLists.txt 加 catkin_python_setup() 调用；
3. catkin install 会把 oscrs/ 装进 devel/lib/python3/dist-packages/；
4. 如果暂时不想动 catkin 配置，可以在 anti_slosh_path_post_processor.py 顶部
   加 sys.path.insert(0, os.path.join(os.path.dirname(__file__), '.'))，
   但这是临时方案，长期应走 catkin_python_setup。
```

风险：catkin_python_setup 配置错会导致 rosrun 找不到模块；
本方案启动后 Step 0 必须先在仿真链路验证 import 路径。

### 6.1 必须实现的：GeoRef smoothing

```text
class GeoRefSmoothingGenerator:
```

```text
class BsplineCorridorGenerator:

  paper_label = "B-spline Corridor"
```

### 6.3 论文若需 timing 维度：Timing Candidate

```text
class TimingCandidateGenerator:
  name = "timing"
  paper_label = "Timing Candidate"
```

## 7. 迁移分阶段

每个 phase 独立 commit，独立验收，可独立 revert。

```text
Phase 0：catkin_python_setup 配置打通（dry-run 一个空 oscrs 包能 rosrun import）
Phase 1：path_utils.py 抽出 sanitize_points / dist；G 与 post_processor 都从这里 import
Phase 2：oscrs/selector.py 抽出 S 层（OscrsSelector class）；
         post_processor 仍持有它的实例，行为不变
Phase 3：oscrs/candidate_generators/base.py + registry.py + georef_smoothing.py；
         post_processor 改用 build("georef_smoothing", params)
Phase 4：yaml 结构迁移 + 后向兼容垫片
Phase 5：post_processor 退化为 thin ROS adapter (~80 行)
Phase 6：(可选) 加第二个 generator (B-spline)，启动条件 [B] 触发
Phase 7：移除 backward-compat 垫片
```

每个 phase 验收：
- `python3 -m py_compile` 静态通过；
- 同 bag (5/9 三个 baseline) refactor 前后用 §6.2 序列 sanity 对照；
- Phase 0/1 还要补 `python3 -c "import oscrs; ..."` 路径测试。

## 10. 不在范围内的事（明确划界）

```text
× ROS 外部多 topic 候选发布（仍按 §9 旧方案理由不做）
× 自定义 ROS msg (CandidateArray 等)
× 改 MPC，引入 MPC 内防晃项
× 改 Ferrari oracle 接口
× 把 selector 也做成 plugin（OSCRS 是论文的方法主体，不应退到通用接口背后）
× 把 candidate_generator 拆成多 ROS 节点
× 用 pluginlib (C++) 做插件
```

理由：本方案焦点是 G 的可插拔，S 是论文方法主体不应抽象掉。
ROS / pluginlib / 多节点通信都属于 over-engineering，不解决论文层的诉求。

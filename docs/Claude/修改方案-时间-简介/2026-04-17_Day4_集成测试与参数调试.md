对每条 bag 运行：

```bash
rosrun scout_local_planner analyze_settling_day3.py \
  /data/a/slosh_bags/sim/day4_integration/<bag>.bag
```


重点记录：

- `/mpc/status_val success_ratio`
- `/mpc/solve_ms` p95
- `/risk_scheduler/u_k` p95
- `/risk_scheduler/fallback_active true_ratio`
- `/slosh/settling_time`
- `/slosh/height` p95
- `mpc_status` 是否出现 `ERROR`

当前残余问题：

- Day3 settling bag 中 `/mpc/status_val success_ratio=0.161`
- Day3 A/B/C smoke 中 B/C 的 success ratio 仍偏低

Day4 要判断低 success ratio 是：

1. 近终点恢复阶段 MPC 本身不可行
2. `SETTLING` 阶段 `Q_tracking=0` 后约束过紧
3. `risk_scheduler` 使 `Q_eta_k / eta_bar` 变化太激进
4. `slosh_use_imu_lateral_accel=true` 后 ay 激励过大
5. 状态码统计包含到达后空求解/停止段，导致 success ratio 被低估

## Step 4：参数快速试探

主方案给出的 Day4 参数范围：

| 参数 | 初始值 | 调整范围 |
|---|---|---|
| `gamma` | `5.0` | `[3, 10]` |
| `rho_0` | `0.3` | `[0.2, 0.5]` |
| `rate_limit_per_step` | `0.05` | `[0.02, 0.1]` |
| `Q_eta_min / Q_eta_max` | `0 / 当前 Q_slosh_max` | 保持当前量级 |
| `beta` | `0.3` | `[0.1, 0.5]` |
| `eps_eta` | `0.1 mm` | `[0.05, 0.2]` |

当前代码中的直接对应参数：

- `risk_scheduler/gamma`
- `risk_scheduler/rho_0`
- `risk_scheduler/rate_limit_per_step`
- `risk_scheduler/Q_eta_min`
- `risk_scheduler/Q_eta_max`
- `risk_scheduler/beta`
- `settling/eta_tol`
- `settling/eta_dot_tol`
- `settling/timeout_s`

建议 Day4 只做小规模仿真 sweep，不做大范围网格：

### 4.1 baseline

```bash
roslaunch scout_local_planner slosh_experiment_sim.launch \
  Q_slosh:=5.0 \
  slosh_use_imu_yaw_rate:=true \
  slosh_use_imu_lateral_accel:=true \
  risk_scheduler_enable:=true
```

### 4.2 保守风险调度

目标：降低 near-goal 约束激进程度，观察 QP 成功率是否提升。

建议临时参数：

- `gamma=3.0`
- `rho_0=0.4`
- `rate_limit_per_step=0.02`
- `beta=0.2`

如果 launch 暂不暴露这些参数，则 Day4 先通过 `rosparam set` 或新增 sim-only launch 参数实现。

### 4.3 放宽 settling 终止

目标：避免 settling 阶段过久或约束过紧。

建议临时参数：

- `settling/eta_tol=0.002`
- `settling/eta_dot_tol=0.05`
- `settling/timeout_s=3.0`

### 4.4 关闭 IMU ay 对照

目标：判断低 success ratio 是否由 IMU ay 激励过大引起。

```bash
roslaunch scout_local_planner slosh_experiment_sim.launch \
  Q_slosh:=5.0 \
  slosh_use_imu_yaw_rate:=true \
  slosh_use_imu_lateral_accel:=false \
  risk_scheduler_enable:=true
```

## Step 5：是否需要改 launch 参数暴露

如果 Day4 参数试探需要频繁修改 `risk_scheduler` 或 `settling` 参数，不建议直接改 YAML 多次。

已采用的方式：

- 在 `slosh_experiment_sim.launch` 中新增仿真专用 arg：
  - `risk_scheduler_gamma`
  - `risk_scheduler_rho_0`
  - `risk_scheduler_rate_limit_per_step`
  - `risk_scheduler_beta`
  - `risk_scheduler_Q_eta_min`
  - `risk_scheduler_Q_eta_max`
  - `settling_eta_tol`
  - `settling_eta_dot_tol`
  - `settling_timeout_s`
- 默认值保持 YAML 当前值
- 实物 launch 不改

保守风险调度可直接用：

```bash
roslaunch scout_local_planner slosh_experiment_sim.launch \
  Q_slosh:=5.0 \
  slosh_use_imu_yaw_rate:=true \
  slosh_use_imu_lateral_accel:=true \
  risk_scheduler_enable:=true \
  risk_scheduler_gamma:=3.0 \
  risk_scheduler_rho_0:=0.4 \
  risk_scheduler_rate_limit_per_step:=0.02 \
  risk_scheduler_beta:=0.2
```

放宽 settling 终止可直接用：

```bash
roslaunch scout_local_planner slosh_experiment_sim.launch \
  Q_slosh:=5.0 \
  slosh_use_imu_yaw_rate:=true \
  slosh_use_imu_lateral_accel:=true \
  risk_scheduler_enable:=true \
  settling_eta_tol:=0.002 \
  settling_eta_dot_tol:=0.05 \
  settling_timeout_s:=3.0
```

通过标准：

- 仿真参数 sweep 可通过 launch 参数完成
- 不影响实物默认行为

## 1. 唯一目标

把候选生成（candidate generation）从 OSCRS 主流程（`path_callback`）中抽出来，
让代码结构上反映论文方法层 `OSCRS = G + S` 的两层划分。

```text
方法层（论文写）：
  G : 候选生成器        当前实例 = GeoRef smoothing
  S : OSCRS 选择器       hard gate + batch-norm score + fallback

实现层（代码现状）：
  G 与 S 全部混在 anti_slosh_path_post_processor.path_callback() 里。

实现层（本方案目标）：
  G 是一个独立模块函数 generate_georef_candidates(...)；
  S 留在 post_processor，调用 G 拿到候选集合，再做后续选择。
```

**本方案不做**：

```text
1. 不引入 CandidateGenerator 抽象基类；
2. 不引入 Candidate dataclass；
3. 不引入 PassthroughGenerator 或任何"为未来"的实例；
4. 不增加 launch arg / yaml 字段；
5. 不重命名既有函数 / 不调整 candidate_specs 形态；
6. 不改 OSCRS rollout / score / hard gate / fallback 任何一行。
```

依据：CLAUDE.md §2 简洁优先 + §3 外科手术式修改。当前只有一个 generator 实例，
抽 class 层级是过早抽象；等真要接 B-spline / timing candidate 时再升级到接口形态。

## 4. 接口设计（最小）

### 4.1 函数签名

`scripts/candidate_generators.py`：

```python
"""候选生成器 G 的运行时实例。

OSCRS 在方法层定义为 G + S 两层结构（见 RA-L 投稿方案 §3）：
    G : 候选生成器，当前实例 = GeoRef smoothing
    S : slosh-constrained 候选选择器（OSCRS proper，留在 post_processor）

本模块只承担 G。S 与 hard gate / score / fallback 仍在 post_processor 内。
"""

from generate_anti_slosh_path_candidates import smooth_path


def generate_georef_candidates(base, candidate_specs, min_segment_length, sanitize_fn):
    """对 base 路径生成 GeoRef smoothing 候选集合。

    Args:
        base: list[(x, y)] 已 resample 过的基础路径。
        candidate_specs: list[(name, iters, gain, drift_limit)]，
            与 post_processor.candidate_specs 同构。name == "original" 时不平滑。
        min_segment_length: float, sanitize 阈值。
        sanitize_fn: callable(points, min_seg) -> points，复用 post_processor.sanitize_points
            （避免本文件再 import post_processor，方向相反才对）。

    Returns:
        list[(name, points)]，顺序与 candidate_specs 严格一致（同分时 OSCRS 取最先）。
    """
    out = []
    for name, iters, gain, drift_limit in candidate_specs:
        if name == "original":
            pts = base
        else:
            pts = smooth_path(base, int(iters), float(gain), float(drift_limit))
            pts = sanitize_fn(pts, min_segment_length)
        out.append((name, pts))
    return out
```

接口约束（必要的几条，全部能从代码静态读出）：

```text
1. 返回顺序与 candidate_specs 一致——OSCRS 同分取最先依赖此性质；
2. "original" 必须按照 spec 表中位置出现（当前在第 0 位）；
3. 不返回 row / score / 任何 OSCRS 中间量——本函数只产候选，不评估。
```

## 5. 论文叙事对齐

完成后论文 §3 可以写成：

```text
§3.1 Candidate Generation.
    We define a candidate generator G : R -> 2^R that maps a raw global
    reference R to a finite set of dynamically executable alternatives.
    In this work, G is instantiated as an online GeoRef smoother that
    produces 5 candidates with monotonically increasing smoothing strength
    {original, mild, medium, mid, strong}.

§3.2 Slosh-Constrained Candidate Selection (OSCRS).
    Given C = G(R), the selector S applies a two-layer procedure:
    a hard feasibility gate (collision + slosh height + residual) and a
    batch-normalized weighted score over the remaining feasible set.
    Fallback semantics are defined for the case where the gate eliminates
    all candidates other than original (fb=1).
```

- apply_oscrs_score() / select_oscrs_candidate() in

## 6. 验收（硬标准）

### 6.1 函数级数值等价性测试（核心硬标准）

不在 ROS 仿真重跑层做 hash，而在**函数层做 numeric exact equality**——
因为本 refactor 本质是同段代码搬家，不应当引入任何浮点 drift。
ROS 仿真重跑会受 timing / TF / costmap 时间戳非确定性影响，hash 等价不可达。

新增 `scripts/test_candidate_generators_equivalence.py`：

```python
import sys
sys.path.insert(0, "src/scout_apps/control/scout_local_planner/scripts")
from generate_anti_slosh_path_candidates import smooth_path
from anti_slosh_path_post_processor import sanitize_points
from candidate_generators import generate_georef_candidates

base = [(0.0, 0.0), (0.5, 0.1), (1.0, 0.3), (1.6, 0.2),
        (2.2, -0.1), (2.8, -0.4), (3.4, -0.5), (4.0, -0.5)]
specs = [
    ("original", 0, 0.0, 0.0),
    ("mild",   18, 0.35, 0.08),
    ("medium", 40, 0.45, 0.12),
    ("mid",    24, 0.30, 0.07),
    ("strong", 56, 0.55, 0.18),
]
min_seg = 0.08

# 旧路径：复刻 path_callback line 476-481 的内联循环逻辑
expected = []
for name, iters, gain, drift_limit in specs:
    if name == "original":
        pts = base
    else:
        pts = smooth_path(base, int(iters), float(gain), float(drift_limit))
        pts = sanitize_points(pts, min_seg)
    expected.append((name, pts))

actual = generate_georef_candidates(base, specs, min_seg, sanitize_points)

assert len(actual) == len(expected)
for (na, pa), (ne, pe) in zip(actual, expected):
    assert na == ne
    assert len(pa) == len(pe)
    for (xa, ya), (xe, ye) in zip(pa, pe):
        assert xa == xe and ya == ye, f"{na}: numeric drift"
print("OK")
```

通过条件：脚本 stdout 输出 `OK`，无 AssertionError。
这是**必过**项——本 refactor 是代码搬家，逐点 float 精确相等是天然性质。

### 6.2 仿真重跑序列 sanity（不比 hash，比关键序列分布）

承认 ROS 重跑有 timing / TF / costmap 时间戳的非确定性。
**不**比 candidate_report 全文 hash，**不**比 path 点 hash，**不**比时间戳。
比 OSCRS 行为层面的关键序列：

```text
对照集（refactor 前后各跑 1 次）：
  SCENARIO=open_user_goal      CONDITION=GEOREF_OSCRS_ACTIVE
  SCENARIO=open_custom_goal    CONDITION=GEOREF_OSCRS_ACTIVE

提取并比较以下序列（容许周期数 ±1 偏差）：
  selected.name 序列                    应当一致或 |差异周期| ≤ 1
  oscrs.active 序列分布                  应当一致或差异 ≤ 1 周期
  fb code 直方图                         应当完全一致
  hard gate 命中候选名集合                应当完全一致
  geometry_best 与 oscrs_best 分歧周期数  应当完全一致

容许差异（属于 ROS 时序而非 refactor 引入）：
  各候选 score 数值在 e-12 量级浮点尾差
  时间戳字段
  /scout/global_path_anti_slosh stamp 序列
```

如果 6.1 通过但 6.2 出现行为差异（fb 直方图不一致），
那是 ROS 时序或 OSCRS 内部状态依赖，本 refactor 不背锅；
如实记录到 `docs/Claude/修改日志-时间/2026-05-09.md`，不阻塞 merge。

## 9. 与实物时序的关系

本方案改动面足够小（净 +2 行业务代码 + 1 新文件 30 行 + 0 新参数 + 0 新 mode），
**可以在实物 baseline 录制之前完成**。理由：

```text
1. 函数级等价性测试 (§6.1) 锁死"代码搬家无 drift"，逐点 float 精确相等；
2. 仿真行为 sanity (§6.2) 比序列分布而非 hash，承认 ROS 时序非确定性；
3. 不引入新 control flow（无 Passthrough、无 launch arg 分支）；
4. 不改任何 yaml、不改任何 launch；
5. 单文件 git revert 即可回退；
6. 实物 baseline 收的数据带的 commit hash 在 refactor 之后，
   论文方法节代码引用与实验数据的 git 状态一致。
```

如果 §6.1 函数级等价性 fail，**立刻 revert** 后再开始实物——
代码搬家就该 numeric exact equal，fail 说明 refactor 引入了不该有的差异。
§6.2 出现序列差异不阻塞 merge，但要在日志中如实记录。
本方案不阻塞实物时间表。

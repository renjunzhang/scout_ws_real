# 2026-04-19 对比算法方案：ISR 基线实现与验证

> 日期：2026-04-19
> 目标：补齐论文对比算法缺口，在不改 MPC 主体的前提下，实现经典 `ZV input shaping` 基线，用于后续论文对比实验。

---

## 0. 背景与约束

根据

- `docs/Claude/总结/论文提纲.md`

当前论文对比结构存在明显缺口：

- 现有 `C0 ~ C5` 基本都是自消融；
- 缺少外部文献级 baseline；
- 审稿时容易被质疑“仅与自己方法内部变体比较”。

当前最短、最稳的补位方案是：

- 增加 `ISR / ZV input shaping` 基线；
- 不改 MPC 主体；
- 只在参考速度层引入 shaping；
- 与 `NOM / Fixed-Q / PROP` 形成最小可发表对比组。

本次不扩展到第二个外部算法，不重开控制主线。

## 1. 方案目标

新增一个可独立开关的 ISR baseline，用于后续实验和论文表格：

- `NOM`：无 slosh 抑制
- `ISR`：经典 ZV input shaping
- `FAS`：固定 `Q_eta` MPC
- `PROP`：完整方法

本次目标不是“把 ISR 做得最优”，而是：

1. 实现一个定义清晰、可复现、可稳定运行的经典基线；
2. 保证它不污染当前 PROP 主线；
3. 后续能用同一条实验链直接跑对比。

---

## 2. ISR 基线定义

采用二脉冲 ZV shaper：

```text
v_shaped(t) = A1 * v_ref(t) + A2 * v_ref(t - t1)

A1 = 1 / (1 + K)
A2 = K / (1 + K)
K  = exp(-zeta * pi / sqrt(1 - zeta^2))
t1 = pi / omega_d
omega_d = omega_0 * sqrt(1 - zeta^2)
```

其中：

- `omega_0` 与 `zeta` 来自当前 slosh 模态参数；
- shaping 只作用于参考速度；
- 不修改内部 MPC 代价、约束、求解结构。

### 2.1 ISR 相对当前基线实际改变的内容

ISR 相对当前 `NOM` / 当前主线基线，**只改变一件事**：

- 对送入 MPC 的参考速度 `v_ref` 做 ZV input shaping

不改变以下内容：

- 路径几何：`x / y / theta_path / kappa / s`
- MPC 状态定义
- MPC 控制量定义
- MPC 代价函数
- MPC 约束
- risk scheduler
- settling / terminal recovery 主逻辑

可理解为：

```text
原始参考速度 v_ref
        ↓
ZV input shaping
        ↓
v_ref_shaped
        ↓
MPC 跟踪 shaped 后的参考
```

因此 ISR 的论文定位应明确写成：

- `reference-side classical baseline`
- 而不是另一套 MPC 控制器

## 3. 实现边界

### 3.1 允许修改

- `PathHandler` 或参考速度生成链路
- 仿真/实验配置项
- 实验脚本与分析脚本
- 论文提纲里的对比表述

### 3.2 不修改

- MPC 状态维度
- MPC 约束形式
- risk scheduler 主逻辑
- settling / terminal recovery 主逻辑

### 3.3 开关要求

必须有明确开关，默认关闭：

- `input_shaping/enable`
- `input_shaping/type = zv`

且要求：

- `PROP` 默认不启用 ISR；
- ISR baseline 单独运行；
- 不与 adaptive Q、risk scheduler、额外补丁耦合成混合方法。

## 4. 代码落点

优先实现路径：

1. 在参考速度生成处，对 `v_ref` 做 shaping
2. 使用环形缓冲保存延迟项
3. 每周期输出 shaped 后的速度参考

建议落点：

- `src/scout_apps/control/scout_local_planner/src/path_handler.cpp`
- 或 `LocalPlannerROS` 中调用 `getReferencePoints()` 后、送入 MPC 前的参考速度处理层

选择原则：

- 尽量不入侵 MPC 主体；
- 尽量不破坏当前 `v_plan / v_exec` 解耦；
- 尽量保持 ISR 与 PROP 只在“参考层策略”上不同。

## 8. 是否需要加入 LQR baseline

当前结论：**暂不加入 LQR baseline。**

原因：

1. 当前论文的直接缺口是“没有外部经典 anti-slosh baseline”，ISR 已经能补这个缺口；
2. 若加入 LQR，需要额外定义：
   - 线性化点
   - 路径跟踪误差模型
   - 与当前速度规划、终点状态机、参考层的耦合方式
3. LQR 实现成本明显高于 ISR，且容易把范围扩成“另一套控制器重实现”；
4. 对当前阶段而言，ISR 已经是最短、最稳、最容易被审稿人接受的经典对比项。

因此当前策略是：

- 先做 `NOM / ISR / FAS / PROP`
- 不新增 LQR

只有在后续论文评审预期或实验结果明确表明：

- ISR 与 PROP 区分度不足，
- 且确实需要一个“经典反馈控制”对照，

才再单独评估是否加入 LQR。

# 2026-04-29 PMG 离线验证设计

## 1. 结论

下一步不再继续在 MPC QP 内增加 `slosh cost / slosh constraint`，也不继续扫固定阈值 `OUTPUT_GUARD`。

候选方向是 `PMG`（Predictive Modal Guard）：基于当前横向模态状态 `(eta_y, eta_y_dot)` 和 signed 横向输入 `u_y = v * omega`，预测短时间窗口内的 signed `eta_y(t)`，只在未来峰值会越界时限制最终发布的 `cmd_omega`。

PMG 必须先离线证伪，通过后才允许写 C++ 控制器代码。

## 2. 当前模型事实

当前 `mpc_params.yaml` 与 `mpc_params_sim.yaml` 的 slosh 参数一致：

```yaml
slosh:
  container_radius: 0.0185
  liquid_height: 0.058
  damping_ratio: 0.05
```

由代码公式计算：

```text
omega_n = sqrt(g * xi_11 / R * tanh(xi_11 * h / R))
xi_11 = 1.8412
omega_n = 31.25 rad/s
f_n = 4.97 Hz
zeta = 0.05
```

事实判断：

- `omega_n` 目前来自几何公式，不是从 04-27/04-28 仿真 bag 中重新辨识得到；
- `zeta=0.05` 是 37 mm 试管采集阶段初值；
- 当前仓库文档里有自由衰减辨识流程，但没有找到带残差或置信区间的 37 mm `omega_eff / zeta_eff` 结果；
- 因此 PMG 不能直接作为“已校准模型控制器”进入闭环，只能先作为离线候选策略验证。

## 3. 必须修正的 PMG 定义

PMG 不允许退化成幅值 guard。

错误形式：

```text
if abs(predicted_eta_peak) > threshold:
    cap abs(v * omega)
```

正确形式：

```text
predict signed eta_y(t+s), s in [0, tau]
eta_min = min_s eta_y(t+s)
eta_max = max_s eta_y(t+s)

accept only if:
  eta_min >= -eta_threshold
  eta_max <=  eta_threshold
```

限幅必须是 signed 的：

- `eta_y > 0` 且 `eta_y_dot > 0`：正在冲正峰，主要限制会继续推高正峰的 `u_y`；
- `eta_y < 0` 且 `eta_y_dot < 0`：正在冲负峰，主要限制会继续推低负峰的 `u_y`；
- `eta_y` 与 `eta_y_dot` 异号：处于回零相位，不应一刀切削掉可抵消激励。

第一版只做 lateral：

```text
state: eta_y, eta_y_dot
input: u_y = v * omega
output cap: cmd_omega
```

不扩展 `eta_x`，不同时处理 longitudinal。

PMG v1 只限制 `cmd_omega`，不改 `cmd_v`：

- `u_y = v * omega` 的下降先由 `omega` 单通道承担；
- `cmd_v` 不动可以最大程度保留路径跟踪能力；
- 避免把 PMG 和 path/profile 层耦合在一起；
- 若后续发现低速大转角下 `omega` 已经限不住 `u_y`，再讨论 v2 是否同时限 `cmd_v`。

## 4. PMG 算法常数

脚本实现必须显式固定以下口径：

```text
tau: 2*pi / omega_d，约 0.20 s；同时扫 0.10 / 0.20 / 0.40 s
eta_threshold: 每条路径用 NOM 主段 eta_max_p95，不使用凭空固定阈值
u_now: tau 内保持当前 odom_v * odom_omega 不变
cap solver: 单变量解析求解 signed u_y 上下界，不使用 bisection
```

说明：

- `tau` 取一个阻尼振荡周期作为主口径，额外两个窗口用于敏感性检查；
- `eta_threshold` 绑定同一路径 NOM 主段统计，避免 P2/P3 因路径难度不同产生不可比阈值；
- `u_now` 用 odom 口径，是为了测试执行层实际激励，而不是计划层激励；
- 由于线性二阶系统对标量 `u_y` 是线性的，`eta_min/eta_max` 对 `u_y` 的可行区间可以直接求交，不应引入迭代求解误差。

## 5. Step 0：模型与 replay 可信度复核

目的：先证明 counterfactual replay 自己可信，否则 PMG replay 数字没有意义。

输入：

- 当前配置：`omega_n=31.25 rad/s`，`zeta=0.05`
- 已有仿真 bag 中的 `/slosh/state`、`/slosh/height`、`/slosh/ay_est`、`/odom`
- 可选实物视觉数据：红色液体视觉高度时序

主段切片必须使用：

```text
/mpc_status == TRACKING AND /terminal/mode == NONE
```

不得把 terminal recovery / settling 段混入 PMG replay。

### 5.1 Baseline reconstruction 校准

对每份 bag：

```text
读取 /slosh/ax_est 与 /slosh/ay_est
用当前 omega_n=31.25, zeta=0.05 重放 lateral slosh 动力学
得到 reconstructed eta_x / eta_x_dot / eta_y / eta_y_dot / h
与 bag 内 /slosh/state 和 /slosh/height 对比
```

判据：

- 若 reconstructed `h_p95` 与 bag 内 `/slosh/height p95` 偏差 `> 15%`，该 bag 的 counterfactual replay 不可信；
- 若多数 bag 偏差 `> 15%`，Step 0 失败，PMG 路线暂停；
- 若偏差 `<= 15%`，counterfactual 框架可继续用于 PMG replay。

补充检查：

```text
再用 odom_v * odom_omega 作为 u_y 做执行代理 replay
```

该检查不替代 `/slosh/ay_est` baseline。它用于判断“最终输出层 cap 后的 cmd/odom 能否可靠映射到 slosh 输入”。若 odom 口径大面积失败，说明 PMG 不能直接把 `cmd_v*cmd_omega` 当作可信未来输入，必须先定义从 output cap 到 `/slosh/ay_est` 的 counterfactual 映射。

### 5.2 ay 输入映射

PMG v1 是 lateral-only，但 `/slosh/height` 仍由 `sqrt(eta_x^2 + eta_y^2)` 得到。因此 Step 1 replay 必须分通道处理：

```text
eta_x 通道：继续使用记录的 /slosh/ax_est 重放，不做 counterfactual
eta_y 通道：用执行代理构造 counterfactual /slosh/ay_est
```

当前 11 包 Step 0C 结果：

```text
odom_v*odom_omega -> /slosh/ay_est:
  corr mean = 0.9585
  slope mean = 0.8766
  best_lag mean = 0.0955 s

cmd_v*cmd_omega -> /slosh/ay_est:
  corr mean = 0.8658
  slope mean = 0.4405
  best_lag mean = 0.1455 s
```

因此 Step 1 首选输入映射：

```text
ay_proxy(t) = 0.88 * odom_v(t - 0.10) * odom_omega(t - 0.10) + b
```

其中 `b` 暂按每包拟合 intercept 使用；若 intercept 量级小于 `ay_p95` 的 5%，可置 0 简化。

不能直接使用：

```text
ay_proxy = cmd_v * cmd_omega
```

原因是 cmd 映射相关性和 scale 都明显差于 odom 映射。

### 5.3 omega_n / zeta 置信度复核

1. 用现有 bag 的 `/slosh/state` 做自由响应片段或低输入片段拟合；
2. 估计主频 `omega_eff` 与阻尼 `zeta_eff`；
3. 若可辨识，给出相对当前 `31.25 rad/s / 0.05` 的偏差。

自由响应片段优先口径：

```text
|cmd_v| < 0.05 m/s
|cmd_omega| < 0.10 rad/s
持续 >= 0.5 s
```

如果没有足够片段：

- 备选 a：用强制响应做频域系统辨识，检查 `FFT(eta_y) / FFT(v*omega)` 的主峰；
- 备选 b：补一次专项自由衰减实验：短 step 激励后立即归零，录 3~5 s。

判定：

- 若 `omega_eff` 或 `zeta_eff` 不确定性明显超过 ±15%，PMG 路线暂停；
- 若没有足够自由衰减片段，不能伪造置信区间，只能记录“缺少辨识证据”，并转向视觉真值或专门辨识实验；
- 若不确定性在 ±15% 内，再进入 Step 1。

### 5.4 参数鲁棒性扫描口径

只做真实鲁棒性测试：

```text
PMG 内部使用扰动参数 omega_tilde / zeta_tilde
reconstruction 仍使用 baseline 参数 omega_n=31.25 / zeta=0.05
```

不做“PMG 和 reconstruction 同时使用扰动参数”的扫描，因为那只是参数敏感度，不是模型偏差鲁棒性。

## 7. 离线验收标准

PMG 进入 C++ 前必须同时满足：

1. P2 replay 不劣于 fixed `OUTPUT_GUARD`；
2. P3 replay 相比 fixed `OUTPUT_GUARD` 降低 `cmd_dwz_abs_integral` 或模态能量 proxy；
3. P3 的 PMG 触发窗口必须不同于 fixed `OUTPUT_GUARD`；
4. `omega_n/zeta` ±20% 扫描下，触发结论不能翻转。

第 3 条量化为：

```text
P3 PMG 触发与 fixed OUTPUT_GUARD 触发的时间重合率 < 60%
AND
PMG 平均触发提前量与 fixed OUTPUT_GUARD 的差异 > 0.15 s
```

若触发窗口几乎一样，说明 `(eta_y, eta_y_dot)` 没有提供新增信息，即使 replay 数字看起来改善，也不能进入 C++。

解释口径：

- replay 不好：直接否决 PMG；
- replay 好：只代表可以进入仿真闭环，不代表实物有效。

## 8. 方案能实现什么

无论 PMG 是否通过，都会产出：

- 当前 37 mm 配置 `omega_n / zeta` 的辨识可信度检查；
- baseline counterfactual replay 可信度；
- PMG 在 P2/P3 既有 bag 上的离线触发和 replay 数据；
- PMG 是否值得进入 C++ 的可证伪结论。

如果通过：

- 只允许实现默认关闭的 lateral-only PMG；
- C++ 改动应集中在发布前输出层；
- 仿真闭环只补 P2/P3 各 2 包，不再盲目录制。

如果不通过：

- 不写控制器代码；
- 转向真实液面视觉、P3 路径可达性或专项自由衰减辨识。

边界：

- 不能证明 PMG 实物有效；
- 不能替代红色液体视觉真值；
- 不能保证新路径泛化；
- 不能解决 path_handler / 路径跟踪误差本身。

## 12. P3 失败假设诊断结果

已新增并运行：

```text
src/scout_apps/control/scout_local_planner/scripts/diagnose_p3_failure_modes.py
```

结论：

```text
P3 的 /slosh/height 峰值几乎完全由 eta_x 通道主导。
```

关键数值：

```text
P2_s_curve NOM eta_x energy ratio:          0.484
P2_s_curve OUTPUT_GUARD eta_x energy ratio: 0.660

P3_mixed NOM eta_x energy ratio:            0.975
P3_mixed OUTPUT_GUARD eta_x energy ratio:   0.979
```

排查结果：

- H1 成立：P3 主导模态是 longitudinal `eta_x`；
- H2 不成立：`/slosh/height` 与 reconstructed height 在模型内部高度一致；
- H3 不成立：P3 的 `cmd_omega - odom_omega` 误差低于 P2；
- H4 不成立：P3 主段没有明显 `status_val` fail 或 recovery 参与。

因此 PMG 负结论的原因不是“相位窗口还没调好”，而是控制对象错了：

```text
lateral-only guard 主要影响 eta_y，
但 P3 的模型 height peak 几乎全由 eta_x 决定。
```

下一步不应直接把 PMG 扩展到 longitudinal 控制器。应先做 longitudinal 输入来源诊断：

- `eta_x` 峰前 `ax_est` 来自速度加减速、terminal 速度变化，还是路径跟踪导致的 v 波动；
- P3 的速度剖面和目标点生成是否让纵向加减速集中在液体同相区间；
- 实物视觉是否也显示 P3 真实液面主要是 longitudinal 晃动。

## 15. Longitudinal 鲁棒性与 combined 决策

新增离线验证：

```text
offline_pmg_replay.py --longitudinal-replay --pmg-omega-scale <scale>
offline_pmg_replay.py --longitudinal-replay --pmg-zeta-scale <scale>
offline_pmg_replay.py --combined-replay
```

鲁棒性扫描采用不对称口径：

- PMG predictor 内部使用扰动参数；
- counterfactual reconstruction 仍使用基准参数；
- 因此测试的是“模型参数估计偏差下 PMG 是否仍有效”。

Longitudinal PMG 结果：

```text

  omega_n * 0.8: -41.16%
  omega_n * 1.2: -17.86%
  zeta * 0.8:    -16.46%
  zeta * 1.2:    -19.92%
```

判定：

- 最弱扰动仍有 `-16.46%` 以上改善；
- 达到“P3 NOM h_p95 改善仍 ≥ 10%”门槛；
- longitudinal PMG 路线不因 `omega_n / zeta` ±20% 偏差被否决。

Combined replay 结果：

```text

  longitudinal-only: -6.75%
  combined:          -12.98%

P2_s_curve OUTPUT_GUARD:
  longitudinal-only: -17.68%
  combined:          -19.94%

P3_mixed NOM:

  combined:          -19.00%

  longitudinal-only: -19.14%

```

判断：

- combined PMG 在 P2/P3 都不劣于 longitudinal-only；
- P2 NOM 的增益明显，说明 y 通道仍有价值；

# 2026-06-03 RGB 在线识别前端隔离方案

## 0. 结论

建议做一个独立前端，但前端只负责显示与现场监控，不参与检测、不参与控制、不写入 planner 逻辑。

三条原则：

```text
隔离: 前端只订阅话题，不反向影响 /liquid/*、/spmpc/*、/cmd_vel。
美观: 一屏看清 RGB overlay、液面曲线、模型预测、控制状态。
方便实物实验: 启动简单、退出不影响 RealSense、录包话题与离线分析口径一致。
```

## 1. 当前数据链

现有在线检测节点：

```text
online_liquid_height_node.py
  input:
    /camera/color/image_raw
    当天 calibration.yaml

  output:
    /liquid/height          # max(left, center, right), mm
    /liquid/height_lcr      # [left, center, right], mm
    /liquid/height_median   # median-LCR, mm
    /liquid/debug_image     # overlay, optional
```

SPMPC 侧已有：

```text
/spmpc/status
/spmpc/solver_backend
/spmpc/slosh_height
/spmpc/slosh_horizon_summary
/spmpc/cost_breakdown
/spmpc/solver_time_ms
/spmpc/debug/progress_s
/cmd_vel
/odom
```

论文真值仍以离线 `red_liquid_infer_from_bag.py` 为准。在线前端只用于现场判断和排错。

说明：上述话题**均为已发布量**，前端是纯消费者(只订阅、不新发任何控制/感知话题)。
单位：`/liquid/*` 与 `/spmpc/slosh_height`、`slosh_horizon_summary` 的高度字段现都已统一为 **mm**，可同图并排；但 `/liquid/*` 是 RGB proxy、`/spmpc/*` 是模型 proxy，均非真值。

## 2. 推荐前端形态

第一版不要做复杂 Web 服务，建议做一个独立 ROS Python 前端：

```text
scripts/liquid_experiment_monitor.py
```

依赖：

```text
rospy
cv_bridge
OpenCV HighGUI 或 matplotlib animation
```

启动：

```bash
roslaunch realsense_liquid_measurement online_liquid_height.launch \
  calibration:=<当天 calibration.yaml> publish_debug:=true

rosrun realsense_liquid_measurement liquid_experiment_monitor.py
```

如果 OpenCV 窗口退出会影响相机进程，则前端必须只订阅 `/liquid/debug_image`，不能直接打开 RealSense 设备，也不能创建/销毁 RealSense pipeline。

## 3. UI 布局

一屏四块：

```text
┌──────────────────────────────┬──────────────────────────────┐
│ RGB overlay                  │ liquid height history         │
│ /liquid/debug_image          │ /liquid/height + L/C/R        │
├──────────────────────────────┼──────────────────────────────┤
│ SPMPC status                 │ control / model diagnostics   │
│ variant/backend/status/ms    │ cmd_v, odom_v, slosh_height   │
└──────────────────────────────┴──────────────────────────────┘
```

显示内容：

```text
RGB:
  overlay 图像
  ROI / tube wall / L-C-R 三列

液面:
  max-LCR 曲线
  L/C/R 三列细线
  当前值、最近 5s peak、最近 5s p95

SPMPC:
  status
  solver_backend
  solver_time_ms
  progress_s
  h_peak_pred / h_p95_pred

控制:
  cmd_v
  odom_v
  简单 ax = d(odom_v)/dt
```

## 4. 隔离规则

前端禁止做这些事：

```text
1. 不订阅后重新发布 /cmd_vel；
2. 不修改 dynamic_reconfigure 相机参数；
3. 不调用 rosservice 去 reset RealSense；
4. 不写 /spmpc/* 参数；
5. 不参与 bag 录制控制；
6. 不把在线曲线作为论文最终统计结果；
7. 不依赖 / import 任何控制包(scout_local_planner / spmpc_local_planner)：
   前端住在 realsense_liquid_measurement，控制包对它零依赖，杀掉前端不影响 planner。
```

前端允许做这些事：

```text
1. 订阅并显示图像和曲线；
2. 本地保存现场 screenshot；
3. 输出一个轻量 CSV log 到用户指定目录；
4. 根据话题缺失显示红色告警。
```

## 5. 实物实验便利性

现场需要快速判断：

```text
相机是否有图；
ROI/HSV 是否明显跑偏；
液面曲线是否有 NaN；
/spmpc/status 是否在正常求解；
solver_time_ms 是否超过 30Hz 控制周期；
在线 RGB peak 是否明显爆掉。
```

前端应提供明显状态灯：

```text
CAMERA OK / LOST
LIQUID OK / NAN
SPMPC OK / FAIL
SOLVER < 33ms / SLOW
BAG RECORDING unknown   # 第一版不接管 rosbag，只显示 unknown 或手动备注
```

## 6. 与离线分析的关系

在线前端只用于现场监控。正式报告流程仍是：

```text
bag -> red_liquid_infer_from_bag.py -> per-frame RGB height CSV
    -> 组间统计 / 图表 / Ferrari-style 指标
```

前端显示的 `/liquid/height` 可以作为现场 smoke 指标，但不替代离线平滑、窗口切分和质量检查。

## 7. 第一版实现任务

```text
1. 新增 liquid_experiment_monitor.py；
2. 只订阅已有话题，不新开相机；
3. 使用 /liquid/debug_image 作为画面源；
4. 保留最近 10-20s ring buffer；
5. 支持 q 退出，退出只关闭前端窗口，不 shutdown 其他 ROS 节点；
6. launch 单独放在 realsense_liquid_measurement/launch/liquid_monitor.launch；
7. 不和 online_liquid_height_node.py 合并。
```

## 8. 后续可选

如果 OpenCV 窗口仍然和实物桌面环境冲突，再换成浏览器前端：

```text
rosbridge_server + lightweight web dashboard
```

但第一版不建议直接做 Web。当前目标是实物实验现场稳定、轻量、可快速退出。

# 2026-04-23 固定路径重放与模板轨迹生成评估

## 结论

今天针对两个现场需求做了代码级判断：

1. **固定路径 replay 起点门控**
2. **点击终点自动生成模板轨迹**

判断结果：

- 起点门控问题优先通过 `manual-start` 解决，而不是继续强化自动回起点
- 模板轨迹生成应作为新工具实现，不建议继续塞进 `fixed_global_path_runner.py`

---

## 1. 固定路径 replay 起点门控

核对文件：

- `src/scout_apps/control/scout_local_planner/scripts/fixed_global_path_runner.py`

已存在能力：

- `--skip-start-wait`
- `--publish-start-goal`

说明当前脚本并非完全不能绕开起点等待，但对实物仍不够顺手。

### 现状问题

- `--skip-start-wait` 会立即 replay，不适合人工摆位
- `--publish-start-goal` 只是发起点，不是“到位后我手动确认开始”

### 今日判断

实物实验里，最合理的不是要求机器人自动精准回到 capture 时的起点，而是：

- 研究者自己把机器人摆到合适位置
- 然后显式触发 replay

因此，最小且有效的改动应是：

- 新增 `--manual-start`

---

## 2. 模板轨迹自动生成

需求是：

- 站在空旷区
- 点击一个终点
- 自动生成：
  - `straight`
  - `single_turn`
  - `s_curve`
  - `mixed`

### 今日判断

不建议把这个能力揉进 `fixed_global_path_runner.py`。

原因：

- fixed path runner 的职责是 capture/replay
- 模板轨迹生成属于另一类功能：由起终点直接构造标准化路径几何

因此更合理的结构是：

- 新建 `template_fixed_path_generator.py`

---

## 3. 推荐实施顺序

### 第一优先级

改现有脚本：

- `fixed_global_path_runner.py`
- 增加 `--manual-start`

目的：

- 明天实物 fixed-path 验证可以直接受益

### 第二优先级

新增新脚本：

- `template_fixed_path_generator.py`

第一版先做：

- `straight`
- `single_turn`
- `s_curve`

### 第三优先级

再更新验证文档与 README。

---

## 4. 今日落地结果

今天已完成第一版代码落地：

### `fixed_global_path_runner.py`

- 新增 `--manual-start`
- 默认行为未改
- 解决的问题是：
  - 实物场景下不必一启动就 replay
  - 可以先人工摆位，再按 Enter 开始

### `template_fixed_path_generator.py`

新增独立模板路径生成脚本：

- 输入：当前机器人位姿 + 点击终点
- 输出：`/scout/global_path_fixed`
- 当前支持：
  - `straight`
  - `single_turn`
  - `s_curve`
  - `multi_s`
  - `sharp_turn`

### 当前判断

- 起点等待问题属于实验工具链问题，不是 MPC 本体问题
- `manual-start` 是最小且实用的修正
- 模板路径自动生成已具备第一版可用形态，适合明天现场先试
- 如果第一版模板效果不够理想，下一步优先调模板控制点，不要先把脚本复杂化

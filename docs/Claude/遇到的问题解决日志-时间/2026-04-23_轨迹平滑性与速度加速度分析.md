# 2026-04-23 轨迹平滑性与速度加速度分析

## 1. 背景

对 2026-04-22 首批 10 个实物红色液体 bag 做轨迹对比分析，聚焦路径形状、速度剖面、加速度和 jerk 的组间差异。

数据：`/data/a/slosh_bags/real/0422`

## 2. 分析脚本

脚本：`src/scout_apps/control/scout_local_planner/scripts/trajectory_analysis.py`

输出目录：`/data/a/traj_analysis_0422/`

### 输出文件

| 文件 | 内容 |
|---|---|
| `trajectory_overlay.png` | 全部 10 条轨迹归一化叠加（起点平移到原点，初始朝向对齐 +x） |
| `trajectory_block_compare.png` | block1（各控制条件）vs block2（Q sweep）分组对比 |
| `speed_accel_panel.png` | v / a / \|jerk\| / ω vs 路径弧长，4 格总览图 |
| `speed_time_series.png` | 速度时序：TRACKING 段 odom_v + 全程 cmd_v |
| `omega_time_series.png` | 角速度时序 |
| `metrics_table.png` | 指标汇总表 |
| `metrics_summary.csv` | 数值结果 CSV |

### 方法说明

- 轨迹归一化：平移到起点为原点，旋转使初始航向为 +x，消除不同包的起点和朝向差异
- 加速度：对 odom_v 做 7 点滑动均值后取中心差分，再做 9 点均值平滑
- jerk：对加速度序列再次差分 + 平滑
- 弧长轴：以归一化轨迹的累积路径长度作为 x 轴，替代时间轴，便于不同包跨路径比较
- 指标统计范围：仅 TRACKING 阶段（过滤 IDLE / REACHED）

## 4. 主要结论

### 4.1 路径形状基本一致

路径长度 6.66 ~ 6.82 m，差异 < 2.5%。归一化后 10 条轨迹高度重合，说明所有包的**实车执行轨迹形状和运动规模基本可比**。block2 路径与 block1 形状基本一致，之前 `diagnose_real_tuning.py` 中 block2 tracking error 更低的结论很可能是**诊断脚本中的坐标系/参考路径对齐问题**造成，而非控制器本身更优。

注意：这里的轨迹归一化只使用实车 odom，自身做起点平移和初始航向对齐。它能说明实车轨迹形状相近，但**不能证明 `/odom` 与 `/mpc/reference_path` 已处于同一坐标系**，也不能替代真正的参考路径跟踪误差验证。

### 4.2 v_max 全部被同一上限约束

10 包 v_max 均在 1.32 ~ 1.36 m/s，说明所有条件都碰到了相同的速度上限（速度剖面几何限速或 v_des 设定），条件间的区别体现在**减速时机和均速**，而不是峰值速度。

### 4.3 PROP2 组表现出更低的均速和更平滑的加速度

PROP2 系列（scheduler 开启）：
- PROP2_Q5 v_mean = 0.654，PROP2_Q0 v_mean = 0.613（低于 NOM 的 0.668）
- PROP2_Q0 的 a_RMS = 0.4922、jerk_RMS = 2.126，是 10 包中最低

这说明 PROP2 组在这批数据里表现出更低均速和更平滑的加速度变化。但该结论目前只能作为**现象描述**，不能单独证明平滑性完全来自 `risk_scheduler`：单包重复数不足、路径进度未严格对齐、`Q_slosh` 与 scheduler 条件也存在组合差异。要证明 Risk-Adaptive Scheduling Layer 的独立贡献，应优先看同路径、同 `Q_slosh`、仅切换 `risk_scheduler_enable` 的 FAS vs PROP 成对对比。

### 4.4 FAS_Q5 也表现平滑

FAS_Q5 的 jerk_RMS = 2.153，是第二低，a_RMS = 0.510 也属低位。FAS 的平滑效果接近 PROP2_Q0，但是在**没有 risk_scheduler 干预**的情况下实现的，说明固定大 Q_slosh 惩罚本身也能带来更平滑的控制输出。

### 4.5 ISR 加速度最不平滑

ISR 的 a_RMS = 0.5537，在 10 包中最高，v_mean = 0.687 也最高。ISR 的 input shaping 在当前实验条件下未带来速度或加速度平滑优势，反而整体"更激进"。

### 4.6 block2 三包内部一致

block2_Q0 / Q5 / Q10 的 a_RMS（0.540 / 0.539 / 0.543）和 jerk_RMS（2.285 / 2.287 / 2.314）非常接近，Q 值变化在轨迹平滑性上未产生可见差异，与视觉液面结果里"Q sweep 无单调趋势"一致。

## 5. 注意事项

- 加速度和 jerk 由 odom_v 数值差分得到，受 odom 噪声影响，绝对数值仅供相对比较，不宜作为精确物理量引用
- jerk_max 受单帧噪声影响较大，建议以 jerk_RMS 为主指标
- 分析范围仅限 TRACKING 阶段，IDLE 加速段和 REACHED 减速段不在统计内
- `trajectory_overlay.png` 使用的是归一化 odom 轨迹，不是地图坐标下与 `/mpc/reference_path` 的误差图
- `speed_accel_panel.png` 的弧长轴来自实车 odom 累积弧长，不是固定路径的 `s_global`；若后续用于论文主图，建议改为固定路径进度对齐
- 当前 `trajectory_analysis.py` 的 `--smooth-window` 参数尚未实际接入 `derive_series()`，脚本内部仍使用固定的 7/9/9 平滑窗口

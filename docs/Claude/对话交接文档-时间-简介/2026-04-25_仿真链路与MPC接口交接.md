```bash
source /home/a/scout_ws/devel/setup.bash
SIM_ENV=open USE_RVIZ=true \
SPAWN_X=0.0 SPAWN_Y=0.0 SPAWN_Z=0.1 SPAWN_YAW=0.0 \
rosrun scout_local_planner launch_sim_nav_stack.sh
```

启动局部 MPC：

```bash
roslaunch scout_local_planner slosh_experiment_sim.launch \
  Q_slosh:=5 \
  risk_scheduler_enable:=false \
  input_shaping_enable:=false \
  enable_slosh_box_constraint:=false \
  slosh_speed_governor_enable:=false
```

## MPC 话题接口

`slosh_experiment_sim.launch` 当前默认接口：

- 输入路径：`/scout/global_path`
- 输入里程计：`/odom`
- 输入 IMU：`/imu/data`
- 输出控制：`/cmd_vel`

注意：`/scout/global_path` 需要 RViz 点目标或固定路径脚本发布后才会有实际路径。没有路径时 MPC 等待或保持空转，不是接口不对齐。

## TF 结论

定位模式下不要重复发布 `odom -> base_footprint`。

当前角色分工：

- Cartographer localization 发布 `map -> odom -> base_footprint`
- bridge 发布 `base_footprint -> base_link`
- `robot_state_publisher` 发布 URDF 固定关节和轮子 link
- `tf_front_alias` 发布 `laser_link -> nanoscan3_front`

`launch_sim_nav_stack.sh` 默认：

```bash
ENABLE_ODOM_TF_BRIDGE=false
SPAWN_WHEEL_CONTROLLERS=false
```

建图手动流程才打开：

```bash
enable_odom_tf_bridge:=true
```

原因：建图配置需要外部 `odom -> base_footprint`；定位配置中 Cartographer 已经 `provide_odom_frame=true`，重复发布会导致 `TF_REPEATED_DATA`。

## 已做代码/文档改动

- `launch_sim_nav_stack.sh` 支持 `SIM_ENV=open|maze|custom`。
- `launch_sim_nav_stack.sh` 支持 `WORLD_NAME`、`MAP_FILE`、`SPAWN_X/Y/Z/YAW`。
- `launch_sim_nav_stack.sh` 默认关闭四个 wheel velocity controller，只保留 `scout_state_controller` 以发布 `/joint_states`。
- `launch_sim_nav_stack.sh` 默认 `ENABLE_ODOM_TF_BRIDGE=false`，避免定位模式重复 TF。
- `scout_nanoscan3_cartographer_localization_sim.launch` 默认使用 `map_sim_empty.pbstream`，并通过 `/odom_carto` 接收单调时间戳 odom。
- `scout_nanoscan3_cartographer_sim.launch` 建图也通过 `/odom_carto` 接收单调时间戳 odom。
- 新增 `open_walled.world`，用于开阔场地仿真。
- `仿真笔记.md` 和 `change_log.md` 已同步当前启动流程。

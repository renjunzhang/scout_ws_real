## 终点状态机 position / yaw 解耦

背景：

```text
诊断脚本显示终点过冲同时伴随 ENDPOINT_YAW_MISMATCH。
此前 goal_stop_pending 依赖 pose_reached，而 pose_reached = position_reached && yaw_reached。
因此位置已经进入 goal_tolerance 时，若终点 yaw 不满足，线速度停车 pending 不会触发，
车辆可能继续追参考并越过终点，随后 terminal recovery 调头。
```

改动：

```text
src/scout_apps/control/scout_local_planner/src/local_planner_ros.cpp
  updateState() 中改为读取 GoalInfo：
    goal_position_reached = goal_info.position_reached
  goal_stop_pending 和 SETTLING 入口改由 position_reached 触发。
  yaw / pose_reached 保留为调试和 terminal recovery 语义，但不再阻止线速度先降为 0。
```

说明：

```text
该改动实现“位置到了先停线速度，yaw 不阻止停车”。
终点姿态问题应作为单独任务处理，不应让 yaw mismatch 继续驱动车辆高速越过终点。
```

验证：

## 终点制动逻辑结构性修复

背景：

```text
实物运行仍出现超过终点后调头。代码检查发现 terminal_recovery.enter_distance 实物默认 0.70m，
大于 goal_capture_distance=0.25m，因此 terminal recovery 会先于 position stop pending 接管。
terminal_slowdown 只把 v_des_cmd 压到 0.18m/s，不会在 goal_tolerance 前形成真正停车制动。
```

改动：

```text
src/scout_apps/control/scout_local_planner/src/local_planner_ros.cpp
  1. terminal recovery 只允许在 position_reached=true 或 goal 已落到车后方时接管；
     在 goal 未到且仍在前方时，不再用 terminal recovery 的 APPROACH_POINT 模式穿过终点。

  2. TRACKING 中 terminal_slowdown 区域新增制动速度上限：
     v_des_cmd <= sqrt(goal_speed^2 + 2 * decel * max(0, goal_dist - goal_tolerance))
     decel 优先使用 terminal_cmd_v_rate_limit。

docs/重要文档/20260513_SloshPriorityMPC有效性验证方案.md
  记录 terminal recovery 接管条件和终点制动速度上限公式。
```

说明：

```text
该修复优先调整终点接近逻辑，不先扩大 terminal distance 参数。
目标是让 MPC 在 TRACKING 内完成平缓制动，terminal recovery 只处理位置已到后的姿态/残余问题，
或已经越过目标后的恢复问题。
```

## 在线 path post-processor 第一版

目标：

```text
把 README-NEW.md 中的在线 path post-processor 方案落成最小 ROS 节点，
使 scout_global_planner 生成的 nav_msgs/Path 可以先经过低激励几何后处理，
再交给 scout_local_planner MPC tracking。
```

新增文件：

```text
src/scout_apps/control/scout_local_planner/scripts/anti_slosh_path_post_processor.py
src/scout_apps/control/scout_local_planner/launch/anti_slosh_path_post_processor.launch
```

节点接口：

```text
sub: /scout/global_path_raw
pub: /scout/global_path_anti_slosh
pub: /anti_slosh_path/debug/original
pub: /anti_slosh_path/debug/mild
pub: /anti_slosh_path/debug/medium
pub: /anti_slosh_path/debug/strong
pub: /anti_slosh_path/metrics
```

第一版算法：

```text
sanitize raw path
resample by ds
generate original / mild / medium / strong smoothing candidates
gate by max_drift, length_ratio, endpoint_error, min_segment_length, direction
score by kappa_p95, dkappa_p95, length_ratio, max_drift
publish best candidate
```

当前边界：

```text
不做 costmap collision check
不做 slosh ODE rollout
不做 SLSQP/global optimization
```

因此该版本只能用于 open field / known safe corridor 的在线接入验证；
maze 或复杂障碍环境仍需要补 footprint/costmap collision check 后才能作为安全结论。

## 在线验证启动口径说明

用户询问以下启动方式是否本身具有液体晃动抑制能力：

```bash
roslaunch scout_local_planner slosh_experiment_sim.launch \
  global_path_topic:=/scout/global_path_anti_slosh \
  Q_slosh:=0 \
  Q_slosh_eta_dot:=0 \
  risk_scheduler_enable:=false \
  energy_profile_enable:=false \
  input_shaping_enable:=false \
  mpc_cmd_vel_lead_time:=0.05
```

结论：

```text
该 local planner 启动口径本身不启用 MPC 内部防晃。
MPC 只作为普通 constrained tracker。
防晃来源只可能是前端 /scout/global_path_anti_slosh。
```

具体解释：

```text
Q_slosh=0
Q_slosh_eta_dot=0
risk_scheduler=false
energy_profile=false
input_shaping=false
```

这些参数关闭了 MPC soft slosh cost、risk scheduler、速度剖面防晃和 input shaping。
因此若未同时启动 `anti_slosh_path_post_processor`，或后处理路径与原始 `/scout/global_path` 几乎相同，
则该配置基本等价于普通 MPC 跟踪，不应称为控制器内部防晃。

论文/实验记录口径：

```text
Proposed = anti_slosh_path_post_processor 生成低激励几何参考
           + slosh_experiment_sim.launch 普通 MPC tracking
```

不能写成：

```text
slosh_experiment_sim.launch 内部 MPC 主动抑制液体晃动。
```

## 在线 post-processor 过度平滑保护

依据：

```text
georef_same_goal_01.bag:
  ay_p95 -22.9%, ax_p95 +40.5%, h_p95 +6.5%

georef_same_goal_02.bag:
  ay_p95 -54.2%, ax_p95 +43.6%, h_p95 +10.4%
```

两包说明 online post-processor 已经生效，但 naive minimum-curvature selection
会总是选择 strong 候选，使路径过度拉直；横向激励下降，但 MPC 更快通过，
纵向 ax/jerk 上升，最终 `/slosh/height` 不降反升。

修改：

```text
anti_slosh_path_post_processor.py
anti_slosh_path_post_processor.launch
README-NEW.md
```

新增 gate：

```text
gates/min_length_ratio = 0.995
gates/min_kappa_ratio  = 0.20
```

含义：

```text
拒绝明显缩短路径的候选；
拒绝把 kappa_p95 压到原始 20% 以下的过度平滑候选。
```

新增 score penalty：

```text
score/w_shortening = 10.0
score/w_over_smooth = 2.0
```

目的：

```text
从 min(kappa, dkappa) 改为 moderate geometry smoothing；
避免把 slosh 激励从 lateral 转移到 longitudinal。
```

后续 georef_same_goal_0203.bag 暴露出该 gate 过硬：

```text
selected_index = 0
accepted_count = 1/4
mild/medium/strong 全部因 over_smooth_kappa 被拒
```

因此继续修改：

```text
1. 取消 min_kappa_ratio hard gate，保留为 score penalty。
2. 新增 max_candidate_level，默认 medium，避免 naive 逻辑继续选择 strong。
3. 新增 target_kappa_ratio=0.35，使 score 偏好中等曲率下降而不是最小曲率。
```

当前选择逻辑：

```text
hard gate:
  max_drift
  length_ratio upper/lower
  endpoint_error
  min_segment_length
  direction
  max_candidate_level

soft score:
  |kappa_ratio - target_kappa_ratio|
  dkappa_ratio
  drift
  path shortening penalty
  over-smoothing penalty
```

下一步验证口径：

```text
candidate_report 应选择 mild 或 medium；
若 selected 仍为 original，说明 length/drift/endpoint gate 仍过紧；
若 selected 为 medium/mild 但 ax/jerk 仍升，说明仅几何在线后处理不足，需要速度/执行层协同。
```

## anti_slosh_path_post_processor 增加 costmap collision check

为了把 GeoRef A/B 从 open field 搬到 maze 同起点同终点，先补 collision check。
方案见：

```text
docs/Claude/修改方案-时间-简介/2026-05-06_post_processor_collision_check.md
```

依据：当前 `global_planner_sim.yaml` 已配置 inflation_layer：

```text
inflation_radius     = 0.5
cost_scaling_factor  = 3.0
lethal_cost_threshold = 65 (static_layer)
```

inflation 已经把 footprint 安全距离编码进 cost 值，所以采用最小可行方案：
点查询 + 单一阈值 reject，不做 footprint polygon、不做 TF、不做 update 增量。

改动：

```text
src/scout_apps/control/scout_local_planner/scripts/anti_slosh_path_post_processor.py
src/scout_apps/control/scout_local_planner/launch/anti_slosh_path_post_processor.launch
src/scout_apps/control/scout_local_planner/README-NEW.md (§9.2 / §9.6)
```

新增订阅：

```text
~costmap_topic   default=/scout/mbf_costmap_nav/global_costmap/costmap
                 nav_msgs/OccupancyGrid
```

新增参数：

```text
~gates/collision_threshold  default=50  (0-100)
~gates/unknown_is_obstacle  default=true
```

`~gates/enable_collision_check` 从 placeholder 升级为实际生效。

算法：

```text
对候选 path 上每个采样点 (x, y):
  ix = floor((x - origin.x) / resolution)
  iy = floor((y - origin.y) / resolution)
  cost = data[iy * width + ix]
  若 ix/iy 越界且 unknown_is_obstacle: reject
  若 cost < 0 且 unknown_is_obstacle: reject
  若 cost >= collision_threshold: reject
任一点 reject 即整条候选 reject，记录 first_violation_idx 与 cost。
```

设计要点：

```text
1. original 候选 (来自 mbf) 跳过 collision check，假定 mbf 输出在安全区。
2. enable_collision_check=true 但 latest_costmap is None 时:
   - 非 original 候选 reject reason="no_costmap"
   - selected 自动回退为 original
   - logwarn_throttle 提示等待 costmap
3. gate 顺序按代价升序，collision 放最后；candidate_report 增加 col 字段。
4. 默认 enable_collision_check=false，open field 同目标 A/B 行为不变。
```

验证：

```text
python3 -m py_compile src/scout_apps/control/scout_local_planner/scripts/anti_slosh_path_post_processor.py
=> OK
```

下一步（用户操作）：

```text
1. maze 启 mbf + post-processor + RViz，订阅 /anti_slosh_path/debug/{mild,medium,strong}
   目视确认 strong 切墙时被 reject，selected 不切墙。
2. 在 maze 同起点同终点跑 raw vs GeoRef 各 3 包，参数仅 global_path_topic 不同：
     raw    : global_path_topic=/scout/global_path
     georef : global_path_topic=/scout/global_path_anti_slosh
   其余参数 (v_max, R_a, R_da, lead_time, Q_slosh=0, risk_scheduler=false ...) 完全一致。
3. 复用现有 metrics 比较 h_p95 / ay_p95 / cmd_ax / jerk / tracking_time / track_p95。
```

边界：

```text
1. 不做 footprint polygon check，依赖 inflation 提供安全裕度；
   若未来换车型/换通道宽度需要重审 inflation_radius 与 collision_threshold。
2. 不做 TF 变换，假定 candidate path 与 costmap 同 frame=map。
3. 不做 costmap update 增量订阅，maze 静态地图够用；
   动态障碍场景需要再加 OccupancyGridUpdate 订阅。
```

## forward v(s) ay gate 与路径采样修正

根据 review，常数 `v_assumed` 会退化成 kappa gate，改为 forward `v(s)` rollout：

```text
v[0] = v_init
v[i] = min(v_max, sqrt(ay_budget / |kappa_i|), sqrt(v[i-1]^2 + 2*a_max*ds))
predicted_ay_i = v[i]^2 * |kappa_i|
predicted_ay_p95 = p95(predicted_ay_i)
gate: predicted_ay_p95(candidate) <= predicted_ay_p95(original) * ay_ratio_limit
```

代码：

```text
anti_slosh_path_post_processor.py
- 新增 predicted_lateral_profile()
- candidate_report 增加 ayr= 与 vmaxp=
- reject reason 增加 ay:<ratio>><limit>

anti_slosh_path_post_processor.launch
- 暴露 ay_ratio_limit, prediction_v_max, prediction_ay_max_budget,
  prediction_a_max, prediction_v_init

run_sim_fixed_path_bag.sh
- 将上述参数接到 GEOREF_TUNED
```

## original fallback 语义修正

问题：

```text

- 但最终 selected=original 时，/scout/global_path_anti_slosh 直接发布 raw_msg，
```


## SPMPC 实物黑匣子录包脚本补强

### 背景

2026-07-02 实物内部晃动 bag 复盘发现：虽然 bag 中已有 `/spmpc/controller_variant`、`/spmpc/slosh_height`、`/spmpc/cost_breakdown`、`/spmpc/debug/delay_compensation` 等基础诊断，但仍缺少若干关键运行时证据，例如 effective config、hard constraint effective、slosh cost monitor、cmd-odom alignment 等。后续 delay-only smoke 和 B0 / B_slosh / B_ours 重跑必须把可能需要的分析参数在录制时一并保存，避免再次出现“实验跑了但事后无法证明配置/约束/相位是否真正生效”的问题。

### 本次改动

- 更新 `src/scout_apps/control/spmpc_local_planner/scripts/record_spmpc_full_rgb_bag.sh`，将其作为实物 SPMPC 黑匣子录包脚本使用。
- 新增 `RECORD_RGB` 开关，并保留 `RECORD_CAMERA` 作为兼容别名：
  - 当前若不做 RGB 真值，可设置 `RECORD_RGB=false`；
  - 脚本仍可在需要时录制 RGB 原始图像和相机内参。
- 增补 SPMPC 关键诊断 topic：
  - `/spmpc/debug/effective_config`
  - `/spmpc/debug/slosh_cost_monitor`
  - `/spmpc/debug/slosh_hard_constraint`
  - `/spmpc/debug/slosh_hard_constraint_effective`
  - `/spmpc/debug/cmd_odom_alignment`
- 预留未来黑匣子诊断 topic 名称，若当前系统未发布则不会中断录包，录包后会在 sidecar 中列出未录到的 selected topic。
- 新增 sidecar / metadata 输出：
  - `${NAME}_existing_selected_topics_at_start.txt`
  - `${NAME}_missing_selected_topics_at_start.txt`
  - `${NAME}_bag_info.txt`
  - `${NAME}_recorded_topics.txt`
  - `${NAME}_selected_topics_not_recorded.txt`
  - `${NAME}_env.txt`
  - `${NAME}_topic_info/`
- 在 `${NAME}_info.txt` 中记录更多 run intent：
  - solver backend、v_ref、w_slosh、slosh_height_max；
  - delay phase mode / linear delay / angular delay；
  - control frequency、map file、goal、launch command、operator note；
  - selected topic 数量和录制开始时已存在/缺失 topic 数量。

### 明确未做

- 未修改 SPMPC 控制器、solver、权重或 acados 数学形式。
- 未实现或强制运行 RGB 真值流程；RGB 仍只是可选录制项。
- 未自动发送 `/cmd_vel`、目标点或启动/停止 planner；该脚本仍只负责录制和保存 metadata。

## SPMPC 实物 fixed-path 单次试验一键脚本

### 背景

实物 fixed-path 试验现场流程中，传感器/定位/底盘栈已有一键启动脚本；后续仍需手动执行固定路径生成、固定终点发送、录包命名和 planner 启动。为减少 run 间命名错误和启动顺序错误，本次新增一个只覆盖 SPMPC 内部消融的 run 级 wrapper。

### 本次改动

- 新增 `src/scout_apps/control/spmpc_local_planner/scripts/run_spmpc_real_fixed_path_trial.sh`。
- 脚本按顺序执行：
  1. 启动 `template_fixed_path_generator.py`；
  2. 调用 `send_fixed_goal.py` 发送固定终点；
  3. 先启动 `record_spmpc_full_rgb_bag.sh` 黑匣子录包；
  4. 再启动 `spmpc_fixed_path.launch` 的指定 SPMPC variant。
- `RECORD_SEC` 默认 60s，`MAX_RECORD_SEC` 默认 60s；若 `RECORD_SEC=0` 或大于 60，会强制改回 60，满足“想停可手动停、超过 60s 必须停”的实物录包口径。
- 根据 `/data/a/slosh_bags/real/20260702_internal_slosh` 中 `/scout/global_path_fixed` 的终点，把 wrapper 默认目标固定为 `GOAL_X=-5.424`、`GOAL_Y=-4.736`；bag 中未保留原始 `/scout/goal` yaw，`GOAL_YAW` 默认保留 `0.0`，且 template generator 只使用 goal x/y。
- wrapper 结束时停止 planner、recorder、path generator，并在 `/cmd_vel` 模式下补发一次 zero command。
- 更新 `docs/实物实验注意事项/对比试验/实物对比试验启动指南.md`，加入一键执行固定路径 + 黑匣子录包 + SPMPC 的最小使用方法、delay-only smoke 示例和命令模板。

### 明确未做

- 未修改 SPMPC 控制器、solver、权重或 acados 数学形式。
- 未把安全 gate 写进脚本；现场急停/遥控由实物操作流程负责。
- 未实现外部 baseline 的一键 wrapper；当前脚本只覆盖 B0 / B_slosh / B_ours / hard variants。

## SPMPC 模型为真值调试 topic 与离线 summary

### 背景

当前实物问题排查先假设 SPMPC 内部模型预测值就是真值，核心问题收缩为：既然模型预测是真值，为什么优化器没有把这个真值压下来。为避免每次实物试验后再反复补录，本次增加四个显式黑匣子 topic，并配套离线 summary 脚本，让单个 bag 能回答 MPC 初始状态、delay compensation、solver input、命令链路干预和 slosh cost/horizon 压力。

### 本次改动

- 在 `DiagnosticsPublisher` 中新增四个 additive debug topic，不改变已有 topic layout：
  - `/spmpc/debug/raw_state`
  - `/spmpc/debug/predicted_state`
  - `/spmpc/debug/solver_input_state`
  - `/spmpc/debug/command_intervention`
- 在 `SpmpcLocalPlannerROS::controlTimerCallback()` 中按链路发布：
  - raw odom/observer state；
  - delay phase predicted state（未启用 prediction 时仍发布 invalid sample）；
  - `problem_.solve()` 实际收到的 solver input；
  - solver output 经 ROS gate、shared limiter 和 zero path 后的 command intervention。
- 新增 `src/scout_apps/control/spmpc_local_planner/scripts/summarize_spmpc_real_trial.py`：
  - 支持传入单个 `.bag` 或 run 目录；
  - 解析 recorder / one-click sidecar；
  - 按 `Float32MultiArray.layout.dim[0].label` 动态解码字段；
  - 输出 `${bag_stem}_summary.json` 与 `${bag_stem}_summary.md`；
  - 对旧 bag 缺新 topic 的情况 graceful degradation，并列入 red flags。
- 更新 `record_spmpc_full_rgb_bag.sh`，确保黑匣子录包 topic whitelist 包含 `/spmpc/debug/predicted_state`。

### 明确未做

- 未修改 solver 目标函数、约束、权重或 acados 数学形式。
- 未改变已有 topic layout。
- 未引入 RGB 真值流程；当前仍按“模型内部预测值为真值”的调试假设推进。
- `command_intervention` 只记录命令链路，不新增安全 gate 或控制逻辑。

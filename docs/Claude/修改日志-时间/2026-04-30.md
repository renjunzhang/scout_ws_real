### 1. 旧 MPC 代价函数路线失效总结

新增：

```text
docs/Claude/总结/2026-04-30_MPC代价函数旧方案失效总结.md
```

核心结论：

```text
MPC 内部 slosh soft cost 可以改变控制行为，
但不能稳定、可泛化地把液体晃动压下去。
```

主要原因：

- slosh 抑制放在短 horizon QP 内部太晚；
- soft cost 与 tracking cost 竞争；
- 惩罚 `eta` 不等于耗散 `eta_dot` 和总模态能量；
- terminal cost 不能解决路径中段激励；
- hard box constraint 容易制造 QP infeasible；
- 计划输入与真实执行激励存在差异；
- P3 主导通道是 longitudinal `eta_x`，不是简单 lateral `ay`。

论文口径调整：

```text
不能写：MPC cost actively suppresses sloshing.
应写：slosh-aware MPC framework + energy-aware reference generation.
```

### 4. PROFILE_ENERGY 方案升级为 v4

继续修改：

```text
docs/Claude/修改方案-时间-简介/2026-04-29_PROFILE_ENERGY速度剖面改进方案.md
```

v4 不再扩展新方向，只锁定实现前必须明确的工程口径：

- `E_norm` 不只依赖同路径 NOM baseline：

```text
离线论文评估: E_ref = same-path NOM baseline p95
在线/真实运行: E_ref = 当前未修正 candidate profile 的 rollout p95
```

- rollout correction 增加接受/回滚机制：

```text
propose correction → rollout evaluate → accept or rollback
```

若 `h_p95_pred` 不降、`eta_dot_pred` 上升、terminal residual 上升或预测任务时间超限，则回滚本轮修正。

- Layer 2 rollout 必须使用 signed input sequence：

```text
ax_i
ay_i = v_i^2 * kappa_i
omega_i = v_i * kappa_i
alpha_i = ax_i*kappa_i + v_i^2*dkappa_i
```

不能用窗口最大绝对值代替真实序列。

- 数值积分口径：

```text
优先线性二阶系统精确离散化
否则至少 RK4
dt_i <= energy_profile_dt_max
```

不使用显式 Euler 作为最终口径。

- jerk 换算明确为时间域：

```text
ax_i = (v_i^2 - v_{i-1}^2) / (2 ds)
jerk_i ≈ v_i * (ax_i - ax_{i-1}) / ds
```

- 在线重规划加入 hysteresis / temporal smoothing，防止 profile 本身抖动制造新激励。

- 增加 debug topic 清单：


- P3 增加纵向专属指标：

### 6. PROFILE_ENERGY Step0 离线 rollout 验证脚本

修改：

```text
src/scout_apps/control/scout_local_planner/scripts/offline_pmg_replay.py
```

新增独立模式：

```bash
python3 src/scout_apps/control/scout_local_planner/scripts/offline_pmg_replay.py \
  <bags...> \
  --profile-energy-rollout \
  --csv /tmp/profile_energy_rollout.csv
```

实现内容：

- 使用 `TRACKING + terminal NONE` 主段；
- 使用 `/slosh/ax_est`、`/slosh/ay_est` 的 signed 输入序列；
- 用线性二阶模态模型精确离散化 rollout；
- 加 `dt_max` 内部子步进，默认 `0.05s`；
- 输出 PROFILE_ENERGY Step0 验收指标：

```text
h_p95_rel_error
peak_time_error_s
eta_dot_corr
eta_dot_best_lag_corr / eta_dot_best_lag_s
risk_recall
eta_x_energy_ratio
eta_x_rms / eta_x_dot_rms
ax_abs_p95 / ay_abs_p95
```

验证命令：

```bash
python3 -m py_compile src/scout_apps/control/scout_local_planner/scripts/offline_pmg_replay.py

```

结果：

```text

  peak_dt=0.050s
  eta_dot_corr=-0.025

P3 NOM run03:
  h_p95_err=0.031
```

结论：

```text

```

这不是直接否定 PROFILE_ENERGY，而是暴露了实现前必须处理的时序风险：

- 如果按严格“时间戳完全一致”验收，当前 Step0 为 FAIL；
- 如果允许一拍积分/发布顺序偏移，模态速度形状高度一致；
- 后续在线 `PathHandler` 实现前，需要明确 profile rollout 与 `/slosh/state` 的时序对齐口径，不能只看 `h_p95`。

## 关键观察

- Day4 先不改控制器核心逻辑，只给仿真 launch 暴露参数入口，方便 C baseline、保守风险调度、放宽 settling、关闭 IMU ay 等小规模试探。
- 本次入口只存在于 `slosh_experiment_sim.launch`，`slosh_experiment.launch` 与实物参数文件不变；因此不会改变实物默认算法。
- 参数默认值保持当前代码默认量级：`gamma=5.0`，`rho_0=0.3`，`rate_limit_per_step=0.05`，`beta=0.3`，`Q_eta_min=0.0`，`Q_eta_max=10.0`，`settling_eta_tol=0.0015`，`settling_eta_dot_tol=0.03`，`settling_timeout_s=3.0`。
- 第一条 Day4 C baseline 能到达，`/slosh/settling_time` 正常发布，IMU frame 为 `imu_link`，IMU ay bias ready true ratio 为 `0.641`。
- 残余问题仍是近终点/停止段相关的 MPC 成功率偏低：本条 `success_ratio=0.225`，但状态机最终通过 `SETTLING -> REACHED`，需要后续区分是真不可行，还是统计包含了停止/终点附近的预期失败样本。
- `risk_scheduler/fallback_active true_ratio=0.317`，未占主导，但比理想情况偏高；下一条建议录 conservative risk，看降低调度激进程度后 fallback 和 success ratio 是否改善。
- Conservative risk 相比 baseline 有明显改善：`success_ratio 0.225 -> 0.517`，`fallback_active true_ratio 0.317 -> 0.275`，`solve_ms p95 8.967ms -> 4.866ms`。
- Conservative risk 的代价是液面估计略高：`height p95 0.003518m -> 0.004406m`；当前仍完成 `SETTLING -> REACHED`，建议再录一条 conservative risk 复现，确认不是路径长度或单次随机因素导致。
- 第二条 conservative risk 仍稳定完成 `SETTLING -> REACHED`，且 `fallback_active true_ratio=0.143`、`solve_ms p95=4.291ms` 更好；但 `success_ratio=0.154`，没有复现第一条的成功率改善。
- 当前结论应收紧为：保守风险调度能稳定到达、降低 fallback 与求解耗时有迹象，但 `mpc/status_val success_ratio` 对单次路径/终点段统计敏感，不能仅凭该指标判断参数优劣。下一步应拆分 TRACKING 段、SETTLING 段、REACHED 后段分别统计。
- 已扩展 `extract_slosh_metrics.py`，默认仍只统计 `TRACKING` 段，但会额外输出 `status_val by mpc_status`。对三条 bag 的新分析表明：
  - baseline 的 `TRACKING` 段 `success=1.000`，整包 `0.225` 主要被 `REACHED=0.000`、`IDLE=0.000` 拉低；
  - conservative risk 1 的 `TRACKING=1.000`，整包 `0.517` 是因为该条 `REACHED=1.000`；
  - conservative risk 2 的 `TRACKING=0.946`，整包 `0.154` 主要由 `SETTLING=0.000`、`REACHED=0.000`、`IDLE=0.000` 拉低。
- 因此 Day4 对 `success_ratio` 的初步定位已经明确：整包指标不能直接用于比较参数优劣，应优先看 `TRACKING` 段成功率，再把 `SETTLING / REACHED / IDLE` 作为状态机行为诊断指标。
- `no_imu_ay` 对照已完成：
  - 整包仍可完成 `TRACKING -> SETTLING -> REACHED`
  - `fallback_active true_ratio=0.023`，明显低于 baseline 与 conservative risk
  - `/slosh/height p95=0.001968m`，也是当前最小
  - 但 `TRACKING success=0.913`，低于 baseline / conservative risk 1 的 `1.000`，也低于 conservative risk 2 的 `0.946`
- 这说明关闭 IMU ay 能让估计与调度更“平静”，但主行驶段求解成功率略变差。当前更合理的判断是：
  - 若优先保主行驶段 MPC 稳定性，继续保留 `slosh_use_imu_lateral_accel=true`
  - 若后续更重视液面指标或 fallback 触发率，可把 `slosh_use_imu_lateral_accel=false` 作为 Day4 的对照备选

## Day4 仿真推荐初值

### 评价口径

Day4 开始采用以下优先级评价参数，而不是直接看整包 `success_ratio`：

1. `TRACKING -> SETTLING -> REACHED` 是否稳定完成
2. `TRACKING` 段 `status_val` 成功率
3. `/risk_scheduler/fallback_active true_ratio`
4. `/mpc/solve_ms` p95 或 TRACKING 段均值
5. `/slosh/height` p95 / rms
6. `/slosh/settling_time`

### 推荐组

| 参数 | 推荐值 | 备注 |
|---|---|---|
| `Q_slosh` | `5.0` | 继续沿用 Day3/Day4 主线 |
| `slosh_use_imu_yaw_rate` | `true` | 仿真已验证稳定 |
| `slosh_use_imu_lateral_accel` | `true` | 先保留，后续再做 no-IMU-ay 对照 |
| `risk_scheduler_enable` | `true` | Day4 主线保持开启 |
| `risk_scheduler_gamma` | `3.0` | 较 baseline 更保守 |
| `risk_scheduler_rho_0` | `0.4` | 提高中点，减缓风险抬升 |
| `risk_scheduler_rate_limit_per_step` | `0.02` | 明显放缓调度变化 |
| `risk_scheduler_beta` | `0.2` | 降低速度折扣激进度 |
| `risk_scheduler_Q_eta_min` | `0.0` | 保持默认 |
| `risk_scheduler_Q_eta_max` | `10.0` | 保持默认 |
| `settling_eta_tol` | `0.0015` | 先保持默认，当前 settling 能完成 |
| `settling_eta_dot_tol` | `0.03` | 先保持默认 |
| `settling_timeout_s` | `3.0` | 先保持默认 |

### 选择理由

- baseline 与 conservative risk 都能完成 `TRACKING -> SETTLING -> REACHED`，但 conservative risk 在两条 bag 上都表现出更低的 `fallback_active` 与更低的求解时间。
- 按 `TRACKING` 段统计：
  - baseline：`success=1.000`
  - conservative risk 1：`success=1.000`
  - conservative risk 2：`success=0.946`
- 这说明 conservative risk 没有明显破坏主行驶段闭环，同时对 near-goal 风险调度激进程度更温和。
- 代价是 `/slosh/height` 指标相对 baseline 略有升高，因此这组参数当前定义为 **Day4 仿真推荐初值**，不是最终定型值。

### 当前结论

- Day4 仿真推荐初值采用 **conservative risk**：
  - `gamma=3.0`
  - `rho_0=0.4`
  - `rate_limit_per_step=0.02`
  - `beta=0.2`
- `settling_*` 先不改，保持默认。
- `slosh_use_imu_lateral_accel` 暂时仍推荐 `true`；`false` 作为备选对照组保留。
- 如果 Day4 结束前只保留一组更偏“仿真闭环稳定”的候选，可升级为：
  - `slosh_use_imu_lateral_accel=true`
  - `gamma=3.0`
  - `rho_0=0.4`
  - `rate_limit_per_step=0.02`
  - `beta=0.2`
  - `settling_eta_tol=0.002`
  - `settling_eta_dot_tol=0.05`
  - `settling_timeout_s=3.0`
- 后续若继续调参，应优先围绕：
  - `slosh_use_imu_lateral_accel=false` 对照
  - `settling_eta_tol / eta_dot_tol` 小幅放宽
  - `gamma / rho_0 / rate_limit_per_step` 的小范围二次细化

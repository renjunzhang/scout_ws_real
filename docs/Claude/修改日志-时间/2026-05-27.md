# 2026-05-27 修改日志

## RGB 视觉主指标口径改为 max-LCR

### 背景

- 20260526 refactor smoke 分析中，center/right 标尺识别不稳定；
- 原流程文档仍把 `median(left, center, right)` 作为主指标；
- 这会在部分批次中被 0 值压低，低估真实壁面爬升。

### 修改

- 更新 `docs/重要文档/红色液体视觉验证固定流程.md`：
  - 固定路径 MPC cost 对比的 RGB 主指标改为：

```text
H_vis(t) = abs(rolling_median(max(h_left, h_center, h_right), window=5))
metric = p95(H_vis) over TRACKING_PRE_TERMINAL
```

  - `median-LCR` 保留为视觉质量检查；
  - 明确 max-LCR 更接近 Ferrari-style maximum sloshing height 的壁面峰值口径；
  - 明确 `/slosh/height` 仍不能替代 RGB 真值。

### 注意

- 如果 median-LCR 和 max-LCR 差异很大，优先检查 ROI、曝光、HSV 和标尺位置；
- 正式论文仍需说明 max-LCR 的视觉链质量和误差来源。

## 新增 SloshPriorityMPC 正式对比实验验证方案

### 背景

- `docs/重要文档/20260518_MPC终点收敛与固定路径验证方案.md` 已覆盖 terminal、固定路径、重构 smoke 和外部 profile 接线；
- 下一步需要面向论文主实验，明确 C/D/E/F/TOPPRA/RUCKIG 的正式对比规则；
- 重点是防止 TOPPRA/RUCKIG 靠明显更慢获得 RGB 优势。

### 修改

- 新增 `docs/重要文档/20260527_SloshPriorityMPC正式对比实验验证方案.md`：
  - 继承 20260518 方案的实物启动、固定路径、录包、分析流程；
  - 明确方法分组：
    - C: ordinary MPC；
    - D: SLOSH_ONLY，论文创新核心；
    - E: SMOOTH_ONLY；
    - F: OURS_FULL，工程完整主线；
    - TOPPRA/RUCKIG: non-slosh external retiming baseline。
  - 明确公平性规则：
    - 同一条 P2_s_curve_d200 JSON；
    - 主窗口为 `TRACKING -> first terminal/capture`；
    - RGB 主指标为 max-LCR p95；
    - TOPPRA/RUCKIG duration 需尽量落在 F 的 ±10% 内。
  - 写入可复制命令：
    - 实物启动；
    - RGB 调参；
    - 固定路径生成；
    - TOPPRA/Ruckig CSV 生成；
    - C/D/E/F/TOPPRA/RUCKIG 启动；
    - pilot 和 randomized block 录包命名；
    - 录后行为分析。

### 结论

- 下一轮先跑 C/D/E/F/TOPPRA/RUCKIG 各 1 包 pilot；
- 若 duration 和 terminal 都通过，再进入每组 n=3 的 randomized block；
- 若 TOPPRA/RUCKIG 比 F 慢超过 10%，先调 profile 参数，不扩展正式统计。

## 正式对比实验方案改为先调 F 再匹配外部 baseline

### 背景

- 20260524/20260526 现有结果已经说明 TOPPRA/RUCKIG 是很强的 smooth-motion baseline；
- 当前 `Q_slosh=5` 不一定是 SloshPriorityMPC 的最佳工作点；
- 直接用未调好的 F 和强平滑 baseline 对比，容易把“ours 参数还没到工作点”误读成“slosh-aware MPC 没有价值”。

### 修改

- 更新 `docs/重要文档/20260527_SloshPriorityMPC正式对比实验验证方案.md`：
  - 明确下一轮顺序改为：

```text
Step 1: 先做 F_Q3 / F_Q5 / F_Q7 / F_Q10 的 Q_slosh sweep；
Step 2: 按 RGB max-LCR p95/RMS/peak、ax/ay、model、duration、tracking error 选择 F*；
Step 3: 再把 TOPPRA/RUCKIG 调到与 F* 近似同速或同 duration；
Step 4: 用 C / D / E / F* / TOPPRA_matched / RUCKIG_matched 做正式随机 block。
```

  - 写入 F 组 `Q_slosh` sweep 命名和录包命令；
  - 写入 TOPPRA/RUCKIG speed-matched 调参顺序：
    - TOPPRA: `v_max 0.80→0.90→1.00`，必要时 `a_max 0.60→0.80`、`decel_max 0.80→1.00`；
    - RUCKIG: `v_max 0.80→0.90→1.00`，必要时 `a_max 0.60→0.80`、`j_max 1.50→2.00→2.50`。
  - 明确 default 与 matched 都要保留参数和 duration，避免被质疑为了 ours 弱化 baseline。

### 约束

- 不通过降低 `R_a/R_da` 来放大 slosh；
- 不启用 `slosh_preview_factor`，除非 peak debug 证明主峰来自 horizon future k>0；
- terminal phase 仍不进入主效果统计；
- `/slosh/height` 仍只作为模型侧 surrogate，不能替代 RGB 真值。

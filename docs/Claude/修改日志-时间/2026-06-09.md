## SPMPC 主线后端运行时口径落地

- 将 `spmpc_local_planner` 的默认 `solver_backend` 从 `primitive` 改为 `continuous_mpcc_acados`，覆盖 `SolverParams` 内置默认值、`config/planner/common.yaml` 以及 `spmpc_experiment.launch` / `spmpc_point_to_point.launch` / `spmpc_fixed_path.launch` 三个入口默认值；未改 launch arg 名称。
- 明确 `primitive` 仅是 fallback/debug rollout sampling + cost ranking，不是 MPCC/mainline；`continuous_mpcc_direct_omega_legacy` 仅作为 RouteB diagnostic/legacy continuous MPCC。
- 新增 backend policy guard：未知 backend 直接 `ROS_FATAL`，不再静默 fallback 到 `primitive`；非主线 backend 禁止 slosh-enabled variant、obstacle、homotopy 和 hard corridor 组合；主线 `continuous_mpcc_acados` 对尚未接入的 obstacle/homotopy/hard corridor 也 fail fast。
- 启动时强制打印 backend、role、variant、mode 和关键 feature flags，便于确认运行时实际口径；`/spmpc/solver_backend` diagnostics 保持发布。
- 将 point-to-point 默认 `obstacle_enable` / `homotopy_enable` 暂时关闭，避免默认主线切到 continuous MPCC 后出现“参数开启但 OCP 未消费”的静默误用。
- 验证：`rg` 确认 SPMPC 配置/launch 中无 `primitive` 默认后端残留；`catkin_make --pkg spmpc_local_planner` 通过；默认 fixed-path / point-to-point launch 均打印 `backend=continuous_mpcc_acados role=SPMPC mainline continuous MPCC`；未知 backend、`primitive+B_ours`、`primitive+obstacle_enable=true`、`continuous_mpcc_direct_omega_legacy+B_ours` 均按预期 `ROS_FATAL`；`continuous_mpcc_direct_omega_legacy+B0` 可作为 diagnostic 启动。
- 项目红线验证：`catkin_make --pkg scout_local_planner` 仍失败，原因是 build 目录下没有 `scout_apps/control/scout_local_planner/all` 目标规则（`没有规则可制作目标`），已按实际输出记录，未改动该包；因此未继续运行 `run_s_curve_smoke_test.sh`。

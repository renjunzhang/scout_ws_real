## Ruckig-style profile cap 仿真检查与执行语义修正

### 输入 bag

```text
/data/a/slosh_bags/sim/20260526/20260526_P2_s_curve_CUSTOM_runruckig_cap02_010814.bag
```

### 检查结果

- Ruckig-style CSV / reference 链路已跑通：
  - `/reference/v_ref_horizon` 最大值 `0.8m/s`；
  - `/mpc_status` 进入 `TRACKING -> SETTLING -> REACHED`；
  - `/mpc/status_val` 全部为成功求解。
- 但执行层 cap 有语义问题：
  - `/profile_cap/v_profile` 最大值 `0.8m/s`；
  - `/profile_cap/cmd_v_pre_cap` 最大值约 `0.884m/s`；
  - `/profile_cap/cmd_v_post_cap` 最大值约 `0.885m/s`；
  - `cmd_v_post_cap - v_profile` 最大值约 `0.085m/s`。

### 原因

- 昨日实现中先做 `min(cmd_v, profile_v)`，再做 jerk limiter；
- jerk limiter 为了限制加速度变化率，会把上一帧较高速度缓慢降下来；
- 结果是短时间内最终 `cmd_v_post_cap` 反而高于 `profile_v`。

### 修改

- 调整 `src/scout_apps/control/scout_local_planner/src/local_planner_ros.cpp`：
  - jerk limiter 之后再次执行 `cmd_v_out = min(cmd_v_out, profile_v)`；
  - 速度 profile hard cap 优先于 jerk 平滑；
  - jerk 仍通过 `/profile_cap/implied_jerk` 诊断，不作为可以突破 profile 的理由。

### 结论

- 论文 baseline 的执行语义应是：

```text
TOPPRA/Ruckig profile 是外部 timing baseline 的硬速度上界；
execution cap 必须保证最终 cmd_v 不超过 profile；
若 hard cap 引入局部 jerk，则作为执行代价报告，而不是放宽 profile 约束。
```


## Ruckig cap03 零速死锁修复

### 输入 bag

```text
/data/a/slosh_bags/sim/20260526/20260526_P2_s_curve_CUSTOM_runruckig_cap03_011806.bag
```

### 现象

- `/scout/global_path_fixed` 持续发布；
- MPC 处于 `TRACKING`，求解成功；
- 但：
  - `/reference/v_ref_horizon` 全程为 0；
  - `/profile_cap/v_profile` 全程为 0；
  - `/profile_cap/cmd_v_post_cap` 全程为 0；
  - `/cmd_vel.linear.x` 全程为 0；
  - odom 位移约 `0.011m`，几乎未动。

### 原因

- Ruckig/TOPPRA 的 spatial profile `v(s)` 在 `s=0` 处物理上为 0；
- 当前 PathHandler 通过 `s_next = s + v_ref * dt` 推进 horizon；
- 若第一步刚好采到 `s=0, v_ref=0`，整个 horizon 无法离开起点，形成零速死锁；
- execution cap 同样用当前 `s_now` 查询 profile，导致最终 `cmd_v` 被锁为 0。

### 修改

- `PathHandler::getReferencePoints()`：
  - 外部 CSV 有效且当前 `profile_v_ref <= 1e-6` 时；
  - 若未到路径末端，则向前看一个小步长 `max(0.02, speed_profile_ds)`；
  - 用前方 profile 速度作为启动参考，避免 horizon 卡在 `s=0`。
- `LocalPlannerROS` 的 execution cap：
  - 同样在 `profile_v <= 1e-6` 时用前方小步长查询 profile；
  - 仅用于外部 profile cap，C/D/E/F 内部速度剖面不受影响。


- diff check 通过。

## Ruckig cap04 CSV near-duplicate endpoint 修复

### 输入 bag

```text
/data/a/slosh_bags/sim/20260526/20260526_P2_s_curve_CUSTOM_runruckig_cap04_012407.bag
```

### 现象

- 实际仍跑成内部速度剖面：
  - `/reference/v_ref_horizon` 最大值 `2.4m/s`；
  - `/profile_cap/active` 全为 0；
  - `/profile_cap/v_profile` 为 `NaN`；
  - `/profile_cap/cmd_v_post_cap` 最高约 `2.4m/s`。
- bag 的第二条 `/experiment/config_summary` 已包含 Ruckig CSV 路径，说明脚本生成了 CSV 并传给 MPC。

### 原因

- 检查 CSV：

```text
/data/a/fixed_paths/sim/baseline_profiles/20260526_P2_s_curve_CUSTOM_runruckig_cap04_012407_ruckig_speed_profile.csv
```

- 最后两行 `s_normalized` 分别约为：

```text
0.9999999994825706
1.0
```

- 差值约 `5e-10`，小于加载器原先的 `1e-9` 严格递增阈值；
- `PathHandler::loadExternalSpeedProfile()` 因此拒绝整个外部 CSV，导致回退到内部速度剖面。

### 修改

- 调整 `PathHandler::loadExternalSpeedProfile()`：
  - 允许数值级 near-duplicate `s_normalized`；
  - 若新 `s` 与上一行差值在 `1e-9` 内，则用后一行替换前一行；
  - 只有明显倒退 `s < prev_s - 1e-9` 才判为错误。

### 验证

```bash
catkin_make -DCATKIN_WHITELIST_PACKAGES=scout_local_planner
git diff --check
```

- 编译通过；
- diff check 通过。

## Scout Local Planner 重构：抽出 ProfileExecutionCap

### 背景

- TOPPRA/Ruckig-style baseline 需要保留 `external_speed_profile_csv` 和执行层 `cmd_v` cap。
- 这段逻辑不属于 MPC 求解，也不属于 terminal 状态机，放在 `LocalPlannerROS::controlLoop()` 会继续放大主循环复杂度。

### 修改

- 新增 `ProfileExecutionCap`：
  - 输入：`cmd_v`、`filtered_v`、`dt`、`PathHandler`、`PathHandlerParams`、`VehicleParams`；
  - 输出：`cmd_v`、是否 applied、`v_profile`、cap 前后速度、implied ax / jerk；
  - 内部持有上一帧 ax，用于可选 jerk limit。
- `LocalPlannerROS`：
  - 只负责读取 ROS 参数并 `setParams()`；
  - 主循环调用 `profile_execution_cap_.apply()`；
  - 继续发布原 `/profile_cap/*` 诊断 topic，topic 语义不变；
  - `resetWarmStart()` 时重置 profile cap 内部 ax 状态。


## Scout Local Planner 重构：抽出 TerminalController

### 背景

- 当前 terminal 主线已经收敛为：
  - `terminal_slowdown`
  - `terminal_capture_stop`
  - `TERMINAL_MPC_STOP`
  - `goal_position_reached + speed_low -> REACHED`
  - `GoalInfo.dx <= 0 -> cmd_v 强制 0`
- 这些逻辑原先散在 `controlLoop()` 和 `updateState()` 里，和 MPC 求解、profile cap、诊断发布耦合。

### 修改

- 新增 `TerminalController`：
  - 持有 `goal_stop_pending` 状态；
  - 负责 terminal capture / release / reached 判定；
  - 负责两段式 terminal velocity envelope；
  - 负责 terminal phase 的 post-MPC `cmd_v` clamp；
  - 输出 `TerminalPlan` 与 `TerminalClampOutput`。
- `LocalPlannerROS`：
  - 删除 terminal 参数成员和 `goal_stop_pending_` 成员；
  - 只读取 ROS 参数并传给 `TerminalController`；
  - `updateState()` 调用 `terminal_controller_.updateState()`；
  - `controlLoop()` 调用 `terminal_controller_.plan()` 和 `clampCommand()`；
  - `/terminal/*` 原 topic 名称和诊断字段保持不变。

### 验证

```bash
catkin_make --pkg scout_local_planner
```

- 编译通过。

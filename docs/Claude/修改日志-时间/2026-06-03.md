## 模块化/解耦合复审（全 diff 过一遍）+ 加固

按方案 §10 红线 + §11 清单审查全部新增/改动，结论：依赖方向、模块职责、参数切换、生成物管理、诊断一致性均满足。复审中加固两个耦合点：

- **参数布局契约（python↔C++）**：`continuous_mpcc_solver_acados.cpp` 加 `static_assert(E_L_REF+1==SPMPC_B0_NP)` 与 `static_assert(W_SLOSH_ETA_DOT+1==SPMPC_SLOSH_NP)`，把 C++ 参数枚举与生成器 NP 绑死——python 模型改了参数布局而 C++ 没同步，则**编译期失败**而非运行期错值。
- **horizon 一致性**：wrapper 改用求解器固化的 `SPMPC_*_N`（codegen 时确定）跑 stage 循环，而非 `input.horizon_steps`，避免 common.yaml 改 N 不重 codegen 导致越界。
- 清理自引入死变量 `prev_w`（J_smooth 只罚纵向 da，与 §4.1/primitive 一致）。

复审确认项：core/solvers/reference/dynamics 零 ROS 依赖；solvers 无反向依赖；ros 仅经 `SpmpcProblem` 用 solver（factory 的 `isKnownSolverBackend` 为前向只读校验）；SloshDynamics 为 primitive 与 continuous 唯一共用物理核；生成物 gitignore；加固后整包在有/无 acados 两种环境均编译通过。

## 连续 MPCC 首次仿真闭环结果（B0 vs B_slosh）

用户在仿真机跑通 B0_continuous / B_slosh_continuous。

- **Phase C/D 闭环验证通过**：两者均到 goal、progress 单调=1.0、solver_ms≈4ms（≪33ms 实时线）、acados b0/slosh 双模型正常工作。
- **诊断对比口径修正**：原 analyze 用控制器内部**预测** h_peak 比较，但 B0(5维)无 slosh 状态恒为 0，跨模型不可比 → 误报"B_slosh 晃动更高"。修复：`analyze_b0_bslosh_compare.py` 增读 `/spmpc/debug/slosh_state`（observer，两次都跑、与控制器模型无关），以 observer eta_norm 作主晃动判定。
- **真实结果**：observer 峰值晃动 B_slosh=0.0100 vs B0=0.0307（**↓67%**），峰值晃动速度 0.310 vs 0.446（↓）；代价是减速（cmd_v 0.47 vs 0.69）。均值略升（0.0033 vs 0.0023）。→ 抗晃在连续 MPCC 上**生效**（降峰值），符合"慢一点换大幅降峰值"的预期。
- **调参信号**：均值略升 + cmd_omega 偏高(0.156 vs 0.025) + J_slosh_eta 尖峰到 4.0 偶尔主导 → `w_slosh=5.0` 偏大。Phase E 第一步建议 w_slosh sweep(1/2/3/5，运行时参数，无需重 codegen)找拐点。

## 认知校正：仿真不测降晃效果，实物 RGB 才是真值

- 仿真无真液体，`/spmpc/debug/slosh_state` 是模型 observer 估计，非真晃动 → sim 永远测不出真实抑晃，sweep 的"非单调"本质是量噪声（同一 B0 两次 cmd_w 0.025 vs 0.311，run-to-run 不可复现）。
- **仿真定位收敛为"集成联调"**：连续 MPCC 在 sim 端到端跑通（acados 双模型/参数切换/到点/实时/诊断/录包/analyze 全通）= 集成验证 PASS。不再为 sim 追降晃数，也不为 sim 做路径钉死/复现工程（为可信 sim 数值服务，已无意义）。
- 抑晃效果与 w_slosh 工作点 → 全部移到实物，以 RGB max-LCR 为真值。

## cost 各项占比监控修复

- **问题**：`/spmpc/cost_breakdown` 的 pct_*(字段12-21)分母用 `|J_total|`，而 total 含负的 J_progress 奖励 → total 近零时百分比爆炸（实测 slosh_pct mean 220% / max 2282%），占比监控失效。
- **修复**(`diagnostics_publisher.cpp`)：分母改为各项绝对值之和 `Σ|J_i|`，pct 有界([-100,100])、可解释；字段布局不变(仍 22 维)。primitive 与 continuous 后端都受益。
- **离线视图**(`analyze_b0_bslosh_compare.py`)：新增 `cost占比` 行，从原始 J 均值算 `|mean(J_i)|/Σ|mean(J_j)|`(不依赖话题 pct，旧 bag 直接可看)。
- **首次占比结果(连续后端)**：B0 = progress 96%/control 3%/contour 1%；B_slosh = **slosh 72%**(eta66+etad6)/progress 24%/**contour 0%**。→ 量化证实 w_slosh=5 偏大：晃动项主导目标、跟踪被挤没，是"画龙"的根因。健康配比应让 slosh ~20-40%。实物 w_slosh 扫可同时盯此占比。
- SOP 加 §5.1 "cost 占比作为 w_slosh 辅助判据"(健康区间 slosh 20-40%, >50%且contour≈0=偏大, <10%=偏小)。

## MPC horizon 内晃动预测摘要

背景：

```text
20260514 C/D 实物 bag 的 Cost Contribution Check 显示：
  D 组 pct_slosh_total_mean ≈ 0.002%
  C 组 pct_slosh_total_mean = 0

需要区分两类原因：
  1. MPC horizon 内没有真正预测出 eta 增长；
  2. horizon 内 eta 已预测出来，但 slosh cost 尺度太小。
```

改动：

```text
src/scout_apps/control/scout_local_planner/src/local_planner_ros.cpp
src/scout_apps/control/scout_local_planner/include/scout_local_planner/local_planner_ros.h
  新增 /mpc/slosh_horizon_summary (std_msgs/Float32MultiArray)。

src/scout_apps/control/scout_local_planner/scripts/record_slosh_experiment.sh
  录包 topic 增加 /mpc/slosh_horizon_summary。

docs/重要文档/20260513_SloshPriorityMPC有效性验证方案.md
  增加 horizon 内 eta 预测诊断字段、检查命令和判断逻辑。
```

字段顺序：

```text
0  eta_norm_0_m
1  eta_norm_max_m
2  eta_dot_norm_0_mps
3  eta_dot_norm_max_mps
4  h_modal_max_mm
5  h_total_max_mm
6  k_h_total_max
7  v_abs_p95_mps
8  omega_abs_p95_radps
9  ax_abs_p95_mps2
10 ay_abs_p95_mps2
11 eta_growth_ratio
12 h_total_0_mm
```

判断：

```text
eta_growth_ratio < 1.1 且 h_total_max_mm 很小：
  horizon 没有预测出明显未来晃动。

eta_growth_ratio 明显 > 1，但 pct_slosh_total 仍 < 1%：
  horizon 内 eta 已预测出来，主要问题是 slosh cost 尺度太小。

eta_growth_ratio 明显 > 1，pct_slosh_total 到 3%-20%，但 RGB 未下降：
  问题转向模型方向、模型保真度或控制权衡。
```

```text

20260514 D 组 pct_slosh_total_mean 约 0.002%，说明晃动项几乎不参与 MPC 决策。
```

改动：

```text
src/scout_apps/control/scout_local_planner/include/scout_local_planner/types.h

    slosh_eta_dot_ratio

docs/重要文档/20260513_SloshPriorityMPC有效性验证方案.md
```

## MPC 数学化架构总结同步

背景：

```text
normalized slosh cost、/mpc/slosh_horizon_summary、terminal_capture_stop
已经进入当前主线，docs/重要文档/mpc_数学化架构总结.md 中的 cost 和 near-goal 描述需要同步。
```

改动：

```text
docs/重要文档/mpc_数学化架构总结.md
  更新 slosh soft cost 数学表达：
    Q_slosh_eta = Q_slosh * h_coeff^2 / h_ref^2
    Q_slosh_eta_dot = slosh_eta_dot_ratio * Q_slosh_eta / omega_n^2

  更新 cost 项数口径：
    基础 8 项 + 可选 2/4 项 slosh + 可选 1 项 omega feedforward。

  新增 /mpc/slosh_horizon_summary 监测量说明和字段顺序。

  更新 near-goal 工程语义：
    terminal_slowdown 属于 MPC 前的参考减速；
    terminal_capture_stop / terminal recovery 属于外层控制；
    slosh cost 有效性统计应优先截在 capture/recovery 之前。
```

## 实物传感器启动脚本等待逻辑修正

背景：

```text
src/scout_apps/control/scout_local_planner/scripts/launch_real_sensors_stack.sh
原先只在每个 roslaunch 后固定 sleep 4s，并检查进程是否仍存活。
实物上进程存活不代表关键 topic 已经发布，可能导致定位、IMU 或相机后续节点启动过早。
```

改动：

```text
src/scout_apps/control/scout_local_planner/scripts/launch_real_sensors_stack.sh
  START_DELAY 默认从 4s 调整为 6s。
  SETTLE_DELAY 默认从 8s 调整为 12s。
  新增 READY_TIMEOUT=45s。
  新增 POST_TOPIC_DELAY=3s。
  新增 wait_for_topic():
    nanoscan3_front 后等待 /scan_front 首包；
    scout_imu_with_tf 后等待 /imu/data 首包；
    realsense2_camera 后等待 /camera/color/image_raw 首帧。

  Cartographer /map 等待默认不强制，避免 /odom 未接好时脚本卡死；
  需要时可用 WAIT_FOR_LOCALIZATION_MAP=true 开启可选 /map 等待。
```


当前求解链路：

```text
LocalPlannerROS::controlLoop
  -> PathHandler::getReferencePoints(...)
  -> std::vector<ReferencePoint> ref_points
  -> MPCSolver::solve(current_state, ref_points)
  -> MPCSolver::buildQP(...)
  -> ConstraintManager::buildQPConstraints(...)
  -> OSQP
```

确认结果：

```text
1. ReferencePoint 当前只有 x/y/theta_path/kappa/s/v_path/v_ref。
   v_ref 只进入 cost_function，是软速度目标，不是硬边界。

2. ConstraintManager 已有 v、a、omega、Δa、Δomega 约束行。
   v/a/jerk 约束可以优先做成已有 bound 的时变 l/u，不需要新增约束行。

3. MPCSolver::updateOSQP 每周期更新 P/A/q/l/u。
   若 Step 2a 只改 l/u，不改稀疏结构，可以保持 OSQP update_bounds 路径。

4. post-processor 当前只发布 /scout/global_path_anti_slosh、metrics、candidate_report 和 debug paths。
   尚未发布 path 点级别 v/a/jerk budget sibling topic。
```

最小实现建议：

```text
Step 1:
  post-processor 为 selected candidate 发布与 path 点对齐的 budget topic。
  正式 topic 建议 trajectory_msgs/JointTrajectory:
    point.positions = [v_upper, a_upper, a_lower, jerk_upper]

Step 2a:
  ReferencePoint 增加可选 budget 字段。
  LocalPlannerROS/PathHandler 将 path 点级别 budget 按 s 插值到 horizon ref_points。
  MPCSolver 把 horizon budget 传给 ConstraintManager。
  ConstraintManager 仅在已有 v/a/Δa 约束行上修改 l/u。
```

边界：

```text
这只覆盖 v/a/jerk 执行一致性。
Step 0a 已显示 omega 也有 2/5 包触发，因此 Step 2a 后必须重点检查 omega/ay 是否被间接压住。
如果 omega 仍反弹，不能把 Step 2a 写成完成版，需要进入 ay/omega 约束设计或停止本方向。
```

实现取舍：

```text

只靠 budget 与 path 点索引对齐不安全；
显式 s 允许 MPC 端按弧长插值，避免索引错位。
```

## Slosh-score 高度口径修正：modal + parabola

依据：

```text
docs/重要文档/Slosh Dynamics论文中建模总结.md
```

问题：

```text
当前在线 slosh-score 的高度预测只使用：
  h_modal = height_coeff * hypot(eta_x, eta_y)

但工程 /slosh/height 的语义是：
  h_total = h_modal + h_parabola
  h_parabola = R^2 * omega_z^2 / (4g)

因此此前 score 优化的 h_pred 与实际评价的 /slosh/height 口径不一致。
```

修改：

```text
anti_slosh_path_post_processor.py
  rollout_slosh_metrics() 中加入 omega = v * kappa。
  计算:
    slosh_h_modal_p95
    slosh_h_parabola_p95
    slosh_h_p95 = p95(h_modal + h_parabola)
    slosh_h_max = max(h_modal + h_parabola)
  report 增加:
    sH   total height p95
    sHm  modal height p95
    sHp  parabola height p95

anti_slosh_path_post_processor.launch
  新增:
    slosh_score_container_radius
    slosh_score_use_parabola_term

run_sim_fixed_path_bag.sh
  透传:
    POST_PROCESSOR_SLOSH_SCORE_CONTAINER_RADIUS
    POST_PROCESSOR_SLOSH_SCORE_USE_PARABOLA
```

默认参数：

```text
container_radius=0.0185
use_parabola_term=true
```

验证：

```text

```

## OSCRS 平行线接入

目标：

```text

```

代码修改：

```text
anti_slosh_path_post_processor.py:
  新增 oscrs/active_enable 参数，默认 false。
  GEOREF_TUNED 行为不变。
  OSCRS shadow/active 均会对候选做 slosh rollout，输出 h/residual/feasible/violation/score。
  OSCRS_ACTIVE 只在 accepted 且 height/residual gate 都通过的 candidate 集合中选择 oscrs_score 最低者。
  若没有 feasible candidate，则 fallback 到 geometry winner。
  candidate_report summary 新增 selected / geo / oscrs / active / fallback 字段。

anti_slosh_path_post_processor.launch:
  暴露 oscrs_active_enable。

  唯一新增行为是 POST_PROCESSOR_OSCRS_ACTIVE_ENABLE=true。
  slosh_score 强制 false，避免与 OSCRS hard gate 混在一起。
```

文档修改：

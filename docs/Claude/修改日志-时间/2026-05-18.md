## 新增 MPC 终点收敛与固定路径验证方案

背景：

```text
当前工作重点回到 MPC cost 本身，不再混入 OSCRS / GeoRef。
在固定路径比较 C/D 组 cost 效果之前，需要先确认当前 terminal 是否稳定收敛，
否则终点过冲、回头或急刹会污染 slosh cost 的实物结论。
```

改动：

```text
docs/重要文档/20260518_MPC终点收敛与固定路径验证方案.md
  新增今日实物验证 SOP：
    1. 先用 launch_real_sensors_stack.sh 启动底盘、雷达、定位、IMU、RealSense；
    2. 再启动 mbf_global.launch；
    3. 再启动 Q_slosh=0 的 MPC terminal smoke；
    4. 录 terminal smoke bag，并用 diagnose_terminal_overshoot.py /
       analyze_terminal_transition.py 判断是否收敛；
    5. terminal 通过后再进入 /scout/global_path_fixed 固定 S 弯路径；
    6. 固定路径阶段只比较 C 组 SMOOTH_SPEED_RELAXED 与 D 组 SLOSH_PRIORITY_MPC。
```

约束：

```text
本方案只验证 MPC cost / terminal；
不启动 OSCRS；
不启动 GeoRef path post-processor；
不使用 /slosh/height 作为真实液面主指标。
```

## 解耦 terminal capture 与外层制动

背景：

```text
20260518 实物 terminal smoke 显示：
  terminal 进入时 odom_v 仍约 0.7-0.86 m/s；
  terminal_ref_v_verdict 多次为 HORIZON_FIRST_STAYS_HIGH_AT_TERMINAL；
  odom_ax / odom_jerk 在 terminal 前后出现高脉冲。

bag 时间序列进一步确认：
  terminal_slowdown 已经降低 v_ref；
  但 terminal_capture_stop_active 分支会在进入半径时直接 publish brake cmd 并 return；
  外层 capture brake 抢走了 MPC 的终点收敛职责。
```

改动：

```text
src/scout_apps/control/scout_local_planner/src/local_planner_ros.cpp
  terminal_capture_stop_active 不再直接 publishCmdVel(brake_v, brake_omega)；
  进入 capture 半径后仅设置 goal_stop_pending_=true；
  /terminal/mode 改为 TERMINAL_MPC_STOP；
  继续执行 MPC solve，由 MPC 负责终点低速收敛；
  goal_stop_pending_ 时提高 Q_v 和 terminal_factor_v；
  goal_stop_pending_ 时 v_des_target=0，但通过 v_des_rate_limit 平滑降低 v_des_eff。

src/scout_apps/control/scout_local_planner/scripts/analysis/analyze_terminal_transition.py
  将 TERMINAL_MPC_STOP 识别为 terminal/capture 事件；
  报告 flag 从 CAPTURE_STOP 改为 TERMINAL_STOP。

docs/重要文档/20260513_SloshPriorityMPC有效性验证方案.md
docs/重要文档/20260518_MPC终点收敛与固定路径验证方案.md
  同步终点语义：
    capture 半径内进入 TERMINAL_MPC_STOP；
    MPC 继续求解；
    外层不再作为主制动控制器。
```

结论：

```text
terminal capture 现在是监督/验收状态，不再是主制动控制器。
下一轮实物 smoke 应检查：
  first_terminal_mode 是否为 TERMINAL_MPC_STOP；
  /reference/v_des_eff 是否连续下降；
  /cmd_vel 和 /odom 是否跟随下降；
  odom_ax / odom_jerk 是否显著低于旧 CAPTURE_BRAKE 结果。
```

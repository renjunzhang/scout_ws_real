## 修复 TERMINAL_MPC_STOP 参考速度反弹

背景：

```text
实物 bag：
  /home/geist/slosh_bags/real/20260518_terminal_smoke/slosh_Q0_20260518_154534_terminal_smoke_run01.bag
  /home/geist/slosh_bags/real/20260518_terminal_smoke/slosh_Q0_20260518_154653_terminal_smoke_run02.bag

现象：
  first_terminal_mode = TERMINAL_MPC_STOP；
  recovery = 0；
  但小车完全没停，仍冲过终点。

诊断：
  TERMINAL_MPC_STOP 进入时 v_des_raw/v_des_target 已经是 0；
  /reference/v_des_eff 曾短暂降到 0；
  下一周期又从 0 反弹到约 0.6-0.8 m/s；
  /reference/v_ref_horizon 随之重新变高，MPC 继续给正向 cmd_v。

根因：
  v_des rate limiter 把 last_v_des_eff_ <= 1e-6 解释为“没有上一轮参考速度”，
  因而用 current_v_ 作为 rate limiter 起点。
  这在启动阶段合理，但在 terminal stop 中会把已经降到 0 的参考速度重新抬高。

第二个问题：
  车体越过终点后 dist 变大，goal_stop_pending_ 被释放，
  terminal/mode 回到 NONE，raw v_des 又恢复巡航速度。
```

修改：

```text
src/scout_apps/control/scout_local_planner/src/local_planner_ros.cpp
  goal_stop_pending_ 或 v_des_target<=0 时，last_v_des_eff_=0 是有效历史值；
  不再回退到 current_v_ 作为 rate limiter 起点；
  goal_stop_pending_ 下若已经越过 goal(dx < terminal_goal_behind_x_)，
  即使 dist 因过冲变大，也不释放 pending stop。
```

预期：

```text
下一轮 terminal smoke 中：
  v_des_raw = 0；
  v_des_target = 0；
  v_des_eff 应连续降到 0 后保持 0；
  v_ref_horizon 不应在 terminal stop 内重新反弹；
  即便过冲，terminal/mode 也应保持 TERMINAL_MPC_STOP，不应回到 NONE 恢复巡航速度。
```

## 引入 terminal 运动学停车包络与诊断话题

背景：

```text
99d62da 后实物 run03 显示：
  v_des_eff / v_ref_horizon 已经能在 TERMINAL_MPC_STOP 内保持 0；
  但进入 terminal 时 odom_v 仍约 0.77 m/s；
  MPC 仅靠 Q_v/terminal_factor_v 软代价减速太慢，仍越过终点约 1.36 m。

新的问题不再是参考速度反弹，而是 terminal 执行层缺少硬停车包络。
```

修改：

```text
src/scout_apps/control/scout_local_planner/src/local_planner_ros.cpp
  新增 computeTerminalVelocityEnvelope():
    v_env(d) = min(v_max_terminal, sqrt(2 * a_brake * max(0, d - goal_tolerance)))

  pre-MPC:
    v_des = min(raw_v_des, v_env)

  post-MPC:
    cmd_v = min(solution.v_cmd, v_env)
    如果 GoalInfo.dx <= 0，cmd_v 强制为 0。
    terminal phase 下同步 filtered_v_ <= cmd_v，避免 publishCmdVel 内部 EMA
    让实际 /cmd_vel 仍高于 envelope。

  in_terminal_phase = goal_stop_pending_ || envelope_active
    解决车体越过 goal 后 dist 重新大于 terminal_slowdown_distance 时，
    dx <= 0 强制 0 保护失效的问题。

  REACHED:
    从仅 speed_low 改为 speed_low && goal_position_reached；
    避免冲过终点后停在容差外却假阳性 REACHED。

src/scout_apps/control/scout_local_planner/include/scout_local_planner/local_planner_ros.h
src/scout_apps/control/scout_local_planner/src/local_planner_ros.cpp
  新增 terminal envelope 诊断话题：
    /terminal/v_envelope
    /terminal/envelope_active
    /terminal/phase_active
    /terminal/cmd_v_pre_clamp
    /terminal/cmd_v_post_clamp

src/scout_apps/control/scout_local_planner/scripts/record_slosh_experiment.sh
  白名单补齐上述 terminal envelope 诊断话题。

docs/重要文档/20260518_MPC终点收敛与固定路径验证方案.md
  重整 terminal smoke：
    terminal_slowdown_v_max:=0.18 作为“强终点收敛 smoke”；
    terminal_slowdown_v_max:=0.80 作为“包络形状诊断 smoke”；
    明确这些 terminal 包只判断终点收敛，不进入晃动效果统计。
```

注意：

```text
terminal_slowdown_v_max 是 envelope 上限。
当 terminal_slowdown_v_max:=0.18 时，envelope 多数时候被常数 0.18 截断；
这有利于先验证不冲过终点，但可能增加 cmd_v/odom ax 脉冲。

```

## terminal 输出层增加线速度变化率限制

背景：

```text
20260518 terminal envelope smoke 对比：
  terminal_slowdown_v_max:=0.18 时不会过冲，但停在容差外，无法 REACHED；
  terminal_slowdown_v_max:=0.80 时可以 REACHED，min_dist 约 0.14 m；
  但 terminal 内 cmd_v / odom_v 的下降仍有明显脉冲。

说明 envelope 已经解决“停不住”，下一步应从结构上限制 terminal 输出加速度，
而不是继续把 terminal_slowdown_v_max 压得更低。
```

修改：

```text
src/scout_apps/control/scout_local_planner/src/local_planner_ros.cpp
  新增通用 limitRate() helper。
  terminal phase 输出层流程改为：
    1. MPC solution.v_cmd
    2. envelope hard clamp
    3. 若 GoalInfo.dx <= 0，cmd_v 强制 0
    4. 未越过 goal 时，用 path_handler/max_tan_decel 对 cmd_v 做变化率限制
    5. 同步 filtered_v_ = cmd_v_out，避免 publishCmdVel 的 EMA 把上一帧高速带回输出

  不新增 ROS arg；terminal 输出限加速度复用 path_params_.max_tan_decel。
```

预期：

```text
下一包建议继续用 terminal_slowdown_v_max:=0.80；
观察 /terminal/cmd_v_pre_clamp、/terminal/cmd_v_post_clamp、/cmd_vel、/odom。
目标是保留 REACHED，同时降低 terminal 内 cmd_ax / odom_ax 脉冲。
```

## 实物启动脚本固定 RealSense RGB 并关闭深度/红外

背景：

```text
实物液面识别只需要 /camera/color/image_raw。
当前 launch_real_sensors_stack.sh 直接调用 rs_camera.launch，未显式设置 RGB 分辨率，
且 realsense2_camera 默认 enable_depth=true。红外图像流默认关闭，但深度流会引入额外负载，
也可能带来与 RGB 液面识别无关的红外投射/反光因素。
```

修改：

```text
src/scout_apps/control/scout_local_planner/scripts/launch_real_sensors_stack.sh
  RealSense 默认改为只开 RGB：
    enable_color:=true
    color_width:=640
    color_height:=480
    color_fps:=30
    enable_depth:=false
    enable_infra:=false
    enable_infra1:=false
    enable_infra2:=false

  增加环境变量覆盖入口：
    REALSENSE_COLOR_WIDTH / REALSENSE_COLOR_HEIGHT / REALSENSE_COLOR_FPS
    REALSENSE_ENABLE_DEPTH / REALSENSE_ENABLE_INFRA / REALSENSE_ENABLE_INFRA1 / REALSENSE_ENABLE_INFRA2

  启动后自动读取一次 /camera/color/camera_info：
    打印实际 width / height；
    若与 REALSENSE_COLOR_WIDTH / REALSENSE_COLOR_HEIGHT 不一致则给 WARN；
    原始 camera_info 保存到本次 LOG_DIR/camera_color_camera_info.log。
```

说明：

```text
关闭 depth/infra 不会削弱 HSV 红色液体识别；HSV 使用 RGB 图像。
真正影响红色区域识别的是可见光照、曝光、白平衡和液面/容器高光。
若后续需要重新调 HSV，应以固定 RGB 配置下的实物图像为准。
```

## sim launch 对齐实物 launch：补 16 个 arg + 对应 param

背景：

```text
仿真跑 anti-slosh S 弯实验时，需要用实物 launch 同款 MPC 参数。
slosh_experiment_sim.launch 落后于 slosh_experiment.launch（real），缺以下 16 个 arg：

  mpc_R_omega / mpc_R_domega
  terminal_slowdown_enable / terminal_slowdown_distance / terminal_slowdown_v_max

  terminal_capture_stop_enable / terminal_capture_stop_distance
  v_des_rate_limit_enable / v_des_accel_limit / v_des_decel_limit

```

修改：

```text

  在 <arg> 节插入 16 个 arg 声明（默认值与 real launch 对齐）；
  在 <node> 的 <param> 节插入对应 16 个 <param> 块。
```

内容：

```text
MPC 权重段（mpc_Q_v 附近）：
  + mpc_Q_lag    (default 0.5)   -> mpc/Q_lag
  + mpc_Q_contour (default 32.0) -> mpc/Q_contour
  + mpc_Q_etheta (default 15.0)  -> mpc/Q_etheta
  + mpc_R_omega  (default 2.0)   -> mpc/R_omega
  + mpc_R_domega (default 4.0)   -> mpc/R_domega

终点 / 速度限幅段（terminal_cmd_omega_rate_limit 之后）：
  + terminal_slowdown_enable / distance / v_max / Q_v / terminal_factor_v
  + terminal_capture_stop_enable / distance
  + v_des_rate_limit_enable / accel_limit / decel_limit

IMU 段（slosh_imu_ay_bias_init_duration 之后）：
  + slosh_imu_ay_scale (default 1.0) -> slosh_estimator/imu_ay_scale
```

保留不动：

```text
sim launch 原有的 sim 专属 arg 全部保留：
  mpc_cmd_vel_lead_time=0.15           Gazebo 反馈滞后补偿
  risk_scheduler_beta / gamma / rho_0 / rate_limit_per_step / Q_eta_min / Q_eta_max
```

## sim S 曲线跟踪首跑 + 与实物 D 组对比 + sim-real 数值 gap 评估

```text

  终端1: launch_sim_nav_stack.sh  (Gazebo + bridge + cartographer + MBF)
  终端2: slosh_experiment_sim.launch  (33 个 arg 全生效)
  终端3: template_fixed_path_generator.py
         --goal-topic /scout/template_goal    ← 关键：换专用 topic 避开 MBF
         --output-topic /scout/global_path_fixed
         --start-heading current
         --spacing 0.05 --amplitude-ratio 0.18
         --min-amplitude 0.25 --max-amplitude 1.20
  终端4: rosbag record + 验证 TF/订阅 + 发 goal (-1, 0) in map
  bag: /home/a/scout_ws/bags/sim_s_curve/20260520_133904_s_curve.bag
```

结果（infrastructure OK）：

```text
路径生成    : 103 点 / 5.08 m / map 帧               OK
路径起点(map): (+3.35, +0.09)                         = robot 当时 map 位姿
路径终点(map): (-1.00, 0.00)                          = goal
robot 终态  : map x ≈ -0.89   (距 goal 11 cm)        到位
cmd_vel.linear.x  range: 0 -> 1.46 m/s              MPC 正常出指令
cmd_vel.angular.z range: -1.43 -> +0.90 rad/s       双向转弯，S 弯生效
```

副现象：

```text
map ↔ odom 帧 yaw 翻转 180°
  map 帧 robot 从 +3.35 → -1.00
  odom 帧 robot 从 -3.38 → +0.84
不影响跟踪正确性（MPC 看 map）；仅 RViz 观感与 Gazebo 方向相反。
cartographer 加载 pbstream 后初始 yaw 对齐结果。
```

与实物 D 组（同 Q_slosh=5，n=3 平均）数值对比：

```text
                    real D     sim D    sim/real
v_p95   [m/s]       1.14      1.36      1.2x
ax_p95  [m/s^2]     0.28      4.01      14x   <<<
ax_rms              0.17      1.84      11x
ay_p95              0.30      2.82      9.4x  <<<
ay_rms              0.13      1.26      9.7x
jerk_p95 [m/s^3]    3.24      506       156x  <<<
jerk_rms            1.51      222       147x
slosh_p95   [mm]    0.89      4.32      4.9x
slosh_peak  [mm]    ~1.0      6.53      6.5x

实物 summary 来源：
/data/a/slosh_bags/real/20260518_fixed_path_cost/red_visual_analysis_20260518/
  fixed_path_cost_effect/fixed_path_cost_effect_summary.csv
```

分层归因（再次确认之前的诊断）：

```text
MPC 命令层 ax_p95 = 2.29 m/s^2（cmd_vel.linear.x 差分）：
  比实物 0.28 已经 8x 高。
  原因：sim 中 odom = cmd（无打滑），MPC 反馈完美 → 自己敢开更猛；
        实物轮胎打滑 → MPC 看到响应慢 → 自我保守。
底盘层放大 2.29 → 4.01 m/s^2：
  skid_steer 插件 torque=1000，无 wheelAcceleration 限制，
  瞬时跟踪 cmd_vel，对 cmd 阶跃产生冲击响应。
两层叠加 = 实物 14x。
```

判定与决定：

```text
sim 当前可用范围：
  trajectory 拓扑验证（能不能停在 goal）        OK 可直接用
  Q_slosh 0 vs 5 趋势对比                       OK 可定性
  ax/ay/jerk/slosh 绝对值与实物互通               不可用
  RL 训练直接 zero-shot 到实物                    不可用

修到能数值互通需要：
  1. cmd_vel rate limiter 节点（~1 小时）+ 标定（半天）→ 估计 sim ax 4.0 → 0.8（降 5x）
  2. 仍距实物 0.28 约 3x，paper 数据仍不能直接拿 sim 出
  3. RA-L 投稿（2026-08）核心数据已经在实物上，paper 数据从实物出更直接

结论：不再为 sim-real 数值 gap 投入。sim 保留做 smoke test：
  - 新 MPC commit 后跑一次确认不崩、能停 goal
  - paper figure 的 trajectory overlay 截图（定性）
  - 训 RL 阶段再评估平台（Isaac Sim / MuJoCo）

主线回到实物 bag 录制 + 分析。
```

新增：

```text
src/scout_apps/control/scout_local_planner/scripts/run_s_curve_smoke_test.sh
```

用途：

```text
把上述 4 终端编排固化为一键脚本，仅用于 smoke test：
```

## 修正固定路径生成口径

背景：

```text
用户指出：
  template_fixed_path_generator.py 实际是根据当前小车起点 + goal 现场生成 P2_s_curve；
  如果每次起点有轻微偏差，生成出的路径也会有轻微差异。

原文“所有组使用同一个 P2_s_curve.json”容易误导为所有包必须复用同一个 JSON。
```

修改：

```text
docs/重要文档/20260518_MPC终点收敛与固定路径验证方案.md
```

要点：

```text
1. 固定路径主流程改为：
   同一模板、同一 goal、同一生成参数；
   每包前回到同一物理起点和朝向；
   允许重新生成 /scout/global_path_fixed。

2. 录包后用：
   path_len；
   trajectory_overlay；
   起始 tracking error；
   检查路径一致性。

3. 复用同一个 JSON 被记录为更严格但风险更高的做法：
   只有小车每次都能回到几乎同一定位起点时才推荐；
   否则初始 tracking error 会污染 C/D/E/F 对比。
```

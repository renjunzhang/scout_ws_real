## 记录 preview slosh penalty 作为后续结构改进候选

背景：

```text
用户讨论：
  当前 slosh 项惩罚 eta/eta_dot，属于液体状态层；
  R_a/R_da 或 ax constraint 直接惩罚纵向激励源头；
  希望记录 slosh 项是否可以在 MPC rollout 中“前预测一步”。
```

修改：

```text
docs/重要文档/20260518_MPC终点收敛与固定路径验证方案.md
  新增“后续结构改进：preview slosh penalty”。
```

要点：

```text
当前形式：
  J_slosh,k = Q_eta * eta_k^2 + Q_eta_dot * eta_dot_k^2

候选形式：
  x_slosh,k+1 = A_d * x_slosh,k + B_d * a_k
  J_slosh,k += Q_eta * eta_{k+1}^2 + Q_eta_dot * eta_dot_{k+1}^2

可扩展：
  multi-step preview:
    sum_i w_i * ||x_slosh,k+i||_Q^2
```

边界：

```text
preview slosh penalty 可以增强当前 a_k 与 slosh cost 的耦合；
但它仍然不是 ax hard limiter；
不能替代 R_a/R_da 或 ax constraint。

推进顺序：
  先跑 20260519 C/D/E/F；
  如果 E/F 证明 ax/jerk 优先级有效，再考虑实现 preview slosh penalty。
```

诊断：

```text
1. 旋转中心整体偏移有改善（pose RMS -24%），说明 mu2 方向 anisotropy 起了一些作用，
   但峰值漂移没动 —— 不排除 bug B（右轮 +0.001 偏置）在主导峰值。
2. 5-20Hz 能量爆炸而总 RMS 只 +16%，说明新增能量集中在高频带。
   头号嫌疑：kd=100 太激进，把接触力对速度扰动的响应放大约 100×，
   造成接触阻尼 ringing。Husky 系常用 kd=1.0；100 是错误量级。
3. 次要嫌疑：mu2=0.3 过低 → 横向速度过零时 ODE 摩擦方向切换冲击；
   maxVel=1.0 + 高 kd → 间歇接触时强阻尼 kick。
4. 不可排除：fdir1 未生效（gazebo-classic #2068 已知 directional friction bug）。
```

## 仿真修复 B + C bisect：均有害，回退到 A v2 单独配置

实验结果（同一 before vs 三个 fix 组合）：

```text
配置       pose drift peak    drop %    pose RMS    imu 5-20Hz      imu wz RMS
baseline   0.2169             ——        0.1269     3.92e-05        0.0550
A v2 only  0.1158             +46.6     0.0673     8.40e-05        0.0617
abc        0.2087             +3.8      0.1322     9.43e-05        0.0507
ac         0.1994             +8.1      0.1341     8.60e-05        0.0428
ab         0.2478             -14.2     0.1651     7.29e-05        0.0659

→ A v2 alone 是局部最优。B 和 C 单独都有害；二者合并也无救。
```

诊断（事后假设）：

```text
B（去 +0.001 让 4 轮共面）有害：
  upstream 故意保留 +0.001 偏置，大概率是为了打破 ODE 4 点接触过约束，
  避免 4 个共面接触点 + 1 个平面带来的载荷剧烈重分配。
  统一为完全共面（B）反而恶化抖动和漂移。
  正确做法应是“对角线偏置”（front-left + rear-right 一组抬高，另对角不动），
  形成三脚架式接触；但本次不深入。

C（torque 1000 → 50）有害：
  原地自转必须 4 轮全部横向滑移，单轮需克服 μ·N 横向摩擦。
  在 ODE skid_steer 插件里，torque 是 fmax 形式约束速度约束力上限。
  fmax = 50 不足以让 ODE 在每一时间步把轮速精确推到目标，造成轮速跟踪误差累积，
  各轮跟踪差异 → 旋转中心被横滑拖着走 → pose 漂反而增大。
  C 的设计目标是减小 sim 阶跃响应，但原地自转工况下负作用更大。
  C 若想真正起效，须在 cmd_vel 层加 ramp 滤波而非压扁 fmax。
```

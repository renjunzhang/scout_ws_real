## 2. 当前工程结构

### 2.1 ROS Adapter

主入口仍是：

```text
src/scout_apps/control/scout_local_planner/scripts/anti_slosh_path_post_processor.py
```

它现在主要承担：

```text
1. 读取 ROS 参数；
2. 订阅 /scout/global_path；
3. 调用 OSCRS pipeline；
4. 发布 /scout/global_path_anti_slosh；
5. 发布 debug paths、candidate_report 和 safety_alarm。
```

它不是完整 plugin registry，也不是 T-MPC++ 多局部优化器复现。当前定位是 reference-layer post-processor。

### 2.2 G: Candidate Generation

主要文件：

```text
scripts/oscrs/generators/georef.py
scripts/oscrs/generators/tail_protect.py
scripts/candidate_generators.py
```

当前正式 generator 仍是 GeoRef smoothing，生成：

```text
original / mild / medium / mid / strong
```

这些不是拓扑不同候选，而是不同曲率、曲率变化和横向激励特性的 reference-shape / excitation-profile candidates。

工程考虑：

```text
1. original 永远保留，作为 fallback anchor；
2. candidate order 保持不变，避免同分 tie-break 漂移；
3. max_candidate_level 作为 G policy 保留诊断行，避免候选被静默隐藏；
4. tail_protect 默认关闭，避免未成熟尾段机制影响主线。
```

### 2.3 F: Feasibility Gates

主要文件：

```text
scripts/oscrs/feasibility.py
```

F 层判断候选是否“可执行”，不判断 slosh 安全。当前包括：

```text
F_geo:
  length_ratio
  max_drift
  endpoint_error
  direction consistency
  min_segment_length

F_collision:
  costmap point-cost check
  collision_threshold
  unknown_is_obstacle
  frame mismatch / no costmap

F_dynamic:
  predicted ay ratio

F_terminal:
  tail_dev / tail_yaw
```

工程考虑：

```text
1. collision check 仍是 point-cost threshold，不升级 footprint polygon；
2. ay_ratio_limit 是执行可行性 gate，不是 slosh hard gate；
3. tail_dev/tail_yaw 已经有诊断字段，但 tail_gate 默认关闭；
4. tail gate 只有在明确验证 tail_protect 不制造接缝问题后才适合进入正式统计。
```

### 2.4 R: Slosh Rollout

主要文件：

```text
scripts/oscrs/slosh_rollout.py
config/oscrs_container.yaml
```

R 层不是 MPC rollout，不调用 OSQP。它做的是：

```text
1. 根据 candidate path 曲率和执行预算生成 forward speed profile；
2. 计算 ax / ay / omega 等预测激励；
3. 用线性模态 slosh model rollout；
4. 输出 sH / sHm / sHp / sHr / sE / sEdot / terminal_E / eta_x_p95 / eta_y_p95 等指标。
```

工程考虑：

```text
1. prediction_v_max 必须和 MPC 真实速度上限一致；
2. 不能为了让 OSCRS hard gate 通过而单边降低 prediction_v_max；
3. /slosh/height 和 rollout prediction 是模型侧指标，不等于 RGB 视觉真值；
4. Ferrari-style height limit 应作为 hard gate，不应被 score 权重覆盖。
```

### 2.5 S: OSCRS Selection

主要文件：

```text
scripts/oscrs/selector.py
scripts/oscrs/diagnostics.py
```

S 层分三步：

```text
S_hard_gate:
  oh = sH  <= eta_lim
  or = sHr <= residual_ratio * eta_lim
  os = oh && or

S_score:
  对 hard-gate-safe candidates 排序
  score 权重只决定安全候选内的偏好

S_select:
  fixed candidate override
  geometry_best
  oscrs_best
  fallback original
```

关键原则：

```text
hard gate > score
```

也就是说，不能通过调 `w_energy / w_eta_dot / w_geom` 让不安全候选通过。score 是排序，不是安全保证。

## 3. Diagnostics 与 Fallback 设计

### 3.1 candidate_report

核心 topic：

```text
/anti_slosh_path/candidate_report
```

当前已经改为 latched publisher，解决 fixed replay 单帧路径容易漏录 report 的问题。

summary 字段包括：

```text
selected
geo
oscrs
active
fallback
fb
orig_safe
takeover
fallback_reason
dominant_stage
dominant_reason
div_path / div_ay / div_ax / div_ax_pulse
div_sH / div_eta_x / div_eta_y
dominant_excitation
diversity_aligned
candidate_collapse
```

row 字段包括：

```text
accepted
reason
score
stage
tail
tail_gate
tail_dev
tail_yaw
axp / axpk / aypk
sH / sHm / sHp / sHr / sE / sEdot
ex / ey
os / oh / or / ov / osc
```

diversity 字段只用于诊断，不参与 F gate、hard gate、score 或 selection。

解释：

```text
dominant_excitation:
  当前候选集中 rollout 主激励维度，取 eta_x / eta_y / balanced。

diversity_aligned:
  候选差异是否覆盖主激励维度。
  例如 P3 若 eta_x 主导但 div_ax / div_eta_x 很小，应判定 G 层没有撬动关键维度。

candidate_collapse:
  path separation 和关键 metric spread 同时过小，说明候选塌缩。
```

### 3.2 fb 语义

当前 fb 是判断 OSCRS 行为的主字段：

```text
fb=-1:
  OSCRS 未 active。

fb=0:
  OSCRS 选到了 slosh-safe candidate。
  当前视为 OSCRS 主通路成功。

fb=1:
  只有 original slosh-safe。

fb=2:
  几何可行，但所有非 original 候选 slosh hard gate 失败。

fb=3:
  无可用几何候选，通常是 F 层被 collision / ay / tail / level cap 拦住。
```

### 3.3 takeover 语义修正

历史上 `takeover` 曾表示：

```text
OSCRS 是否改写了 geometry selector 的选择。
```

这个语义会造成 `fb=0` 但 `takeover=0` 的混乱，例如 geometry selector 和 OSCRS 都选 `strong`。

当前工程口径已改为：

```text
takeover=1:
  OSCRS active 后发布了非 original 的 slosh-safe candidate。
```

对旧 bag，`validate_georef_oscrs_bag.py` 和 `check_oscrs_takeover.py` 已做兼容推断：

```text
active=1 && fb=0 && selected!=original
```

会被视为 takeover 行为通过。

如果后续论文需要表达“OSCRS 是否优于 geometry-only selector”，应新增独立字段，不再复用 `takeover`。

### 3.4 safety_alarm

topic：

```text
/anti_slosh_path/safety_alarm
```

用途：

```text
1. 所有候选 hard gate 失败时报警；
2. 帮助现场快速区分 fb=2 / fb=3；
3. 不作为效果指标，只作为行为正常性与安全诊断。
```

注意：带 safety_alarm 的包不建议进入正式有效性统计，除非该包专门用于 failure case 分析。

## 4. 当前已修复的工程问题

### 4.1 fixed replay 绕过 post-processor

问题：

```text
PATH_MODE=replay + GEOREF_OSCRS_ACTIVE
fixed_global_path_runner.py 直接发布到 /scout/global_path_anti_slosh
导致 post-processor 没收到 /scout/global_path
因此没有 candidate_report
```

修复：

```text
GLOBAL_PATH_TOPIC:
  MPC 输入话题，通常 /scout/global_path_anti_slosh

PATH_SOURCE_OUTPUT_TOPIC:
  fixed/template path source 输出话题
  启用 post-processor 时默认 /scout/global_path
```

修复后，fixed replay 应出现：

```text
/scout/global_path
/scout/global_path_anti_slosh
/anti_slosh_path/candidate_report
```

### 4.2 tail_protect 与 tail_gate 解耦

原问题：

```text
tail_protect=true 同时改几何并启用 terminal reject
导致 fallback 暴增，无法区分是几何拼接问题还是 gate 太严。
```

当前设计：

```text
tail_protect_enable:
  是否执行 raw-tail replacement。

tail_gate_enable:
  是否让 tail_dev / tail_yaw 参与 reject。
```

默认：

```text
tail_protect_enable=false
tail_gate_enable=false
```

建议：

```text
1. 正式主线先用 tail_protect=false；
2. tail_protect=true, tail_gate=false 只做诊断；
3. tail_gate=true 只做 smoke，不进入主效果统计；
4. 后续若继续 tail，应考虑 blend 替代 hard replacement。
```

### 4.3 max_candidate_level 诊断可见性

早期失败中，`max_candidate_level=mild` 会把 `mid/medium` 挡掉，表面上看像 OSCRS hard gate 失败。

当前设计：

```text
1. GeoRef G 仍生成完整候选 row；
2. 被 cap 的候选不静默消失；
3. report 中显示 reject_stage=GENERATION_SKIPPED；
4. reason 显示 level:medium>mild。
```

这样可以从 candidate_report 直接判断到底是：

```text
G 没放候选进来
F 拒了候选
R/S slosh gate 拒了候选
score 选输了
```

## 5. 当前参数边界

### 5.1 不应随便改的参数

```text
prediction_v_max:
  必须与 MPC 真实 vehicle_v_max / cmd_vel 上限一致。

eta_lim_mm:
  是液面安全硬门，不应为了提高 takeover 任意放宽。

residual_ratio:
  是 terminal residual 门，默认 0.2，除非明确看到 residual 主导失败，否则不优先动。
```

### 5.2 可以用于 smoke 的参数

```text
max_candidate_level:
  mild / medium / strong
  用于确认候选集合是否有足够可选项。

ay_ratio_limit:
  用于区分 dynamic gate 是否过严。

tail_protect_enable / tail_gate_enable:
  用于定位 terminal 几何问题，不作为主效果配置。
```

### 5.3 当前推荐主线配置

仿真通路验证：

```text
CONDITION=GEOREF_OSCRS_ACTIVE
tail_protect_enable=false
tail_gate_enable=false
max_candidate_level=medium 或根据 smoke 临时放开
```

tail 诊断支路：

```text
tail_protect_enable=true
tail_gate_enable=false
```

tail gate smoke：

```text
tail_protect_enable=true
tail_gate_enable=true
只用于通路验证，不进正式统计。
```

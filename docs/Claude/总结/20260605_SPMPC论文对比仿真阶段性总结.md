## 5. B_ours 未到终点诊断

原始 B_ours 配置：

```yaml
B_ours:
  w_control: 0.3
  w_smooth: 1.0
  w_slosh: 5.0
  w_progress: 0.2
```

原始 B_ours 结果：

```text
B_ours_ACADOS_OK:      1102 帧
ACADOS_SOLVE_FAILED_4:   29 帧
GOAL_REACHED:             0 帧
progress max:          0.162
最后 distance_to_goal: 约 7.70 m
cmd_v mean:            约 0.044 m/s
```

判断：

```text
不是 terminal 停车逻辑导致。
不是单纯记录时间不够。
是 w_slosh=5.0 与 smooth/control 同时叠加后过于保守，优化器中途倾向于近似停车。
```

## 6. B_ours 降低 w_slosh 的验证

单独跑了：

```text
B_ours, w_slosh = 2.0
```

输出目录：

```text
/data/a/spmpc_paper_compare/bours_wslosh_sweep_20260605
```

结果：

```text
GOAL_REACHED:          1334 帧
B_ours_ACADOS_OK:       643 帧
ACADOS_SOLVE_FAILED_4:    2 帧
progress max:          0.985
final distance:        约 0.139 m
```

说明：

```text
B_ours 将 w_slosh 从 5.0 降到 2.0 后，可以到终点。
```

这基本确认：

```text
B_ours 原始问题主要是 slosh 权重过高，而不是路径、仿真、terminal 或 acados 后端完全不可用。
```

## 7. 当前建议

暂时不要动 `B_slosh`，因为：

```text
B_slosh w_slosh=5.0 可以到终点。
```

建议只给 `B_ours` 单独调权重：

```yaml
B_ours:
  w_slosh: 2.0
```

后续可以做小 sweep：

```text
B_ours w_slosh = 2.0
B_ours w_slosh = 3.0
B_ours w_slosh = 4.0
```

选择标准：

```text
1. 能到终点
2. slosh peak 低
3. tracking error 不明显变差
4. ACADOS_SOLVE_FAILED 少
5. terminal 前 pre_terminal 指标更好
```

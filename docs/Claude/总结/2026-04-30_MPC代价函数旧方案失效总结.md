# 2026-04-30 MPC 代价函数旧方案失效总结

## 1. 结论

旧方案的核心假设是：

```text
只要把 slosh 状态 eta / eta_dot / modal_energy 放进 MPC 代价函数，
优化器就会主动选择更不激发液体的控制量，
从而稳定降低 /slosh/height。
```

当前实验和诊断已经说明，这个假设不成立。更准确的结论是：

```text
MPC 内部 slosh soft cost 可以改变控制行为，
但不能稳定、可泛化地把液体晃动压下去。
```

因此论文不能写成“通过 MPC 代价函数主动抑制液体晃动”。如果后续 `PROFILE_ENERGY` 成功，贡献应改写为：

```text
在 slosh-aware MPC tracking 框架中，通过能量感知速度剖面提前生成低激励参考，
MPC 负责在动力学约束下跟踪该参考。
```

也就是：MPC 是执行和约束平台，不是单靠 slosh cost 产生防晃效果的核心机制。

## 2. 旧方案为什么不合理

### 2.1 把晃动抑制放在 QP 内部太晚

MPC 每个周期只看到有限时域内的局部参考和当前 slosh 状态。液体是低阻尼二阶振子，当前控制输入对未来液面峰值的影响存在相位延迟和记忆效应。

在这种系统里，某一周期内降低 `eta` 代价，并不等价于降低后续液面峰值。优化器可能只是把激励从当前窗口挪到窗口外，或把位移能量转移到速度项。

因此，旧方案的问题不是“权重还没调对”，而是抑制逻辑放在了过短、过局部的 QP 视野内。

### 2.2 soft cost 会和 tracking cost 竞争

当前 MPC 的主任务仍是路径跟踪。代价函数中同时存在：

```text
J_tracking
J_speed
J_input_smooth
J_slosh
```

当路径几何要求快速转向或加减速时，`J_tracking` 会强烈要求跟上参考，而 `J_slosh` 只是软惩罚。只要跟踪误差代价更高，优化器就会接受一定液体激励。

提高 `Q_slosh` 并不能从结构上解决这个冲突，只会带来新的 Pareto 取舍：

```text
Q_slosh 小  → 晃动项没有足够影响
Q_slosh 大  → tracking / 任务时间 / 可达性恶化
```

这也是为什么多轮 `Q_slosh / Q_eta_dot / terminal_factor / modal_energy` 调参没有形成稳定主线。

### 2.3 惩罚 eta 不等于耗散模态能量

液体模态能量至少同时包含：

```text
E ~ omega_n^2 * eta^2 + eta_dot^2
```

只惩罚 `eta`，可能降低位移峰值，但不一定降低 `eta_dot`。后续 PMG 闭环结果已经给出同类失败模式：

```text
h_p95 下降
eta_dot 明显上升
```

这说明“压低液面高度峰值”可能只是把能量推到模态速度上，并没有真正抑制晃动。

旧方案中即使加入 `Q_slosh_eta_dot`，也没有解决根本问题。原因是 `eta` 和 `eta_dot` 的相位关系由低阻尼振子动力学决定，简单加权会改变相位取舍，但不保证在跨路径场景中稳定耗散总能量。

### 2.4 terminal cost 只能管终端，不解决路径中段激励

`terminal_factor_slosh_eta / eta_dot` 只能增强 horizon 末端状态代价。它对终点残余晃动有一定解释空间，但不能解决路径中段的主要激励。

在 P2/P3 这类路径中，液体峰值往往由弯道、换向或纵向加速度脉冲触发。terminal slosh cost 对这些中段事件没有直接控制力。

因此 terminal cost 不应被包装成全局 anti-slosh controller。

### 2.5 hard/box constraint 容易制造不可行

如果把液面高度约束写成硬约束：

```text
|eta_k| <= eta_bar
```

并且约束包含 `k=0`，那么只要当前估计状态已经超过 `eta_bar`，QP 会立即不可行。优化器没有机会“从当前超限状态逐步恢复”。

这类 hard constraint 更像安全边界或监控约束，不适合作为主要抑制机制。若要严谨使用，应引入 slack variable，但这又会回到 soft penalty 的权衡问题。

## 3. 为什么 MPC 代价函数无法主动把液体晃动压下去

### 3.1 控制变量不是液体输入的直接独立变量

MPC 控制的是车辆：

```text
u = [a, omega]
```

液体受到的是车辆激励：

```text
ax
ay = v * omega
alpha / domega
```

这些激励是车辆速度、角速度、路径几何和执行动态共同作用的结果。优化器并不是直接控制 `eta`，而是通过车辆动作间接影响液体。

当路径跟踪要求和液体抑制目标冲突时，slosh cost 只能给出软偏好，不能保证激励真的降低。

### 3.2 计划输入和实际执行存在差异

MPC 预测域使用的是计划控制和模型传播，真实底盘执行存在延迟、饱和、滤波和跟踪误差。

历史诊断中已经看到类似现象：

```text
cmd_v * cmd_omega -> /slosh/ay_est 的 scale 约 0.44
odom_v * odom_omega -> /slosh/ay_est 的 scale 约 0.88
```

这说明命令层计划和真实激励之间差距很大。MPC 内部代价函数即使在预测里“认为”降低了晃动，真实执行层也可能用另一种方式通过路径，导致实际激励没有按预期下降。

### 3.3 有限 horizon 不覆盖液体记忆

液体首模周期约 `0.2 s` 量级，但晃动衰减时间由阻尼决定，通常比 MPC 短时域更长。

MPC 的短 horizon 适合车辆局部跟踪，但不天然适合评估“当前激励在未来多个振荡周期后的液面峰值”。这使得 QP 内部的 slosh cost 容易变成局部相位调节，而不是全局能量抑制。

### 3.4 P3 失败说明主激励通道不是简单 lateral ay

P3 诊断结果：

```text
eta_x energy ratio ≈ 0.975
```

说明 P3 的模型估计晃动主要来自 longitudinal `eta_x`，不是 lateral `eta_y`。这直接否定了只靠横向 `ay = v * omega` 或曲率限速来解释所有路径的思路。

进一步诊断：

```text
corr_ax_vref ≈ -0.11
corr_ax_track ≈ -0.62
status_fail_ratio = 0
```

这说明 P3 的纵向激励不是一个简单的参考速度剖面相关事件，也不是 solver/recovery 失败。它更像 MPC 在复杂路径跟踪过程中主动产生的纵向加速度脉冲。

这种情况下，单纯把 `eta_x` 放进 cost 并不能保证优化器会提前避免触发事件；它可能仍然为了 tracking 选择激励较大的通过方式。

## 4. 历史实验如何支持这个判断

### 4.1 MPC 内部 cost 路线没有单独通过

已尝试或分析过：

```text
Q_slosh
Q_slosh_eta_dot
terminal_factor_slosh_eta
terminal_factor_slosh_eta_dot
Q_ay_pred
Q_modal_energy / ENERGY_WIN
R_da / R_domega 平滑加权
```

结论：

```text
没有任何 MPC 内部 slosh cost 配置单独形成 P2/P3 可泛化通过证据。
```

常见失败模式：

```text
h_rms / h_p95 小幅下降但 eta_dot 上升
ay_p95 下降但 energy 不降
任务时间或 tracking 口径不可比
只在 P2 有局部正结果，P3 不泛化
```

### 4.2 输出层方法证明“事后裁剪”也不稳

`OUTPUT_GUARD` 在 P2 有效，但 P3 失败。PMG 离线看起来更聪明，但闭环 P2 暴露 `eta_dot` 大幅上升。

这说明问题不只是“触发阈值不对”或“没有相位意识”。更根本的问题是：

```text
求解后修改 cmd_vel 会破坏 MPC 原本计划；
下一周期 MPC 会为了追踪路径重新补偿；
补偿动作可能产生新的 ax / omega 脉冲。
```

输出层方法的失败反过来说明，抑制逻辑应该前移到参考生成层，而不是放在 QP 后面。

### 4.3 参考速度剖面层出现过最强 P2 正结果

P2 `PROFILE_SAFE` 中等强度：

```text
tracking_time_s        +12.7%
h_rms                  -22.5%
h_p95                  -20.8%
modal_energy_norm      -21.7%
eta_dot                -11.9%
odom_ay_abs_p95        -24.2%
```

这说明“提前降低可执行激励”方向有价值。它不是 MPC cost 成功，而是参考生成层让 MPC 从一开始就跟踪低激励速度。

因此后续 `PROFILE_ENERGY` 的合理性来自这里，而不是来自旧的 `Q_slosh` 调权路线。

## 5. 对论文写法的影响

不能写：

```text
The MPC cost actively suppresses liquid sloshing.
Increasing slosh-related weights enables the controller to reduce slosh.
The risk-adaptive MPC alone achieves robust slosh suppression.
```

可以写：

```text
We build a slosh-augmented tracking MPC framework and show that direct slosh costs inside the QP are insufficient for robust cross-path slosh suppression.
```

如果 `PROFILE_ENERGY` 成功，可以写：

```text
The proposed energy-aware speed profiling layer reduces future excitation before MPC optimization,
allowing the tracking MPC to follow a low-excitation reference while respecting vehicle dynamics.
```

更完整的论文定位应改为：

```text
Energy-Aware Speed Profiling for Slosh-Aware MPC Tracking
```

而不是：

```text
Risk-Adaptive Slosh Cost MPC
```

## 6. 旧方案应如何保留价值

旧方案不应作为最终控制主线，但仍有价值：

- 提供了 8 维 slosh-augmented tracking MPC 基线；
- 提供了 `/slosh/state / height / eta_dot / modal_energy / excitation` 诊断体系；
- 证明了单纯调 `Q_slosh` 不足；
- 证明了 output cap / PMG 这类事后裁剪存在闭环补偿副作用；
- 帮助定位 P3 的主导问题是 longitudinal `eta_x` 通道。

这些可以支撑论文中的 ablation 和 failure analysis，但不能被包装成成功 controller。

## 7. 后续方向

后续如果继续追求成功控制，应优先做：

```text
PROFILE_ENERGY / EASP:
  在 PathHandler::updateSpeedProfile() 中提前生成低激励 v_ref(s)
  同时约束 ax / ay / omega / alpha / eta_dot 风险
  让 MPC 跟踪已经低激励的参考
```

同时必须保留停止条件：

```text
P2 eta_dot 上升 → 停止
P2 tracking_time > +15% → 停止
P2 h_p95 不降 → 停止
P3 不能稳定 reached → 停止
P3 h_p95 / energy / eta_dot 任一不降 → 停止
```

如果 `PROFILE_ENERGY` 仍失败，应转向：

```text
真实液面视觉测量
omega_n / zeta 自由衰减辨识
P3 路径几何可达性审查
```

```text
slosh rollout correction 可以降低模型估计晃动指标；
```

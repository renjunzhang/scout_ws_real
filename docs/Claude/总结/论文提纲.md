# RA-L 论文提纲

> 2026-04-30 重写版。主线从“风险自适应 MPC”调整为“Slosh-Rollout-Corrected Speed Profiling for Slosh-Aware MPC Tracking”。

---

## 论文定位一句话

> **Slosh-Rollout-Corrected Speed Profiling for Slosh-Aware MPC Tracking of Liquid-Carrying Mobile Robots**

中文定位：

```text
面向给定几何路径和 /cmd_vel 接口的移动机器人液体搬运任务，
本文在 MPC tracking 前端生成经线性模态晃动预演校正的路径速度参考 v_ref(s)，
使 MPC 跟踪低激励参考，而不是依赖 MPC 内部 slosh soft cost 或输出层硬裁剪。
```

关键口径：

- 不是首次提出“速度剖面防晃”；
- 不是复现 flatness + HSMC；
- 不是证明 MPC 代价函数能主动压晃动；
- 创新点在“给定路径 + `/cmd_vel` 局部规划 + MPC tracking”场景下的 signed slosh rollout corrected path-speed profiling，以及系统消融验证。

---

## 主要贡献

### Contribution 1: Slosh-rollout-corrected path-speed profiling

在给定全局/局部几何路径上生成 `v_ref(s)`：

```text
Layer 1: geometry-aware speed cap
  kappa / dkappa / ay / omega / alpha 风险生成初始 v(s)

Layer 2: signed linear-modal slosh rollout correction
  用 ax / ay 有符号序列预测 eta_x / eta_y / eta_dot / modal_energy
  对高风险窗口做平滑速度修正
  每轮修正后 accept / rollback
```

### Contribution 2: Reference-first anti-slosh MPC tracking architecture

防晃逻辑放在 MPC 优化之前：

```text
anti-slosh speed profile generation → constrained MPC tracking
```

MPC 的角色是跟踪低激励参考并满足车辆约束；不是靠 QP 内部 `Q_slosh` 把液体晃动主动压下去。

### Contribution 3: Execution-fidelity-aware validation

不仅报告 `/slosh/height` 指标，还检查低激励 profile 是否被 MPC/底盘真正执行：

```text
v_ref_vs_odom_rmse
ax_ref_vs_odom_ax_corr
ay_ref_vs_odom_ay_corr
profile_violation_ratio
odom_v_exceeds_profile_ratio
```

P3 额外报告 longitudinal 指标，避免只压 `ay=v²κ` 而掩盖 `eta_x` 失败：

```text
eta_x_energy_ratio
eta_x_rms
eta_dot_x_rms
odom_ax_abs_p95
cmd_a_abs_p95
v_ref_jerk_p95
```

## Related Work 写法

### A. Input shaping and command filtering

说明 ZV/ZVD input shaping、命令滤波和传统低激励控制能减少部分晃动，但通常不直接结合给定路径上的 signed slosh rollout 和 MPC tracking 执行一致性验证。

### B. WMR path design and acceleration pattern

必须引用 wheeled mobile robot 搬运圆柱容器的 path design / acceleration pattern / input shaping 相关工作。强调已有工作会设计曲率半径或加速度模式，但本文目标是在已有路径上生成 `v_ref(s)`，而不是重新设计完整几何路径。

### C. Slosh-free trajectory optimization

引用机械臂或移动平台 slosh-free trajectory generation / QP trajectory optimization。区别是这些方法通常优化完整末端轨迹或全局轨迹，本文只在局部规划层修正路径速度剖面，并由 MPC 执行。

### D. Flatness/rest-to-rest trajectory generation

引用 flatness-based rest-to-rest anti-slosh trajectory 和 feedforward maneuver。本文受“reference first”思想启发，但不采用四轮麦克纳姆力矩级 HSMC，也不直接替换全局轨迹。

建议表达：

```text
Existing slosh suppression methods include input shaping, model-based motion profile optimization,
slosh-free trajectory optimization, and flatness/rest-to-rest trajectory generation.
These works demonstrate that suppressing slosh at the reference generation level is often more effective
than post-hoc command modification.
```

接本文差异：

```text
Unlike prior works that design full rest-to-rest trajectories, robot-arm end-effector trajectories,
or torque-level controllers, this work targets a differential-drive local planning setting.
Given a geometric path, we generate a slosh-rollout-corrected path-speed reference before MPC optimization,
and use MPC as a constrained tracking layer.
```

## 方法节提纲

### II. Problem Formulation

内容：

- 差速/类差速移动底盘，控制接口为 `/cmd_vel=[v,omega]`；
- 给定几何路径 `p(s)`，目标是生成路径速度参考 `v_ref(s)`；
- 液体模型采用线性单模态 MSD：

```text
eta_x_ddot + 2 zeta omega_n eta_x_dot + omega_n^2 eta_x = -ax
eta_y_ddot + 2 zeta omega_n eta_y_dot + omega_n^2 eta_y = -ay
```

- 路径诱导激励：

```text
ax_i    = (v_i^2 - v_{i-1}^2) / (2 ds)
ay_i    = v_i^2 * kappa_i
omega_i = v_i * kappa_i
alpha_i = ax_i * kappa_i + v_i^2 * dkappa_i
```

写作要点：

- 明确是 `linear modal slosh rollout`，不是 nonlinear fluid model；
- `/slosh/height` 若无视觉验证，只能称为 model-estimated slosh height；
- 说明目标不是最短时间，而是在任务时间约束下减少晃动指标。

### III. Slosh-Augmented MPC Tracking Baseline

内容：

- 8 维 slosh-augmented tracking MPC；
- 状态包含 `e_l, e_c, e_theta, v, eta_x, eta_x_dot, eta_y, eta_y_dot`；
- MPC 接收局部参考点和 `v_ref`；
- 本文把 MPC 作为 constrained tracking layer。

写作要点：

- 明确旧路线失败：`Q_slosh / Q_eta_dot / terminal / modal_energy` 没有稳定泛化；
- 不把 MPC 内部 slosh cost 写成主贡献；
- 说明为什么需要把防晃前移到参考生成层。

### IV. Geometry-Aware Speed Profile

这是 ablation baseline，不是最终方法。

内容：

- 对路径曲率做抗噪：

```text
kappa_smooth
dkappa = central difference on smoothed kappa
ignore isolated one-point spikes
minimum risk-window length
```

- 计算几何风险：

```text
kappa_max
dkappa_max
ay_pred
omega_pred
alpha_pred = ax*kappa + v^2*dkappa
```

- 生成初始速度上限：

```text
v <= sqrt(lat_accel / |kappa|)
v <= omega_max / |kappa|
v <= sqrt(alpha_max / |dkappa|)
```

- forward/backward pass 限制 `ax/decel`。

写作要点：

- 这个方法叫 `Geometry-only profile`；
- 用它证明“只靠几何风险限速是否足够”。

### V. Slosh-Rollout-Corrected Speed Profiling

这是核心方法。

#### V-A. Signed modal rollout

使用逐点有符号输入：

```text
ax_i
ay_i = v_i^2 * kappa_i
omega_i = v_i * kappa_i
alpha_i = ax_i*kappa_i + v_i^2*dkappa_i
```

不能用窗口最大绝对值代替 signed sequence。

rollout 数值方法：

```text
优先线性二阶系统精确离散化
备选 RK4
dt_i <= dt_max
```

#### V-B. Candidate-profile normalization

离线论文评估：

```text
E_ref = same-path NOM baseline p95
```

在线运行：

```text
E_ref = 当前未修正 candidate profile 的 rollout p95
```

指标：

```text
E_norm = E_rollout / E_ref
eta_dot_norm = |eta_dot| / eta_dot_candidate_p95
```

#### V-C. Smooth correction and accept/rollback

对高风险窗口使用 cosine taper 平滑降低 `v_cap(s)`，而不是整段硬乘 `window_scale`。

每轮修正后重新 rollout，若发生以下情况则回滚：

```text
h_p95_pred 没降
eta_dot_pred 上升
terminal residual 上升
tracking_time_pred 超限
```

#### V-D. Jerk and temporal smoothing

时间域 jerk：

```text
jerk_i ≈ v_i * (ax_i - ax_{i-1}) / ds
```

在线重规划防抖：

```text
risk hysteresis
v_ref_new <- beta * v_ref_new + (1-beta) * v_ref_prev
```

#### V-E. Terminal residual

末端窗口：

```text
s in [s_end - terminal_window, s_end]
```

报告：

```text
terminal_energy_pred
terminal_eta_norm
terminal_eta_dot_norm
```

### VI. Execution Fidelity Diagnostics

用于证明生成的低激励 profile 真被执行。

指标：

```text
v_ref_vs_odom_rmse
ax_ref_vs_odom_ax_corr
ay_ref_vs_odom_ay_corr
profile_violation_ratio
odom_v_exceeds_profile_ratio
```

作用：

- 区分 profile 设计失败；
- MPC/底盘跟踪失败；
- slosh 模型与 `/slosh/height` 不一致。

## 必须避免的表述

不能写：

```text
We propose the first speed-profile-based anti-slosh method.
The MPC cost suppresses liquid sloshing.
The proposed method reduces real liquid height.
We reproduce the flatness-based rest-to-rest HSMC method.
```

可以写：

```text
We propose a slosh-rollout-corrected speed profiling layer for slosh-aware MPC tracking.
The method is inspired by reference-first anti-slosh trajectory generation,
but is adapted to a mobile robot local planning setting with a fixed geometric path and /cmd_vel interface.
```

## 2. 代码层 G + S 两层（L2 重构后现状）

### 2.1 文件分布

```text
scripts/
  candidate_generators.py          ← G (单函数 generate_georef_candidates, 36 行)
  anti_slosh_path_post_processor.py ← S + ROS adapter (1000+ 行)
  generate_anti_slosh_path_candidates.py ← smooth_path / 几何工具
  test_candidate_generators_equivalence.py ← G 函数级 numeric exact 等价性测试

config/
  oscrs_container.yaml             ← 容器物理 + slosh model + score 权重

launch/
  anti_slosh_path_post_processor.launch ← 全部 ROS arg 入口
```

### 2.2 G 接口（已稳定）

```python
generate_georef_candidates(
    base,                # list[(x,y)] 已 resample
    candidate_specs,     # list[(name, iters, gain, drift_limit)]
    min_segment_length,  # float
    sanitize_fn,         # callable, 通过参数注入避免反向 import
) -> list[(name, points)]
```

OSCRS 同分时取最先出现者 — **依赖 candidate_specs 顺序**。这是 L2 残留的隐式耦合之一。

### 2.3 S 内部职责（仍混在 post_processor）

```text
1. 候选准入 cap   max_candidate_level 把 specs 按 candidate_levels 顺序裁掉
2. 几何 gate      length / drift / endpoint / direction / min_seg / kappa
3. 安全 gate      collision check (costmap), ay_ratio_limit
4. OSCRS rollout  对每条候选做 slosh model rollout, 计算 sH/sHm/sHp/sHr/sE/sEdot
5. OSCRS hard gate  oh = (sH < eta_lim_mm/1000)
                    or = (sHr < residual_ratio × eta_lim_mm/1000)
                    os = oh ∧ or
6. score          gscore (geometry-only) + sscore (含 OSCRS 项)
7. selector       active=1 时优先 OSCRS feasible 集合, fallback 链按 fb 码
8. publish        path_to_msg 注入 raw 首尾 orientation (yaw 修复)
```

### 2.4 一次 path_callback 数据流

```text
/scout/global_path  (MBF 单帧)
   ↓
resample(ds=0.10)
   ↓
G: generate_georef_candidates(base, specs, min_seg, sanitize_points)
   ↓ list[(name, points)] 共 5 条
filter by max_candidate_level cap
   ↓ list[(name, points)] 1-5 条
对每条:
    evaluate_candidate
    → row {accepted, gscore, sscore, sH, sHm, sHp, sHr, sE, sEdot,
            os, oh, or, ov (violation amount), osc (oscrs score), col}
   ↓
publish_candidate_report
   ├── geometry_best = arg-min gscore 在 accepted 中
   ├── oscrs_best    = arg-min sscore 在 accepted ∧ os=1 中 (active 时)
   ├── selected      = oscrs_best (若 takeover) 否则 geometry_best 否则 original
   ├── fb code       (-1/0/1/2/3, 详见 §3)
   ├── takeover      = (active ∧ selected==oscrs ∧ selected≠geometry_best)
   └── safety_alarm  (仅在 fallback 时发, 含 hard_gate_failed/min_violation)
   ↓
/scout/global_path_anti_slosh  (selected path)
   ↓
MPC slosh_experiment.launch (global_path_topic 订阅)
   ↓
/cmd_vel
```

## 3. fb / takeover / fallback 语义（必须背熟）

```text
fb = -1   OSCRS 未 active (oscrs_active_enable=false)
         FIXED 与早期 TUNED 都是这个;
         不计入 OSCRS 评估。

fb =  0   OSCRS 接管成功
         至少一条非 original 候选通过 OSCRS hard gate (os=1);
         oscrs_best 被选中。
         A 档理想样本 (selected ∈ {mid, medium});
         B 档可接受 (selected = mild)。

fb =  1   只有 original slosh-safe
         original 通过 hard gate 但所有非 original 都失败;
         publish original;
         视为 takeover=0 (OSCRS 没"接管"任何东西)。

fb =  2   几何可行但 slosh hard gate 全失败
         至少一条非 original 通过几何 gate (accepted=1),
         但所有候选 os=0;
         publish original (geometry_best fallback);
         touches safety_alarm。
         phase3 长路径 fb=2 的根因: max_candidate_level=mild 把
         mid/medium 挡掉, 剩 mild 自身 sH=27>25 过不了 hard gate。

fb =  3   无可用几何候选
         所有非 original 都被几何/安全 gate 拒;
         publish original;
         touches safety_alarm。
```

```text
takeover = 1 当且仅当:
    active=1
  ∧ oscrs_row 存在且 oscrs_feasible=1
  ∧ selected.name == oscrs_row.name
  ∧ selected.name != geometry_best.name

takeover = 0 包含 active=1 但 selected==geometry_best 的情形 —
即 OSCRS 与 geometry-only selector 选了同一条路径,
不能宣称 OSCRS 有额外物理贡献 (saturated)。
```

`fallback` 字段 = `oscrs_active_enable ∧ fb != 0`，与 fb 一对一。

## 4. 参数住哪里（按调参症状定位）

### 4.1 launch arg（`anti_slosh_path_post_processor.launch`）

| arg | default | 作用 | 调参典型场景 |
|---|---|---|---|
| `max_candidate_level` | medium | 候选准入封顶 | OSCRS fb=2 但 mid/medium sH 应能过门 → 检查 cap 是否仍是 mild |
| `fixed_candidate_name` | "" | FIXED 模式强制选定候选 | FIXED 主线设 mild |
| `min_segment_length` | 0.02 | sanitize 段长阈 | reason=min_seg 时 |
| `enable_collision_check` | false | 是否 costmap 碰撞检查 | 实物正式 = true |
| `costmap_topic` | `/scout/mbf_.../global_costmap/costmap` | 碰撞检查 topic | reason=no_costmap/frame_mismatch |
| `collision_threshold` | 50 | 碰撞代价上限 0-100 | reason=collision → 90 → 100 |
| `ay_ratio_limit` | 1.0 | candidate ay / baseline ay 上限 | reason=ay → 1.0 → 3.0 → 3.5 |
| `prediction_v_max` | 2.0 | OSCRS rollout 速度上限 | **永远 = MPC cmd_vel.linear.x_max** 不单边改 |
| `prediction_ay_max_budget` | 2.0 | OSCRS rollout 横向 ay 预算 | 与 prediction_v_max 同步 |
| `mild_iters / mild_gain / mild_max_drift` | 18 / 0.35 / 0.08 | mild 平滑形状 | TUNED 选不到 mild → 提强度;现场过冲 → §9.4 调小 |
| `medium_iters / medium_gain / medium_max_drift` | 40 / 0.45 / 0.12 | medium 平滑形状 | A 档 selected=medium 但过冲 → 调小 |
| `mid_iters / mid_gain / mid_max_drift` | 24 / 0.30 / 0.07 | mid 平滑形状 |  |
| `strong_iters / strong_gain / strong_max_drift` | 56 / 0.55 / 0.18 | strong 平滑形状 | 过冲风险高, 实物 SAFE 路线不开放到 strong |
| `oscrs_shadow_enable` | false | 是否运行 shadow rollout | OSCRS active 时 = true |
| `oscrs_active_enable` | false | OSCRS 是否实际接管 selector | OSCRS_ACTIVE 主线 = true |
| `oscrs_eta_lim_mm` | 25.0 | η peak 硬门 (mm) | **物理基础, 不可让步给"让 takeover"** |
| `oscrs_residual_ratio` | 0.2 | 残振门 = ratio × eta_lim | reason=residual / sHr 主导 → 0.5 |
| `oscrs_config` | (路径) | yaml 路径 | 永远显式传, 不依赖 launch default |

### 4.2 yaml（`config/oscrs_container.yaml`）

```text
slosh_score:
  height_coeff_mode:    observer_linear  # 晃动高度系数估计模式
  eta_lim_mm:           25.0             # 与 launch arg 同步
  residual_ratio:       0.2              # 与 launch arg 同步
  score:
    use_legacy_score:   false
    w_energy_rms:       0.3   # OSCRS score 权重: 模态能量 RMS
    w_eta_dot_rms:      0.3   # 模态速度 RMS (残振速率)
    w_terminal_E:       0.2   # motion-end 能量
    ...
  legacy:               # 仅当 use_legacy_score=true 才生效, 当前未用
    w_energy / w_eta_dot / w_terminal / w_kappa / w_dkappa / w_ay
```

注意：`eta_lim_mm` 与 `residual_ratio` 在 launch arg 与 yaml 都有；
launch arg 优先 (rospy.get_param 读 ~oscrs/...)，yaml 是 fallback 默认。
**永远在 launch 命令显式传**，不依赖 yaml 默认。

### 4.3 代码内部（不暴露 ROS, 改要碰文件）

```text
candidate_specs (post_processor.py:203-209)
   5 元组 (name, iters, gain, drift_limit), 顺序锁定 OSCRS 同分 tie-break

candidate_levels (post_processor.py:210)
   {name: i}, max_candidate_level cap 用 i 比较

sanitize_points / cumulative_s / curvature_series / ...
   几何工具, 改这些会影响 evaluate_candidate 全部指标
```

### 4.4 必须保持一致的跨参

```text
prediction_v_max  =  MPC slosh_experiment.launch 内 cmd_vel.linear.x_max
                    任一边单改都会让 OSCRS rollout 与执行口径脱节 (Layer 2a 失效)

oscrs_eta_lim_mm (launch)  =  slosh_score.eta_lim_mm (yaml)
oscrs_residual_ratio       =  slosh_score.residual_ratio
                    都在 launch arg 显式传, 避免读 yaml 旧值

candidate_specs 顺序     OSCRS 同分时取最先出现者
                         改顺序会改 selector 行为
```

## 5. OSCRS 论证链 3 层（结合 phase3/4 实测）

| 层 | 验证内容 | 当前状态 |
|---|---|---|
| **Layer 1** | candidate set 里存在 slosh-better-than-RAW 的路径 | 部分 — phase3 长路径 medium sH=6mm << original 32mm 物理上存在；phase4 短路径模型侧 -17.5%；视觉真值 A_rank=0.5 不稳定 |
| **Layer 2a** | rollout 输入口径 = 实车执行 (prediction_v_max) | 通 — 钉死 2.0 = MPC v_max |
| **Layer 2b** | rollout 输出 sH = 实物真液面 η peak | **未通** — phase4 run01 OSCRS e_p95=−0.513mm (模型低估视觉 0.5mm)，A_rank=0.5 |

只有 50% 与视觉一致 — 不足以单独支撑 OSCRS hard gate 实验保真度声明。

       scripts/anti_slosh_path_post_processor.py:100-104 (path_to_msg 用注入值覆盖首尾)

   global_path.poses[-1].orientation == global_path_anti_slosh.poses[-1].orientation

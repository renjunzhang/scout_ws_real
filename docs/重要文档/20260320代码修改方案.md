## 1. 当前结论

前四刀落地以后，当前 `Q=0` 仍然会出现：

- 终点附近高速掠过 goal
- 冲过终点后继续前进
- goal 落到车后后，系统仍停留在 forward-only tracking 语义里

因此，当前主问题已经不再是：

- 终点 yaw 判定退化
- “进容差就直接硬切零速”
- `v_des_cmd=0` 却被 speed profile 抬回正值

这些都已经修过了。

当前剩下的主矛盾更准确地说是：

- **terminal 阶段缺少 recovery 结构**
- **forward-only tracking MPC 冲过终点后没有明确补救行为**
- **执行链仍有剩余滞后，会放大冲过头**

换句话说：

- **不是全局路径更新频率问题**
- **也不是 slosh / Q_slosh 问题**
- **现在要补的是 near-goal / terminal behavior，而不是继续大扫 MPC 权重**

## 2. 已有证据支持的根因

### 2.1 已修复的问题不再是当前主因

下面这些问题都已经通过代码修改被显式修过：

- `isGoalReached()` 终点 yaw 判定退化
- `goal_stop_pending_` 进容差后直接 `publishCmdVel(0,0)`
- `goal_stop_pending_` 下 `v_des_cmd=0` 不能真正压住 `v_ref`
- `goal_stop_pending_` 一帧滑出容差就立刻释放

因此，当前 bag 里依然“冲过终点继续前进”，不能再归因到上面这几条。

### 2.2 当前主因：forward-only terminal 没有 recovery

当前代码在终点附近仍然是：

- 正常 tracking MPC
- `goal_stop_pending_` 下把 `v_des_cmd` 压到 `0`
- 一旦速度足够低才切 `REACHED`

但它仍然**没有**处理下面这种情况：

- 已经高速掠过终点
- goal 已经落到 `base_link` 后方
- 当前又不允许倒车（`v_min = 0.0`）

此时系统没有：

- terminal align to goal point
- terminal approach back to goal
- terminal final yaw align

也就是说，当前不是“没路径了”，而是：

- **有路径**
- **但局部控制语义仍然是 forward-only tracking**
- **一旦冲过头，系统没有明确的 near-goal recovery 行为**

### 2.3 `goal_stop_pending_` 的释放逻辑仍然偏粗

当前 `goal_stop_pending_` 虽然已经有最小锁存，但释放仍只依赖：

- `goal_dist > max(goal_capture_distance, goal_tolerance + 0.15)`

这意味着：

- 如果车子已经冲过终点并离开一段距离
- pending stop 仍可能被释放
- 之后 `v_des_cmd` 会恢复为巡航值

它现在不再是最先要修的 bug，但仍属于：

- **会放大终点失败的 terminal 状态机缺陷**

### 2.4 执行链仍有剩余滞后

当前如果使用 `slosh_experiment.launch`，输出 EMA 在 launch 层已经关掉了。

因此现在更值得怀疑的滞后不是 YAML 默认滤波，而是：

- `MPCSolver` 里 `omega_cmd` 仍然取首两步均值
- 底盘本体执行响应本身也有迟滞

这会放大：

- 近终点修正偏慢
- 冲过后再反向修的相位延迟

### 2.5 当前不是全局路径更新策略问题

从最近 bag 看：

- `/scout/global_path` 仍存在
- `/local_path` 仍持续发布

因此“冲过终点后继续往前”当前**不是**因为：

- 全局路径没有更新
- 需要把全局路径改成固定频率重规划

当前更准确的判断是：

- **冲过终点后，goal 到车后，而局部规划没有 terminal recovery**

## 3. 第一优先级修改

### 3.1 下一刀：补最小 terminal recovery

当前最短路径不是继续扫参数，而是：

- 在 `TRACKING` 分支最前面插一个 near-goal terminal recovery 分支
- 当 goal 已进入近终点区域但还未真正 `REACHED` 时，
  不再完全依赖 normal tracking MPC 自动收尾

第一版 terminal recovery 只做 3 个 mode：

1. `ALIGN_TO_POINT`
   - goal 在 `base_link` 后方，或 bearing 太大
   - 先原地对准 goal 点
2. `APPROACH_POINT`
   - goal 在前方，但位置还差几厘米
   - 小速度继续靠近
3. `ALIGN_FINAL_YAW`
   - 位置已到，但 final yaw 还没对齐
   - 原地补 final yaw

这一刀的目的不是“让 MPC 更复杂”，而是：

- **补上 tracking MPC 天生不擅长的 terminal behavior**

### 3.2 用统一的 `GoalInfo` 承载终点几何

为了让 terminal recovery 不再在多个函数里重复拼几何量，
建议增加一组统一接口：

- `GoalInfo`
- `PathHandler::getGoalInfo()`

第一版需要的信息只有：

- `dx / dy / dist / bearing`
- `goal_yaw_err`
- `position_reached`
- `pose_reached`

注意：

- 第一版只做统一几何出口
- **先不要顺手引入更多 terminal 状态机**
- **先不要同时做 path tail 清理**

## 4. 第二优先级修改

### 4.1 `omega_cmd` 直接取第一步的最小 A/B

这一阶段不要再围绕输出 EMA 纠缠。

如果使用的是：

- `slosh_experiment.launch`
- 或已同步的 `test_mpc.launch`

那么 launch 层输出 EMA 已经关掉了。

因此现在更值得做的执行链 A/B 是：

- `omega_cmd = u_first(OMEGA)`

而不是：

- 首两步均值

目的：

- 验证 terminal 阶段的剩余相位滞后是否明显来自这半步均值

涉及文件：

- `src/scout_apps/control/scout_local_planner/src/mpc_solver.cpp`

### 4.2 终点参数只做最小配套，不再当主线

当前这些参数可以继续保持保守值：

- `goal_capture_min_speed = 0.0`
- `goal_capture_distance = 0.25`
- `lookahead_distance = 0.70`
- `max_tan_decel = 0.7`

但它们现在不再是主线。

原因：

- 只靠继续拧这些参数，解决不了“goal 到车后时没有 recovery”这个结构问题

## 5. 当前不建议做的修改

下面这些暂时不要和 terminal recovery 混在一起：

- 大范围重调 `Q_contour / Q_lag / R_domega / Q_omega_ff`
- 直接引入 terminal reverse
- 改全局路径为固定频率重规划
- 再次大改 `lookahead_distance`
- 同时改 IMU 开关、anti-slosh 参数、终点逻辑

原因：

- 这些修改会把根因混在一起
- 当前还没必要，而且会掩盖 terminal recovery 是否真正有效

按第一性原理，当前最短路径是：

1. 补 terminal recovery
2. 再做 `omega_cmd` 第一帧 A/B
3. 最后才继续扫终点参数或更大范围权重

## 6. 修改后验证顺序

每次只改一项或一类，并录新 bag。

建议顺序：

1. 加最小 terminal recovery
   - 录一条 `Q=0` bag
2. 看冲过终点后是否先对准 goal 点、再小速度靠回
3. 再做 `omega_cmd` 第一帧 A/B
4. 如果 terminal recovery 已有效，但仍有轻微末端摇摆，再微调终点参数

验证时重点看：

- `/mpc_status`
- `/cmd_vel`
- `/odom`
- `/scout/goal`
- `/scout/mbf_costmap_nav/exe_path/feedback`
- `/scout/mbf_costmap_nav/move_base/feedback`
- `/local_path`
- `/scout/global_path_smooth`

通过标准：

- 冲过终点后不再继续前向发散
- goal 到车后方时，能先转向再补靠近
- 位置到后能补 final yaw
- `Q=0` 下 base planner 自身能稳定进入 `REACHED`

## 7. 一句话执行建议

当前最值得立即动代码的不是继续扫参数，而是：

1. 补最小 terminal recovery
2. 再做 `omega_cmd` 第一帧 A/B

在这之前，不要再把全局路径更新频率、slosh 参数和终点问题混在一起。

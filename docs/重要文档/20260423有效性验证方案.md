# 有效性验证方案：Risk Scheduler + Slosh 抑制项

> 两个核心问题：① `Q_slosh` 相比无抑制是否有效；② `risk_scheduler` 相比固定 Q 是否改善持续风险。  
> 现场只录 bag，回来统一离线分析。0422 已有预实验（n=1/条件），本轮目标 **≥5次/条件**，支持统计检验。

---

## 0. 实验前必须注意的两个风险

1. **`PROP_Q5` 仍依赖 IMU ay 与 bias ready**
   - 当前启动口径里 `slosh_use_imu_lateral_accel:=false`，含义只是“不把 IMU 横向加速度作为 slosh 模型激励输入”。
   - 但 `risk_scheduler` 仍使用 `imu_ay_unbiased_` 与 `v·ω` 的差值计算不确定性 `u_k`。
   - 因此 `PROP_Q5` 组现场必须确认 IMU 正常、静止零偏已 ready、`/risk_scheduler/u_k` 不长期异常，否则 scheduler 行为会被 IMU 状态污染。

2. **不要用单次 peak 百分比硬判 `PROP` 成败**
   - 0422 预实验中 `PROP_Q5` 更像降低 `p95 / RMS` 持续风险暴露，而不是稳定压低瞬时最高峰。
   - 当前成功判据里的 `PROP peak` 相比 `FAS` 恶化阈值需要结合重复实验的 paired difference、effect size、bootstrap CI 和非参数检验一起看。
   - 如果 `PROP_Q5` 的 `p95/RMS` 稳定优于 `FAS_Q5`，但 `peak` 略差，应按“risk redistribution / sustained risk reduction”解释，不应直接判失败。

### 1.1 非贡献但强影响的结构冻结表

这些结构**不是论文主贡献**，但会显著改变速度、激励强度、液面峰值或终点行为。主实验必须固定口径。

| 结构 | 作用 | 当前状态 / 参数 | 主实验口径 |
|---|---|---|---|
| `tracking_curvature_speed_cap_enable` | TRACKING 中基于局部 `kappa/dkappa` 再压一次 `v_des_cmd` | **关闭**；运行时默认 `false`，`mpc_params.yaml` 未显式打开 | **固定关闭** |
| `slosh_speed_governor/enable` | 根据当前残余晃动再降参考速度 | `enable=false` | **固定关闭** |
| `input_shaping/enable` | ISR/ZV 对 `v_ref` 做输入整形 | `enable=false`；仅 ISR 组打开 | 非 ISR 组**固定关闭** |
| `heading_align/enable` | 起点附近航向误差大时原地转向 | `enable=false` | **固定关闭** |
| `terminal_recovery/enable` | near-goal 终点恢复，直接改变末段 `cmd_vel` | `enable=true` | 保持开启；**主分析裁剪到 tracking/motion phase** |
| `settling/enable` | 终点残余晃动收敛模式 | `enable=false` | **固定关闭**；不作为本轮结论对象 |
| `filter/alpha_v` | `cmd_vel` 线速度 EMA | `1.0` | **冻结** |
| `filter/alpha_omega` | `cmd_vel` 角速度 EMA | `1.0` | **冻结** |
| `filter/kappa_boost` | 曲率自适应角速度滤波增强 | `0.0` | **冻结** |
| `safety/tracking_feasibility_guard_enable` | solve fail 后的 mild/strong 降速保护 | 代码默认 `true`；yaml 未显式覆盖 | 保持现状，不单独做变量 |
| `safety/tracking_reentry_v_cap` | 重进 TRACKING 初始速度上限 | `0.8` | **冻结** |
| `safety/tracking_reentry_ramp_steps` | 重进 TRACKING 爬坡步数 | `5` | **冻结** |
| `path_handler/lookahead_distance` | 影响参考点选取与切弯程度 | `0.50` | **冻结** |
| `path_handler/max_lat_accel` | 路径几何/速度剖面横向加速度预算 | `2.0` | **冻结** |
| `path_handler/speed_profile_omega_max` | 规划层 `omega` 上限 | `1.5` | **冻结** |
| `path_handler/time_parameterize` | 是否启用全局速度剖面 `v(s)` | `true` | **冻结** |
| `path_handler/use_bspline_smoothing` | 全局路径平滑缓存 | `false` | **冻结** |

说明：

- 0422 首批 10 个实物 bag 是在 **`tracking_curvature_speed_cap_enable = false`** 口径下采集的，因此当前结论只针对 **cap off** 条件。
- 如果后续要研究 `cap on/off`，必须单独做一组配对实验，不能混入主统计。

## 2. 路径设计

### 路径集合（按优先级）

| 路径 | 描述 | 长度 | 优先级 |
|---|---|---|---|
| `P3_mixed` | 直线 + 单弯 + S 弯 | 10~15 m | **必做** |
| `P2_s_curve` | 连续 S 弯（≥2 次方向切换） | 10~12 m | **必做** |
| `P1_single_turn` | 单个大角度转弯（≥90°） | 8~10 m | 建议做 |
| `P0_straight` | 长直线 | ≥ 8 m | 负对照，sanity check |

### 路径激励要求

- 转弯段 `v·ω` 峰值 ≥ 0.3 m/s · rad/s（scheduler 才会激活）
- 单弯角度 ≥ 70°
- S 弯两次切换间距 1.5 ~ 3 m
- **路径录制前先空跑一次**，确认轨迹和速度剖面符合预期

### 路径文件存放

```
/data/a/fixed_paths/
  P0_straight.json
  P1_single_turn.json
  P2_s_curve.json
  P3_mixed.json
```

录制路径：
```bash
rosrun scout_local_planner fixed_global_path_runner.py \
  --mode capture --input-topic /scout/global_path \
  --path-file /data/a/fixed_paths/P3_mixed.json
```

重放路径：
```bash
rosrun scout_local_planner fixed_global_path_runner.py \
  --mode replay --path-file /data/a/fixed_paths/P3_mixed.json \
  --output-topic /scout/global_path_fixed \
  --manual-start \
  --start-pos-tol 0.05 --start-yaw-tol 0.10
```

空旷场地也可直接点终点生成模板路径：
```bash
rosrun scout_local_planner template_fixed_path_generator.py \
  --template s_curve \
  --goal-topic /move_base_simple/goal \
```

## 7. 离线分析指标

### 主指标（视觉，红色液体 HSV 三标尺）

```
h_mm_smooth_corr = rolling_median(median(h_left, h_center, h_right) - h0)
```

| 指标 | 含义 |
|---|---|
| `peak(h_mm_smooth_corr)` | 瞬时最高液面 |
| `p95(h_mm_smooth_corr)` | 持续高风险暴露 |
| `RMS(h_mm_smooth_corr)` | 整体波动强度 |
| `max(L,C,R) peak` | 保守瞬时峰值（辅助） |

### 控制侧指标（辅助）

| 指标 | 用途 |
|---|---|
| `v_des_eff p95` | scheduler 是否实际介入 |
| `a_RMS / jerk_RMS` | 控制平滑性 |
| 任务完成时间 | 效率代价 |
| `rho_k` 分布 | 风险调度强度 |

`/slosh/height` 仅作模型辅证，不替代视觉主指标。

## 8. 结论判据

### Q_slosh 抑晃有效
**`FAS_Q5` vs `NOM`**：peak / p95 / RMS 至少两项更低，任务时间代价可接受 → 抑晃有效

### Risk Scheduler 有效
**`PROP_Q5` vs `FAS_Q5`**：

| 结果 | 解释 |
|---|---|
| p95/RMS 更低，peak 不低 | scheduler 降低持续风险，不优化瞬时峰 → **可接受，这是预期** |
| peak 和 p95/RMS 均更低 | scheduler 全面优于固定 Q |
| 速度明显更慢但液面无改善 | scheduler 只带来效率损失 → 问题 |
| PROP 全面不如 FAS | 调度律或参数需要重整 |

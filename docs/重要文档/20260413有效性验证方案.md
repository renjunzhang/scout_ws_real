# 有效性验证方案（实物实验）

> 验证目标：仅靠 MPC 里的 `Q_slosh` 软代价，是否能降低液面晃动风险。
> 工作流：**现场只录包 → 回来离线分析**。

---

## 一、整体逻辑

```
现场（硬件）                    回来（离线）
─────────────────────           ──────────────────────────
1. 固定路径采集（一次性）        Phase A：验证视觉"尺子"可信
2. 静止 static bag              Phase B：Q=0/5/10 液面对比
3. 按 randomized block 录包     提取指标、画图、判定
```

**只改一个变量**：`Q_slosh = 0 / 5 / 10`，其他所有参数全程锁死。

---

## 二、现场操作

### 2.1 实验前提条件（每次进实验室先检查）

- [ ] 试管：37 mm 内直径，58 mm 液面高度，试管中心对齐车体中心
- [ ] RealSense 固定安装，曝光设为固定（关闭自动曝光）
- [ ] 机器人静止时先录一个 **pre-session static bag**（10~15 s）
- [ ] 确认 IMU 话题正常：`rostopic hz /imu/data`（期望 ≥ 50 Hz）
- [ ] 确认 `/imu/data` 的 `frame_id` 正确

---

### 2.2 第一次采集固定路径（只做一次，后续复用）

**目的**：抓取全局规划器发出的第一条 `/scout/global_path`，保存为 JSON，后续所有实验全部复用这条路径。

**终端 1**：正常启动 local planner（先用默认话题，不用 `_fixed`）：
```bash
roslaunch scout_local_planner slosh_experiment.launch Q_slosh:=0
```

**终端 2**：启动路径采集，等到第一条路径发布后自动保存退出：
```bash
rosrun scout_local_planner fixed_global_path_runner.py \
  --mode capture \
  --input-topic /scout/global_path \
  --path-file /data/fixed_path.json
```

采集成功后：
```bash
ls -lh /data/fixed_path.json   # 确认文件存在
```

> 这一步只做一次。文件保存后，后续所有实验都用 `--mode replay` 从这个 JSON 发布固定路径。

---

### 2.3 正式实验流程（每次录包）

#### 启动顺序

**终端 1**：启动 local planner，订阅固定路径话题，只改 `Q_slosh`：

```bash
# Q_slosh = 0 / 5 / 10，每次只改这一个数字
roslaunch scout_local_planner slosh_experiment.launch \
  global_path_topic:=/scout/global_path_fixed \
  Q_slosh:=0
```

**终端 2**：发布固定路径（等机器人回到起点后自动开始发布）：
```bash
rosrun scout_local_planner fixed_global_path_runner.py \
  --mode replay \
  --path-file /data/fixed_path.json \
  --output-topic /scout/global_path_fixed \
  --base-frame base_link \
  --start-pos-tol 0.05 \
  --start-yaw-tol 0.10
```

**终端 3**：录包（每次录包前确认机器人已到起点、路径已发布）：
```bash
rosrun scout_local_planner record_slosh_experiment.sh 0 block1_Q0_run1
# 第一个参数是 Q_slosh，第二个是 bag 名前缀
```

#### 每次 motion bag 结束后

- 把机器人手动推回到起点，对齐朝向
- 等 `/scout/global_path_fixed` 重新发布（`fixed_global_path_runner.py` 会检测起点对齐）
- 开始下一次录包

---

### 2.4 录包顺序：Randomized Block

**不要**连续录完所有 Q=0，再录 Q=5，再录 Q=10。

按如下 block 顺序（提前写好，现场照着执行）：

```
Block 1:  Q5  →  Q0  →  Q10
Block 2:  Q0  →  Q10 →  Q5
Block 3:  Q10 →  Q5  →  Q0
```

每个 block **前后各录一个 static bag**（机器人完全静止，容器不动，10~15 s）。

**最低目标**：3 个 block = 每组 3 次 = 共 9 个 motion bag + 8 个 static bag（每 block 前后各一个，首尾共享）。

**更稳目标**：5 个 block = 每组 5 次 = 共 15 个 motion bag。

---

### 2.5 现场 bag 命名约定

```
static_pre_block1.bag
block1_Q5_run1.bag
block1_Q0_run1.bag
block1_Q10_run1.bag
static_post_block1.bag

static_pre_block2.bag
block2_Q0_run1.bag
...
```

> 命名里带 block 编号和 Q 值，回来分析时不用翻记录。

---

### 2.6 现场只录包，不分析

现场不需要：
- 不需要跑 `extract_slosh_metrics.py`
- 不需要跑 supervised 模型推理
- 不需要做人工标注

现场只需要确认：
- [ ] 机器人跑完了整条路径，没有中途停死
- [ ] bag 文件大小合理（不是空包）
- [ ] `mpc_status` 话题有数据（`rostopic echo -n 5 /mpc_status`）
- [ ] static bag 时相机和容器确实静止

---

### 2.7 现场可能需要调参的情况

**实验中绝对不能动的参数**（动了就作废已录 bag）：

| 参数 | 锁定值 |
|---|---|
| `filter_alpha_v` | 1.0 |
| `filter_alpha_omega` | 1.0 |
| `filter_kappa_boost` | 0.0 |
| `enable_slosh_box_constraint` | false |
| `slosh_speed_governor_enable` | false |
| `risk_scheduler_enable` | false |
| `slosh_use_imu_lateral_accel` | false |
| `slosh_use_imu_yaw_rate` | true |
| 容器参数（radius/height） | 37mm/58mm |

**正式实验前可以调**（调完后冻结）：

| 问题现象 | 可调参数 | 位置 |
|---|---|---|
| 横向误差大，贴不住路径 | 调大 `Q_contour`（当前32.0） | `mpc_params.yaml` |
| 直线段左右摇摆 | 调大 `Q_etheta`（当前15.0） | `mpc_params.yaml` |
| 转向时抖动 | 调大 `R_domega`（当前5.0） | `mpc_params.yaml` |
| 整体速度过快 | 降低 `v_max`（建议先试 1.0 m/s） | `mpc_params.yaml` |
| 弯道速度仍高 | 降低 `max_lat_accel`（当前2.0） | `mpc_params.yaml` |
| 终点冲过/抖动 | 降低 `terminal_recovery/v_max`（当前0.18） | `mpc_params.yaml` |
| REACHED 总不触发 | 放宽 `goal_tolerance`（当前0.20 m） | `mpc_params.yaml` |

**调参顺序**：先把 `v_max` 降到 1.0 跑一次确认能跑通，再逐步调跟踪质量，基线 Q=0 连续跑 2 次 completion time 差异 < 5% 后冻结所有参数，开始正式录包。

## 三、离线分析（回来后）

离线分析分两条平行的线，**互相支撑，不能互相替代**：

```
维度A：视觉液面分析        维度B：轨迹与控制分析
────────────────────        ────────────────────────
数据精度：趋势级            数据精度：精确（无测量误差）
来源：supervised 模型       来源：/cmd_vel、/odom（直接录包）
回答：液面是否真的低了      回答：MPC 的控制行为是否真的改变了
```

两条线合在一起才能说清楚：**控制行为变了（B）→ 激励变小 → 液面趋势性下降（A）**。

---

### 3.1 Phase A：视觉液面分析（趋势级）

#### 第一步：验证视觉"尺子"可信（每次实验都要做）

对所有 motion bag 和 static bag 跑 supervised 模型全帧推理，抽样人工标注验证：

- motion bag：每个抽 30~40 帧（路径进度均匀采样 21 帧 + 峰值事件帧去重）
- static bag：每个抽 15~20 帧
- 盲标：标注时不显示 Q 值、supervised 预测值、/slosh/height

| 指标 | 达标阈值 |
|---|---|
| MAE（supervised vs 人工） | ≤ 0.25 mm |
| Corr | ≥ 0.85 |
| p95 abs error | ≤ 0.60 mm |
| static jitter | ≤ 0.08 mm |

不达标则视觉结果只能作趋势性辅证，不能做定量主指标。

#### 第二步：液面趋势可视化

**可视化1：路径颜色热图（每个 Q 各一张，同色标叠放对比）**

- 按弧长进度（每 0.1 m）采样机器人位置 (x, y) 和 supervised height
- 用颜色编码液面高度，画在地图坐标系上
- 三张图放并排：Q=0 / Q=5 / Q=10，直接看弯道处颜色变化

> 用弧长进度采样，而不是时间采样。原因：Q 大时速度可能偏慢，同一时刻对应不同路径位置，无法对比。

**可视化2：液面趋势曲线（三线叠图）**

- x 轴：归一化路径进度 0~100%（弧长归一化，不是时间）
- y 轴：supervised height，做滑动窗口平滑（窗口约 0.5 m 等效弧长）
- 每个 Q 值：median ± IQR（3~5 次 bag 的统计）
- 三条线叠在一张图，颜色区分 Q=0/5/10

#### 第三步：液面定量指标

| 指标 | 说明 |
|---|---|
| supervised height p95 | 高分位液面风险 |
| supervised height AUC above 0.5 mm | 超阈值累计面积 |
| supervised height max | 峰值 |
| /slosh/height p95 | 模型侧估计（辅证，对齐视觉趋势） |

---

### 3.2 Phase B：轨迹与控制分析（精确）

数据来源全部是 `/cmd_vel` 和 `/odom`，精确，不依赖视觉，没有测量不确定性。

#### 分析1：横向激励（最关键）

v·ω 是液体晃动的直接物理激励来源（离心加速度）。如果 Q_slosh 有效，弯道段的 v·ω 峰值应该下降。

从 bag 直接计算（或用已录的 `/slosh/ay_est`）：

| 指标 | 说明 |
|---|---|
| v·ω 峰值 | 弯道最大横向激励 |
| v·ω RMS（仅弯道段） | 整体横向激励强度 |
| v·ω 超阈值时间比例 | 超 0.3 m/s² 的时间占比 |

**可视化**：同样画路径颜色热图，颜色改为 v·ω 大小。这张图与视觉液面热图叠放，可以直接看"激励大的地方 = 液面高的地方"是否一致。

#### 分析2：控制输出平滑度

Q_slosh 增大时，MPC 为了减少晃动会主动压制弯道角速度。

| 指标 | 说明 |
|---|---|
| ω 峰值 | Q 大时是否下降 |
| ω RMS | 整体角速度强度 |
| dω/dt 峰值（角加速度） | 控制输出的激进程度 |
| v 标准差 | 速度一致性（速度抖动大说明控制不稳） |

**可视化**：v 曲线和 ω 曲线按路径进度画三线叠图（Q=0/5/10），看弯道段是否有明显差异。

#### 分析3：路径跟踪误差（可比性验证）

确认 Q 大时不是以牺牲跟踪精度为代价换来的液面下降。

- 将 `/odom` 轨迹投影到 `/data/fixed_path.json`，计算每个时刻的横向偏差
- 按路径进度分段报告，不要只报全段平均

| 指标 | 说明 |
|---|---|
| 横向跟踪误差 p95 | 若 Q 大时明显恶化，结论降级 |
| completion time | 若相差 > 10%，结论降级 |
| average speed | 同上 |

---

### 3.3 两条线的结论组合

| 情况 | 结论 |
|---|---|
| B 线 v·ω 下降 + A 线液面趋势下降 + 可比性满足 | 强结论：MPC 通过减少激励降低了液面风险 |
| B 线 v·ω 下降 + A 线液面无明显趋势 | 控制行为改变了，但液面改善超出视觉分辨率，弱结论 |
| B 线 v·ω 不变 + A 线液面下降 | 可疑，需检查是否 completion time 变长（跑慢了） |
| B 线 v·ω 不变 + A 线液面无变化 | Q_slosh 在当前参数下未产生显著效果 |

---

### 3.4 可比性排除规则

以下情况该 bag 不能写成"纯 anti-slosh 改善"：

- completion time 与 Q=0 基线相差 > 10%
- average speed 相差 > 10%
- 横向跟踪误差明显恶化
- solver fail 频繁（> 5%）
- 起点姿态不满足固定路径门限（yaw_err > 0.10 rad）
- static bag 显示明显光照/曝光漂移

---

### 3.5 判定标准

**可以写强结论的前提**：

- [ ] Phase A 视觉尺子过线
- [ ] B 线：v·ω 峰值或 RMS 相对下降 ≥ 15%（弯道段）
- [ ] A 线：supervised p95 或 AUC 相对下降 ≥ 20%，或绝对下降 ≥ 0.3 mm
- [ ] completion time 和 average speed 变化 < 10%
- [ ] 高峰帧人工复核支持视觉趋势

**只能写趋势性结论的情况**：

- 视觉改善量 0.05~0.1 mm，或仅出现在单个 bag
- B 线控制行为改变，但 A 线视觉无法分辨

## 六、论文表述边界

**可以写**：

> The supervised visual estimator provides a reliable offline evaluation signal for medium-scale slosh changes.
>
> Under matched fixed-path experiments, increasing Q_slosh reduces high-percentile liquid-surface risk while maintaining comparable tracking behavior.

**不能写**：

- supervised 模型是逐帧真值
- 0.05~0.1 mm 的改善已被可靠证明
- 只凭 `/slosh/height` 证明控制器有效
- completion time 明显变长时宣称纯 anti-slosh 机制独立有效

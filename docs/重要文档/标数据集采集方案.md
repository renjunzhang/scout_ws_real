# 标数据集采集方案

## 1. 目的

本文用于给当前项目中的两种新试管尺寸提供一套可直接落到 `scout_local_planner` 的参数初值，并说明这些参数和论文
`Sloshing Dynamics Estimation for Liquid-filled Containers under 2-Dimensional Excitation`
建模口径的对应关系。

本次覆盖的两种容器为：

- 试管 A：内直径 `28 mm`，静止液面高度 `58 mm`
- 试管 B：内直径 `37 mm`，静止液面高度 `58 mm`

下面默认：

- 上述“直径”指**容器内径**
- 液体为水
- 试管中心仍按当前工程假设，位于机体旋转中心附近
- 运行模型仍采用当前工程默认配置：
  - `mode_index = 1`
  - `use_linear_model = true`
  - `use_parabola_term = true`

如果给出的 `28 mm / 37 mm` 实际上是**外径**，则不能直接使用本文的 `container_radius`，必须重新量内径。

### 2.2 与论文总结文档的一致口径

根据 [Slosh Dynamics论文中建模总结.md](/home/a/scout_ws/docs/重要文档/Slosh%20Dynamics论文中建模总结.md) 和当前代码实现，参数对应关系如下：

- `container_radius = R = 直径 / 2`
- `liquid_height = h = 静止液面高度`
- `mode_index = 1`
  - 当前工程只使用第一模态
- `use_linear_model = true`
  - 当前工程默认采用 L 模型对应的液面高度映射
- `use_parabola_term = true`
  - 当前工程额外叠加工程化的旋转抛物面项
- `damping_ratio = zeta`
  - 这个量**不能只靠几何尺寸直接推出**
  - 需要通过自由衰减实验或回放拟合辨识

论文与当前代码一致使用的第一模态公式为：

\[
\omega_1^2 = g \cdot \frac{\xi_{11}}{R} \cdot \tanh\left(\frac{\xi_{11} h}{R}\right)
\]

其中：

- `xi_11 = 1.8412`
- `g = 9.81`

当前代码在 `use_linear_model = true` 时，对应的液面高度系数为：

\[
\eta = \frac{4 h m_1}{m_F R} \sqrt{x_1^2 + y_1^2}
\]

也就是文档和代码里常说的 `height_coeff (L)`。

### 2.3 是否要根据“具体激励频率/运动周期”去改液体模型参数

结论：

- **不需要**因为某一条 bag 的具体激励频率或运动周期变化，就去改几何模型参数
- 激励频率/运动周期主要用于：
  - 判断这批数据是否覆盖了有代表性的输入频段
  - 检查理论首模频率和实测主响应频率是否接近
  - 进一步辨识 `damping_ratio`

对于同一根试管、同一装液高度，下面这些参数应保持不变：

- `container_radius`
- `liquid_height`
- `liquid_density`
- `mode_index`
- `offset_x`
- `offset_y`
- `use_linear_model`
- `use_parabola_term`

原因是当前代码里，首模频率 `omega_1`、模态质量 `m_1`、高度系数 `height_coeff` 都是由容器几何和模型选择决定的，而不是由某一次实验轨迹的运动周期决定的。

只有下面这些量会通过实验数据进一步修正：

- `damping_ratio`
  - 通过自由衰减或回放拟合修正
- `Q_slosh`
  - 属于控制器代价参数，不属于容器物理参数
- `slosh_height_max`
  - 属于控制器约束阈值，不属于容器物理参数

因此正确顺序是：

1. 先按实物测量固定几何参数
2. 再用多组实验数据检查理论频率和实测主响应是否匹配
3. 若衰减不对，优先辨识 `damping_ratio`
4. 若理论主频长期明显偏离实测主频，再考虑后续引入 `omega_eff` 一类辨识参数
5. 不要为了拟合某一次 bag 的运动周期，反向篡改 `container_radius` 或 `liquid_height`

### 3.2 当前阶段推荐的 `damping_ratio`

`damping_ratio` 不能仅根据 `R/h` 直接由论文公式唯一确定，因此这里把 `28 mm` 和 `37 mm` 分开处理。

建议这样处理：

- 对当前正在运行的 `28 mm` 试管：
  - 可继续使用 `damping_ratio = 0.12`
  - 这次把液高从 `55 mm` 修正到 `58 mm`，不需要因此立刻把阻尼比也推倒重来
  - 但如果后续重新做自由衰减辨识，仍然可以再更新
- 对新的 `37 mm` 试管：
  - 作为**采集阶段初值**先设 `damping_ratio = 0.05`
  - 采完第一批自由衰减数据后，再回写该试管自己的辨识值

原因：

- `0.12` 是当前 `28 mm` 水试管的工程可用值，当前可以继续保留
- 但它不应直接外推到 `37 mm`
- `0.05` 更适合作为“仅已知几何尺寸、尚未辨识”的新试管中性起点

## 5. 采集阶段建议

如果当前目标是“为新试管采一批可用于后续验证或辨识的数据”，建议先按下面的实验口径执行：

### 5.1 先采基线辨识数据，不急着开 anti-slosh

建议先使用：

- `Q_slosh = 0`
- `enable_slosh_box_constraint = false`
- `slosh_speed_governor_enable = false`

先做几组自由衰减和简单转弯激励，目的是：

- 检查理论频率和实测主频是否接近
- 用实测自由衰减重新拟合 `damping_ratio`

### 5.2 先改几何参数，再改阻尼

对这两种试管，推荐顺序是：

1. 先按实物确认 `container_radius` 和 `liquid_height`
2. 对 `28 mm` 当前试管，可先保持 `damping_ratio = 0.12`
3. 对 `37 mm` 新试管，先用 `damping_ratio = 0.05` 跑第一批数据
4. 再根据对应试管的实测衰减结果分别更新 `damping_ratio`
5. 最后再做 `Q_slosh = 0 / 5 / 10 / 20` 的控制对照实验

### 5.3 暂不在本文中给 `slosh_height_max` 新值

本文只根据“直径 + 当前液高”给出 slosh 建模参数初值。

`mpc/slosh_height_max` 还取决于：

- 容器总内高
- 液面到容器口的剩余裕量
- 你希望用于控制的保守程度

在当前没有提供容器总内高之前，不建议仅凭 `28 mm / 37 mm` 和 `58 mm` 液高直接重设该值。

如果当前只是做数据采集或参数辨识：

- 可继续保持 `enable_slosh_box_constraint = false`
- `slosh_height_max` 暂不作为主配置项

## 8. 速度限制通过哪些参数调节

当前 `scout_local_planner` 的“速度限制”不是单一参数，而是分四层生效。调速时应按下面的层级理解。

### 8.1 第一层：MPC/车辆硬边界

这层是最硬的上限，直接限制优化问题里的状态和控制：

- `vehicle/v_max = 3.0`
  - 线速度硬上限
- `vehicle/v_min = 0.0`
  - 线速度下限，当前禁用倒车
- `vehicle/omega_max = 1.0`
  - 角速度硬上限
- `vehicle/a_max = 1.5`
  - 线加速度硬上限
- `vehicle/alpha_max = 2.5`
  - 角加速度硬上限
- `vehicle/j_max = 3.0`
  - 线 jerk 上限

这层决定了“优化器无论如何都不允许超过什么”。

### 8.2 第二层：路径参考速度生成

这层决定 `PathHandler` 给 MPC 的 `v_ref` 长什么样，通常比硬边界更早起作用。

当前主要参数为：

- `path_handler/max_lat_accel = 2.0`
  - 曲率大时通过 `v <= sqrt(a_y_max / |kappa|)` 压低参考速度
  - 这是转弯时最关键的限速参数
- `path_handler/max_tan_accel = 1.5`
  - 限制参考速度上升有多快
- `path_handler/max_tan_decel = 0.7`
  - 限制参考速度下降有多快
- `path_handler/goal_capture_distance = 0.25`
  - 进入终点捕获区后，开始切到末端速度策略
- `path_handler/goal_capture_min_speed = 0.0`
  - 终点捕获区最低参考速度
- `path_handler/goal_speed = 0.0`
  - 末端期望速度

另外，当前代码在生成局部参考前会先取一个名义速度：

- `v_des_cmd = 0.8 * vehicle/v_max`

所以按当前 `vehicle/v_max = 3.0`，名义参考起点是：

- `v_des_cmd = 2.4 m/s`

随后再被 `max_lat_accel`、`max_tan_accel`、`max_tan_decel` 和终点捕获逻辑继续压低。

如果你的问题是“实际跑起来为什么转弯时速度变慢”，优先看：

- `path_handler/max_lat_accel`
- `path_handler/max_tan_decel`

### 8.3 第三层：slosh speed governor

这是液面感知的附加降速层，只在下面条件成立时才生效：

- `slosh_speed_governor/enable = true`

而你当前给出的命令：

```bash
roslaunch scout_local_planner slosh_experiment.launch Q_slosh:=5
```

默认是：

- `slosh_speed_governor/enable = false`

所以这次实验里，这一层**不参与限速**。

如果以后要启用它，关键参数是：

- `slosh_speed_governor/ay_max_base`
  - 给速度治理提供横向加速度预算
- `slosh_speed_governor/k_eta`
  - 按残余液面高度进一步缩紧速度
- `slosh_speed_governor/v_des_min`
  - speed governor 限速后的最低参考速度
- `slosh_speed_governor/eta_deadband`
  - 小晃动死区
- `slosh_speed_governor/eta_exit_ratio`
  - 退出滞回
- `slosh_speed_governor/preview_distance`
  - 前方曲率预览距离
- `slosh_speed_governor/min_active_steps`
  - 激活后至少持续几个控制周期

如果要做纯 `Q_slosh` 消融实验，应继续保持：

- `slosh_speed_governor/enable = false`

否则“速度变慢”就不再只是 `Q_slosh` 的效果。

### 8.4 第四层：终点恢复阶段限速

靠近终点时，控制器可能切到 terminal recovery 逻辑，这一层也会单独收紧速度：

- `terminal_recovery/max_omega = 0.8`
- `terminal_recovery/v_min = 0.05`
- `terminal_recovery/v_max = 0.18`

所以如果你观察到“快到终点时速度明显很小”，不要先怀疑 `Q_slosh`，应先确认是不是进入了 terminal recovery。

### 8.5 输出滤波不是硬限速

`slosh_experiment.launch` 里还有三项和输出相关：

- `filter/alpha_v`
- `filter/alpha_omega`
- `filter/kappa_boost`

它们作用在 `cmd_vel` 发布前的平滑环节，不是 MPC 约束里的硬速度上限。

对于当前命令，它们被 launch 设成：

- `filter/alpha_v = 1.0`
- `filter/alpha_omega = 1.0`
- `filter/kappa_boost = 0.0`

这意味着实验模式下基本关闭了额外输出低通，所以当前看到的速度变化主要来自：

- 路径参考速度生成
- MPC 约束
- 终点恢复逻辑

而不是发布端滤波。

## 9. 调速时的实际建议

如果你的目标是“只做 `Q_slosh` 对照，不额外引入别的限速因素”，建议保持：

- `enable_slosh_box_constraint = false`
- `slosh_speed_governor_enable = false`
- `filter_alpha_v = 1.0`
- `filter_alpha_omega = 1.0`
- `filter_kappa_boost = 0.0`

如果你的目标是“单纯把整条轨迹跑慢一些”，优先改：

- `path_handler/max_lat_accel`
- `path_handler/max_tan_accel`
- `path_handler/max_tan_decel`

如果你的目标是“绝对不让 planner 超过某个车速”，优先改：

- `vehicle/v_max`

如果你的目标是“根据液面估计结果主动降速”，再去启用并调整：

- `slosh_speed_governor/*`

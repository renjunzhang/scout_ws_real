## 2. 第一阶段：terminal 收敛 smoke（当前版本必须先复查）

目的：

```text
确认当前 terminal_slowdown + v_des_rate_limit + TERMINAL_MPC_STOP 能让小车稳定停车；
确认不会冲过终点后调头；
确认 terminal 附近没有明显 ax / jerk 脉冲。
```

本轮优先测试对象：

```text
先测试当前新结构：
  terminal capture 只进入 TERMINAL_MPC_STOP；
  不再由外层 CAPTURE_BRAKE 直接发制动速度；
  MPC 继续负责最后一段减速。

不要先回到旧命令做主验证。
旧命令只适合作为对照包，用来证明新结构是否降低 terminal 附近 ax / jerk。
```

当前 terminal 结构：

```text
1. terminal_slowdown_distance 内启用两段式运动学速度包络：
   capture 前：
     v_env(d) = min(v_slowdown_max,
                    sqrt(v_capture^2 + 2 * max_tan_decel * max(0, d - capture_distance)))

   capture 后：
     v_env(d) = min(v_capture,
                    sqrt(2 * max_tan_decel * max(0, d - goal_tolerance)))

  其中：
     v_slowdown_max = terminal_slowdown_v_max
     v_capture      = terminal_recovery.v_max
     max_tan_decel  = min(path_handler/max_tan_decel, v_des_decel_limit)

   这样 terminal 前 1s 不再保持 0.77m/s 左右的高参考速度；
   进入 capture 后也不会直接把 v_des_raw 砍成 0 导致停在容差外。

2. pre-MPC：
   v_des = min(raw_v_des, v_env)
   若已经进入 TERMINAL_MPC_STOP 但位置还没到：
     raw_v_des = v_capture
   若位置已到或 goal 已在车后：
     raw_v_des = 0

3. post-MPC：
   cmd_v = min(MPC_cmd_v, v_env)
   如果 GoalInfo.dx <= 0，cmd_v 强制为 0。
   未越过 goal 时，用有效减速度对 cmd_v 做变化率限制：
     min(path_handler/max_tan_decel, v_des_decel_limit)
   terminal phase 下会同步 cmd_v EMA 滤波状态，避免上一帧高速被滤波器带回输出。

4. REACHED：
   必须同时满足 speed_low 和 goal_position_reached；
   冲过终点后停在容差外，不再假阳性 REACHED。
```

注意 `terminal_slowdown_v_max` 的含义：

```text
terminal_slowdown_v_max 现在是 slowdown 外层包络最高速度，不再等同于 capture 内目标速度。
capture 入口和 capture 内低速目标由 terminal_recovery.v_max 给出，当前配置为 0.18m/s。

如果 terminal_slowdown_v_max:=0.18：
  整个 slowdown 段都会很慢；
  只作为极保守不越界参考，不作为优先验证参数。

如果 terminal_slowdown_v_max:=0.80：
  slowdown 段允许正常速度；
  但在 capture_distance 附近会由两段式 envelope 压到 v_capture≈0.18；
  当前优先用该配置验证 terminal_approach_1s 是否平顺。
```

后续如需复查 terminal，建议录包顺序：

```text
1. 当前两段式 envelope smoke（第一包实物优先）：
   terminal_slowdown_distance:=1.50
   terminal_slowdown_v_max:=0.80
   terminal_capture_stop_distance:=0.70
   录 terminal_smoke_twostage_d150_run01/02

2. 如果第 1 步停车干净，再回到 terminal_slowdown_distance:=1.20 做一包对照；
   用于判断 1.50 是否只是保守余量，还是实物必须参数。

3. 如果第 1 步仍有明显 ax/jerk 或冲过终点，先停固定路径 cost 主实验；
   回看 /terminal/v_envelope、/terminal/cmd_v_pre_clamp、/terminal/cmd_v_post_clamp 和 /cmd_vel。
```

## 3. 第二阶段：固定路径 MPC cost / ax-jerk 调参对比

目的：

```text
固定路径形状，比较 C/D/E/F/G 五组 MPC cost；
验证 slosh cost 已经进入优化后，进一步确认显式提高 a / Δa 权重是否能压住早段 ax 和 RGB peak。
```

本阶段仍然不启动 OSCRS / GeoRef post-processor。

20260518 fixed_path_cost 已有结论：

```text
D 组相对 C 组：
  v_p95、ay_p95、model_p95 有下降；
  pct_slosh_total 约 20%，说明 slosh cost 已经参与优化；
  但 model_peak 没下降，RGB h_abs_peak / p95 也没有下降。

峰值定位：
  model_peak 多发生在 first terminal 前 0.03s 左右，和 terminal 前 ax 减速脉冲相关；
  RGB peak 在 D 组三次都集中在 TRACKING 后约 7s、路径里程 s≈1.5m；
  该处 D 组 ay 降了，但 odom_ax 没有明显降。

因此下一轮不是继续堆 Q_slosh，而是验证 ax/jerk 优先级。
```

本轮不做的事：

```text
1. 不改固定路径速度剖面来单独照顾 D/F 组；
2. 不启用 energy_profile / input_shaping / risk_scheduler / speed_governor；
```

固定路径主实验的 terminal 规则：

```text

C/D/E/F/G 比较只看 TRACKING_PRE_TERMINAL：
  这段内还没有 terminal envelope 接管；
  更能反映 MPC cost 和 slosh cost 对轨迹/速度/加速度的影响。
```

### 3.1 固定路径选择

优先顺序：

```text
P2_s_curve:
  首选。主要考察 ay / omega / domega / eta_y / RGB 液面。

P0_straight:
  用于复查 ax / terminal，不作为第一条 slosh cost 主路径。

P3_mixed:
  P2_s_curve 有结果后再跑，作为综合路径。
```

先只做：

```text
P2_s_curve
```

固定路径生成方式保持所有组完全一致：

```text
template_fixed_path_generator.py 负责生成 /scout/global_path_fixed；
send_fixed_goal.py 或 rostopic pub 只负责提供终点 goal；
所有组使用同一模板、同一 goal、同一生成参数；
每包前尽量回到同一起点姿态后，可以重新生成 P2_s_curve；
不按组修改路径形状或速度剖面。
```

不要把“固定路径”理解成完全复用同一个 JSON：

```text
template_fixed_path_generator.py 的输入包含当前小车起点；
如果每包起点有小偏差，重新生成的 P2_s_curve 也会有小差异。

因此现场主流程是：
  1. 每包前把车回到同一物理起点和朝向；
  2. 用同一个 goal；
  3. 用同一套 template_fixed_path_generator.py 参数重新生成 /scout/global_path_fixed；
  4. 录包后用 path_len、trajectory_overlay、起始 tracking error 检查路径一致性。
```

更严格但风险更高的做法：

```text
第一次在标准起点生成 P2_s_curve.json；
后续所有组直接重复发布同一个 JSON。

只有当小车每次都能回到几乎同一定位起点时才推荐；
否则初始 tracking error 会变大，反而污染 C/D/E/F/G 对比。
```

### 3.2 分组参数

本轮建议先跑 5 组，每组 3 包：

```text
C: SMOOTH_SPEED_RELAXED
   不加 slosh，作为平滑/降速基础对照。

D: SLOSH_PRIORITY
   在 C 的速度和平滑设置上加 Q_slosh=5，复现 20260518 D 组边界。

E: AX_JERK_PRIORITY
   不加 slosh，提高 R_a / R_da，验证单纯纵向加速度/jerk 平滑能否压住 RGB peak。

F: SLOSH_PLUS_AX_JERK
   在 D 基础上提高 R_a / R_da，验证 slosh + ax/jerk 是否优于单纯平滑。

G: SLOSH_PLUS_AX_JERK_PREVIEW
   在 F 基础上打开 slosh_preview_factor，验证 one-step preview slosh 加权是否优于 F。
```

参数表：

```text

D     3.0  0.5  1.5   2.0      6.0       5        0.0      eta=5, eta_dot=3
E     3.0  1.0  2.0   2.0      6.0       0        0.0      off

```

说明：

```text
E/F 只提高 a 和 Δa 的权重，不降低 R_a/R_omega。
如果 E/F 仍不能压住早段 RGB peak，再考虑更强一档 R_a=1.5、R_da=3.0；
不要第一轮直接大幅调参。
```

G 组说明：

```text
slosh_preview_factor 是可回退开关：
  0.0 = 完全旧行为；
  0.5 = 对预测状态 x_1..x_N 额外加 0.5 份 slosh 权重。

G 组不是默认主线，只用于回答：
  在 F 的 slosh + ax/jerk 结构上，进一步强调一步后的预测液体状态是否更有效。

第一轮只用 slosh_preview_factor:=0.5。
如果行为过慢、pct_slosh_total 过高或 tracking 变差，立即回退到 0.0。
```

## 5. 后续结构改进：preview slosh penalty

当前已加入可回退开关：

```text
slosh_preview_factor
```

本节原本作为 E/F 后的结构候选；现在在第二阶段中新增 G 组小剂量测试：

```text
G = F + slosh_preview_factor:=0.5
```

回退方式：

```text
slosh_preview_factor:=0.0
```

当前 slosh state cost 可以理解为：

```text
J_slosh,k = Q_eta * eta_k^2 + Q_eta_dot * eta_dot_k^2
```

其中：

```text
x_slosh,k = [eta_x, eta_dot_x, eta_y, eta_dot_y]
x_slosh,k+1 = A_d * x_slosh,k + B_d * a_k
```

问题：

```text
eta / eta_dot 是二阶系统状态，带记忆和相位延迟；
当前 a_k 对 eta_k 的影响不直接；
如果只惩罚 eta_k，优化器不一定能及时压住当前 ax 脉冲。
```

可选结构改进：

```text
one-step-ahead slosh penalty:
  先用当前候选控制 a_k 预测 x_slosh,k+1；
  再对 eta_{k+1} / eta_dot_{k+1} 计 slosh cost。

形式：
  x_slosh,k+1 = A_d * x_slosh,k + B_d * a_k
  J_slosh,k += Q_eta * eta_{k+1}^2
             + Q_eta_dot * eta_dot_{k+1}^2
```

也可以扩展成 multi-step preview：

```text
J_slosh,k += sum_i w_i * ||x_slosh,k+i||_Q^2

例如：
  i = 1, 2, 3
  w = 1.0, 0.8, 0.5
```

预期作用：

```text
让当前控制 a_k 更直接地影响 slosh cost；
减少“slosh 项有占比，但压不住当前 ax 脉冲”的现象；
作为 slosh-state penalty 的结构增强，而不是单纯堆 Q_slosh。
```

边界：

```text
preview slosh penalty 仍然不是 ax hard limiter；
如果模型相位/幅值与 RGB 不一致，它仍可能压不住真实峰值；
因此它不能替代 R_a / R_da / ax constraint。
```

建议推进顺序：

```text
1. 先跑 C/D/E/F/G；
2. 先确认 E/F 是否能压住早段 ax/RGB p95；
3. 再看 G vs F，判断 preview 是否提供额外收益；
4. preview 改动后必须重新检查 cost_breakdown、/mpc/slosh_horizon_summary 和 RGB 真值。
```

论文表述建议：

```text
The slosh-aware MPC can combine a liquid-state penalty with an excitation-shaping penalty.
The liquid-state penalty may be evaluated on previewed slosh states to increase the coupling
between the current acceleration command and the predicted liquid response.
```

中文口径：

```text
不是只惩罚液体当前晃起来后的状态；
也可以惩罚当前控制一步以后将造成的液体预测状态；
但纵向激励源头仍需要 R_a/R_da 或 ax constraint 共同约束。
```

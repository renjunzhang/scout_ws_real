# 20260518 MPC 终点收敛与固定路径验证方案

目标：

```text
先验证当前 MPC terminal 是否稳定收敛；
如果 terminal 收敛，再进入固定路径 MPC cost 对比；
本方案只验证 MPC cost / terminal，不涉及 OSCRS / GeoRef / path post-processor。
```

核心原则：

```text
1. 先跑 terminal smoke，不通过就不录固定路径 cost 主实验。
2. 固定路径对比只改变 MPC cost 参数，不改变路径、不打开 OSCRS。
3. 真实液面结论以 RGB 视觉为准，/slosh/height 只作为模型调试量。
4. terminal_slowdown / TERMINAL_MPC_STOP 段只用于判断终点是否平稳，不作为 slosh cost 主效果窗口。
```

## 2. 第一阶段：terminal 收敛 smoke

目的：

```text
确认当前 terminal_slowdown + v_des_rate_limit + TERMINAL_MPC_STOP 能让小车稳定停车；
确认不会冲过终点后调头；
确认 terminal 附近没有明显 ax / jerk 脉冲。
```

本轮优先测试对象：

```text
先测试当前新结构：
  terminal capture 只进入 TERMINAL_MPC_STOP；
  不再由外层 CAPTURE_BRAKE 直接发制动速度；
  MPC 继续负责最后一段减速。

不要先回到旧命令做主验证。
旧命令只适合作为对照包，用来证明新结构是否降低 terminal 附近 ax / jerk。
```

当前 terminal 结构：

```text
1. terminal_slowdown_distance 内启用运动学停车包络：
   v_env(d) = min(terminal_slowdown_v_max, sqrt(2 * max_tan_decel * max(0, d - goal_tolerance)))

2. pre-MPC：
   v_des = min(raw_v_des, v_env)

3. post-MPC：
   cmd_v = min(MPC_cmd_v, v_env)
   如果 GoalInfo.dx <= 0，cmd_v 强制为 0。
   未越过 goal 时，用 path_handler/max_tan_decel 对 cmd_v 做变化率限制。
   terminal phase 下会同步 cmd_v EMA 滤波状态，避免上一帧高速被滤波器带回输出。

4. REACHED：
   必须同时满足 speed_low 和 goal_position_reached；
   冲过终点后停在容差外，不再假阳性 REACHED。
```

注意 `terminal_slowdown_v_max` 的含义：

```text
terminal_slowdown_v_max 是 envelope 的上限。

如果 terminal_slowdown_v_max:=0.18：
  envelope 大部分时候被 0.18 截断；
  实测不会过冲，但容易停在 goal tolerance 外，无法 REACHED；
  现在只作为保守不越界参考，不作为优先验证参数。

如果 terminal_slowdown_v_max:=0.80：
  envelope 更多由 sqrt(2ad) 决定；
  实测可以 REACHED，但 terminal 内 ax 脉冲偏大；
  当前优先在 0.80 基础上验证输出层限加速度。
```

建议录包顺序：

```text
1. 输出限加速度 smoke：
   terminal_slowdown_v_max:=0.80
   录 terminal_smoke_rate_limited_run01/02

2. 如果第 1 步仍有明显 ax 脉冲，再考虑降低 terminal_slowdown_v_max 到 0.60-0.70，
   或单独调小 path_handler/max_tan_decel。

3. 如果第 1 步仍然冲过终点，先停固定路径 cost 主实验；
   回看 /terminal/v_envelope、/terminal/cmd_v_pre_clamp、/terminal/cmd_v_post_clamp 和 /cmd_vel。
```

## 5. 是否进入下一步

进入 P3_mixed 的条件：

```text
1. terminal smoke 三包都无明显过冲；
2. P2_s_curve 的 C/D 对比中 terminal 没有污染主窗口；
3. cost_breakdown 显示 D 组 slosh cost 有可见占比；
4. D 组相对 C 组在 ay/omega/jerk 或 RGB 液面上至少有方向一致的改善。
```

如果 P2_s_curve 看不出差异：

```text
先查 horizon 内 eta 是否真的被预测出来；
再查 Q_slosh_eta 归一化尺度；
不要直接大幅堆 Q_slosh，也不要降低 R_a/R_omega 制造效果。
```

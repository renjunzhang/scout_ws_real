### 1.3 当前 IMU 数据发布内容总结
当前 `/imu/data` 实际发布内容可整理为：

- 消息类型：
  - `sensor_msgs/Imu`
- 已发布并可直接读到的字段：
  - `header.stamp`
    - 这帧 IMU 消息的 ROS 时间戳
  - `header.frame_id`
    - 这帧数据声明所使用的坐标系名字
    - 当前只是消息头里的字符串，不单独证明物理安装方向一定正确
  - `orientation`
    - IMU 姿态四元数
    - 由厂家输出的欧拉角转换而来
    - 表示 IMU 当前朝向，不是角速度
  - `angular_velocity.x`
    - 绕 `x` 轴角速度，单位 `rad/s`
  - `angular_velocity.y`
    - 绕 `y` 轴角速度，单位 `rad/s`
  - `angular_velocity.z`
    - 绕 `z` 轴角速度，单位 `rad/s`
    - 对你当前项目最重要，主要用于 yaw rate
  - `linear_acceleration.x`
    - `x` 方向线加速度，单位 `m/s^2`
    - 当前驱动发布的数据里保留重力投影
  - `linear_acceleration.y`
    - `y` 方向线加速度，单位 `m/s^2`
    - 对你当前项目最重要，主要用于 lateral accel
  - `linear_acceleration.z`
    - `z` 方向线加速度，单位 `m/s^2`
    - 静止放平时通常接近 `+9.8`，可用来判断当前数据是否含重力分量
- 当前驱动**没有认真填充**、通常表现为全 `0` 的字段：
  - `orientation_covariance`
    - 姿态协方差，理论上表示姿态估计不确定性
  - `angular_velocity_covariance`
    - 角速度协方差，理论上表示角速度测量不确定性
  - `linear_acceleration_covariance`
    - 线加速度协方差，理论上表示加速度测量不确定性

说明：

- `orientation` 来自厂家串口输出的欧拉角，驱动里再转成四元数
- `angular_velocity` 和 `linear_acceleration` 直接来自厂家串口数据
- 当前 `covariance` 全 `0` 不表示“误差为 0”，而是表示厂家驱动没有提供这部分协方差
- 磁力计**不在** `/imu/data` 里，而是单独发布在 `/wit/mag`

### Todo 1：做 `lateral_accel` 的低风险导航 A/B

目标：

- 判断 `slosh_use_imu_lateral_accel:=true` 是否值得进入默认正式配置

     - `slosh_use_imu_lateral_accel:=false`
     - `slosh_use_imu_alpha_z:=false`
   - B 组：
     - `slosh_use_imu_yaw_rate:=true`
     - `slosh_use_imu_lateral_accel:=true`
     - `slosh_use_imu_alpha_z:=false`

这三个参数的意义分别是：

- `slosh_use_imu_yaw_rate`
  - 是否使用 IMU 的 `angular_velocity.z` 作为 slosh 估计里的偏航角速度输入

  - 是否使用 IMU 的 `linear_acceleration.y` 作为 slosh 估计里的横向加速度输入
  - `false` 时通常退回到运动学近似 `a_y ≈ v * omega`
  - `true` 时改用经过当前预处理后的 IMU `ay`
- `slosh_use_imu_alpha_z`
  - 是否使用 IMU 的 `angular_velocity.z` 差分得到的 `alpha_z` 作为角加速度输入
  - 当前零偏心配置下，它对主模态传播作用很弱，因此暂不作为主线
2. 路线选开阔、低风险、无复杂障碍环境
3. 只做低速导航，不同时修改：
   - `Q_slosh`
   - `v_max`
   - near-goal 参数
   - 其他 tracking 参数
4. 每组至少录 2 包，动作/目标尽量一致

验收标准：

- `true` 组不引入明显 solver failure
- `true` 组不引入明显 tracking 回归
- `/slosh/ay_est` 切换逻辑正确
- 若 `height`、`height_pred_max` 或控制更平稳，则可考虑提升为默认正式配置

输出：

- 一段 A/B 结论

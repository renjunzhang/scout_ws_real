## 1. 方法定义

最终方法名：

```text
OSCRS:
Online Slosh-Constrained Reference Selection
```

中文：

```text
在线晃动高度约束参考选择。
```

系统结构：

```text
MBF raw global path
        ↓
GeoRef candidate generator
  original / mild / medium / mid / strong
        ↓
per-candidate slosh-height rollout
        ↓
Layer 1 hard gate
  collision / drift / endpoint / length
  h_pred <= eta_lim
  residual_h <= 0.2 eta_lim
        ↓
Layer 2 score
  time / geometry / slosh margin
        ↓
selected anti-slosh reference path
        ↓
normal MPC tracking
  Q_slosh = 0
  Q_slosh_eta_dot = 0
  no PMG / no output cap / no constrained-MPC
```

核心边界：

```text
OSCRS 不修改 MPC 求解器。
OSCRS 不复活 Q_slosh。
OSCRS 不改变 vehicle_v_max / R_a / R_da / lead_time。
OSCRS 不启用 risk_scheduler / energy_profile / input_shaping / PMG / output guard。
OSCRS 不承诺严格 slosh-free，只承诺 slosh-reduced / low-excitation。
OSCRS 第一版只选择路径，不发布速度 profile。
```

## 1.5 模型参数一致性前置（必须在 Step 0 之前完成）

OSCRS 的所有判据都依赖 slosh rollout 与闭环 /slosh/height 的口径一致。
若仿真侧 omega_n / zeta / height_coeff 与观测器侧不同，PASS/SATURATED/FAIL
都不可信。本节锁定一组前置标定，作为后续所有 Step 的前提。

容器物理参数固化：

```text
R           = 容器内半径 (mm), 来自实物测量
h           = 静态液面高度 (mm), 来自实物液位标定
omega_n     = sqrt(g * xi_{1n}/R * tanh(xi_{1n} * h/R))    Ferrari 式(1)
              其中 xi_{1n} = 1.841
m_F         = 液体总质量 (g)
m_n         = m_F * 2R/(xi_{1n} h (xi_{1n}^2-1)) * tanh(xi_{1n} h/R)   Ferrari 式(2)
height_coeff = xi_{1n}^2 * h * m_n / (m_F * R)              Ferrari 式(13)
zeta        = 默认 0.05（与当前实验复现口径一致）
              备选: physics-derived ζ from Ferrari 式(3), 仅在 ablation 启用
```

参数文件位置：

```text
src/scout_apps/control/scout_local_planner/config/oscrs_container.yaml   (新增)
  R_mm: ...
  h_mm: ...
  m_F_g: ...
  liquid_density: ...
  liquid_viscosity: ...
  zeta: 0.05
  height_coeff_mode: closed_form   # closed_form | manual
```

观测器侧对齐检查：

```text
launch 中 anti_slosh_path_post_processor 与 slosh observer 必须读同一份
oscrs_container.yaml；
若任一侧仍硬编码 omega_n=31.25 / height_coeff=经验值，必须迁移到 yaml。
```

通过条件（任一不满足直接 BLOCK Step 0）：

```text
1. 离线脚本读 oscrs_container.yaml 重算 omega_n,
   与当前 slosh observer 在线 omega_n 差距 < 1%；
2. 用 RAW_TUNED 五包数据，rollout 出的 h_total(t) 与 /slosh/height(t)
   在 tracking 段内 Spearman ρ ≥ 0.5；
3. 若不满足，先调 zeta（先固定 omega_n）让 ρ ≥ 0.5 再继续；
   仍不满足则 BLOCK，转入观测器/容器参数复检。
```

理由：

```text
当前 /slosh/height 是模型估计；slosh rollout 也用同族模型。
两者本应高度一致 —— 如果不一致，说明参数硬编码不齐或模型分支已分岔，
不解决会让所有后续 PASS/SATURATED/FAIL 判据失效。
```

## 2. 为什么不是继续 slosh-score

当前 slosh-score 的问题：

```text
1. 只有 weighted score，没有 eta_lim 语义。
2. 权重会把 h / eta_dot / ay 相互交易，无法给出安全约束。
3. 已有 hscore_total x3 没有让 /slosh/height 优于 geometry-only GeoRef。
4. 继续调 w_h / w_E / w_ay 是低收益调参，不是 RA-L 方法贡献。
```

OSCRS 的改法：

```text
先用 Ferrari 式 hard constraint 建立 feasibility；
再在可行集合中选择代价最低候选。
```

即：

```text
score is not the safety mechanism;
hard gate is the safety mechanism.
```

## 3. 第一阶段：Step 0 离线诊断

```text

```

如果不存在，OSCRS 在线接入没有意义，应先扩 candidate generator 或只做论文分析。

`time_proxy` 显式定义：

```text

v_floor 与 prediction/v_init 一致下限不低于 0.05 m/s。
```

`spearman_rho_pred_vs_obs`：rollout 内部 dt 序列下 h_total_pred(t) 与同步重采样
的 /slosh/height(t) 的 Spearman 相关，验证模型方向一致性（用于 §1.5 通过条件 2）。

### 3.4 Step 0 判据

判据分两层。第一层检查模型自洽（前置过 §1.5 后通常已满足）；第二层检查
candidate 集合内是否存在 slosh-feasible 优势候选。

第一层（模型一致性，FAIL fast）：

```text
若多于 30% 的 (bag, candidate) 行 spearman_rho_pred_vs_obs < 0.5，
直接 FAIL，回到 §1.5 重新标定，不进入第二层。
```

第二层（候选可行性，三分支）：

```text
PASS:
  open_user_goal 五包中至少 4 包出现:
    (a) 存在 ≥1 个非 original candidate 同时通过 geom + height + residual gate；
    (b) 该候选 predicted h_p95 < geometry-only selected 的 h_p95 至少 5%；
    (c) eta_lim ∈ {20, 25, 30} mm 中至少两档同时满足 (a)(b)。
  open_goal_b 至少 2 包独立复现 (a)(b) 任一。

SATURATED:
  (a) 满足但 (b) 不满足，
  即 OSCRS 能找到 slosh-feasible candidate，但相对 geometry-only 改进 < 5%；
  或 (b) 满足但只在 eta_lim=30 mm 一个最宽档下成立。

FAIL:
  (a) 在多数包中不成立，
  即所有非 original 都被 height/residual gate 淘汰；
  或 predicted h 排序与闭环排序系统反向（Spearman ρ ≤ 0）。
```

各分支的具体下一步动作：

```text
PASS → 进入 Step 1 (§4)，OSCRS_ACTIVE 可作为正式平行线：
  1. 锁定通过的 eta_lim 值进 launch 默认；
  2. 开启 GEOREF_OSCRS_SHADOW，确认 shadow 不改变 GEOREF_TUNED 行为；
  3. 开启 GEOREF_OSCRS_ACTIVE，跑 1 包 smoke 验证 fallback 路径正确；
  4. 跑 GEOREF_OSCRS_ACTIVE x3/x5 闭环；
  5. 与 GEOREF_TUNED 三方对比，进入 §5。

SATURATED → 论文形态调整：
  1. 论文 contribution 重排：C1 (η_lim 安全保证) 主、C3 (failure-informed) 次,
     C2 (统一 predictor) 退化为 method 章节支撑；
  2. 仿真扩到 ≥6 个 open 场景（含 long_path、obstacle_pair）做 robustness sweep；
  3. 仍允许开发 Step 1，但必须先以 GEOREF_OSCRS_SHADOW 证明不会误判；
  4. GEOREF_OSCRS_ACTIVE 只能作为平行线进入仿真/实物对比，不能替代 GEOREF_TUNED；
  5. 投稿目标降级评估（IROS / ICRA 仍可，RA-L 可投但说服力下降）。

FAIL → 模型/候选先修：
  1. 检查 candidate generator 输出多样性（mild/medium/strong κ 分布是否真的覆盖低端）；
  2. 用 Ferrari 式 (3) 试算 zeta_physics 与默认 0.05 的差距，作为 ablation；
  3. 若 zeta 修正不能让 ρ 上升，转向观测器侧排查 height_coeff 是否分支；
  4. 若仍失败，转向"加入 width-inflated B-spline candidate"扩 generator;
  5. 6 周内不能让 Step 0 至少达到 SATURATED，则 OSCRS 仅保留为离线分析，
     回到 GEOREF_TUNED + 实物验证。
```

```yaml
  eta_p95_lim_mm: 20.0      # 仅在 ablation 中启用，主线只用 eta_lim_mm 单门槛

  fallback_to_geometry: true
```

参数依据：

```text
eta_lim_mm = 25:
  当前容器内净空 ≈ 30-40 mm（与杯口与液面距离）；
  Ferrari 论文用 15 mm 对应 h=40mm 容器；
  Scout 容器净空更大，η_lim 取 25 mm 给出 80% 安全裕度。
  Step 0 五包扫描确认该值可行后锁定，不再在线调。

eta_p95_lim_mm:
  默认 20 mm。第一版主线只用 eta_lim 单门槛（与 Ferrari 一致），
  eta_p95_lim 仅在 §5 ablation 中扫描，避免双门槛同时开导致 Hard gate 过严。

residual_ratio = 0.2:
  Ferrari 式(19f) 同值，便于直接对照。
  Scout 上若 SATURATED，可在 ablation 扫到 0.3 / 0.4 看候选 pass-rate 变化。

settle_duration = 2.0s:
  Ferrari 用 0.25 t_end，open_user_goal 当前 t_end ≈ 9.5 s 给 2.4 s；
  取 2.0 s 略保守且整数便于复算。
  在 §6 oracle 与 settle_duration 对照 ablation。

rollout_dt = 0.05s:
  与 /slosh/height 默认发布频率 20 Hz 一致；
  避免 rollout-vs-observed 两条曲线时间步不齐造成 ρ 计算偏差。

rollout_scheme = rk2:
  线性二阶系统首选半隐式或 RK2；
  显式 Euler 在 ω_n ≈ 31 时 dt=0.05s 接近临界，可能不稳；
  ablation 中比较 rk2 vs semi_implicit 选稳定项。
```

### 4.3.1 Rollout 数值口径

时域 ODE，ds 序列与 dt 序列衔接：

```text
对 candidate (s_i, v_i, ax_i, ay_i)：
  dt_i = ds_i / max(v_i, v_floor)
  累计 t_i = sum_{k≤i} dt_k
  在固定 dt = rollout_dt = 0.05 s 上重采样 ax(t), ay(t)
  时域 ODE 用 RK2 / 半隐式积分:
    eta_x(t) / eta_y(t) / eta_dot(t)
    h_modal(t) = height_coeff * sqrt(eta_x^2 + eta_y^2)
    h_parabola(t) = R^2 * omega(t)^2 / (4g)         若 use_parabola_term=true
    h_total(t) = h_modal(t) + h_parabola(t)

t > t_end 段（settle）:
  ax = ay = 0
  仍按 dt = rollout_dt 积分 settle_duration 长度
  得到 h_residual_max = max_{t ∈ [t_end, t_end+settle_duration]} h_total(t)
```

### 4.4 Hard gate 顺序

候选检查顺序：

```text
1. original 特殊处理：
   original 不做 collision 自检（假定 MBF 已安全）。
   但 original 仍参加 slosh hard gate —— 否则 fallback 链断了。

2. geometry gate (non-original)：
   endpoint
   length_ratio
   max_drift
   direction
   collision

3. rollout (所有候选，包括 original)：
   v_rollout
   ax / ay / omega / omega_dot
   h_total(t)
   residual h_total(t > t_end)

4. slosh hard gate：
   h_max_pred       <= eta_lim
   h_residual_max   <= residual_ratio * eta_lim
   eta_p95_lim 仅 ablation 启用，第一版主线只看 h_max + residual。
```

集合分类与 fallback 优先级：

```text
S_full   = {non-original candidates 通过 geom + slosh hard gate}
S_height = {non-original candidates 通过 geom，但只通过 slosh hard gate 的 h_max}
S_geom   = {non-original candidates 通过 geom 但 slosh gate 失败}
S_original = {original，仅判 slosh gate}

selection 优先级:

  case 1: |S_full| >= min_feasible_count
    → 在 S_full 内按 §4.5 score 选最优 candidate;
       fallback_code = 0；

  case 2: 0 < |S_full| < min_feasible_count
    → 在 S_full 内按 score 选；同时记录 oscrs_marginal=1;
       fallback_code = 0;
       不视为 fallback，但置位边缘 flag 以便 §5.2 监控;

  case 3: |S_full| = 0 且 original 通过 slosh gate
    → 选 original；
       fallback_code = 1（slosh-safe fallback）；

  case 4: |S_full| = 0 且 original 不通过 slosh gate
       但 |S_geom| > 0
    → 在 S_geom 内按 violation 最小者选；
       fallback_code = 2（violation-min fallback，方法不可保证安全）；
       发布 SAFETY_ALARM 日志一次；

  case 5: 全部失败
    → 选 geometry-only 现有 selected；
       fallback_code = 3（退化到旧策略）；
       发布 SAFETY_ALARM 日志一次。
```

violation 聚合公式（与 §3.3 字段一致）：

```text
violation = max(0, h_max_pred / eta_lim - 1)
          + max(0, h_residual_max / (residual_ratio * eta_lim) - 1)
          + 0.2 * max(0, time_proxy / (1.15 * t_proxy_raw) - 1)
```

`SAFETY_ALARM` 是 ROS_WARN 一次性日志（不刷屏），同时在 candidate_report
中置位 fb=2 / fb=3，便于离线复盘。

理由：

```text
S_geom violation-min 的 case 4 是为了不让 OSCRS 在边界 case 一律退回
geometry-only —— 那等于 OSCRS 没接入。
但 case 4 必须发出 SAFETY_ALARM,
论文 limitation 段明确写出 "OSCRS by-construction 仅在 case 1/2 成立"。
```

### 4.5 Score 只用于可行集合内部

Score 不参与 safety 判定。Hard gate 已经把不安全候选淘汰；
score 只在 |S_full| ≥ 2 时决定"在多个 slosh-feasible 候选中选哪个最优"。

可行候选内的 score（越小越好）：

```text
score =
  w_time     * time_proxy_norm
+ w_h_margin * height_margin_norm
+ w_residual * residual_margin_norm
+ w_geo      * geometry_penalty_norm
```

各项定义：

```text
time_proxy_norm        = time_proxy / max_j(time_proxy_j)
height_margin_norm     = (h_max_pred / eta_lim) / max_j(...)
residual_margin_norm   = (h_residual_max / (residual_ratio * eta_lim)) / max_j(...)
geometry_penalty_norm  = (kappa_p95 / max_j(kappa_p95)
                          + 0.5 * length_ratio_excess / max_j(...))
                         / 1.5
```

`max_j` 在当前规划周期 S_full 内取（**batch 内归一化**），不跨周期；
单候选 batch 时 score 退化为常数，由 case 1/2 直接选该候选。

第一版默认权重：

```text
w_time     = 1.0     # 时间最优是首要 secondary 目标
w_h_margin = 0.5     # 鼓励"远离 eta_lim"的候选
w_residual = 0.5     # 鼓励"残振余地大"
w_geo      = 0.2     # 几何平滑作弱平衡项，防长且过平滑
```

边界：

```text
1. score 公式不参与 PASS/SATURATED/FAIL 判定；
2. 权重不调，只在论文 ablation 章节展示一次 sensitivity (±50%)；
3. 出现 score 主导决策但 hard gate 边缘的情况（case 2 marginal），
   候选选择以 score 为准，但 candidate_report 必须置 oscrs_marginal=1。
```

## 6. 第四阶段：Ferrari offline oracle

RA-L 加分项，不阻塞 OSCRS 主实现。

### 6.1 目标与定位

```text
对同一条 raw path r(s)，求 motion law s(t) 使
  J = int_0^t_end (1 + k jerk^2) dt 最小,
  s.t. slosh hard constraints + Scout 动力学约束。

输出:
  offline optimal v(t), tracking_time_oracle, h_max_oracle
论文用途:
  "OSCRS recovers X% of the offline-NLP-oracle's η-compliance margin
   at four-orders-of-magnitude lower compute cost."
```

### 6.2 Scout 形式与 Ferrari 的差异处理

```text
Ferrari: 6-DOF SCARA, 路径 r(s) ∈ R^3, θ(s) 是独立可选 (式17 取线性)。
Scout:   2D differential drive, 路径 (x(s), y(s)) 在地面平面,
         θ(s) 必须等于 path tangent atan2(dy/ds, dx/ds),
         即 θ 不是独立优化变量 —— 这是与 Ferrari 的硬性差异。
```

oracle 形式：

```text
变量:    s(t), 控制 u = s_dddot
状态:    [s, s_dot, s_ddot, eta_x, eta_y, eta_dot_x, eta_dot_y]   (7 状态)
动力学:  s_ddot 来自 u 三阶链;
         eta_x/y 来自 §4.3.1 同一组 ODE，输入 ax/ay 由
           ax(s_dot, s_ddot) = s_ddot * t_hat - s_dot^2 * kappa(s) * 0    (沿切向)
           ay(s_dot, s_ddot) = s_dot^2 * kappa(s)                          (向心)
         (注意 Scout 是非完整约束，无侧向 a_x 自由度，
          这与 Ferrari §III-A 的 r(s) 在 R^3 自由对应不同。)
约束:
  h_total(t) <= eta_lim
  h_total(t > t_end) <= 0.2 * eta_lim   (settle 段同 §4.3 t_settle=2s)
  0 <= s_dot <= v_max
  |s_ddot| <= a_max
  |u| <= jerk_max
  s(0) = 0, s(t_end) = L_path
  s_dot(0) = s_dot(t_end) = 0
```

### 6.3 求解器与实现

```text
方案 A: CasADi + IPOPT (Ferrari 原口径)
  优点：与 Ferrari 完全可比，paper writing 直接引用其 setup。
  缺点：装环境/写 multiple-shooting 需 1-2 周。

方案 B: scipy 等价 trajopt (Python 原生)
  优点：无外部依赖。
  缺点：收敛性弱于 IPOPT，dense problem 仅 100-150 节点。

推荐方案 A，时间预算 3-4 周。
节点数从 Ferrari 默认 151 起步。
```

### 6.4 输出对接

```text
oracle 输出 v(t) -> 用 fakeOdom 或 record_replay 在仿真重放，
录 RAW topic chain (不进 GeoRef，不进 OSCRS) 一包,
归类为新 condition: ORACLE_REPLAY x3。
该包指标进 §8 主表第六列，与 OSCRS 直接比 h_max / tracking_time。
```

### 6.5 延期处置

```text

  1. 把 §8 主表 oracle 列改为 "non-converged within 3000 iter (CasADi/IPOPT)"
     作为 limitation 章节材料 —— 这本身就是 Ferrari NLP 在 nonholonomic 移动底盘
```

## 1. 一句话定义

OSCRS（Online Slosh-Constrained Reference Selection）是一个放在全局路径和 MPC tracking 之间的在线参考选择层：

```text
MBF raw global path
        ↓
GeoRef candidate generator
        ↓
OSCRS slosh rollout + hard gate + score
        ↓
selected low-slosh reference path
        ↓
normal MPC tracking
```

它不是新的 MPC，不是在线液面反馈控制器，也不是连续轨迹优化器。它的核心功能是：在有限个几何候选路径中，用液体模态模型预测每条路径的晃动风险，先排除违反晃动高度/残振约束的候选，再在可行候选中选一个综合风险最低的参考路径。

## 2. 在系统中的位置

当前系统中有三条可对比路线：

```text
RAW:
  MBF raw path → normal MPC

GEOREF_TUNED:
  MBF raw path → geometry-only GeoRef selection → normal MPC

GEOREF_OSCRS_ACTIVE:
  MBF raw path → same GeoRef candidates → OSCRS selection → normal MPC
```

三条线的 MPC 必须保持一致：

```text
Q_slosh = 0
Q_slosh_eta_dot = 0
no PMG
no OUTPUT_GUARD
no energy_profile
no input_shaping
no reference-constrained MPC
```

因此，RAW / GEOREF_TUNED / OSCRS 的唯一核心差异是进入 MPC 的参考路径不同。这样实验结果才能归因到“参考生成/选择层”，而不是 MPC 参数或后处理器差异。

## 3. 数学问题形式化

设 MBF 给出的原始全局路径为：

```text
P0 = {p0, p1, ..., pM},   pj = (xj, yj)
```

GeoRef candidate generator 从 `P0` 生成有限候选集合：

```text
C = {c0, c1, ..., cN}
```

其中：

```text
c0 = original
c1...cN = mild / medium / mid / strong 等平滑候选
```

每条候选路径按弧长参数化：

```text
ci(s) = [xi(s), yi(s)]ᵀ,   s ∈ [0, Li]
```

OSCRS 要解决的是有限集合选择问题：

```text
choose c* ∈ C
```

使得：

```text
1. c* 满足几何可行性；
2. c* 满足预测晃动高度和末端残振约束；
3. 在可行候选中，c* 的综合 slosh/geometry score 最小。
```

这不是连续最优控制问题，而是 finite candidate constrained selection。

## 4. 候选路径到车辆激励的映射

对每条候选路径，先计算几何量：

```text
κ(s)      = path curvature
dκ/ds     = curvature derivative
```

再用前向速度 rollout 近似路径执行速度。当前工程第一版没有优化速度，只用统一的速度上界、横向加速度预算和纵向加速度预算生成一个可比的 proxy：

```text
v0 = min(v_init, v_max)

v_curv,k  = sqrt(ay_budget / max(|κk|, ε))
v_accel,k = sqrt(vk-1² + 2 a_max Δs)

vk = min(v_max, v_curv,k, v_accel,k)
```

由此得到车辆局部激励：

```text
ax,k = (vk² - vk-1²) / (2 Δs)
ωk   = vk κk
αk   = ax,k κk + vk² (dκ/ds)k
ay,k = vk² κk
```

如果容器中心相对车辆 yaw 轴有偏置 `(ox, oy)`，则容器中心等效激励为：

```text
ax_eff = ax - α oy - ω² ox
ay_eff = ay + α ox - ω² oy
```

当前默认 `ox=0, oy=0`，即容器中心与 yaw 轴重合。

## 5. 晃动模态 rollout

OSCRS 使用一阶线性模态模型预测液体广义坐标：

```text
η̈x + 2ζωn η̇x + ωn² ηx = -ax_eff
η̈y + 2ζωn η̇y + ωn² ηy = -ay_eff
```

当前在线实现采用：

```text
ωn = 31.25 rad/s
ζ  = 0.05
dt = 0.05 s
semi-implicit Euler
initial state = 0
```

路径执行段结束后，OSCRS 会追加零输入自由衰减段：

```text
T_settle = 2.0 s
ax_eff = 0
ay_eff = 0
```

这段不是控制动作，只用于预测“车停下后液体剩余能量是否仍会造成超限”。

## 6. 液面高度和能量指标

模态高度项：

```text
h_modal = ch sqrt(ηx² + ηy²)
```

当前在线 OSCRS 默认采用与 `/slosh/height` 观测器一致的 `observer_linear` 系数：

```text
ch = 4 h mn / (mF R)
```

Ferrari 闭式高度系数：

```text
ch,Ferrari = ξ² h mn / (mF R)
```

目前 Ferrari 闭式只建议用于离线 ablation，不直接改在线观测器口径，避免破坏 GEOREF_TUNED 主线。

可选离心抛物面项：

```text
h_parabola = ω² R² / (4g)
```

总预测高度：

```text
h_total = h_modal + h_parabola
```

模态能量：

```text
E = ωn²(ηx² + ηy²) + η̇x² + η̇y²
```

OSCRS 当前主要记录：

```text
h_p95        = tracking 段 h_total 的 95 分位数
h_max        = tracking 段 h_total 最大值
h_residual   = settle 段 h_total 最大值
eta_dot_rms  = sqrt(mean(η̇x² + η̇y²))
energy_rms   = sqrt(mean(E²))
terminal_E   = motion-end 的 E
```

注意：`terminal_E` 是车辆运动结束瞬间的能量，不是 2 秒自由衰减结束后的能量。原因是 residual gate 已经约束了自由衰减段是否越界，`terminal_E` 更能反映“停车时还剩多少待消散能量”。

## 7. Layer 1：硬约束 gate

每条候选首先经过几何 gate：

```text
endpoint error
path length ratio
max drift
direction preservation
collision / costmap check
predicted ay ratio
```

通过几何 gate 后，再经过 OSCRS slosh hard gate：

```text
h_max <= η_lim
h_residual <= residual_ratio · η_lim
```

当前默认：

```text
η_lim = 25 mm
residual_ratio = 0.2
residual limit = 5 mm
```

定义非原始可行集合：

```text
S_full = { ci ∈ C | ci != original,
                  geometry_pass(ci),
                  h_max(ci) <= η_lim,
                  h_residual(ci) <= residual_ratio · η_lim }
```

这里特意把 `original` 排除在 `S_full` 外。原因是 OSCRS 的 takeover 语义要清楚：只有选择了非原始且通过 gate 的候选，才算 OSCRS 真正改变了参考路径。

## 8. Layer 2：批内归一化 score

若 `S_full` 非空，OSCRS 在 `S_full` 内做加权评分。

对每个指标做 batch normalization：

```text
Nq(ci) = q(ci) / max(cj ∈ S_full) q(cj)
```

当前 score：

```text
J(ci) =
  wh   N(h_p95)
+ wE   N(energy_rms)
+ wd   N(eta_dot_rms)
+ wT   N(terminal_E)
+ wg   N(geometry_score)
```

默认权重：

```text
wh = 1.0
wE = 0.3
wd = 0.3
wT = 0.2
wg = 0.2
```

选择规则：

```text
c* = argmin ci∈S_full J(ci)
```

如果 `S_full` 为空，则 OSCRS 不强行选择不可行候选，而是回退到 geometry-best 路径，并在 `candidate_report` / `safety_alarm` 中暴露原因。

## 9. Fallback 语义

`candidate_report` 中的 `fb` 不是错误码，而是 OSCRS 当前决策状态：

```text
fb = 0:
  OSCRS 选中了非 original 且通过 hard gate 的候选。
  这是 OSCRS 有效接管 candidate selection 的唯一干净状态。

fb = 1:
  original 本身 slosh-safe，但没有非 original 候选通过完整 gate。

fb = 2:
  存在几何候选，但 slosh hard gate 失败。

fb = 3:
  没有可用几何候选，基本回退原路径。

fb = -1:
  OSCRS shadow/active 未启用。
```

`takeover=1` 的含义更窄：

```text
active_enable = true
oscrs_best exists
oscrs_best feasible
published path == oscrs_best
oscrs_best != geometry_best
```

论文中如果要证明 OSCRS 相比 geometry-only GeoRef 有额外作用，应该优先统计 `takeover=1` 的包或片段，而不是只看 `oscrs_active_enable=1`。

## 10. 数学性质

### 10.1 有限候选最优性

OSCRS 只在候选集合 `C` 内最优：

```text
c* = argmin over S_full
```

它不保证全局最优路径，也不保证存在真正 slosh-free trajectory。候选生成器没生成出来的路径，OSCRS 不可能选到。

### 10.2 模型条件安全性

若 `fb=0`，则在当前 rollout 模型和当前阈值下：

```text
h_max(c*) <= η_lim
h_residual(c*) <= residual_ratio · η_lim
```

这是模型条件保证，不是真实液面物理保证。实际液面仍受以下因素影响：

```text
ωn / ζ / height_coeff 误差
高阶模态
液面非线性
传感器噪声
底盘执行偏差
MPC tracking 偏差
地图/定位误差
```

因此实物论文表述应该写：

```text
model-predicted slosh constraint satisfaction
```

不要写：

```text
guaranteed spill-free control
```

### 10.3 Score 的尺度不变性

批内归一化使 score 对不同物理量纲不敏感：

```text
h_p95, energy_rms, eta_dot_rms, terminal_E, geometry_score
```

可以被放进同一加权和。

但代价是：

```text
J(ci) 只适合同一 planning cycle 内比较；
不同 cycle 之间的 J 数值不直接可比。
```

所以论文中不要拿不同场景的 `osc` 绝对值比较，只比较同一候选批里的排序和最终闭环指标。

### 10.4 Hard gate 优先于 score

OSCRS 的安全语义来自 hard gate，不来自 score。

也就是说：

```text
score 不能把一个违反 h_max 或 residual 的候选“交易”成可接受。
```

这点比旧 slosh-score 更清楚。旧 slosh-score 只是 weighted cost，可能用较好的几何分数抵消较差的晃动指标；OSCRS 先判可行，再排序。

### 10.5 残振约束的 rest-to-rest 近似

Ferrari 类方法强调路径结束后的 residual slosh。OSCRS 的残振 gate：

```text
h_residual <= residual_ratio · η_lim
```

是 rest-to-rest 思想的弱化版本：

```text
不是强制 η(tf)=0, η̇(tf)=0；
而是要求车辆停止后的自由响应峰值足够小。
```

它工程上比完整 rest-to-rest trajectory optimization 轻量，但数学保证也更弱。

### 10.6 与 MPC 解耦

OSCRS 不改变 MPC 代价函数和约束矩阵。MPC 仍然只是 constrained tracker：

```text
selected reference path → MPC tracking → /cmd_vel
```

因此 OSCRS 的数学问题和 MPC 求解问题是解耦的。优点是工程风险低、归因清楚；缺点是不能保证底盘真实执行完全等于 OSCRS rollout 使用的 proxy `v(s)`。

## 11. 与 Ferrari / Muchacho 路线的关系

### 11.1 与 Ferrari 的关系

Ferrari 2026 更接近：

```text
given assigned path
optimize motion law s(t)
subject to slosh height constraints
```

OSCRS 当前更接近：

```text
given MBF path
generate finite geometry candidates
predict each candidate's slosh height
select a feasible low-risk reference
```

共同点：

```text
1. 都把防晃放在 reference / trajectory generation 层；
2. 都使用 slosh-height model；
3. 都强调 height constraint / residual slosh，而不是 MPC soft cost。
```

差异：

```text
1. Ferrari 是连续优化，OSCRS 是有限候选选择；
2. Ferrari 优化 motion law，当前 OSCRS 第一版只选路径，不发布速度 profile；
3. Ferrari 可作为离线 oracle，OSCRS 是在线工程层；
4. Ferrari 的目标更强，OSCRS 的实时性和 ROS/MBF 适配更强。
```

### 11.2 与 Muchacho 的关系

Muchacho 类 slosh-free trajectory optimization 直接生成满足防晃结构的机器人轨迹。OSCRS 不直接求全局 slosh-free trajectory，而是在现有移动机器人导航链路中插入参考后处理层。

对 Scout `/cmd_vel=[v,ω]` 平台，这种处理更现实：

```text
不要求重写全局规划器；
不要求 torque-level controller；
不要求机械臂末端姿态自由度；
只要求 MPC 能跟踪被选中的低激励参考路径。
```

## 12. 论文中可以这样描述贡献

推荐表述：

```text
We propose an online slosh-constrained reference selection layer for liquid-carrying mobile robot navigation. Given a global path, the method generates a finite set of geometry-preserving candidate references, predicts their slosh response using a first-mode modal model, rejects candidates violating predicted height and residual-slosh constraints, and selects the minimum-risk feasible reference for a standard MPC tracker.
```

中文：

```text
本文提出一种在线晃动高度约束参考选择方法。该方法在全局路径与局部 MPC tracking 之间生成有限个几何候选参考，利用一阶液体模态模型预测候选路径的液面高度和残余晃动，先剔除违反高度/残振约束的候选，再选择综合晃动风险最低的可行参考路径供普通 MPC 跟踪。
```

可以强调：

```text
1. reference-first，而不是 MPC soft-cost-first；
2. hard gate before score；
3. geometry-only GeoRef 与 OSCRS 的平行对比；
4. takeover / fallback 语义可诊断；
5. 与 Ferrari 路线一致但适配 ROS/MBF/Scout 差速底盘。
```

不要强调：

```text
1. 首次提出 anti-slosh path planning；
2. 证明全局 slosh-free；
3. 实时液面闭环控制；
4. MPC 主动消晃；
5. 任意地图/任意轨迹已保证。
```

## 15. 当前边界

当前 OSCRS 已经是工程落地的在线参考选择器，但仍有明确边界：

```text
1. 第一版只选路径，不生成 time-optimal s(t)；
2. rollout 使用一阶线性模态，不是完整非线性流体模型；
3. initial slosh state 当前按零初值预测，不是实时液面闭环；
4. height_coeff 在线默认对齐 observer_linear，不强制切 Ferrari closed-form；
5. score 在 S_full 内归一化，不能跨场景比较绝对值；
6. OSCRS 是否优于 GEOREF_TUNED 必须由实物 RAW / GEOREF / OSCRS 三线对比判断。
```

因此，最稳妥的论文定位是：

```text
OSCRS is an online, model-guided, slosh-constrained reference selection layer,
not a globally optimal slosh-free trajectory planner.
```

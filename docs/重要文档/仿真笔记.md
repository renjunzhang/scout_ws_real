# 仿真笔记

## 1. 当前目标

当前仿真主线不是完整复刻实物液面视觉，而是建立一条稳定、可重复、可录 bag 的 anti-slosh MPC 验证链路：

1. 使用官方 AgileX Scout Mini Gazebo 底盘。
2. 使用本项目 bridge 层统一 `/scan_front`、`/imu/data`、`/odom`、`/tf`。
3. 使用 Cartographer 建图/定位。
4. 使用 MBF 全局规划 + `scout_local_planner` 局部 MPC。
5. 在开阔场地录制 bag，用 `/slosh/height`、轨迹、MPC 状态分析改进效果。

当前推荐场景是：

- world: `/home/a/scout_ws/src/scout_ros/scout_description/worlds/open_walled.world`
- map: `/home/a/scout_ws/src/scout_apps/scout_maps/maps/map_sim_empty.pbstream`

旧迷宫场景仍可保留用于回归：

- world: `/home/a/scout_ws/src/scout_ros/scout_description/worlds/maze_course.world`
- map: `/home/a/scout_ws/src/scout_apps/scout_maps/maps/map_carto.pbstream`

## 3. 推荐启动方式

### 3.1 一键启动导航骨架

脚本：

```text
/home/a/scout_ws/src/scout_apps/control/scout_local_planner/scripts/launch_sim_nav_stack.sh
```

脚本会启动：

- Gazebo + 官方 Scout Mini bridge
- Cartographer localization sim
- MBF global planner sim

局部 MPC 仍单独启动。

开阔场地：

```bash
source /home/a/scout_ws/devel/setup.bash
SIM_ENV=open USE_RVIZ=true \
SPAWN_X=0.0 SPAWN_Y=0.0 SPAWN_Z=0.1 SPAWN_YAW=0.0 \
rosrun scout_local_planner launch_sim_nav_stack.sh
```

旧迷宫场地：

```bash
source /home/a/scout_ws/devel/setup.bash
SIM_ENV=maze USE_RVIZ=true \
rosrun scout_local_planner launch_sim_nav_stack.sh
```

手动指定 world 和 map：

```bash
source /home/a/scout_ws/devel/setup.bash
SIM_ENV=custom USE_RVIZ=true \
WORLD_NAME=/home/a/scout_ws/src/scout_ros/scout_description/worlds/open_walled.world \
MAP_FILE=/home/a/scout_ws/src/scout_apps/scout_maps/maps/map_sim_empty.pbstream \
SPAWN_X=0.0 SPAWN_Y=0.0 SPAWN_Z=0.1 SPAWN_YAW=0.0 \
rosrun scout_local_planner launch_sim_nav_stack.sh
```

说明：

- `SIM_ENV=open` 是当前推荐默认。
- `WORLD_NAME` 和 `MAP_FILE` 会覆盖 `SIM_ENV` 默认值。
- 脚本默认 `SPAWN_WHEEL_CONTROLLERS=false`，即关闭四个 wheel velocity controller，只保留 `scout_state_controller`。
- 脚本默认 `ENABLE_ODOM_TF_BRIDGE=false`；定位模式下由 Cartographer 发布 `map -> odom -> base_footprint`，避免重复 TF。
- 保留 `scout_state_controller` 是为了发布 `/joint_states`，否则 RViz RobotModel 会缺轮子关节状态。

### 3.2 启动局部 MPC

基础固定 Q 仿真：

```bash
roslaunch scout_local_planner slosh_experiment_sim.launch \
  Q_slosh:=5 \
  risk_scheduler_enable:=false \
  input_shaping_enable:=false \
  enable_slosh_box_constraint:=false \
  slosh_speed_governor_enable:=false
```

后续做结构改进验证时，再逐项打开 scheduler、input shaping 或 box constraint，避免多个变量同时变化。

## 4. 建图流程

### 4.1 启动开阔世界底盘

```bash
source /home/a/scout_ws/devel/setup.bash

roslaunch scout_description scout_mini_true_empty_bridge.launch \
  world_name:=/home/a/scout_ws/src/scout_ros/scout_description/worlds/open_walled.world \
  gui:=true \
  x:=0.0 y:=0.0 z:=0.1 yaw:=0.0 \
  enable_odom_tf_bridge:=true \
  spawn_wheel_controllers:=false
```

说明：

- `enable_odom_tf_bridge:=true` 只用于建图流程，给 Cartographer 建图提供 `odom -> base_footprint`。
- `spawn_wheel_controllers:=false` 避免四个 wheel velocity controller 和官方 skid-steer 插件抢轮子。
- 关闭 wheel velocity controllers 时仍会启动 `scout_state_controller`，保证 `/joint_states` 和 RobotModel 正常。

### 4.2 启动 Cartographer 建图

```bash
source /home/a/scout_ws/devel/setup.bash
source /home/a/scout_ws/src/scout_apps/sensors/cartographer_ws/install_isolated/setup.bash

roslaunch nanoscan3_mapping scout_nanoscan3_cartographer_sim.launch
```

当前建图配置：

- `scout_2d_sim.lua` 中 `use_odometry = true`
- Cartographer 订阅 `/scan_front`
- `/odom` 先经过 `odom_monotonic_relay.py` 过滤为 `/odom_carto`
- Cartographer 实际订阅 `/odom_carto`

这样既保留 odom 约束，又避免重复时间戳触发：

```text
map_by_time.h:43 Check failed: data.time > std::prev(...)
```

### 4.3 建图运动建议

不要长时间原地高速自转。Scout Mini 是四轮 skid-steer，原地自转必须横向滑移，Gazebo 会有轻微 stick-slip 抖动。

推荐建图运动：

```bash
roslaunch scout_bringup scout_teleop_keyboard.launch
```

或用小半径圆弧：

```bash
rostopic pub -r 20 /cmd_vel geometry_msgs/Twist \
"{linear: {x: 0.12, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.3}}"
```

## 5. 关键话题

当前仿真链关键话题：

- `/scan_front`：2D 激光，由 bridge 从 `/scan` relay。
- `/imu/data_raw`：Gazebo IMU plugin 原始输出。
- `/imu/data`：经 `imu_frame_relay.py` 统一 frame 后输出。
- `/odom`：官方 Gazebo skid-steer 插件输出。
- `/odom_carto`：`odom_monotonic_relay.py` 过滤后的 Cartographer odom 输入。
- `/joint_states`：`scout_state_controller` 输出，RViz RobotModel 需要。
- `/cmd_vel`：底盘速度命令。
- `/risk_scheduler/*`：risk scheduler 状态。
- `/slosh/*`：晃动估计与 anti-slosh 相关信号。

不要再单独启动：

```bash
roslaunch nanoscan3_bringup nanoscan3_front_sim.launch use_rviz:=false
```

原因：`scout_mini_true_empty_bridge.launch` 已经提供 `/scan -> /scan_front` relay 和相关 TF，重复启动会造成话题/TF 混乱。

## 6. 关键 TF

目标 TF 链：

```text
map -> odom -> base_footprint -> base_link -> laser_link -> nanoscan3_front
                                      |
                                      -> imu_link
                                      -> camera_link
```

当前角色：

- Cartographer localization 发布 `map -> odom`。
- `odom_tf_broadcaster.py` 可发布 `odom -> base_footprint`。
- `tf_footprint_base` 发布 `base_footprint -> base_link`。
- `robot_state_publisher` 发布 URDF 固定关节和轮子 link。
- `tf_front_alias` 发布 `laser_link -> nanoscan3_front`。

检查命令：

```bash
rosrun tf tf_echo odom base_link
rosrun tf tf_echo base_link nanoscan3_front
rostopic hz /joint_states
```

如果 RViz RobotModel 报错，优先检查：

```bash
rostopic info /joint_states
rostopic hz /joint_states
rosparam get /robot_description
```

`spawn_wheel_controllers:=false` 时，必须仍有 `scout_state_controller` 发布 `/joint_states`。

## 7. 已确认问题与处理

### 7.1 `/scan_front` 全是 `inf`

原因：

- 初版 `open_walled.world` 是 20m x 20m。
- 雷达 `range_max=8.0m`。
- 小车在中心时看不到墙。

处理：

- `open_walled.world` 改为 12m x 12m，墙在 `x/y = +/-6m`。

### 7.2 Cartographer 使用 `/odom` 会崩溃

典型报错：

```text
map_by_time.h:43 Check failed: data.time > std::prev(trajectory.end())->first
```

处理：

- 不关闭 odom 约束。
- 使用 `odom_monotonic_relay.py` 把 `/odom` 过滤为 `/odom_carto`。
- Cartographer 建图和定位都订阅 `/odom_carto`。

### 7.3 RobotModel 报错

原因：

- 关闭四个 wheel velocity controllers 时，如果连 `scout_state_controller` 也不启动，就没有 `/joint_states`。
- RViz RobotModel 的轮子连续关节需要 `/joint_states`。

处理：

- `spawn_wheel_controllers:=false` 时只启动 `scout_state_controller`。
- 不启动四个 `scout_motor_*_controller`。

### 7.4 自转轻微抖动

结论：

- 当前转向方向正常，不是 wheel axis 符号问题。
- 轻微抖动主要来自 Gazebo 四轮 skid-steer 接触模型。
- 不建议继续改 wheel axis。
- 不建议使用过重的 ODE 物理参数，实时因子会下降并导致速度体感变慢。

验证时建议：

- 避免把“原地自转是否完美”作为 MPC 结论。
- 重点看正常路径跟踪中的转弯响应。
- 建图和验证时优先用小半径圆弧，而不是长时间原地自转。

### 7.5 KDL root inertia warning

启动时可能出现：

```text
The root link base_link has an inertia specified in the URDF, but KDL does not support a root link with an inertia.
```

当前判断：

- 这是 RobotModel/KDL 的常见 warning。
- 不是 Gazebo 速度暴降或转向异常的主因。
- 暂不为这个 warning 改官方模型。

```text
+ 本地 bridge 层
+ open_walled.world / maze_course.world 可切换
+ Cartographer 建图/定位
+ MBF 全局规划

```

## 9. 后续建议

1. 默认使用 `SIM_ENV=open` 做 anti-slosh MPC 仿真验证。
2. 保留 `SIM_ENV=maze` 只做回归对照。
3. 不再单独启动 `nanoscan3_front_sim.launch`。
4. 不再修改 wheel axis。
5. Cartographer 保持 `use_odometry=true`，但通过 `/odom_carto` 输入。
6. 如果 TF 异常，优先查 `/joint_states`、`map -> odom`、`odom -> base_footprint` 是否齐全。
7. MPC 代码验证时必须录 bag，避免只凭 RViz 观感判断。

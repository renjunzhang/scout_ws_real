# Scout Mini 自主导航课题阶段梳理（实事求是版）

> 依据当前仓库中的开发文档、修改记录与已有代码结构整理。本文只陈述“已完成且有证据的工作”，并明确“仍未完成项”。

## 1. 研究课题及背景简介

### 1.1 课题目标
本课题面向 **AgileX Scout Mini 差速底盘**，构建一套可在“仿真 + 实物”运行的自主导航系统，核心创新点是：
- 在常规路径跟踪控制基础上，引入 **液体晃动抑制约束**；
- 采用 **Frenet 误差建模 + MPC 优化控制**，在路径跟踪与运动平稳性之间平衡。

### 1.2 工程背景与系统边界
当前系统以 ROS Noetic 为基础，集成了：
- 激光雷达感知（SICK nanoscan3）；
- Gmapping / Cartographer 建图与 AMCL / Cartographer 定位；
- move_base、MBF、自定义 A* 全局规划；
- 自研 MPC 局部规划（含液体晃动模型）。

换言之，本课题不是“单算法验证”，而是“从传感器到控制输出的可运行导航链路”。

## 2. 当前进展与阶段性成果

### 阶段 A：基础导航链路打通（已完成）
- 已形成实物与仿真的分步启动流程（底盘、雷达、建图/定位、全局规划、局部规划）。
- 已明确 TF 主链和关键话题，能够在 RViz 中观测地图、路径与控制结果。

**做到的程度**：
- 具备“可复现启动”的工程文档与命令级流程，能够支持重复调试。

### 阶段 B：MPC 局部规划器原型到可运行版本（基本完成）
- 已建立 `scout_local_planner` 包，完成节点化、参数化和 launch 集成。
- 已接入 OSQP（v0.6.2）并形成稀疏 QP 求解链路。
- 已实现与全局路径 `/scout/global_path` 的对接，并能稳定输出 `/cmd_vel`。
- 已做过一轮关键控制逻辑修复：
  - 控制增量代价跨步项修正；
  - lookahead/参考点更新逻辑修正；
  - 线性化名义轨迹逐步推进；
  - 路径时间戳刷新避免误停。
- **液体晃动抑制融入方式（当前实现口径）**：
  - 采用 **软约束优先** 的方式融入 MPC：将晃动状态（如 `η_x, η̇_x, η_y, η̇_y`）通过代价项加权惩罚，并可配合松弛变量避免 QP 不可行；
  - 不将晃动状态直接作为“必须满足”的硬边界主约束，以避免在高曲率/突变工况下因不可行而导致控制中断；
  - 对安全相关的速度、角速度、加速度边界仍保留硬约束（底盘物理与安全边界），形成“**安全硬约束 + 晃动软约束**”的组合策略。

**做到的程度**：
- 处于“可运行 + 可继续迭代优化”的状态，不再是纯框架或空壳。

### 阶段 C：液体晃动建模集成（已完成初步集成）
- 已建立 `slosh_models` 独立库并迁移原始晃动模型代码。
- 已在规划器设计中采用“增广状态”方式引入液体晃动相关状态量。

**做到的程度**：
- 已完成“模型接入”，但“抑制效果量化评估”尚未在文档中形成闭环结论。

### 阶段 D：全局规划多路线并行（已完成）
- 已可使用 move_base、MBF、自定义 simple_global_planner 三种全局规划路径来源。
- 已统一下游接口，面向局部规划器发布全局路径。

**做到的程度**：
- 具备多方案切换能力，为对比实验和鲁棒性调试提供了条件。

## 4. 目前存在的主要问题与瓶颈

### 4.1 算法层面瓶颈（核心）
- 当前版本虽可运行，但距离“高质量 MPC”仍有差距：
  - 速度规划 `v(s)`、时间参数化、路径预处理、求解失败恢复等能力仍在“计划/改进中”，并非全部落地为稳定版本；
  - 终端约束、线性化鲁棒性等高级控制细节仍需强化。

### 4.2 参数整定与可迁移性瓶颈
- 当前参数仍以经验调参为主，存在“同一参数在仿真可用、实车效果退化”的情况。
- 参数之间存在耦合（如速度上限、加速度约束、代价权重、lookahead 设置），单参数调整后往往需要联动回归测试。
- 缺少“参数版本 + 对应实验结果”的统一追踪机制，导致回溯困难、复现实验成本偏高。

### 4.3 实车验证深度不足
- 已有实物流程和若干调试记录，但尚未看到系统化、可量化的对比实验结果（如抑振效果指标、误差统计、成功率统计）。
- 因此目前更准确的定位是“工程可运行 + 功能可演示”，尚未到“实验结论充分”的阶段。
- 当前测试更偏“功能可跑通”，而非“统计显著性验证”：
  - 不同速度档位下的跟踪误差分布未形成统一统计；
  - 弯道、急停、狭窄通道等高风险工况覆盖不足；
  - 连续长时运行稳定性（漂移、累计误差、偶发失败率）记录不足。

### 4.4 液体晃动抑制的证据链仍不完整
- 已实现“晃动模型接入”，但“抑制收益”还缺少标准化评估闭环。
- 目前缺少一致的评价指标体系，例如：
  - 晃动状态峰值 / 均方值；
  - 恢复时间（扰动后回稳时间）；
  - 路径跟踪精度与抑振效果之间的权衡曲线。
- 尚未形成典型对照组（无抑振、弱抑振、强抑振）下的横向比较结论。

### 4.5 环境与依赖复杂度高
- Cartographer 需要独立工作空间和额外 source 顺序，环境管理复杂。
- OSQP 依赖安装和版本兼容有门槛，部署可重复性依赖文档执行质量。
- 编译链与运行链存在“对操作顺序敏感”的问题，一旦 source 顺序或编译白名单配置错误，容易出现隐蔽故障。
- 不同机器（工控机/开发机）上的依赖版本差异，可能导致“同代码不同表现”。

### 4.6 系统集成风险仍在
- 多套全局规划与多定位方案并存，灵活但也增加了参数耦合和排障成本。
- 话题、TF、参数文件在实物与仿真间存在差异，维护成本较高。
- 部分故障具有跨模块特征（定位抖动→路径异常→局部控制振荡），排障需要跨包联动分析，定位周期较长。
- 安全侧策略仍偏基础（更多依赖人工监看），异常工况下的自动降级与保护动作尚需强化。

### 4.7 工程化与交付层面瓶颈
- 目前文档较全，但“可一键复现实验”的自动化程度仍有限（启动编排、日志采集、结果汇总未完全自动化）。
- 缺少统一的数据资产管理：实验原始数据、处理脚本、图表输出与结论之间关联还不够紧密。
- 论文交付所需的“方法-实验-结论”证据链尚未完全闭合，尤其是统计显著性和泛化性说明。

6. **参数管理收敛**：仿真/实物参数差异可追踪、可解释，减少“经验调参黑箱”。

### P3（交付与论文导向）

## 7. 本学期科研计划（可执行版）

> 规划周期：2026年3月—2026年9月（以“论文投稿 + 实验闭环 + 系统可复现交付”为主线）。

### 7.1 本学期核心目标（量化）

1. **实验闭环目标（6月底前）**
   - 完成不少于 **60 组** 可复现实验（仿真 30 组 + 实车 30 组），覆盖直线、S 弯、急停、窄通道四类工况。
   - 输出统一指标表：
     - 横向误差 RMSE、航向误差 RMSE；
     - 控制输入抖动（`a`、`ω` 一阶差分均方）；
     - 晃动峰值与恢复时间。
   - 目标门槛：相对“无抑振基线”，**晃动峰值下降 ≥20%**，且横向误差恶化不超过 **10%**。

2. **模型与控制优化目标（7月底前）**
   - 在 `scout_local_planner` 中完成并稳定启用：
     - 速度规划 `v(s)`；
     - 时间参数化参考生成；
     - 求解失败降级策略（重试/降级/安全停车）。
   - 稳定性目标：在 20Hz 控制循环下，连续运行 30 分钟，求解成功率 **≥99%**。

3. **论文投稿目标（9月）**

   - **8月15日前完成定稿**（补齐消融实验与局限性分析）。

### 7.4 风险点及备选方案

1. **风险：实车实验资源不足（场地/时间/硬件状态）**
   - 备选：将实验矩阵拆分为“核心必做 + 扩展可选”，先保证核心 30 组实车完成；不足部分以高保真仿真补齐并明确标注。

2. **风险：MPC 求解在高动态工况下不稳定**
   - 备选：
     - 启用保守参数集（降速、收紧约束）；
     - 切换到“安全模式”控制策略（低速跟踪 + 强制制动阈值）；
     - 保留 TEB 作为应急对照控制器，保证任务连续性。

3. **风险：抑振收益不显著，难以支撑论文结论**
   - 备选：
     - 扩展指标（频域能量、恢复时间分位数）；
     - 增加更具挑战的工况（连续弯道 + 速度扰动）；
     - 调整论文叙事为“稳定性增强框架 + 工程实证”，避免过度依赖单一指标。

4. **风险：投稿窗口与实验进度冲突**
   - 备选：
     - 采用“双轨稿件”策略：先完成短稿/Workshop 版本锁定成果，再迭代长稿；
     - 若 9 月主目标 venue 赶不上，转投时间窗口更匹配的会议/期刊。

5. **风险：环境依赖导致复现失败**
   - 备选：
     - 固定依赖版本清单（OSQP、Cartographer、ROS 包）；
     - 提供最小可运行配置与容器化说明；
     - 每月执行一次“从零环境复现”检查。

## 3. 已完成阶段摘要

### 阶段 0：实验口径固定

目标：

- 让 bag 能明确恢复出“哪一次任务、何时开始、何时结束”

实际修改：

- 新增 `episode_id_`，发布 `/slosh/episode_id`
- slosh 状态更新从 `TRACKING` 分支移出，改为每个控制周期都更新
- `REACHED` 后继续保留一段调试输出
- `record_slosh_experiment.sh` 补录：
  - `/slosh/episode_id`
  - `/scout/goal`
  - `/scout/current_goal`
  - `/clock`

结果：

- bag 已可恢复 goal 与 episode 区间
- 仍可能出现全局路径重复发布，但不影响继续推进后续阶段

涉及文件：

### 阶段 1：实验模式下去除隐藏 EMA

目标：

- 让 slosh 实验尽量减少“模型外隐藏动态”

实际修改：

  - `filter/alpha_v = 1.0`
  - `filter/alpha_omega = 1.0`
  - `filter/kappa_boost = 0.0`

结果：

- `slosh_experiment.launch` 变成 anti-slosh 实验统一入口

### 阶段 3：第一版盒约束代理（无 slack）

目标：

- 将液面峰值从“纯软代价”推进到“受控量”

实际修改：

- 新增 `mpc/enable_slosh_box_constraint`
- 运行时计算 `slosh_eta_bar`
- 对每个预测步增加：
  - `-eta_bar <= ETA_X(k) <= eta_bar`
  - `-eta_bar <= ETA_Y(k) <= eta_bar`
- 预留抛物面项预算后再换算 `eta_bar`

结果：

- 盒约束已接入 QP
- 已验证不破坏求解与到达
- 在已测试工况下更多表现为“安全护栏”，尚未成为主导约束

### 阶段 4：slosh-aware 速度治理

目标：

- 不只靠 MPC 被动抑制，而是从参考速度侧减少激励

本阶段最终形成的实现：

- `LocalPlannerROS` 内部根据风险计算 `v_des_eff`
- 风险量不再用模态位移，而改为：
  - `height_risk = max(getSloshHeight(), last_predicted_height_max_)`
- 使用 `eta_ratio = height_risk / slosh_height_max`
- 增加死区与滞回：
  - `eta_deadband`
  - `eta_exit_ratio`
- 增加最小保持周期：
  - `min_active_steps`
- `PathHandler` 新增：
  - `getMaxCurvatureAhead(lookahead_dist, preview_dist)`
- 终点捕获区临时关闭 governor，避免末端提前停死

本阶段顺带修复的问题：

- 终点前速度过早降为 0、卡在 `TRACKING` 不收敛
- 已通过 `goal_capture_distance + goal_capture_min_speed` 修复

当前状态：

- **功能已打通**
- **实物已验证 governor 可触发**
- **但还没有完成标准化单任务 A/B 验证**

实物阶段性结论（按 `TRACKING` 段统计）：

- `Q=5` 与 `Q=10` 的实物 bag 中，`speed_governor_active` 已不再全程为 0
- governor 介入比例约：
  - `Q=5`：`81.2%`
  - `Q=10`：`80.8%`

为什么现在还不能把阶段 4 标为“正式完成”：

1. 当前实物 bag 不是标准化单任务  
2. 每个 bag 包含多个 goal / 多个 episode  
3. `Q=5` 与 `Q=10` 路线不完全一致，不能直接当严格 A/B 结论

### 阶段 5：状态同步一致性

目标：

- 打通 slosh 内部模型状态与 MPC 增广状态之间的双向同步

实际修改：

- `LiquidSloshModel` 新增：
  - `setState(const Eigen::Vector4d&)`
- `SloshIntegration::readFromAugmentedState()` 不再是空壳

- 补充了未配置时的防御式返回

结果：

- slosh 内部状态与 MPC 状态已可双向同步
- 为 warm-start、一致性重建、外部观测回写预留了接口

涉及文件：

## 4. 当前推荐做法

当前不建议继续推进控制器结构性修改。更合理的顺序是：

1. 固化实验流程
2. 批量整理已有 bag
3. 只补标准化单任务的 `Q=0 / 5 / 10` 对比
4. 等阶段 4 完成标准化 A/B 后，再决定是否进入阶段 6

当前明确不建议：

- 暂不进入阶段 6（slack 变量重构）
- 暂不继续叠加新的 anti-slosh 控制逻辑
- 暂不优先做阶段 7 的 IMU 接口

## 5. 离线分析工具

新增脚本：

- `src/scout_apps/control/scout_local_planner/scripts/extract_slosh_metrics.py`

用途：

- 支持单个 bag、多 bag、整目录扫描
- 默认只统计 `TRACKING` 段
- 可导出汇总 CSV
- 可导出按 episode 明细 CSV

示例：

```bash
python3 src/scout_apps/control/scout_local_planner/scripts/extract_slosh_metrics.py \
  /data/a/slosh_bags \
  --csv /tmp/slosh_metrics.csv \
  --per-episode
```

主要输出指标：

- `tracking_time_s`
- `height_rms_m`
- `height_max_m`
- `height_pred_rms_m`
- `height_pred_max_m`
- `solve_ms_mean`
- `solve_fail_count`
- `governor_active_ratio`
- `v_des_eff_mean`
- `reached_count`
- `episode_count`

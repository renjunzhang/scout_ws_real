## 3. 已完成阶段摘要

### 阶段 0：实验口径固定

已完成内容：

- 新增 `episode_id_`，发布 `/slosh/episode_id`
- slosh 状态更新从 `TRACKING` 分支移出，改为每个控制周期都更新
- `REACHED` 后继续保留一段调试输出
- `record_slosh_experiment.sh` 补录：
  - `/slosh/episode_id`
  - `/scout/goal`
  - `/scout/current_goal`
  - `/clock`

效果：

- bag 已可恢复 goal 与 episode 区间
- 后续标准化单任务实验已可稳定分析

### 阶段 1：实验模式下去除隐藏 EMA

已完成内容：

- 仅在 `slosh_experiment.launch` 中覆盖：
  - `filter/alpha_v = 1.0`
  - `filter/alpha_omega = 1.0`
  - `filter/kappa_boost = 0.0`

效果：

- `slosh_experiment.launch` 成为 anti-slosh 实验统一入口
- `test_mpc.launch` / `test_mpc_sim.launch` 的日常行为不受影响

### 阶段 2：预测峰值监测

已完成内容：

- 新增话题：
  - `/slosh/height_pred_max`
  - `/slosh/constraint_active`
- 预测高度包含：
  - 模态项 `h_coeff * hypot(eta_x, eta_y)`
  - 抛物面项 `R^2 * omega^2 / (4g)`（若启用）

效果：

- 已能在线监测预测峰值
- 已能录入 rosbag 并用于离线分析

### 阶段 3：第一版盒约束代理（无 slack）

已完成内容：

- 新增 `mpc/enable_slosh_box_constraint`
- 运行时计算 `slosh_eta_bar`
- 对每个预测步增加：
  - `-eta_bar <= ETA_X(k) <= eta_bar`
  - `-eta_bar <= ETA_Y(k) <= eta_bar`
- 预留抛物面项预算后再换算 `eta_bar`

效果：

- 盒约束已接入 QP
- 已验证不破坏求解与到达
- 在已测试工况下更多表现为“安全护栏”

### 阶段 4：slosh-aware 速度治理

目标：

- 不只靠 MPC 被动抑制，而是从参考速度侧减少激励

最终实现：

- `LocalPlannerROS` 内部根据风险计算 `v_des_eff`
- 风险量使用：
  - `height_risk = max(getSloshHeight(), last_predicted_height_max_)`
- 归一化：
  - `eta_ratio = height_risk / slosh_height_max`
- 已加入：
  - `eta_deadband`
  - `eta_exit_ratio`
  - `min_active_steps`
- `PathHandler` 新增：
  - `getMaxCurvatureAhead(lookahead_dist, preview_dist)`
- 终点捕获区临时关闭 governor，避免末端提前停死

同时修复：

- 终点前速度过早降为 0、卡在 `TRACKING` 不收敛
- 已通过 `goal_capture_distance + goal_capture_min_speed` 修复

#### 阶段 4 标准化单任务实物结果

实验条件：

- 相同起点
- 相同终点
- 每个 bag 仅 1 个 goal、1 个 episode
- 对比组：`Q=0 / 5 / 10`

按 `TRACKING` 段统计的 3 次均值：

| Q | tracking_time (s) | height_rms (m) | height_max (m) | pred_rms (m) | pred_max (m) | solve_mean (ms) | fail | governor_ratio | v_des_eff_mean |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 0 | 10.78 | 0.003427 | 0.008669 | 0.024816 | 0.036379 | 2.837 | 0 | 0.000 | 0.800 |
| 5 | 12.90 | 0.003555 | 0.009295 | 0.017846 | 0.032168 | 3.394 | 0 | 0.908 | 0.515 |
| 10 | 15.67 | 0.003210 | 0.010257 | 0.018312 | 0.032316 | 3.418 | 0 | 0.901 | 0.482 |

结论：

- `Q=0` 时 governor 不介入
- `Q=5/10` 时 governor 在大部分 `TRACKING` 周期介入
- 三组实验均：
  - `solve_fail_count = 0`
  - `reached = 3 / 3`
- 预测峰值明显下降：
  - `pred_rms` 从 `Q=0` 的 `0.0248` 降到 `Q=5/10` 的约 `0.018`
- 但当前 `/slosh/height` 估计值没有同步稳定下降

当前结项口径：

- 当前没有真实液面高度传感器，也没有 IMU 闭环
- 因此阶段 4 只能按“模型估计版 anti-slosh 速度治理”验收
- 在这一口径下，阶段 4 已满足：
  - governor 稳定触发
  - `pred_rms` 明显下降
  - `solve_fail_count = 0`
  - `reached = 3 / 3`

当前推荐参数点：

- 推荐 `Q=5` 作为阶段 4 当前版本默认实验点

理由：

- 相比 `Q=0`，`Q=5` 已体现预测侧收益
- 相比 `Q=10`，`Q=5` 的任务时间代价更小
- `Q=10` 虽然 `height_rms` 略低，但当前不适合作为默认点

- 支持单个 bag、多 bag、整目录扫描

- `tracking_time_s`
- `height_rms_m`

- `solve_ms_mean`
- `solve_fail_count`

推荐启动方式：

```bash
roslaunch scout_local_planner slosh_experiment.launch \
  Q_slosh:=5 \
  enable_slosh_box_constraint:=true \
  slosh_speed_governor_enable:=true \
  slosh_use_imu_lateral_accel:=true \
  slosh_use_imu_yaw_rate:=true \
  slosh_use_imu_alpha_z:=true \
  slosh_imu_topic:=/imu/data
```

阶段 7 验证流程：

1. 先确认 IMU 话题实际存在
```bash
rostopic list | grep imu
rostopic hz /imu/data
rostopic echo -n1 /imu/data
```

2. 确认 IMU 坐标系与安装外参
```bash
rosrun tf tf_echo base_link imu_link
```
若实物不是 `imu_link`，替换成实际 frame。重点确认：
- `linear_acceleration.y` 对应车体横向
- `angular_velocity.z` 对应车体偏航角速度

3. 只切 IMU 参数启动实验，不同时改 governor 参数
```bash
roslaunch scout_local_planner slosh_experiment.launch \
  Q_slosh:=5 \
  enable_slosh_box_constraint:=true \
  slosh_speed_governor_enable:=true \
  slosh_use_imu_lateral_accel:=true \
  slosh_use_imu_yaw_rate:=true \
  slosh_use_imu_alpha_z:=true \
  slosh_imu_topic:=/imu/data
```

4. 启动后确认参数生效
```bash
rosparam get /scout_local_planner/slosh_estimator/use_imu_lateral_accel
rosparam get /scout_local_planner/slosh_estimator/use_imu_yaw_rate
rosparam get /scout_local_planner/slosh_estimator/use_imu_alpha_z
rosparam get /scout_local_planner/slosh_estimator/imu_topic
```

5. 行驶过程中检查 slosh 估计输入是否已切到 IMU 来源
```bash
rostopic echo /slosh/ay_est
rostopic echo /slosh/alpha_est
rostopic echo /slosh/state
```
预期：
- 开启 IMU 后，`/slosh/ay_est` 不再只是 `v*omega` 的间接结果
- 转弯和加减速时，`/slosh/ay_est`、`/slosh/alpha_est` 会有更直接响应

6. 若行为异常，先回退到旧方案定位问题
```bash
roslaunch scout_local_planner slosh_experiment.launch \
  Q_slosh:=5 \
  enable_slosh_box_constraint:=true \
  slosh_speed_governor_enable:=true \
  slosh_use_imu_lateral_accel:=false \
  slosh_use_imu_yaw_rate:=false \
  slosh_use_imu_alpha_z:=false
```

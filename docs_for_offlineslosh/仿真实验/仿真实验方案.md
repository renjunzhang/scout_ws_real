### 0.2 实验依赖结构

```text
固定 P2 几何路径
  ↓
生成 P2 离线速度/控制计划
  ↓
生成全相位 recovery 数据 → fit/tune/held-out gate
  ↓
组装 P2 nominal＋真实停稳尾段＋recovery＋B_exec = V3
  ↓
冻结独立 Plant、C0--C4/IS、seeds、Williams 顺序和统计规则
  ↓
development：C4 稳定性＋C1 task-only 公平匹配
  ↓
clean commit → clean build → hash-bound session → readiness
  ↓
人工 approval
  ↓
正式 16 blocks × 6 conditions = 96 trials
  ↓
trial-level paired analysis
```

任何上游对象改变，下游证据都必须重新生成。不得只替换一个 CSV 或 YAML 后沿用旧 session。

### 0.3 “重复”有三种含义

| 类型 | 目的 | 是否可用相同 seeds | 能否形成新论文样本 |
| --- | --- | --- | --- |
| 可复现性检查 | 验证同一冻结输入可再次得到一致结果 | 可以，但输出必须进入新目录 | **不能**；这是重复计算，不是独立样本 |
| development 重跑 | 排错、回归、链路检查 | 只能用登记的 development seeds | **不能** |
| 独立 replication | 检验新随机块或新路径上的泛化 | 必须预注册新 seeds/路径并新建 session | 可以作为独立补充实验，但不能混入原 16-block 主分析 |

正式主矩阵本身只执行一次。当前执行器不自动重试；不能把反复运行同一 seed 后挑选成功结果称为重复性实验。

## 1. 固定任务：先有全局路径，再做防晃规划

### 1.1 固定顺序

本方案不是先优化运动再反推出路线，而是：

```text
先固定 P2 S 弯的 x/y/yaw 几何
→ 再沿该几何做离线防晃速度与控制规划
→ 再建立相位恢复和 V3 执行资产
```

正式主矩阵的六种条件共用同一条几何路径。C0、C1、IS 在线跟踪该路径；C2 回放沿该路径生成的 nominal；C3、C4 使用同一 P2/V3 相位资产。Phase-Rejoining 可改变接回的相位和有限控制 residual，但不会在线换一条几何路线。

### 1.2 冻结 P2 路径

- 文件：`/data/a/spmpc_exec_identification/phase_rejoin_p2_recovery_final_dev_v1_20260822.cElpPI/inputs/P2_s_curve.json`
- 坐标系：`map`
- 几何点数：185
- 几何长度：约 `9.182 m`
- 起点：约 `(3.448, 0.205) m`
- 终点：约 `(-3.612, 3.956) m`
- P2 离线计划：1070 点，约 `35.63 s`
- V3 停稳尾段：121 steps，合同为 `publish_zero_settle_hold_v2`

固定单一路径是为了让 C0--C4/IS 的主比较只改变控制条件，不混入路线差异。它不证明对任意路径都有效；路径泛化必须作为新的 replication，使用新路径、新 P2/V3/recovery 和新 session，不能替换本主矩阵的 P2。

### 1.3 路径改变会使什么失效

| 改动 | 必须重新生成/冻结 |
| --- | --- |
| P2 几何或终点朝向 | offline plan/report、nominal validation、recovery phase coverage、V3、session |
| 时间离散或 30 Hz 控制周期 | offline plan、双通道队列、solver/codegen 合同、V3、session |
| Plant 参数 | Plant freeze、development readiness、session；不能冒充实车标定 |
| gate/radii/B_exec/recovery policy | recovery fit/held-out、V3、development 闭环、session |
| condition config、正式 seeds/order/statistics | 新 freeze_id 和新 session；旧正式结果不得混用 |
| 代码、编译器、STL 或 executable | clean rebuild 和新 session |

## 2. 冻结对象与唯一实验变量

### 2.1 所有正式 trial 都固定的对象

| 层 | 冻结内容 |
| --- | --- |
| 任务 | P2 S 弯几何、目标位置/朝向、45 s 运动上限、固定 4 s 液面尾窗 |
| 控制周期 | 30 Hz，22D 双通道执行增广，N=10 Full SQP（使用该 backend 的条件） |
| 资产 | P2 offline plan/report、1070 行 V3、held-out gate、B_exec、recovery policy |
| Plant | 独立 Scout 执行＋独立低阶液体 stress truth，`physical_parameter_claim=false` |
| 评价 | 外部 Plant 液面、trial-level 统计、失败保留规则 |
| 设计 | seeds 3101--3116、每 block 六条件、冻结 Williams 顺序 |
| 运行环境 | Git commit、clean tree、编译器/STL/浮点合同、runner/auditor/executable hash |

### 2.2 一个 trial 中允许变化的对象

- `condition_id`：C0、C1、C2、C3、C4 或 IS；
- `seed`：决定冻结 Plant 合同中的噪声、抖动等随机实现；
- 由闭环自然产生的状态、命令和任务结果。

路径、权重、gate、V3、Plant 配置、成功定义和分析阈值都不是 trial-level 自变量。

### 2.3 真值隔离

允许的因果链：

```text
控制器最终发布命令
→ 线/角各自延迟、惯性、增益、噪声和饱和
→ 独立 Scout 运动
→ 独立液体 Plant
→ 外部液面真值，只进入标签、CSV、summary 和最终评价
```

禁止的数据流：

```text
外部 Plant 液体状态
↛ controller feature / internal observer
↛ phase score / recovery gate / recovery action
↛ residual command / solver parameter
```

该 Plant 是带已知偏差的仿真 stress object，不是 DualSPHysics/CFD，也不是实车参数真值。

- 总计 `16 × 6 = 96` 个完整 trial；

同 seed 的六个条件构成一个配对块。统计样本数是 16 个 block，不是 96×MPC 周期。

## 5. 指标、假设与决策规则

### 5.1 主指标

统计单位是完整 trial：

$$
Y_{\mathrm{sim}}=Q_{0.95}\left(\{h_{\mathrm{ext}}(t)\mid
t\in\mathcal W_{\mathrm{motion+4s\ tail}}\}\right).
$$

`external_measured_height_q95_m` 来自独立 Plant，窗口包括完整运动段和固定 4 s 尾段。内部 observer 液面只能做机制解释，不能替代主指标。

### 5.2 预注册主问题

| 问题 | 正式对比 | 判定 |
| --- | --- | --- |
| 完整方法是否优于普通基线？ | C4−C0 | paired mean 的 95% 上界 `<= -0.0005 m` |
| 收益是否不只是因为更慢/平滑？ | C4−C1 | 同一液面门通过，同时任务非劣通过 |
| empirical gate 是否有因果价值？ | C4−C3 | 同一液面门通过；完整机制结论还需仿真 5 受控偏离 |
| 离线 nominal 本身有什么效果？ | C2 相对基线 | 完整报告，当前不是硬主 claim |
| 与传统 ZVD 如何取舍？ | IS 相对 C4/基线 | 完整报告；不要求 C4 必须击败 IS |

### 5.3 任务非劣与统计合同

- 最小有意义液面差：`0.0005 m`；
- 区间：10,000 次确定性 paired bootstrap；
- estimator：paired mean；
- C4 对 C0、C1、C3 均要求 `upper95(mean(C4-comparator)) <= -0.0005 m`；
- C4 对 C0/C1 完成时间相对差的 95% 上界：`<= 10%`；
- C4 对 C0/C1 tracking q95 绝对差的 95% 上界：`<= 0.05 m`；
- 失败、停车和未完成 trial 全部保留，并使正式整体 PASS 失败；
- 不按 MPC 周期或液面采样点扩样。

### 5.4 完整性指标

每个 trial 还必须保留：

- `sequence_completed`、`task_success`、完成原因和终点误差；
- solver failures、controlled stops、raw solver/coordinator status；
- current/terminal gate、B_exec 和 truth-isolation 审计；
- tracking、完成时间、速度、加速度和 jerk；
- Full SQP 四项 KKT 与 backend/end-to-end wall time；
- cycle CSV 和 summary JSON 的 hash。

这些是实现与因果完整性证据，不是额外的独立统计样本。

## 6. 实验包结构与权威输入

### 6.1 目录角色

```text
SESSION_DIR/
  formal_session.yaml              # 全部冻结引用及 SHA-256
  controller_manifest.json         # runner/auditor/executable/solver/condition 实现
  formal_planner_binding.yaml
  materialization_report.json
  tools/                            # 本 session 的冻结工具副本

READINESS_DIR/
  formal_readiness.json             # READY_NOT_EXECUTED 或 NO_GO

FORMAL_OUT/
  campaign_manifest.json
  cycles/                           # 周期级诊断，不作为统计样本
  summaries/                        # 96 个 trial-level JSON，正式分析入口

ANALYSIS_OUT.json                   # paired trial-level 分析结果
```

### 6.2 权威输入规则

Agent 的任务消息必须显式给出：

- `EXPECTED_COMMIT`；
- `SESSION_DIR` 和 `formal_session.yaml` SHA-256；
- `READINESS_REPORT`；
- 若授权正式运行，再给 `HUMAN_APPROVAL`；
- 一个尚不存在的 `FORMAL_OUT`；
- 是否只审计、是否允许执行正式矩阵。

Agent **不得**按修改时间自动选择“最新”session，不得自行生成 approval，不得从旧对话猜路径。Git HEAD、工作树或任一 hash 不匹配时立即停止。

正式 session 的绝对路径和 SHA 不写死在本文，因为文档自身的提交也属于 Git provenance；每个新 commit 都需要新的外部 session。以用户交接的 run card 为唯一权威。

### 6.3 冻结 Agent 与执行 Agent 的职责分界

```text
冻结 Agent：修改 → 测试 → 本地 clean commit → -j2 clean build → 物化 session
执行 Agent：只核验 session/readiness/approval → 运行冻结副本 → 分析
```

- 构建和单元测试必须发生在 session 物化之前；
- session 物化后不得再编辑、提交、重新 codegen 或重新构建；
- 执行 Agent 不运行 `catkin_make`，而是由 frozen auditor 核验已绑定 executable；
- 若执行前发现必须改文档、代码或配置，旧 session 立即降级为 stale，回到冻结流程生成新 session；
- 物化工具属于 release-engineering，不允许普通执行任务手改 session YAML 或补填 hash。

### 7.3 SOP-C：运行一次正式 96-trial campaign

没有明确人工许可时禁止执行本节。必须调用 session 内的 frozen runner，不能手写 seed/condition 循环：

```bash

```

执行器会重新审计 session/资产/clean commit，严格按 Williams CSV 串行运行 96 条，不自动重试，并持续写入 `campaign_manifest.json`。正常完成状态应为：

```text
COMPLETE_FORMAL_CAMPAIGN_UNANALYZED
completed_trial_count=96
```

正式任务失败仍应由 C++ runner 正常写出 summary 并保留；进程/文件等基础设施失败会停止 campaign。当前工具不自动执行“基础设施补跑”，任何 replacement 都需要单独人工审查，且原失败证据不得删除。

### 7.4 SOP-D：正式 trial-level 分析

分析器只扫描输入目录的直接子文件，因此必须指向 `FORMAL_OUT/summaries`，不能指向 campaign 根目录或 `cycles/`：

```bash
set -euo pipefail

SESSION_SHA256=<reviewed-session-sha256>
FORMAL_OUT=/data/a/spmpc_exec_identification/<completed-formal-campaign-dir>
FROZEN_ANALYZER=/data/a/spmpc_exec_identification/<reviewed-session-dir>/tools/analyze_phase_rejoin_simulation_campaign.py
ANALYSIS_OUT=/data/a/spmpc_exec_identification/<new-analysis-dir>/formal_analysis.json

test ! -e "${ANALYSIS_OUT}"
python3 "${FROZEN_ANALYZER}" \
  --input-dir "${FORMAL_OUT}/summaries" \
  --output "${ANALYSIS_OUT}" \
  --stage formal \
  --frozen-session-sha256 "${SESSION_SHA256}" \
  --preregistered-min-effect-m 0.0005
```

## 9. 失败分类与 NO-GO 处理

| 失败类型 | 例子 | 正确处理 |
| --- | --- | --- |
| Preflight/provenance | dirty tree、hash 不符、approval 缺失 | 创建正式输出前失败关闭；不运行 trial |
| 基础设施 | 进程异常、磁盘写入失败、文件缺失 | 停止并保留 manifest/stdout/stderr；不自动重试 |
| 方法/任务失败 | solver failure、controlled stop、未完成、液面不正向 | 保留为正式结果；不得补跑到成功 |
| 资产或实现 bug | condition 语义错、真值泄漏、错误 V3 | 整个 session 作废，修复后新 commit、新 freeze_id、96 条从头运行 |
| 统计门未通过 | 效果不足 0.5 mm 或任务非劣失败 | 如实报告负结果；不得根据正式结果调 C1/gate/V3/Plant |

共同禁止事项：

- 不删除失败 trial，不挑 seed，不按周期扩样；
- 不放宽 beta、V3 radii、B_exec、residual authority、KKT 或成功定义追求通过；
- 不重新拟合 held-out gate 迁就正式结果；
- 不覆盖 `/data/a/...` 证据，不把大数据加入 Git；
- 不使用 DualSPHysics，不接触实车，不运行高并发任务；构建最多 `-j2`；
- readiness 不等于人工许可，人工许可也不等于正式结果 PASS。

### 0.3 “重复”有三种含义

| 类型 | 目的 | 是否可用相同 seeds | 能否形成新论文样本 |
| --- | --- | --- | --- |
| 可复现性检查 | 验证同一冻结输入可再次得到一致结果 | 可以，但输出必须进入新目录 | **不能**；这是重复计算，不是独立样本 |

## 1. 固定任务：先有全局路径，再做防晃规划

### 1.1 固定顺序

本方案不是先优化运动再反推出路线，而是：

```text
先固定 P2 S 弯的 x/y/yaw 几何
→ 再沿该几何做离线防晃速度与控制规划
→ 再建立相位恢复和 V3 执行资产
```

正式主矩阵的六种条件共用同一条几何路径。C0、C1、IS 在线跟踪该路径；C2 回放沿该路径生成的 nominal；C3、C4 使用同一 P2/V3 相位资产。Phase-Rejoining 可改变接回的相位和有限控制 residual，但不会在线换一条几何路线。

### 1.2 冻结 P2 路径

- 文件：`/data/a/spmpc_exec_identification/phase_rejoin_p2_recovery_final_dev_v1_20260822.cElpPI/inputs/P2_s_curve.json`
- 坐标系：`map`
- 几何点数：185
- 几何长度：约 `9.182 m`
- 起点：约 `(3.448, 0.205) m`
- 终点：约 `(-3.612, 3.956) m`
- P2 离线计划：1070 点，约 `35.63 s`
- V3 停稳尾段：121 steps，合同为 `publish_zero_settle_hold_v2`

固定单一路径是为了让 C0--C4/IS 的主比较只改变控制条件，不混入路线差异。它不证明对任意路径都有效；路径泛化必须作为新的 replication，使用新路径、新 P2/V3/recovery 和新 session，不能替换本主矩阵的 P2。

### 1.3 路径改变会使什么失效

| 改动 | 必须重新生成/冻结 |
| --- | --- |
| P2 几何或终点朝向 | offline plan/report、nominal validation、recovery phase coverage、V3、session |
| 时间离散或 30 Hz 控制周期 | offline plan、双通道队列、solver/codegen 合同、V3、session |
| Plant 参数 | Plant freeze、development readiness、session；不能冒充实车标定 |
| gate/radii/B_exec/recovery policy | recovery fit/held-out、V3、development 闭环、session |
| condition config、正式 seeds/order/statistics | 新 freeze_id 和新 session；旧正式结果不得混用 |
| 代码、编译器、STL 或 executable | clean rebuild 和新 session |

### 2.2 一个 trial 中允许变化的对象

- `condition_id`：C0、C1、C2、C3、C4 或 IS；
- `seed`：决定冻结 Plant 合同中的噪声、抖动等随机实现；
- 由闭环自然产生的状态、命令和任务结果。

路径、权重、gate、V3、Plant 配置、成功定义和分析阈值都不是 trial-level 自变量。

### 2.3 真值隔离

允许的因果链：

```text
控制器最终发布命令
→ 线/角各自延迟、惯性、增益、噪声和饱和
→ 独立 Scout 运动
→ 独立液体 Plant
→ 外部液面真值，只进入标签、CSV、summary 和最终评价
```

禁止的数据流：

```text
外部 Plant 液体状态
↛ controller feature / internal observer
↛ phase score / recovery gate / recovery action
↛ residual command / solver parameter
```

该 Plant 是带已知偏差的仿真 stress object，不是 DualSPHysics/CFD，也不是实车参数真值。

### 3.1 C1 公平性解释

C1 的目的不是预先“战胜”C4，而是检验 C4 的收益相对一个 independently tuned、较慢且更平滑的普通 MPCC 是否仍存在，从而削弱通用替代解释。冻结配置只读取任务完成、tracking、完成时间、速度、加速度和 jerk；不得读取外部 Plant 液面、内部液体 observer 或 C4 防晃指标。

冻结结果：

- seeds 8801--8805 全部在 `43.77--44.53 s` 内 `GOAL_REACHED`；
- 未延长 45 s，也未放宽 `|v| <= 0.03 m/s` 停稳门；
- `solver_failures=0`、`controlled_stops=0`；
- C1 比 C4 development 参考更慢且更平滑，是保守 comparator，不声称精确等时或精确平滑匹配，因此不能写成已经证伪所有速度/平滑解释；
- `pilot_tuned_and_frozen=true`，以后不得根据液面结果回调。

直线、定曲率圆弧和 S 弯只是 C1 task-only 独立回归，不进入正式主矩阵。

### 4.2 正式顺序

- 16 个 paired block，每个 seed 对应一个 block；
- 每个 block 恰好运行 C0、C1、C2、C3、C4、IS 各一次；
- 总计 `16 × 6 = 96` 个完整 trial；

- 正式 runner 严格串行，不使用高并发，不自动重试。

同 seed 的六个条件构成一个配对块。统计样本数是 16 个 block，不是 96×MPC 周期。

`16` 是当前工程冻结数，不是天然充分的样本量；16 blocks 与 0.5 mm margin 尚无 prospective power/precision 论证，论文必须把这一点列为局限，不能宣称既定统计功效。

## 5. 指标、假设与决策规则

### 5.1 主指标

统计单位是完整 trial：

$$
Y_{\mathrm{sim}}=Q_{0.95}\left(\{h_{\mathrm{ext}}(t)\mid
t\in\mathcal W_{\mathrm{motion+4s\ tail}}\}\right).
$$

`external_measured_height_q95_m` 来自独立 Plant，窗口包括完整运动段和固定 4 s 尾段。内部 observer 液面只能做机制解释，不能替代主指标。

### 5.2 预注册主问题

| 问题 | 正式对比 | 判定 |
| --- | --- | --- |
| 完整方法是否优于普通基线？ | C4−C0 | **唯一预注册 primary**：paired mean 的 95% 上界 `<= -0.0005 m`，通过 C4/C0 任务非劣，且 C4/C0 为零 method-failed pairs |
| 收益相对平滑基线是否仍存在？ | C4−C1 | 只在 C4−C0 通过后按 fixed sequence 检验；通过可削弱通用的慢/平滑替代解释，但因 C1 非精确匹配不能写成已证伪该解释；失败不推翻 primary |
| nominal gate enforcement 是否产生可见效应？ | C4−C3 | 单独报告 paired effect/CI、activation、recovery、zero request 和失败；不套用 0.5 mm hard gate，也不 veto overall efficacy |
| C2/IS 描述性参考 | 条件级结果 | 报告各自 trial 分布与失败，不进 hard decision，也不作组件归因 |

### 5.3 任务非劣与统计合同

- C4−C0/C4−C1 当前预注册液面 margin：`0.0005 m`；
- 区间：10,000 次确定性 paired bootstrap；
- estimator：paired mean；
- C4−C0 是唯一预注册 primary 系统效果对比；只有它通过后才解释 C4−C1 的 fixed-sequence secondary fairness comparison；
- C4 对相应 comparator（C0；若进入第二层则 C1）完成时间相对差的 95% 上界：`<= 10%`；
- C4 对相应 comparator tracking q95 绝对差的 95% 上界：`<= 0.05 m`；
- C4−C3 输出 trial-level paired effect/CI、activation 和失败，但不进入 primary decision；
- method failure 明确定义为任务/runtime 失败、solver failure、controlled stop、publication/receipt/history failure、fail-closed zero request，以及 C3/C4 缺失或失败的 KKT audit；
- 失败、停车和未完成 trial 全部保留，但按所涉 contrast 判断：C4/C0 必须为零 method-failed pairs，C1 只影响 fixed-sequence fairness，C3 只影响 nominal mechanism，C2/IS 只影响各自 descriptive benchmark；不存在任一无关条件失败就让 primary 失败的全局 `no_failed_trials` 门；
- 失败 trial 若已完成 motion-plus-tail 窗口，仍使用其数值；若 runtime 失败使完整窗口不存在，则保留 trial 和 pair、不删除也不插补，涉及该 pair 的 effect/CI 标为不可估计，对应 claim 失败；
- 不按 MPC 周期或液面采样点扩样。

### 5.4 完整性指标

每个 trial 还必须保留：

- `sequence_completed`、`task_success`、完成原因和终点误差；
- solver failures、controlled stops、raw solver/coordinator status；
- current/terminal gate、B_exec 和 truth-isolation 审计；
- tracking、完成时间、速度、加速度和 jerk；
- Full SQP 四项 KKT 与 backend/end-to-end wall time；
- cycle CSV 和 summary JSON 记录。

这些是实现与因果完整性证据，不是额外的独立统计样本。

没有明确人工许可时禁止运行 seeds 3101--3116。获批后只调用冻结的

### 7.3 Trial-level 配对分析

简化 analyzer 直接读取 `summaries/`：

```bash
python3 <SESSION_DIR>/tools/analyze_phase_rejoin_simulation_campaign.py \
  --input-dir <FORMAL_OUT>/summaries \
  --output <NEW_ANALYSIS_JSON> \
  --stage formal \
  --frozen-session-sha256 <SESSION_SHA256> \
  --preregistered-min-effect-m 0.0005
```

- C4−C0：唯一预注册 primary，连同 C4/C0 任务非劣和失败规则判断；
- C4−C1：primary 通过后才解释的 fixed-sequence secondary fairness comparison；通过仅说明收益相对 SmoothMPCC 仍存在并削弱通用替代解释；
- C4−C3：gate-enforcement effect/CI，连同 activation、recovery、zero request 和失败报告，不 veto primary；
- C2/IS：只给出条件级描述性结果，不进入 hard decision。

## 8. 正式主矩阵后的可选扩展（不阻塞当前实验）

以下设计只保留为后续研究备忘，不进入当前 freeze/readiness，也不应在 96 trials 前继续实现。正式主矩阵自身已有的 30 Hz 与失败遥测按第 5--7 节直接报告。

### 8.1 仿真 5：受控偏离与 recovery

- 只比较严格 C3/C4；
- 偏离类型、幅度、发生相位和 seed 必须在运行前冻结；
- 使用可配对的小幅执行偏离，不使用动态障碍或人工临时干预；
- 报告 gate activation、actual rejoin、错误放行、gate coverage、zero request、外部液面、tracking、停车和 contrast-specific failure；
- 不得用主矩阵结果反向选择最有利偏离。

名义仿真 4 的 C4−C3 只是一项不 veto primary 的 manipulation/effect 检查；即使是结构上的单因素对比，若 gate 从未介入，也不能支撑“gate 对一般偏离有益”。仿真 5 才是 empirical-gate 广义因果价值的主要控制实验。

### 8.2 仿真 6：A0--A3 单因素消融

### 8.3 仿真 7：鲁棒边界

分别扫描线/角延迟、惯性、增益、液体频率/阻尼、初始余晃和时间对齐误差。先冻结范围和网格，再运行；目标是报告有效范围和失效边界，不是寻找一组最好看的参数。

### 8.4 仿真 8：30 Hz 与失败处理

在冻结目标机上报告：

- Full SQP backend 与端到端 p50/p95/p99/max；

## 9. 失败分类与 NO-GO 处理

| 失败类型 | 例子 | 正确处理 |
| --- | --- | --- |
| Preflight | dirty tree、冻结对象不符、approval 缺失 | 创建正式输出前失败关闭；不运行 trial |
| 基础设施 | 进程异常、磁盘写入失败、文件缺失 | 停止并保留执行记录/stdout/stderr；不自动重试 |
| 方法/任务失败 | solver failure、controlled stop、未完成 | 保留为正式结果；不得补跑到成功；只作用于包含该条件的对应 contrast |
| 资产或实现 bug | condition 语义错、真值泄漏、错误 V3 | 整个 session 作废，修复后新 commit、新 freeze_id、96 条从头运行 |
| primary 统计门未通过 | C4−C0 效果不足 0.5 mm、C4/C0 任务非劣或失败门未通过 | 如实报告 primary 负结果；不得根据正式结果调 C1/gate/V3/Plant |
| 条件化/机制门未通过 | C4−C1 fairness 或 nominal C4−C3 不支持 | 限制对应强化/机制主张，不反向否决已经支持的 C4−C0 |

共同禁止事项：

- 不删除失败 trial，不挑 seed，不按周期扩样；
- 不放宽 beta、V3 radii、B_exec、residual authority、KKT 或成功定义追求通过；
- 不重新拟合 held-out gate 迁就正式结果；
- 不覆盖 `/data/a/...` 证据，不把大数据加入 Git；
- 不使用 DualSPHysics，不接触实车，不运行高并发任务；构建最多 `-j2`；
- readiness 不等于人工许可，人工许可也不等于正式结果 PASS。

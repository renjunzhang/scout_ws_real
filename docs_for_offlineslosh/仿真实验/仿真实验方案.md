## 2. 正式实验前按什么顺序冻结

正式实验前只走下面一条顺序链。前一门未通过，不进入后一门。

```text
F0 保留当前代码和开发证据
  ↓
F1 闭合 C4 多 seed development 稳定性
  ↓
F2 用纯任务指标冻结 C1 公平匹配
  ↓
F3 物化并哈希绑定正式 session、executable 和全部资产
  ↓
F4 readiness audit = READY_NOT_EXECUTED
  ↓
人工审查并签署绑定 session SHA-256 的 approval
  ↓
仿真 4：执行 16 × 6 个正式 trial
```

### F1：C4 多 seed 稳定性（已完成）

旧 pilot 曾出现 8701 early gate-stop 和 8702/8703 晚段 `ACADOS_MINSTEP`。在不放宽 beta、V3 radii、residual authority、KKT 合同或成功定义的前提下，补齐完整 horizon B_exec 可达性前置见证后，8701--8705 均满足 `solver_failures=0`、`controlled_stops=0`、`sequence_completed=true`、`task_success=true`。这仍只是 development 放行证据，不授权正式 seeds 3101--3116。

修复规则固定如下：

1. 只使用与 recovery fit/tune/held-out 和正式 seeds 互斥的新 development seeds；
2. 对第一个失败周期记录 22D 初态、候选窗口、selected phase、stage/terminal 具名约束余量、四项 KKT、SQP/QP 迭代和 raw solver status；
3. 先判断是候选执行不兼容、经验 gate 合法拒绝、OCP 不可行，还是 Full SQP 数值失败；
4. 不放宽 beta、V3 radii、residual authority、`1e-6` KKT 合同或任务成功定义；
5. 不重试、吞掉错误，也不使用 stored recovery 掩盖 solver failure；
6. 修复后至少在一组新的 development seeds 上全部满足 `solver_failures=0`、`controlled_stops=0`、`sequence_completed=true`、`task_success=true`，才能进入 F2。

如果 gate 拒绝是冻结规则下的正确行为，结论应是当前方法/资产对该扰动范围覆盖不足，而不是把拒绝改名为成功。

### F2：再冻结 C1 公平匹配

C1 的目的不是战胜 C4，而是排除“C4 只是更慢或更平滑”的替代解释。旧实现只按 9D 几何误差和虚拟进度奖励求解，虚拟进度可脱离车体切向速度前冲，角速度也缺少曲率前馈，因此即使换成直线也会逐渐漂转和停滞。当前候选已显式闭合：

```text
e_heading = theta - phi_ref
v_tangent = v cos(e_heading)
omega_ref = d(phi_ref)/ds * v_s - K_heading sin(e_heading)
```

代价中新增周期航向误差、`v_s` 与真实切向速度耦合、曲率角速度前馈/航向反馈，并在终点参考跨度小于 `0.20 m` 时使用切线解析延拓，避免局部三次拟合退化。四个新增参数 `w_heading`、`w_progress_coupling`、`w_yaw_rate_tracking`、`heading_feedback_gain` 已贯通配置、runner 审计、stage 参数和三套 mainline acados manifest；C0/IS 显式置零，legacy direct-omega schema 不变。

C1 冻结必须遵守：

- 只调整显式登记的任务闭环/平滑参数和一个全局时间尺度；当前 runner 接受的 development scale 范围为 `[0.5, 2.0]`；
- 只使用完成时间、tracking q95、速度/加速度/jerk 等任务运动指标选候选；
- **外部 Plant 液体真值、控制器内部液体 observer、C4 防晃指标都不得参与 C1 调参或择优**；
- 候选必须先在全部 C1 development seeds 上完成任务且无 runtime/solver failure；不能挑成功 seed；
- 从通过完成性门的候选中，按预注册的任务匹配损失选择唯一配置；冻结后把 `pilot_tuned_and_frozen` 改为 true，并记录候选表、命令、seed、输入 hash 和选择理由；
- 如果不存在完成可靠的候选，保持 `NO_GO`，先修复普通 MPCC 的任务闭环，不能用液面结果倒推 C1 参数。

终点停稳的剩余根因是：进入 `capture_stop` 时旧逻辑会放宽已经收紧的 slowdown envelope，车辆在终点附近重新加速。修复后 capture 只能继续收紧 slowdown/capture/braking 三者的最小 envelope；45 s 和 `0.03 m/s` 速度门均未修改。固定 seed 8801 的三条独立 task-only 回归也已用最终配置重新通过：

| 路径 | motion time | tracking q95 | 最终位置误差 |
| --- | ---: | ---: | ---: |
| 6 m 直线 | 28.10 s | 0.00035 m | 0.0110 m |
| 半径 3 m、90°定曲率圆弧 | 22.83 s | 0.01337 m | 0.0169 m |
| 6 m S 弯 | 28.70 s | 0.00857 m | 0.0105 m |

最终配置固定为 `v_ref=0.32`、`w_control=w_smooth=w_alpha=w_du_a=w_du_vs=0.1`，其余航向—进度参数保持上述结构。终点合同固定为 slowdown `(0.60 m, 0.80 m/s)`、capture `(0.50 m, 0.80 m/s)`。选择候选时只读取任务完成、tracking、速度、加速度和 jerk，没有读取任何外部/内部液面指标。

最终 development seeds 8801--8805 全部在 `43.77--44.53 s` 内 `GOAL_REACHED`，`solver_failures=0`、`controlled_stops=0`；tracking q95 为 `0.09065--0.09460 m`，accel q95 为 `0.08929--0.09919 m/s²`，jerk q95 为 `2.4870--2.6229 m/s³`。证据与冻结理由见 [C1 停稳与公平配置冻结记录](../方案/20260823_PhaseRejoining_C1停稳与公平配置冻结记录.md)。

C1 比 C4 development 参考更慢且更平滑，不能声称精确等时；它作为保守 comparator 排除了“C4 只是更慢/更平滑”的替代解释。冻结后不得根据正式液面结果回调 C1。`pilot_tuned_and_frozen=true`，F2 已完成。

### F3：物化正式 session

模板位于：

`src/scout_apps/control/spmpc_local_planner/config/simulation/phase_rejoin_session_template_v1.yaml`

模板当前故意保留空路径和空 hash，状态为 `pilot_candidate_bound`。正式物化时必须创建新 session，而不是把假 hash 填进模板。至少绑定：

- clean Git commit、compiler/STL/floating-point contract；
- closed-loop runner 源文件 hash、executable hash、controller manifest 和 V3 validator；
- Plant、planner、P2 path、offline plan/report/generator；
- nominal builder、V3 artifact、validation report；
- recovery dataset、fit manifest、radii bounds、held-out report；
- 六个 condition config、正式顺序表和分析脚本；
- freeze_id、正式 seeds 3101--3116、`formal_trials_started=false`。

`runtime.runner` 与 `runtime.executable` 是两个不同对象：前者是只接受已审查 session 的 Python 正式调度器，后者是单 trial C++ 可执行文件。controller manifest 必须分别记录两者的 SHA-256。正式调度器还依赖与其相邻、同样被复制冻结的 readiness auditor；不得退回到手写 shell 循环。

任一 hash、路径、condition 语义或 C1 freeze 改变，都必须重新生成 session。`planar_r03` 的已知偏差和 `physical_parameter_claim=false` 必须保留。

### F4：只做 readiness audit

readiness 工具只检查 session 和资产，不运行 trial。放行状态必须是：

```text
READY_NOT_EXECUTED
formal_trials_started=false
reasons=[]
```

当前模板审计必须返回 `NO_GO`。物化 session 的 readiness 即使返回 `READY_NOT_EXECUTED`，也只表示自动检查未发现缺项，不构成人工许可。正式执行器还必须读取人工编写的 approval JSON，并逐项确认：

```json
{
  "schema": "spmpc_formal_simulation_human_approval_v1",
  "approved": true,
  "session_sha256": "<被审查的 formal_session.yaml SHA-256>",
  "formal_seeds_authorized": [3101, 3102, 3103, 3104, 3105, 3106, 3107, 3108, 3109, 3110, 3111, 3112, 3113, 3114, 3115, 3116],
  "reviewer": "<人工审查者>",
  "approved_at": "<带时区的审查时间>"
}
```

approval 缺失、session hash 不一致、seed 列表不完全一致、Git HEAD/工作树不再匹配冻结点时，正式执行器必须在创建输出目录前失败关闭。执行时严格按冻结顺序串行运行 96 条，不做隐式重试；task failure 作为正式结果保留，基础设施错误则停止并保留 manifest 证据。

## 4. 独立 Plant 和真值隔离

正式数据的因果链必须是：

```text
控制器最终发布命令
→ 线/角各自的延迟、惯性、增益、噪声和饱和
→ 独立 Scout 运动
→ 独立低阶液体 Plant
→ 外部液面真值，仅用于 rollout 标签和最终评价
```

禁止的数据流是：

```text
外部 Plant 液体状态
↛ controller feature
↛ liquid observer
↛ phase score
↛ recovery gate/action
↛ residual command
```

控制器只可使用自己的 execution horizon、odom 派生运动和内部 observer。外部液体真值只能进入 CSV、summary、recovery rollout 标签和最终分析。

该 Plant 是有意与控制器不同的独立低阶 stress object，包含参数偏差和未建模二阶模态；它不是 DualSPHysics/CFD，也不代表真实容器液面。固定 seed 的字节级复现只对同一 executable、编译器、STL 和浮点环境承诺。

## 5. 正式指标和统计合同

### 5.1 统计单位与主指标

统计单位是一个完整 trial，不是 MPC 周期或液面采样点。主指标为：

$$
Y_{\mathrm{sim}}=Q_{0.95}\left(\{h_{\mathrm{ext}}(t)\mid
t\in\mathcal W_{\mathrm{motion+4s\ tail}}\}\right).
$$

这里的 `external_measured_height_q95_m` 来自独立 Plant，并包含完整运动段和固定 4 s 尾段。内部 observer 液面只作机制解释。

### 5.2 已冻结的 V1 正式合同

- 正式 seeds：3101--3116，共 16 个 paired block；
- 每个 block 六个条件，共 96 个 trial；
- 条件顺序：`phase_rejoin_formal_order_v1.csv` 中冻结的 Williams 平衡顺序；
- 最小有意义差异：`0.0005 m`；
- 区间：10,000 次确定性 paired bootstrap，estimator 为 paired mean；
- C4 对 C0、C1、C3：`upper95(mean(C4-comparator)) <= -0.0005 m`；
- C4 对 C0/C1 完成时间：相对差的 95% 上界不超过 `10%`；
- C4 对 C0/C1 tracking q95：绝对差的 95% 上界不超过 `0.05 m`；
- 失败、停车和未完成 trial 全部保留，并使正式整体 PASS 失败；
- 只有基础设施故障允许同 seed、同 condition 补跑，原失败证据仍保留。

C2 和 IS 必须完整报告，但当前 V1 不以“C4 必须击败 IS”作为论文主 claim 的硬门；若不优于 IS，应报告取舍，不能宣称优于传统 input shaping。

## 6. 仿真 4 及后续阶段

### 仿真 4：正式核心矩阵

在单一冻结 P2 核心路径上执行 16×6 配对 trial，回答：

1. C4 是否相对 C0 降低独立液面；
2. C4 是否在任务非劣的同时相对 C1 仍有收益；
3. C2 和 IS 的收益与代价是什么；
4. C3 monitor-only 消融是否暴露更多错误放行、失败或尾段液面。

正式结果出来后不再修改 seed、条件顺序、主窗口、阈值或分析器。若发现实现/资产 bug，整批正式 session 作废，修复后创建新 freeze_id 并从头运行。

### 仿真 5：受控偏离与恢复

只比较严格 C3/C4，使用冻结、可配对的小幅执行偏离。偏离幅度必须在正式运行前登记，不使用动态障碍或不可复现人工干预。报告 actual rejoin、错误放行、gate coverage、外部液面、tracking、停车和失败。

### 仿真 6：A0--A3 单因素消融

- A0：无液体离线目标 vs C2；
- A1：相位对齐但 residual=0 vs C3；
- A2：严格 C3 vs C4；
- A3：IdealExec vs IdentifiedExec，分别生成一致资产。

每组只能改变一个因素；未通过的组件不能借 C0/C4 总体结果宣称贡献。

### 仿真 7：鲁棒性边界

按预注册范围分别扫描线/角延迟、惯性、增益、液体频率/阻尼、初始余晃和时间对齐误差。目标是报告有效范围和失效边界，不做无目的的大型全因子网格。

### 仿真 8：30 Hz 和失败处理

在冻结目标机上报告完整 backend 与端到端的 p50/p95/p99/max、超过 33.3 ms 比例和最长连续超时。development seed 8601 的耗时通过只证明当前单 seed 链路，不替代正式矩阵的实时性统计。

## 7. 数据组织和禁止事项

- 新输出写到 `/data/a/spmpc_exec_identification` 下的新目录，所有工具拒绝覆盖；
- cycle CSV 用于诊断，summary JSON 才是 trial-level 分析输入；
- fit/tune/held-out、development、formal seeds 必须互斥；
- 不删除失败 trial，不按周期扩样，不挑最好 seed；
- 不重新拟合 held-out gate 来迁就 C4 readiness 失败；
- 不修改 V3 radii、B_exec、residual authority、Plant 或成功定义来追求通过；
- 不把 `/data/a/...` 大数据加入 Git；
- 不使用 DualSPHysics，不接触实车，不运行高并发任务；构建最多 `-j2`。

## 8. 什么时候才算仿真正式完成

至少同时满足：

1. readiness audit 在冻结 session 上为 `READY_NOT_EXECUTED`；
2. 16×6 正式核心矩阵完整、失败保留、分析合同不可变；
3. C4 对 C0 的独立液面达到预注册门槛；
4. 若要排除慢/平滑解释，C4 对 C1 的液面和任务非劣门同时通过；
5. C3/C4 受控偏离支持 recovery gate 的独立机制结论；
6. 只对真正通过的 A0--A3 给出组件结论；
7. 鲁棒性给出有效范围，实时性给出完整分位统计；
8. 代码、资产、环境和分析均可由 hash 追溯。

即使全部通过，也只能声称“方法在冻结的独立低阶仿真范围内有效”，不能声称真实 Scout、真实液面、CFD 或一般安全证书已经得到验证。

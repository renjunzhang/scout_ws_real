# 旧 DualSPHysics 尝试复盘与当前仿真主线边界

- 复盘日期：2026-08-21
- 复盘对象：`docs/实物实验注意事项/对比试验/仿真接入液体/`
- 用途：决定当前 Phase-Rejoining 仿真主线先做什么、暂时不做什么
- 证据边界：只整理既有记录，不把旧开发结果升级为正式结论

## 1. 先给结论：旧尝试不是“液体程序完全失败”

旧记录实际包含三类不同结果，不能都归为同一种失败：

1. **基础设施和构建曾多次 NO-GO，后来被逐步解决。**早期受 QEMU、内存、
   AppArmor、编译和一次性执行门禁影响；后续 RTX 5080 candidate 已完成构建、静态审计和
   1 s GPU functional smoke。这些结果只回答“程序能否受控运行”，不回答液体是否可信。
2. **液体单独开发验证后来通过。**早期 DDT/CFL 分支确实出现持续回弹和 9/17 个绝对稳态
   指标超限；后来采用 `Shifting=None / CFL=0.1 / ViscoArtificial=0.3`，完成独立冷启动、
   restart、CPU/GPU parity，以及零运动、小幅平移和偏航的 development-only 验证。
3. **真正要用于论文的主链没有完成。**阶段 5“小车已执行运动到液体的单向回放”和阶段 6
   “液体结果与控制方法/实物参考比较”没有开始；没有形成 C0--C4 配对结果，也没有实物液面
   参考。因此旧工作不能回答“新控制方法是否防晃”。

最准确的描述是：**旧项目完成了部分 CFD 工具链和液体单体验证，但小车—液体—方法比较主实验
未闭合；物理保真也未验证。**

## 2. 这个判断来自哪些旧证据

### 2.1 工具链最终能跑，但这不是防晃证据

[RTX 5080 阶段 3--6 续接记录](../../docs/实物实验注意事项/对比试验/仿真接入液体/20260811_RTX5080_DualSPHysics_GPU液体仿真阶段3-6续接方案_Agent执行版.md)
第 21--73 行记录了：构建、静态审计和 GPU smoke 已通过，但结论被明确限制为
development-only，不能代表 settled state、数值收敛或实物保真。

这说明当时的主要问题后来已不再是“没有可执行程序”。本轮若重新从 CUDA、QEMU 或 GenCase
开始，不会自动补上缺失的方法比较证据。

### 2.2 早期液体数值平台确实不稳定

同一记录第 75--104 行和第 584--623 行保留了早期失败分支：

- CFL 从 0.2 降到 0.1 后四项主指标虽然改善，但仍有 9/17 个绝对稳态指标超限；
- 速度 RMS 降到最低点后再次回升，回弹比仍约为 1.75；
- 失败集中在速度、动能、位置冻结和持续回弹，不是文件损坏或 GPU runtime 错误；
- 后续 artificial-viscosity 候选通过的是固定软件、固定数值合同下的液体单独开发验证，
  `PHYSICAL_FIDELITY_VALIDATED` 仍为 `false`。

因此本轮不能把“CFD 能产生有限输出”直接当作外部真值；任何高保真分支仍须先做静水、频率、
阻尼、相位和分辨率验证。

### 2.3 小车耦合和比较阶段没有执行

同一记录第 240--280 行与第 1355--1430 行明确写明：

- 阶段 5、6 均未启动、未准入；
- 主 bag 尚未封存，motion handoff ABI 尚未物化；
- 旧架构只允许 two-pass、离线、单向运动耦合，不是实时双向 FSI；
- `/cmd_vel`、计划轨迹或控制器内部状态不能代替 `/odom` 已执行运动；
- 实物 reference 缺失，不能生成 physical comparison PASS。

这正是旧尝试没有回答控制研究问题的根本原因。

### 2.4 旧 source attempt 的任务失败不能被液体回放改写

同一记录第 226--238 行保留了一条 `METHOD_FAILURE / GOAL_TIMEOUT`。液体事后回放无论成功
还是失败，都不能覆盖该任务结论。这条边界对本轮同样有效：任务失败、求解失败和停止动作必须
进入方法统计，不能只在成功轨迹上计算液面。

### 2.5 分辨率和实物保真仍是未完成项

[最初的 DualSPHysics 接入方案](../../docs/实物实验注意事项/对比试验/仿真接入液体/20260805_DualSPHysics物理液体接入SIM-R8方案.md)
第 537--559 行已经指出：当研究门槛是 1 mm 时，`dp=2 mm` 只能用于 smoke，不能支持 1 mm
级结论；第 779--851 行把数值物理验证、实物保真、development replay 和 formal 复审划成了
不同门禁。旧记录没有完成实物幅值、频率、阻尼、相位和方法排序的五维验证。

## 3. 当前主线为什么先用独立低阶 Plant

当前要回答的是控制方法问题，不是先回答 CFD 工程问题。正式主比较至少需要 C0、C1、C2、C4
和 input shaping，多种配对 seed、受控偏离、消融和参数扫描。旧记录估计 DualSPHysics 每 1 s
物理时间约消耗 78--80 s wall time；若把它直接放进全部开发循环，参数调试、错误定位和统计冻结
都会非常慢。

所以当前采用分层证据：

```text
L0 解析/单元参考
  验证延迟、事件时刻、Jacobian、状态和单位
        ↓
L1 独立 C++ Scout＋低阶液体 Plant（当前主线）
  快速完成 C0--C4/IS、配对统计、受控偏离、消融和鲁棒性
        ↓
H1 DualSPHysics 小规模离线复核（后续可选增强）
  只复核预注册的少量代表性轨迹，不参与调参，不冒充实物真值
        ↓
P 实物液面实验
  最终验证真实幅值、频率、阻尼、相位和方法排序
```

独立低阶 Plant 不是 CFD 替代品。它的目的只有两个：

1. 让控制器内部液体模型不能给自己当裁判；
2. 以足够低的成本建立完整、配对、可复现的方法证据链。

## 4. 这次必须从旧尝试继承的硬约束

| 约束 | 本轮落实方式 | 防止重演的问题 |
| --- | --- | --- |
| 运行完成不等于效果通过 | campaign 只写 `COMPLETE_DEVELOPMENT_*`，另有 `effect_claim=false` | 把 solver `rc=0` 写成防晃 PASS |
| 外部对象只消费最终发布命令 | 独立 Plant 不读取 solver 预测液面或预测状态 | 控制器自己出题、自己打分 |
| 使用实际执行时序 | 线/角独立 delay、tau、gain、jitter；尾窗等零命令最晚到达后才开始 | 用命令时间冒充物理作用时间 |
| 外生噪声按物理时钟推进 | jitter、线过程、角过程、液面噪声为独立 RNG 流；命令事件不得重采样 | 事件切步改变随机因果 |
| 失败进入统计 | 求解失败、停止、超时和未到达都保留 | 只分析成功样本 |
| 开发与正式数据隔离 | smoke、pilot、formal seed 三组互斥，formal seeds 预先锁定 | 用开发结果反复调参后冒充正式测试 |
| create-new 输出 | 目录和 CSV/JSON 均拒绝覆盖；失败后保留 partial 证据 | 覆盖失败结果或复用 identity |
| 高保真分支先验证自身 | 若以后启用 DualSPHysics，先做静水、收敛、频率/阻尼/相位和实物参考 | 把有限数值输出当物理真值 |

## 5. 当前明确不做什么

在 C0--C4/IS 的独立 Plant 主比较闭合前，本轮不做：

- 重建旧 RTX 5080 / QEMU / AppArmor 工具链；
- 把 DualSPHysics 放入在线控制环；
- 双向液体反作用力或实时 FSI；
- 88 条 bag 全量回放；
- 用旧 development-only SPH 数值设定正式的 1 mm 防晃门槛；
- 用旧 bag 或旧试跑结果选择正式条件、阈值或 seed；
- 把低阶 Plant、DualSPHysics 或 Gazebo 结果写成真实液体已经改善。

## 6. 何时值得重新启用 DualSPHysics

只有同时满足以下条件，才建议新开 H1 高保真复核工作包：

1. 独立 Plant 上的 C0/C1/C2/C4/IS 正式定义和 runner 已冻结；
2. C4 相对 C0、C1 的外部液面结果达到预注册工程门槛；
3. 从正式定义中预先选定极少量代表性轨迹，不能看完效果后挑最好 case；
4. 容器、液位、物性、安装位姿和 motion ABI 已冻结；
5. SPH 静水、数值收敛、主频、阻尼、相位和自由衰减重新验收；
6. 明确 H1 只做模型一致性/排序复核，最终物理结论仍等待实物实验。

若 H1 与低阶 Plant 排序不一致，应报告模型适用域和差异来源，不能只保留对方法有利的一路。

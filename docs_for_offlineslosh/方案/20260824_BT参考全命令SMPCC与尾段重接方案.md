## 2. 已完成的原前置任务：老 S-MPCC 快速 Go/No-Go

本节保留运行前冻结的问题、范围和判据；实际结果见第 9 节，不得在看到结果后回改本节门槛。

### 2.1 要回答的问题

> 老 S-MPCC 在跟踪完整 BT 参考后，能否在合理执行扰动下明显改善跟踪，同时保持完整过程液面非劣？

这一步不开发尾段接纳器、不拟合经验 gate、不开发复杂状态机。若基础候选控制器本身没有价值，后续模块无法把它变成有价值的方法。

### 2.2 最小代码范围

只做三件事：

1. 从现有离线 artifact 构造完整预测域参考，不再只给老 S-MPCC 一个 \(v_{\mathrm{ref}}(s)\)；
2. 使用 `4f656f03` 的 15D 执行模型对齐到预计发布时刻，再提取老 continuous S-MPCC 需要的 10 维物理状态；快速验证阶段不把老 solver 强行改写成 15D OCP；
3. 参考至少包含 \(x,y,\psi,s,v,\omega\)、低阶液体名义状态和完整减速—沉降尾段；老 S-MPCC 仍输出完整第一拍 \(v,\omega\)，但进度只能在 BT 相位附近小范围变化，不能按几何最近点自由改写整段时序。

先增加 monitor 模式：实际发布 BT，只记录 S-MPCC 候选。确认参考和求解行为正常后，才在 development 仿真中直接发布 S-MPCC 候选。Go/No-Go 阶段保持 artifact 原时钟，只复用 15D 对齐和相位诊断，不启用 `4f656f03` 的 residual 权限收缩、经验后继接纳或 tail-commit 干预，以免无法判断完整 S-MPCC 本身是否有价值。

### 2.3 最小测试矩阵

只比较两种控制器：

| 条件 | 含义 |
| --- | --- |
| G-BT | 当前已经 5/5 成功的 BT |
| G-SMPCC-BT | 跟踪完整 BT 参考、直接发布完整命令的老 S-MPCC |

只使用两类具有实物意义的扰动：

1. **初始位姿偏差**：起点位置和航向存在合理误差；
2. **短时执行扰动**：运动中短暂速度限幅或增加一段合理附加延迟。

扰动大小必须在看结果前冻结，并来自预期实物误差范围。可以保留少量无扰动运行做回归检查，但不为制造优势增加极端场景。

每种扰动使用相同的 5 个 development seeds 做配对比较。记录：

- trial 是否完成及是否受控停车；
- tracking q95、最大误差和恢复时间；
- 完整窗口及尾段液面 q95；
- 最终位置/航向误差和完成时间；
- S-MPCC 命令相对 BT 命令的实际偏离比例。

### 2.4 简单 Go/No-Go 条件

这是开发筛选，不是正式统计检验。运行前冻结一个 tracking 主指标、液面非劣容差和命令差异死区。

必须同时满足：

1. 两类扰动下均为 5/5 完成，不能增加方法导致的 controlled stop；
2. 预先选择的 tracking 主指标至少 4/5 seeds 同向改善，配对中位改善达到约 10%；
3. 完整窗口和尾段液面 q95 相对 BT 位于预先冻结的重复性容差内，没有系统性变差；
4. 超过命令差异死区的运动周期占比足够，证明 S-MPCC 确实在工作，而不是数值上退化成 BT；
5. 改善不能只来自明显增加完成时间。

判定规则：

```text
全部满足
   └─ GO：进入路线 A，只增加最小尾段兼容性检查

任一关键条件失败
   └─ NO-GO：停止老 S-MPCC 路线，不继续调 gate 或堆状态机
              转入路线 B 的在线相位重定时
```

允许修复明确的接口、单位或实现错误；不允许为了把 NO-GO 调成 GO 进行多轮 seed-aware 权重搜索。

## 4. 原 NO-GO 分支：路线 B（已触发，仍可采用）

### B1：定义低维在线问题

令 \(\tau\) 为离线轨迹时间相位，只优化短预测域内的相位推进率

\[
\tau_{k+1}=\tau_k+\rho_k\Delta t,
\qquad \rho_{\min}\leq\rho_k\leq\rho_{\max}.
\]

决策变量优先只取 \(\rho_{0:N-1}\) 或更少的分段常数速度缩放，不重新优化二维几何路径，也不直接自由优化整段 \(v,\omega\)。

目标只保留必要部分：

- tracking 和进度恢复；
- 相位推进率偏离 1 的代价及变化率；
- 预测低阶液体晃动；
- 终端机器人、液体和执行队列对离线尾段相位的匹配。

### B2：正确重构时间缩放后的参考

不能只把参考索引从 \(t\) 改成 \(\tau\)。若 \(\rho=d\tau/dt\)，机器人参考速度需要与时间缩放一致，例如

\[
v_{\mathrm{ref},k}\approx \rho_k\bar v(\tau_k),
\qquad
\omega_{\mathrm{ref},k}\approx \rho_k\bar\omega(\tau_k).
\]

由此产生的新加速度和角加速度必须经过双通道延迟执行模型，并重新预测液体状态。离线液体名义状态 \(\bar z^\ell(\tau_k)\) 只能作为匹配目标，不能假设时间缩放后液体仍自动等于该名义状态。

### B3：终端尾段匹配与承诺式重接

预测终端以 `4f656f03` 的 15D 布局为共同合同，至少匹配：

- 位置、航向、线速度和角速度；
- 低阶液体位移和速度；
- 进度状态、4 个线速度 pending 命令和 1 个角速度 pending 命令；
- 一个单调且邻近的离线尾段相位。

匹配成功后，直接向现有 `TailCommitStateMachine` 提交首个经过最终发布事务确认的尾段命令；状态机进入 `Committed` 后连续推进到 `Released`。求解失败或匹配不足时继续当前 BT，不触发 tail-commit，也不因在线优化失败停车。

当前 `PhaseProgressGovernor` 的连续索引、ADVANCE/HOLD 和事务式 commit 可用于实现相位游标和诊断，但路线 B 的连续 \(\rho_k\) 优化仍需单独实现；不能把现有离散 HOLD/ADVANCE 直接称为在线时间律优化。

### B4：最小 development 对比

| 条件 | 用途 |
| --- | --- |

| D-RT | 完整相位重定时方法 |

## 7. 仿真主线与实物主线

本方案分成两条验证主线，但二者是**前后串行**关系，不是同时推进：

```text
仿真主线（开发端电脑）
方法 Go/No-Go → 路线收敛 → development 多 seed
→ 正式仿真 → 冻结 release
                    │
                    │ 只有仿真 GO 才放行
                    ▼
实物主线（Scout）
执行/时间/RGB 标定 → 实车参数回灌仿真
→ monitor 与低速 pilot → 正式实物对比
```

### 7.1 仿真主线：原计划与当前工作

全部在开发端电脑和独立 Plant 中完成：

1. 从 `4f656f03` 重建并复跑 BT，确认基线和记录链；
2. 第 2 节的老 S-MPCC Go/No-Go 已完成并 No-Go；
3. 先审查第 10 节路线 C 的结构可行性；若失败，直接实现路线 B；
4. 使用 development seeds 做名义、初始位姿偏差、短时执行扰动和小范围参数变化验证；
5. 检查完整窗口液面、尾段、tracking、完成时间、失败和控制周期实时性；
6. 方法收敛后冻结代码、配置、artifact、分析器和实现身份；
7. 使用全新正式 seeds/session 完成仿真对比。

仿真主线至少满足以下条件后，才允许进入实物主线：

- 选定方法在全部预定 development 场景稳定完成；
- 相对基线的 tracking 改善和液面非劣/改善同时成立；
- 尾段无方法导致的失控或受控停车；
- 30 Hz 控制周期满足实时性要求；
- 新正式仿真没有推翻 development 方向；
- 方法版本和实验 release 已冻结。

若仿真 Go/No-Go 或正式仿真失败，工作停留在开发端，不开始防晃效果实物试验。

### 7.2 实物主线：仿真通过以后再做

实物阶段按下面顺序执行：

1. 标定 Scout 线/角双通道延迟、惯性、命令生效时间和时间戳；
2. 标定 IMU、RGB 液面测量、容器、液位和静置条件；
3. 用实测参数生成实物专用执行合同和离线 artifact；
4. 把实测参数回灌独立 Plant，在开发端重跑选定方法和基线；
5. 回灌仿真仍正向后，先做只记录不干预的 monitor；
6. 再做低速、小样本 pilot，检查安全、命令切换、尾段和 RGB 数据质量；
7. pilot 通过并冻结实物 release 后，才执行随机化、配对的正式实物对比。

实车标定不是论文效果证据。若标定后修改控制模型、方法参数或离线轨迹，之前的仿真 release 失效，必须回到仿真主线重新验证；不能直接在实物上边调边做正式对比。

正式实物评价以独立 RGB 液面为准，控制器内部低阶液体状态只用于控制和机制解释。具体安全、标定和数据流程继续以 `docs_for_offlineslosh/实物实验/实物实验方案.md` 为准，但其中旧 PR-RMPC/C0–C4 名称应在新路线冻结后再统一更新。

## 8. 明确不做的事情

- Go/No-Go 前不开发复杂接纳器、经验 gate 或大状态机；
- 老 S-MPCC 失败后不继续用多轮调参挽救；
- 不同时开发和叠加两条在线修正核心；
- 不使用极端、人为偏向某方法的扰动制造优势；
- 不使用独立仿真 liquid truth 或未来信息做在线决策；
- 不因可选在线模块失败而停车，BT 或硬安全合同失效除外；
- 不复用看过结果的旧正式 seeds 作为新方法论文证据；
- 不把 seeds 9921–9923 的“完成”解释成新方法相对 BT 有效；
- 没有严格证明时，不宣称递归可行性或安全证书。

## 9. 已完成的老 S-MPCC 判定与当前边界

P0--P3 已经完成。BT 名义、D1、D2 共 15 个 trial 均为 5/5 完成；D1 monitor 的老 S-MPCC candidate 为 1310/1310 成功，但首个 D1 direct canary 未完成任务，并出现 5 次 `ACADOS_QP_FAILURE`。该 canary 的 tracking q95 相对同 seed BT 恶化 25.38%，完整液面 q95 增加 0.065053 mm，超过冻结的 0.010 mm 非劣界。campaign 按预定规则在第 17 个 trial 后停止，没有补跑或调权重。

准确结论是：

> “老 S-MPCC 接入完整 BT 参考后直接发布完整命令”不可行；该结果不能证明所有针对 BT 专门设计的 MPC 均不可行。

老 S-MPCC 虽读取完整 BT 参考，但仍拥有完整命令覆盖权，没有把控制权限限制为 BT 附近的小修正，也没有保证 residual 对液体造成的终端响应重新接回 BT 尾段。继续修改它的权重、gate 或状态机将违反原 Go/No-Go 规则。

因此后续若继续研究 MPC，必须建立全新方法身份和结构。第 10 节给出一个 BT-aware residual MPC 的重新设计；它先做独立的结构可行性检查，失败仍直接回到第 4 节的低维在线相位重定时。

## 10. 路线 C：BT 中心、小残差、终端可恢复 MPC 重新设计

### 10.1 方法定位与命名边界

新方法暂定实现身份：

```text
bt_centered_residual_terminal_mpc_v1
```

它不是：

- 老 `continuous_mpcc_acados` 的另一组权重；
- `G-SMPCC-BT` 的尾段补丁；
- 原 C3/C4 PR-RMPC、经验 gate 或 Tail-Commit 候选的改名版本；
- 在线相位重定时。路线 C 中 artifact 时钟和相位索引不是优化变量。

它要回答的新问题是：

> 在 BT 闭环命令始终作为基准和可执行后备的前提下，能否施加物理上受限、液体终端效应可消除的小 residual，改善扰动下的 tracking，同时保持 BT 的防晃时序和尾段可恢复性？

### 10.2 五个不可放松的结构不变量

1. **BT 是名义闭环策略，不只是参考曲线。** 每个预测 stage 都从预测状态重新计算 BT 命令，而不是只读取 artifact 的开环 `v/omega`。
2. **MPC 只能优化小 residual。** 发布候选始终为 `u_BT + delta_u`；不能自由输出完整 `v/omega`，也不优化自由虚拟进度 `v_s`。
3. **零 residual 始终是方法后备。** 求解、终端匹配或收益检查失败时发布完全相同的 BT 命令；不得因可选 MPC 失败而停车。
4. **优化前缀后必须有 BT-only 恢复后缀。** residual 只在短控制域内非零，随后在预测域中硬置零，让预测显式回答“现在这次修正以后，BT 能否接回来”。
5. **尾段匹配包含机器人、液体和命令队列。** 只匹配位置或 artifact index 不够；终端必须进入相位索引的 BT 可恢复集合，并在尾段前把 residual authority 收缩到零。

这五条是方法定义，不是可调权重。任一条缺失，都不能使用该 implementation ID。

### 10.3 状态、基准命令和优化变量

继续使用预计发布时刻的 15D 执行对齐状态：

\[
\xi=
[x,y,\psi,v,s,\omega,
\eta_x,\dot\eta_x,\eta_y,\dot\eta_y,
q_v^0,q_v^1,q_v^2,q_v^3,q_\omega^0]^\top .
\]

其中命令队列显式表示线、角通道不同的延迟。独立 Plant 的液体真值仍不得进入控制器。

令 \(i_k\) 为当前冻结 BT 时钟索引。预测 stage 的 BT 基准不是固定命令表，而是

\[
u^{BT}_j=\pi_{BT}(\xi_j,i_k+j),
\qquad
u_j=u^{BT}_j+g_{i_k+j}r_j,
\]

其中 \(u=[v_{pub},\omega_{pub}]^\top\)，\(r=[\delta v,\delta\omega]^\top\)，\(g_i\in[0,1]\) 是只由 artifact phase 决定的 residual authority envelope。

在线只优化前 \(H_u\) 个 residual knots；总预测域为

\[
H=H_u+H_r,
\qquad r_j=0\quad (j\ge H_u),
\]

其中 \(H_r\) 是固定 BT recovery suffix。它至少覆盖最大命令延迟、队列冲洗和终端可恢复检查所需的时间，不能再使用只看到一两个命令生效周期的超短 horizon。为控制在线维数，前缀 residual 可采用少量分段常数或低阶基函数，而不是每个长预测 stage 都增加自由变量。

### 10.4 在线优化问题

同时构造两个从同一 execution-aligned 状态出发的预测：

```text
BT counterfactual：全域 r = 0
MPC candidate：短前缀 r != 0，随后固定 r = 0 并继续 BT
```

候选使用与真实发布一致的双通道 delay、FIFO、执行器和低阶液体动力学：

\[
\xi_{j+1}=F_{i_k+j}(\xi_j,u_j).
\]

目标函数以 BT counterfactual 为比较基准，而不是把 artifact 当普通轨迹重新跟踪：

\[
J = \sum_{j=0}^{H-1}
\left(
\|e^{track}_j\|_Q^2+
\|z^\ell_j\|_{Q_\ell}^2+
\|r_j\|_R^2+
\|r_j-r_{j-1}\|_S^2
\right)
+V^{BT}_{i_k+H}(\xi_H).
\]

其中：

- tracking 项只奖励相对 BT counterfactual 的扰动恢复，不允许通过大幅改变完成时间制造改善；
- liquid 项使用控制器内部低阶状态，评价 residual 产生的增量液体响应及绝对液体能量；
- residual magnitude、slew 和累计作用均受罚；
- \(V^{BT}_i\) 是从第 \(i\) 相位继续执行 BT 到停稳尾段的 phase-indexed terminal value，不是普通几何终点代价。

由于 `r=0` 是显式候选，优化器在模型内不应返回比 BT 更差的解。考虑局部求解和模型误差，发布前仍要求

\[
J_{candidate}+m_{model}\le J_{BT},
\]

其中 \(m_{model}\) 在看 held-out 结果前由模型误差上界冻结。该比较是方法内的确定性 model-based dominance check，不使用经验成功标签或独立 Plant 真值。

### 10.5 小 residual 的硬权限

“小修正”必须由硬约束定义，不能只靠 `R` 权重希望优化器自行变小：

\[
|\delta v_j|\le g_{i_k+j}\epsilon_v,
\qquad
|\delta\omega_j|\le g_{i_k+j}\epsilon_\omega.
\]

还必须同时满足：

- `u_BT + r` 的线/角速度、加速度和角加速度限制；
- 相邻 residual 及最终实际发布命令的 slew 限制；
- residual 累计进度和航向作用预算
  \[
  \left|\sum_j\delta v_j\Delta t\right|\le E_s,
  \qquad
  \left|\sum_j\delta\omega_j\Delta t\right|\le E_\psi;
  \]
- 相对 BT counterfactual 的 pose、progress、液体状态和队列偏差 tube；
- 接近 actuator limiter、模型不连续区或尾段时自动减小 \(g_i\)，在预先冻结的 tail-entry phase 之前变为零。

\(\epsilon_v,\epsilon_\omega,E_s,E_\psi\) 必须从执行器余量、BT rate limit、模型误差和可恢复集合反推，不允许通过已查看的 9911--9915 效果反复搜索。

### 10.6 显式保护 BT 防晃相位

BT 的防晃效果来自完整 forcing 时序，而不是单个时刻液面最小。为防止 residual 破坏模态相消，至少约束 residual 对预测终端液体状态的增量响应：

\[
\Delta z_H^\ell
=z_H^{\ell,candidate}-z_H^{\ell,BT},
\qquad
\|W_\ell\Delta z_H^\ell\|_\infty
\le\epsilon_\ell(i_k+H).
\]

在线性化模型中，该量可以写成各 residual 对终端液体状态贡献的叠加：

\[
\Delta z_H^\ell
\approx\sum_{j=0}^{H_u-1}
\Phi^\ell_{H,j+1}B^\ell_j r_j.
\]

这相当于要求 residual 序列自身也满足一个小型输入整形/终端相消条件。越接近尾段，\(\epsilon_\ell(i)\) 越小；进入沉降和零命令尾段后必须为零或只保留数值容差。若在当前状态和权限下只有 `r=0` 能满足该条件，就发布 BT，而不是放宽液体终端约束。

### 10.7 相位索引的 BT 可恢复终端管

离线为每个 artifact phase 构造 15D 集合 \(\mathcal T_i^{BT}\)。其语义是：从集合中的状态撤销 residual、只执行 BT，仍能满足命令/液体约束并进入停稳尾段。

理想的鲁棒递推为：

\[
\mathcal T_i^{BT}=\left\{\xi:\
\pi_{BT}(\xi,i)\text{ 可执行},
F_i(\xi,\pi_{BT}(\xi,i),w)\in
\mathcal T_{i+1}^{BT},\ \forall w\in\mathcal W
\right\},
\]

终端从完整 settled tail set 反向构造，至少包含：

- 位置、航向、线速度、角速度和 progress；
- 四个低阶液体状态；
- 四个线速度 pending 命令和一个角速度 pending 命令；
- 对应 phase 的命令、液体和状态约束余量。

工程实现分两级：

1. 先沿 artifact 和 BT 闭环线性化 15D deviation dynamics，通过 backward Riccati/robust predecessor 得到 phase-indexed ellipsoid 或 box tube；
2. 再用控制器模型的非线性 BT-only rollout 检查候选首拍及 recovery suffix。独立 Plant 只作实验评价，不能参与在线接纳。

若集合仅由有限采样和 rollout 拟合，只能称为 `empirical BT-recoverable tube`，不得宣称递归可行性或鲁棒安全证书。只有完成不确定性集合、反向可达性和闭环不变性验证后，才能提升主张等级。

在线 candidate 必须满足

\[
\xi_H^{candidate}\in\mathcal T_{i_k+H}^{BT}.
\]

若当前 BT-only counterfactual 本身不能到达相应 tube，则本周期不启用 residual；这不是放宽约束的理由。

### 10.8 尾段重接方式

路线 C 的最小版本不需要在运动早期进入旧 Tail-Commit。它通过三件事自然回到 BT：

1. 每个 OCP 都包含 `r=0` 的 BT recovery suffix；
2. phase-indexed terminal tube 逐步收紧到 settled tail set；
3. authority envelope \(g_i\) 在 tail-entry 之前单调降到零，之后同一 trial 不再重新打开 residual。

tail-entry 合同至少要求：

\[
\|W_\ell(z^\ell-z_i^{\ell,BT})\|_\infty\le\epsilon_{tail}^\ell,
\quad
\|W_q(q-q_i^{BT})\|_\infty\le\epsilon_{tail}^q,
\quad r=0.
\]

这样最终发布序列连续地退化为 BT，而不是在尾端从一个自由 S-MPCC 命令突然切回 artifact。只有该核心方法先证明有增量价值后，才考虑复用 `TailCommitStateMachine` 做一个单调的 residual-disable lifecycle lock；不得再次用早期 Tail-Commit 掩盖 residual 实际没有作用的问题。

### 10.9 运行时流水线与失败语义

每周期固定顺序为：

```text
观测＋最终命令 history
        ↓
预计发布时刻 15D execution alignment
        ↓
BT counterfactual 闭环 rollout
        ↓
小 residual OCP＋固定 BT recovery suffix
        ↓
terminal tube＋liquid response＋model dominance 检查
        ↓
通过：u_BT + residual      失败：原样 u_BT
        └──────────┬──────────┘
                   ↓
          唯一 PublicationTransaction
                   ↓
        receipt/history/Plant 的唯一命令事实
```

确定性的 limiter、supervisor cap 和双通道延迟必须进入预测或在最终命令上重新验证；不能优化一个命令、实际发布另一个被静默裁剪的命令。未知执行扰动由 receipt/history 在下一周期进入 execution alignment，并由冻结的不确定性 tube 吸收。

方法只允许以下 fallback：

- solver 不可用、超时或非有限；
- residual/tube/terminal/dominance 合同不通过；
- 最终命令会被未建模的普通 pipeline 改写；
- 当前相位已经进入 residual-off 区间。

这些情况均发布 BT，不触发 controlled stop。若大量周期都 fallback 或 residual 数值上退化成零，则方法按机制判据 No-Go，不能靠“仍然完成任务”宣称成功。

### 10.10 与两个已失败候选的区别

| 项目 | 老全命令 S-MPCC | 原 PR-RMPC/Tail-Commit | 新路线 C |
| --- | --- | --- | --- |
| BT 的角色 | 普通时序参考 | 后备/尾段来源 | 每个预测 stage 的名义闭环策略 |
| 在线权限 | 自由完整 `v/omega` | residual，但增量价值未成立 | 硬限幅小 residual，累计权限受限 |
| phase | 老 `s/v_s` 结构仍可主导 | 离散 rejoin/commit | artifact clock 固定，不优化 phase |
| delay state | 10D OCP 外部适配 | 15D 短 horizon | 15D 直接进入 residual deviation prediction |
| residual 之后 | 无强制 BT-only suffix | 早期 commit 后基本执行 BT | 每次优化内都强制固定 BT recovery suffix |
| 液体终端 | 只有普通 cost/窗口 | 经验 gate 与尾段接纳 | residual 增量液体响应硬约束＋phase-indexed terminal tube |
| 失败时 | direct 验证中不能回退 | BT/Tail-Commit | exact BT 是方法定义内的零 residual |
| 方法身份 | `G-SMPCC-BT` | 原 C3/C4 | 全新 backend/config/implementation ID |

代码上不得修改或复用老 solver 的 implementation ID。建议新建独立的：

- `BtClosedLoopCounterfactualRollout`；
- `BtResidualMpcSolver`；
- `BtRecoverableTubeArtifact`；
- `bt_residual_monitor` / `bt_residual_direct` runner modes；
- condition、telemetry、analyzer 和 campaign schema。

可以复用 15D execution builder、BT policy、artifact loader 和唯一命令事务，但不复用旧经验 gate 作为核心终端证明。

### 10.11 最低成本的分阶段验证

不直接开发完整长路线，先按以下顺序作一次结构 Go/No-Go：

#### CR0：离线结构可行性

- 沿冻结 BT artifact 生成 15D closed-loop linearization、terminal value 和初版 recoverable tube；
- 在名义状态及 D1/D2 合理状态包络上，求解“短 residual prefix＋BT recovery suffix”；
- 检查是否存在非零 residual，既能带来预测 tracking 改善，又能满足命令、累计 phase、液体终端和 tube 约束；
- 若绝大多数状态只有 `r=0` 可行，或改善必须依赖放大 residual/放松液体终端，立即停止路线 C，转路线 B。

#### CR1：闭环不变量和 monitor

- `r=0` 的全链路命令必须与 BT bitwise/容差内一致；
- candidate 与 BT 使用同一个 execution-aligned 初态、cap 和 publication model；
- monitor 只发布 BT，记录 predicted candidate、BT counterfactual、terminal tube margin、液体终端增量和求解时间；
- 先跑一个未用于调参的 D1 canary；任何非有限、tube 假通过、terminal prediction 明显失配或 30 Hz 超时都停止。

#### CR2：direct canary

- 只允许通过全部结构合同的第一拍 residual 发布；其他周期 exact BT fallback；
- 先跑一个 D1 direct canary，再跑一个 D2 direct canary；
- 任一 canary 未完成、tracking 明显变差、完整/尾段液面越界，或方法主要靠 fallback/零 residual，立即 `NO_GO_ROUTE_B`。

#### CR3：冻结 5-seed development 对比

canary 通过后才冻结权重、tube、residual bounds、authority schedule、seeds 和 analyzer。比较：

| 条件 | 用途 |
| --- | --- |
| C-BT | exact BT 基线 |
| C-RES-MONITOR | 只发布 BT，验证预测与机制 |
| C-RES-DIRECT | 完整路线 C |
| C-RES-NO-LIQUID-TERMINAL | 仅作消融，不能作为可发布主方法 |
| C-RES-NO-DELAY | 仅作消融，解释 15D 对齐作用 |

9911--9915 已经被查看，只能用于回归和失败复现，不能再作为新方法的未见效果证据。路线 C 必须在运行前冻结一组新的 development seeds；正式实验还要再使用独立的新 seeds/session。

### 10.12 路线 C 的冻结通过条件

除重新冻结的 tracking、液面和完成时间判据外，还必须同时满足机制合同：

1. D1/D2 下 BT 和路线 C 均为 5/5 完成，无方法导致的 controlled stop；
2. tracking 主指标每类至少 4/5 改善，配对中位改善达到预先冻结的实质阈值；
3. 完整过程和 fixed-tail 液面相对 BT 非劣；
4. 所有实际发布 residual 均满足 pointwise、slew、累计 phase、liquid terminal 和 terminal tube 约束；
5. residual-off tail 区间内实际 residual 为零，液体和五个 pending commands 位于冻结 tail-entry 容差内；
6. 非零 residual 和 candidate acceptance 占比达到预先冻结的最低值，不能退化成 BT；
7. prediction-to-observation 误差位于冻结模型误差 envelope 内，不能依赖独立 Plant 真值在线修正；
8. p99 端到端控制耗时低于 30 Hz 预算，deadline miss 为零；
9. 完成时间没有通过显著变慢换取 tracking 或液面改善。

任何关键条件失败，都停止修改 residual 权限、terminal tube 或 acceptance 阈值，不再叠加经验 gate 和新状态机，直接采用第 4 节的低维在线相位重定时。

### 10.13 建议实施顺序

```text
CR0 冻结方法定义、状态/命令语义和不确定性边界
 ↓
CR1 构造 BT closed-loop counterfactual 与 15D deviation model
 ↓
CR2 离线 backward terminal value / recoverable tube
 ↓ 结构可行性失败 → 路线 B
CR3 小 residual QP/OCP＋固定 BT recovery suffix
 ↓
CR4 unit/property tests＋单 seed monitor
 ↓ monitor 失败 → 路线 B
CR5 D1/D2 direct canary
 ↓ canary 失败 → 路线 B
CR6 冻结新 development seeds 和 5-seed campaign
 ↓
CR7 通过后才做消融、正式仿真和是否需要 lifecycle lock 的评估
```

最近一步不是写完整在线 solver，而是完成 CR0--CR2 的离线结构可行性包：明确 15D deviation dynamics、residual 权限、BT recovery suffix 长度和 phase-indexed terminal tube。如果在这一步无法证明存在有用的非零可行 residual，就不进入在线实现。

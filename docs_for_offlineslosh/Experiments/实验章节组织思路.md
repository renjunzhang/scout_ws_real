# Phase-Rejoining Residual S-MPCC：Experiments 章节组织思路

> 文档定位：规定论文实验要回答的问题、公平比较链、放行门、指标和统计规则。它不是已完成结果，也不授权直接进入实物 `enforce`。
>
> 当前结论：Phase-Rejoin 已完成 development 模块、单元测试和 S0–S4 proxy 分支验证，但双通道前沿仍有 B0 因果/时间索引缺口；正式 OfflineSloshOCP artifact、held-out empirical gate、新实物 runner 和防晃性能证据均未完成。

## 1. 实验最终要证明什么

整章围绕一个问题：

> 在冻结路径和容器条件下，考虑 Scout 的真实执行延迟与惯性后，完整离线防晃尾段、双通道联合预测中的有限 residual 和前沿后终端重接检查，能否降低独立 RGB 测得的液面晃动，同时不以明显更慢、跟踪更差或更多失败换取结果？

“改善”不能笼统地写成相对旧 S-MPCC 或内部液体模型，而应分成：

- **唯一 primary comparator：**完整方法 C4 相对普通 MPCC C0；
- **固定顺序的公平性检验：**主比较通过后，再检验 C4 相对 SmoothMatch C1，排除“只是更慢/更平滑”；
- **系统证据阶梯：**C0–C4 展示从普通控制到完整系统的总体差异，但不直接当作单因素因果链；
- **组件归因：**用第 3.2 节的严格配对消融分别判断离线液体目标、在线 residual、执行模型与 recovery 机制。

只有独立 RGB 主指标正向、任务指标满足预注册公平性且失败率没有恶化，才可称“防晃性能改善”。内部 slosh monitor 方向正向只能解释机制，不能替代真实液面结论。

### 1.1 避障与路径范围

当前实验是**静态净空环境中的冻结路径跟踪**，不是在线避障实验：

- `corridor_enable=false`、`obstacle_enable=false`、`homotopy_enable=false`；当前主线 backend 对启用这些功能会拒绝初始化。
- MBF 可在试验前生成一条候选全局路径，但必须冻结点列、坐标系与 hash，并据此重新生成 OfflineSloshOCP artifact。
- trial 运行中不根据新障碍实时绕行。若人员或独立安全系统发现障碍，应终止 trial 并请求停车；下一次 trial 前再离线重规划并重建 artifact。这不是当前 planner 的自动障碍检测功能。
- 动态障碍不属于首篇论文主张。预先生成并冻结的 MBF 路径最多是“另一种路径来源”的泛化实验，不能写成在线避障能力。

## 2. 研究问题与证据

| 研究问题 | 要回答的内容 | 主要证据 |
| --- | --- | --- |
| RQ1 执行与总 lead 是否可信 | 双通道执行模型能否预测真实运动；总 lead 内液体预测和第一拍控制作用是否可用 | held-out 命令—Nokov/odom—IMU/RGB 回放、G0 |
| RQ2 防晃是否真实正向 | C4 是否相对 C0/C1 降低真实液面，且任务公平 | 正式配对实物 RGB、完成时间、tracking、失败率 |
| RQ3 各模块为什么有效 | OfflineSloshOCP、执行模型、有限 residual 分别贡献什么 | A0–A3 严格配对消融；C0–C4 只作系统证据阶梯 |
| RQ4 经验 gate 是否有用 | gate 的误判率、实际重接率以及 gate 外降级是否正确 | held-out 仿真/回放、少量安全实物偏离 |
| RQ5 系统是否可运行 | 30 Hz、合同检查、安全覆盖与求解失败是否合格 | solver/runtime/diagnostic/command-chain 统计 |

RQ1 是进入在线方法的必要条件；RQ2 决定论文能否声称真实防晃收益；RQ3 和 RQ4 才支撑核心机制解释；RQ5 只证明可部署性，不单独构成算法创新。

## 3. 系统比较阶梯与严格组件消融

### 3.1 核心条件

| 条件 | 精确定义 | 它回答什么 |
| --- | --- | --- |
| **C0 OrdinaryMPCC** | 无液体状态/代价、无 OfflineSlosh、无执行前沿重接和 recovery gate；保留普通 contour/lag/progress 与公共安全链 | 完整方法相对普通 MPCC 的端到端收益 |
| **C1 SmoothMatch** | 在 C0 基础上使用独立 development 数据冻结平滑权重，只允许用一个全局速度/时间尺度匹配 C4 完成时间；速度、加速度和 jerk 包络只设容差并完整报告 | 排除收益只是因为更慢或更平滑 |
| **C2 OfflineReplay** | 使用与 C4 完全相同的正式 OfflineSloshOCP artifact、起点、底盘控制和发布/安全链；按冻结时钟推进，令在线 $\delta u=0$，不启用 gate 或保存动作 | 完整离线相位抵消本身是否有效 |
| **C3 ResidualNoGate** | 与 C4 使用相同 artifact、双通道 delay-augmented OCP/等价 bridge、相位候选、residual 边界和安全链；terminal empirical gate、执行兼容约束与 stored action 关闭，所有 solver-feasible 修正均视为放行；solver/候选/合同失败时确定性请求 $(0,0)$ | 无恢复判据的在线系统表现 |
| **C4 Full** | 双通道 delay-augmented 执行对齐、邻近相位选择、有限 residual、terminal empirical gate＋执行状态兼容约束、stored recovery action 与 fail-closed 全部启用 | 完整目标方法 |

比较时，路径、容器、起始 pose/yaw、初始液位与液体静置/zero-lock、机器人约束、定位、底盘内部控制器、最终 limiter、安全门和终止规则必须相同，并由 trial manifest 记录有效参数。

C0–C4 是便于读者理解系统层级的**比较族**，不是逐项单因素消融：例如 C1→C2 同时改变在线/离线结构，C2→C3 同时引入相位对齐和 residual。组件因果结论只能来自下面的严格配对。

这些是**目标实验协议，不是当前已有开关**。当前 runtime 只有 `phase_rejoin=off|monitor|enforce`：尚无 C2 的冻结时钟零 residual runner，也无 C3 的“保留 nominal-relative OCP、同时关闭 solver/post gate 与 stored action”模式；用超宽 gate 近似 C3 会改变失败语义，禁止这样替代。

### 3.2 严格组件消融

| 配对 | 额外条件 | 两边唯一计划差异 | 可支持的结论 |
| --- | --- | --- | --- |
| **A0：OfflineSmoothReplay vs C2** | OfflineSmoothReplay 使用相同执行模型、离线求解/回放链、时间网格和约束，但液体目标权重为 0 | 是否启用离线液体目标 | OfflineSloshOCP 完整相位安排的价值 |
| **A1：PhaseAlignedNoResidual vs C3** | PhaseAlignedNoResidual 使用相同 artifact、执行前沿、候选相位和 fallback，但强制 $\delta u=0$ | 是否启用有限 residual | residual 的独立价值 |
| **A2：C3 vs C4** | 两边使用相同 residual OCP；按上表冻结失败 fallback | terminal gate、执行兼容约束与 stored recovery action 这一联合机制是否启用 | recovery 机制的控制收益；不能单凭该对比拆分内部组件 |
| **A3：IdealExec vs IdentifiedExec** | 相同离线/在线结构、路径、液体模型与约束，只改变冻结执行模型及其一致 artifact | 是否使用已辨识双通道执行模型 | 执行感知模型的价值 |

如需单独识别“相位对齐”本身，再比较 C2 与 PhaseAlignedNoResidual；这项不默认进入主论文矩阵。

### 3.3 不可混用的旧名字

- `B_slosh_matched0/5` 只是旧 100 ms 液体代价消融，不等于 C0、C3 或 C4。
- 历史 `B_smooth` 不是针对新 C4 调出的 SmoothMatch，不能直接充当 C1。
- 旧在线 S-MPCC 可作为 legacy comparator，但不能代替 C0–C4 的系统证据阶梯，也不能代替 A0–A3 的严格配对消融。
- ZV 固定曲线可作为传统外部参考；`mpc_local_planner`、TEB 或 DWA 只能作系统级参考，不负责证明本文机制。

## 4. 平台、路径与冻结资产

### 4.1 平台和测量链

实验平台至少记录：

- Scout Mini 的最终发布命令、底盘反馈和安全改写；
- Nokov/定位位姿与 source timestamp；
- odom 与 processed IMU；
- 独立 RealSense RGB 液面测量及有效标志；
- 内部 slosh observer、execution-front 状态、相位候选、gate metric、求解状态和最终命令。

RGB 是物理主测量，内部低阶模型和 slosh monitor 是解释性测量。二者必须分别报告，不能相互替代或只选择方向有利的一路。

### 4.2 路径层级

建议只设两个层级：

1. **P-core：**高激励、可重复、静态净空的冻结核心路径，用于全部主结果；
2. **P-MBF（可选）：**MBF 在静态地图中预先生成、随后冻结的第二路径，用于路径来源泛化。

只有 P-core 全部门通过后才运行 P-MBF。每条路径拥有独立 path hash、碰撞复核和 OfflineSloshOCP artifact；不能让两条路径共用一个恢复对象。

### 4.3 每个 release 必须冻结

- Git commit、构建产物、配置 dump 和实验协议 ID；
- 地图/`.pbstream`、TF、footprint、路径点列及 SHA-256；
- 执行模型、液体模型、容器、装液量和温度范围；
- RGB 标定、相机设置、ROI、时间偏差及文件 hash；
- OfflineSloshOCP artifact、gate schema、合同 ID 和 SHA-256；
- C0–C4 的有效参数、运行顺序、主指标窗口与停止规则。

旧 G3R3 的路径、RGB 标定和 runner 只能作为 development 参考，不能自动继承为新 Phase-Rejoin 正式资产。

## 5. 正式实验前的 G0–G4 放行门

| Gate | 必须完成的检查 | NO-GO 后的处理 |
| --- | --- | --- |
| **G0 因果前沿、完整 lead 与可控性** | 先证明快通道在共同前沿前对新命令的依赖已进入模型，且物理 epoch 与 $n_f\Delta t$/artifact 索引一致；再以 $t=t_c+\widehat d_c$ 验证名义完整 lead $(t-t_s)+n_f\Delta t+N_\ell\Delta t$，并报告实际 $d_c$ 及 $d_c-\widehat d_c$ 的分布/边界。联合终端相对预计发布时刻约 333.3 ms；另验证第一拍灵敏度、约 4.97 Hz IMU 幅相与跨工况延迟稳定性 | 将实现改为双通道 delay-augmented OCP 或严格等价的凝聚 bridge，并统一时间索引；仍不通过则降低延迟、增加真实液体校正，或退回离线前馈＋低频纠偏 |
| **G1 正式离线 artifact** | 真正由 OfflineSloshOCP 生成；完整 slowdown–settle–zero-hold 尾段；命令和状态约束通过；路径/模型/容器合同与 hash 完整 | 修正离线求解与终端所有权，不进入在线 gate |
| **G2 RGB 可检测性** | source timestamp 正确；motion+tail 有效率；标定复现；噪声、零漂、延迟和最小可检测差异可接受 | 修复测量链或扩大可辨识激励，不能改用内部 monitor 代替 |
| **G3 held-out empirical gate** | fit、tuning、test 按完整 trial 分离；冻结并覆盖执行状态兼容集；报告 coverage、false-accept、false-reject 和实际重接；禁止 development 人工半径进入正式 artifact | 重建保守 gate/兼容集或放弃 recovery 主张 |
| **G4 小规模 development 配对** | C0–C4 命令链、完成时间匹配、RGB 方向、tracking、residual 分离度、gate 分支和 recorder/postflight 均可审计 | 修正协议或方法，不扩大正式样本数“碰结果” |

G0–G4 全部通过后才能冻结 formal release 和随机表。表中的“可检测、可接受、稳定、正向”等词都必须在相应 test 数据解盲前换成数值门槛、区间规则与失败动作。任一门失败时，应保留 NO-GO 记录，不能通过扩大 gate、放宽 residual、允许 development artifact 或删掉失败 trial 绕过。

### 5.1 当前工程 NO-GO 清单

- 当前 predictor 仍是 history-only exact-$d_f$ 传播，而 selector 使用 $n_f=\lceil d_f/\Delta t\rceil$；差分延迟的新命令依赖和约 13.3 ms 的 epoch/index 偏差尚未解决，G0 结构门直接 NO-GO。
- 当前只有 9 维 development gate，未实现终端 buffer/惯性状态兼容集；不同 pending history 可在相同 9 维误差下导致不同恢复结果，G3 同样 NO-GO。
- 当前实物 runner 未统一传递双通道 time constant、完整历史、Phase mode、artifact/contract/frame 等参数；C2/C3/C4 的正式 runner 均不存在。
- 当前 recorder 未强制记录 `/spmpc/debug/phase_rejoin`，现有 short-horizon postflight 只验证旧 `B_slosh_matched0/5`，不能放行新比较族。
- 当前 phase analyzer 默认使用 `/slosh/height` proxy 且命令 topic 与实物 runner 默认值不一致；正式主分析必须重建为离线 RGB max-LCR、C0–C4/A0–A3 和 failure-inclusive 口径。
- 当前本机 10 维、$N=3$ codegen 可运行，但生成物被 Git 忽略、未纳入安装且依赖工作区路径；正式 release 必须生成、安装、冻结 hash 并做干净机复现。未来 delay-augmented solver 还需新的 schema/codegen 证据。

## 6. 数据划分与实验阶段

### 6.1 互斥数据池与锁定顺序

| 数据池 | 用途 | 锁定规则 |
| --- | --- | --- |
| $D_{\mathrm{id,fit}}$ / $D_{\mathrm{id,test}}$ | 执行与液体模型拟合 / 独立总 lead 验证 | test 不参与模型选择 |
| $D_{\mathrm{gate,fit}}$ / $D_{\mathrm{gate,test}}$ | gate 构造 / 独立分类与重接评价 | test 不调半径或阈值 |
| $D_{\mathrm{dev,tune}}$ / $D_{\mathrm{dev,pilot}}$ | C1/C4 与流程开发 / 冻结后的 G4 小样本检查 | pilot 后不得回调参数；若回调则另开新 pilot |
| $D_{\mathrm{main,confirm}}$ / $D_{\mathrm{recovery,confirm}}$ | 主物理效果 / 组件与恢复确认 | 两者均在 release 冻结后采集并分别统计 |

数据池按完整 trial 或完整 block 划分，禁止把同一条轨迹相邻帧随机拆成 train/test，也禁止把 main confirmation 的结果用于修改 recovery 协议后仍声称同一冻结 release。

### 6.2 分阶段执行

#### E0：测量与执行链辨识

- 分别辨识线/角延迟、惯性、增益和适用域；
- 用未参与拟合的完整 trial 比较纯延迟、一阶模型和候选数据模型；
- 验证 Nokov、odom、IMU、RGB 和命令的 source-time 对齐；
- 完成 G0 的总 lead、主频幅相和首拍灵敏度检查。

这一阶段只回答模型是否可信，不证明防晃有效。

#### E1：OfflineSloshOCP 与 artifact 验证

- 对 P-core 生成完整名义序列与终端尾段；
- 检查全部状态/命令约束、非现实尖峰、终点截断和 artifact 合同；
- 在参数扰动和非线性液体仿真中比较 OfflineSmoothReplay 与 C2；
- 用 actual-input replay 区分“执行模型误差”和“液体模型误差”。

#### E2：empirical gate 构造与 held-out 验证

- 在 $D_{\mathrm{gate,fit}}$ 上按相位构造 gate；
- 在 $D_{\mathrm{gate,test}}$ 的独立 rollout/replay 上形成混淆矩阵；
- 记录 gate coverage、实际重接率和 false-safe；
- 单独验证 stored recovery action 被提出、通过安全链和真正发布的比例。

#### E3：小规模 development 实物

- 只在 $D_{\mathrm{dev,tune}}$ 调整 C1/C4 和流程，随后冻结候选；
- 用新的 $D_{\mathrm{dev,pilot}}$ 完成 C0–C4 命令分离、RGB 可检测性、trial 窗口与停止规则检查；
- pilot 只决定 G4 GO/NO-GO，不再回调参数；
- 只用于 G2/G4，不进入正式论文效果统计。

#### E4：冻结路径主实物确认

- 在 P-core 上运行预先生成的随机平衡 block；
- 主性能矩阵比较 C0、C1、C2、C4；
- 同时保留所有失败、停车和数据采集故障标签；
- 该阶段决定 RQ2 能否给出正向结论。

#### E5：组件与恢复实验

- 在 $D_{\mathrm{recovery,confirm}}$ 使用 A1、A2 及 gate 分类评价分解 residual 与 recovery 机制；
- 使用预注册的小初始位姿偏差、附加命令延迟/限幅或短时速度门；
- 大规模不可恢复样本优先在仿真/回放中测试，实物只做已安全审查的边界确认；
- 禁止用不可重复的人工推车或动态障碍作为正式扰动。

P-MBF、第二容器和更多载荷只作为核心结论通过后的扩展，不阻塞首篇论文。

## 7. 建议的实验矩阵

不要把所有条件塞进同一个大矩阵。用相互衔接的小矩阵回答不同问题：

| 矩阵 | 条件 | 场景 | 主要结论 |
| --- | --- | --- | --- |
| M1 主效果 | C0、C1、C2、C4 | P-core、名义起点 | 普通控制、平滑公平性、离线计划和完整方法的真实 RGB 差异 |
| M2 组件消融 | A0、A1、A2 的成对条件 | 名义与小幅预注册偏差 | 离线液体目标、有限 residual 和 recovery 联合机制各自的作用 |
| M3 执行模型消融 | A3：IdealExec vs IdentifiedExec | 成对仿真；历史回放只评 prediction；必要时独立小规模实物评 efficacy | 区分运动/激励预测收益与最终控制收益 |
| M4a gate 分类 | 冻结 C4 gate，不需要 C3 | $D_{\mathrm{gate,test}}$ 的独立标签 | coverage、false-accept、false-reject 和最差相位 |
| M4b recovery 控制 | C3 vs C4 | $D_{\mathrm{recovery,confirm}}$ 仿真/回放＋少量安全实物边界 | failure-inclusive 重接、停车和真实液体结果 |

五级系统证据阶梯由 M1 与 M4b 合并展示，不能要求指标逐级单调，也不能替代 M2–M4 的组件证据：

```text
C0 OrdinaryMPCC
→ C1 SmoothMatch
→ C2 OfflineReplay
→ C3 ResidualNoGate
→ C4 Full
```

正式重复次数不沿用旧 40/64/88 矩阵。最小有意义效应（SESOI）先依据 freeboard 风险、物理意义和 RGB 最小可检测差异确定；再用与 confirmation 分离的 pilot 估计 block 内差值方差，冻结功效分析、样本量和随机表。

## 8. 指标与“正向”的判定

### 8.1 唯一物理主指标

建议冻结为：

$$
Y_{\mathrm{RGB}}=
P95_{\mathrm{motion+tail}}
\big(\mathrm{max\mbox{-}LCR}_{\mathrm{RGB}}(t)\big).
$$

motion 起点、到点判定、tail 长度、无效帧规则、单位和左右标尺合成方式必须在 formal freeze 前固定。若最终选择别的 RGB 指标，也只能有一个主指标，不能看完结果再在 peak、RMS 与 P95 中挑最有利者。

### 8.2 关键次指标

**真实液体：**RGB RMS、peak、tail RMS、settling time、有效帧率和左右标尺一致性。

**任务：**完成时间、到达/停车/失败、contour/yaw RMSE 与 P95、终点误差。

**运动公平性：**$v$、$\omega$、加速度、角加速度、jerk、命令频谱和完成时间包络。

**方法机制：**名义偏差、第一拍 residual、饱和比例、相位索引跳变、gate coverage、实际重接时间、stored action 提出率与真实发布率。

**实时性：**solver p50/p95/max、超过 $33.3\,\mathrm{ms}$ 的比例、实际发布频率、求解失败、状态过旧、合同失效和安全改写比例。

内部 slosh monitor 的 peak/RMS/相位只能作为 secondary mechanism outcome，必须与 RGB 并列画图并报告不一致情形。

### 8.3 什么条件下才叫改善

C4 的 confirmatory 判断采用固定顺序：先检验 C4 相对 C0 的主比较；通过后才检验 C4 相对 C1 的平滑公平性比较。两者使用同一个预注册 RGB 主指标，但以 fixed-sequence gatekeeping 控制多重性。可以声称“相对普通 MPCC 改善”至少需要：

1. 相对 C0，独立 RGB 主指标的配对效应及区间达到预注册 SESOI；
2. 若进一步声称收益不是减速/平滑造成，C4 相对 C1 的固定第二检验也通过；
3. 完成时间和 tracking 落在预注册 non-inferiority margin 内；
4. 成功率、停车、求解失败和安全事件满足预注册 margin 或零事件率上界；
5. 只对实际通过 A0–A3 的模块给出组件归因，不要求 C0–C4 指标逐级单调。

若 RGB 降低但明显更慢、路径误差更大或失败更多，只能报告 trade-off，不能写“总体优于普通 MPC”。

## 9. recovery gate 的专门评价

必须先冻结“实际恢复成功”的独立标签。仿真使用未参与建 gate 的高保真模型/真状态、真实约束、执行状态兼容条件和尾段结果；实物使用独立 RGB、任务完成、安全约束与预注册 tail 阈值。内部 9 维 observer/gate 误差只作解释，不能同时充当预测器和 ground truth。

混淆矩阵只在执行状态兼容集内评价 9 维 empirical gate；兼容集外直接判为不可放行，并单独报告其拒绝率。

| gate 判断 | 实际恢复成功 | 实际恢复失败 |
| --- | ---: | ---: |
| 可恢复 | true accept | **false accept / false-safe** |
| 不可恢复 | false reject | true reject |

主要报告：

- false-accept 及其区间，而不只报总体 accuracy；
- false-reject 和正常运行 coverage；
- 执行状态兼容集的 coverage 与拒绝率；
- 每个相位的样本覆盖与最差相位；
- 从偏离到重接所需时间；
- gate 外是否按合同请求 $(0,0)$；
- stored action 被提出后，是否被 limiter/安全层覆盖，以及最终实际发布了什么。

用于拟合 gate 的 rollout 不能再次进入该表。若只有 Monte Carlo 椭球结果，论文仍只能称 empirical gate/set。

## 10. 随机化、失败和统计规则

- **统计单位：**一次完整 trial；视频帧、控制周期和路径采样点不是独立样本。
- **随机化：**同一 block 内各条件各运行一次，使用预先生成的平衡顺序；电量、温度、装液、地面和日期作为 block 元数据。
- **开发隔离：**模型选择、权重、SmoothMatch、gate 阈值和异常规则冻结后，才能采集 $D_{\mathrm{main,confirm}}$ 与 $D_{\mathrm{recovery,confirm}}$。
- **失败保留：**方法失败、求解失败、安全停车和超时均属于结果；只有预先定义的外部采集故障可以补做，并保留原 attempt。
- **主分析：**报告每个 block 的原始配对差、稳健汇总、效应量与置信/可信区间；补充 leave-one-block-out 敏感性。
- **多重结果：**只对一个主指标作 confirmatory 判断；C0/C1 两个比较按预注册 fixed-sequence gatekeeping；secondary 指标报告完整结果及必要的多重比较控制。
- **不提前停在有利方向：**futility 或 safety stop 规则须预注册；不得看见正向后提前结束或负向后临时扩样。
- **可追溯性：**每个图表能追溯到 manifest、bag、分析脚本版本、排除原因和原始 trial ID。

## 12. 最终 Experiments 章节顺序

正式论文建议按下列顺序写，避免先展示有利结果再补协议：

1. **IV-A Research Questions and Scope：**RQ1–RQ5、冻结路径和无在线避障边界；
2. **IV-B Platform and Protocol：**平台、容器、P-core、传感器、RGB 主指标、资产冻结和数据划分；
3. **IV-C Comparators：**C0–C4、公平控制量与可选 legacy comparator；
4. **IV-D Model and Artifact Validation：**G0、执行模型、总 lead、OfflineSloshOCP 与 G1；
5. **IV-E Main Physical Results：**M1 的 RGB、任务和失败结果，回答 RQ2；
6. **IV-F Ablations：**M2/M3，解释离线计划、执行模型和 residual；
7. **IV-G Recovery Evaluation：**M4 混淆矩阵、实际重接与 fail-closed；
8. **IV-H Runtime and Limitations：**30 Hz、极端超时、适用域、无在线避障和 empirical 证据边界。

整章最重要的逻辑不是“动作看起来更平滑”，而是依次证明：执行预测在总 lead 内可信，离线完整相位抵消在真实 RGB 上成立，有限 residual 有独立价值且受到限制，最后 empirical gate/执行兼容条件能减少错误放行。

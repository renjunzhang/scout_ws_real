# Phase-Rejoining Residual MPC（PR-RMPC）：Experiments 章节组织思路

> 文档定位：规定论文实验要回答的问题、公平比较链、放行门、指标和统计规则。它不是已完成结果，也不授权直接进入实物 `enforce`。
>
> 当前结论：PR-RMPC 的 source-level 方法合同已经实现，包括共同预计发布时刻、22 维 unequal-delay 增广状态、十步 Full SQP、V3 artifact、完整预测域 $\mathcal B^{\mathrm{exec}}$、冻结的有界恢复反馈和唯一最终命令事务；C0–C4/IS 的 strict independent-plant runner 也已存在。但本轮工作树修订尚未形成新的 clean commit、formal session 或 readiness。历史 commit `7775dd68` 的 `READY_NOT_EXECUTED` 只证明该旧资产链内部一致，不能授权当前 dirty revision；人工 approval 未签发，正式 96 trials 为 0/96，实物验证也尚未开始。因此当前只能主张“方法已实现”，不能主张防晃性能正向或授权实物 `enforce`。

## 1. 实验最终要证明什么

整章围绕一个问题：

> 在冻结路径和容器条件下，考虑 Scout 的真实执行延迟与惯性后，完整离线防晃尾段、双通道联合预测中的有限 residual 和前沿后终端重接检查，能否降低独立 RGB 测得的液面晃动，同时不以明显更慢、跟踪更差或更多失败换取结果？

“改善”不能笼统地写成相对 legacy S-MPCC 或内部液体模型，而应分成：

- **唯一 primary comparator：**完整方法 C4 相对普通 MPCC C0；
- **固定顺序的公平性检验：**主比较通过后，再检验 C4 相对 SmoothMatch C1，排除“只是更慢/更平滑”；
- **系统证据阶梯：**C0–C4 展示从普通控制到完整系统的总体差异，但不直接当作单因素因果链；
- **组件归因：**当前只用 A2 严格判断 empirical gate enforcement；离线液体目标、在线 residual 和执行模型的独立价值须等 A0/A1/A3 扩展条件另行实现并冻结后再判断。

只有独立 RGB 主指标正向、任务指标满足预注册公平性且失败率没有恶化，才可称“防晃性能改善”。内部 slosh monitor 方向正向只能解释机制，不能替代真实液面结论。

### 1.1 避障与路径范围

当前实验是**静态净空环境中的冻结路径跟踪**，不是在线避障实验：

- `corridor_enable=false`、`obstacle_enable=false`、`homotopy_enable=false`；当前主线 backend 对启用这些功能会拒绝初始化。
- MBF 可在试验前生成一条候选全局路径，但必须冻结点列、坐标系与 hash，并据此重新生成 OfflineSloshOCP artifact。
- trial 运行中不根据新障碍实时绕行。若人员或独立安全系统发现障碍，应终止 trial 并请求停车；下一次 trial 前再离线重规划并重建 artifact。这不是当前 planner 的自动障碍检测功能。
- 动态障碍不属于首篇论文主张。预先生成并冻结的 MBF 路径最多是“另一种路径来源”的泛化实验，不能写成在线避障能力。

## 2. 研究问题与证据

| 研究问题 | 要回答的内容 | 主要证据 |
| --- | --- | --- |
| RQ1 执行与总 lead 是否可信 | 双通道执行模型能否预测真实运动；总 lead 内液体预测和第一拍控制作用是否可用 | held-out 命令—Nokov/odom—IMU/RGB 回放、G0 |
| RQ2 防晃是否真实正向 | C4 是否相对 C0/C1 降低真实液面，且任务公平 | 正式配对实物 RGB、完成时间、tracking、失败率 |
| RQ3 各模块为什么有效 | empirical gate、OfflineSloshOCP、执行模型、有限 residual 分别贡献什么 | 当前严格 A2；A0/A1/A3 扩展实现后的配对证据；C0–C4 只作系统证据阶梯 |
| RQ4 经验 gate 是否有用 | gate 的误判率、实际重接率以及 gate 外降级是否正确 | held-out 仿真/回放、少量安全实物偏离 |
| RQ5 系统是否可运行 | 30 Hz、合同检查、安全覆盖与求解失败是否合格 | solver/runtime/diagnostic/command-chain 统计 |

RQ1 是进入在线方法的必要条件；RQ2 决定论文能否声称真实防晃收益；RQ3 和 RQ4 才支撑核心机制解释；RQ5 只证明可部署性，不单独构成算法创新。

## 3. 系统比较阶梯与严格组件消融

### 3.1 核心条件

| 条件 | 精确定义 | 它回答什么 |
| --- | --- | --- |
| **C0 OrdinaryMPCC** | 无液体状态/代价、无 OfflineSlosh、无执行前沿重接和 recovery gate；保留普通 contour/lag/progress 与公共安全链 | 完整方法相对普通 MPCC 的端到端收益 |
| **C1 SmoothMatchMPCC** | 在 C0 基础上使用只看任务/运动结果的独立 development seeds 冻结平滑设置；工程条件固定 `global_time_scale=1.0`。完整报告完成时间和运动包络，不宣称已与 C4 精确等时 | 检验收益是否只能由更慢或更平滑解释 |
| **C2 OfflineReplay** | 按冻结时钟回放 C4 所用 V3 artifact 的同一 final-command nominal sequence；在线 residual 恒为 0，不让 9 维 empirical gate 或 14 维执行兼容 gate 介入控制；保留公共 trial、最终发布记录和独立 plant 评价合同 | 完整离线相位安排本身的描述性价值；它不是 C4 的单因素消融 |
| **C3 ResidualNoGate** | 与 C4 共用同一 V3 artifact、邻近单调相位选择、十步 22 维 Full SQP、residual authority、完整预测域 $\mathcal B^{\mathrm{exec}}$、冻结的有界恢复反馈、失败语义和最终命令事务。9 维 empirical metric 在 NLP 与 supervisor 中均只计算/记录，不参与放行 | empirical gate 为 monitor-only 时的完整 residual 系统 |
| **C4 PhaseRejoinResidual** | 在 C3 的完全相同合同上 enforce 9 维 empirical gate：terminal gate 约束 residual 轨迹，current gate 约束 recovery admission；其余 22 维 OCP、$\mathcal B^{\mathrm{exec}}$、有界恢复反馈和发布链均不变 | 完整 PR-RMPC 方法 |

比较时，路径、容器、起始 pose/yaw、初始液位与液体静置/zero-lock、机器人约束、定位、底盘内部控制器、最终 limiter、安全门和终止规则必须相同，并由 trial manifest 记录有效参数。

C0–C4 是便于读者理解系统层级的**比较族**，不是逐项单因素消融：例如 C1→C2 同时改变在线/离线结构，C2→C3 同时引入相位对齐和 residual。组件因果结论只能来自下面的严格配对。

这些条件已经由独立 plant 的 strict condition files/runner 实现，不再是“尚待增加的目标开关”。特别是，C2 已有 final-command nominal replay runner；C3 也不是通过放宽 gate 半径近似，而是显式的 empirical monitor-only 语义。条件 schema 为兼容旧 v1 文件仍保留布尔键 `stored_recovery_action`；对 C3/C4，该键只能解释为“启用 V3 recovery 路径”的兼容性断言，实际控制律是随当前机器人误差计算并受幅值/发布速率限制的冻结反馈 $\kappa_j(e_r)$，绝不是逐相位保存的固定动作。论文不得把该 legacy 键名当作方法组件或消融因素。

### 3.2 严格组件消融与扩展计划

| 配对 | 额外条件 | 两边唯一计划差异 | 可支持的结论 |
| --- | --- | --- | --- |
| **A0：OfflineSmoothReplay vs C2** | OfflineSmoothReplay 使用相同执行模型、离线求解/回放链、时间网格和约束，但液体目标权重为 0 | 是否启用离线液体目标 | OfflineSloshOCP 完整相位安排的价值 |
| **A1：PhaseAlignedNoResidual vs C3** | PhaseAlignedNoResidual 使用相同 artifact、执行前沿、候选相位和 fallback，但强制 $\delta u=0$ | 是否启用有限 residual | residual 的独立价值 |
| **A2：C3 vs C4** | 两边共用同一十步 22 维 Full SQP、V3 artifact、residual authority、全时域 $\mathcal B^{\mathrm{exec}}$、有界恢复反馈、失败语义和最终命令事务 | **唯一差异：**同一 9 维 empirical gate 是 monitor-only（C3）还是 enforce（C4） | empirical admission rule 的因果贡献；不能归因于 $\mathcal B^{\mathrm{exec}}$ 或 recovery policy，因为两边均启用它们 |
| **A3：IdealExec vs IdentifiedExec** | 相同离线/在线结构、路径、液体模型与约束，只改变冻结执行模型及其一致 artifact | 是否使用已辨识双通道执行模型 | 执行感知模型的价值 |

当前 formal 六条件矩阵中，只有 A2/C3–C4 已形成严格的单因素工程对比。A0、A1 和 A3 是保留的扩展计划，必须另行实现/冻结对应条件并建立新 session 后才能给出因果结论。如需单独识别“相位对齐”本身，再比较 C2 与 PhaseAlignedNoResidual；这项不默认进入当前 96-trial 矩阵。

### 3.3 不可混用的旧名字

- `B_slosh_matched0/5` 只是旧 100 ms 液体代价消融，不等于 C0、C3 或 C4。
- 历史 `B_smooth` 不是针对新 C4 调出的 SmoothMatch，不能直接充当 C1。
- 旧在线 S-MPCC 只能明确标为 legacy comparator；PR-RMPC 正文方法名不得再写成 S-MPCC、residual MPCC 或 online local planning，也不能用 legacy 条件代替 C0–C4/A0–A3。
- ZV 固定曲线可作为传统外部参考；`mpc_local_planner`、TEB 或 DWA 只能作系统级参考，不负责证明本文机制。

## 4. 平台、路径与冻结资产

### 4.1 平台和测量链

实验平台至少记录：

- Scout Mini 的最终发布命令、底盘反馈和安全改写；
- Nokov/定位位姿与 source timestamp；
- odom 与 processed IMU；
- 独立 RealSense RGB 液面测量及有效标志；
- 内部 slosh observer、execution-front 状态、相位候选、gate metric、求解状态和最终命令。

RGB 是物理主测量，内部低阶模型和 slosh monitor 是解释性测量。二者必须分别报告，不能相互替代或只选择方向有利的一路。

### 4.2 路径层级

建议只设两个层级：

1. **P-core：**高激励、可重复、静态净空的冻结核心路径，用于全部主结果；
2. **P-MBF（可选）：**MBF 在静态地图中预先生成、随后冻结的第二路径，用于路径来源泛化。

只有 P-core 全部门通过后才运行 P-MBF。每条路径拥有独立 path hash、碰撞复核和 OfflineSloshOCP artifact；不能让两条路径共用一个恢复对象。

### 4.3 每个 release 必须冻结

- Git commit、构建产物、配置 dump 和实验协议 ID；
- 地图/`.pbstream`、TF、footprint、路径点列及 SHA-256；
- 执行模型、液体模型、容器、装液量和温度范围；
- RGB 标定、相机设置、ROI、时间偏差及文件 hash；
- OfflineSloshOCP artifact、gate schema、合同 ID 和 SHA-256；
- C0–C4 的有效参数、运行顺序、主指标窗口与停止规则。

旧 G3R3 的路径、RGB 标定和 runner 只能作为 development 参考，不能自动继承为 PR-RMPC 正式资产。

### 5.1 当前工程状态与放行缺口

- **已经实现：**共同预计发布时刻、最终发布历史驱动的 pending queues、22 维 unequal-delay dynamics、十步 acados Full SQP、V3 artifact、全预测域 $\mathcal B^{\mathrm{exec}}$、9 维 empirical gate 的 monitor/enforce 分支、冻结的有界恢复反馈、fail-closed supervisor 和 publication receipt/guarded phase commit 已形成 source-level 闭环。
- **条件 runner 已存在：**strict independent-plant runner 能显式运行 C0、C1、C2、C3、C4 和 IS；C2 是 final-command nominal replay，C3 是与 C4 同 solver/执行集/recovery/发布链的 empirical monitor-only 条件。不能再写成 C2/C3 尚未实现，也不能用“超宽 gate”替代 C3。
- **当前修订尚未冻结：**本轮工作树有未提交修订，没有绑定它的新 clean commit、build、formal session、readiness report 或人工 approval。当前 recovery 工具/报告 schema 的修订也要求重新生成并逐级绑定 held-out report、fit manifest、V3 artifact 和 session，不能沿用旧 hash 冒充当前证据。
- **历史状态仅供追溯：**commit `7775dd68` 的旧 session 曾得到 `READY_NOT_EXECUTED`，且 `formal_trials_started=false`；它只证明旧资产链内部一致，不是本轮代码的 readiness，更不是效果结果。
- **正式数据尚不存在：**冻结计划为 16 个 seeds 与 C0–C4/IS 六条件交叉，共 96 trials；人工 approval 未签发，campaign 未启动，当前计数为 0/96，因此没有 formal independent-plant 效应、运行时统计或 gate 控制收益可报告。
- **实物仍为独立 NO-GO：**Scout command-to-motion 辨识、publication-to-actuation 边界、Nokov/odom/IMU/RGB source-time 标定、shadow/no-motion、独立 RGB 可检测性、随机表和安全审批仍须按实物 release 单独完成；simulation readiness 不能授权 real-robot `enforce`。

## 6. 数据划分与实验阶段

### 6.1 互斥数据池与锁定顺序

| 数据池 | 用途 | 锁定规则 |
| --- | --- | --- |
| $D_{\mathrm{id,fit}}$ / $D_{\mathrm{id,test}}$ | 执行与液体模型拟合 / 独立总 lead 验证 | test 不参与模型选择 |
| $D_{\mathrm{gate,fit}}$ / $D_{\mathrm{gate,tune}}$ / $D_{\mathrm{gate,held}}$ | 基础半径/边界拟合 / 单一全局 shrinkage 选择 / 独立分类与重接评价 | held-out 只打开一次，不调半径、边界、阈值或 recovery gains |
| $D_{\mathrm{dev,tune}}$ / $D_{\mathrm{dev,pilot}}$ | C1/C4 与流程开发 / 冻结后的 G4 小样本检查 | pilot 后不得回调参数；若回调则另开新 pilot |
| $D_{\mathrm{main,confirm}}$ / $D_{\mathrm{recovery,confirm}}$ | 主物理效果 / 组件与恢复确认 | 两者均在 release 冻结后采集并分别统计 |

数据池按完整 trial、完整 recovery rollout 或完整 block 划分，禁止把同一条轨迹相邻帧随机拆成 fit/tune/held-out，也禁止把 main confirmation 的结果用于修改 recovery 协议后仍声称同一冻结 release。

### 6.2 分阶段执行

#### E0：测量与执行链辨识

- 分别辨识线/角延迟、惯性、增益和适用域；
- 用未参与拟合的完整 trial 比较纯延迟、一阶模型和候选数据模型；
- 验证 Nokov、odom、IMU、RGB 和命令的 source-time 对齐；
- 完成 G0 的总 lead、主频幅相和首拍灵敏度检查。

这一阶段只回答模型是否可信，不证明防晃有效。

#### E1：OfflineSloshOCP 与 artifact 验证

- 对 P-core 生成完整名义序列与终端尾段；
- 检查全部状态/命令约束、非现实尖峰、终点截断和 artifact 合同；
- 在参数扰动和非线性液体仿真中比较 OfflineSmoothReplay 与 C2；
- 用 actual-input replay 区分“执行模型误差”和“液体模型误差”。

#### E2：empirical gate 构造与 held-out 验证

- 在 $D_{\mathrm{gate,fit}}$ 上按相位拟合 9 维基础半径和 14 维执行边界，只允许 $D_{\mathrm{gate,tune}}$ 选择一个全局 shrinkage；
- 在 $D_{\mathrm{gate,held}}$ 的独立 recovery rollout 上一次性形成混淆矩阵；
- 分母分离地记录 recovered coverage、unrecovered false accept、accepted-sample conditional false-safe、各自 Wilson 区间、逐相位 coverage 和实际重接结果；
- 单独审计有界恢复反馈 proposal、safety arbitration、priority arbitration、finalizer/limiter、sink receipt/history 与 guarded phase commit；只有 receipt 确认的最终命令才能进入执行历史。

#### E3：冻结的 independent-plant formal simulation

- 在新的 clean commit、build、v2 held-out/fit 链、V3 artifact、formal session 和 readiness 全部 hash-bound 后，才能申请与该 session SHA-256 精确绑定的人工 approval；
- 按预先冻结的交错顺序运行 C0、C1、C2、C3、C4、IS 六条件与 16 个 seeds 的全部 96 trials，不得见结果后挑选重跑；
- 以独立 plant liquid truth、任务、失败和 runtime 为 trial-level 结果；C3/C4 的 paired difference 只归因于 empirical gate monitor/enforce；
- 当前 revision 尚无新 session/readiness/approval，campaign 未启动，必须明确报告为 0/96，而不能把旧 `7775dd68` readiness 写成当前效果证据。

#### E4：小规模 development 实物

- 只在 $D_{\mathrm{dev,tune}}$ 调整 C1/C4 和流程，随后冻结候选；
- 用新的 $D_{\mathrm{dev,pilot}}$ 完成 C0–C4 命令分离、RGB 可检测性、trial 窗口与停止规则检查；
- pilot 只决定 G4 GO/NO-GO，不再回调参数；
- 只用于 G2/G4，不进入正式论文效果统计。

#### E5：冻结路径主实物确认

- 在 P-core 上运行预先生成的随机平衡 block；
- 主性能矩阵比较 C0、C1、C2、C4；
- 同时保留所有失败、停车和数据采集故障标签；
- 该阶段决定 RQ2 能否给出正向结论。

#### E6：组件与恢复实物实验

- 在 $D_{\mathrm{recovery,confirm}}$ 使用已实现的 A2 和另行冻结后的 A1，分别评价 empirical admission enforcement 与 finite residual；
- 使用预注册的小初始位姿偏差、附加命令延迟/限幅或短时速度门；
- 大规模不可恢复样本优先在仿真/回放中测试，实物只做已安全审查的边界确认；
- 禁止用不可重复的人工推车或动态障碍作为正式扰动。

P-MBF、第二容器和更多载荷只作为核心结论通过后的扩展，不阻塞首篇论文。

不要把所有条件塞进同一个大矩阵。用相互衔接的小矩阵回答不同问题：

| 矩阵 | 条件 | 场景 | 主要结论 |
| --- | --- | --- | --- |

| M1 主效果 | C0、C1、C2、C4 | P-core、名义起点 | 普通控制、平滑公平性、离线计划和完整方法的真实 RGB 差异 |

Layer S 的 formal 计划已经固定为 16 个 locked seeds 与六条件交叉的 96 trials，但本轮 revision 必须重新物化 session，且当前尚未启动。Layer H 的实物重复次数不沿用旧 40/64/88 矩阵，也不直接照搬仿真 16 seeds；最小有意义效应（SESOI）先依据 freeboard 风险、物理意义和 RGB 最小可检测差异确定，再用与 confirmation 分离的 pilot 估计 block 内差值方差，冻结功效分析、样本量和随机表。

## 8. 指标与“正向”的判定

### 8.1 唯一物理主指标

建议冻结为：

$$
Y_{\mathrm{RGB}}=
P95_{\mathrm{motion+tail}}
\big(\mathrm{max\mbox{-}LCR}_{\mathrm{RGB}}(t)\big).
$$

motion 起点、到点判定、tail 长度、无效帧规则、单位和左右标尺合成方式必须在 formal freeze 前固定。若最终选择别的 RGB 指标，也只能有一个主指标，不能看完结果再在 peak、RMS 与 P95 中挑最有利者。

### 8.2 关键次指标

**真实液体：**RGB RMS、peak、tail RMS、settling time、有效帧率和左右标尺一致性。

**任务：**完成时间、到达/停车/失败、contour/yaw RMSE 与 P95、终点误差。

**运动公平性：**$v$、$\omega$、加速度、角加速度、jerk、命令频谱和完成时间包络。

**方法机制：**名义偏差、第一拍 residual、饱和比例、相位索引跳变、gate coverage、实际重接时间、有界恢复反馈 proposal、速率限制、安全/优先级改写、最终 publication receipt 与 guarded phase commit。

**实时性：**solver p50/p95/max、超过 $33.3\,\mathrm{ms}$ 的比例、实际发布频率、求解失败、状态过旧、合同失效和安全改写比例。

内部 slosh monitor 的 peak/RMS/相位只能作为 secondary mechanism outcome，必须与 RGB 并列画图并报告不一致情形。

### 8.3 什么条件下才叫改善

C4 的 confirmatory 判断采用固定顺序：先检验 C4 相对 C0 的主比较；通过后才检验 C4 相对 C1 的平滑公平性比较。两者使用同一个预注册 RGB 主指标，但以 fixed-sequence gatekeeping 控制多重性。可以声称“相对普通 MPCC 改善”至少需要：

1. 相对 C0，独立 RGB 主指标的配对效应及区间达到预注册 SESOI；
2. 若进一步声称收益不是减速/平滑造成，C4 相对 C1 的固定第二检验也通过；
3. 完成时间和 tracking 落在预注册 non-inferiority margin 内；
4. 成功率、停车、求解失败和安全事件满足预注册 margin 或零事件率上界；
5. 只对实际通过 A0–A3 的模块给出组件归因，不要求 C0–C4 指标逐级单调。

若 RGB 降低但明显更慢、路径误差更大或失败更多，只能报告 trade-off，不能写“总体优于普通 MPC”。

## 9. recovery gate 的专门评价

必须先冻结“实际恢复成功”的独立标签。仿真使用未参与建 gate 的高保真模型/真状态、真实约束、执行状态兼容条件和尾段结果；实物使用独立 RGB、任务完成、安全约束与预注册 tail 阈值。内部 9 维 observer/gate 误差只作解释，不能同时充当预测器和 ground truth。

混淆矩阵只在执行状态兼容集内评价 9 维 empirical gate；兼容集外直接判为不可放行，并单独报告其拒绝率。

| gate 判断 | 实际恢复成功 | 实际恢复失败 |
| --- | ---: | ---: |
| 可恢复 | true accept（TA） | **false accept（FA）** |
| 不可恢复 | false reject（FR） | true reject（TR） |

必须分开报告以下三个不同条件概率，且分别以自己的二项分母计算 Wilson 区间：

$$
r_{\mathrm{cov}|\mathrm R}
=\frac{\mathrm{TA}}{\mathrm{TA}+\mathrm{FR}},
\qquad
r_{\mathrm{FA}|\neg\mathrm R}
=\frac{\mathrm{FA}}{\mathrm{FA}+\mathrm{TR}},
$$

$$
r_{\mathrm{FS}|\mathrm A}
=\frac{\mathrm{FA}}{\mathrm{TA}+\mathrm{FA}}.
$$

其中 $r_{\mathrm{FA}|\neg\mathrm R}$ 是“在实际未恢复样本中错误接受的比例”，冻结 gate-selection 门作用于它的 Wilson 上置信界；$r_{\mathrm{FS}|\mathrm A}$ 是“在所有已接受样本中最终失败的比例”，只是另一个条件诊断，不能套用前者的区间。若 $\mathrm{TA}+\mathrm{FA}=0$，conditional false-safe 的估计和区间必须记为未定义/null，并同时报告 accepted count 为 0，不能写成 0 或有利证据。

此外报告：

- false reject、recovered-sample coverage 及其独立 Wilson 区间，而不只报总体 accuracy；
- 执行状态兼容集的 coverage 与拒绝率；
- 每个相位的样本覆盖与最差相位；
- 从偏离到重接所需时间；
- gate 外是否按合同请求 $(0,0)$；
- 有界恢复反馈被提出后，依次经过 safety、priority arbitration、finalizer/limiter 和 sink receipt 后最终实际发布了什么，以及该 receipt 是否更新 history/允许 guarded phase commit。

用于拟合 gate 的 rollout 不能再次进入该表。若只有 Monte Carlo 椭球结果，论文仍只能称 empirical gate/set。

C3 与 C4 使用相同的 $\mathcal B^{\mathrm{exec}}$、有界恢复反馈和失败语义：C3 只记录上述 9 维 metric，C4 才 enforce 它。因此 C4–C3 的差异只能解释为 empirical admission enforcement 的作用，不能写成“启用 execution compatibility、stored action 或整个 recovery 机制”的联合收益。

## 10. 随机化、失败和统计规则

- **统计单位：**一次完整 trial；视频帧、控制周期和路径采样点不是独立样本。
- **随机化：**同一 block 内各条件各运行一次，使用预先生成的平衡顺序；电量、温度、装液、地面和日期作为 block 元数据。
- **开发隔离：**模型选择、权重、SmoothMatch、gate 阈值和异常规则冻结后，才能采集 $D_{\mathrm{main,confirm}}$ 与 $D_{\mathrm{recovery,confirm}}$。
- **失败保留：**方法失败、求解失败、安全停车和超时均属于结果；只有预先定义的外部采集故障可以补做，并保留原 attempt。
- **主分析：**报告每个 block 的原始配对差、稳健汇总、效应量与置信/可信区间；补充 leave-one-block-out 敏感性。
- **多重结果：**只对一个主指标作 confirmatory 判断；C0/C1 两个比较按预注册 fixed-sequence gatekeeping；secondary 指标报告完整结果及必要的多重比较控制。
- **不提前停在有利方向：**futility 或 safety stop 规则须预注册；不得看见正向后提前结束或负向后临时扩样。
- **可追溯性：**每个图表能追溯到 manifest、bag、分析脚本版本、排除原因和原始 trial ID。

## 12. 最终 Experiments 章节顺序

正式论文建议按下列顺序写，避免先展示有利结果再补协议：

1. **IV-A Research Questions and Claim Boundary：**RQ1–RQ5、冻结路径、独立 plant/RGB 边界和无在线避障主张；
2. **IV-B Frozen Assets, Data Separation, and Trial Unit：**旧 `7775dd68` 与当前 revision 的边界、数据池、trial 单位和 failure-inclusive 规则；
3. **IV-C Conditions and Identifiable Contrasts：**C0–C4/IS 的精确工程合同，明确只有 C4–C3/A2 是当前严格单因素消融；
4. **IV-D Layer S Release Gates and Status：**22 维 solver/causal/KKT、V3 artifact、held-out gate、session/readiness/approval 链以及 0/96 状态；
5. **IV-E Layer S Evaluation：**96 trials 执行后才填写 independent-plant、gate、任务、失败与 runtime 结果；当前只能写 protocol 和 pending 状态；
6. **IV-F Layer H Platform and Protocol：**Scout、容器、P-core、Nokov/IMU/RGB、shadow/no-motion、主指标、随机化和安全升级顺序；
7. **IV-G Planned Physical Results and Extensions：**M1/M2/M3/M4 的 RGB、任务、失败、recovery 和扩展路径；没有数据前不得预填正向叙述；
8. **IV-H Runtime, Evidence Boundary, and Limitations：**30 Hz、publication receipt 边界、极端超时、适用域、无在线避障和 empirical 非证书边界。

整章最重要的逻辑不是“动作看起来更平滑”，而是依次证明：source-time/22 维执行合同正确；冻结方法在独立 plant 的 failure-inclusive formal simulation 中有效；随后才在独立 RGB 上验证真实液体收益和任务公平性；最后用分母正确的 held-out 统计与 C3/C4 配对只评价 empirical gate enforcement。任一层尚未采集时都应保留 pending，而不能由实现完成度替代效果证据。

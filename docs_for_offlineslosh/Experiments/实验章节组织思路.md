# 新方案的创新点与实验章节怎么组织（简明版）

> 这份文档主要用于我们自己讨论。
>
> 它说明两件事：
>
> 1. 新方法完成后，文章真正可以说的创新是什么；
> 2. 实验要怎样安排，才能分别证明这些创新。
>
> 它不是已经冻结的正式实验方案，也不表示相关功能已经完成。

## 1. 文章的创新点变成了什么

新文章不应再把创新概括成“在线 MPC 加入液体模型”。这个说法更适合旧方案。

新方案更合适的创新点有三条。

### 创新点 1：防晃规划考虑 Scout 的真实执行效果

旧系统外面已经有延迟预测、限幅和安全处理，但旧的规划模型没有把下面这段过程直接放进机器人—液体预测中：

> 最终发布命令 → 延迟和惯性 → 小车实际运动。

新方法先用实物数据辨识：

> 最终发布的速度命令，经过多长延迟、怎样的惯性变化，才变成小车真正的线速度和角速度。

然后离线和在线规划都使用这个真实响应模型。

这条创新的重点不是发明了新的辨识算法。纯延迟、一阶惯性和数据拟合模型本身都很常见。真正的重点是：

> 防晃规划不再用理想命令直接计算液体激励，而是先预测小车实际怎样运动，再计算液体受到的激励。

### 创新点 2：离线安排完整防晃动作，在线只做有限修正

旧方法每个控制周期都重新规划未来动作，可能会不断改变原本需要前后配合的防晃节奏。

新方法把职责分开：

- 离线规划负责整条路径上的加速、转弯、反向激励、减速和终点收尾；
- 在线控制负责修正跟踪误差和小扰动；
- 在线修正有明确的大小和变化速度限制，不能随意推翻离线动作。

这条创新想解决的问题是：

> 怎样既保留整段液体相位抵消动作，又能应对实物小车不可能完全照着离线计划运行的问题。

### 创新点 3：液体只预测约 100 ms，但检查还能不能接回后续动作

旧方案在完整 2 秒内使用液体预测，但目前证据表明远期液体状态不够可信。

新方案第一版只使用前 3 个控制间隔的液体预测：从当前时刻走到第 3 个未来节点，在 30 Hz 下约为 100 ms。

100 ms 末端不要求液体已经平静，而是检查：

> 当前机器人、命令、执行状态和液体状态，是否还处在能够接回后面离线防晃序列的范围内。

第一版这个范围由仿真和数据得到，因此只能叫“经验可恢复范围”。只有以后完成严格证明，才能把它说成具有数学保证的可恢复区域（论文里常叫 tube 或 funnel）。

### 不是主要创新的内容

下面这些内容很重要，但不宜单独包装成论文核心创新：

- 一阶液体晃动模型；
- 纯延迟、一阶惯性或离散数据模型（ARX）；
- acados 和 SQP-RTI 求解器；
- RGB 液面测量；
- 普通路径跟踪和 contour/lag error；
- 记录大量 ROS 诊断话题。

这些内容是新方法能够成立和验证的基础。

## 2. 新文章最核心的问题

整篇文章可以围绕一句话展开：

> 考虑 Scout 真实执行误差后，先离线生成完整防晃动作，再用受限制的在线修正和 100 ms 可恢复检查，能否在真实小车上减少液体晃动，同时保持路径跟踪、完成时间和运行可靠性？

实验必须分别回答：

1. 小车响应模型准不准；
2. 完整新方法在实物上有没有真实防晃效果；
3. 效果究竟来自执行模型、离线计划还是在线修正；
4. 100 ms 末端的可恢复检查是否真的有保护作用；
5. 整套方法能否以 30 Hz 稳定运行。

## 3. 旧实验设计哪些保留，哪些改变

| 内容 | 新实验中的处理 |
|---|---|
| 高风险路径和低风险路径 | 高风险路径用于核心实验；低风险路径在核心结果通过后再做 |
| 每次实验前静置、检查初始位置和朝向 | 保留 |
| RGB 液面结果作为主要物理证据 | 保留 |
| 完成时间、路径误差、成功率 | 保留 |
| 区分求解器命令、最终命令和实际运动 | 保留并加强 |
| 同一组内各种方法随机排序 | 保留 |
| 失败实验不能只挑成功的重跑 | 保留 |
| Smooth-match 排除“只是走得更慢” | 保留 |
| 原来的 ZV 固定曲线 | 可作为可选外部参考，不再代表新方法的离线版本 |
| 旧 S-MPCC | 可作为上一代方法参考 |
| 人工液体相位和 zero-state replay | 降为辅助分析，不再是核心实验 |
| 40/64/88 次固定矩阵 | 不直接沿用，重新按新比较关系计算 |
| 第二容器 | 放到核心方法通过后的扩展实验 |

最大的变化是：

> 旧实验把固定曲线和在线 S-MPCC 当成两套对手；新方案本身已经包含离线防晃序列，因此要改成“只执行离线计划”“离线计划加在线修正”“完整方法”等内部对比。

## 4. 建议的研究问题

建议把实验章节分成四个主要问题，最后再单独报告实时性。下面的 RQ1–RQ4 只是“研究问题 1–4”的编号。

### RQ1：Scout 响应模型是否可信

问题：

> 在没有参与模型拟合的完整实验中，冻结的响应模型能否比纯延迟模型更准确地预测 Scout 的实际线速度、角速度和运动激励？

这一步只证明小车模型是否可靠，还不能证明防晃有效。

### RQ2：完整新方法是否真的减少液体晃动

问题：

> 在完成时间和路径任务相近的情况下，完整新方法能否比普通平滑控制和旧在线 S-MPCC 减少 RGB 测到的液体晃动，并降低到达终点后的残余晃动？

这是整篇文章最重要的实物问题。

### RQ3：新方法为什么有效

问题：

> 实物效果是因为考虑了 Scout 真实响应、因为离线完整防晃计划，还是因为在线小幅修正？

这一部分通过逐项关闭新方法的组成部分来回答。

具体用三组比较拆开看：

1. 普通平滑计划与只执行离线防晃计划，判断完整离线规划有没有价值；
2. 不考虑 Scout 真实响应与考虑真实响应，判断执行模型有没有价值；
3. 只执行离线计划与加入有限在线修正，判断在线修正有没有价值。

### RQ4：100 ms 可恢复检查是否有用

问题：

> 在没有参与可恢复范围建立的仿真和安全实物情况下，这个范围能否少出现“判断可以恢复，但实际上恢复失败”的情况？超出范围时，系统能否正确减速、停车或进入后备策略？

这一问题只能支持“经验上有保护作用”，不能直接得出严格数学保证。

### 支持性问题：能否稳定实时运行

还要报告：

- 30 Hz 是否稳定；
- 求解时间是否经常超过 33 ms；
- 求解失败多少次；
- 安全层改写命令多少次；
- 无法可靠判断当前处于离线序列哪一段的次数；
- 超出可恢复范围多少次；
- 实际发布频率是否稳定。

实时运行是方法可用的必要条件，但不应被包装成主要算法创新。

## 5. 不要把所有对照组塞进一个大实验

新方法包含多个部分。如果所有条件都放进每一组实物实验，实验数量会迅速变得很大，也很难解释。

更合理的做法是：每个问题使用最需要的对照组。

### 5.1 主实物效果实验

建议主要比较四种方法：

| 条件 | 作用 |
|---|---|
| 完成时间匹配的普通平滑控制 | 排除“只是走得更慢” |
| 旧在线 S-MPCC | 与上一代方案比较 |
| 只执行离线防晃计划 | 判断没有在线修正时能做到什么 |
| 完整新方法 | 离线计划、在线有限修正和可恢复检查全部启用 |

如果实验资源有限，旧在线 S-MPCC 可以作为次要参考，不一定进入每一个正式实验组。

原始 B_smooth 可以继续保存为普通基线，但主要结论应优先与完成时间匹配的版本比较。

这里的“完成时间匹配”必须针对完整新方法重新调节，并在正式实验前冻结。不能直接沿用旧论文中为了匹配旧 S-MPCC 而设置的参数。

“只执行离线防晃计划”也要定义清楚：它与完整方法使用相同的离线序列起点、底盘内部速度控制、限幅和安全层，只把在线修正设为零，并让离线序列按正常速度前进。这样比较的差别才集中在在线修正，而不是换了一套执行系统。

### 5.2 执行模型作用实验

为了单独判断 Scout 响应模型是否重要，比较：

1. 离线规划假设“命令立即变成实际运动”；
2. 离线规划使用实物辨识得到的 Scout 响应模型。

两者使用相同路径、液体模型、限制和执行层。

先在仿真和历史数据回放中比较，再决定是否进入小规模实物实验。

另外，用完成时间匹配的普通平滑计划与“只执行离线防晃计划”比较，才能单独看出完整离线防晃规划本身的作用。

### 5.3 在线修正作用实验

使用同一条离线防晃计划比较：

1. 不允许在线修正；
2. 允许有边界的在线修正。

重点看：

- 路径误差是否减小；
- 实际运动是否更接近离线计划；
- 液体效果是否保持或改善；
- 在线修正是否经常顶到上限；
- 离线序列位置是否平稳。

这组实验可加入小的初始位置或朝向误差，以及预先规定的轻微扰动。不要使用难以重复、可能不安全的人工推车作为正式扰动。

### 5.4 可恢复范围作用实验

比较：

1. 在线修正但没有可恢复检查；
2. 完整方法，启用可恢复检查。

这组对比首先在大量仿真和回放中完成，因为“故意进入不可恢复状态”不适合直接在实物上大量尝试。

实物实验只选择经过安全审查的轻微偏差：

- 预计仍在可恢复范围内的情况，检查能否正常接回；
- 预计超出范围的情况，只检查系统是否正确减速或停止，不强行完成危险动作。

实验开始前必须把“恢复成功”写清楚。建议统一规定：从第 3 个未来节点开始，按当时对应的离线收尾动作继续运行；只有在规定时间内回到允许误差范围，并且安全到达终点、终点残余晃动没有超限，才算恢复成功。具体时间和阈值要在正式测试前冻结。

### 5.5 可选的外部参考

如果篇幅和实验资源允许，可以保留旧 ZV 固定曲线作为传统方法参考。

必须把它清楚地叫作“ZV 固定曲线”或“传统固定曲线”，不能与新方法生成的离线防晃计划混用同一个名称。

## 6. 建议分阶段完成实验

### 阶段 A：Scout 响应模型

目的：

- 收集命令、Nokov、odom 和 IMU；
- 先平滑 Nokov 位姿，再计算实际线速度和角速度；
- 比较纯延迟、一阶惯性加延迟和数据拟合模型；
- 用完整实验划分训练集和验证集；
- 把小车物理执行延迟与 IMU 滤波、消息时间戳带来的延迟分开；
- 冻结最后选中的模型。

放行条件：

- 在独立验证实验上明显优于纯延迟模型；
- 线速度和角速度都达到预定精度；
- 连续预测一小段时间时不会快速发散；
- 实际加速度和转弯激励的预测误差可以接受；
- 数据激励足够，参数没有明显不可辨识问题。

如果激励不足、参数无法可靠确定，或者独立验证没有明显优于纯延迟模型，就明确判定本阶段没有通过，不强行选择更复杂的模型。

### 阶段 B：离线防晃计划的仿真检查

目的：

- 检查离线计划是否满足路径、速度和命令限制；
- 检查考虑真实响应后，预测运动是否更接近实物数据；
- 检查终点液体残余；
- 检查离线计划是否比普通平滑轨迹更有希望。

放行条件：

- 离线求解成功且限制没有明显违反；
- 多次仿真和模型扰动下结果稳定；
- 不依靠不现实的命令尖峰；
- 在线修正为零时可以复现离线计划。

### 阶段 C：固定路径主实物实验

目的：

- 在高风险路径上验证真实 RGB 防晃效果；
- 比较普通平滑、旧方案、离线计划和完整新方法；
- 同时报告完成时间、路径误差、成功率和命令干预。

这一阶段决定文章能否提出主要物理效果结论。

### 阶段 D：在线修正和轻微扰动

目的：

- 检查在线修正能否处理小的初始偏差和执行偏差；
- 检查修正是否始终受到限制；
- 检查修正后是否仍能保留离线防晃收尾。

### 阶段 E：可恢复范围验证

目的：

- 使用与建立范围不同的仿真和回放数据；
- 统计“判断安全但实际失败”的比例；
- 检查范围外是否正确触发减速、停车或后备策略；
- 只做少量经过安全审查的实物确认。

### 阶段 F：可选扩展

只有核心实验成功后再考虑：

- 低风险路径；
- 局部静态障碍；
- 第二容器；
- 不同载荷；
- 动态可信时域。

这些扩展不应阻塞第一篇核心论文，也不应在没有完成时写进主方法。

局部静态障碍需要单独作出选择：如果论文声称方法可以有限绕障，就必须同时测试“允许范围内能够接回”和“超出范围后正确减速或停止”；如果第一篇论文不做这组实验，就应明确把障碍能力排除在本文范围外。

## 7. 每类实验主要看什么

### 7.1 小车响应模型

分别看线速度和角速度：

- 预测的延迟、增益和变化快慢是否接近真实情况；
- 预测速度与动捕速度的差值；
- 均方根误差（RMSE）、相关性和残余误差；
- 连续预测一段时间后的误差；
- 预测的纵向激励和转弯激励是否接近真实值；
- 物理执行延迟与 IMU 或时间戳处理延迟是否被分开报告；
- 不同速度范围下是否仍然可靠；
- 哪些实验超出模型适用范围。

不要只报告相关性高。即使曲线形状相似，时间错位或幅值偏差仍可能破坏防晃效果。

### 7.2 真实液体效果

真实物理效果继续由 RGB 决定，内部液体模型只能用于解释。

至少报告：

- 运动期间液面晃动的 p95（95% 的时刻不超过这个水平）；
- 运动期间液面晃动的峰值或 RMS；
- 到达后固定时间内的残余晃动 RMS；
- 液体恢复到稳定范围所需时间。

旧实验把到达后晃动放在次要位置。新方法专门优化完整收尾，因此到达后的残余晃动应升级为关键结果。

### 7.3 任务完成情况

至少报告：

- 完成时间；
- 路径误差；
- 是否成功到达；
- 是否安全停止；
- 是否出现求解失败；
- 是否因为数据或相位问题中止。

防晃变好但任务明显变慢、路径误差明显变大或失败更多，不能直接称为整体更好。

### 7.4 在线修正是否真的“有限”

至少报告：

- 在线修正量的大小；
- 修正量达到上限的时间比例；
- 最终命令偏离离线计划多少；
- 离线序列前进速度偏离正常值多少；
- 安全层修改了多少求解器命令。

这些结果用于证明在线控制器没有偷偷重新变成自由规划器。

### 7.5 可恢复范围

最重要的是：

- 判断“可以恢复”后，实际却恢复失败的比例；
- 判断“不能恢复”但实际可以恢复的比例；
- 可恢复范围覆盖了多少正常状态；
- 范围外是否正确触发后备动作；
- 不同离线序列位置的判断是否稳定。

如果约束允许临时放宽，还必须报告放宽了多少次、每次放宽了多少，不能只报告最终有没有成功。

用于建立可恢复范围的数据，不能再用于报告最终准确率。

### 7.6 实时运行

至少报告：

- 求解时间中位数、p95 和最大值；
- 超过 33 ms 的比例；
- 实际控制频率；
- 求解失败次数；
- 命令被安全层改写的比例；
- 状态过旧和序列位置判断失败次数。

## 8. 正式实物实验的基本规则

这些规则可以从旧实验设计继续保留。

### 一次完整运行才算一个样本

不能把视频帧、控制周期或路径采样点当成大量独立样本。

### 使用随机成组对比

同一实验组中，各种方法都运行一次，顺序随机。这样能减少液体温度、电量、地面状态和当天设备状态的影响。

### 正式数据和开发数据分开

用于调参数、选择模型和建立可恢复范围的数据，不能混入最后的正式效果统计。

### 失败实验不能只挑成功的重跑

求解失败、安全停止、路径失败都属于方法结果，应保留。

只有与方法无关的录像损坏、动捕断流等采集故障，才可以按预先规则补做。

### 实验次数不要直接照搬旧的 8 组

先用开发数据估计实验波动，再决定正式需要多少组。确定后不能因为结果不理想就临时增加样本。

### 主要比较提前确定

建议主要比较顺序为：

1. 完整新方法与完成时间匹配的普通平滑控制；
2. 如果第一项成立，再比较完整新方法与旧在线 S-MPCC；
3. 然后解释执行模型、离线计划和在线修正分别带来的变化。

这样可以避免看到结果后再临时挑选有利对比。

### 9.4 实验阶段和数据划分

## 10. 每个结果能够说明什么

| 结果 | 可以说明 | 不能说明 |
|---|---|---|
| 响应模型优于纯延迟 | 在测试范围内更准确预测 Scout 运动 | 新方法一定能减少液体晃动 |
| 离线计划仿真液体更小 | 计划在模型中有潜力 | 实物 RGB 一定更好 |
| 完整方法优于平滑基线 | 新系统在报告条件下有真实物理收益 | 对所有路径、容器都有效 |
| 完整方法优于只执行离线计划 | 有限在线修正有实际价值 | 可以无限制修改离线计划 |
| 考虑真实响应优于理想响应 | 执行模型对当前平台有帮助 | 所用辨识方法本身是全新算法 |
| 可恢复范围的误判较低 | 在报告数据范围内有经验保护作用 | 已证明递归可行或全局安全 |
| 30 Hz 大部分周期按时完成 | 当前硬件上具有实时运行能力 | 没有任何极端超时或失败风险 |

## 11. 整个实验章节最重要的一句话

> 实验不能只证明新方法生成了不同动作，而要依次证明：它更准确地预测了 Scout 怎样执行命令，离线防晃计划在真实 RGB 上有效，在线修正确实有限且有帮助，并且 100 ms 末端的可恢复检查能够减少错误放行。

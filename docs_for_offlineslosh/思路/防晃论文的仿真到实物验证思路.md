这里的核心关系是：

> **控制器代码和模型形式共用；仿真参数、实车参数、离线轨迹、恢复规则和正式数据分别冻结，不能混用。**

两条线路分别保留参数、轨迹和数据，但不是同时开工：**先完整做通仿真，再开始实物。**本文所说的“冻结”，就是把代码、参数和规则固定并记录下来，之后不能根据正式结果随意改动。

## 1. 为什么要分成两条线路

仿真和实物面对的“被控制对象”本来就不同：

| 内容           | 仿真线路                | 实物线路                     |
| -------------- | ----------------------- | ---------------------------- |
| 控制器内部代码 | 同一套 C++ 代码         | 同一套 C++ 代码              |
| 内部模型形式   | 同一套线/角双通道模型   | 同一套线/角双通道模型        |
| 内部模型参数   | 仿真版本参数            | 用实车数据辨识的参数         |
| 外部被控对象   | 独立的仿真 Scout 和液体 | 真实 Scout 和真实液体        |
| 离线防晃轨迹   | 按仿真参数生成          | 按实车参数重新生成           |
| 恢复判定规则   | 用独立仿真数据验证      | 用实车参数和独立数据重新验证 |
| 最终结论       | 方法在仿真中有效        | 真实液面是否降低             |

控制器内部模型要保持同一种含义，但参数不必相同。仿真中的“假 Scout＋假液体”反而不能与控制器内部模型完全一样，否则相当于控制器自己出题、自己判卷。

新的 backend 仍是严格 opt-in：默认 `continuous_mpcc_acados`、`delay_augmented_phase/enabled=false`，且默认 recovery hash 为空，所以旧行为不变、误开启会被拒绝。独立 plant、开发参数 v1、全相位 recovery、开发 held-out V3 和 C0--C4/IS 统一 runner 已经建立。cycle 10 的 phase 10 硬不可行问题已通过“22D B_exec 资格过滤后再做 9D 评分”从因果结构上修复；求解后的 current/terminal gate 保留。Full SQP 已在 cycle 2 满足四项 KKT，但真实 seed 推进至尾段 cycle 993 时仍达到 20 次迭代上限，stationarity 未通过。C1 还未公平匹配，C3 也还不是“与 C4 使用同一优化器、只关闭 gate”的严格消融。因此仍不能运行或宣称正式 C0--C4 结果。

1. V3 名义轨迹的尾段改为“最终发布命令先归零，命令队列和底盘响应随后真实衰减并停稳”，不再要求发布零命令的同一时刻车速也瞬间归零；

3. 恢复规则按完整 recovery trial 划分 fit、tune 和 held-out，独立液体真值不进入控制器，统计单位不能用 MPC 周期扩样；
4. recovery sampler 和 production coordinator 共用同一“冻结反馈律＋22 维发布速率事务”，避免离线标签使用在线无法发布的命令跃变；
5. 正式仿真配置绑定程序、路径、plant、planner、名义轨迹、恢复规则、条件定义和随机种子，并在启动前逐项核对文件 hash。

这些只是把仿真证据链做正确，还不是正向结果。全相位开发数据和独立 held-out gate 已经形成，但 gate 的冻结最低 coverage 只有 0.10，且单 seed C4 development 闭环没有完成任务。当前 **NO-GO** 已进一步收敛为“尾段小 B_exec 半径的平方约束导致 Jacobian 放大，Full SQP 在 20 次内未满足 stationarity 合同”；独立审计虽证明 cycle 993 的 primal 硬约束均满足，却不能代替 KKT 收敛。不得把 held-out 分类通过、候选误选修复或 primal 可行改写成完整方法防晃性能正向。

## 3. 线路一：先把仿真完整做通

### 仿真1：建立独立的仿真 Scout 和液体

控制器发出最终命令后，仿真对象再独立模拟：

```text
最终命令
→ 线/角两路延迟
→ 响应惯性、增益、死区和饱和
→ Scout真实运动
→ 液体响应
```

仿真对象至少要允许参数偏差、噪声和时间抖动。液体仿真最好比控制器内部的低阶模型更复杂；如果暂时做不到，也必须改变参数并加入未建模误差，不能使用完全相同的方程和参数自证。

### 仿真2：冻结一次仿真实验

把一次仿真需要的内容固定下来：

- 代码版本；
- 仿真地图和路径；
- 控制器参数；
- 仿真 Scout 和液体参数；
- 启动、录包和分析程序；
- 失败规则和结果指标。

以后看到结果再调参数，就必须生成新的仿真版本，旧结果不能与新结果混在一起。

### 仿真3：生成仿真专用轨迹和恢复规则

```text
运动 → 减速 → 抵消余晃 → 静置保持
```

**无量纲缩放与伴随量定位（2026-08-22 后续纠正）**：把 codegen 的 `scale_x/scale_u` 应用于 OCP 决策变量后，同一 seed 8601 cycle 2 snapshot 的 stationarity 从 2.20009 降到 0.0158641。随后发现该结果仍受求解器配置缺陷污染：Full SQP 显式使用 `HPIPM SPEED_ABS`，而该模式设置 `comp_dual_sol_eq=0`，不计算 dynamics equality costate。`qp_solver_cond_N=N=10` 在 partial-condensing 中实际表示“不做 condensing”，不是“满 condensing”；此前据此作出的“§7.3 分支 4、真实 terminal 跟踪残差”结论撤销。

Full SQP 已通过生成脚本改为 `HPIPM BALANCE`，RTI reference 保持 `SPEED_ABS`，OCP、权重、V3、gate 半径、B_exec 和 residual authority 均未改变。修复后同一快照的 stage 0..9 `pi` 全部非零，terminal x 代价梯度 `-1.583e-2` 被 incoming `pi[9]` 正确抵消，x 分量 residual 降至约 `-4.2e-6`。这证明 `-2.38 mm` terminal x 误差本身不是 KKT 违反。

新的独立 C++ 完整分解使用 `res_stat_N = cost_grad_N - incoming_pi[N-1] - ineq_adj_N`，并同时覆盖 empirical 9D gate 与 14 项 execution bounds。当前最大项转为 terminal `eta_x_dot`（index 7）：`cost_grad=-4.5166448e-3`、`incoming_pi=-4.4738975e-3`、`ineq_adj=3.9132e-9`，得到 `res_stat=-4.2751176e-5`，与 acados 逐位一致。四项残差为 stationarity `4.2751e-5`、equality `5.13e-11`、inequality `0`、complementarity `6.85e-7`；20 次后仍为 `NLP_STATUS_2`，iteration 2 起 `alpha=0.057648`，stationarity 单调下降但未达到 `1e-6`。

因此当前准确状态是：**缺失 π 的工程缺陷已经修复，但冻结的 20 次 Full SQP KKT 合同仍未闭合。** 按“修复明确 dual 错误后完整 SQP 仍失败则停止”的规则，本轮不继续调 globalization、迭代上限、容差或资产参数，也不运行 seed 8601 两次完整闭环；这些仍是明确 NO-GO 项。

**FUNNEL、B_exec 一步不变性与 PhaseClock 后续诊断（2026-08-22）**：同一 cycle 2 快照表明 MERIT 的失败步应用问题可由当前 acados 支持的 `FUNNEL_L1PEN_LINESEARCH` 避开；配合 `HPIPM BALANCE` 后，四项 KKT 均低于 `1e-6`。为避免 residual-authority 合法的发布命令在下一周期使 selector 无候选，stage 硬约束增加了“新命令相对名义队列尾项仍位于冻结 B_exec”不变性。随后发现的 cycle 57 失败并非新 OCP 不可行，而是整数纳秒控制时钟与 `dt=0.0333333333` 资产时间轴的亚纳秒比较误差；PhaseClock lookup-only 的 1 ns 容差已使完整 probe 全程 clock 最大步进恢复为 1。

如果实物最终没有成功，这套结果可以独立整理成一般应用型控制或机器人论文。但只能声称“仿真中有效”，不能声称真实液面已经降低。

## 4. 线路二：仿真通过后再做实物

### 实物1：标定 Scout 和测量时间轴

使用最终容器、液位和载荷，记录最终发布命令、Nokov、odom、IMU 和 RGB，辨识：

- 线速度和角速度延迟；
- 响应惯性和增益；
- 死区、饱和和可能的方向差异；
- ROS、Nokov、IMU 和 RGB 的时间偏差。

### 实物2：完成实车基础验证

详细技术文档把这一步叫 `G0`。人话就是检查：

1. Scout 的执行延迟是否稳定；
2. 从读取状态到预测终点的整段预测是否足够准确；
3. 第一拍在线修正在实车上是否真的高于噪声；
4. IMU 和 RGB 的时间、幅值和相位是否可信。

四项全部通过，才是“可以继续”；任一项不通过就停止，先修正延迟、模型或传感器。这一步通过不代表防晃性能已经成功。

### 实物3：重新生成实物专用资产

实物线路继续使用相同控制器代码，但必须替换为实车参数，并重新生成：

- 实物专用离线防晃轨迹；
- 执行状态匹配条件；
- 恢复判定规则；
- 实物实验配置和版本记录。

仿真线路的轨迹和恢复规则不能直接拿来上车。

### 实物4：重跑仿真，再做只观察、不控制的检查

先用实车标定参数配置控制器，再重跑仿真，确认代码修改后仍然正向。外部仿真 Scout 和液体仍要保留独立的参数偏差与未建模误差，不能与控制器内部模型完全相同。随后在实车上只观察控制器判断、不让它实际控制车辆，确认接回尾段的判断、时间索引和最终命令记录正确。

这两项通过后，才允许正式实物实验。

### 实物5：正式实物对比

名义主实验：

- C0、C1、C2、C4；
- 使用同一路径、容器、液位、起始条件和安全限制；
- 主要比较独立 RGB 液面高度，同时检查完成时间和路径误差。

恢复实验：

- C3、C4；
- 只做预先审查过的小幅、可重复偏离；
- 大量危险或明显不可恢复的情况留在仿真和录包回放中。

最终防晃结论只由独立 RGB 实物结果给出，控制器内部液面只能解释原因。

## 5. 两条线路共用什么，必须分开什么

### 共用

- 控制器 C++ 代码和双通道模型形式；
- 最终命令出口和记录方式；
- C0–C4 的定义；
- 分析指标和失败统计原则；
- “异常时停止，不偷偷放宽规则”的原则。

### 分开

- 执行和液体参数；
- 离线防晃轨迹；
- 执行状态匹配条件和恢复规则；
- 仿真冻结版本与实物冻结版本；
- 用于调参、独立验证和最终结论的数据。

任何一条线路只要根据验证结果改了模型或阈值，就必须生成新版本，并重新采集独立验证数据。

### 仿真无法代替实物的部分

以下内容不在仿真里伪造“已对齐”：

- RGB、Nokov、IMU 和 ROS 的多时钟偏差；
- Scout 在不同电量、载荷和地面下的真实延迟、死区和方向差异；
- 相机观察平面的有符号液面相位与 max-LCR 标定；
- 驱动器/CAN 的真实执行回执和现场安全边界。

仿真只复用它们的**数据结构、时间含义、双通道模型形式和失败关闭逻辑**。具体数值与正式结论必须留到实物重新标定和验证。

## 6. 暂时不做什么

- DualSPHysics/CFD；
- 动态障碍和在线重规划；
- 第二容器和大量路径；
- 鲁棒不变集、递归可行性等重理论扩展；
- 无法公平复现的外部防晃基线。

核心仿真和第一条实物路径通过后，再考虑第二冻结路径或可信的 input-shaping/fixed-profile 对照。

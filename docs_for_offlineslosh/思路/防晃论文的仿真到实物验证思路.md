### 整体路线

状态符号：`✅` 表示当前阶段已完成；`△` 表示方法已就绪但 release 手续尚未完成；`○` 表示尚未开始正式采集。

```text
两条主线共用的方法与工程准备
✅ PR-RMPC 方法、22D unequal-delay 执行链、失败语义
✅ C0--C4/IS runner、C1 冻结、C3/C4 严格对比和统计规则
   ↓
主线一：正式仿真，先建立论文保底
✅ 独立 Plant、P2/V3/recovery/held-out gate 与 development readiness
△ 当前位置：最终 clean HEAD → build/freeze/readiness → 人工 approval
○ 16 seeds × C0--C4/IS = 96 个正式 trials
   ├─ C4−C0 未受支持：如实报告负/不确定结果，不得调参改写
   └─ C4−C0 受支持：形成可独立成稿的“仿真有效”证据保底
                         ↓
主线二：实物验证，用于提升到真实液面结论
○ 标定 Scout／容器／液体／Nokov/odom／IMU／RGB 与多时钟
○ 重建实物专用轨迹、执行边界、gate/recovery 和安全 release
○ shadow/no-motion、低风险 development pilot 和正式实物对比
   ├─ 实物通过：形成带真实液面证据的完整稿件
   └─ 实物失败：保留仿真论文保底，不声称真实液面降低
```

这里的“保底”不是把 development 结果当作论文结果，而是先完成独立 Plant 上的正式主矩阵。只有 C4−C0 primary 受支持时，才存在“仿真有效”的备用稿；实物线路不得回过头改写该正式仿真结论。

## 1. 已有开发证据能说明什么

当前可以确认：

- P2 离线计划共 1070 个离散点、约 35.63 s；内部低阶模型结果只证明离线计划链正常，不是独立 Plant 的正式结论。
- recovery 数据共 44,940 条完整 rollout，fit/tune/held-out 三组的 seed 与 rollout 互斥。
- 冻结 held-out gate 的 recovered coverage 为 0.7297；未恢复样本中 false accept 为 $5/699$，95% Wilson 上界为 0.01663。这是开发 gate 的经验证据，不是安全保证。
- C4 seed 8601 两次完整 development 闭环与 seeds 8701--8705 readiness 均完成，无 solver failure/recovery/controlled stop。
- C1 seeds 8801--8805 均 `GOAL_REACHED`，直线、定曲率圆弧和 S 弯回归均通过；液面结果没有参与 C1 选择。
- 严格 C3 在 development seed 8601 中曾出现 terminal empirical monitor reject 而继续发布非零 solver 命令，证明 monitor-only 语义已真正实现。
- 最新回归为 Python 52 项通过（1 项跳过），C++ 三组定向测试为 26/26、25/25 和 9/9；论文 core clean build 为 9 页，无 error、undefined reference 或 Overfull。

当前不能确认：

- C4 相对 C0 的正式独立 Plant 液面改善；
- C4 相对 C1 的收益是否仍存在；
- nominal 路径上 C3/C4 是否有足够 gate activation 支持较强的机制解释；
- 对其他路径、其他容器、大参数扰动或真实 Scout/真实液体的泛化；
- gate 的形式安全性、递归可行性或在线避障能力。

## 2. 正式仿真主矩阵

### 2.1 冻结对象

全部 96 trials 共用：

- 同一条固定几何路径和 P2/V3 资产；
- 同一独立 Plant、起点、初始液面、控制频率、测量窗口和停止规则；
- seeds 3101--3116；
- 每个 seed block 中 C0、C1、C2、C3、C4、IS 各一次，共 $16\times6=96$ trials；
- 正式运行前已生成的交错顺序、主指标、失败定义和配对分析规则。

正式运行开始后，不得替换路径、Plant、条件配置、seed、顺序、门限或统计规则，也不得用正式液面结果回调 C1/C4/gate/V3。

### 2.2 六个条件

| 条件 | 实际含义 | 论文角色 |
| --- | --- | --- |
| C0 OrdinaryMPCC | 无离线液体资产、无相位重接、无在线 residual/gate 的普通几何 MPCC | 总体效果主基线 |
| C1 SmoothMPCC | C0 加独立 task-only development 冻结的平滑设置，`global_time_scale=1.0` | 削弱“只是更慢/更平滑”解释；不是精确等时匹配 |
| C2 OfflineReplay | 按冻结时钟回放 C4 所用 final-command nominal，无在线 residual 和 empirical/execution-gate intervention | 条件级离线参考，不是单因素消融 |
| C3 GateMonitorPR-RMPC | 与 C4 共用 22D Full SQP、V3、residual、全时域 $\mathcal B^{\mathrm{exec}}$、recovery 和发布链；9D empirical gate 只计算/记录 | gate-enforcement 严格配对的 monitor 侧 |
| C4 PhaseRejoinResidual | 完整方法：unequal-delay 执行增广、相位重接、有界 residual、$\mathcal B^{\mathrm{exec}}$、empirical gate enforce、recovery 和 fail-closed supervisor | 提出方法 |
| IS ZVD | 冻结的单模态 ZVD 输入整形参考 | 外部条件级参考，不进入 hard decision |

C0--C4 是一组便于理解的系统条件，不能被解读为逐级单因素消融。当前六条件中，只有 C3/C4 是结构上的 gate-enforcement 严格配对。

### 2.3 三组核心比较

| 比较 | 地位 | 解释规则 |
| --- | --- | --- |
| C4−C0 | **唯一 primary** | 评价完整方法相对普通 MPCC 的总体效果；不归因于单个组件 |
| C4−C1 | **primary 通过后的 fixed-sequence secondary** | 正向只能削弱通用的慢/平滑替代解释；未通过不反向否决已支持的 C4−C0 |
| C4−C3 | **gate-enforcement 机制对比** | 报告 paired effect/CI、gate activation、recovery、zero request 和失败；不使用 0.5 mm 硬门，不 veto primary |

C2 和 IS 只报告各自的 trial-level 分布与失败，不承诺 C4−C2 或 C4−IS 的配对效应/CI，也不作组件归因。

### 2.4 统计与失败语义

- 主指标是独立 Plant 外部测得液面高度在 motion-plus-fixed-tail 完整 trial 窗口的 Q95。
- 统计单位是完整 trial/seed block，不是 MPC 周期或 Plant 积分点。
- C4−C0 的 paired mean 10,000 次 bootstrap 95% CI 上界必须不高于 $-0.0005$ m；同时完成时间相对非劣上界为 10%，tracking Q95 差上界为 0.05 m。
- C4/C0 必须为零 method-failed pairs；C1 失败只影响第二层，C3 失败只影响 gate 机制层，C2/IS 失败只影响各自描述性结果。
- method failure 包括任务/runtime 失败、solver failure、controlled stop、publication/receipt/history failure、fail-closed zero request，以及 C3/C4 缺失或失败的 KKT audit。
- 方法失败 trial 保留为正式结果，不补跑到成功。若已完成测量窗，仍保留数值；若 runtime 错误使窗口不完整，则 trial 和 pair 继续保留，不删除、不插补，涉及它的 effect/CI 记为 `NOT_ESTIMABLE`，对应 claim 失败。
- C4−C3 只在 gate 确实 activation 时具有较强机制解释。如果介入很少或为零，就如实写成稀疏/无机制识别，不为制造 activation 修改路径或 gate。

## 3. 正式仿真的唯一剩余流程

### 3.1 开跑前

1. 处理另一窗口的工作树修改，将本路线图同步纳入最终提交，获得 clean HEAD。
2. 对该 HEAD 做一次 current/clean build。
3. 重新物化 formal session，只核对路径、Plant、P2/V3、六条件、seeds、交错顺序和分析规则；同时确认 C3/C4 的 pilot/causal-ready 标志和 residual authority 一致。
4. readiness 通过后由人工审查并签发 approval。
5. 仅通过正式 runner 按冻结顺序串行运行 96 trials。

这一流程不再新增逐文件 hash 层、claim 状态树、manifest 事务、递归配置等价或大量 mutation tests。已有的最小 session 绑定机制用于防止误跑，不再被扩展成新的论文研究对象。

### 3.2 开跑后

- 不根据中间结果提前停在有利方向，也不在不利方向临时扩样。
- 不自动重试、不挑 seed、不删除 method-failed trial。
- 方法失败作为结果保留并继续 campaign；文件缺失、不可读或进程无法启动等基础设施故障按冻结规则停止并保留记录。
- 如果发现实现/condition 错误或真值泄漏，整个 session 作废；修复后使用新 commit 和新 session 从头执行，不与旧 trial 混用。
- 96 trials 完成后使用已冻结 analyzer 生成一次 trial-level 分析；结果只决定论文主张强度，不回调方法。

## 4. 正式仿真后如何写结论

| 结果 | 可以写 | 不可以写 |
| --- | --- | --- |
| C4−C0 通过 | 在冻结路径、独立 planar Plant、当前样本与精度下，完整方法相对 OrdinaryMPCC 降低液面且任务非劣 | 真实液体有效、任意路径有效、单一组件已被归因 |
| C4−C1 也通过 | 收益在独立冻结 SmoothMPCC 下仍存在，削弱通用慢/平滑替代解释 | C1 与 C4 精确等时/等平滑，或所有慢/平滑解释已被证伪 |
| C4−C1 未通过 | 保留已支持的 C4−C0 总体结论，同时报告公平性 trade-off | 相对平滑基线仍有收益 |
| C4−C3 有效果且有 activation | 在当前合同和介入样本中，empirical-gate enforcement 与观测到的差异一致 | gate 对一般偏离有安全保证，或整个 recovery 机制的独立价值已证明 |
| C4−C3 activation 很少/为零 | 报告稀疏机制证据和 held-out gate 结果 | 用接近零的控制介入声称广义 gate 因果收益 |
| C4−C0 未通过 | 如实报告正式主比较为负或不确定，分析失败/trade-off | 用重跑、换 seed、调参或选择子集将其改写为正向 |
| C2/IS | 各条件的分布、失败和工程参考 | 单组件因果结论或 hard decision |

因此，仿真线路完成后可以形成一篇只声称“在冻结独立仿真合同下有效”的论文；不能把这一结论外推为真实液面已降低。

## 5. 从正式仿真进入实物

只有在仿真主矩阵完成、结果被冻结解释后，才开启实物线路：

```text
正式仿真 96 trials 完成
  → 冻结仿真结论，不回调正式仿真
  → 标定真实 Scout／容器／液体／多时钟
  → 资格验证 RGB、Nokov/odom、IMU 与命令时间轴
  → 重新生成实物专用离线轨迹、执行边界与 recovery/gate
  → shadow/no-motion 和低风险 development pilot
  → 新实物 release 与正式实物对比
```

### 5.1 实物标定与基础资格

使用最终容器、液位和载荷，记录最终发布命令、Scout 执行、Nokov/odom、IMU 和 RGB，至少确定：

- 线速度和角速度的实际延迟、响应惯性、增益、死区和饱和；
- ROS、最终命令、Nokov/odom、IMU 和 RGB 之间的 source-time 对齐；
- RGB 液面 max-LCR 的标定、噪声、符号/相位和 motion-plus-tail 窗口可检测性；
- 实车执行预测是否足以支持后续 phase-rejoining。

这一层通过只说明“可以安全地继续开发”，不说明真实防晃性能已经正向。

### 5.2 实物专用资产与 pilot

控制器代码和模型形式可复用，但不得直接复用仿真数值资产。必须使用实物标定数据重新生成：

- 实物专用 OfflineSloshOCP 轨迹和 V3；
- 两路命令执行模型参数与 $\mathcal B^{\mathrm{exec}}$；
- 实物 recovery 数据划分、empirical gate 和有界 recovery 参数；
- 实物安全边界、停止规则、试验配置和分析 release。

先做 shadow/no-motion 检查，再用与正式数据隔离的小规模低风险 development pilot。任何 pilot 后参数修改都要生成新实物 release；不得将调参 pilot 混入正式实物结果。

### 5.3 正式实物对比

实物主结论仍按相同的逻辑层级：

- C4−C0 是真实液面总体效果 primary；
- C4−C1 只在 primary 通过后评价，用来削弱慢/平滑替代解释；
- C4−C3 只在安全、预注册且确有 gate activation 的范围内解释；
- 主测量使用独立 RGB 液面，控制器内部液体状态只用于机制解释。

实物的路径、容器、液位、起点、初始静置、定位、底盘内部控制器、limiter、安全门和终止规则必须在各条件间保持一致。

## 6. 仿真与实物的共用与隔离

| 内容 | 是否共用 | 规则 |
| --- | --- | --- |
| 控制器 C++ 架构、发布链和失败关闭 | 共用 | 保持同一方法语义 |
| unequal-delay 双通道模型形式 | 共用 | 参数必须分别辨识 |
| C0/C1/C2/C3/C4/IS 论文含义 | 原则共用 | 实物条件须另行安全审查和冻结 |
| Plant/真实 Scout 与液体参数 | 不共用 | 仿真 Plant 不得冒充实物参数 |
| 离线轨迹、V3、$\mathcal B^{\mathrm{exec}}$、gate/recovery | 不共用数值 | 实物线路必须重新生成和独立验证 |
| development/formal 数据 | 不共用 | 不混合调参、held-out 和正式结论数据 |

仿真只能复用实物所需的数据结构、source-time 含义、执行模型形式和 fail-closed 逻辑。RGB/Nokov/IMU/ROS 多时钟、Scout 的真实死区/饱和/电量/载荷效应以及现场安全边界不能用仿真“已对齐”代替。

## 7. 明确推迟的工作

以下都不是当前 96-trial 正式仿真的前置条件：

- A0/A1/A3 扩展单因素消融；
- 延迟、液体频率、阻尼和初始偏离的大规模鲁棒性扫描；
- 第二路径、第二容器或新 seed 的独立 replication；
- DualSPHysics/CFD 高保真流体仿真；
- 动态障碍、在线重规划和地图更换；
- 鲁棒不变集、递归可行性或形式安全证明；
- 新的实验平台状态机、逐文件哈希层、深层配置等价和大量 mutation tests。

这些工作若在主矩阵之后开展，必须使用新的预注册条件/session，不能改写或混入当前 16-block primary。

## 0. 先看懂整个方法

### 0.1 一句话框架

PR-RMPC 先沿冻结路径离线生成一条防晃名义序列；在线根据真正发布过的命令，把机器人、液体状态和线／角两路命令队列推到预计发布时刻，在邻近相位中寻找可以接回名义尾段的位置，再由 22 维 residual MPC 只做有界小修正。若求解或重接条件不成立，监督器只能选择冻结恢复反馈或 fail-closed 零命令，最后所有分支都经过同一个安全与发布事务。

```text
离线层
固定路径
  → M1 OfflineSloshOCP 防晃名义序列与 V3 artifact
  → recovery rollout 生成 gate／B_exec／恢复合同

在线层
M2 内部液体状态 ─┐
M3 双通道执行对齐 ├→ M4 邻近相位与执行资格
                   → M5 22D PR-RMPC 有界修正
                   → M6 gate／recovery／fail-closed 监督
                   → M7 唯一安全发布事务与命令历史

评价层
M8 独立 Plant 或实物 RGB 液面，只评价，不向控制器泄漏真值
```

### 0.2 八个模块的简单解释

| 模块 | 简单作用 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| M1 离线名义与 V3 | 先规划“怎样沿固定路径走得更不晃”，并保留完整减速、停车和沉降尾段 | 固定路径、内部低阶液体模型、执行模型与约束 | 名义机器人／液体／命令队列序列，以及逐相位恢复合同 |
| M2 内部液体状态 | 用车辆激励传播一阶模态液体记忆，供相位评分和在线优化使用 | odom 或经过资格验证的 IMU、历史状态 | 4 维内部液体状态；不是外部液面真值 |
| M3 双通道执行对齐 | 分别描述线速度和角速度命令何时生效，并把 source-time 状态推到预计发布时刻 | 最终发布命令历史、线／角执行合同、机器人状态 | 对齐后的机器人状态、执行器输出和两路 pending queues |
| M4 相位与执行资格 | 只在时钟附近单调寻找接回位置，先排除当前或未来命令队列不兼容的候选 | 对齐后的 22 维状态、V3、$\mathcal B^{\mathrm{exec}}$ | 一个相位索引及完整预测域可执行 witness |
| M5 22D PR-RMPC | 在名义命令附近求一个有限 residual，不重新规划路径，也不允许任意跳相 | 已选相位、22 维初态、名义尾段和有界 residual | 经过 KKT、硬约束与 causal rollout 复核的第一拍命令 |
| M6 gate 与 recovery | 判断 residual 或恢复是否允许接回；不允许时 fail closed | 9 维 empirical gate、14 维执行兼容集、冻结恢复反馈 | residual、bounded recovery 或零请求三选一 |
| M7 安全发布与历史 | 统一限幅、仲裁和发布，只把真正交给 transport 的命令写回历史 | 控制候选、安全状态和 publication receipt | 唯一最终命令、命令历史以及是否提交相位 |
| M8 独立评价 | 在完整运动＋固定尾段上计算外部液面、任务和失败统计 | 独立仿真 Plant，或未来的 RGB／Nokov／IMU | trial-level 指标、配对效应、置信区间和失败记录 |

### 0.3 BT 不是 PR-RMPC 的一个小模块

BT（bounded tracking）是当前的简化备选方法：按固定时钟执行同一 V3 轨迹，只用冻结的有界机器人反馈修正跟踪，并考虑预计生效时刻和命令队列；它不使用 22 维求解器、相位重接、empirical gate 或液体真值，但继续经过 M7 的安全、发布和历史链。

因此：

- PR-RMPC 成功时，论文叙述更完整，核心是“执行感知的相位重接＋有界在线优化”；
- PR-RMPC 失败而 BT 成功时，论文应改为“离线完整防晃轨迹＋执行感知的有界在线跟踪”；
- 不能把 BT 藏进 PR-RMPC 后仍称为原方法，也不能用 BT 的开发结果证明 PR-RMPC 有效。

## 3. 整体路线：仿真和实物并列推进

仿真用于在实物实验失败时保留一条可独立解释的论文路线；实物用于获得真实液面结论。两条线共用方法形式、数据结构和失败语义，但不共用数值参数、资产、调参数据或正式结论。

```text
共同方法与工程底座
✅ 固定路径／任务定义、M1 离线资产链、M7 发布链、M8 评价与失败语义
🔴 当前 PR-RMPC 的 M3--M6 不放行
△ BT 是简化候选，尚未冻结
   ├──────────────────────────────┐
   ↓                              ↓
仿真主线：论文保底              实物主线：真实液面证据
✅ v1 正式 96/96，结果 FAIL      ○ Scout 双通道执行辨识
△ PR-RMPC 最后一次单因素诊断    ○ Nokov/odom/IMU/RGB 多时钟资格
△ 或冻结 BT 简化方法            ○ 实物专用 V3／边界／gate（若保留）
○ 新版本＋全新 seeds 正式仿真   ○ shadow/no-motion 与低风险 pilot
○ 冻结并如实报告新正式结论      ○ 全新 release 的正式实物对比
```

两条主线遵守三个隔离原则：

1. 实物成功或失败都不能回过头改写 v1 或未来已经开始的正式仿真；
2. 仿真参数不能直接冒充实物参数，尤其不能直接复用当前 `0.15/0.22 s + tau=0`；
3. 某条线根据 development 结果修改方法后，必须建立新版本、使用全新未见 seeds／trials，并透明披露 post-hoc 来源。

## 4. 仿真主线下一步

### 4.1 PR-RMPC 只剩一次单因素机会

唯一值得做的诊断是把当前纯延迟执行合同替换成“delay＋一阶惯性”的完整双通道合同。delay 与 time constant 必须联合确定，不能在原 `0.15/0.22 s` 上简单叠加 Plant 的 time constant，否则可能重复计算滞后。

诊断规则：

1. 先把现有辨识值只作为 development oracle／候选，不作为论文或实物正式参数；
2. 只改变执行模型及其必须机械重生的 solver／V3 状态，不同时修改 cost、gate 数值、residual、预测长度、安全或统计；
3. 先跑 C3 seed 9911，分离执行模型／求解器问题和 terminal gate enforcement；
4. C3 完整完成且执行兼容不再贴边后，才跑同 seed 的 C4；
5. 单 seed 通过后才扩到 9912--9915。

继续 PR-RMPC 的最低条件：

- `5/5` 完成任务；
- 无 solver failure、controlled stop、zero request、deadline、receipt 或 history 异常；
- 完整窗口与 10%--90% 辅助窗口都向 BT 方向改善；
- 相同任务下 tracking 和完成时间不明显劣化；
- C4 相对 C3 必须出现可解释的 gate 介入，否则删除或降级 gate 贡献。

任一阶段失败就停止，不再同轮放宽 gate／$\mathcal B^{\mathrm{exec}}$、修改 cost、增加 SQP 或换统计窗口救结果。

### 4.2 若转 BT

BT 成为主方法时，需要做的是收敛论文，而不是继续扩张平台：

1. 将当前 development-only 实现整理、测试并提交；
2. 将 Methods 改写为“离线完整防晃轨迹＋执行感知有界跟踪”；
3. 保留 OrdinaryMPCC、SmoothMPCC 和 OfflineReplay 三类必要对照；
4. 删除 PR-RMPC 的 gate 因果主张，不再强行保留 C3/C4 命名；
5. 冻结后使用全新 seeds 和 session 运行正式仿真。

### 4.3 新正式仿真的共同规则

无论最终选择 PR-RMPC 还是 BT：

- 固定路径、Plant、seed、配置、顺序、完整 motion-plus-tail 主窗口和统计口径；
- 统计单位是完整 trial／seed，不是控制周期；
- 保留所有失败 trial，不删除、不补跑到成功；
- 完整窗口是主结果，路径进度 10%--90% 只能作为辅助解释；
- 正式实验开始后不再回调参数；
- 新方法版本必须使用全新 seeds／session，不与 v1 或 9911--9915 混合；
- 正式 bag 写入 `/data/a/slosh_bags/sim`；
- 不再新增逐文件审计层、复杂 claim 状态树或大规模 mutation tests。

若 PR-RMPC 保留，核心比较仍是 C4−C0 总体效果、C4−C1 排除仅仅更慢／更平滑、C4−C3 评价 gate；C2／IS 只作辅助。若转为 BT，则应重新冻结适合 BT 的简化比较，不能沿用 C4−C3 制造不存在的 gate 贡献。

## 5. 实物主线

实物线不必等待新的正式仿真结束才开始基础标定，但必须在任何 `enforce` 或正式采集前完成自己的资格链。

### 5.1 执行与测量资格

使用最终容器、液位、载荷和预定地面，记录最终发布命令、Scout 执行、Nokov/odom、IMU 和 RGB，至少确定：

- 线／角两路的 delay、time constant、增益、死区、饱和和跨工况漂移；
- ROS、最终命令、Nokov/odom、IMU 和 RGB 的 source-time 对齐；
- RGB 液面 max-LCR 的标定、噪声、符号／相位和完整尾窗可检测性；
- 用未参与辨识的 bag 比较“纯延迟”和“delay＋惯性”谁更能预测真实 `v/omega`；
- 在不发布控制命令的 shadow replay 中，PR-RMPC 是否仍出现 gate 大量拒绝、执行边界贴边或求解失败。

双通道模型的 schema 可以共用，仿真和实物的数值参数与资格不能共用。只有 held-out 预测和 shadow 稳定，才允许进入低风险实物闭环。

### 5.2 实物专用资产与正式实验

根据最终选择的方法重新生成：

- 实物专用 OfflineSloshOCP／V3；
- 实物执行边界；
- 若保留 PR-RMPC，则生成实物 recovery 数据、empirical gate 和恢复反馈；
- 实物安全边界、停止规则、试验配置和分析 release。

先做 shadow/no-motion，再做与正式数据隔离的小规模低风险 pilot。正式实物主测量使用独立 RGB 液面；控制器内部液体状态只用于控制和机制解释，不能自证效果。

# 防晃论文：从仿真到实物的工作路线

> 这份文档回答“接下来大致要做哪些事”。具体参数、命令和统计规则分别放在 Methods、Experiments 和实物标定文档中。

> **正式实物闭环的硬性前置条件：**这里的“正式实物闭环”不是代码能够发布 `/cmd_vel`，也不是理想底盘上的一次正向仿真，而是同一个冻结 release 同时满足：**执行与测量参数已经标定、控制因果关系正确、带标定执行模型的仿真已经通过**。三项缺一时只能进行 development、shadow 或低速接线 smoke，不能进入正式 pilot、C0–C4 实物对比，也不能宣称方法已经适配 Scout 实物。

## 1. 最终要证明什么

论文只需要建立一条清楚的证据链：

> **仿真说明方法在设计模型中为什么有效；实物保真度实验说明模型在目标工作区间具有控制价值；正式实物对比最终证明真实液面降低。**

三类结论不能互相替代：

1. 仿真中的 `/slosh/height` 只能证明模型内机制；
2. 模型保真度只能证明模型“足够可用”，不等于控制方法已经有效；
3. 防晃性能最终由独立 RGB 实物结果决定。

论文中的证据顺序是“仿真→保真度→实物”，但实际工作要先把测量链和实车参数准备好：

```text
证据链资格检查
→ Scout执行模型辨识
→ 完成目标方法和正式artifact
→ 带冻结执行模型的因果仿真验收
→ 实物模型保真度验证
→ 小规模pilot
→ 正式实物闭环对比
```

正式实物闭环形成前必须闭合下面三件事：

1. **经过标定：**冻结 \(d_v,d_\omega,\tau_v,\tau_\omega\)、适用工况、执行误差边界、计算/发布延迟 \(d_c\)、IMU/RGB时间关系及平台真实限幅；当前 `0.15/0.22 s` 和零时间常数只能作为候选值。
2. **因果正确：**预测从预计发布时间出发，最终 \(u^{\mathrm{pub}}\) 进入命令历史；本周期新命令在线/角差分延迟区间内的作用必须进入 delay-augmented OCP 或严格等价 bridge，不能只用旧命令把状态搬到共同前沿。
3. **仿真通过：**使用当前冻结 commit、solver、artifact 和 runner，在独立仿真执行层中施加标定后的非零延迟、惯性及必要非线性；完成 C0–C4、受控偏离和参数扰动，并同时通过 slosh、任务公平性、安全和实时性门。零延迟、瞬时跟随底盘上的正向 proxy 结果不满足这一条件。

## 3. 第一步：先把证据链打通

这一步不是论文的第四个贡献，而是后续所有结果的前置资格门。

### 要做的事

- [ ] `cycle_id`贯通同一控制周期中的状态快照、OCP、求解命令、限幅后命令、最终发布命令和控制审计；
- [ ] Nokov、odom、IMU 和 RGB 保留各自的 source/exposure timestamp，再按物理时间离线关联，不强行共用 `cycle_id`；
- [ ] 标定 ROS、Nokov、IMU 和 RGB 时间轴的偏差及不确定度；
- [ ] recorder 同时记录最终 `/cmd_vel`、执行状态、Phase-Rejoin诊断、Nokov、odom、IMU和RGB；
- [ ] 每条预测状态携带明确的目标物理时刻，禁止按 bag 索引或最近帧直接配对。

### RGB需要两个输出

- **`max-LCR`：**继续作为液面 P95、peak、RMS 和 freeboard 的主效果量；
- **有符号量 \(h_R-h_L\)：**用于观察平面的过零、主频、相位和衰减。

单相机只能验证观察平面的液面相位，不能宣称完整验证二维液体四状态。约 4.97 Hz 下，10 ms 时间误差约等于 18°相位误差，所以 RGB 曝光时间必须单独校准。

### 完成标志

输出一份时间轴审计报告和一份 RGB 标定报告。时间轴不能闭合时，不进入 F2 或正式实物实验。

## 4. 第二步：辨识并冻结 Scout 执行模型

- [ ] 使用与正式实验相同的安装位置、总质量和重心；
- [ ] 先使用等质量刚性配重或密封容器辨识，再用正式开放容器和液位做独立验证；
- [ ] 分别执行安全的直线加减速、转向和组合运动；
- [ ] 使用最终发布的 `/cmd_vel`，而不是求解器限幅前命令；
- [ ] 以 Nokov 为车体运动基准，odom 检查在线状态，IMU 检查加速度、角速度和关键频率幅相；
- [ ] 分别辨识线/角通道的延迟、时间常数、增益、死区、限幅和交叉耦合；
- [ ] 检查参数在重复 trial、电量变化和正式地面条件下的波动。

辨识数据与验证数据必须按完整 trial 分开。当前约 150 ms 线速度延迟和 220 ms 角速度延迟只能作为初值，不能直接视为正式参数。

### 完成标志

得到冻结的执行模型、适用范围和 held-out 误差报告。经 limiter 和安全链后的第一拍命令必须在真实 \(v,\omega\) 或液体激励上产生高于执行噪声的差异。

## 6. 第四步：做低阶模型仿真

仿真使用与后续实物一致的路径、artifact、条件定义和限制。

这里必须把“液体模型仿真”和“底盘执行仿真”同时闭合。执行层应独立接收最终 \(u^{\mathrm{pub}}\)，再施加冻结的 \(d_v,d_\omega,\tau_v,\tau_\omega\) 及已被数据支持的增益、死区、饱和或方向不对称；控制器内部 predictor 不能同时充当被验证的仿真对象。当前零延迟、瞬时速度跟随的 proxy 只保留为接线 smoke，不作为正式仿真通过证据。

### 基线和作用

| 条件 | 主要回答的问题 |
| --- | --- |
| **C0 OrdinaryMPCC** | 相对普通 MPCC 是否降低模型晃动 |
| **C1 SmoothMatch** | 收益是否只是因为更慢或更平滑 |
| **C2 OfflineReplay** | 完整离线防晃序列本身是否有效 |
| **C3 ResidualNoGate** | 没有 recovery admission 时 residual 会怎样 |
| **C4 Full** | 完整方法的系统表现 |
| **Legacy S-MPCC** | 新方案相对旧在线长时域方案的差别，仿真次要对照 |

C1 在独立开发数据上只用一个全局时间/速度尺度匹配完成时间；速度、加速度、jerk和命令频谱只设容差并完整报告，不要求逐项精确相同。

### 要运行的场景

- [ ] 执行链验收：确认仿真 plant 的命令—真实速度响应复现冻结执行模型及误差范围；
- [ ] 名义路径：C0、C1、C2、C4；
- [ ] 受控偏离：C3 与 C4，优先使用附加延迟/限幅和短速度门；
- [ ] 参数扰动：液体频率、阻尼和执行延迟在标定范围内变化；
- [ ] 机制检查：第一拍 residual、相位索引、gate、stored action、停车分支和30 Hz实时性。

### 仿真通过标志

- 当前冻结 release 的构建、单元测试、确定性 replay 和端到端仿真全部通过；
- C4 的内部液体状态和独立仿真 slosh monitor 相对预注册基线均为正向；
- 完成时间、速度、加速度、jerk和路径误差满足公平性门，不能用单纯变慢换取“防晃改善”；
- 在标定范围内扰动延迟和惯性后，执行前沿、terminal gate、recovery/受控停车与安全分支仍符合合同；
- 每项结果能够追溯到同一个 commit、配置、solver、artifact 和仿真执行模型 hash。

任一项未通过，都不能进入正式实物闭环；先修改方法或执行模型，生成新 release 后重新完成本节验收。

### 仿真能写的结论

> 在冻结低阶模型及其参数扰动范围内，完整方法降低模型预测晃动，并改善在线修正与离线防晃尾段的兼容性。

不能把同源模型的正向结果写成真实液体性能。

## 7. 第五步：做实物模型保真度验证

### F1：验证液体模型本身

用离线平滑的 Nokov/odom 运动学驱动冻结的低阶液体模型，并用 IMU 交叉检查，再与同步 RGB 比较：

- [ ] 用 `max-LCR`比较幅值、P95、peak和衰减；
- [ ] 用 \(h_R-h_L\) 比较观察平面的主频、过零和相位；
- [ ] 报告模型和RGB不一致的工况，不只展示最好曲线。

F1使用实测运动，是对液体模型的“实际运动输入上限检查”，不能冒充在线预测结果。

### F2：验证完整在线预测链

使用控制器实际能够获得的状态、最终命令历史和冻结执行模型进行预测。时间语义固定为：

```text
状态时刻 t_s
→ 预计发布时间
→ 约220 ms物理慢通道 / 约233.3 ms栅格共同前沿
→ 前沿后约100 ms液体窗口
→ 预计发布时间后约333.3 ms联合终端
```

- [ ] 在线预测按“预计发布时间”建立，实际发布时间只用于事后误差审计；
- [ ] RGB真值按校准后的曝光时刻插值或相位拟合；
- [ ] actual-motion replay达到绝对保真门；在专门制造执行失配的工况中，再检查它是否优于planned-input replay；
- [ ] 用少量安全候选做配对反事实：重复同一预激励，分别执行 residual 第一拍和 stored-recovery 第一拍，随后采用相同尾段/闭环策略；
- [ ] 配对前匹配有符号液面值及斜率、机器人状态、相位索引和pending命令buffer；动作或RGB差异低于可检测范围时记为tie，不强行判对错。

### 完成标志

模型在目标工作区间具有足够的观察平面相位、候选排序和完整 lead 预测能力。若根据验证结果修改模型或 gate，原验证数据立即降为开发数据，必须重新采集新的 held-out 数据。

## 8. 第六步：做小规模 pilot 并冻结正式协议

pilot不用于论文最终效果估计，只决定流程是否可用和正式试验需要多少block。

### pilot要检查

- [ ] C0–C4最终发布命令确实不同且符合各自定义；
- [ ] C1完成时间匹配达到预设容差；
- [ ] RGB主指标可检测，signed RGB和所有时间戳有效；
- [ ] tracking、完成时间、安全、solver和recorder/postflight全部通过；
- [ ] C3/C4在受控偏离中确实产生不同决策；
- [ ] 用配对方差和预注册有意义效应确定正式block数。

旧实验的 `0.10 mm＋2/3 block正向`只能作为development晋级候选，必须根据新RGB标定、重复性和实际物理意义重新确认，不能直接升级为正式SESOI。

### pilot通过后冻结 `FREEZE_ID`

至少绑定：

- git commit、solver生成物和分析脚本hash；
- C0–C4配置、正式路径和OfflineSloshOCP artifact hash；
- 执行/液体模型及适用范围；
- 容器、液位、载荷、安装位置和RGB标定；
- motion＋fixed-tail窗口、主/次指标和检验顺序；
- 失败、重试、缺失RGB、硬件故障和停止规则；
- 正式试验的平衡顺序和计划block数。

目前不要预先把“40＋24＝64条”认定为充分样本量。它可以作为资源预算参考，但 nominal 与 recovery 是两个独立矩阵，最终数量由pilot分别决定。

## 9. 第七步：做正式实物闭环对比

### 名义主实验

同一block内运行 C0、C1、C2、C4，采用预先生成的平衡顺序；每条trial开始前满足相同的液体沉降条件。

正式判断顺序：

1. **C4 vs C0：**相对普通 MPCC 是否降低真实液面；
2. **C4 vs C1：**排除单纯减速或平滑解释；
3. **C4 vs C2：**报告在线纠偏的任务收益与防晃代价。

### Recovery实验

在独立矩阵中比较 C3 与 C4。每条trial只安排一个预注册偏离episode，优先使用可重复的附加延迟/限幅或短速度门。

- false-safe、恢复成功和失败以独立episode/trial统计；
- cycle-level coverage只作描述，不能把几百个周期当成独立样本；
- 同时报告phase-bin coverage和最差相位；
- 样本量不足时只能报告经验结果，不能宣称低绝对失效率或安全认证。

### 主指标和公平性

- **唯一主物理指标：**motion＋tail窗口内独立RGB max-LCR的trial-level P95；
- **辅助液体指标：**peak、RMS、freeboard和有符号相位曲线；
- **任务指标：**完成时间、tracking、成功/停车/失败；
- **公平性指标：**速度、加速度、角加速度、jerk和命令频谱；
- **工程指标：**solver时间、状态过旧、合同失败、安全覆盖和最终发布命令。

若RGB降低但明显更慢、跟踪更差或失败更多，只能报告trade-off，不能写“总体优于普通MPCC”。

## 10. 数据怎样分开

| 数据 | 用途 | 不能做什么 |
| --- | --- | --- |
| `D_id` | 执行和液体模型辨识 | 不能充当held-out fidelity |
| `D_fid` | 模型与完整lead独立验证 | 不能调模型、gate或阈值 |
| `D_dev` | 控制器、gate和流程开发 | 不能进入正式效果估计 |
| `D_pilot` | 检查流程、估计方差和正式规模 | 不能与confirmation合并 |
| `D_confirm` | 最终名义与recovery结论 | 不能看结果后继续调参并追加池化 |

污染规则只有一句：

> 使用某批验证结果修改任何模型、阈值或gate后，这批数据对新release不再是held-out；必须生成新的`FREEZE_ID`，重新pilot，并采集全新的验证或confirmation数据。旧数据仍保留为旧release的真实记录。

统计单位始终是完整trial、block或预注册recovery episode，不是RGB帧、IMU样本或MPC周期。

## 11. 暂时不做什么

- **DualSPHysics：**暂不进入主线，也不是投稿前置条件。实物主实验完成后，如仍需补充非线性液体解释，再在服务器上运行少量代表工况；
- **动态障碍和在线避障：**当前不扩展，先证明固定路径上的防晃与恢复机制；
- **第二容器和大量路径：**核心证据通过后再考虑；
- **Input shaping实物基线：**外部辨识度高，但只有在实现和公平性检查可靠后才作为次要实物对照；Legacy S-MPCC先保留为仿真对照。

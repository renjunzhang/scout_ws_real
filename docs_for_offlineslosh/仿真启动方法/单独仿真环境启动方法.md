## 1. 先选对入口

当前有两个不同用途的“仿真环境”，不能混用。

| 入口 | 用途 | 能否产生论文正式液面数据 |
| --- | --- | --- |
| 独立 C++ Scout＋液体 Plant＋closed-loop runner | Phase-Rejoining 控制链、外部液面、C0--C4/IS trial | **唯一正式入口；当前只开放 development** |
| Gazebo proxy＋Cartographer＋RViz | ROS topic、TF、定位、传感器和可视化联调 | **不能**；没有本文冻结的独立液体真值 |

因此，只想复现 seed 8601 或检查 C4/C3 时，不需要启动 ROS、Gazebo、RViz、路径发布器或 SPMPC node。Gazebo proxy 的启动方法放在本文后半部分。

## 8. Gazebo proxy：只做 ROS/定位/可视化检查

只有需要 `/map`、`/odom`、激光、IMU、TF 和 RViz 时才启动 proxy。它不是正式液体 Plant。

在新的 Bash 终端运行：

```bash
START_PROXY=true \
START_LOCALIZATION=true \
START_PATH_PUBLISHER=false \
START_SPMPC=false \
SCOUT_PROXY_FULL_ROS_MASTER_URI=http://localhost:11328 \
SCOUT_PROXY_FULL_GAZEBO_MASTER_URI=http://localhost:11362 \
MAP_FILE=/data/a/scout_sim_replacement/maps/proxy_world_manual_saved_20260611_154348.pbstream \
SPAWN_X=-4.0 \
SPAWN_Y=0.0 \
SPAWN_Z=0.0 \
SPAWN_YAW=0.0 \
USE_RVIZ=true \
GAZEBO_GUI=true \
TRACKING_RVIZ=true \
LOCALIZATION_RVIZ=false \
/data/a/scout_sim_replacement/scripts/launch_proxy_sim_localization_env.sh
```

无界面时把以下四项设为 false：

```text
USE_RVIZ=false
GAZEBO_GUI=false
TRACKING_RVIZ=false
LOCALIZATION_RVIZ=false
```

终端出现 `stack is up; press Ctrl-C to stop` 后，再连接同一 ROS master 检查：

```bash
source /opt/ros/noetic/setup.bash
export ROS_MASTER_URI=http://localhost:11328
export GAZEBO_MASTER_URI=http://localhost:11362

rostopic echo --noarr -n 1 /map
rostopic echo --noarr -n 1 /odom
rostopic echo --noarr -n 1 /scan_front
rostopic echo --noarr -n 1 /imu/data
timeout 5s rosrun tf tf_echo map base_link
```

该入口不会启动路径、SPMPC、对比 runner 或 rosbag。`/cmd_vel`、`/scout/global_path` 和 `/scout/global_path_fixed` 不应有发布者。

停止时只在启动终端按 `Ctrl-C`，不要使用 `killall`、`pkill`，也不要仅关闭 Gazebo 窗口。

## 9. 常见误区

- Gazebo proxy 画面正常，不等于防晃 Plant 或正式液面指标正常；
- seed 8601 单次通过，不等于 C4 多 seed readiness 通过；
- `READY_NOT_EXECUTED` 不等于论文结果 PASS；
- C1 运行成功不等于已经公平匹配；
- summary 中内部 observer 液面不能替代外部 `primary_metric`；
- `/data/a/...` 是证据目录，不加入 Git，不覆盖旧运行；
- 当前不使用 DualSPHysics，不接触实车，不启动正式多种子 campaign。

# 单独仿真环境启动方法

> 更新日期：2026-08-20
>
> 这份文档只说明怎样启动当前 `control/spmpc_local_planner` 使用的仿真环境，不启动路径、局部控制器、对比算法或录包。

下面的命令按 Bash 编写。如果当前终端是 zsh，先运行：

```bash
bash
```

再执行后续命令。不要在 zsh 里直接 `source setup.bash`。

## 1. 使用哪个入口

当前 offline-slosh 分支研究的是：

```text
src/scout_apps/control/spmpc_local_planner
```

因此，单独查看 Gazebo、定位、地图和传感器时，使用：

```text
/data/a/scout_sim_replacement/scripts/launch_proxy_sim_localization_env.sh
```

`src/scout_apps/simulation/spmpc_sim_local_planner` 是另一套隔离的 SIM-R8 实现，不与这里的环境和控制器混用。SIM-R8 正式仿真目前仍是 `DESIGN_ONLY / FORMAL_SIM_NO-GO`，不是本文档的启动对象。

## 2. 启动环境

在一个新 Bash 终端运行：

```bash
START_PROXY=true \
START_LOCALIZATION=true \
START_PATH_PUBLISHER=false \
START_SPMPC=false \
SCOUT_PROXY_FULL_ROS_MASTER_URI=http://localhost:11328 \
SCOUT_PROXY_FULL_GAZEBO_MASTER_URI=http://localhost:11362 \
MAP_FILE=/data/a/scout_sim_replacement/maps/proxy_world_manual_saved_20260611_154348.pbstream \
SPAWN_X=-4.0 \
SPAWN_Y=0.0 \
SPAWN_Z=0.0 \
SPAWN_YAW=0.0 \
USE_RVIZ=true \
GAZEBO_GUI=true \
TRACKING_RVIZ=true \
LOCALIZATION_RVIZ=false \
/data/a/scout_sim_replacement/scripts/launch_proxy_sim_localization_env.sh
```

四个 `START_*` 开关要显式写出。这样即使当前终端遗留了旧环境变量，也不会误启动路径或 SPMPC。

当前使用的地图是：

```text
/data/a/scout_sim_replacement/maps/proxy_world_manual_saved_20260611_154348.pbstream
```

这个 proxy 环境命令不要省略 `MAP_FILE`，也不要依赖脚本内部的默认地图。

## 3. 它会启动什么

启动顺序是：

```text
独立 roscore
→ proxy Gazebo 和 Scout 模型
→ 等待 /odom、/scan_front、/imu/data
→ Cartographer 定位
→ 等待 /map 和关键 TF
→ tracking RViz
→ 保持运行，等待 Ctrl-C
```

它会启动：

- Gazebo server 和 Gazebo 窗口；
- Scout proxy 底盘和传感器；
- Cartographer 定位；
- `/map`、`/odom`、`/scan_front`、`/imu/data` 和 TF；
- tracking RViz；
- 只负责限幅的命令保护节点。

它不会启动：

- `/scout/global_path` 或 `/scout/global_path_fixed` 的发布器；
- SPMPC；
- DWA、TEB、`mpc_local_planner` 或 LT-DWA；
- rosbag recorder；
- 对比实验 runner。

环境中的命令保护节点会订阅 `/cmd_vel` 并发布 `/cmd_vel_drive`。它本身不会生成运动命令。

## 4. 无图形界面启动

不需要 Gazebo 和 RViz 窗口时运行：

```bash
START_PROXY=true \
START_LOCALIZATION=true \
START_PATH_PUBLISHER=false \
START_SPMPC=false \
SCOUT_PROXY_FULL_ROS_MASTER_URI=http://localhost:11328 \
SCOUT_PROXY_FULL_GAZEBO_MASTER_URI=http://localhost:11362 \
MAP_FILE=/data/a/scout_sim_replacement/maps/proxy_world_manual_saved_20260611_154348.pbstream \
USE_RVIZ=false \
GAZEBO_GUI=false \
TRACKING_RVIZ=false \
LOCALIZATION_RVIZ=false \
/data/a/scout_sim_replacement/scripts/launch_proxy_sim_localization_env.sh
```

这个脚本仍会占用当前终端，只是不打开图形窗口。

如果只想打开一种界面：

| 需要的界面 | 设置 |
|---|---|
| 只开 RViz | `USE_RVIZ=true GAZEBO_GUI=false TRACKING_RVIZ=true LOCALIZATION_RVIZ=false` |
| 只开 Gazebo | `USE_RVIZ=true GAZEBO_GUI=true TRACKING_RVIZ=false LOCALIZATION_RVIZ=false` |

通常不同时打开 tracking RViz 和 Cartographer 自带的 RViz，所以 `LOCALIZATION_RVIZ` 保持 `false`。

## 5. 启动后的检查

环境终端出现下面这句话，才表示脚本内部的 topic 和 TF 等待已经通过：

```text
stack is up; press Ctrl-C to stop
```

再开一个 Bash 终端，连接到这个独立 ROS master：

```bash
source /opt/ros/noetic/setup.bash
set -euo pipefail
export ROS_MASTER_URI=http://localhost:11328
export GAZEBO_MASTER_URI=http://localhost:11362

rostopic echo --noarr -n 1 /map
rostopic echo --noarr -n 1 /odom
rostopic echo --noarr -n 1 /scan_front
rostopic echo --noarr -n 1 /imu/data

TF_CHECK="$(timeout 5s rosrun tf tf_echo map base_link 2>&1 || true)"
printf '%s\n' "${TF_CHECK}"
grep -Fq 'Translation:' <<< "${TF_CHECK}"
grep -Fq 'Rotation:' <<< "${TF_CHECK}"
```

然后检查控制和路径话题没有发布者：

```bash
set -euo pipefail

# 先确认 ROS master 可连接，避免把连接失败误当成“没有节点”。
rosnode list >/dev/null

assert_no_publishers() {
  local topic="$1" info publishers
  if ! rostopic list | grep -Fxq "${topic}"; then
    return 0
  fi
  info="$(rostopic info "${topic}")"
  publishers="$(awk '
    /^Publishers:/ {inside=1; next}
    /^Subscribers:/ {inside=0}
    inside && /^[[:space:]]*\*/ {print}
  ' <<< "${info}")"
  if [[ -n "${publishers}" ]]; then
    printf 'ERROR: %s has publishers:\n%s\n' "${topic}" "${publishers}" >&2
    return 1
  fi
}

assert_no_publishers /cmd_vel
assert_no_publishers /scout/global_path
assert_no_publishers /scout/global_path_fixed
```

最后在 RViz 中人工确认：

- 地图正常显示；
- 激光点与地图墙体对齐；
- RobotModel 位置和方向正确；
- TF 没有明显跳变或错位。

任何一项不正常，都不要接入路径或控制器。

## 6. 端口、日志和停止方法

默认端口是：

```text
ROS_MASTER_URI=http://localhost:11328
GAZEBO_MASTER_URI=http://localhost:11362
```

底层脚本不会直接采用当前 shell 中普通的 `ROS_MASTER_URI` 和 `GAZEBO_MASTER_URI`。需要换端口时，必须设置：

```text
SCOUT_PROXY_FULL_ROS_MASTER_URI
SCOUT_PROXY_FULL_GAZEBO_MASTER_URI
```

两者必须使用空闲且不同的端口。后续接入该环境的所有终端，也必须使用同样的端口。

默认日志写到：

```text
/data/a/scout_sim_replacement/logs/proxy_localization_spmpc_<时间戳>/
```

停止时，在启动环境的原终端按 `Ctrl-C`。脚本会停止它自己启动的进程。

不要使用 `killall` 或 `pkill`，也不要只关闭 Gazebo 窗口后就认为整个环境已经停止。

## 7. 不要当成“单独环境”的入口

- `launch_proxy_sim_localization_spmpc.sh`：用于一次启动环境、路径和 SPMPC；
- `launch_proxy_spmpc_localized_attach.sh`：用于向已有环境接入路径和 SPMPC；
- `run_strict_fresh_fair_comparison_n3.sh`：用于完整对比实验；
- 直接运行 `stable_world.launch`：只有 Gazebo，没有本文约定的定位和地图链路；
- `rosrun scout_local_planner launch_sim_nav_stack.sh`：旧工作区仿真入口，不再使用。

前四个不一定是废弃脚本，只是不符合本文“只启动环境”的边界。

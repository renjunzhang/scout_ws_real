## 1. 先选对入口

当前有两个不同用途的“仿真环境”，不能混用。

| 入口 | 用途 | 能否产生论文正式液面数据 |
| --- | --- | --- |
| Python 正式调度器＋独立 C++ Scout/液体 Plant trial runner | Phase-Rejoining 控制链、外部液面、C0--C4/IS trial | **唯一正式入口；必须同时有匹配的 readiness 和人工 approval** |
| Gazebo proxy＋Cartographer＋RViz | ROS topic、TF、定位、传感器和可视化联调 | **不能**；没有本文冻结的独立液体真值 |

因此，只想复现 seed 8601 或检查 C4/C3 时，不需要启动 ROS、Gazebo、RViz、路径发布器或 SPMPC node。Gazebo proxy 的启动方法放在本文后半部分。

## 6. readiness audit：它不会启动正式实验

当前模板故意缺少绑定路径/hash，因此下面命令应返回退出码 4 和 `NO_GO`：

```bash
set -u

READINESS_TOOL=/home/a/scout_ws/src/scout_apps/control/spmpc_local_planner/tools/simulation/run_independent_plant_campaign.py
SESSION_TEMPLATE=/home/a/scout_ws/src/scout_apps/control/spmpc_local_planner/config/simulation/phase_rejoin_session_template_v1.yaml
READINESS_PARENT="$(mktemp -d /data/a/spmpc_exec_identification/phase_rejoin_readiness_manual_20260823.XXXXXX)"
READINESS_OUT=${READINESS_PARENT}/template_audit

set +e
python3 "${READINESS_TOOL}" \
  --campaign formal \
  --session "${SESSION_TEMPLATE}" \
  --out-dir "${READINESS_OUT}"
READINESS_RC=$?
set -e

printf 'readiness exit code: %s\n' "${READINESS_RC}"
python3 -m json.tool "${READINESS_OUT}/formal_readiness.json"
test "${READINESS_RC}" -eq 4
```

正式 session 完整绑定后，退出码 5 和 `READY_NOT_EXECUTED` 只表示“资产可开始审查”，仍不会运行任何 C0--C4 trial。

未传 `--frozen-session-sha256` 的 development 调用，`spmpc_phase_rejoin_closed_loop_trial` 写出的 summary 明确带有：

```text
formal_trials_started=false
development_pilot_only=true
```

所以不能把手工运行结果重命名成正式数据。只有冻结的正式调度器才能向 C++ runner 传入 session hash，并核验 summary 中：

```text
formal_trials_started=true
development_pilot_only=false
frozen_session_sha256=<被审查的 session SHA-256>
```

### 6.1 人工 approval

readiness 报告生成后，人工先审查 session、materialization report、readiness 的 `asset_inventory` 与 `reasons=[]`。审查者自行在 session 目录之外的新文件中写入：

```json
{
  "schema": "spmpc_formal_simulation_human_approval_v1",
  "approved": true,
  "session_sha256": "<formal_session.yaml SHA-256>",
  "formal_seeds_authorized": [3101, 3102, 3103, 3104, 3105, 3106, 3107, 3108, 3109, 3110, 3111, 3112, 3113, 3114, 3115, 3116],
  "reviewer": "<人工审查者>",
  "approved_at": "2026-08-23T20:00:00+08:00"
}
```

不要由自动化工具代写 approval。任何字段缺失、session SHA 或 seed 顺序不一致都会在正式输出目录创建前失败关闭。

### 6.2 正式执行命令（只在人工批准后）

从被审查 session 的 `runtime.runner.path` 取得冻结调度器，而不是使用工作树里的同名脚本。命令模板为：

```bash
FROZEN_SESSION=/data/a/spmpc_exec_identification/<session-dir>/formal_session.yaml
READINESS_REPORT=/data/a/spmpc_exec_identification/<readiness-dir>/formal_readiness.json
HUMAN_APPROVAL=/data/a/spmpc_exec_identification/<approval-file>.json
FORMAL_OUT=/data/a/spmpc_exec_identification/<new-formal-campaign-dir>
FROZEN_RUNNER=/data/a/spmpc_exec_identification/<session-dir>/tools/run_phase_rejoin_formal_campaign.py

python3 "${FROZEN_RUNNER}" \
  --session "${FROZEN_SESSION}" \
  --readiness-report "${READINESS_REPORT}" \
  --human-approval "${HUMAN_APPROVAL}" \
  --out-dir "${FORMAL_OUT}"
```

正式调度器要求工作区 HEAD 与 clean 状态仍匹配 session，重新审计全部 hash，严格按冻结 CSV 串行执行 96 条且不重试。缺人工许可时不要试运行此命令，也不要创建占位 approval。

## 9. 常见误区

- Gazebo proxy 画面正常，不等于防晃 Plant 或正式液面指标正常；
- seed 8601 和 8701--8705 development 通过，不等于正式 C0--C4/IS 矩阵已经执行；
- `READY_NOT_EXECUTED` 不等于论文结果 PASS；
- C1 development 冻结成功不等于正式液面比较已经执行或正向；
- summary 中内部 observer 液面不能替代外部 `primary_metric`；
- `/data/a/...` 是证据目录，不加入 Git，不覆盖旧运行；
- 当前不使用 DualSPHysics，不接触实车；没有匹配的人工 approval 时不启动正式多种子 campaign。

## 1. 先看结论

实物运行前需要完成三类工作：

1. **标定**：从实测数据辨识底盘执行延迟、惯性、IMU、液体模态和 RGB 液面测量等物理量；
2. **确定**：根据安全边界和实验设计确定速度/加速度限制、液面阈值、控制权重、相位搜索范围等设计参数；
3. **冻结**：把地图、路径、容器、标定文件、artifact、代码、二进制和完整运行参数按 SHA-256 固定下来。

当前代码还**不能直接进入 Phase-Rejoin 实物 `enforce`**。主要原因是：

- `0.15 s / 0.22 s` 只是现有线、角速度延迟候选值，近期数据还显示延迟随控制方法变化，线速度约 `0.17–0.22 s`、角速度约 `0.22–0.35 s`，尚未跨工况冻结；
- `linear_time_constant_sec` 和 `angular_time_constant_sec` 当前都为 `0.0`，不代表底盘没有惯性，而是尚未完成辨识；
- processed-IMU 的 gyro-z 已有局部标定证据，当前二维水平/yaw 范围所需的平面外参也已由动捕辅助冻结为 `imu_to_base_yaw=0`、IMU→容器中心 `XY=[-0.100,+0.045] m`；当前仍缺的是 accelerometer 平面信号链、主频幅相和端到端时间验收，而不是完整六自由度外参；
- 液体的几何参数已有候选配置，但固有频率、阻尼、输入耦合和“模型状态到真实液高”的映射仍需用独立液面数据辨识；
- 尚未用 held-out 实物数据证明从当前时刻到约 `250–320 ms` 总 lead 的液体预测可靠；
- 当前实物 runner 尚未传递 Phase-Rejoin artifact、mode、contract ID、双通道惯性时间常数和完整历史开关；
- 当前 recorder 尚未录制 `/spmpc/debug/phase_rejoin`；
- 当前正式 freeze 目录只有旧 S-MPCC 协议模板，现有 validator 也不构成新 Phase-Rejoin 方法的正式放行；
- Phase-Rejoin debug 当前明确给出 `state_complete_for_certificate=false`，只能称经验恢复 gate，不能称鲁棒 recovery certificate。

因此实物推进顺序应固定为：

```text
机械与坐标确认
→ 时钟、传感器和独立液面测量标定
→ 安全架上的底盘执行链辨识
→ 液体模型辨识
→ G0：总 lead 预测、控制灵敏度、IMU 幅相和延迟稳定性
→ 生成并验证正式 V2 Phase-Rejoin artifact
→ phase_rejoin=monitor
→ 审核 held-out 结果与 false-accept
→ 安全架低速 enforce
→ 固定路径地面低速 enforce
```

任何前一阶段没有形成可复查的数据、报告和冻结文件，都不能跳到下一阶段。

### 5.2 需要采集的数据

先在安全架或大净空低速区域完成多档阶跃、斜坡及小幅 PRBS/chirp：

- 只改变线速度，角速度保持零；
- 只改变角速度，线速度保持零；
- 同时改变线、角速度，检查耦合；
- 正负方向都测；
- 至少覆盖计划正式实验的低、中、高命令区间；
- 在低/高电量、目标地面和目标载荷下重复；
- 为辨识集与 held-out 验证集预先划分不同 trial，不能在同一段数据上拟合和验收。

每次必须记录最终发布的 `/cmd_vel`，而不是只记录求解器输出；响应至少包含 `/odom`、`/scout_status` 中的轮速/电压，以及 IMU。

建议先拟合双通道“纯延迟 + 一阶惯性”模型：

$$
\tau_v\dot v^r+v^r=K_v u_v(t-d_v),
\qquad
\tau_\omega\dot\omega^r+\omega^r=K_\omega u_\omega(t-d_\omega),
$$

并用 held-out 数据检查模型残差。如果一阶模型在转弯、制动或不同幅值下系统性失效，应升级模型，不能把误差塞进更大的 gate。

最终输出至少包括：

- $d_v,d_\omega,\tau_v,\tau_\omega,K_v,K_\omega$ 的点估计和置信区间；
- 每个工况的分布、跨 trial 漂移和最坏值；
- 命令死区、量化、饱和、制动距离和 watchdog；
- 训练/held-out 误差曲线；
- 允许使用该模型的电量、地面、载荷和速度范围；
- 一份只读 `actuation_calibration.yaml` 及 SHA-256。

## 6. 时间、频率和端到端延迟

### 6.1 当前频率配置

| 项目 | 当前值 | 说明 |
| --- | ---: | --- |

### 6.2 必须测量的时间量

每条数据链都要区分：

```text
source timestamp
→ 传感器/固件内部延迟
→ 驱动接收时间
→ 滤波有效时间
→ observer 状态时间
→ 求解开始/结束
→ 最终命令发布时间
→ 底盘真正产生运动的时间
→ RGB 对应物理液面的成像时间
```

需要统计：

- topic 实际频率、周期抖动、丢帧率、重复时间戳和乱序；
- source stamp 与 receive stamp 的差；
- ROS 主机、传感器设备和相机时钟是否同源，是否发生跳变；
- `/odom`、IMU、RGB、TF 和控制周期之间的 raw skew；
- recorder 对大图像吞吐的影响；
- RGB 液面相对真实事件或共同激励的时间延迟；
- 求解时间的分位数、超时、跳周期和最坏连续超时长度。

当前 `state_timing` 默认值为：

| 参数 | 当前值 |
| --- | ---: |
| `require_common_epoch` | `true` |
| `max_raw_skew_sec` | `0.080 s` |
| `odom_history_sec` | `1.0 s` |
| `max_interpolation_gap_sec` | `0.050 s` |
| `max_robot_extrapolation_sec` | `0.010 s` |

这些是软件准入门限。应先由实物统计确定正常分布和故障分布，再冻结门限；不能用门限本身证明时间链正确。

- accelerometer 平面 x/y 的有效尺度、轴向符号和动态幅相验收；
- gyro-z 的量化、温漂和当前运行链复核；
- 传感器内部延迟、ROS 驱动延迟和滤波相位；
- 静止 bias 的温度、开机时间和重复性；
- 约 `4.97 Hz` 液体主频附近的增益与相位误差；
- 与动捕、编码器/odom 和独立液面之间的端到端相位关系；
- 容器保持水平、实验室地面平整且 roll/pitch 可忽略这一适用条件的现场确认。

优先将当前 processed-IMU 平面链作为整体，用既有 tuning/held-out bag 和当前代码验证幅值、相位、过零点、静止残差及时间戳。只有端到端验收失败时，才回查 accelerometer 内参或轴向问题。IMU、支架或容器水平安装关系变化时重做平面动捕标定；只有以后扩展到明显 roll/pitch、坡面或三维运动时，才做完整三轴内参、六自由度外参和三维杠杆臂。

### 7.3 当前代码层面的范围与剩余 blocker

当前 processed-IMU 管线执行重力扣除、每次静止 bias、单 yaw、gyro-z affine 和平面 XY 杠杆臂补偿，正好覆盖当前二维模型所需外参，所以缺少完整六自由度参数路径不是当前 blocker。管线尚无 accelerometer scale/misalignment matrix；若端到端平面幅相验收失败，再按证据结构化增加相应参数，不能从旧 planner 抄一个零散比例补丁。以后若纳入 roll/pitch，再升级完整六自由度接口并重新标定。

此外，管线虽然生成 accel/gyro/alpha 各自的 effective timestamp，但 `SloshObserverBank` 当前按统一 `measurement_stamp` 积分。相位敏感的 `enforce` 前必须明确各分量的重对齐策略，并用约 `4.97 Hz` 实物数据验证；否则“已补偿滤波相位”的说法不成立。

## 8. 容器与液体模型标定

### 8.1 一手物理量

`config/containers/tube_default.yaml` 当前为：

| 参数 | 当前值 | 要确认/标定什么 |
| --- | ---: | --- |
| `slosh/container_radius` | `0.0185 m` | 容器内半径，而非外径的一半 |
| `slosh/liquid_height` | `0.058 m` | 静止液面到底部的实际高度 |
| `slosh/liquid_density` | `1000 kg/m³` | 目标温度下的液体密度 |
| `slosh/damping_ratio` | `0.05` | 必须用自由衰减或受迫响应辨识 |
| `slosh/mode_index` | `1` | 检查一阶模态是否足以覆盖工作域 |
| `slosh/slosh_height_ref` | `0.005 m` | 代价归一化尺度，不是防溢阈值 |
| `slosh/slosh_height_max` | `0.001 m` | 当前阈值需要重新解释和冻结 |
| `slosh/slosh_eta_dot_ratio` | `0.3` | 代价权重设计参数，不是物理量 |
| `slosh/use_linear_model` | `true` | 必须限定线性模型有效幅值 |
| `slosh/use_parabola_term` | `false` | 当前统一为 modal-only 评价口径 |

还必须记录液体种类、配方、动力黏度、温度、装液质量/体积、允许装液误差、自由液面到容器口的余量、表面张力/润湿状态以及是否使用染料。

### 8.2 需要辨识的动态模型

当前控制器采用双轴低阶模型：

$$
\ddot\eta_x+2\zeta\omega_n\dot\eta_x+\omega_n^2\eta_x=-\kappa_x a_x,
$$

$$
\ddot\eta_y+2\zeta\omega_n\dot\eta_y+\omega_n^2\eta_y=-\kappa_y v\omega.
$$

必须从实物数据辨识或验证：

- 固有频率 $\omega_n$ 及其随液深、温度和装液误差的变化；
- 阻尼比 $\zeta$ 及振幅依赖性；
- 纵向和横向耦合增益 $\kappa_x,\kappa_y$；
- 验证交叉轴耦合，并确认容器水平、地面平整和 roll/pitch 可忽略的适用边界；超界时才扩展模型并重标外参；
- 模态状态到真实液面最大高度的转换系数；
- 一阶模型的线性有效域和失效幅值；
- 静止、匀速、加速、转弯和停车尾段上的误差。

当前几何闭式模型给出约 `4.97 Hz` 的一阶固有频率，它只是实验设计的先验。正式值应由独立 RGB 液面或其他真实液面测量完成自由衰减和受迫响应辨识。

建议数据分为：

1. 小幅自由衰减，用于 $\omega_n,\zeta$；
2. 纵向低幅扫频/脉冲，用于 $\kappa_x$；
3. 稳定转弯和角速度变化，用于 $\kappa_y$；
4. 正式路径形状的 combined excitation，用于 held-out 验证；
5. 接近安全上限但不溢出的验证，用于确定线性模型有效域。

最终 `liquid_model_id.yaml` 必须同时保存点估计、置信区间、适用温度/液深/振幅范围、数据集 hash 和拟合脚本 hash。

### 8.3 液面安全阈值

应先从容器实际 freeboard 中扣除以下不确定度，再确定允许液面：

```text
容器口余量
− 装液误差
− RGB/模型测量误差上界
− 动态未建模裕度
− 安装倾斜裕度
= 可声明的安全液面幅值
```

然后分别冻结：

- 物理防溢硬阈值；
- 控制器模型约束 `slosh_height_max`；
- 代价归一化 `slosh_height_ref`；
- monitor warning 阈值和 fail-closed 阈值。

这四个数含义不同，不能互相替代。当前 `slosh_height_max=1 mm`、`slosh_height_ref=5 mm` 若未经解释，不应直接作为论文中的实物安全合同。

- residual authority、gate 半径、终端合同；
- 载荷、容器位置或 IMU/observer 状态定义。

## 13. G0：新方法最关键的放行门

若线速度延迟约 `150 ms`、角速度延迟约 `220 ms`，前沿后液体窗口为 `100 ms`，则在线 gate 实际评估的是当前时刻约 `250–320 ms` 之后的状态。不能只验证 `100 ms` 模型。

### 13.1 总 lead 预测

在 held-out 实物 trial 上，从当前增广状态和真实命令历史预测到：

$$
T_{lead,c}=d_c+T_\ell,
\qquad c\in\{v,\omega\}.
$$

报告机器人速度、双轴液体状态和独立 RGB 液面在整个 lead 上的误差、置信区间及不同工况的最坏值。若误差在 terminal gate 尺度下不可接受，必须降低控制链延迟、引入真实液体状态校正，或退回离线前馈加低频纠偏。

### 13.2 新命令的可控灵敏度

用相同初始状态、只改变第一拍小幅 $\delta v/\delta\omega$ 的成对实验或高可信复现实验，验证新命令在 gate 终端产生的液体状态变化大于测量噪声和模型不确定度。若第一拍在总 lead 终端没有可检测作用，在线短时优化没有实物意义。

### 13.3 IMU 幅相

在液体主频约 `4.97 Hz` 附近比较 processed-IMU、参考传感器和 RGB 液面，报告增益、相位、component-effective timestamp 及不确定度。只报告时域相关系数不足以证明相位控制有效。

### 13.4 延迟稳定性

按 trial、方法、速度、电量、地面和载荷分别报告 $d_v,d_\omega,\tau_v,\tau_\omega$。若同一冻结参数无法覆盖正式条件，应按工况建立明确模型，或缩窄实验条件；不能用一个平均延迟代表所有 trial。

### 13.5 G0 判定记录

G0 报告必须由预注册指标给出逐项 `GO/NO-GO`，并保存：

- calibration 与 held-out trial 清单；
- 分析脚本和环境；
- 原始数据及 hash；
- 误差阈值来源；
- 失败样本和排除规则；
- 最终签字/审核日期。

## 17. 重标定和 artifact 失效条件

以下任一变化都要触发对应重标定；涉及状态转移或运行合同时，通常还必须重建 artifact：

- 容器、液体种类、液深、温度、黏度、染料或夹具变化；
- IMU、支架或容器的水平相对安装变化：重做平面动捕外参；安装未变且封签/快速检查通过时继续复用冻结值；
- 方法纳入明显 roll/pitch、非水平容器、坡面或三维运动：新增完整六自由度外参和三维杠杆臂标定；
- 载荷、质量分布或质心变化；
- 轮胎、地面、电量区间、底盘固件或 CAN 链路变化；
- 控制频率、滤波器、observer、时间戳语义或 topic/frame 变化；
- 路径、地图、定位方案、footprint 或场地变化；
- 速度/加速度限幅、终端或安全参数变化；
- 液体模型、控制权重、residual authority 或 gate 半径变化；
- Git revision、acados codegen、编译选项或运行二进制变化；
- 相机曝光、增益、白平衡、分辨率、镜头位置或照明变化。

对可重复拆装件应定义“快速复核”与“完整重标定”的量化边界。当前平面外参的快速复核以安装封签、配置/hash 一致性和短平面运动检查为主，不默认用尺复测 XYZ；超过边界时使对应 freeze 失效。

## 18. 最终实物放行表

只有下表全部勾选后，才能从 `monitor` 进入 `enforce`：

- [ ] 机械尺寸、质量、容器和当前模型所需 frame 关系已冻结；IMU→容器中心只要求已冻结的 XY/yaw，不要求 Z；
- [ ] `/cmd_vel` 唯一发布者和急停/受控停车已在安全架验证；
- [ ] 线/角延迟、时间常数、限幅和制动已跨正式工况辨识；
- [ ] 动捕平面外参报告/hash 已绑定，安装未变化，runtime `yaw=0、XY=[-0.100,+0.045] m` 与报告一致；
- [ ] 当前使用轴的 IMU 平面信号链、主频幅相、端到端延迟和 READY/fail-closed 已通过；
- [ ] 液体 $\omega_n,\zeta,\kappa_x,\kappa_y$、液高映射和有效域已通过 held-out；
- [ ] RGB 独立液面标定、时间延迟和有效率已通过；
- [ ] 地图、定位、路径、footprint 和碰撞复核已冻结；
- [ ] `250–320 ms` 总 lead 预测通过 G0；
- [ ] 第一拍残差对终端液体状态具有可检测作用；
- [ ] 正式 V2 artifact 为 `empirical_held_out`，完整尾段与合同校验通过；
- [ ] recovery coverage、false-accept、false-reject 和实际重接率已审核；
- [ ] 新实物 runner 已传递全部 Phase-Rejoin 参数并有 dump-params 测试；
- [ ] recorder 已录齐 `/spmpc/debug/phase_rejoin` 等关键证据；
- [ ] monitor trial 未出现合同、时间、非有限值或命令链异常；
- [ ] 专用只读 manifest、唯一 freeze ID、全部 SHA-256 和 clean build receipt 已生成；
- [ ] 安全架低速 enforce 通过后，才允许固定路径地面低速 enforce。

如果 G0 不通过，应明确退回“执行感知的离线防晃前馈 + 低频纠偏”，而不是继续增大 gate 或调整口径。实物标定的目标不是让当前参数看起来合理，而是确定哪些模型在什么条件下真的可信。

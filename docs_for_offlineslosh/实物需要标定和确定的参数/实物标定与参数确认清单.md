# Phase-Rejoining Residual S-MPCC 实物标定与参数确认清单

> 更新日期：2026-08-20
>
> 适用范围：Scout Mini、试管容器、processed IMU、RealSense RGB 液面测量、冻结路径、OfflineSloshOCP 与 Phase-Rejoining Residual S-MPCC
>
> 文档性质：实物标定、辨识、冻结和放行清单；不是某一批实验的 `GO` 证明

## 1. 先给结论

实物运行前需要确定的内容不只是 YAML 中的几个数，而是下面六条互相绑定的链路：

```text
容器与液体
→ IMU、相机、容器中心和底盘之间的几何/时间关系
→ 最终发布命令到真实线角速度的双通道执行模型
→ 真实刚体激励到液体状态和可见液面高度的模型
→ 地图、冻结路径、OfflineSloshOCP 名义序列和恢复对象
→ 在线控制、安全监督、记录与分析合同
```

截至本文日期，当前代码可以用于开发和仿真，但 **Phase-Rejoin 实物 `enforce` 仍为 `NO-GO`**。至少还有五个硬缺口：

1. `0.15 s / 0.22 s` 只是历史延迟候选，线、角通道的一阶惯性、死区和跨工况稳定性没有用最终控制链重新冻结；
2. 当前液体模型的 `zeta=0.05`、`kappa_x=kappa_y=1` 及平面旋转处理没有完成独立 held-out 实物确认；
3. 正式 OfflineSloshOCP artifact、完整 Markov 恢复状态、可执行恢复策略及 held-out false-accept 统计尚未形成；
4. 必须先通过总 lead 约 `250--320 ms` 的 G0 预测可信度和控制灵敏度门，不能只证明前沿后的 `100 ms` 模型有效；
5. 通用 launch 已有 Phase-Rejoin 参数，但当前实物 trial wrapper、black-box recorder 和 postflight 尚未形成绑定 artifact/hash、记录 `/spmpc/debug/phase_rejoin` 并验证其合同的正式 runner。

IMU 平面外参不再列入上述缺口。对本文限定的“容器水平、实验室平地、只考虑平面运动和 yaw”范围，动捕辅助得到的 `imu_to_base_yaw=0` 和 IMU 到容器中心 XY 杠杆臂 `[-0.100,+0.045] m` 已冻结，可直接复用；当前不需要重新尺测 XYZ，也不需要辨识 Z 或完整六自由度外参。

仓库中的 development artifact 生成器会明确写入 `offline_slosh_ocp=false`，当前 V2 development 恢复命令也只是名义 `u_pub`，不能改名后用于正式实物或论文结果。正式实验中必须保持：

```text
phase_rejoin/allow_development_artifact_in_enforce = false
```

## 2. 参数分级和使用规则

| 级别 | 含义 | 处理方式 |
|---|---|---|
| A：必须实测标定/辨识 | 物理几何、时间偏移、执行模型、IMU、液体动力学、RGB 映射 | 用专门标定数据估计，并用完整 held-out trial 验证 |
| B：每批现场确认 | 设备身份、安装未变化、液深、温度、电量、地面、话题频率、时间戳、地图和路径 | 每个实验 batch 开始前检查并记录 |
| C：设计与安全参数 | 速度限制、代价权重、时域、gate 半径、终点和受控停车逻辑 | 用 development 数据选择，正式 batch 前预注册并冻结 |
| D：派生 artifact | 离散模型、OfflineSloshOCP 序列、恢复集合/策略、路径 hash、codegen | 由 A--C 和冻结路径生成，不允许手工填一个近似值 |

必须遵守以下纪律：

- 标定集、调参集和 held-out 验证集按**完整 trial**分开，不能按同一 bag 的采样点随机拆分；
- RGB 是独立物理评价链，不进入在线控制，也不能一边看正式 RGB outcome 一边改模型或权重；
- 当前值、候选值和已经正式冻结的值必须分开写，不能把“代码默认值”称为“实测参数”；
- 正式 batch 第一条开始后，硬件、液体、路径、配置、分析脚本或 artifact 任一变化，都要产生新的 `FREEZE_ID`；
- 所有外部资产保存绝对路径、SHA-256、生成脚本版本和原始报告，不能只在启动命令中保留一个路径字符串。

当前二维水平范围内，Z 高度不会进入 yaw 刚体运动的 XY 加速度换算；完整 roll/pitch、Z 向平移和六自由度 hand-eye 也不是本方法第一版的前置条件。只要 IMU、支架和容器的水平安装关系未变，就不重新标定这组平面外参。若安装发生变化，或者以后扩展到明显 roll/pitch、坡面或三维运动，再重新做相应外参。

当前仍需完成的是 processed-IMU **信号链验收**，而不是重新做平面外参：

- 验证设备固件滤波、软件滤波和时间戳链的联合幅频、相频和群延迟；
- 在约 `4.97 Hz` 液体主频附近报告幅值比、相位误差和不确定度；
- 验证 50 Hz 频率、丢包、重复/倒退时间戳、host receive age、READY 和 fail-closed 行为。

如果上述端到端平面幅相验收不通过，再回查 accelerometer 平面尺度、轴向或安装问题；不预先把完整三轴内参和六自由度外参列为当前必做项。

当前代码还有两项结构性边界，不能靠改 YAML 数字绕过：

1. 新 SPMPC 链没有 accelerometer scale/cross-axis 或完整六自由度 `IMU -> base` 标定参数路径；这不阻塞当前已冻结的二维平面外参，但旧 planner 中出现过的 `imu_ay_scale=0.367156` 不被当前 `spmpc_local_planner` 消费，禁止误抄。只有平面幅相验收失败或方法扩展到三维时，才评估结构化增加这些参数；
2. observer 的状态时间目前主要由 measurement stamp 统一减去 `sensor_delay_sec=15 ms` 得到，accel/gyro/alpha 的三个滤波延迟没有把各分量重新采样到同一物理 epoch。在 `4.97 Hz` 附近，`6.834/5.020/15.001 ms` 分别约等于 `12.2°/9.0°/26.9°` 相位，因此必须设计统一的 timestamp-aware 重对齐链并重新验证，而不是继续叠加常数补丁。

### 3.7 当前实物 runner/记录链边界

当前实际链路是：

```text
run_spmpc_short_horizon_matched_trial.sh
→ run_spmpc_real_fixed_path_trial.sh
→ spmpc_fixed_path.launch
→ spmpc_experiment.launch
```

它属于 G3R3 short-horizon development 协议，运行 `delay_phase=shadow`，不是 Phase-Rejoin 实物 `enforce` 链。

`spmpc_experiment.launch` 和 `spmpc_fixed_path.launch` 已暴露 `phase_rejoin_mode`、artifact、contract ID、frame ID、短时域和 residual bounds；专用 generated solver 也存在于源码树中。但当前实物 wrapper：

```text
scripts/run_spmpc_real_fixed_path_trial.sh
scripts/run_spmpc_short_horizon_matched_trial.sh
```

只传线/角 delay override，没有传 `linear/angular_time_constant_sec`、Phase-Rejoin mode、artifact、contract ID、frame ID 和 complete-history 参数，也没有在 sidecar 中冻结它们，因而实际仍会采用 launch 默认 `phase_rejoin=off` 及 `tau_v=tau_omega=0`。当前主 black-box recorder 的固定 topic 列表也没有 `/spmpc/debug/phase_rejoin`，现有 postflight 不验证 artifact identity、front/current/terminal index、gate 决策和恢复命令。

因此，在任何实物 `monitor/enforce` 前，需要一次集中式 runner 改造：以一个正式 Phase-Rejoin runner 统一绑定参数、hash、recorder 和 postflight；不要从旧 G3/G3R3 shell 中临时拼接若干 launch override。

## 4. 必须实测、验证或确认复用的参数

### 4.1 容器、液体和安装几何

| 要确定的数据 | 推荐方法 | 验收与归档 | 写入位置 |
|---|---|---|---|
| 容器唯一 ID、内半径、有效高度、freeboard | 卡尺多方向测内径；静止状态量液深和距口高度 | 报告均值、重复性和仪器精度；照片绑定 ID | `tube_default.yaml` 或新容器 YAML；freeze manifest |
| 液体配方、密度、温度、黏度代理 | 称量定容；记录温度和配比 | 每次配液生成 batch ID；同批不补液 | manifest/sidecar；必要时容器 YAML |
| IMU 与容器中心的平面关系 | 复用已冻结的动捕辅助平面外参；每批确认安装未变化 | `yaw=0`、IMU 到容器中心 XY=`[-0.100,+0.045] m` 与冻结报告/hash 一致；不重复尺测 XYZ | `imu_shadow/lever_arm_*` + freeze manifest |
| 容器/支架质量与刚度 | 称重并做静态晃动检查 | 支架无可见相对运动；质量写入载荷记录 | batch metadata |
| 相机和动捕刚体的任务相关位姿 | 相机按 RGB 测量需要标定；动捕按执行模型真值需要确认 frame | 独立数据误差不恶化；IMU 平面外参直接绑定既有冻结报告 | TF、相机标定、IMU config |

半径、液深或液体批次变化都会改变模态参数。容器 YAML 改动后，离散液体模型、acados 运行合同、OfflineSloshOCP 序列和 phase artifact 必须一起重生成。

### 4.2 Scout 双通道执行模型

标定的因果输入必须是**最终实际发布命令** `u_pub`，而不是求解器原始动作：

```text
u_opt
→ terminal/safety/shared limiter
→ u_pub（/cmd_vel）
→ Scout 内环
→ v_real, omega_real
```

优先用 Nokov/VRPN 计算 `v_real, omega_real`，`/odom` 只作在线反馈和对照。已有数据表明 `/odom` 角速度约低报 `8--10%`，且比例随速度和滑移变化，不应直接冻结一个永久增益。

至少比较以下候选：

```text
M0: 纯延迟
    y(t) = u_pub(t-d)

M1: 纯延迟 + 一阶惯性
    tau_v * dv/dt + v = u_pub_v(t-d_v)
    tau_w * dw/dt + w = u_pub_w(t-d_w)

M2: M1 + 经数据支持的静态增益、死区、饱和或方向不对称
```

除连续响应模型外，还要单独冻结命令量化、底盘固件限幅、watchdog 超时、通信中断后的保持/归零规则、制动距离和急停行为；这些非线性离散事件不能被一个 `tau` 吸收。

采集要求：

- 线速度阶跃/ramp、角速度左右阶跃和反转、联合 S 弯都要覆盖；
- 各激励重复，并覆盖预注册的低/中电量、实际载荷和正式地面；
- 记录 `/cmd_vel`、`/spmpc/debug/cmd_vel_output`、`/spmpc/debug/control_cycle_audit`、`/odom`、`/imu/data`、动捕 pose/status 和所有源时间戳；
- 导数必须由时间对齐后的平滑速度求得，不能对量化 odom 直接逐点差分；
- 拟合、模型选择、held-out 验证按完整 trial 分开。

验收原则：

1. 选中的模型在 held-out trial 上明确优于纯延迟和零阶保持基线；
2. 延迟置信区间和跨 trial 离散度应不大于预注册的执行前沿余量；建议首先以一个控制周期 `33.3 ms` 为稳定性检查尺度；
3. 预测误差的高分位必须小于对应 phase recovery gate 预留半径，不能先定大 gate 再掩盖执行误差；
4. 正反转、左右转、电量和地面分层均报告，若参数不稳定，应采用工况调度模型或更保守包络；
5. 最终冻结 `d_v,d_omega,tau_v,tau_omega`、模型结构、适用工况、误差集合 `W_exec` 和报告 SHA-256。

写入位置：

```text
config/planner/common.yaml -> delay_phase/*
正式执行模型报告和参数文件 -> freeze manifest 引用的外部/仓库冻结资产
OfflineSloshOCP 与 phase artifact -> 使用完全相同的执行模型合同
```

若实际辨识需要非零 time constant 或死区，而当前预测器不能表达，应先统一扩展执行模型和单一配置源，再重新 codegen、测试和生成 artifact；不要在 ROS wrapper、离线 OCP 和分析脚本中分别打补丁。

### 4.3 IMU 和时间同步

当前二维水平范围按以下顺序完成：

1. **复用平面外参**：绑定 `KEEP_NOMINAL_PLANAR_EXTRINSIC` 报告和 hash，使用 `yaw=0、r_{IT,xy}=[-0.100,+0.045] m`；不重新尺测 XYZ，也不把 Z 写入当前液体激励模型；
2. **安装一致性**：每批确认 IMU、支架和容器未拆装、未水平移动或转动；一致时继续复用，变化时重新做平面动捕标定；
3. **时间偏移**：用既有 `15 ms` 作为候选，对高信噪比边沿/宽频激励验证传感器延迟、ROS receive lag 和不确定度；
4. **滤波幅相**：测量 raw/device/software filter 在 `1--10 Hz`，尤其约 `4.97 Hz` 的增益和相位；
5. **在线 READY 合同**：验证平放静止 bias window、warm-up、丢帧、clock reset、freshness 和 fail-closed 行为。

容器中心平面加速度使用已经冻结的 `r_x=-0.100 m、r_y=+0.045 m`：

```text
a_target_x = a_imu_x - alpha_z*r_y - omega_z^2*r_x
a_target_y = a_imu_y + alpha_z*r_x - omega_z^2*r_y
```

当前纯 yaw 平面模型只使用 `r_x,r_y`，Z 不进入上述 XY 换算。运行时仍要正确处理重力、已冻结的平面 yaw、杠杆臂和符号；仅使用 `a_y=v*omega` 不能替代 processed-IMU 刚体补偿。完整六自由度外参只在以后扩展到明显 roll/pitch 或三维运动时再做。

验收时分别报告：

- 静态 bias、noise/MAD、温漂和姿态残差；
- 动态幅值、相位、RMSE、丢帧率和最大 gap；
- 主频附近的幅相误差对 `250--320 ms` 液体预测的实际影响；
- 发生 packet gap、fallback、reset 或源时间戳异常时是否拒绝 phase-rejoin 命令。

正式 Phase-Rejoin trial 推荐 `processed_imu + fail_closed`；任何运动中 fallback 都应判该 trial 失效，而不是无标记地切到 odom。

### 4.4 液体动力学与液面映射

建议辨识顺序固定为：

```text
时间和执行链
→ omega_n、zeta
→ kappa_x、kappa_y 与平面旋转/耦合
→ height_coeff 或可见高度映射
→ 必要时增加高阶、非线性或时变项
```

不应在执行延迟未知时同时拟合阻尼，否则延迟相位很容易被错误吸收到 `zeta` 中。

最低数据集：

- 直线急停后的纵向自由衰减；
- 左/右转和反转后的横向自由衰减；
- 低风险宽频联合激励，用于检验首模外的频率成分；
- 静止、运动和到达后完整尾段；
- 同步的实际容器中心加速度、processed IMU、odom、动捕和 RGB 液面。

要辨识或确认的量：

| 参数/选择 | 当前实现 | 实物需要回答的问题 |
|---|---|---|
| `omega_n` | 由 `R,h,mode_index` 计算 | 实测主频是否稳定在约 `4.97 Hz`；是否随液深/温度变化 |
| `zeta` | YAML 为 `0.05` | 自由衰减包络在 held-out trial 是否匹配 |
| `kappa_x,kappa_y` | runtime contract 当前固定为 `1,1` | 真实输入增益和两轴不对称是否可忽略 |
| 坐标旋转/科氏耦合 | 当前低阶实现有限；`step()` 不使用传入的 `omega_z` | 转弯时 body-frame 模态传播是否需要 rotation-consistent 模型 |
| `c_h` | 几何公式约 `1.819` | modal proxy 与 RGB 可见高度的尺度关系是否泛化 |
| 模态阶数 | 首模 | 残差中是否存在稳定高阶峰或非线性 |
| parabola | 默认关闭 | 是否只作为独立解释项；不得与 modal/RGB 指标混用 |

验证必须使用 actual-input replay：

```text
u_pub
→ 识别后的 Scout 执行模型或动捕真值
→ a_x = dot(v_real), a_y = v_real * omega_real（经完整坐标/杠臂处理）
→ 液体模型
→ 与 held-out RGB 比较
```

至少报告主频、幅值比、相位差、相关性、MAE/RMSE/P95、峰值时刻、衰减时间，以及“预测安全但 RGB 实际超界”的 false-safe。内部 `/spmpc/slosh_height` 下降不能代替 RGB 正向。

### 4.5 RGB 三标尺和时间链

每次重新安装相机/容器或改变分辨率、焦距、曝光和照明后，重新完成：

- 相机序列号、固件、camera info、畸变和实际分辨率/帧率确认；
- 固定曝光、增益、白平衡和照明，保存可重放的相机参数文件；
- ROI、左右内壁线、试管轴、静止液面和三标尺参考点；
- `mm_per_pixel`、`height_bias_mm`、HSV 阈值、置信度与 clipped 规则；
- 30 个干净有效帧的 zero lock；
- 静止噪声、漂移、量化梯级、有效率、处理延迟和 source stamp 完整性；
- 人工标尺/人工标签 held-out 检查，包括 MAE、bias、P95 和相位延迟。

当前 online validator 的基本工程门是：

| 项目 | 当前门槛 |
|---|---:|
| camera info rate | 不低于 `27 Hz`（30 Hz 的 90%） |
| online scalar rate | `>=10 Hz` |
| online 最大 source-time gap | `<=0.35 s` |
| pre-motion 与 motion+tail 有效率 | `>=90%` |
| P95 publish lag | `<=0.50 s` |
| future skew | `<=0.05 s` |
| 有效消息 | `valid && zero_locked && status_code=0 && status=OK` |

这些只是当前采集完整性门，尤其 `0.50 s` publish-lag 门不能证明约 `5 Hz` 的相位足够准确。用于模型辨识和 G0 时，必须测出并补偿真实 source-to-physical 延迟，使其相位不确定度进入预测误差预算。

论文主指标还要预先冻结语义，例如：

```text
H_vis = /liquid/measurement.height_max_lcr_mm
窗口 = first effective motion 到 first arrival 后 5 s
滤波 = 因果 5 点 rolling median
主统计量 = trial/block 级 P95
```

“中央液面”“三标尺最大值”“模态高度”和“距容器口剩余余量”不是同一个量，不能混用。

### 4.6 地图、定位、TF 和冻结路径

每条正式路径应冻结并记录：

- 地图文件、分辨率、原点和 SHA-256；
- `map -> odom -> base_link` TF 树、更新率、时间戳和跳变统计；
- 路径 `frame_id`、点列、点数、长度、方向、起终点、曲率和最小障碍余量；
- 固定起点门、朝向门、goal tolerance 和路径 SHA-256；
- 路径清理/平滑算法、参数、输入 MBF 原始路径 hash 和输出报告；
- replay topic 必须为当前合同指定的 `/scout/global_path_fixed`。

验收包括 RViz 人工对齐、无定位跳变、起点可重复性、路径碰撞复核以及多次空载/低速 replay 的投影误差。地图、TF 或路径任一变化都会使 OfflineSloshOCP 和 phase artifact 失效。

## 5. Phase-Rejoin 专用参数和 artifact

### 5.1 当前在线设计值

当前 `common.yaml` 中：

| 代码键 | 当前值 | 类型 |
|---|---:|---|
| `phase_rejoin/liquid_horizon_steps` | `3`，即约 `100 ms` | C |
| `phase_rejoin/max_residual_v` | `0.08 m/s` | C |
| `phase_rejoin/max_residual_omega` | `0.20 rad/s` | C |
| candidate backward/forward radius | `1 / 3` steps | C |
| initial forward radius | `4` steps | C |
| max clock lead | `1` step | C |
| candidate position/yaw/velocity/liquid weights | `1.0 / 0.5 / 0.5 / 1.0` | C |
| artifact dt tolerance | `1e-4 s` | C/合同 |
| path length/geometry tolerance | `0.05 / 0.075 m` | C/合同；正式值应与路径误差预算协调 |
| model/command tolerance | `1e-6 / 1e-8` | C/数值合同 |

这些是设计参数，不是通过物理标定自动得到的数。必须在 development 数据上选择并预注册，不能根据正式结果临时扩 gate 或增大 residual bounds。

### 5.2 正式 artifact 必须绑定的字段

正式候选 schema 应为 `phase_rejoin_empirical_v2`，证据等级应为 `empirical_held_out`；`development_only` 不能进入正式 `enforce`。

正式 OfflineSloshOCP/恢复 artifact 至少绑定：

```text
schema、evidence_level、source、contract_id、frame_id
git revision、codegen hash、dt、path hash、path length/geometry
container/liquid batch、execution-model ID、IMU planar-extrinsic freeze ID、IMU signal-chain report ID
two_zeta_omega_n、omega_n_sq、kappa_x、kappa_y
command/rate/acceleration bounds
完整 x,y,yaw,s,v,omega, actuator/buffer, eta,eta_dot 序列
u_opt、u_pub、a、alpha、v_s
terminal_contract、settling/zero-hold 合同
每相位 recovery set 参数、误差集合和可执行策略 kappa_i
生成、验证和 held-out 报告 SHA-256
```

当前 CSV 中的九维 gate 半径为 `r_x,r_y,r_yaw,r_v,r_omega,r_eta_x,r_eta_x_dot,r_eta_y,r_eta_y_dot`。它们没有覆盖执行器状态和命令历史，当前诊断也明确保持 `state_complete_for_certificate=false`，所以恢复误差还不是完整 Markov 状态，只能称 empirical recovery gate，不能称为证书。

还有一个接口边界：当前 V2 loader 只接受 `recovery_contract=nominal_command_v1`，并强制 `kappa_v/kappa_omega` 等于同相位名义 `u_pub`。若正式方法需要独立的 `kappa_i(e)`，必须统一升级 schema、loader、在线调用和验证合同；不能手工把另一套策略塞进现有 CSV。升级前当前实现只能验证“回放名义恢复命令”，不能声称已经保存了状态反馈恢复策略。

### 5.3 恢复集合和策略怎样标定

每个代表性相位施加预注册的小偏离：位置/yaw 偏差、速度偏差、液体相位偏差、附加延迟、短时速度门或限幅。用完整实际执行链 rollout，估计经验恢复域并同时保存恢复动作：

```text
R_i^emp + kappa_i^emp
```

训练集用于拟合集合和策略，held-out trial 用于统计：

- gate coverage；
- false accept/false-safe：判为可恢复但实际越界或未重接；
- false reject；
- 实际重接成功率、时间和最大液面；
- 不同相位、电量、地面和液体批次的分层结果。

正式放行不能只写“Monte Carlo 都成功”。应预注册样本量和置信区间，并要求 held-out false-accept 上界满足安全风险预算。只有进一步证明鲁棒逐拍前驱包含、终端正不变和策略可移位，才可以把 empirical set 升级称为 recovery funnel/certificate。

### 5.4 `enforce` 的代码合同

当前代码还要求：

```text
solver_backend = continuous_mpcc_acados（10D slosh 主线）
delay_phase/mode = fixed_closed_loop
delay_phase/require_complete_history = true
phase_rejoin/liquid_horizon_steps 与专用 generated solver N 完全一致
post-solver limiter 若可能改命令，则必须 fail closed
V2 artifact 具有经 loader 验证的完整 slowdown-settle-zero-hold 尾段
terminal_zero_hold_steps >= liquid_horizon_steps + 2（当前 N=3 时至少 5 步）
artifact contract/path/model/command 全部匹配
```

这些条件满足只说明软件合同一致，不说明物理参数和恢复证据已通过。

## 6. 控制、安全和求解器参数：需要冻结，但不要冒充标定

### 6.1 时域、权重和限制

当前主配置为 `30 Hz`、`dt=0.0333333333 s`、机器人 horizon `60`。需要冻结：

- planner variant 与 `v_ref`；
- contour、lag、progress、速度、控制、平滑、液体和 residual 各权重；
- `slosh_cost_horizon_steps` 与 tail discount；
- `v/omega/a/alpha` 及增量界；
- phase candidate 搜索半径、打分权重和 residual bounds；
- hard/soft liquid limit 的物理语义；
- warm-start、fallback 和 solver backend；
- generated solver JSON/共享库 hash，以及它绑定的 `N`、`dt`、状态和参数维度。

`dt`、`N`、模型系数或 bounds 变化后必须重新 codegen；只改 YAML 而继续用旧 generated solver 不可接受。

### 6.2 时间戳和状态准入

当前需要核对并冻结：

```text
slosh_observer/max_imu_state_age_sec = 0.10 s
slosh_observer/max_odom_state_age_sec = 0.50 s
slosh_observer/max_future_skew_sec = 0.005 s
state_timing/max_raw_skew_sec = 0.080 s
state_timing/max_interpolation_gap_sec = 0.050 s
state_timing/max_robot_extrapolation_sec = 0.010 s
tf_timeout_sec = 0.05 s
```

这些门应由传感器时延、丢包分布和 G0 误差预算支持，不能为了提高“有效率”随意放宽。

### 6.3 终点、安全和失效动作

需要预先确定并测试：

- `goal_tolerance=0.20 m`、到点最大速度/角速度；
- slowdown/capture-stop 距离与速度上限；
- terminal omega clamp 和 near-goal clamp；
- tracking projection `0.50 m / 0.20 s`；
- solver failure、observer failure、artifact mismatch、gate reject 时的受控停车；
- 人工急停始终具有最高优先级；
- `/cmd_vel` 唯一发布者和退出时持续零命令；
- `u_opt -> u_pub` 任何未被合同允许的修改都应 fail closed 并被记录。

实时性至少同时看 solver P95/max、完整控制周期 inter-arrival、deadline overrun 和命令发布间隔。当前 development 资格门使用 solver P95 `<25 ms`，而控制周期预算为 `33.3 ms`；平均耗时不能替代最坏情况和 deadline 统计。

## 8. G0：实物 Phase-Rejoin 的唯一前置放行门

以当前候选为例：

```text
执行前沿       = max(d_v,d_omega) ≈ 150--220 ms 或更长
可信液体窗口   = 3 × 33.3 ms ≈ 100 ms
恢复终端总 lead = 约 250--320 ms
```

必须在独立 held-out 数据上同时通过：

| Gate | 必须提交的证据 | 不通过时怎样处理 |
|---|---|---|
| G0-A 执行模型 | `u_pub -> v_real,omega_real` 总 lead 预测误差和跨工况稳定性 | 降低控制链延迟、分工况建模或扩大安全余量；不能假装纯延迟成立 |
| G0-B 液体预测 | actual-input 模型在 `250--320 ms` 的状态/高度误差、相位和 false-safe | 先修模型、坐标、IMU/RGB 时间链；暂停 recovery gate |
| G0-C 控制灵敏度 | 新命令对终端液体状态的变化大于执行噪声和测量分辨率 | 若不可控/不可辨识，退回离线前馈和低频纠偏 |
| G0-D IMU 主频保真 | 约 `4.97 Hz` 的增益、相位及其不确定度 | 改传感器/滤波/校正，不得靠调权重掩盖 |
| G0-E 参数稳定性 | trial、电量、载荷、地面和方向分层结果 | 使用调度模型或限定适用域；超域 fail closed |

预测误差的高分位加扰动余量必须严格小于经验恢复 gate 的最小有效裕量；方法引起的可检测液面差还应高于 RGB 噪声/量化门。若总 lead 预测失效，不能把“100 ms 窗口”简单后移后继续运行。

为了让第一轮 G0 可执行，建议在正式采集前预注册下面的**初始候选门槛**。它们是下一轮验证目标，不是当前已经通过的结果：

| 项目 | 建议初始门槛 |
|---|---:|
| 运动期间软件 admission | frame、source stamp、gap `<=35 ms`、receive age `<=100 ms`、future skew `<=5 ms`、bias/common-epoch/TF 全程 `100%` 通过；无 READY reset/fallback |
| processed IMU 在 `4--6 Hz` | gain error `<=10%`、phase error `<=10°`、coherence `>=0.8` |
| 执行延迟稳定性 | 跨 held-out trial 漂移超过一个控制周期 `33.3 ms` 即 `NO-GO` |
| 执行前沿状态误差 P95 | `v <=0.03 m/s`、`omega <=0.05 rad/s` |
| 总 lead 液体预测 | 对带方向的 L/C/R 液面 proxy：coherence `>=0.8`、phase error `<=10--15°`、gain error `<=15%`；对非负 `H_vis` 另报 MAE/P95 和峰值时序，不能机械套相位相关 |
| recovery false-safe | held-out 观测接近 0，并报告由预注册样本量得到的置信上界，而不是只报点估计为 0 |

如果这些阈值相对测量分辨率或安全裕量不合理，应在看正式 outcome 之前根据误差预算修改并签署新协议；不能在结果出来后移动门槛。

## 9. 正式冻结清单

每个正式 batch 的 manifest 至少包含：

### 9.1 软件和构建

- Git branch、clean revision、submodule 状态；
- ROS/OS/acados 版本；
- build/test report 及 SHA-256；
- generated solver JSON、共享库、codegen 参数和 hash；
- runner、recorder、postflight、RGB 和统计分析脚本 hash。

### 9.2 硬件和环境

- Scout 序列号、CAN `500000 bit/s`、轮面状态、载荷；
- 电池起止电压/SOC 和允许区间；
- 地面、温度、照明、场地照片；
- 容器 ID、液体 batch、半径、液深、freeboard、温度；
- IMU、相机、动捕设备序列号、固件和安装照片。

### 9.3 标定与模型

- 动捕辅助 IMU→容器中心平面外参冻结报告及 SHA-256；当前范围不要求 Z 或完整六自由度 hand-eye；
- IMU bias/scale/filter/time report；
- Scout execution-model 参数、适用域、误差集合和 held-out report；
- 液体 `omega_n,zeta,kappa_x,kappa_y,c_h`、模型结构和 held-out report；
- RGB calibration、camera parameters、metric/window rule 和各自 SHA-256。

### 9.4 路径和方法 artifact

- 地图、冻结路径、几何/碰撞报告及 hash；
- OfflineSloshOCP 输入、输出、求解状态和验证报告；
- phase artifact `contract_id`、schema、evidence level、完整尾段和恢复策略；
- recovery held-out false-accept/false-reject/重接报告；
- `phase_rejoin`、delay、observer、safety、terminal、variant 和 solver 参数 dump。

### 9.5 执行合同

- 唯一 `FREEZE_ID`、protocol ID、随机顺序和 trial label；
- `/cmd_vel` 唯一 publisher；
- READY、freshness、common-epoch、artifact 和 G0 全部为 PASS；
- 失败/重试/排除规则和人工急停规则；
- 正式第一条之后所有输入资产只读。

现有 `freeze_manifest.template.yaml` 仍是旧协议模板，只能参考字段结构，不能直接把 `status` 改成 `GO` 用于新 Phase-Rejoin 方法。

## 10. 重新标定/重新生成触发矩阵

| 变化 | 必须重做的内容 |
|---|---|
| 换试管、液深/配方/温度范围变化、补液或泄漏 | 容器测量、液体辨识、RGB zero/calibration、OfflineSloshOCP、recovery artifact |
| 容器支架或水平位置/角度变化 | 重新做 IMU→容器中心平面 XY/yaw 外参、RGB、路径碰撞包络和 artifact；仅高度变化不进入当前平面杠杆臂，但仍复核包络/质心 |
| IMU、支架或容器相对安装变化 | 重新做 IMU→容器中心平面 XY/yaw 外参；只有扩展到 roll/pitch/三维运动时才要求完整六自由度 |
| IMU 驱动/固件/滤波变化，但机械安装未变 | 平面外参继续复用；重新验证时延、幅相、时间戳和 observer |
| 相机拆装、焦距/分辨率/曝光/照明变化 | camera info、ROI、三标尺、HSV、zero、时间链 |
| 轮胎/轮面、载荷、底盘固件或地面变化 | 执行模型、odom 偏差和安全 limits；必要时液体 held-out |
| 电池超出已验证区间 | 执行模型重新验证或停止 |
| 地图、定位配置、路径或起终点变化 | TF/path 验证、OfflineSloshOCP 和 recovery artifact |
| `dt`、horizon、模型、bounds、状态维数变化 | acados codegen、build/test、OfflineSloshOCP、artifact |
| terminal/safety/limiter/publish 链变化 | 重新确定 `u_pub` 合同和执行模型，重生成 artifact |
| recovery gate、策略、candidate 或 residual bounds 变化 | 新 development/held-out 数据、新 artifact、新 `FREEZE_ID` |
| 时间戳跳变、预测残差漂移或 false-safe 出现 | 立即停止 enforce，审计时钟/传感器/模型，只重做受影响的标定或 artifact；不默认使平面外参失效 |

## 11. 推荐执行顺序

```text
S0 设备身份、急停、唯一 cmd publisher、时钟和记录链
↓
S1 容器/液体几何与安装确认；绑定已冻结的 IMU 平面外参和 RGB 标定
↓
S2 Scout 线角双通道执行模型辨识与 held-out
↓
S3 processed IMU 幅相、时间和 READY/fail-closed 验证；不重新辨识已冻结的平面杠杆臂
↓
S4 液体 omega_n/zeta/input gain/高度映射辨识与 actual-input held-out
↓
S5 RGB 独立测量标定与 held-out 人工标尺验证
↓
S6 G0 总 lead 预测和控制灵敏度
↓
S7 地图/路径冻结，生成正式 OfflineSloshOCP 序列
↓
S8 拟合恢复集合与策略，用独立 R1 数据统计 false-accept
↓
S9 phase_rejoin=off 回归 → monitor 实物只审计 → 安全台架/低速 enforce smoke
↓
S10 新 FREEZE_ID 下的预注册正式实验
```

任何一步失败都应回到对应模型或测量链修正；不要通过放宽 gate、增大 residual bounds 或继续叠加补丁来“跑通”。

## 12. 每条实物 trial 前的最小现场检查

- [ ] Git revision、build/codegen、runner 和所有冻结资产 hash 与 manifest 一致；
- [ ] 容器 ID、液体 batch、液深、温度、安装和相机视野未变化；
- [ ] IMU、支架和容器的水平相对安装未变化，runtime `yaw=0、XY=[-0.100,+0.045] m` 与平面外参冻结报告/hash 一致；
- [ ] 电量、载荷、地面处于执行模型适用域；
- [ ] CAN、`/odom`、`/imu/data`、`/map`、TF、相机、RGB scalar 频率和时间戳正常；
- [ ] processed IMU 已在完整静止 bias window 后 `READY`，无 reset/fallback；
- [ ] RGB 已在运动前 `valid + zero_locked + STATUS_OK`，标定和相机参数 hash 正确；
- [ ] `map -> base_link` 对齐，机器人位于冻结起点/朝向门内；
- [ ] 固定路径、OfflineSloshOCP artifact、`contract_id` 和 phase debug 合同通过；
- [ ] `/cmd_vel` 只有当前 runner 一个发布者，急停和受控停车已验证；
- [ ] recorder 已包含 `/spmpc/debug/phase_rejoin`、最终命令、执行状态、observer、RGB 和完整 source stamps；
- [ ] 当批 G0、恢复 held-out 和 false-accept 报告为 PASS；
- [ ] 现场不修改权重、延迟、ROI、HSV、gate、路径或 artifact。

只有以上项目全部闭合，才可以把当前方法从 development `monitor` 推进到受控的实物 `enforce`。

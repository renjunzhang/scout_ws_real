# RTI质量退出验证与旧稳定基线回归

2026-09-19。**“最多三次、合格早退”使完整模型闭环通过；冷启动仍出现MINSTEP；Gazebo仍在实际jerk及停车校验上失败。用户已确认实际jerk≤1不是必须的物理要求，因此本轮停止扩展，默认关闭该新增约束，回到旧稳定运行物组织对比。**

## 1. 两项最小检查

RTI使用`rti_iterations=3、rti_min_iterations=1`，残差和生成约束合格后进入完整校验；实际jerk、预测轨迹、区域、代价及发布时限检查均保留，液面硬约束关闭。35个定向用例通过，包含B0／Full提前退出及不可控FIFO约束拒绝。

27.8秒历史失败没有完整的原始求解器快照。本次从原始初态回放834拍已执行控制，重建28维状态及全部执行器队列；沿途CSV记录的车辆／命令状态和模型液面误差均为0，冷启动初值的物理状态与FIFO也完全对齐。使用新capsule及从反馈重算的计划初值，固定三次、暂不加墙钟预算来单独检查重置候选，**仍在第一次RTI报`ACADOS_MINSTEP`，QP第13次迭代失败**。

这是重建反馈的冷启动检查，不是缺失的旧primal／dual／QP内存的精确回放；旧终端内部状态和虚拟进度控制历史也未完整保存。结果不支持把重置直接接入停车恢复，不能认定或排除旧内存为唯一根因。本轮未增加恢复重置。

用户确认：新增实际jerk约束是为了改善FP-AS对比，不是必须的物理限制。因此`planned_slosh`默认`actual_jerk_max`恢复0，**原命令jerk=1、执行器适配、状态对齐、完整安全校验和液面软代价继续保留**。质量早退能力及显式3／1入口保留；不引入未通过的停车恢复重置，也不再试跑。

严格区分两件事：当前源码关闭新增开关；对比证据则使用**归档旧稳定二进制**。关闭开关不等于当前新运行物已获得旧版验证。

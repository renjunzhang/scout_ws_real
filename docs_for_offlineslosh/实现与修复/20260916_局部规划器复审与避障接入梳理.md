### REVIEW-01：终点制动没有沿用预测区域合同

[SpmpcProblem当前区域检查](../../src/scout_apps/control/spmpc_local_planner/src/core/spmpc_problem.cpp#L214)仅检查当前位姿。进入[terminal_plan.owns_command分支](../../src/scout_apps/control/spmpc_local_planner/src/core/spmpc_problem.cpp#L362)后，普通停车生成jerk受限命令便直接返回success；没有调用[OcpPlanningAdapter的预测区域核验](../../src/scout_apps/control/spmpc_local_planner/src/planning/ocp_planning_adapter.cpp#L235)。complete-stop虽然预测尾段，但[调用方](../../src/scout_apps/control/spmpc_local_planner/src/core/spmpc_problem.cpp#L279)只查液面和首命令速度，[TaskStopManager](../../src/scout_apps/control/spmpc_local_planner/src/core/task_stop_manager.cpp#L181)未消费区域几何。

复现使用圆包络0.426 m、margin0.02 m，区域右边界x=1 m，允许中心到x=0.554 m。机器人x=0.53 m、actual/command速度0.2 m/s、线速度FIFO全为0.2，目标x=0.55 m：

```text
ok=1 success=1 status=TERMINAL_DRAINING cmd=0.198889 clearance=0.024000 ocp=0
4个FIFO前缀步之后：x=0.556866 clearance=-0.002866
```

这里前4步的实际运动仍由此前5拍线速度FIFO决定，后续新命令不能立即消除位移。例子证明当前返回的“成功停车”没有区域可行性含义；它**不证明这个初态还存在可避免越界的控制**。在下一拍发现已越界再发零，也不能消除延迟/惯性。处理方向应包含进入停车前的可停止余量、完整尾段扫掠检查及不可避免越界的明确状态，不能只补一个“失败就零速”分支。

### REVIEW-02：普通MPCC初态的位姿和速度时刻不一致

默认`frames.use_tf_pose=true`。ROS通过[solver_consumes_selected_state决定是否做共同时间对齐](../../src/scout_apps/control/spmpc_local_planner/src/ros/spmpc_local_planner_ros.cpp#L1979)。raw、geometry、planned_mpcc默认不消费液体，进入[robotStateFromLatest](../../src/scout_apps/control/spmpc_local_planner/src/ros/spmpc_local_planner_ros.cpp#L2498)：速度来自latest odom，位姿来自`lookupTransform(..., ros::Time(0))`，TF返回的时间戳没有保存/核对。

随后[非液体分支](../../src/scout_apps/control/spmpc_local_planner/src/ros/spmpc_local_planner_ros.cpp#L2121)将该混合状态标为odom源时间，再交给[predictExplicitActuator](../../src/scout_apps/control/spmpc_local_planner/src/ros/spmpc_local_planner_ros.cpp#L2232)前推到求解前时刻。若TF位姿比odom晚100 ms，相应运动可能被重复积分；若TF较旧，则会漏计运动。以匀速0.25 m/s示意，100 ms错配对应25 mm，已与5 cm终点容差同量级。此数值是量纲示例，不是新实测误差。

这会影响投影、区域净空和任务目标，并使液体开启/关闭组拥有不同的车体初态时间处理。修正边界应是：**所有组的车体pose/twist都对齐到一个明确时刻**，是否消费液体只决定是否再与液体时刻对齐。必须记录和验收真实TF/odom时刻，不能只在诊断字段里把时间写成相等。本机未运行ROS1整节点，因此尚无现场触发频率数据。

### REVIEW-03：允许偏离原线后，全路径最近点更容易选错分支

[ProgressProjector](../../src/scout_apps/control/spmpc_local_planner/src/reference/progress_projector.cpp#L46)扫描所有后续线段，仅以`min_s`防后退，没有可达前跳上界、上一segment邻域或分支身份。[TrajectoryReference::project](../../src/scout_apps/control/spmpc_local_planner/src/reference/trajectory_reference.cpp#L50)也采用全后续段最近投影；本轮数值反例直接验证的是前者。

生产函数输入路线`(0,0)→(2,2)→(0,2)→(2,0)`：

```text
位置(.999,.999)，s=1.412799
位置(1.001,.999)，min_s=1.412799，s=6.244055
位置回到(.999,.999)，min_s=6.244055，s仍为6.244055
```

位置只变2 mm，进度却跳4.831 m；单调保护反而阻止纠正。此后region cell、参考、终点剩余距离可能都选错。自交反例已复现，近邻折返/规划曲线自接近也应补验；不能推断普通单弯样例一定触发。

处理方向是把投影限定到连续可达的进度/segment邻域，并为重新定位单独定义恢复条件。限制应允许正常切角，不能重新用很小的原线跟踪误差阻止自主缓弯。

### REVIEW-04：无上层计划时，已到达锁存没有重新核对位置

[SpmpcProblem的goal_pose_ready](../../src/scout_apps/control/spmpc_local_planner/src/core/spmpc_problem.cpp#L242)只在有task_plan时包含位置条件；没有计划时基本只检查yaw。[传给TerminalController的completion_ready](../../src/scout_apps/control/spmpc_local_planner/src/core/spmpc_problem.cpp#L294)因此可在位置已经偏离时仍为true。[TerminalController锁存分支](../../src/scout_apps/control/spmpc_local_planner/src/core/terminal_controller.cpp#L58)不会再检查`goal.position_reached`。

在deadline=12 s、goal_tolerance=0.05 m、普通停车、空FIFO下，先在x=0.55 m到达目标；再模拟外扰/定位修正到x=0.35 m，yaw与速度不变：

```text
goal first: GOAL_REACHED reached=1
goal displaced: GOAL_REACHED reached=1 position_reached=0 goal_error=0.200000
```

这影响raw/geometry的完成统计和外扰检测。在计时任务超过deadline后，外层deadline检查可能改报失败，但在此之前错误到达状态仍存在；无deadline时可持续保持。处理方向是统一所有组的实时位置/朝向/运动/队列完成条件。失去完成条件之后是否重新规划属于另一项状态机决策，不应靠仍报到达掩盖。

### REVIEW-05：不发布速度模式缺少真实命令历史输入

`command_history_`只由[recordPublishedCommand](../../src/scout_apps/control/spmpc_local_planner/src/ros/spmpc_local_planner_ros.cpp#L1308)写入；[publishZeroCommand](../../src/scout_apps/control/spmpc_local_planner/src/ros/spmpc_local_planner_ros.cpp#L1462)和[publishCommand](../../src/scout_apps/control/spmpc_local_planner/src/ros/spmpc_local_planner_ros.cpp#L1548)在`publish_cmd_vel=false`时都提前返回。当前[订阅入口](../../src/scout_apps/control/spmpc_local_planner/src/ros/spmpc_local_planner_ros.cpp#L1027)没有外部最终命令历史订阅。

从空历史启动即形成闭环：predictExplicitActuator发现[NO_CMD_HISTORY](../../src/scout_apps/control/spmpc_local_planner/src/ros/execution_state_predictor.cpp#L184) → 初始化失败 → 不发布零命令也不记录历史 → 下一拍仍为空。即使外部bag播放`/cmd_vel`，当前节点也不会将它接入该buffer。

因此`publish_cmd_vel=false`可以用于检查参数和传感器接纳，但当前不能宣称已经支持完整无运动显式OCP回放。应区分“物理输出关闭”和“消费带来源身份的已记录最终命令”；不能往历史里虚构已执行零命令来让检查通过。

### 已知问题复核：求解完成后缺少命令有效期判断

当前前推目标是[求解前时刻](../../src/scout_apps/control/spmpc_local_planner/src/ros/spmpc_local_planner_ros.cpp#L2235)。[求解后的发布链](../../src/scout_apps/control/spmpc_local_planner/src/ros/spmpc_local_planner_ros.cpp#L2349)记录solve_end并检查既有状态/安全门，但没有以整周期年龄拒绝过期u0；[publishCommand](../../src/scout_apps/control/spmpc_local_planner/src/ros/spmpc_local_planner_ros.cpp#L1544)也没有deadline检查。

这对应既有RUN-02，不算本轮新增发现。9月16日模型闭环已有最坏约100 ms的证据；`v_max*dt`的区域扫掠余量基于名义dt，不能自动覆盖超时。需统一计算预算、发布年龄和停车延迟余量；单纯增加RTI次数会加重此问题。

## 2. 本轮排除或保留待验的事项

- 四个新profile已关闭旧`tracking_safety`，不能再把其“贴线安全门”当默认自主几何受限的已证实原因。
- common中`reference.preprocess_enable=false`；“默认二次平滑导致计划路线身份不符”不成立。若另外开启预处理，应重新核对路线身份。
- 区域有车体圆包络、相邻cell空间交集、预测节点额外扫掠余量；不是完全没有footprint/区域检查，缺口集中在上述终端旁路及真实时间链。
- 计划初态与现场起点的接纳范围尚需现场定义，但在线从偏离名义的真实状态求解本来就是框架能力；不能仅以“不是完全相同初态”认定bug。
- 完整计划进度终值仍为原路线长度，并非优化后几何弧长。本轮未把两者不同当成停车bug。
- 未实现在线后缀反馈、全局区域拓扑搜索、连续自由终止时间及动态避障，属于能力边界；不与代码缺陷混记。

## 5. 避障接入的最小梳理（尚未进入实施设计）

**先界定第一步为“已知静态障碍场景内的区域自主缓弯”**。原路线可以不平滑，允许区域必须真实排除障碍物；MPCC在其内选缓弯。显式区域不等于要求重新贴线，也不等于已经具备突发障碍的在线左右绕行能力。

需要按顺序厘清以下事项：

1. **先补控制有效性边界。** 处理本轮投影、车体时间、停车区域、完成状态和回放缺口，并核验最坏周期；否则加障碍约束仍可在旁路失效。
2. **静态任务先复用现有区域接口。** 在同一已测空闲区域中给raw和完整方法相同空间权限；可以先离线准备/核验凸cell。若原路线穿障碍，要明确一条可行的引导/区域序列，仅靠连续弱跟踪不保证搜索到另一绕行拓扑。
3. **再梳理地图到局部区域的数据适配。** 固定地图来源、frame、unknown、膨胀归属及容量处理。复用MotionRegion/半空间装配和独立碰撞检查；不可为了塞入当前每cell最多8条边而直接删除障碍约束。
4. **保持任务区域与在线障碍约束分工。** 当前plan严格绑定region身份/内容；未来动态局部图变化不能直接冒充新task region覆盖它，否则计划合同会失效。需要区分固定任务空间与随时间更新的局部碰撞约束，保留deadline和原任务身份。
5. **覆盖全部命令路径。** 当前点、OCP各节点及节点间、真实FIFO前缀、终端制动尾段、故障时旧命令残留都使用同一空间口径。硬碰撞边界不能因液体恢复预算而放宽。
6. **先看最小反例再扩大实验。** 静态单障碍、窄通道、角点、贴边制动、图外/unknown、动态图断流、TF延迟、求解超时、自交投影分别核对。记录真实净空、碰撞检查结果、任务完成、耗时、曲率和液面，不以低路径误差验收自主规划。

以后若需要“新障碍出现后自主从左右两侧选路”，再增加局部几何引导/候选选择和一致的剩余任务检查；这不是第一步打开一个开关能完成的事。当前没有新增避障参数、类层次、动态障碍预测或实施排期，先据此复盘后再定具体改动。

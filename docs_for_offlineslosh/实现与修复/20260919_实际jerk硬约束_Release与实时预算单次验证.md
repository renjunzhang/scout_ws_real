# 实际 jerk 硬约束：Release 与实时预算单次验证

2026-09-19。**Release 后 S 模型闭环 42.433 s 完成，最大求解调用 27.976 ms，实际模型 jerk 未超限；但出现三次预算保护停车，未通过“无异常”门槛。按预先停止条件收尾，没有启动 Gazebo，没有生成新的 B0／FP-AS／Full 有效对比图。**

## 做了什么

- 复用已有 jerk=1 的 task／plan，不重新规划、不扫参。在线液面仍为软代价（权重5），硬约束关闭，进度奖励0。
- native 和 ROS 都显式 Release 构建（C++ `-O3 -DNDEBUG`）；生成求解库保留默认 `-O2`，未启用 fast-math，模型和物理参数不变。
- 新增 `acados/rti_min_iterations`，默认1，保留原有配置行为。本次最小次数和上限都为3，避免模型固定三次、ROS“可行即退出”的策略差异。预算不足三次时拒绝求解结果，沿用已验证停车与恢复，不放宽发布截止时间。
- native 本次启用真实墙钟预算30.333 ms（30 Hz周期减3 ms发布预留），记录每拍实际次数和分段耗时。ROS 构建完成，提供单次运行覆盖入口，但因模型门槛失败没有运行。

## 原因和剩余缺口

Release 后主要耗时在RTI内部：实际求解拍RTI耗时P95为17.959 ms、最大27.442 ms；三次被拒绝拍的solver setup均小于1 ms。现有证据不支持把剩余问题归因于重复模型校验，也不支持继续压成两次RTI或放宽时限。

若继续推进，最小下一步是保存逐次RTI耗时及预算估计，区分QP计算尖峰与系统调度波动，再针对证据处理；当前日志没有这些细节，原因尚不能进一步确定。本轮不为得到成功结果追加运行。

30 Hz网格上的执行器模型加速度差约束，包含FIFO换头，但不是连续高频jerk或实车保证。本次同模型闭环尚未覆盖ROS收发时序、120 Hz执行器适配与里程计失配。模型液面峰值0.626548 mm仅作留档，不是独立真实液面测量或新版本防晃收益。

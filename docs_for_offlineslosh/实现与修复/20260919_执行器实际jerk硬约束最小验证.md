# 执行器实际 jerk 硬约束：实现与最小验证

2026-09-19。代码提交 `f37a1e1c`。**约束已实现且测试通过；新增 S 路径模型闭环未完成，不是新的成功仿真结果。在线液面保持软代价，硬约束关闭。**

## 做了什么

- 保留原命令加速度 ±0.6 m/s²、命令 jerk ±1 m/s³；新增执行器模型输出的**纵向 jerk ±1 m/s³**。定义为 30 Hz 下 `(a[k+1]−a[k])/dt`，其中 `a=(gain×延迟队列头−实际速度)/tau`，包含 FIFO 换头，覆盖预测时域及停车尾段。
- 求解器增加一个线性硬约束行；用当前响应参数和生产 RK4 离散化构造。求解前检查不可改变的延迟前缀，求解后从真实输入状态完整重放检查。超限拒绝，不修补历史、不裁剪状态。
- Full 与 FP-AS 离线规划、Python/C++ 计划验证接受相同的可选 `motion_limits.actual_jerk_max`；在线为 `ablation/actual_jerk_max`。两者必须匹配，0 表示关闭，旧计划缺字段按 0 解释，不给历史数据补上不存在的保证。
- Full 实验 profile 默认设 1；通用实车配置仍为 0，未改变实物部署。仿真 runner 按任务合同设置并检查实际加载值，保存实际链接的库。调试消息 schema 升为 9，记录新上限，旧 schema 8 液体回放仍可读取。
- 正常停车按执行器响应推导更保守的命令 jerk：`min(J_cmd, J_actual×tau×(1−r)/(gain×dt))`，`r` 是生产 RK4 一拍速度衰减率。当前参数约 0.849624 m/s³。对求解器给出的首命令仍按公共限制与实际尾段验证，未缩小整个 OCP 的命令上限。故障停车保留；不可挽回的历史超限明确失败，不宣称紧急停车也一定满足新限制。

这是**控制网格上的执行器模型约束**。速度命令逐拍保持，连续时间加速度存在跳变，不能称为任意高频连续 jerk 保证；也没有新增横向／角 jerk 限制或独立实物液面证据。

**两次模型闭环尝试均保留：**

1. 首次 4.367 s，旧停车生成器只保证命令 jerk，预测停车尾段的实际 jerk 超限，于是提前停车并超时。保留在 `native_before_stop_fix/`。这是明确实现缺口，按规则修复后只重跑受影响检查。
2. 修复后 25.300 s 触发 `PREDICTION_DYNAMICS_VIOLATION`，停车后曾恢复；26.833 s 又出现 `ACADOS_SOLVE_FAILED_4`，日志含 QP `ACADOS_MINSTEP`。随后故障停车，45.033 s 报期限失败。行驶 4.182 m，距终点 0.985 m。实际 jerk 始终满足本轮模型检查，没有放宽限制。

第二次剩余问题是当前 RTI 数值／闭环可行性，尚未定位到新的明确实现错误；不能证明任务在该 jerk 上限下不可行。按停止条件不改权重、不增加求解迭代试档、不追加 Gazebo。下一步应检查 25.3 s 的状态、暖启动、动力学缺陷及 QP 活跃约束。

部分模型闭环的液面峰值 0.651455 mm 仅归档，**不能与上一版已完成的 Full／FP-AS Gazebo 数据作收益比较**。约40秒共同档的历史成功结果仍属于旧的仅命令 jerk 版本。

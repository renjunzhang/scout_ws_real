## 1. 实现分工与边界

包根：`src/scout_apps/control/spmpc_local_planner`。

| 模块 | 当前职责 |
| --- | --- |
| `reference/motion_region` | 显式凸区域及有序 cell；圆形包络覆盖车体，预测节点额外收缩 `max_speed * dt`，检查节点间运动余量；当前实际点在停车与完成分支也检查 |
| `scripts/planning/task.py` | 完整初态、物理参数、区域、目标、期限、评价窗与目标权重的输入合同；未知目标项、非有限数、无效尺度显式拒绝 |
| `scripts/planning/optimizer.py` | CasADi/IPOPT 全状态 multiple shooting；联合优化命令、几何与时序，包含车辆、FIFO、jerk 记忆、液体、真实目标和 TAIL |
| `scripts/planning/validation.py` | 从同一初态重新传播完整状态；核验运动、区域、停车与细化液体峰值；生成模型内报告 |
| `reference/trajectory_plan`、`trajectory_reference` | 计划身份和模型合同；按时间或保存的计划进度采样、投影。索引只归一化允许的数值误差，原始完整状态不被重写 |
| `reference/horizon_reference_builder` | 装配 N+1 阶段参考；四个速度/进度速度节点，检查存储断点误差并缩小局部区间；启动/等待/尾段保留时间语义 |
| `planning/ocp_planning_adapter` | 不依赖 ROS/acados API 的区域、计划、目标装配与预测核验；检查运行时与计划的物理参数、区域和停车合同 |
| `core/task_clock`、`spmpc_problem` | 持续任务时钟；重复发布路线不续期；时钟倒退/换源或计时任务换路线明确失败；真实位置、朝向、实际运动和队列共同判断停车 |
| `scripts/planning/suffix.py` | 从真实 28 维预测状态重放名义后缀或重新优化，不清零液体/FIFO，不投影回名义位姿，不改变在线命令 |
| `ros/planning_config_ros`、诊断消息 | 类型化参数读取、启动拒绝无效合同；schema 8 保存计划/区域/阶段身份及完整预测状态 |
| `scripts/experiments/recording_contract.py` | 按 launch 顺序合并并冻结配置、文件 hash、Git 状态；录制前核对实际 ROS 参数 |

上层采用固定 30 Hz 网格，运输时长由任务给定（默认等于 deadline）；没有实现连续自由终止时间优化或全局区域拓扑搜索。`progress_scale` 是优化变量，MOVE/BRAKE 段满足 `v_s[k] = scale * (v_actual[k] + v_actual[k+1]) / 2`，尺度上下限暴露为任务参数。这样移动不能靠暂停虚拟进度制造多值空间参考；计划进度的终值仍是原路线长度，不能用优化后几何弧长替换。

下层使用真实状态重新预测，contour 仅为弱偏好，独立区域约束提供空间权限。几何拟合采用局部归一化坐标，代价、诊断与采样使用同一坐标域。曲率项采用 `sqrt(v_actual² + speed_floor²)` 正则化并按弧长型权重累计；这是有限低速惩罚，**不是零速处真实曲率的定义**。低速转动单独统计。

期限进入预测窗口后，在对应节点约束真实目标位置/朝向和实际速度；命令、FIFO、加速度记忆清零。真实目标软代价帮助避免弱跟踪下停在目标之外，但它与防晃、曲率、速度参考仍有权衡。这不是递归可行性或液体硬沉降证明。

## 2. 关键审查修正

- 参数布局由 Python 共源生成 C++ 索引，B0/slosh 为 **NP 92/104、NX 24/28、NU 3**；液体版本 1、代价版本 3、snapshot/horizon schema 8。旧 schema 7 的参数只支持带来源身份的显式转换，不用新代价重构冒充旧版代价。
- 两模型 stage 与 terminal 均有 **20 个状态 box**，包含 actual 速度、命令、完整 FIFO 和加速度记忆；此前生成终端节点没有这些 bounds。
- RTI 成功后仍检查预测动力学缺陷、区域/参考区间、车辆/控制边界、jerk、目标和液体限制；不把 solver status 0 当成可行性证书。
- 已真正消费 `warm_start.use_previous_solution`：从当前完整实态重放移位的上次解；没有上次解时可用完整名义计划。重复 RTI 不在每次迭代重置初猜。
- 统一进度的数值容差为 `1e-6`，包括独立传播累积误差；容差仅用于进度坐标，不扩大空间区域。解决终点 `2 + 2e-11` 和名义后缀微小误差被误拒绝的问题。
- 普通 MPCC 停车不依赖液体状态；仍按 jerk 释放命令/FIFO。无效发布历史返回失败，不假装清空历史或完成停车。
- 修正验证工具：观察窗口不抵扣到达期限；失败记录实际停止时间；评价积分不多算末端一拍；记录完整有效参数和初次 OCP 参数。
- `PredictedHorizon.model_states` 记录所有 FIFO，检查点工具拒绝从 24 维 B0 预测虚构液体初态。参数/消息变更需在 ROS1 环境重新生成消息并整体编译。

## 3. 暴露的实验入口

配置目录：`config/experiments/trajectory_mpcc/`；共同停车、jerk、RTI 和评价合同放在 `trajectory_common.yaml`，单组文件不再重复覆盖这些字段。

| Profile | 参考与几何 | 在线液体 |
| --- | --- | --- |
| `raw_mpcc` | 原路线、巡航参考，contour 1，新曲率/目标软代价关闭 | 代价、约束、恢复、风险 governor、液体停车决策全部关闭 |
| `geometry_mpcc` | 原路线、区域自主几何，contour 0.02 | 关闭 |
| `planned_mpcc` | 完整上层计划、progress 参考、区域自主几何 | 关闭 |
| `planned_slosh` | 与 planned_mpcc 相同计划和非液体设置 | 开启液体代价；硬液面约束默认关闭，可用 overlay 开启 |

当前下层几何候选：`curvature_weight=0.05`、`curvature_rate_weight=0.01`、`speed_regularization=0.05`、`goal_weight=2`；goal 归一化为 0.3 m 和 1 rad。除有意设置不同的 contour 外，共同常规权重明确写出；planned 两组的非液体参数完全匹配。`rti_iterations=5`、`max_prediction_defect=1e-4`、命令 jerk 1 m/s³、`actual_v_min=-0.002` 为软件候选。参数暴露不代表已完成实物校准。

主比较是 raw 与完整方法。planned 两组共用同一上层液体计划，隔离的是下层液体项；**这四个 profile 不是“上层液体开关 × 下层液体开关”的完整析因设计**。后者需另生成 `objective.liquid=0`、`objective.liquid_terminal=0` 的上层计划，再分别跑两种下层模式。固定几何时间律对照、独立液体对象和剩余段进入在线目标仍是后续工作。

录制使用 `scripts/record_trajectory_mpcc_comparison.sh`，可先设 `VALIDATE_ONLY=true`。必须提供同一实际区域和正 deadline；planned 必须有计划。manifest 保存完整合并配置、artifact 副本/hash、Git SHA/status/diff；实际录制前读取 `/spmpc_local_planner` 私有参数逐叶核对。脚本本身不 launch 节点、不发速度命令。记录了原路线、完整预测、实际命令、代价、停车、液体观测和 TF；独立相机/液面数据仍需使用原有采集链另行录制。

`corner_task.example.yaml` 与 `corner_region.example.yaml` 只是软件样例，不能当成实测空闲区域。启动及只校验示例见该配置目录 README。规划 latched JSON 只覆盖 planning 字段，且 property_tree 将标量写成字符串；完整配置以 manifest 和核对后的 live 参数为准。

## 4. 软件验证结果

最终 C++ 验证：15/15 个 CTest 程序通过，包括真实 acados 回放/代价重构、区域、完整参考、任务时钟和普通停车。Python 定向检查 61 项通过，另新增完整检查点导出 1 项通过，共 62 项；ROS/rosbag 依赖的历史全套测试没有在此主机运行。录制脚本只进行了输入校验，未真正录 bag。

三任务 × 四组 × 两种执行器条件共 24 次串行闭环，**22 次按时完成**。扰动为 plant 两个执行器时间常数乘 1.15，控制器仍使用原参数；它是有限的模型失配测试，不是独立液体对象。液体反馈直接使用 plant 模型状态，属于理想反馈的模型内测试。

下表只列名义执行器的主比较，液面峰值为 30 Hz 节点的 modal 高度。曲率能量包含低速正则化，不能单独解释为无条件的几何曲率积分。

| 任务 | 组 | 完成时刻 s | 曲率能量 | 实际距离 m | 液面峰值 mm |
| --- | --- | ---: | ---: | ---: | ---: |
| 直线 | raw | 4.967 | 0 | 0.5639 | 0.751 |
| 直线 | planned_slosh | 4.500 | 约 0 | 0.5807 | 0.783 |
| 单弯 | raw | 11.700 | 5.6010 | 1.9135 | 0.893 |
| 单弯 | planned_mpcc | 5.133 | 1.5740 | 1.5194 | 1.193 |
| 单弯 | planned_slosh | 5.533 | 1.5725 | 1.5117 | 1.194 |
| 连续弯 | raw | 16.100 | 11.3120 | 2.8325 | 0.893 |
| 连续弯 | planned_slosh | 7.233 | 1.0077 | 2.2379 | 1.213 |

直线/单弯/连续弯的期限分别是 8/12/18 s，固定评价窗均延续到 deadline + 1 s。所有成功组都经过完整评价窗、区域、命令/实际速度及 jerk 检查。两次失败均为单弯 `geometry_mpcc`（无上层）返回 `ACADOS_SOLVE_FAILED_4`；其失败前更低的曲率不计作成功。

planned 与 planned_slosh 的 6 对运行逐项核对了共同 92 个 stage-0 OCP 参数，全部相同。直线中在线液体项相对同计划液体关闭组降低了模型峰值，但整套方法相对 raw 尚未降晃；弯道几何变缓同时运行明显更快，不能将组合结果全部归因于液体项。

完整组周期耗时 P95 约 21–34 ms，最高约 100 ms；即使串行运行，也未满足 30 Hz 每周期 33.3 ms 的要求。不得将这些结果表述为实物实时可用。

三条计划的名义后缀回放均通过。6 个在线预测末端接“同绝对时间的名义命令”均失败，检查保留了真实进度、FIFO 和液体。单弯名义执行器的一个 3 s 预测末端另做完整重优化，IPOPT 返回 `Infeasible_Problem_Detected`，未找到候选；这不是全局无解证明，也不妨碍之后继续滚动闭环成功，但说明局部可接受预测不保证当前搜索能接回完整剩余任务。后缀信息尚未参与控制，因此不能声称解决了剩余任务可行性。

保留的开发负结果还包括：独立虚拟进度造成空间参考多值、单次 RTI/不复用初猜导致停滞，以及下层曲率权重 1.0 时终点朝向调整不足。最终默认降低曲率权重；没有通过放宽目标、区域或 deadline 把这些失败改成成功。

完整 24 行结果和生成物身份保存在仓库 `test/native/results/20260916_geometry_trials.csv` 与 `20260916_geometry_identity.json`。原始 CSV、参数 manifest、horizon/checkpoint 和日志位于 `/tmp/scout_geometry_verified_20260916/`；独立后缀重优化报告为 `/tmp/scout_geometry_final_20260916/corner_reoptimized_suffix.json`。临时目录可能被清理，精简结果及可复现任务已提交。

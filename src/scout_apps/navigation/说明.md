# navigation 模块说明

## 最后更新：2026-02-02

---

## 模块概述

`navigation` 负责 `move_base` 全局规划链路，核心输出是 `/scout/global_path`。  
当前 launch 已支持两种模式统一切换：

- `mode:=mpc`（默认）：move_base 只提供全局路径，底盘由 MPC 控制
- `mode:=teb`：move_base 使用 TEB 作为局部规划并直接发速度

## 关键参数（已补充）

`move_base_global.launch` 与 `move_base_global_sim.launch` 共同支持：

- `ns`：默认 `/scout`
- `mode`：`mpc | teb`，默认 `mpc`
- `remap_goal`：默认 `true`
- `base_global_planner`：默认 `global_planner/GlobalPlanner`

`mode` 的行为：

- `mode:=mpc`
  - `base_local_planner` 设为 `dwa_local_planner/DWAPlannerROS`（占位）
  - `cmd_vel` 重映射到 `/scout/move_base_cmd_vel`（不直接控底盘）
- `mode:=teb`
  - `base_local_planner` 设为 `teb_local_planner/TebLocalPlannerROS`
  - 加载 `config/teb_local_planner.yaml`
  - `cmd_vel` 重映射到 `/cmd_vel`（move_base 直接控底盘）

## 话题接口

| 方向 | 话题 | 类型 | 说明 |
|------|------|------|------|
| In | `/scout/goal` | `geometry_msgs/PoseStamped` | 目标点输入（`remap_goal:=true` 时） |
| Out | `/scout/global_path` | `nav_msgs/Path` | 全局路径输出（`~GlobalPlanner/plan` remap） |
| Out | `/scout/move_base_cmd_vel` | `geometry_msgs/Twist` | `mode:=mpc` 时的 move_base 速度输出（旁路） |
| Out | `/cmd_vel` | `geometry_msgs/Twist` | `mode:=teb` 时的实际底盘控制输出 |

> 注意：`mode:=mpc` 时，底盘应由 `scout_local_planner` 发布 `/cmd_vel`；不要和 TEB 同时控车。

## 配置说明（已修正）

配置文件：

- `config/global_planner.yaml`（实物）
- `config/global_planner_sim.yaml`（仿真）
- `config/teb_local_planner.yaml`（仅 `mode:=teb` 生效）

关键参数现状：

- `transform_tolerance`（global/local costmap）= `1.0`（实物与仿真）
- 实物 `planner_frequency = 0.05`
- 仿真 `planner_frequency = 0.2`
- 仿真/实物静态层均启用：
  - `track_unknown_space: true`
  - `unknown_cost_value: 255`
  - `lethal_cost_threshold: 65`（避免墙体 99 被当可通行）

## 自研全局规划器（simple_global_planner）计划

目标：不再依赖 `move_base_global.launch`，提供**独立全局路径规划节点**，输入输出与当前链路对齐。

### 编译
在 `scout_ws` 下执行：

```bash
     catkin_make -DCATKIN_WHITELIST_PACKAGES=scout_global_planner
     source /home/a/scout_ws/devel/setup.bash
```

### 对齐的输入输出

- **输入**：`/scout/goal`（`geometry_msgs/PoseStamped`）
  - 支持 `move_base_simple/goal` remap 到 `goal`（便于 RViz 发送目标）
- **输入**：`/map`（`nav_msgs/OccupancyGrid`）
  - 静态地图或实时更新地图
- **输出**：`/scout/global_path`（`nav_msgs/Path`）
  - `frame_id = map`，与 MPC 的 `/scout/global_path` 完全对齐

### 规划算法（第一阶段）

- **A\* 规划**（8 邻域）
  - 代价：直邻 `1.0`，对角 `sqrt(2)`
  - 启发式：欧氏距离
- **障碍判定**：
  - 栅格值 `>= occ_threshold` 视为障碍
  - `allow_unknown=false` 时，未知区域视为不可通行

### 运行方式

```bash
roslaunch scout_global_planner simple_global_planner.launch
roslaunch scout_global_planner simple_global_planner_sim.launch
```

### 计划参数（与当前接口兼容）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `map_frame` | `map` | 规划坐标系 |
| `base_frame` | `base_link` | 机器人坐标系 |
| `planner_frequency` | `1.0` | 规划频率（Hz） |
| `allow_unknown` | `false` | 是否允许未知区域 |
| `occ_threshold` | `65` | 障碍阈值 |
| `inflation_radius` | `0.35` | 硬膨胀半径（米），路径远离墙体 |
| `shortcut_smoothing` | `true` | 线段可达时进行路径捷径化 |
| `smooth_path` | `true` | 启用平滑优化（保留可达性约束） |
| `smooth_weight_data` | `0.2` | 数据保持权重 |
| `smooth_weight_smooth` | `0.4` | 平滑权重 |
| `smooth_tolerance` | `1e-4` | 平滑收敛阈值 |
| `smooth_max_iterations` | `200` | 平滑迭代上限 |

### 文件清单

- 新增节点：`scout_global_planner/src/simple_global_planner_node.cpp`
- 新增启动文件：
  - `scout_global_planner/launch/simple_global_planner.launch`
  - `scout_global_planner/launch/simple_global_planner_sim.launch`
- 更新构建：`scout_global_planner/CMakeLists.txt`、`package.xml`

### 分步实施（详细计划）

1. **实现节点**
   - 订阅 `/map`、`/scout/goal`，使用 TF 获取 `map->base_link`
   - A\* 规划，输出 `nav_msgs/Path`（`frame_id=map`）
2. **对齐 I/O**
   - 话题名称与原全局规划保持一致：`/scout/global_path`
3. **编译与验证**
   - `catkin_make` 或 `catkin build` 后运行 launch
   - `rostopic echo /scout/global_path` 验证路径
4. **联调 MPC**
   - MPC 订阅 `/scout/global_path` 即可，无需 move_base

## 历史修复记录（保留）

### 2026-01-30 仿真全局规划“穿墙”修复

- 现象：`/map` 正常但全局路径穿墙
- 原因：墙体占据值常为 99，默认阈值会把其当“高代价可通行”
- 处理：静态层使用 `lethal_cost_threshold: 65` 并跟踪未知区域
- 结果：全局路径可稳定绕障

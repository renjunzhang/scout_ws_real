# navigation 模块说明

## 最后更新：2026-01-28

---

## 模块概述

`navigation` 文件夹包含 Scout 机器人的全局导航相关功能包。当前使用 ROS Navigation Stack 的 `move_base` 框架，配合 `global_planner` 进行全局路径规划。

---

## 包结构

```
navigation/
└── scout_global_planner/
    ├── config/
    │   └── global_planner.yaml    # move_base + costmap 配置
    ├── launch/
    │   └── move_base_global.launch
    ├── include/scout_global_planner/  # 预留
    ├── src/                           # 预留
    ├── CMakeLists.txt
    └── package.xml
```

## 使用方法

### 启动顺序

```bash
# 1. 底盘驱动
roslaunch scout_bringup scout_mini_robot_base.launch

# 2. 激光雷达
roslaunch nanoscan3_bringup nanoscan3_front.launch use_rviz:=false

# 3. 定位（提供 map -> odom 变换）
roslaunch nanoscan3_localization scout_nanoscan3_amcl.launch use_rviz:=true

# 4. 全局规划
roslaunch scout_global_planner move_base_global.launch
```

### RViz 配置

1. **Fixed Frame**: `map`
2. **2D Nav Goal 话题**: 修改为 `/scout/goal`（Panels → Tool Properties）
3. **添加 Path 显示**: 话题选择 `/scout/global_path`

> 说明：你目前在 **AMCL 的 RViz 界面** 发送 goal，这样可以，但必须把 2D Nav Goal 的话题改为 `/scout/goal`，否则 move_base 收不到目标点。

---

## 话题接口

| 方向 | 话题 | 类型 | 说明 |
|------|------|------|------|
| In | `/scout/goal` | `geometry_msgs/PoseStamped` | 目标点输入（RViz 2D Nav Goal） |
| Out | `/scout/global_path` | `nav_msgs/Path` | 全局路径输出（由 GlobalPlanner/NavfnROS remap） |
| Out | `/scout/move_base_cmd_vel` | `geometry_msgs/Twist` | move_base 速度输出（默认旁路，不控制底盘） |

---

## TF 依赖

```
map -> odom -> base_link -> nanoscan3_front
```

| 变换 | 发布节点 |
|------|----------|
| `map -> odom` | AMCL 或 Gmapping |
| `odom -> base_link` | scout_mini_robot_base.launch |
| `base_link -> nanoscan3_front` | nanoscan3_front.launch |

## 配置说明

配置文件：
- `config/global_planner.yaml`（实物默认）
- `config/global_planner_sim.yaml`（仿真专用）

### 全局代价地图 (global_costmap)
- 使用静态地图层 + 膨胀层
- 膨胀半径：0.5m
- 地图话题：`/map`
- TF 容错：`transform_tolerance: 0.2`（实物与仿真已对齐）

### 局部代价地图 (local_costmap)
- 滚动窗口模式：10m × 10m
- 膨胀半径：0.5m
- TF 容错：`transform_tolerance: 0.2`（实物与仿真已对齐）

### 速度输出与 MPC 协作
- move_base 默认输出到 `/scout/move_base_cmd_vel`，不再抢占 `/cmd_vel`
- MPC 仍发布 `/cmd_vel` 控制底盘
- 如需让 move_base 直接控制底盘：启动时设 `cmd_vel_out:=/cmd_vel` 并停止 MPC

### 规划器
- **全局规划器**：`global_planner/GlobalPlanner`（Dijkstra）
- **局部规划器**：`dwa_local_planner/DWAPlannerROS`（仅占位，速度输出已重映射）

## 2026-01-30 仿真全局规划修复记录

### 现象
仿真中全局路径出现“穿墙”，`/map` 正常发布但 `global_costmap` 仍将墙体视为可通行区域。

### 原因
Cartographer 发布的 OccupancyGrid 中墙体代价多为 **99**，而 `costmap_2d::StaticLayer` 默认将 **>=100** 才视为致命障碍，导致 99 只被当作高代价但可通行。

### 处理方式
新增仿真专用配置 `global_planner_sim.yaml`，将静态层阈值降低，并启用未知区域跟踪：
- `static_layer.lethal_cost_threshold = 65`
- `static_layer.track_unknown_space = true`
- `static_layer.unknown_cost_value = 255`

同时让仿真 launch 使用该配置：
- `launch/move_base_global_sim.launch` 加载 `config/global_planner_sim.yaml`

### 结果
仿真全局规划不再穿墙，全局路径可正确绕障。

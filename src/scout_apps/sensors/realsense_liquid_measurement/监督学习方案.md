# 监督学习方案

## 协作原则

1. 本方案只解决“离线液面高度证据链是否可信”，不提前讨论闭环控制替换。
2. 先把任务定义、标签协议、评估口径锁死，再决定是否值得继续投入模型。
3. 任何学习模型都必须先超过当前规则链 baseline，才有资格进入下一阶段。
4. 本文件优先定义方案、口径、标准和执行顺序；实际执行进展以 `监督学习方案log.md` 和当前 artifact 为准。
5. 监督学习方案后续建立的所有脚本，文件名统一以 `SL_` 开头，避免与现有 `v1/v2` 规则链、分析链和调试链脚本混名。
6. 不要假设我清楚自己想要什么。动机或目标不清晰时，停下来讨论。
7. 目标清晰但路径不是最短的，直接告诉我并建议更好的办法。
8. 遇到问题追根因，不打补丁。每个决策都要能回答“为什么”。
9. 输出说重点，砍掉一切不改变决策的信息。
10. 新方案的修改日志统一记录在 `监督学习方案log.md`，不混入旧方案日志。

## 当前核心目标

**最终业务目标：证明在同任务、同路径、可比激励下，`Q=5` 时液体晃动比 `Q=0` 更轻微。**

**当前技术目标：建立一条面向当前时刻最大液面抬升（MSH）的离线监督学习证据链，并用人工标签严格验证 `/slosh/height` 对当前 MSH 的解释力。**

这条证据链的用途是：

- 在固定视角、固定试管、固定背景条件下，从 RealSense 侧视 ROI 估计当前液面高度；
- 用人工标签校验当前 `v2` 几何链与 `/slosh/height` 的有效性；
- 判断是否值得继续把学习模型发展为离线主分析器或实时辅助估计器。

## 1. 目标与边界

### 1.1 总目标

本方案不是：

- 不直接替换当前 `slosh-aware tracking MPC`；
- 不先做学习控制；
- 不做强化学习；
- 不把学习模型直接接入 MPC 闭环；
- 不追求任意视角、任意容器、任意背景泛化；
- 不先做 3D 真液面重建；
- 不先做大规模模型搜索。

本方案要先回答的是：

1. 在当前固定实验场景下，能否用人工标签建立一条更可信的液面高度证据链；
2. 当前 `v2` 规则链和 `/slosh/height` 分别离人工标签有多远；
3. 学习模型是否真的值得替代“几何规则 + bias 修正”的旧主线。

### 1.2 当前判断

当前 `v2` 几何链已经具备：

- ROI、壁线、still level、tube axis 的标定；
- `center` / `peak` 双口径输出；
- `valid / confidence / accept_for_peak_report` 门控；
- 与 `/slosh/height`、`/slosh/height_pred_max` 的对比链；
- 人工逐帧标注入口；
- 动力学窗口数据导出；
- 人工标签误差分析。

但当前 `v2` 几何链更适合作为：

- ROI 对齐与旋正工具；
- still-level 零位参考；
- 旧规则 baseline；
- 主动采样与人工标注辅助链；

而不应再被默认视为后续论文中的最终液面高度测量主方法。

### 1.3 当前阶段结论

当前学习方案的正确定位是：

- 不是替代控制器；
- 不是先做 RL；
- 不是继续把 `v2` 几何链当最终测量器；
- 而是把 `v2` 几何链降级为“ROI 对齐 + 旧规则基线 + 标签辅助链”，把学习模型提升为候选离线主证据链。

当前已经完成到的阶段是：

- `0401` 新 scene 的 calibration、debug、FSL、旧方案 baseline、human holdout 分析都已打通；
- 真标签 `SL` 单帧视觉模型已经训练完成，并在 held-out test 上超过 `/slosh/height`；
- 当前最佳模型是基于 `raw rectified ROI` 的单帧 `SL visual`，而不是 `roi_debug_path` 版本，也不是当前 `K-frame temporal-average` 版本。

## 3. 任务定义

本方案采用 **MSH-first 的双任务结构**：主任务围绕 `peak / MSH`，辅助任务保留 `center / main liquid level`。

### 3.1 主任务 T1：MSH / 峰值证据链

目标：

\[
\hat y_t^{peak} \approx \texttt{human\_peak\_y\_rect\_px}
\]

以及派生目标：

\[
\hat h_t^{peak} \approx \texttt{human\_peak\_mm}
\]

含义：

- 当前帧在当前固定观测平面内可辨认的峰值液面位置与峰值抬升高度；
- 这是当前 MSH 判断的直接监督目标；
- 它服务于验证 `/slosh/height` 是否能估计当前时刻最大液面抬升；
- 它是本方案的主训练目标与主验证目标。

这样定义的原因是：

- 你的核心问题已经收缩为“MSH 是否估计得准”；
- `/slosh/height` 的工程语义更接近当前时刻总最大液面抬升，而不是中心主液面；
- 因此标签主线必须围绕 `peak`，而不是继续围绕 `center`。

### 3.2 辅助任务 T_aux：主液面诊断通道

目标：

\[
\hat y_t^{center} \approx \texttt{human\_center\_y\_rect\_px}
\]

以及派生目标：

\[
\hat h_t^{center} \approx \texttt{human\_height\_mm}
\]

含义：

- 当前帧主液面中心位置与主液面高度；
- 它保留为辅助诊断通道，不再是论文主 claim 的核心任务；
- 它用于检查零位、几何映射、标签一致性和部分难帧的视觉 sanity check。

### 3.3 T1 与 T_aux 的关系

必须明确：

- `T1` 是主训练口径、主验证口径、主结论口径；
- `T_aux` 只作为辅助诊断任务；
- 标注阶段允许两者并行，但精力分配必须向 `peak` 倾斜；
- 评估时必须把 `peak/MSH` 结果与 `center` 结果分开报，禁止混成单一总分。

### 3.4 当前主张

当前最推荐的主线是：

- 先以 `human_peak_y_rect_px / human_peak_mm` 建立 MSH 主证据链；
- 少量保留 `human_center_y_rect_px / human_height_mm` 作为辅助诊断子集；
- 用这两条标签链分别评估：
  - `peak` 旧规则链；
  - `/slosh/height`；
  - dynamics-only baseline；
  - pure vision peak estimator；
  - fusion helper model。

## 4. 标签协议

### 4.1 标签字段

统一标签字段定义如下：

- `human_center_y_rect_px`
- `human_peak_y_rect_px`
- `human_height_mm`
- `human_peak_mm`
- `label_quality`
- `label_valid`
- `label_skip_reason`

### 4.2 标签原语与派生量

从物理意义上，人工标注真正判断的是“液面对应的图像位置”，不是公式意义上的毫米值。

因此本方案在概念上区分两层：

- 原始视觉判断：液面对应的 `y_rect`
- 派生物理量：经 still-level 和 `F(y)` 映射后的 `mm`

必须明确：

- `*_y_rect_px` 是第一性视觉标签；
- `*_mm` 是由当前 still-level 与 `F(y)` 派生出来的分析标签；
- 后续任何学习实验都必须保留这两层，不允许只保留 `mm` 而丢掉原始视觉位置标签。

当前由于现有标注器已支持的是毫米录入，因此当前执行口径仍沿用：

- `human_peak_mm`
- `human_height_mm`

但后续任何分析都要记住：

- 人工标签本质上代表“视觉判定到的液面位置”；
- `mm` 只是当前固定几何链下的派生表示；
- 评估学习模型时，要把“视觉识别误差”和“几何映射误差”分开理解。

### 4.3 原始视觉标签定义

- `human_peak_y_rect_px`
  - 定义：旋正后 ROI 坐标系下，人工判定的峰值液面所在 `y` 行
  - 语义：`human_peak_mm` 的底层视觉标签
- `human_center_y_rect_px`
  - 定义：旋正后 ROI 坐标系下，人工判定的主液面中心所在 `y` 行
  - 语义：`human_height_mm` 的底层视觉标签

原则：

- 后续 pure vision 训练优先拟合 `human_peak_y_rect_px`；
- `human_center_y_rect_px` 只作为辅助头或辅助诊断量；
- `mm` 作为统一汇报口径与物理解释口径；
- 对同一批实验，`y_rect -> mm` 的 still-level 与 `F(y)` 映射必须固定；
- 不允许不同模型各自使用不同的后处理映射；
- 若 `y_rect` 与 `mm` 结论冲突，先回溯几何映射，不先怪模型。

### 4.4 `human_peak_mm` 定义

- 定义：当前帧在当前固定观测平面内可辨认的峰值抬升高度，相对于 still-level 零位；
- 单位：mm；
- 语义：当前 MSH 判断的主标签；
- 说明：它不等同于“真实 3D 全局最高液面点”，只代表当前观测平面里的峰值口径。

### 4.5 `human_height_mm` 定义

- 定义：当前帧主液面中心高度，相对于 still-level 零位的相对抬升量；
- 单位：mm；
- 语义：辅助诊断标签；
- 零位参考：沿用当前 `v2` still-level 定义，不另起新零位体系。

### 4.6 标签质量等级

统一采用：

- `A`：清晰、无明显反光、边界可判；
- `B`：基本清晰，但边界略有不确定；
- `C`：仅可给粗略参考，不进入主训练；
- `X`：跳过。

训练规则：

- 主训练中的 `peak` 标签只使用 `A + B`；
- `C` 仅用于误差分析或低权重实验；
- `X` 不进入训练；
- `center` 标签可以更稀疏，仅作为辅助诊断或辅助头监督；
- `human_peak_mm` 宁缺毋滥。

### 4.7 跳过规则

以下情况应跳过或标低质量：

- 反光严重；
- meniscus 边界模糊；
- ROI 外溢；
- 液面与背景无法区分；
- 画面严重遮挡；
- 当前帧无法确定峰值或主液面所在位置。

不允许在明显看不清时强行给高精度数值。

## 5. 样本挑选策略

当前不采用均匀抽帧。第一批标签集优先标“高价值困难样本”。

### 5.1 第一批建议规模

- `200–500` 帧；
- 只追求高价值，不追求覆盖全部时间轴；
- 建议精力分配：
  - `80%` 用于 `human_peak_*`
  - `20%` 用于 `human_center_*`

### 5.2 优先标注帧类型

优先级如下：

1. `peak` 规则链与 `/slosh/height` 分歧大的帧；
2. `accept_for_peak_report_v2 = 0` 的帧；
3. 峰值附近帧；
4. 静止零位与近零峰值帧；
5. 强激励段帧；
6. `temporal_jump` 大、`fit_rms` 大、`confidence` 低的帧。

### 5.3 第二批标签

第一批之后再补：

- 正常稳定帧；
- 衰减段；
- 不同 bag / 日期 / 光照条件；
- 不同速度档与不同路径段。

目的是让主任务 `T1` 学到峰值响应，而不是只会修少数困难样本。

## 6. 数据集构建与切分

### 6.1 基本原则

**严格按 bag / 日期切 train-val-test，不允许按帧随机切。**

### 6.2 原因

- 同一 bag 内相邻帧高度相关；
- 随机按帧切分会导致时间泄漏；
- 验证结果会虚高，失去真实泛化意义。

### 6.3 推荐切分方式

- `Train / Val / Test` 按 bag 互斥；
- 至少再补一版 `leave-one-bag-out`；
- 若样本量允许，再补一版 `leave-one-day-out`。

### 6.4 统一 split 原则

无论后续使用哪类模型，都必须遵守同一套 split。

禁止：

- 不同 baseline 使用不同切分；
- 为了“看起来更好”在不同 bag 上挑选性汇报。

## 7. Baseline 设计

监督学习证据链的 baseline 分成两类口径：`独立证据链` 与 `工程辅助器`。

### 7.1 独立证据链 baseline

#### B0：`peak_rel_mm_v2`

这是当前旧视觉峰值规则链 baseline，应包含：

- 原始 `peak_rel_mm_v2`
- 如有必要，可做最小量的后处理校正，但不把它包装成新方法

其中：

- `B0` 只代表旧峰值规则链；
- 它是 MSH 任务下必须先超过的旧视觉基线。

#### B1：`/slosh/height`

这是 physics proxy baseline，表示当前 slosh model 对液面响应的工程估计。

必须明确：

- `/slosh/height` 在本方案中始终视为“待验证工程 proxy”，不是人工真值；
- 它可以作为 baseline；
- 但不能在 pure vision 证据链里被默认升格成准真值。

它有两种用途：

- 对 `T1`：看它能否解释当前 MSH；
- 对 `T_aux`：只作辅助对照，不是主对比口径。

#### B0_aux：bias-corrected `center_rel_mm_v2`

这是辅助诊断 baseline，用于：

- 检查零位与映射是否异常；
- 对照 `center` 辅助头是否崩坏；
- 给低质量峰值帧提供次级 sanity check。

### 7.2 工程辅助 baseline

#### B2：dynamics-only 学习器

基于历史窗口动力学特征训练：

- MLP
- 小 TCN

它用来回答：

- 只看动力学和 IMU 特征，能否解释人工标签；
- 当前任务是不是本质上更像“状态估计问题”而不是“读图问题”。

但它不是最终主方案。

### 7.3 baseline 的结论顺序

必须按下面顺序解释结果：

1. 旧峰值规则链能做到什么；
2. `/slosh/height` 能做到什么；
3. 不看图的 dynamics-only 模型能做到什么；
4. pure vision peak estimator 是否真的超过前三者；
5. 融合模型是否进一步提高；
6. `center` 结果只作为辅助诊断，不参与主结论排序。

## 8. 模型路线

本方案把模型路线明确分成两条：`pure vision evidence chain` 与 `fusion helper model`。

### 8.1 Track P：Pure Vision Evidence Chain

这条线的目的，是建立一条**不借助 `/slosh/height` 自身作为输入**的独立视觉证据链。

#### P0：旧规则主基线

- `peak_rel_mm_v2`

#### P1：单帧 ROI 视觉模型

输入：

- 旋正后的 ROI 图像

优先输出：

- `pred_peak_y_rect_px`

派生输出：

- `pred_human_peak_mm`

可选辅助输出：

- `pred_center_y_rect_px`
- `pred_human_height_mm`

它回答的是：

- 单帧图像里是否已经包含足够的峰值 / MSH 信息。

#### P2：短时序 ROI 视觉模型

输入：

- 最近 `K` 帧旋正 ROI 图像序列

优先输出：

- `pred_peak_y_rect_px`

派生输出：

- `pred_human_peak_mm`

可选辅助输出：

- `pred_center_y_rect_px`
- `pred_human_height_mm`

这是当前最值得投入的主模型方向，因为：

- 静止抖动、动态段、峰值出现与衰减都带有时间记忆；
- 只看单帧往往不足以稳定判断峰值口径。

### 8.2 Track F：Fusion Helper Model

这条线的目的，是追求更高工程精度，但它不再被视为“独立证据链”。

可融合输入包括：

- ROI 图像或 ROI 短时序；
- 动力学特征：`v`、`omega`、`imu_ax`、`imu_ay` 等；
- 旧规则输出：`peak_rel_mm_v2`；
- 可选辅助规则输出：`center_rel_mm_v2`；
- 物理 proxy：`/slosh/height`。

必须明确：

- 如果模型把 `/slosh/height` 或旧规则输出当输入，它就只能叫“融合辅助器”；
- 它不能再被用于反过来证明 `/slosh/height` 自己是对的。

### 8.3 当前路线优先级

当前优先级应为：

1. `B0/B1/B2`
2. `Track P` 单帧视觉
3. `Track P` 短时序视觉
4. `Track F` 融合辅助器

只有当 `Track P` 先成立，整条学习证据链才算站住。

### 8.4 模型输入输出与推荐网络结构

#### 8.4.1 总体原则

模型结构遵循以下原则：

1. 先预测第一性视觉量，再派生物理量。
2. 先轻量，再时序，再融合。
3. 回归优先，不采用“离散高度分类 + 硬 `argmax`”作为默认主方案。
4. 若采用逐行概率图结构，可使用 `row-heatmap + soft-argmax` 这类连续位置估计变体。

#### 8.4.2 B2：dynamics-only baseline 结构

输入：

\[
X_t^{dyn} \in \mathbb{R}^{K \times D}
\]

当前最小版本 `D=6`，包括：

- `v_mps`
- `omega_radps`
- `ax_cmd_mps2`
- `ay_model_mps2`
- `imu_ax_mps2`
- `imu_ay_mps2`

默认输出：

- `pred_human_peak_mm`

可选输出：

- `pred_human_height_mm`
- `pred_confidence`

推荐结构：

- `B2-MLP`
  - 输入展平为一维向量
  - `MLP(64~128) -> ReLU -> MLP(32~64) -> ReLU -> Linear`
  - 适合最小可运行 baseline
- `B2-TCN`
  - `2~3` 层 `1D temporal conv`
  - `ReLU -> temporal pooling -> MLP -> Linear`
  - 更适合处理相位、振荡和时间记忆

#### 8.4.3 P1：单帧 pure vision 模型

输入：

\[
X_t^{img} \in \mathbb{R}^{H \times W \times C}
\]

建议：

- `C=1` 灰度先行
- 后续如有必要再试 RGB

优先输出：

- `pred_peak_y_rect_px`

可选辅助输出：

- `pred_center_y_rect_px`
- `pred_confidence`
- `pred_valid`

派生输出：

- `pred_human_peak_mm`
- `pred_human_height_mm`

推荐结构 `P1-CNN-Regressor`：

- `Conv(3x3, 16) -> ReLU -> MaxPool`
- `Conv(3x3, 32) -> ReLU -> MaxPool`
- `Flatten -> MLP(64) -> ReLU -> Linear(1)`

说明：

- 它的目标不是追求最终上限；
- 它先回答“单帧 ROI 里是否已经包含足够的峰值 / MSH 信息”。

#### 8.4.4 P2：短时序 pure vision 模型

输入：

\[
X_{t-K+1:t}^{img} \in \mathbb{R}^{K \times H \times W \times C}
\]

优先输出：

- `pred_peak_y_rect_px`

可选辅助输出：

- `pred_center_y_rect_px`
- `pred_confidence`

派生输出：

- `pred_human_peak_mm`
- `pred_human_height_mm`

推荐结构 `P2-CNN+Temporal`：

- 每帧共享轻量 CNN encoder，得到 `frame feature`
- 时序头三选一：
  - `temporal average + MLP`
  - `TCN`
  - `small GRU`
- 输出头：
  - `Linear -> pred_peak_y_rect_px`
  - 可选 `Linear -> pred_center_y_rect_px`

推荐优先级：

1. `CNN + temporal average + MLP`
2. `CNN + TCN`
3. `CNN + GRU`

原则：

- 先从最轻结构开始；
- 不在样本量仍小的时候一开始就上复杂时序模型。

#### 8.4.5 F：fusion helper model

输入可融合以下任意子集：

- ROI 图像或 ROI 短时序
- dynamics-only 特征序列
- 旧规则输出：`peak_rel_mm_v2`
- 可选辅助规则输出：`center_rel_mm_v2`
- 物理 proxy：`/slosh/height`

输出：

- `pred_human_peak_mm`
- 可选 `pred_human_height_mm`
- 可选 `pred_confidence`

推荐结构 `F-CNN+Dyn-MLP`：

- 图像分支复用 `P1/P2` 视觉分支，得到 `z_img`
- 动力学分支用 `MLP` 或 `TCN`，得到 `z_dyn`
- 融合层：
  - `Concat(z_img, z_dyn, optional rule/proxy features)`
  - `MLP(64~128) -> ReLU -> Linear head(s)`

说明：

- 该结构只作为增强器；
- 不再作为独立证据链。

#### 8.4.6 损失函数建议

主损失优先作用在峰值 `y_rect`：

\[
\mathcal{L}_{peak} = \text{Huber}(\hat y_{peak}, y_{peak}^{gt})
\]

若有辅助 `center` 头：

\[
\mathcal{L}_{center} = \text{Huber}(\hat y_{center}, y_{center}^{gt})
\]

对派生 `mm` 可加弱约束：

\[
\mathcal{L}_{mm} = \text{Huber}(\hat h, h^{gt})
\]

总损失建议：

- `T1-only`
  - \[
    \mathcal{L} = \mathcal{L}_{peak}
    \]
- `T1 + T_aux`
  - \[
    \mathcal{L} = \lambda_1 \mathcal{L}_{peak} + \lambda_2 \mathcal{L}_{center} + \lambda_3 \mathcal{L}_{mm}
    \]

建议：

- `\lambda_1 = 1.0`
- `\lambda_2 = 0.2 ~ 0.4`
- `\lambda_3 = 0.1`

原则：

- `peak` 是主任务，权重大；
- `center` 是辅助诊断任务；
- `mm` 只作弱约束，不反过来主导训练；
- `peak loss` 只在存在 `human_peak` 标签的样本上启用。
- `center loss` 只在存在 `human_center` 标签的样本上启用。

#### 8.4.7 Confidence / Abstain 结构

`pred_confidence` 是可选输出，不是当前 `v1` 必需项。

当前优先级应为：

1. 先把 `pred_peak_y_rect_px` 做稳；
2. 再决定是否加 `pred_confidence`；
3. 最后再把 `abstain` 机制接入完整评估链。

若后续启用 `pred_confidence`，其用途是：

- `confidence >= \tau_high`：正常输出
- `\tau_low <= confidence < \tau_high`：低置信输出
- `confidence < \tau_low`：`abstain`，回退旧规则链或人工复核

## 9. 评估口径

在本方案中，`0.1 mm` 的表述必须统一理解为：

- 当前目标门槛；
- 不是现阶段已证明能力；
- 只有在留出 bag 上的 `T1` 指标稳定过线后，才可宣称具备 `0.1 mm` 级别的 MSH 识别能力。

### 9.1 T1：`human_peak_mm`

至少报告：

- MAE
- RMSE
- bias mean / bias median
- peak amplitude error
- peak timing error
- peak coverage
- bag-wise MAE
- 与 `/slosh/height` 的相对提升

说明：

- `Corr` 可以报，但不是主决策指标；
- 这个任务更关心 MSH 的绝对误差、峰值幅值、峰值时刻和可覆盖率。

建议把 `T1` 验收拆成两级：

- 一级：`static / near-zero peak jitter <= 0.05 ~ 0.08 mm`
- 二级：held-out bag 上 `peak / MSH MAE <= 0.10 ~ 0.15 mm`

原则：

- 一级通过，说明静态噪声地板足够低；
- 二级通过，才说明动态 MSH 识别真正接近 `0.1 mm` 级别；
- 若只通过一级，不得宣传已具备 `0.1 mm` 级动态 MSH 识别能力。

### 9.2 T_aux：`human_height_mm`

辅助报告：

- MAE
- RMSE
- bias mean / bias median
- static jitter
- bag-wise MAE
- 仅用于辅助诊断，不作为主结论指标。

### 9.3 Coverage 与 Abstain

模型不要求每帧都强行给答案。

评估时应允许：

- `pred_peak`
- `pred_center`
- `pred_confidence`

若 `confidence` 低，可：

- abstain；
- 回退到旧规则链；
- 标记为人工复核。

因此所有模型都应同时报告：

- 精度
- coverage
- abstain 后的有效性能

## 10. Go / No-Go 标准

### 10.1 对 T1

新模型必须同时满足：

- 在留出 test bag 上，`peak MAE` 相对 `B0/B1` 中更强者改善 `>= 10%`；
- `peak amplitude error` 相对 `B0/B1` 中更强者改善 `>= 10%`；
- `peak timing error` 相对 `B0/B1` 中更强者改善 `>= 10%`；
- `coverage >= 70%`；
- 至少在 `2` 个及以上独立 test bag 上同时成立。

若要进一步宣称“具备 `0.1 mm` 级别 MSH 识别能力”，还必须额外满足：

- `static / near-zero peak jitter <= 0.05 ~ 0.08 mm`
- held-out bag 上 `peak / MSH MAE <= 0.10 ~ 0.15 mm`

说明：

- 上述两条是更高一级的精度门槛；
- 在达到之前，只能表述为“以 `0.1 mm` 为目标门槛持续验证”，不能表述为“已经实现 `0.1 mm` 级别识别”。

### 10.2 对 T_aux

若启用辅助 `center` 头，则应满足：

- `static jitter` 不高于 `B0_aux` 的 `1.05` 倍；
- `bag-wise center MAE` 不出现系统性崩坏；
- 该辅助头只用于诊断，不参与主过线判断。

### 10.3 对 Pure Vision Track

只有当 `Track P` 同时满足下面条件，才可称其为候选离线主证据链：

- 满足 `10.1` 的全部数值门槛；
- 不是只在单一 bag 上明显更好；
- bag-wise 汇总上稳定过线；
- 结论不依赖把 `/slosh/height` 或旧规则输出当模型输入。

### 10.4 对 Fusion Track

即使 `Track F` 精度更高，也只能先作为：

- 工程辅助分析器；
- 辅助估计器；
- 与 pure vision 并行报告的增强模型；

不能直接拿它替代独立证据链结论。

### 10.5 决策规则

- 若 pure vision 模型没有稳定超过 `B0`：不替换 `v2` 规则链；
- 若 pure vision 模型略优但不稳定：只作为辅助分析器；
- 若 pure vision 模型稳定超过 `B0/B1`：再讨论部署为离线主证据链；
- 即使部署，也先不进入 MPC 闭环。

## 12. 当前推荐执行顺序

当前建议严格按下面顺序推进：

1. 先锁定 `T1/T_aux`、标签协议、split 规则；
2. 先补一批 `200–500` 帧高价值困难样本，优先补 `human_peak_*`；
3. 少量补 `human_center_*` 作为辅助诊断锚点；
4. 同步保留 `human_peak_y_rect_px` / `human_center_y_rect_px` 作为底层视觉标签；
5. 先打穿 `B0/B1/B2` 三类 baseline；
6. 如果 baseline 不够，再进入 `Track P` 单帧 peak 视觉；
7. 若单帧有效，再进入 `Track P` 短时序 peak 视觉；
8. 若短时序视觉稳定超过 baseline，再考虑 `Track F` 融合；
9. 最后才讨论工控机部署。

### 12.1 当前执行状态

## 13. 当前阶段唯一主张

当前阶段最重要的不是“做更复杂的模型”，而是先把下面四件事做实：

1. `peak/MSH` 主任务定义一致；
2. split 规则一致；
3. baseline 口径一致；
4. pure vision 与 fusion 记账分离。

如果这四件事没锁死，后面无论模型多复杂，结论都不够干净。

## 14. 当前版本结论

当前这份监督学习方案的结论是：

- 先把 `v2` 几何链视为 ROI 对齐、零位参考和 baseline；
- 先以 `human_peak_y_rect_px / human_peak_mm` 建立 MSH 主证据链；
- 少量保留 `human_center_y_rect_px / human_height_mm` 作为辅助诊断标签；
- 先比较 `peak_rel_mm_v2`、`/slosh/height`、`dynamics-only`；
- 若它们都不够，再投入 ROI peak 视觉主模型；
- 当前 `0401` 上，pure vision 已经站住，而且 `raw ROI` 单帧版优于 `/slosh/height`；
- 当前最佳模型是 `raw ROI -> human_peak_mm` 的单帧视觉模型；
- 当前 `K-frame temporal-average` 仍未超过单帧 raw ROI，不是下一步主线；
- `0.1 mm` 在当前方案中只能被视为目标门槛，不能在 `T1` 的 held-out bag 验证过线前被当作既有能力对外宣称。

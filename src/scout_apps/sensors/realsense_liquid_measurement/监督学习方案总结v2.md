### 2.1 split 防泄漏说明

当前 split 是按 **bag/session 级别** 划分，不是按帧随机划分。

实验原则：

- 同一个 bag/session 不会同时出现在 train、val、test
- 同一个 `row_id` 不会同时出现在 train、val、test
- 同一个当前帧 `raw_rectified_roi_path` 不会同时出现在 train、val、test
- temporal 输入窗口只在本 split、本 session 内构造，不跨 split 取历史帧
- `val` 只用于 best epoch / early stopping
- `test` 只用于训练结束后的事后评估，不参与模型选择

已做过一次数据级核对：

- `train ∩ val bag = 0`
- `train ∩ test bag = 0`
- `val ∩ test bag = 0`
- `train ∩ val row_id = 0`
- `train ∩ test row_id = 0`
- `val ∩ test row_id = 0`
- `val` temporal history 命中 train session/frame：`0 / 1134`

## 3. 当前主线与阶段收敛版

当前主线已经从“单帧 pure vision”切到 **short temporal pure vision regression**。  
最终证明有效的配置不是早期的 `K-frame temporal average`，而是：

- `raw_rectified_roi_path`
- `human_peak_mm`
- `K = 7`
- `GRU temporal head`
- `current-frame anchor`
- target weighting：`1.0 / 1.5 / 3.0`

### 3.1 `K=7` 样本构造规则

当前 `K=7` 不应表述为“原始视频连续 7 帧 `t-6 ~ t`”。更准确的表述是：

- 每个训练样本有一个目标帧 `t`
- 目标帧 `t` 必须有人工标签 `human_peak_mm`
- 输入是同一 session、同一 split 内的 `7` 个历史 raw ROI 图像
- `history_frames = 7`
- `history_step = 1`
- 标签只挂在当前目标帧 `t`
- loss 只对当前目标帧 `t` 的 `human_peak_mm` 计算
- 序列中的历史帧不单独计算 loss
- temporal window 是 causal/history window，不是以 `t` 为中心的对称窗口

真实实现逻辑：

- 对每个目标帧 `t`，理论查询帧为 `t-6, t-5, t-4, t-3, t-2, t-1, t`
- 当前 frame table 来自当前 split 的 manifest 行，而不是原始视频的每一帧
- 因为人工标注大多是每隔 `5` 帧标一次，所以可用 frame 通常是稀疏的
- 若理论查询帧不存在，脚本会取“不超过该查询帧的最近可用帧”
- 若序列开头不够历史帧，会重复使用该 session 的第一帧
- 因此 `history_indices` 中可能出现重复 frame index

示例：

```text
当前目标帧 t = 277
可用标注帧附近 = 267, 272, 277
history_indices = 267,272,272,272,272,272,277
label = human_peak_mm(frame 277)
```

论文中建议写成 `short temporal sequence of recent ROI frames`，不要写成 `seven consecutive video frames`。除非后续改脚本，直接从 `debug_session.csv` 的原始逐帧图像构造 `t-6...t`。

### 3.2 当前模型结构

当前模型是轻量时序视觉回归器，不是大 CNN。

| 模块 | 当前配置 |
|---|---|
| 输入 | `K=7` 个 raw ROI，灰度，`96 x 192` |
| 每帧 CNN 第 1 层 | `Conv2d(1, 16, kernel=3, padding=1) + ReLU + MaxPool2d(2)` |
| 每帧 CNN 第 2 层 | `Conv2d(16, 32, kernel=3, padding=1) + ReLU + MaxPool2d(2)` |
| 池化 | `AdaptiveAvgPool2d((8, 16))` |
| frame embedding | `Flatten + Linear(32*8*16, 64) + ReLU` |
| temporal head | `GRU(input_size=64, hidden_size=64, batch_first=True)` |
| GRU 层数 | PyTorch 默认 `1` 层 |
| 是否双向 | 否 |
| current-frame anchor | 将 GRU 最后一帧 summary 与当前帧 embedding 拼接 |
| regressor | `Linear(128, 64) + ReLU + Linear(64, 1)` |
| dropout | 无 |
| 输出 | 单标量 `human_peak_mm` |

## 5. 与旧单帧 2 层 CNN + MLP 方案对比

旧方案可以概括为：

- 单帧 `raw ROI`
- 轻量两层 CNN encoder
- MLP 回归头
- 直接回归一个 `human_peak_mm`，也就是 `peak/MSH` 标量

当前方案可以概括为：

- 连续 `K=7` 帧 `raw ROI`
- 每一帧仍使用轻量两层 CNN encoder
- 用 `GRU` 做短时序聚合
- 将 `GRU temporal summary` 和当前帧特征做 `current-frame anchor` 拼接
- MLP 回归 `human_peak_mm`
- 训练时使用 target weighting `1.0 / 1.5 / 3.0`，缓解高峰样本稀疏导致的压峰

因此当前方案不是“换成更大的 CNN”，而是在原轻量 CNN 基础上加入：

- 短时序信息
- 当前帧 anchor
- 高峰幅值加权训练

关键指标对比：

| 方案 | test MAE | test RMSE | Corr |
|---|---:|---:|---:|
| 旧 official best 单帧 raw ROI | `0.1869 mm` | `0.2843 mm` | `0.9106` |

相对旧 official best，当前 temporal best：

- `MAE` 从 `0.1869 mm` 降到 `0.1567 mm`，约下降 `16%`
- `RMSE` 从 `0.2843 mm` 降到 `0.2494 mm`
- `Corr` 从 `0.9106` 提升到 `0.9364`

相对后续单帧 retrain `weighted_v2`，当前 temporal best：

- `MAE` 从 `0.1988 mm` 降到 `0.1567 mm`
- `RMSE` 从 `0.3281 mm` 降到 `0.2494 mm`
- `Corr` 从 `0.8704` 提升到 `0.9364`

从曲线效果看，主要提升是：

- 连续性更好，不再完全依赖单帧局部纹理
- 上升/下降趋势跟随更稳定
- 低幅值段明显更稳，当前 best 在 `low <= 0.2 mm` 上的 MAE 约 `0.0742 mm`

但剩余问题仍然明确：

- 高峰段仍会存在压峰
- `high > 0.5 mm` 的 MAE 仍约 `0.3724 mm`
- 不能宣称已经做到每一帧都小于 `0.3 mm`

- 大多数帧误差明显收紧
- 少数高峰帧仍存在系统性压峰

在 held-out test `554` 帧上：

- `|err| > 0.2 mm`：`118` 帧

- 低幅值段已经明显收紧

## 8. 推荐评估口径

后续对外、汇报、交接时，**不要只报 MAE**。  
原因很直接：不同 bag、不同时间段的真实峰值高度分布不同，同样 `0.2 mm` 的绝对误差，在 `0.1 mm` 峰值段和 `2.0 mm` 峰值段含义完全不同。

推荐最少同时报告下面 6 组指标：

1. `overall MAE`
   - 继续保留，回答“平均每帧绝对偏差多少 mm”
2. `|err| > 0.3 mm` 的帧比例
   - 直接对应工程阈值是否满足
3. `low / mid / high` 分层 MAE
   - 建议固定分层：
   - `low <= 0.2 mm`
   - `mid 0.2 ~ 0.5 mm`
   - `high > 0.5 mm`
4. `p95 abs error` 和 `max abs error`
   - 用来刻画尾部风险，避免被平均值掩盖
5. `bag-wise metrics`
   - 每个 held-out test bag 至少报：
   - `MAE`
   - `p95 abs`
   - `max abs`
   - `|err| > 0.3 mm` 帧数
6. 相对误差口径
   - 推荐只在 `target > 0.5 mm` 上报
   - 避免 near-zero 样本让比例误差失真
   - 当前 best 的 `target > 0.5 mm` 平均相对误差约 `28.95%`

若只能给一页摘要，推荐指标组合是：

- `MAE`
- `RMSE`
- `|err| > 0.3 mm` 比例
- `high > 0.5 mm` 的 MAE
- `p95 abs error`

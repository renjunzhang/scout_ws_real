# 新的高度分析方案

## 协作原则

1. 不要假设我清楚自己想要什么。动机或目标不清晰时，停下来讨论。
2. 目标清晰但路径不是最短的，直接告诉我并建议更好的办法。
3. 遇到问题追根因，不打补丁。每个决策都要能回答“为什么”。
4. 输出说重点，砍掉一切不改变决策的信息。
5. 新方案的修改日志统一记录在 `新的高度分析方案log.md`，不混入旧方案日志。

## 当前核心目标

**最终业务目标：证明在同任务、同路径、可比激励下，`Q=5` 时液体晃动比 `Q=0` 更轻微。**

**当前主目标：验证 `/slosh/height` 能否估计“当前时刻的液面峰值高度（MSH）”。**

- 当前必须先澄清量的定义：
  - `/slosh/height`：模型当前时刻的总最大液面抬升，语义更接近 `MSH`
  - `height_center_rel_mm_bias_corrected_v2`：图像中央主液面高度，不是峰值真值
- 因此 `center` 不再是严格主真值口径：
  - 它只保留为当前工程代理和辅助手段
- `/slosh/height_pred_max` 也不代表当前时刻 `MSH`：
  - 它是预测时域内的峰值包络，不是当前时刻量

## 当前效果与判断

当前以 `0325_rezero_bias` 为唯一主基线，核心结果是：

- 静止包 `Q5_static`
  - `raw_MAE = 0.007837 mm`
  - `raw_bias_median = 0.000000 mm`
  - 说明 `front_back_midpoint` 零位定义 + `1.233421 mm` bias 修正已把静态零位压到很小
- 运动包
  - `Q5_test1`: `raw_MAE = 0.093253 mm`, `raw_corr = 0.521`
  - `Q5_test2`: `raw_MAE = 0.092495 mm`, `raw_corr = 0.688`
  - `Q5_test3`: `raw_MAE = 0.063274 mm`, `raw_corr = 0.430`
  - `Q0_test1`: `raw_MAE = 0.189001 mm`, `raw_corr = 0.420`
- 残余问题
  - `Q5_test1` 的高误差段中，更多是模型侧局部低估
  - 但也仍存在少量视觉 `center` 近静态异常帧
- 当前主判断
  - 代码和论文口径已经说明：`/slosh/height` 更接近当前 `MSH`
  - 所以此前 `center vs /slosh/height` 的一致性，只能算工程近似验证
  - 当前正式口径应改成：
    - 主判断指标：`/slosh/height`
    - 过渡性工程代理：`height_center_rel_mm_bias_corrected_v2`
    - 后续严格真值：人工或更稳健的视觉峰值口径
- 当前限制
  - `Q0_test1` 与 `Q5_test1/2/3` 的路径、时长、激励并不严格可比
  - 因此这批数据能支持“/slosh/height 是否可用”的判断，但还不能单独支持“Q=5 一定优于 Q=0”的强结论

## 任务定义

当前任务不是继续修补旧的 `29 mm -> mm_per_pixel` 临时方案，而是建立一套新的、独立的高度分析方案，用于回答：

1. 单相机侧视情况下，如何更合理地定义“当前帧最高液面高度”。
2. 如何把图像中的 `y_px` 映射成更可信的 `h_mm`。
3. 如何让视觉结果与 `/slosh/height`、`/slosh/height_pred_max` 的比较更可解释。

新方案先冻结双口径输出：

- `height_peak_rel_mm_v2`
- `height_center_rel_mm_v2`

它们的语义分别是：

- `height_peak_rel_mm_v2`
  - **当前帧、当前观测平面内、最高液面候选相对静止基线的非负抬升高度**
- `height_center_rel_mm_v2`
  - **当前帧、管中心拟合液面相对静止基线的非负抬升高度**

## 为什么必须开新方案

旧方案已经能作为“相对液面证据链”使用，但毫米链存在结构性问题：

1. 当前 `29 mm` 标定仍然是单一比例，默认：
   - `h_mm = y_px * mm_per_pixel`
2. 实际场景中，像素高度与物理高度并不是严格线性且全局一致，原因包括：
   - 镜头畸变
   - 透视
   - 圆柱试管折射
3. 当前旧方案中的“最高液面”依然是检测器定义出来的代理量，虽然已经分成了：
   - signed 调试量
   - 非负主输出
   但它还没有和新的高度映射严格绑定。

因此，新方案要改成：

- 不再默认 `single mm_per_pixel`
- 而是显式建立：
  - `F: y_px -> h_mm`

## 新方案要解决的核心问题

新方案只聚焦 3 个问题。

### 问题 1：尺度映射不再可信

当前 `29 mm` 标定本质是：

- 找两个点
- 得一个全局 `mm_per_pixel`

这无法处理：

- 不同高度位置的尺度变化
- 畸变和透视导致的局部非线性

### 问题 2：最高液面定义需要更直观

当前旧方案虽已输出非负最高液面，但本质仍偏向：

- 检测器内部定义出来的峰值代理

新方案希望做到：

- 先找可接受的最高候选行
- 再通过明确的高度映射转成 `mm`

### 问题 3：模型对比时误差难拆

当前视觉 vs `/slosh/height` 的误差可能混着：

- 几何误差
- 尺度误差
- 候选误差
- 基线误差

新方案要让这些误差更容易分层排查。

## v1 冻结规则

下面这 5 条从现在开始视为 **v1 固定规范**，不再悬而未决：

1. `0 mm` 定义为：
   - **静止液面 = 0 mm**
2. 物理标尺零点：
   - 只作为元数据记录
   - 不进入 `height_peak_rel_mm_v2` 的主定义
3. `F` 的坐标系：
   - 使用**旋正后的 ROI 坐标系**
   - 不使用整图坐标系
4. `x_px` 在 v1 中：
   - 只做记录和一致性检查
   - 不参与高度映射计算
5. 标尺点点击口径：
   - **点击每条刻线的中心**
   - 不点边缘

这 5 条后面不再反复讨论，除非明确决定进入 `v2.1` 或更高版本。

- 更合理的高度映射

- 更可解释的模型比较

## 新方案总体设计

新方案总体上拆成 4 层。

### 层 1：几何层

沿用现有 line-based 几何：

- `ROI`
- `left_wall_line`
- `right_wall_line`
- `still_level_line`
- `tube_axis_line`

这层不推翻，只复用。

### 层 2：标尺层

不再只给两个点和一个 `29 mm`，而是给一组标尺参考点：

- 每个点都带：
  - 旋正后 ROI 坐标 `x_px, y_px`
  - 对应真实高度 `h_mm`

第一版建议：

- 每 `5 mm` 标一条

不是必须每 `1 mm` 都标。

### 层 3：映射层

建立：

- `F(y_rect_px) -> h_mm`

第一版先做：

- `piecewise_linear`

后面再视情况升级。

### 层 4：检测层

检测层仍然基于旧方案的成熟部分：

- ROI 旋正
- global threshold
- adaptive threshold
- edge fallback
- temporal gate

但输出不再直接乘单一 `mm_per_pixel`，而是：

- 先得到 `y_peak_raw_rect`
- 先得到 `y_center_raw_rect`
- 再做 `h_peak_rel_mm = F(y_peak_raw_rect)`
- 再做 `h_center_rel_mm = F(y_center_raw_rect)`

## 高度定义

新方案必须把高度定义写死，避免后面反复摇摆。

### 调试定义

- `y_peak_raw_rect`
  - 当前帧最高液面候选行
  - 坐标系是**旋正后 ROI**
- `y_center_raw_rect`
  - 当前帧中心拟合液面行
  - 坐标系是**旋正后 ROI**
- `height_peak_rel_px_signed_v2`
  - 有符号像素相对抬升
- `height_center_rel_px_signed_v2`
  - 有符号像素相对抬升
- `height_peak_rel_mm_signed_v2`
  - 有符号毫米相对抬升
- `height_center_rel_mm_signed_v2`
  - 有符号毫米相对抬升

### 双口径报告定义

- `height_peak_rel_px_v2`
  - 非负像素相对抬升
- `height_peak_rel_mm_v2`
  - 非负毫米相对抬升
- `height_center_rel_px_v2`
  - 非负像素相对抬升
- `height_center_rel_mm_v2`
  - 非负毫米相对抬升

### 左右侧输出

保留：

- `height_left_rel_mm_v2`
- `height_right_rel_mm_v2`

当前阶段冻结的双口径主报告量是：

- `height_peak_rel_mm_v2`
- `height_center_rel_mm_v2`

解释：

- `peak`
  - 用来描述当前帧可见最高液面候选
  - 更接近“峰值包络”语义
- `center`
  - 用来描述当前帧中心液面
  - 更接近“静止液面 / 主液面”语义

当前主液面口径固定为：

- `height_center_rel_mm_v2`

当前 `peak` 口径固定为：

- `height_peak_rel_mm_v2`
  - 作为次级诊断量保留
  - 不作为当前主液面定义

静止包优先用 `center` 判断零位是否正确，不再要求 `peak` 在静止包上必须接近 `0`。

### 与模型量的关系

新方案不再强行单口径对齐所有模型量，而是先固定：

- 主比较：
  - `height_center_rel_mm_v2` vs `/slosh/height`
- 峰值包络比较：
  - `height_peak_rel_mm_v2` vs `/slosh/height_pred_max`

诊断阶段仍允许额外交叉查看：

- `height_peak_rel_mm_v2` vs `/slosh/height`
- `height_center_rel_mm_v2` vs `/slosh/height_pred_max`

## 验收标准

### 静止包

静止包必须至少满足：

- `valid_v2` 不能接近 `0`
- `accept_for_peak_report_v2` 不能接近 `0`
- `height_center_rel_mm_v2` 接近 `0`
- `height_peak_rel_mm_v2` 允许存在稳定正偏置，但不能明显漂移
- 曲线没有明显系统性偏置

### 运动包

运动包至少满足：

- 比旧方案更少的假峰
- 更稳定的尾部
- `center` 口径能稳定反映主液面趋势
- `Q=0` 和 `Q=5` 之间有可重复差异

### 模型对比

模型比较不要求一开始就数值一致，但至少要看：

- 时序是否同步
- `center` 与 `/slosh/height` 的主趋势是否一致
- `peak` 与 `/slosh/height_pred_max` 的峰值出现时刻是否接近
- `Q=0` / `Q=5` 的趋势是否一致

## 已做决策与理由

### 决策 1：新方案与旧方案彻底分开

理由：

- 旧方案还能用
- 新方案风险高，不能污染现有主线

### 决策 2：新方案不再使用单一 `mm_per_pixel`

理由：

- 当前场景存在明显位置相关尺度误差

### 决策 3：第一版高度映射使用分段线性插值

理由：

- 简单
- 可解释
- 工程风险低

### 决策 4：第一版优先使用 `5 mm` 间隔标尺点

理由：

- 标注成本可控
- 已足够验证方案是否成立

### 决策 5：v1 固定“静止液面 = 0 mm”

理由：

- 直接服务于 `height_center_rel_mm_v2` 与 `height_peak_rel_mm_v2` 的相对高度定义
- 避免把“物理标尺零点”和“相对抬升”混成一个概念
- 后续如果需要物理绝对高度，可作为单独元数据扩展

### 决策 6：v1 的高度映射坐标系固定为旋正后 ROI

理由：

- 旧提取链本身先做 ROI 旋正
- 用整图坐标会让标尺点和检测点不在同一坐标系
- 这一步如果不冻结，后面一定返工

### 决策 7：v1 中 `x_px` 只做记录，不参与计算

理由：

- 当前目标是 1D 高度映射
- 如果让 `x` 进入计算，接口会立刻升级成 2D 映射问题
- 当前阶段没有必要把复杂度抬这么高

### 决策 8：v1 中标尺点点击刻线中心

理由：

- 标注口径必须唯一
- 中心比“上边缘/下边缘”更稳定
- 后续人工复标和多人协作更容易一致

### 决策 9：新方案所有产物放到 `/data/a/realsense_validation_v2/`

理由：

- 避免与旧方案目录混淆

### 决策 10：当前阶段冻结双口径输出

冻结：

- `height_center_rel_mm_v2`
- `height_peak_rel_mm_v2`

理由：

- 静止包结果已经表明：
  - `center` 基本贴近 `0 mm`
  - `peak` 存在稳定正偏置
- 说明 `peak` 和 `center` 本来就在描述不同物理语义
- 在没有证明单一口径足够之前，不应该强行合并成一个量

### 决策 11：`center` 作为当前主液面口径

固定：

- 当前主液面口径 = `height_center_rel_mm_v2`

保留：

- `height_peak_rel_mm_v2`
  - 作为次级诊断量
  - 单独重审物理定义与候选逻辑

理由：

- 静止包与运动包结果都表明：
  - `center` 更像 `/slosh/height`
  - `peak` 还不像稳定的 `/slosh/height_pred_max` 代理
- 所以现阶段更稳的工程路径不是继续让 `peak` 代表主液面
- 而是把“主液面”和“峰值候选”明确分开

# sensors

本目录包含 Nanoscan3 前置激光雷达相关的三个功能包：

- **nanoscan3_bringup**：驱动与前置雷达启动。启动 `sick_safetyscanners`，发布 `/scan_front` 和 `/scan_front_filtered`，并发布 `base_link -> nanoscan3_front` 静态 TF。入口：`launch/nanoscan3_front.launch`。
- **nanoscan3_mapping**：基于 gmapping 的建图包，订阅 `/scan_front` 生成地图，可选 RViz。入口：`launch/scout_nanoscan3_gmapping.launch`。
- **nanoscan3_localization**：基于 AMCL 的定位包，加载 `scout_maps` 包内地图进行定位，可选 RViz。入口：`launch/scout_nanoscan3_amcl.launch`（`map_file` 参数可覆盖）。

## 快速使用

### 1. 建图（Gmapping）
```bash
# 终端 1：底盘
roslaunch scout_bringup scout_mini_robot_base.launch

# 终端 2：雷达
roslaunch nanoscan3_bringup nanoscan3_front.launch use_rviz:=false

# 终端 3：建图
roslaunch nanoscan3_mapping scout_nanoscan3_gmapping.launch use_rviz:=true

# 终端 4：键盘控制
rosrun teleop_twist_keyboard teleop_twist_keyboard.py

# 保存地图到 scout_maps 包内
rosrun map_server map_saver -f $(rospack find scout_maps)/maps/map122
```

### 2. 定位（AMCL）
```bash
# 终端 1：底盘
roslaunch scout_bringup scout_mini_robot_base.launch

# 终端 2：雷达
roslaunch nanoscan3_bringup nanoscan3_front.launch use_rviz:=false

# 终端 3：定位（可按需指定 map_file）
roslaunch nanoscan3_localization scout_nanoscan3_amcl.launch use_rviz:=true
```

## 话题与 TF 约定
- 话题：`/scan_front`（原始）与 `/scan_front_filtered`（滤波后）
- TF：`map -> odom -> base_link -> nanoscan3_front`
- 雷达坐标系：`nanoscan3_front`（默认）

## 地图管理
- 地图统一放在 `scout_maps` 包：`$(rospack find scout_maps)/maps/`
- 推荐命名：`mapXXX.yaml` / `mapXXX.pgm`

## 设备与参数
- 雷达 IP、主机 IP、外参见 `nanoscan3_bringup/launch/nanoscan3_front.launch`。
- 定位参数（AMCL）见 `nanoscan3_localization/launch/scout_nanoscan3_amcl.launch`。

## 修改记录

### 2026-01-30 仿真 gmapping 参数优化

**问题现象**：
- 仿真中 gmapping 建图时，RViz 中 base_link axes 明显抖动/跳变
- 建图效果差，地图容易偏移

**根本原因**：
- `libgazebo_ros_skid_steer_drive.so` 使用理想运动学模型计算里程计
- 但 Gazebo 物理引擎模拟了滑移转向的轮子打滑
- 两者不一致导致里程计累积误差，尤其转弯时
- gmapping 默认参数对里程计信任过高

**修改文件**：`nanoscan3_mapping/launch/scout_nanoscan3_gmapping_sim.launch`

**参数调整**：

| 参数 | 默认值 | 修改值 | 说明 |
|------|--------|--------|------|
| `srr` | 0.1 | 0.2 | 平移引起的平移误差容忍度 |
| `srt` | 0.2 | 0.2 | 平移引起的旋转误差 |
| `str` | 0.1 | 0.2 | 旋转引起的平移误差 |
| `stt` | 0.2 | **0.4** | 旋转引起的旋转误差（关键！滑移转向重点） |
| `particles` | 30 | 80 | 粒子数，越多越稳定 |
| `minimumScore` | 0 | 100 | 扫描匹配最低分，防止错误匹配 |
| `delta` | 0.05 | 0.05 | 地图分辨率 5cm |
| `maxUrange` | - | 8.0 | 激光最大可用距离 |
| `maxRange` | - | 10.0 | 激光最大测量距离 |
| `linearUpdate` | 1.0 | 0.2 | 移动 0.2m 更新一次 |
| `angularUpdate` | 0.5 | 0.25 | 旋转 14° 更新一次 |
| `temporalUpdate` | -1 | 2.0 | 静止 2 秒也更新 |

**效果**：
- ✅ axes 不再跳变
- ⚠️ 建图仍有一定漂移（滑移转向仿真的固有问题）

**使用建议**：
- 慢速移动（0.2~0.3 m/s）
- 避免原地旋转，尽量大弧度转弯
- 如仍不稳定，可尝试增大 `stt` 到 0.5~0.6 或 `particles` 到 100~150

#### 问题 5：运行时 libglog.so.1 找不到（重要！）
```
error while loading shared libraries: libglog.so.1: cannot open shared object file
```

**根本原因**：
- 系统安装的是 glog 0.4.0，提供 `libglog.so.0`
- 如果 `~/.bashrc` 中有 Conan 安装的 glog (0.6.0)、gflags、ceres-solver 的 `LD_LIBRARY_PATH`，这些库依赖 `libglog.so.1`
- 程序运行时会从 `LD_LIBRARY_PATH` 优先加载 Conan 版本的 ceres，而 Conan ceres 依赖 `libglog.so.1`

**诊断方法**：
```bash
# 检查 LD_LIBRARY_PATH 是否包含 conan 路径
echo $LD_LIBRARY_PATH | tr ':' '\n' | grep conan

# 检查 cartographer_node 的依赖
ldd ~/scout_ws/src/scout_apps/sensors/cartographer_ws/install_isolated/lib/cartographer_ros/cartographer_node | grep -E "glog|ceres|not.found"
```

**解决方案**：

1. **注释掉 `~/.bashrc` 中冲突的 Conan 路径**（推荐）：
   ```bash
   # 编辑 ~/.bashrc，找到并注释掉以下路径（如果存在）：
   # export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:/home/a/.conan/data/gflags/...
   # export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:/home/a/.conan/data/glog/...
   # export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:/home/a/.conan/data/ceres-solver/...
   
   # 保留 osqp 和 libunwind（如果 MPC 模块需要）
   ```

2. **或者使用干净环境启动脚本**：
   ```bash
   # 使用已创建的脚本
   ~/scout_ws/src/scout_apps/sensors/nanoscan3_mapping/scripts/start_cartographer_clean.sh
   ```

3. **如果修改了 .bashrc，需要打开新终端**（或重新登录）才能生效

**验证修复**：
```bash
# 在新终端中执行
ldd ~/scout_ws/src/scout_apps/sensors/cartographer_ws/install_isolated/lib/cartographer_ros/cartographer_node | grep "not found"
# 应该没有任何输出
```

**Conan 路径冲突的背景**：
- 如果之前安装过 MPC 相关的 Conan 包（如 osqp、ceres-solver），可能会在 `~/.bashrc` 中添加这些路径
- Conan 版本的 glog 是 0.6.0（导出 libglog.so.1），与系统 glog 0.4.0 冲突
- 解决方法是只保留必要的 Conan 路径（osqp、libunwind），注释掉与系统库冲突的路径（gflags、glog、ceres-solver）

#### 问题 6：编译时缺少 ROS 包依赖（pcl_conversions、tf2_eigen）
```
Could NOT find pcl_conversions (missing: pcl_conversions_DIR)
Could NOT find tf2_eigen (missing: tf2_eigen_DIR)
```

**原因**：
- cartographer_ros 依赖某些 ROS 包，这些包不在系统的默认 apt 源中或未被 rosdep 检测到
- `rosdep install` 只能安装已知的依赖，对于这些包可能失败

**解决**：
```bash
# 手动安装缺失的 ROS 包
sudo apt-get install -y ros-noetic-pcl-conversions ros-noetic-tf2-eigen

# 然后重新编译
cd ~/scout_ws/src/scout_apps/sensors/cartographer_ws
rm -rf build_isolated devel_isolated
source /opt/ros/noetic/setup.bash
catkin_make_isolated --install --use-ninja -j4 -DCMAKE_BUILD_TYPE=Release \
    -DBUILD_GRPC=OFF -DBUILD_TESTING=OFF -DCATKIN_ENABLE_TESTING=OFF
```

#### 问题 7：GMOCK_LIBRARY 找不到
```
CMake Error: The following variables are used in this project, but they are set to NOTFOUND.
Please set them or make sure they are set and tested correctly in the CMake files:
GMOCK_LIBRARY
```

**原因**：
- cartographer_ros 包含测试代码，即使设置 `-DBUILD_TESTING=OFF`，仍会尝试链接 gmock 库

**解决**：
```bash
# 编译时同时添加两个参数
catkin_make_isolated --install --use-ninja -j4 \
    -DCMAKE_BUILD_TYPE=Release \
    -DBUILD_GRPC=OFF \
    -DBUILD_TESTING=OFF \
    -DCATKIN_ENABLE_TESTING=OFF
```

**现象**：
- 打开终端后手动执行 `source ~/scout_ws/devel/setup.bash`
- 然后 `roslaunch nanoscan3_mapping scout_nanoscan3_cartographer_sim.launch` 报错找不到 cartographer_node

**根本原因**：
- `~/.bashrc` 已经按正确顺序配置了 source（主工作空间 → cartographer_ws）
- 手动 source 会覆盖 `ROS_PACKAGE_PATH`，丢失 cartographer_ws 的路径

**解决方案**：
- **直接打开新终端，不要手动 source**
- `~/.bashrc` 会自动配置好所有环境

**正确启动方式**：
```bash
# 直接在新终端运行（不需要手动 source）
roslaunch nanoscan3_mapping scout_nanoscan3_cartographer_sim.launch
```

### Cartographer 仿真建图完整流程

```bash
# 终端 1：启动仿真环境
roslaunch scout_description scout_mini_gazebo.launch use_rviz:=false

# 终端 2：键盘控制
roslaunch scout_bringup scout_teleop_keyboard.launch

# 终端 3：激光雷达（仿真）
roslaunch nanoscan3_bringup nanoscan3_front_sim.launch use_rviz:=false

# 终端 4：Cartographer 建图（直接打开新终端运行，不要手动 source）
roslaunch nanoscan3_mapping scout_nanoscan3_cartographer_sim.launch
```

### 保存 Cartographer 地图

```bash
# 1. 完成轨迹
rosservice call /finish_trajectory 0

# 2. 保存为 pbstream 格式
rosservice call /write_state "{filename: '/home/geist/scout_ws/src/scout_apps/scout_maps/maps/map_carto122.pbstream'}"

# 3. 转换为标准 ROS 地图格式（yaml + pgm）
rosrun cartographer_ros cartographer_pbstream_to_ros_map \
  -pbstream_filename=/home/geist/scout_ws/src/scout_apps/scout_maps/maps/map_carto122.pbstream \
  -map_filestem=/home/geist/scout_ws/src/scout_apps/scout_maps/maps/map_carto122 \
  -resolution=0.05
```

### 环境配置验证脚本

创建验证脚本快速检查环境配置：

```bash
#!/bin/bash
# 保存为 ~/scout_ws/check_carto_env.sh

echo "=== 检查 ROS_PACKAGE_PATH ==="
echo $ROS_PACKAGE_PATH | tr ':' '\n' | grep -i cartographer

echo ""
echo "=== 检查 cartographer_ros 路径 ==="
rospack find cartographer_ros

echo ""
echo "=== 检查 nanoscan3_mapping 路径 ==="
rospack find nanoscan3_mapping

echo ""
echo "=== 检查依赖库 ==="
ldd ~/scout_ws/src/scout_apps/sensors/cartographer_ws/install_isolated/lib/cartographer_ros/cartographer_node 2>/dev/null | grep -E "not.found|glog|ceres"

echo ""
echo "=== 检查 LD_LIBRARY_PATH 中的 Conan 路径 ==="
echo $LD_LIBRARY_PATH | tr ':' '\n' | grep conan
```

运行：`bash ~/scout_ws/check_carto_env.sh`

## 功能包说明

### 1. slosh_models（液体晃动建模库）

提供液体晃动的物理建模，基于 Mass-Spring-Damper 等效模型。

**核心类：**
- `LiquidSloshModel`：液体晃动动力学模型
  - 基于论文 "Sloshing Dynamics Estimation for Liquid-filled Containers under 2-Dimensional Excitation" (ECCOMAS 2021)
  - 输入：容器加速度 `[ax, ay]`
  - 输出：液面晃动高度 `η`
  - 支持旋转修正（Lp模型）

- `MPCVelTracker`：带液体晃动约束的MPC速度跟踪器
  - 使用 OSQP 求解器
  - 支持增广状态空间法（晃动状态作为优化变量）
  - 液体晃动抑制通过软约束实现

**依赖：**
- Eigen3
- OsqpEigen（可选，用于MPC求解）

### 2. scout_local_planner（MPC局部规划器）✅ 已完整实现

基于 Frenet MPC 的局部路径跟踪器，**已集成液体晃动模型框架**。

**MPC 架构设计：** *(2026-02-01 更新)*
- **基础状态空间** (4维)：Frenet 坐标系 `x_base = [e_l, e_c, e_θ, v]`
  - `e_l`：纵向误差（沿路径方向）
  - `e_c`：横向误差（垂直路径方向）
  - `e_θ`：航向误差
  - `v`：线速度
- **晃动状态空间** (4维)：`x_slosh = [η_x, η̇_x, η_y, η̇_y]`
  - `η_x`：X方向模态位移 [m]
  - `η̇_x`：X方向模态速度 [m/s]
  - `η_y`：Y方向模态位移 [m]
  - `η̇_y`：Y方向模态速度 [m/s]
- **增广状态空间** (8维)：`x = [x_base; x_slosh]`
- **控制输入**：`u = [a, ω]`（线加速度、**角速度**）← 直接控制 ω
- **输出**：`cmd_vel = [v, ω]`，v 从状态读取，ω 从控制量读取
- **求解器**：OSQP（ROS Noetic 旧版 API）

**核心类：**
| 类名 | 功能 |
|------|------|
| `CubicSpline` / `CubicSpline2D` | 三次样条插值，计算 κ(s), θ_path(s) |
| `PathHandler` | 路径接收、TF变换、Frenet投影、参考点生成 |
| `DiffDriveModel` | 差速驱动 Frenet 动力学，离散化线性化，支持增广晃动状态 |
| `SloshIntegration` | 液体晃动模型集成接口，封装 LiquidSloshModel |
| `CostFunction` | 二次代价函数（状态跟踪 + 控制 + 变化率 + 晃动）|
| `ConstraintManager` | 状态/控制边界约束 |
| `MPCSolver` | QP 问题构建与 OSQP 求解 |
| `LocalPlannerROS` | ROS 节点封装 |

**话题：**
- 订阅：
  - `/odom`：里程计（geometry_msgs/Odometry）
  - `/scout/global_path`：全局路径（nav_msgs/Path，来自 move_base）
- 发布：
  - `/cmd_vel`：速度指令（geometry_msgs/Twist）
  - `/local_path`：MPC 预测轨迹（nav_msgs/Path）

**参数配置：** 见 `config/mpc_params.yaml`

**运行方式：**
```bash
roslaunch scout_local_planner test_mpc.launch
```

## 参数调优指南

### MPC 核心参数（config/mpc_params.yaml）

#### 状态权重（影响跟踪精度）

| 参数 | 默认值 | 说明 | 调参建议 |
|------|--------|------|----------|
| `Q_el` | 1.0 | 纵向误差权重 | 一般不需要调 |
| `Q_ec` | 10.0 | **横向误差权重** | ⬆️ 增大：路径跟踪更精确，但可能抖动 |
| `Q_etheta` | 5.0 | **航向误差权重** | ⬆️ 增大：转弯更积极 |
| `Q_v` | 1.0 | 速度跟踪权重 | 控制是否紧跟参考速度 |

#### 控制权重（影响平滑度）

| 参数 | 默认值 | 说明 | 调参建议 |
|------|--------|------|----------|
| `R_a` | 1.0 | 加速度惩罚 | ⬆️ 增大：加减速更平滑 |
| `R_alpha` | 1.0 | 角加速度惩罚 | ⬆️ 增大：转向更平滑 |
| `R_da` | 0.1 | 加速度变化率惩罚 | ⬆️ 增大：控制更连续 |
| `R_dalpha` | 0.1 | 角加速度变化率惩罚 | ⬆️ 增大：控制更连续 |

#### 车辆约束

| 参数 | 默认值 | 说明 | 调参建议 |
|------|--------|------|----------|
| `v_max` | 1.0 m/s | 最大线速度 | 测试时先用 0.3~0.5 |
| `v_min` | -0.3 m/s | 最小线速度（倒车）| 不需要倒车可设为 0 |
| `omega_max` | 1.0 rad/s | 最大角速度 | 根据转弯需求调整 |
| `a_max` | 0.5 m/s² | 最大加速度 | 过大可能打滑 |
| `alpha_max` | 1.0 rad/s² | 最大角加速度 | 过大可能不稳 |

### 链路检查（先做再调参）

- 路径输入：`/scout/global_path` 有持续输出，且 `header.frame_id=map`
- TF 关系：`map -> odom -> base_link` 连通且稳定
- 里程计：`/odom` 的 `linear.x` 和 `angular.z` 有数值且方向正确
- 速度命令：只有一个 `/cmd_vel` 发布者（避免被 move_base/遥控覆盖）
- 频率一致：`control_rate` 与 `mpc/dt` 匹配（当前 20Hz 与 0.05s）

### 推荐调参流程

**第 1 步：保守起步**
```yaml
# 先用保守参数测试
mpc:
  Q_ec: 20.0       # 横向误差重要
  Q_etheta: 10.0   # 航向也重要
  R_a: 2.0         # 平滑加速
  R_alpha: 2.0     # 平滑转向

vehicle:
  v_max: 0.3       # 低速测试！
  a_max: 0.2       # 保守加速度

path_handler:
  lookahead_distance: 0.5  # 路径前视量（越大越平滑，越小越贴边）
```

**第 2 步：观察行为**
- 跟踪不准 → 增大 `Q_ec`, `Q_etheta`
- 抖动严重 → 增大 `R_a`, `R_alpha`, `R_da`, `R_dalpha`
- 响应太慢 → 减小控制权重 R 系列
- 速度跟不上 → 检查 `v_max` 和 `Q_v`
- 转弯过早/过晚 → 调整 `lookahead_distance`

**第 3 步：逐步放开速度**
```yaml
# 稳定后逐步提高
vehicle:
  v_max: 0.5 → 0.8 → 1.0
  a_max: 0.3 → 0.4 → 0.5
```

### 动力学模型（不需要修改）

差速驱动 Frenet 模型已正确实现：
```
ė_l = v - v_path           # 纵向误差
ė_c = v · e_θ              # 横向误差
ė_θ = ω - κ·v              # 航向误差
v̇ = a                      # 速度动力学
ω̇ = α                      # 角速度动力学
```

Scout Mini 差速底盘使用此模型是正确的。

### 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 机器人不动 | MPC 求解失败 | 检查 `/mpc_status`，降低约束 |
| 跟踪偏差大 | Q 权重太小 | 增大 `Q_ec`, `Q_etheta` |
| 抖动/震荡 | R 权重太小 | 增大 `R_a`, `R_alpha`, `R_da`, `R_dalpha` |
| 响应迟钝 | R 权重太大 | 减小控制权重 |
| 速度跟不上 | 约束太紧 | 检查 `v_max`, `a_max` |
| 走一会停 | 路径超时 | 适当增大 `path_timeout` 或确认路径是否持续更新 |

## 修改记录

### 2026-02-01：控制架构重构（方案 A）

**修改背景**：路径跟踪"不丝滑"的根本原因是 ω 通过 α 积分间接控制，存在一步延迟。

**架构变更**：
| 项目 | 修改前 | 修改后 |
|------|--------|--------|
| 状态 x | [e_l, e_c, e_θ, v, ω] (5D) | [e_l, e_c, e_θ, v] (4D) |
| 控制 u | [a, α] | [a, ω] |
| 总维度(含晃动) | 9D | 8D |

**修改的文件**：
1. `types.h` - StateIndex::BASE_DIM 5→4，移除 OMEGA；ControlIndex::ANG_ACC→OMEGA
2. `diff_drive_model.cpp/.h` - 重写动力学，ay=v·ω
3. `cost_function.cpp` - ANG_ACC→OMEGA, R_dalpha→R_domega
4. `constraint_manager.cpp` - 状态约束仅约束 v
5. `mpc_solver.cpp` - omega_cmd 从控制量获取
6. `local_planner_ros.cpp` - 状态构建、参数加载
7. `slosh_integration.h` - 注释更新
8. `mpc_params_sim.yaml` / `mpc_params.yaml` - R_alpha→R_omega

**优势**：
- ω 直接控制，无积分延迟
- 轨迹跟踪更平滑
- ay = v·ω 可直接用于液体晃动计算

## 调参指南

### 参数文件位置
- 仿真：`scout_local_planner/config/mpc_params_sim.yaml`
- 实车：`scout_local_planner/config/mpc_params.yaml`

### 核心参数说明

#### 1. 状态代价权重 Q
| 参数 | 含义 | 调参建议 |
|------|------|----------|
| `Q_el` | 横向偏差代价 | 增大→减小横向偏移，但可能过于激进 |
| `Q_ec` | 纵向偏差代价 | 通常较小，防止加减速过于频繁 |
| `Q_theta` | 航向偏差代价 | 增大→航向跟踪更紧，转弯可能不够平滑 |
| `Q_v` | 速度跟踪代价 | 增大→速度跟踪更准，但可能加速过猛 |

#### 2. 控制代价权重 R（关键调参项）
| 参数 | 含义 | 调参建议 |
|------|------|----------|
| `R_a` | 线加速度惩罚 | 增大→加减速更平滑，但响应变慢 |
| `R_omega` | 角速度惩罚 | **核心参数**，增大→转向更保守，减少摆动 |

#### 3. 控制变化率代价权重（平滑性核心）
| 参数 | 含义 | 调参建议 |
|------|------|----------|
| `R_da` | 线加速度变化率惩罚 | 增大→加减速更渐进，减少冲击 |
| `R_domega` | **角速度变化率惩罚** | **最重要**，增大→转向更丝滑 |

#### 4. 前馈参数
| 参数 | 含义 | 调参建议 |
|------|------|----------|
| `enable_omega_ff` | 启用角速度前馈 | 建议开启，利用曲率信息 |
| `Q_omega_ff` | 前馈权重 | 增大→更主动跟踪曲率 |

### 调参流程建议

**第一步：保守起步**
```yaml
Q_el: 5.0
Q_theta: 2.0
R_omega: 1.0
R_domega: 0.5
```

**第二步：提升响应性**（如果跟踪滞后）
```yaml
Q_el: 10.0
Q_omega_ff: 2.0
R_omega: 0.5
```

**第三步：改善平滑性**（如果出现抖动）
```yaml
R_domega: 1.0    # 最有效的参数
R_omega: 1.5
```

### 常见问题排查

| 现象 | 可能原因 | 调参方向 |
|------|----------|----------|
| 转弯抖动/摆动 | R_domega 太小 | 增大 R_domega 至 0.5~2.0 |
| 弯道切内弯 | Q_el 太小 | 增大 Q_el，减小 R_omega |
| 直道蛇行 | 前馈过强 | 减小 Q_omega_ff |
| 响应迟缓 | R 权重太大 | 降低 R_omega, R_domega |

### 推荐初始参数
```yaml
# 状态代价
Q_el: 10.0
Q_ec: 1.0
Q_theta: 5.0
Q_v: 2.0

# 控制代价
R_a: 1.0
R_omega: 0.5

# 变化率代价（平滑性关键）
R_da: 1.0
R_domega: 0.5

# 前馈
enable_omega_ff: true
Q_omega_ff: 1.0
```

### 注意事项
1. **每次只调一个参数**，观察效果后再调下一个
2. **R_domega 是平滑性的核心参数**，优先调整
3. 实车参数通常比仿真更保守（R 系列权重更大）
4. 高速时需要增大 R_omega 和 R_domega 保证稳定

## 下一步开发计划：避障功能集成

### 目标
在 MPC 局部规划器中集成实时避障能力，使机器人能够在跟踪全局路径的同时避开动态/静态障碍物。

### 实现方案对比

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **A: 代价地图软约束** | 将 costmap 代价作为 MPC 代价项 | 与现有 MPC 框架无缝集成 | 需要处理代价梯度 |
| **B: 障碍物硬约束** | 将障碍物区域作为 QP 不等式约束 | 保证安全 | 可能导致不可行 |
| **C: 速度障碍法 (VO)** | 在速度空间中避障 | 适合动态障碍物 | 与 Frenet MPC 融合复杂 |
| **D: 局部路径重规划** | 检测到障碍物时调用局部重规划 | 解耦设计 | 响应可能滞后 |

**推荐方案**：**A + B 混合** - 代价地图软约束 + 安全距离硬约束

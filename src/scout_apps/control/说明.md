## 功能包说明

### 1. slosh_models（液体晃动建模库）

提供液体晃动的物理建模，基于 Mass-Spring-Damper 等效模型。

**核心类：**
- `LiquidSloshModel`：液体晃动动力学模型
  - 基于论文 "Sloshing Dynamics Estimation for Liquid-filled Containers under 2-Dimensional Excitation" (ECCOMAS 2021)
  - 输入：容器加速度 `[ax, ay]`
  - 输出：液面晃动高度 `η`
  - 支持旋转修正（Lp模型）

- `MPCVelTracker`：带液体晃动约束的MPC速度跟踪器
  - 使用 OSQP 求解器
  - 支持增广状态空间法（晃动状态作为优化变量）
  - 液体晃动抑制通过软约束实现

**依赖：**
- Eigen3
- OsqpEigen（可选，用于MPC求解）

### 2. scout_local_planner（MPC局部规划器）✅ 已完整实现

基于 Frenet MPC 的局部路径跟踪器，**已集成液体晃动模型框架**。

**MPC 架构设计：**
- **基础状态空间** (4维)：Frenet 坐标系 `x_base = [e_l, e_c, e_θ, v]`
  - `e_l`：纵向误差（沿路径方向）
  - `e_c`：横向误差（垂直路径方向）
  - `e_θ`：航向误差
  - `v`：线速度
- **晃动状态空间** (4维)：`x_slosh = [η_x, η̇_x, η_y, η̇_y]`
  - `η_x`：X方向模态位移 [m]
  - `η̇_x`：X方向模态速度 [m/s]
  - `η_y`：Y方向模态位移 [m]
  - `η̇_y`：Y方向模态速度 [m/s]
- **增广状态空间** (8维)：`x = [x_base; x_slosh]`
- **控制输入**：`u = [a, ω]`（线加速度、**角速度**）← 直接控制 ω
- **输出**：`cmd_vel = [v_cmd, ω_cmd]`
  - `v_cmd = v0 + 0.5 * a0 * dt`
  - `omega_cmd = 0.5 * (omega0 + omega1)`
- **求解器**：OSQP（ROS Noetic 旧版 API）

**核心类：**
| 类名 | 功能 |
|------|------|
| `CubicSpline` / `CubicSpline2D` | 三次样条插值，计算 κ(s), θ_path(s) |
| `PathHandler` | 路径接收、TF变换、Frenet投影、参考点生成 |
| `DiffDriveModel` | 差速驱动 Frenet 动力学，离散化线性化，支持增广晃动状态 |
| `SloshIntegration` | 液体晃动模型集成接口，封装 LiquidSloshModel |
| `CostFunction` | 二次代价函数（状态跟踪 + 控制 + 变化率 + 晃动）|
| `ConstraintManager` | 状态/控制边界约束 |
| `MPCSolver` | QP 问题构建与 OSQP 求解 |
| `LocalPlannerROS` | ROS 节点封装 |

**话题：**
- 订阅：
  - `/odom`：里程计（`nav_msgs/Odometry`）
  - `/scout/global_path`：全局路径（`nav_msgs/Path`，可来自 `MBF` / `move_base_global.launch mode:=mpc` / `simple_global_planner.launch`）
  - `/imu/data`：可选 IMU 输入（`sensor_msgs/Imu`，仅在启用对应参数时订阅）
- 发布：
  - `/cmd_vel`：速度指令（`geometry_msgs/Twist`）
  - `/local_path`：MPC 预测轨迹（`nav_msgs/Path`）
  - `/scout/global_path_smooth`：局部平滑样条可视化（`nav_msgs/Path`，仅可视化，不参与控制）
  - `/mpc_status`：状态机（`IDLE / TRACKING / REACHED / ERROR`）
  - `/mpc/status_val`：求解成功标志（1=成功，0=失败）
  - `/mpc/solve_ms`：单次求解耗时
  - `/slosh/*`：液体晃动调试与实验话题

**参数配置：** 见 `config/mpc_params.yaml`

**运行方式：**
```bash
roslaunch scout_local_planner test_mpc.launch
```

## 使用方法

### 编译

```bash
cd ~/scout_ws
catkin_make
source devel/setup.bash
```

### 运行局部规划器

```bash
# 完整启动顺序
# 1. 底盘驱动
roslaunch scout_bringup scout_mini_robot_base.launch

# 2. 激光雷达
roslaunch nanoscan3_bringup nanoscan3_front.launch use_rviz:=false

# 3. 定位（AMCL）
roslaunch nanoscan3_localization scout_nanoscan3_amcl.launch use_rviz:=true

# 4. 全局规划（任选其一，只要发布 /scout/global_path）
roslaunch scout_global_planner mbf_global.launch
# 或
roslaunch scout_global_planner move_base_global.launch mode:=mpc
# 或
roslaunch scout_global_planner simple_global_planner.launch

# 5. MPC 局部规划（订阅 /scout/global_path，发布 /cmd_vel）
roslaunch scout_local_planner test_mpc.launch

# 6. 仿真日常跟踪
roslaunch scout_local_planner test_mpc_sim.launch

# 7. anti-slosh 实验（实物或仿真）
roslaunch scout_local_planner slosh_experiment.launch \
  Q_slosh:=5 \
  enable_slosh_box_constraint:=true \
  slosh_speed_governor_enable:=true
```

## 调参与排障

### 先确认链路，再调参数

- `/scout/global_path` 有持续输出，且 `header.frame_id=map`
- TF `map -> odom -> base_link` 连通且稳定
- `/odom` 的 `linear.x` 和 `angular.z` 数值正常、方向正确
- `control_rate` 与 `mpc/dt` 一致（当前默认 20 Hz 与 0.05 s）
- `/cmd_vel` 没有被其他节点抢占

### 当前实物调参前提

- `mpc_params.yaml` 当前默认已关闭输出端 EMA：
  - `filter/alpha_v = 1.0`
  - `filter/alpha_omega = 1.0`
  - `filter/kappa_boost = 0.0`
- 当前基础跟踪调参默认基于“无额外输出低通”的执行链进行。

### 当前主要参数分组（实物以 `config/mpc_params.yaml` 为准）

#### 状态与参考相关

| 参数 | 当前作用 | 说明 |
|------|----------|------|
| `Q_contour` / `Q_ec` | 横向贴路径强度 | 当前实物默认启用 `use_contour_lag=true`，优先看 `Q_contour` |
| `Q_lag` / `Q_el` | 纵向误差强度 | 影响沿路径推进误差 |
| `Q_etheta` | 航向误差权重 | 过大时容易转向过激 |
| `Q_v` | 速度跟踪权重 | 影响跟随 `v_ref` 的积极程度 |
| `enable_omega_ff` / `Q_omega_ff` | 曲率前馈 | 利用 `omega_ref = v_ref * kappa` 提前给转向趋势 |

#### 控制平滑与约束

| 参数 | 当前作用 | 说明 |
|------|----------|------|
| `R_omega` | 角速度惩罚 | 增大后转向更保守 |
| `R_domega` | 角速度变化率惩罚 | 当前最关键的平滑参数 |
| `R_a` | 加速度惩罚 | 增大后加减速更柔和 |
| `R_da` | 加速度变化率惩罚 | 配合 jerk 约束使用 |
| `vehicle/omega_max` | 角速度上限 | 响应能力上界 |
| `vehicle/alpha_max` | 角速度变化率硬约束 | 过大可能更激进 |
| `vehicle/v_max` | 最大线速度 | 上限过高时更难调顺 |
| `vehicle/a_max` / `vehicle/j_max` | 纵向响应能力 | 过大可能打滑或冲击更强 |

#### 路径与速度曲线

| 参数 | 当前作用 | 说明 |
|------|----------|------|
| `path_handler/lookahead_distance` | 前视距离 | 越大越平滑，越小越贴路径 |
| `path_handler/max_lat_accel` | 曲率限速 | 限制弯道速度 |
| `path_handler/max_tan_accel` | 切向加速上限 | 影响 `v(s)` 提速速度 |
| `path_handler/max_tan_decel` | 切向减速上限 | 影响终点和急弯减速 |
| `path_handler/goal_capture_distance` | 终点捕获区 | 避免末端过早停死 |
| `path_handler/goal_capture_min_speed` | 捕获区最低参考速度 | 帮助最后一段靠近目标 |

### 推荐调参顺序

1. 先做基础跟踪基线
   - 优先用 `test_mpc.launch`
   - 或者用 `slosh_experiment.launch`，但保持：
   - `Q_slosh:=0`
   - `enable_slosh_box_constraint:=false`
   - `slosh_speed_governor_enable:=false`

2. 先调约束和路径层，再调权重
   - 先看 `vehicle/v_max`、`vehicle/omega_max`、`vehicle/a_max`、`vehicle/alpha_max`
   - 再看 `path_handler/lookahead_distance`、`path_handler/max_lat_accel`、`path_handler/max_tan_accel`、`path_handler/max_tan_decel`
   - 最后再调 `Q_contour/Q_ec`、`Q_lag/Q_el`、`Q_etheta`、`Q_v`、`R_omega`、`R_domega`、`R_a`、`R_da`

3. 每次只改 1 到 2 个参数
   - 单次改动控制在 10% 到 30%
   - 不要同时改 `lookahead_distance`、`Q_contour` 和 `R_domega`

4. 基础跟踪稳了再开 anti-slosh
   - 先 `Q_slosh:=5`
   - 再开 `enable_slosh_box_constraint:=true`
   - 最后开 `slosh_speed_governor_enable:=true`

### 常见现象与优先调整方向

| 现象 | 优先看哪些参数 | 调整方向 |
|------|----------------|----------|
| 跟踪不顺滑、`cmd_vel.angular.z` 锯齿 | `R_domega`、`R_omega`、`lookahead_distance`、`vehicle/alpha_max`、`vehicle/omega_max` | 先增大 `R_domega`；再适当增大 `R_omega`；必要时增大 `lookahead_distance`；若仍太激进，降低 `alpha_max` 或 `omega_max` |
| 车左右摆头、直道蛇行 | `R_omega`、`R_domega`、`lookahead_distance`、`Q_contour/Q_ec`、`Q_etheta` | 先压低过激转向；若仍明显摆头，再适当降低路径贴合激进度 |
| 弯道跟不上、切弯或贴墙 | `Q_contour/Q_ec`、`Q_etheta`、`lookahead_distance`、`max_lat_accel`、`vehicle/omega_max` | 先提高横向/航向跟踪，再看是否需要减小前视或提高响应能力 |
| 终点附近提前停住 | `goal_capture_distance`、`goal_capture_min_speed`、`goal_tolerance`、`yaw_tolerance` | 先调终点捕获区，再适当放宽到点判据 |
| `status_val` 频繁为 0 | `vehicle/*` 约束、`path_handler/max_*`、`enable_slosh_box_constraint`、`slosh_speed_governor_enable` | 先降低激进程度，必要时先关闭 anti-slosh 附加机制 |

## 液体晃动状态与当前进度

### 当前已经接入的能力

- 8 维增广状态：`[e_l, e_c, e_theta, v, eta_x, eta_x_dot, eta_y, eta_y_dot]`
- `SloshIntegration` 已接入 `DiffDriveModel` 和 `LocalPlannerROS`
- slosh 软代价已接入 `CostFunction`
- 第一版 slosh 盒约束已接入 `ConstraintManager`
- 当前残余晃动感知 speed governor 已接入 `LocalPlannerROS`
- 已有完整实验入口：`slosh_experiment.launch`
- 已有调试话题：`/slosh/state`、`/slosh/height`、`/slosh/height_pred_max`、`/slosh/v_des_eff`、`/slosh/speed_governor_active`

### 当前系统定位

当前系统更准确的描述是：

- **参考路径跟踪型 MPC**
- **已接入初版基于模型估计的 anti-slosh 扩展**

它不是：

- 真实液面闭环控制
- 已完成 IMU 闭环验证的系统
- MPCC 型统一进度/几何/液体风险联合优化器

### 当前建议的 anti-slosh 使用顺序

1. 用 `Q_slosh:=0` 跑通基础跟踪
2. 开 `Q_slosh:=5` 验证 soft cost
3. 再开 `enable_slosh_box_constraint:=true`
4. 最后开 `slosh_speed_governor_enable:=true`

### 当前已知局限

- `/slosh/height` 是模型估计值，不是实测液面高度
- 当前横向激励仍主要基于 `ay = v * omega`
- IMU 接口已预留，但是否有真实 IMU 话题需要以实机为准
- governor 在 MPC 外层，属于启发式速度治理，不是统一联合优化

## 仿真/实物对齐结论

### 当前共同控制链

仿真和实物当前共同的主控制链都是：

```text
/scout/global_path
    ↓
PathHandler
    ↓
ref_points（进程内数据）
    ↓
MPCSolver
    ↓
/cmd_vel
```

共同输入输出：

- 输入：`/scout/global_path`、`/odom`、TF `map -> odom -> base_link`
- 输出：`/cmd_vel`、`/local_path`、`/mpc_status`

### 当前一致点

- `heading_align` 在当前实物和仿真 YAML 中都默认关闭
- `publish_smoothed_path` 在当前实物和仿真 YAML 中都默认开启
- `/scout/global_path_smooth` 只用于可视化，不参与控制

### 当前差异点

- 实物日常入口：`test_mpc.launch`，加载 `config/mpc_params.yaml`
- 仿真日常入口：`test_mpc_sim.launch`，加载 `config/mpc_params_sim.yaml`
- anti-slosh 实验入口：`slosh_experiment.launch`，通过 `sim:=true/false` 切换参数文件
- 实物默认关闭输出 EMA；仿真参数仍保留 EMA
- 仿真环境通常还有 `/clock`，实物没有

## 下一步开发计划：避障功能集成

### 目标
在 MPC 局部规划器中集成实时避障能力，使机器人能够在跟踪全局路径的同时避开动态/静态障碍物。

### 实现方案对比

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **A: 代价地图软约束** | 将 costmap 代价作为 MPC 代价项 | 与现有 MPC 框架无缝集成 | 需要处理代价梯度 |
| **B: 障碍物硬约束** | 将障碍物区域作为 QP 不等式约束 | 保证安全 | 可能导致不可行 |
| **C: 速度障碍法 (VO)** | 在速度空间中避障 | 适合动态障碍物 | 与 Frenet MPC 融合复杂 |
| **D: 局部路径重规划** | 检测到障碍物时调用局部重规划 | 解耦设计 | 响应可能滞后 |

**推荐方案**：**A + B 混合** - 代价地图软约束 + 安全距离硬约束

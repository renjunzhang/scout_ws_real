`control` 文件夹包含 Scout 机器人的局部控制相关功能包，主要负责：
- 局部路径规划（MPC控制器）

## 功能包说明

### 1. slosh_models（液体晃动建模库）

提供液体晃动的物理建模，基于 Mass-Spring-Damper 等效模型。

**核心类：**
- `LiquidSloshModel`：液体晃动动力学模型
  - 基于论文 "Sloshing Dynamics Estimation for Liquid-filled Containers under 2-Dimensional Excitation" (ECCOMAS 2021)
  - 输入：容器加速度 `[ax, ay]`
  - 输出：液面晃动高度 `η`
  - 支持旋转修正（Lp模型）

- `MPCVelTracker`：带液体晃动约束的MPC速度跟踪器
  - 使用 OSQP 求解器
  - 支持增广状态空间法（晃动状态作为优化变量）
  - 液体晃动抑制通过软约束实现

**依赖：**
- Eigen3
- OsqpEigen（可选，用于MPC求解）

### 2. scout_local_planner（MPC局部规划器）✅ 已完整实现

基于 Frenet MPC 的局部路径跟踪器，**第 1 步实现已完成**（5 维状态跟踪，无晃动抑制）。

**MPC 架构设计：**
- **状态空间**：Frenet 坐标系 `x = [e_l, e_c, e_θ, v, ω]`
  - `e_l`：纵向误差（沿路径方向）
  - `e_c`：横向误差（垂直路径方向）
  - `e_θ`：航向误差
  - `v`：线速度
  - `ω`：角速度
- **控制输入**：加速度 `u = [a, α]`（线加速度、角加速度）
- **输出**：`cmd_vel = [v, ω]` 从优化状态读取，不是控制量！
- **求解器**：OSQP（ROS Noetic 旧版 API）

**核心类：**
| 类名 | 功能 |
|------|------|
| `CubicSpline` / `CubicSpline2D` | 三次样条插值，计算 κ(s), θ_path(s) |
| `PathHandler` | 路径接收、TF变换、Frenet投影、参考点生成 |
| `DiffDriveModel` | 差速驱动 Frenet 动力学，离散化线性化 |
| `CostFunction` | 二次代价函数（状态跟踪 + 控制 + 变化率）|
| `ConstraintManager` | 状态/控制边界约束 |
| `MPCSolver` | QP 问题构建与 OSQP 求解 |
| `LocalPlannerROS` | ROS 节点封装 |

**话题：**
- 订阅：
  - `/odom`：里程计（geometry_msgs/Odometry）
  - `/scout/global_path`：全局路径（nav_msgs/Path，来自 move_base）
- 发布：
  - `/cmd_vel`：速度指令（geometry_msgs/Twist）
  - `/local_path`：MPC 预测轨迹（nav_msgs/Path）

**参数配置：** 见 `config/mpc_params.yaml`

**运行方式：**
```bash
roslaunch scout_local_planner test_mpc.launch
```

## 参数调优指南

### MPC 核心参数（config/mpc_params.yaml）

#### 状态权重（影响跟踪精度）

| 参数 | 默认值 | 说明 | 调参建议 |
|------|--------|------|----------|
| `Q_el` | 1.0 | 纵向误差权重 | 一般不需要调 |
| `Q_ec` | 10.0 | **横向误差权重** | ⬆️ 增大：路径跟踪更精确，但可能抖动 |
| `Q_etheta` | 5.0 | **航向误差权重** | ⬆️ 增大：转弯更积极 |
| `Q_v` | 1.0 | 速度跟踪权重 | 控制是否紧跟参考速度 |

#### 控制权重（影响平滑度）

| 参数 | 默认值 | 说明 | 调参建议 |
|------|--------|------|----------|
| `R_a` | 1.0 | 加速度惩罚 | ⬆️ 增大：加减速更平滑 |
| `R_alpha` | 1.0 | 角加速度惩罚 | ⬆️ 增大：转向更平滑 |
| `R_da` | 0.1 | 加速度变化率惩罚 | ⬆️ 增大：控制更连续 |
| `R_dalpha` | 0.1 | 角加速度变化率惩罚 | ⬆️ 增大：控制更连续 |

#### 车辆约束

| 参数 | 默认值 | 说明 | 调参建议 |
|------|--------|------|----------|
| `v_max` | 1.0 m/s | 最大线速度 | 测试时先用 0.3~0.5 |
| `v_min` | -0.3 m/s | 最小线速度（倒车）| 不需要倒车可设为 0 |
| `omega_max` | 1.0 rad/s | 最大角速度 | 根据转弯需求调整 |
| `a_max` | 0.5 m/s² | 最大加速度 | 过大可能打滑 |
| `alpha_max` | 1.0 rad/s² | 最大角加速度 | 过大可能不稳 |

### 链路检查（先做再调参）

- 路径输入：`/scout/global_path` 有持续输出，且 `header.frame_id=map`
- TF 关系：`map -> odom -> base_link` 连通且稳定
- 里程计：`/odom` 的 `linear.x` 和 `angular.z` 有数值且方向正确
- 速度命令：只有一个 `/cmd_vel` 发布者（避免被 move_base/遥控覆盖）
- 频率一致：`control_rate` 与 `mpc/dt` 匹配（当前 20Hz 与 0.05s）

### 推荐调参流程

**第 1 步：保守起步**
```yaml
# 先用保守参数测试
mpc:
  Q_ec: 20.0       # 横向误差重要
  Q_etheta: 10.0   # 航向也重要
  R_a: 2.0         # 平滑加速
  R_alpha: 2.0     # 平滑转向

vehicle:
  v_max: 0.3       # 低速测试！
  a_max: 0.2       # 保守加速度

path_handler:
  lookahead_distance: 0.5  # 路径前视量（越大越平滑，越小越贴边）
```

**第 2 步：观察行为**
- 跟踪不准 → 增大 `Q_ec`, `Q_etheta`
- 抖动严重 → 增大 `R_a`, `R_alpha`, `R_da`, `R_dalpha`
- 响应太慢 → 减小控制权重 R 系列
- 速度跟不上 → 检查 `v_max` 和 `Q_v`
- 转弯过早/过晚 → 调整 `lookahead_distance`

**第 3 步：逐步放开速度**
```yaml
# 稳定后逐步提高
vehicle:
  v_max: 0.5 → 0.8 → 1.0
  a_max: 0.3 → 0.4 → 0.5
```

### 动力学模型（不需要修改）

差速驱动 Frenet 模型已正确实现：
```
ė_l = v - v_path           # 纵向误差
ė_c = v · e_θ              # 横向误差
ė_θ = ω - κ·v              # 航向误差
v̇ = a                      # 速度动力学
ω̇ = α                      # 角速度动力学
```

Scout Mini 差速底盘使用此模型是正确的。

### 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 机器人不动 | MPC 求解失败 | 检查 `/mpc_status`，降低约束 |
| 跟踪偏差大 | Q 权重太小 | 增大 `Q_ec`, `Q_etheta` |
| 抖动/震荡 | R 权重太小 | 增大 `R_a`, `R_alpha`, `R_da`, `R_dalpha` |
| 响应迟钝 | R 权重太大 | 减小控制权重 |
| 速度跟不上 | 约束太紧 | 检查 `v_max`, `a_max` |
| 走一会停 | 路径超时 | 适当增大 `path_timeout` 或确认路径是否持续更新 |

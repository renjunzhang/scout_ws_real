## 当前结论

区域、曲率目标、全程计划、完整阶段参考、持续任务时钟和离线后缀检查**已经实现**，本轮再修复5项核心/接线问题。stub 17个、真实acados 18个C++测试程序均已通过；本轮Python 49项通过，2项因缺roslaunch受阻。24次模型闭环仍完成22次，失败均为无上层的单弯 `geometry_mpcc`。缓弯已观察到，但完整方法相对raw尚未稳定降低模型液面峰值，本轮最长周期82.2 ms，未通过30 Hz验收。

本包仍是 ROS1/catkin；本次 ROS2 Jazzy 主机只验证独立生产核心和真实 acados，没有整节点编译、录制或实物验收。[软件验证记录](../../../../docs/实物实验注意事项/对比试验/解决问题的思路/20260916_两层协同实现与软件验证记录.md)保存任务、结果和负例，本文只维护当前状态。

## 实验比较与配置

主比较为原路线直接进入普通 `raw_mpcc`，对比完整 `planned_slosh`。`geometry_mpcc` 检查只有下层自主几何时的变化；`planned_mpcc` 与 `planned_slosh` 共用同一上层液体计划，隔离下层液体项。上层是否考虑液体需另生成目标权重关闭的计划。

四组共同区域、运动限制、目标容差、期限、jerk 和评价窗口。raw 的新几何/目标软代价、全部液体决策关闭；其 contour 为 1，另外三组为 0.02。几何权重 0.05、曲率变化权重 0.01、目标权重 2 和 RTI 5 次均为软件候选。`trajectory_common.yaml` 开 MPC 停车交接和 jerk，`terminal.complete_stop.enable=false`；此前 `model_v234_development.yaml` 是历史开发覆盖层，不能无条件叠到新四组上。

默认四组使用普通停车，均未开启完整液体稳定等待；raw 的液体决策必须保持关闭，液体组可另用覆盖层启用并单独记录。基础 observer 默认仍为 odom，实物 I0/processed-IMU 来源须用覆盖层明确配置并核对实际 selection。没有新相机融合估计器，内部 modal 高度不等于实测液面。

四组的区域停车尾段检查始终启用，复用 `terminal.complete_stop` 下的预算和quiet参数；`enable=false`仅关闭完整液体稳定等待。连续投影窗口、停车预算和回放来源的参数入口见配置README；不再复制另一套控制参数。

| 问题 | 当前证据与下一步 |
| --- | --- |
| 停车全段速度边界 | TaskStop未接收实际/命令速度上界，首命令合法时后续仍可能越界并返回valid；复用现有运动限制逐节点核验，区分不可改变的FIFO前缀 |
| 普通参考末端退化 | raw/geometry在进度终点拟合常值样本，切向受浮点残差支配；端点曲率差分还可产生假尖峰。统一参考边界处理，再隔离复跑失败组 |
| 外部回放配置入口 | launch最后覆盖history source/topic，recorder未暴露对应参数；目前需launch显式参数与planner overlay双传同值，后续统一现有合同入口 |
| 缓弯但未稳定降晃 | 单弯和连续弯变短、变快，模型液面峰值高于 raw；须平衡真实目标、速度/进度和液体项，固定评价窗分辨几何与减速贡献 |
| 无上层单弯失败 | 两个执行器条件下 geometry 返回 `ACADOS_SOLVE_FAILED_4`；失败前的低曲率不算成功 |
| 剩余任务可接续性 | 6 个真实在线末端接名义后缀均失败，一个后缀重优化未找到可行解；后缀尚未参与在线目标 |
| 实时性 / RUN-02 | 本轮各组P95最大59.6 ms、最长周期82.2 ms；计算后命令有效期与运输延迟仍未闭合，不能只统计solver time或将跨轮计时变化当作优化收益 |
| 静止噪声 / RUN-01 | 新配置 actual_v_min=-0.002 缓解原非负边界与微负测量冲突；尚无静止/真回退标定，不能认定实物已解决 |
| 低速执行器 / RUN-03 | 固定 FOPDT 尚未覆盖死区、摩擦、换向与现场传输差异；quiet 阈值和停车应按测量噪声复核 |
| 物理液面边界 / LIQ-01 | freeboard/margin、液量、安装和传感作用点须实测；恢复目标/预算不能从旧模型直接移植 |
| 空间与避障 | 显式区域依赖人工/任务输入；动态障碍、地图到区域和在线拓扑选路没有完整主线链路 |
| ROS 与新实物 | 消息及 solver 整体重建、frame/时间/实际参数/不发布速度回放和执行链检查仍须完成 |

后续顺序：先修上述三类遗漏，关闭命令有效期与最坏周期缺口并在ROS1环境核查整节点、时间/回放接线；再复盘速度/目标/防晃权衡和可接续性，完成标定后冻结新实物版本。共同deadline不代表耗时匹配，应单独报告耗时与晃动的取舍。避障继续按已有梳理评估，不直接把旧obstacle开关视为完整避障能力。

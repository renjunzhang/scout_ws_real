## 0. 这份文档的用途

这不只是一份“待修 bug 列表”，还是后续修改 SPMPC 时必须遵守的回归保护契约。

任何后续改动都必须：

1. 对应本文一个稳定的问题 ID；
2. 先增加能复现该问题的测试，再改行为；
3. 明确记录修改了 B0/slosh 共用链路还是 slosh 特有链路；
4. 不得靠放宽物理约束、更换路径、隐藏后限幅或调 slosh 权重来掩盖 B0 跟踪问题；
5. 在代码、生成求解器、配置、路径 SHA 和实验证据之间建立可追溯关系。

本文中的状态含义：

- `CONFIRMED`：代码路径已确认，可给出明确触发条件。
- `CONDITIONAL`：代码确实存在风险，是否触发取决于路径、终点位置或运行配置。
- `TO_IMPLEMENT`：改法已定义，但尚未改代码。
- `TO_VALIDATE`：已实现后仍必须通过仿真/延迟工厂/实物门。

## 1. 当前架构与不可破坏的模式边界

### 1.1 B0 与 slosh 主线

| slosh 主线 | B0 6 维 + `[eta_x,eta_x_dot,eta_y,eta_y_dot]`，10 维 | 与 B0 相同 | `N=60, NX=10, NU=3, NP=32` |

来源：

- `scripts/acados/spmpc_acados_model.py:8-24,29-45,65-86`
- `generated/acados/spmpc_b0/acados_solver_spmpc_b0.h`

### 1.2 RouteB 的定位

`continuous_mpcc_direct_omega_legacy` 使用 `omega` 直接作为控制。它是诊断后端，可用于判断 alpha-state 链路问题，但不得在没有明确方法学变更和公平性重新验证时，悄然取代 B0/slosh 正式主线。

### 1.3 当前关键默认值

- `dt=1/30 s`，`N=60`，`Tf=2.0 s`。
- fixed-path 平台约束：`v_max=0.8 m/s`，`omega_max=1.2 rad/s`，`a_max=0.6 m/s^2`，`alpha_max=1.2 rad/s^2`。

- `delay_phase.mode=off`，但配置中已记录线/角延迟 `0.15/0.22 s`。
- `reference.lookahead_distance=0.6 m`，fixed-path 中默认 `preprocess_enable=false`。

## 2. 审查结论

当前确实存在能够解释“入弯转向不及时”和“大曲率弯过不去”的代码/结构问题，不应先归因于 slosh 权重或单纯调参。

最重要的因果链是：

```text
执行延迟未进入默认闭环
  + cmd_omega 每拍都从滞后 odom_omega 只积分一个 dt
  + objective 没有 yaw / omega=v*kappa 前馈
  + 却惩罚 omega 和 alpha
  + v_ref 只按 omega 上限限速，不管 alpha 可达性
  + 远期路径被单个三次多项式改变
= 车在转弯前缺少建立角速度的动机，等位置误差已出现后才大幅纠正
```

在大曲率或曲率快速变化段，又会叠加：

```text
自己生成的参考速度对 alpha_max 不可达
  -> OCP 只能在减速、外切、滞后或求解失败中取舍
  -> anti-creep 又对进一步减速施加重罚
  -> 偏离后可被 projection/spin safety 锁死
```

## 3. 已确认问题清单

### SPD-01：`v_ref` 是软代价参考，却被现场流程误当成低速安全上限

**状态：`CONFIRMED`，优先级 P0。**

C02_v2/B0/a02 设置 `V_REF=0.10 m/s`，但发布线速度 P95/最大约为 `0.350/0.363 m/s`，核心运动段超过 `0.30 m/s` 的比例约 `23.7%`，且没有任何后置线速度 limiter 介入。当前代价同时奖励虚拟进度并惩罚 `v_s-v_ref`；忽略其他耦合项时：

```text
v_s* = v_ref + w_progress*v_s,max/(2*w_vs)
     = 0.10 + 0.2*0.8/(2*0.3)
     = 0.3667 m/s
```

该值与实测速度上沿接近。因此必须拆开两个契约：`v_ref` 继续表示优化软目标，另设可审计的运动安全硬上限，并在 OCP bounds、运行时配置、runner 前门和 postflight 中保持一致。不得再用调低 `V_REF` 代替速度上界。

### VAL-01：postflight 只证明数据完整，不能判定路径跟踪质量

**状态：`CONFIRMED`，优先级 P0。**

C02_v2/B0/a02 的自动 postflight 为 `pass=true`：solver/artifact、topic、时间戳、路径 SHA、B0 不消费液体状态和命令发布契约均完整；但同一 bag 的 contour error P95/最大约为 `0.149/0.159 m`，yaw error P95/最大约为 `0.400/0.410 rad`，`alpha` 接近硬上限的比例约 `66.9%`。这说明当前 PASS 只能命名为 acquisition/data-integrity pass。

正式运动入口必须再增加独立的 tracking-quality gate，至少检查实际速度上界、contour/yaw P95 与最大值、进度连续性、控制饱和占比、delay configured/applied 一致性、终点状态和安全介入。阈值必须在正式 R01 前冻结；质量 gate 未通过时不得仅凭现有 postflight 启动下一条。

### TRK-01：指令从滞后实测状态重新积分，实物入弯角速度建立过慢

**状态：`CONFIRMED`，优先级 P0。**

当前出口：

```cpp
cmd_v     = measured_v     + a_0     * dt;
cmd_omega = measured_omega + alpha_0 * dt;
```

位置：`src/solvers/continuous_mpcc_solver_acados.cpp:1090-1095`。

当 `alpha_max=1.2` 且 `dt=0.0333 s` 时，一拍最多只能让发布命令超前实测角速度约 `0.04 rad/s`。若底盘角通道有 `0.18~0.28 s` 延迟，odom 在多个控制周期内几乎不变，后续命令就会不断从同一个滞后值重新起步。线速度通道也有同样问题，一拍只能超前约 `0.02 m/s`，会让弯前减速也滞后。

代码已有延迟状态预测器，但 `config/planner/common.yaml:170-178` 默认为 `off`。历史实物证据与此高度一致：

- `docs/实物实验注意事项/后续改进/20260627_SPMPC实物延迟与相位补偿_模块化修改方案.md:143-156`：`cmd_omega -> odom_omega` 约 `0.18~0.28 s`。
- `docs/实物实验注意事项/对比试验/实物对比实验/0705B0_fixed_path基础跟踪调试指南.md:412-424`：同一 B0，`fixed_closed_loop 0.15/0.22` 干净到点，delay off + 保守角向权限发生 `TRACKING_UNSAFE_PROJECTION`。

**注意：**若某个具体 runner 已显式传入 `fixed_closed_loop`，本问题在该 run 中会被部分缓解；不能只看 `common.yaml`，必须看 `/spmpc/debug/effective_config` 和 delay diagnostics。

### SAFE-01：`spin_fail` 把合法持续转弯也当成原地旋转

**状态：`CONFIRMED`，优先级 P0。**

当前 tracking gate 的判断只是：

```text
tracking phase
AND (abs(measured_omega) > 0.5 OR abs(cmd_omega) > 0.5)
AND duration >= 2.0 s
```

终点阶段对应阈值更低，为 `0.2 rad/s` 和 `2.0 s`。代码没有检查线速度、路径进度、投影是否正常或车是否真的原地打转。

位置：

- `src/ros/spmpc_local_planner_ros.cpp:1292-1318`
- `src/ros/spmpc_local_planner_ros.cpp:1321-1385`
- `config/planner/common.yaml:120-134`

例如 `v=0.25 m/s`、半径 `0.4 m` 的 90° 圆弧需要 `omega=0.625 rad/s`，转弯时间约 `2.51 s`。车即使完全正确地沿路径行驶，也会被当前逻辑置为 `TRACKING_SPIN_FAIL`，之后锁存零命令。

这是一个安全逻辑 bug，但修复时不能直接删掉 safety gate。必须改为“高角速度 + 低平移/低进度 + 持续时间”的组合判定，并保留真正原地自旋时的 fail-closed 能力。

### COST-01：跟踪 objective 没有航向误差和曲率角速度前馈

**状态：`CONFIRMED`，优先级 P1。**

`scripts/acados/spmpc_acados_cost.py:33-46` 的 tracking cost 只有 contour/lag 位置误差，没有：

- `yaw - path_yaw` 误差；
- `omega - v*kappa` 误差；
- 弯前 `alpha` 或 `omega` 前馈。

同时 `scripts/acados/spmpc_acados_cost.py:189-205` 在惩罚 `omega` 幅值和 `alpha` 幅值。因此在车还位于中心线上、contour error 尚小时，提前建立角速度只有控制代价、没有直接跟踪收益。虽然未来位置误差会间接提醒 OCP，但在 SQP-RTI 单步、延迟状态和参考拟合误差同时存在时，这种间接信号不够稳定，容易表现为“误差出现后才转”。

### FEAS-01：曲率限速只管 `omega_max`，不管 `alpha_max`

**状态：`CONFIRMED`，优先级 P1。**

当前只根据：

```text
omega = v*kappa
v <= omega_max/abs(kappa)
```

生成曲率参考速度，见 `scripts/acados/spmpc_acados_cost.py:49-73`。这不足以保证 alpha-state 模型可达。若按弧长跟踪：

```text
omega_ref = v*kappa
alpha_required = d(omega_ref)/dt
               = a*kappa + v^2*d(kappa)/ds
```

因此不仅曲率大小，曲率变化率也决定能否跟踪。当前 OCP 又有 `abs(alpha)<=1.2 rad/s^2` 硬约束。

对现有路径按当前曲率口径做只读量化时：

- `P3_mixed` 的高分位角加速度需求已约为 `1.1~1.2 rad/s^2`，紧贴硬上限；
- `slosh_priority_p2_s` 的 p99 需求约 `4 rad/s^2`，在 `v_ref=0.25 m/s` 下明显不可达。

这不表示几何路径在任何速度下都不可达；它表示“当前系统自己给出的参考速度”对自己的 `alpha_max` 局部不可达。OCP 只能降到参考速度以下或接受几何误差。

该代价又强制 `v_ref >= 0.3*v_cruise`，并用 anti-creep 对低于 `v_ref` 的速度额外重罚，会把“安全减速过弯”变贵，进一步增加外切或滞后的可能。

### REF-01：acados 主线不使用 `lookahead_distance`，并用单个三次多项式拟合整段路径

**状态：`CONFIRMED`，优先级 P1。**

`reference/lookahead_distance=0.6` 被 ROS 参数读取，但只在 primitive backend 中使用：

- `src/solvers/rollout_sampling_solver.cpp:169`

acados 主线实际使用：

```cpp
s_end = s0 + params_.v_max * Tf;
```

见 `src/solvers/continuous_mpcc_solver_acados.cpp:672-680`。fixed-path 默认下是 `1.6 m`，然后用 12 个样本点为 x(s)/y(s) 各拟合一个三次多项式，见同文件 `222-235`。

影响：

1. 调 `lookahead_distance` 对主线完全无效；
2. 在 S 弯、紧凑连续弯或高曲率处，OCP 跟踪的不再是原路径，而是被单个多项式改写后的几何；
3. 拟合区间按 `v_max` 而不是实际 `v_ref/v_s` 可达距离确定，远处几何可以反过来扭曲当前附近的切向；
4. 多项式使用全局 `s`、而不是 `sigma=s-s0`，路径弧长较大时还会增加数值条件问题。

只读拟合复现已在现有紧凑 S 路径上观察到厘米级位置误差和约 `10~20 deg` 量级的局部切向误差。定量结果必须与路径 SHA 绑定，不得对可变的 `/home/geist/fixed_paths/...` 文件只记文件名。

### REF-02：进度投影可以跳到任意远的后方路段，且不可恢复

**状态：`CONFIRMED`，优先级 P1。**

`src/reference/progress_projector.cpp:46-80` 在所有 `s>=last_s` 的线段中搜索全局最近点，没有：

- 局部索引/弧长窗口；
- 单周期最大前跳量；
- 航向一致性；
- 路段连通性；
- 自交/近距离平行段解歧。

`src/core/spmpc_problem.cpp:111-121,154-175` 又使 `last_progress_s_` 只增不减。因此在回头弯、自交、靠得很近的平行段上，一次误跳就可能永久丢失正确路段。现有 projection distance safety 也抓不住“空间距离小、但 s 跳得很远”的情况。

### CFG-01：部分代价归一化与曲率限速常量在 codegen 时写死，可与运行时约束不一致

**状态：`CONFIRMED`，point-to-point/运行时 override 下为高风险，优先级 P1。**

`scripts/acados/generate_spmpc_acados.py:71-110` 在生成时固化 fixed-path 平台值：

```text
v_max=0.8, omega_max=1.2, a_max=0.6, alpha_max=1.2
```

`spmpc_acados_cost.py` 用这些 `cfg` 常量做代价归一化和曲率限速。但 launch 会在运行时再加载 experiment config；`config/experiments/point_to_point.yaml:1-3` 把约束改成 `v_max=0.45, omega_max=0.75`，C++ wrapper 会更新硬约束，但已生成代价里的 `1.2` 不会变。

结果是：OCP 的硬角速度上限可能是 `0.75`，而参考限速仍认为可以用 `1.2`。高曲率下会自己制造参考/约束冲突。同理，任何 `alpha_max` 运行时消融也会改变硬约束，但不会改已生成代价的归一化尺度。

### TERM-01：终点阶段角速度硬夹可以让终点附近的大曲率弯不可跟踪

**状态：`CONDITIONAL`，优先级 P2。**

当车进入 terminal phase 后，`src/core/terminal_controller.cpp:153-159` 把 `omega` 夹到：

- 普通终点区：`0.25 rad/s`；
- 目标 `0.35 m` 内：`0.10 rad/s`。

配置见 `config/planner/common.yaml:99-123`。如果高曲率弯放在终点前 `1.2 m` 内，这个后置夹限可能低于 `v*kappa` 所需角速度，且该限幅不在 OCP 内，会破坏求解命令与实际发布命令一致性。

终点成功判定使用欧式距离是合理且已有测试固化的，不应随意改掉；但 slowdown/capture/clamp 的进入还应同时确认车已在路径尾段，避免路径早期空间靠近终点时过早介入。

## 4. 次级但必须一并防回归的问题

### REF-03：路径首尾曲率有退化向量 bug

`src/reference/reference_spline.cpp:38-50` 在首点使 `p_lo=p`，在尾点使 `p_hi=p`，然后计算 `atan2(0,0)`。这会使直线路径首尾的曲率依赖路径在地图中的绝对朝向，而不是真实几何。主要影响 warm start 限速、终点附近状态和诊断。

### REF-04：`max_reference_fit_error` 实际没有检查 OCP 使用的多项式

`src/warm_start/diff_drive_flatness_warm_start.cpp:112-123` 先把 warm-start 位置直接设为 spline 采样点，`192-195` 又用同一 spline 采样点去比较，因此 `reference_fit_error` 基本恒为 0。它没有测量 `fitReferencePolynomials()` 送入 OCP 的三次多项式与原路径的误差。

### CFG-02：`smooth_priority_enable=false` 不代表平滑代价关闭

`B0` 中 `smooth_priority_enable=false`，但 `w_alpha/w_du_a/w_du_vs` 的负值会回退到 `w_smooth=0.1`，且 acados cost 无条件使用它们。`smooth_priority_enable` 目前主要是变体身份/诊断字段，不是行为开关。后续必须在名称和行为中选一个明确契约，不能让开发者根据字面误判。

### REF-05：fixed-path 默认不预处理

`common.yaml` 中 `preprocess_enable=false`。重复点、折线噪声和不连续曲率可直接进入投影、曲率计算和多项式拟合。但不得为了快速修复而全局默认打开平滑：这会静默改变已冻结路径的几何和 SHA 语义。正确做法是先做输入几何验证，再对需要预处理的路径生成新身份。

## 5. 改进时必须保持的不变量

### 5.1 机器人基线不变量

1. B0 与 slosh 的 `[x,y,yaw,v,s,omega]` 动力学、`[a,alpha,v_s]` 控制语义必须一致。
2. `v_max/omega_max/a_max/alpha_max`、延迟模式、指令后限幅、参考路径和终点逻辑必须在正式 B0/slosh 对比中相同。
3. 修 B0 不得靠把 `alpha_max` 提高到超出共享物理约束；放宽 alpha 只能是带明确标记的诊断消融。
4. 不得用 terminal clamp、safety zero 或后置 rate limiter 隐藏 OCP 输出问题。任何 solver 后的命令变化都必须有诊断、契约和回归测试。
5. RouteB 只作诊断对照，不得无记录地替换 alpha-state formal 主线。

### 5.2 slosh 公平性不变量

1. 修复跟踪链时先让 B0 通过，不先调 `w_slosh`。
2. 机器人共享修复必须同时进入 B0 和 slosh generated solver/wrapper；不得让 slosh 方独有更好的转向前馈或延迟补偿。
3. slosh solver 要求 robot/liquid 共同 epoch 时，不得为了跟踪表现强行使用 `fixed_robot_only`。
4. `w_slosh=0`、液体初值为 0 的 matched slosh solver 应在允许的数值容差内复现 B0 机器人命令趋势。不一致必须可解释，不得默认归因于求解器噪声。

### 5.3 生成求解器不变量

1. 源头是 `scripts/acados/spmpc_acados_model.py` 和 `spmpc_acados_cost.py`；不得手改 `generated/acados/**`。
2. 参数向量增删/重排时，Python `PARAM_NAMES/PIDX`、C++ enum/wrapper、generated `NP` 必须在同一个原子提交中更新。
3. 任何共享 cost/model 改动都必须重生成 B0 和 slosh；若共享函数也被 legacy 使用，还必须检查两个 direct-omega 诊断模型。
4. 生成物必须记录 acados 版本、生成器 commit、配置 hash、`N/NX/NU/NP/NH`，启动时不匹配应 fail closed，不应只靠维度 `static_assert`。

## 6. 分阶段实施方案

### Stage 0：先冻结证据和添加失败测试，不改控制行为

**状态：`TO_IMPLEMENT`。**

目标是先让现有 bug 成为可重复、可自动判定的失败，避免后续“这次好像更好”式修改。

必须增加：

1. `SAFE-01` 合法圆弧回归：`r=0.4 m, v=0.25 m/s, 90 deg`，持续角速度超过 2 s 时不得触发 spin fail。
2. 真正原地旋转回归：高 `omega`、低 `v`、低 progress 持续超时必须触发并锁存。
3. `TRK-01` 纯延迟 plant 回归：线/角延迟 `0.15/0.22 s`，检查饱和 `a/alpha` 下命令建立速度。
4. `REF-03` 任意地图朝向直线的首/尾曲率必须为 0。
5. `REF-04` 故意构造无法由单个三次多项式精确表示的路径，现有 fit-error gate 必须先显示为假阴性。
6. `REF-02` 回头弯、平行近距离段和自交路径投影回归。
7. `CFG-01` 运行时 `omega_max=0.75` 与 codegen `1.2` 不一致的契约测试。
8. `SPD-01` 速度契约回归：低速 runner 的最终发布速度不得超过冻结硬上限，且配置/有效值/审计报告一致。
9. `VAL-01` 质量门回归：构造数据完整但 contour/yaw/速度超限的 trial，acquisition pass 与 tracking-quality fail 必须同时被正确表达。

同时冻结一组最小路径 corpus，不依赖可变的外部文件：

- 直线（多个绝对朝向）；
- 定曲率圆弧；
- 曲率连续的 clothoid/类 clothoid；
- 曲率快速换符号的 S 弯；
- 回头弯/近平行段/自交；
- 终点前大曲率弯。

每条 fixture 必须有固定 SHA 和预期几何量：长度、`kappa_max`、`d(kappa)/ds`、理论 `omega/alpha` 需求。

### Stage 1：修复 safety 误判和延迟下的指令/状态一致性

**状态：`TO_IMPLEMENT`。**

#### 1A. 重构 spin fail，不删除 fail-closed

将 ROS 类内的时长/锁存逻辑提取为可单测模块。建议触发条件至少包含：

```text
high_omega
AND low_linear_motion
AND low_progress_rate
AND persists_for_timeout
```

投影距离、goal phase 和 cmd/measured 一致性可用作附加证据。不得把“有正向 progress 的高曲率转弯”视为 spin。阈值必须有滞回和最小持续时间，避免噪声反复切换。

#### 1B. 以“命令实际生效时刻的预测状态”作为 OCP x0

首选方向是完善现有 delay-phase 链路，而不是在求解器外独立累加上一拍命令：

1. 用命令历史将 raw odom 推到新命令实际生效的 epoch；
2. OCP x0 使用该 execution-state；
3. 发布的 `cmd_v/cmd_omega` 与 OCP 第一步预测状态一致；
4. 线速度和角速度的延迟要分通道落实，不能简单把两者都积分 `max(0.15,0.22)`；
5. 无完整历史、odom stale、时钟回退时必须有明确降级和诊断。

不建议只把出口改成 `last_cmd + alpha*dt`，同时仍用 raw measured omega 作为 OCP x0。那会导致求解器认为的初始角速度和真实下发命令分裂，只是把问题移位。

配置上应分开仿真与实物 profile：零延迟仿真不必装作有 `0.22 s` 延迟；已识别延迟的实物入口不应默认 off。

### Stage 2：先修正参考几何和可达速度，再加转向前馈

**状态：`TO_IMPLEMENT`。**

#### 2A. 参考几何

优先顺序：

1. 修复 `ReferenceSpline` 首尾单边差分，禁止对零向量求角。
2. 明确 `lookahead_distance` 契约：要么主线真正使用，要么删除/重命名，不得继续保留无效参数。
3. 不再用单个全局-s 三次多项式表示整个复杂 horizon。优先选择分段样条/逐 stage 参考；若暂时保留多项式，至少必须：
   - 使用 `sigma=s-s0` 局部坐标；
   - 锨定 `s0` 的位置和切向；
   - 只拟合实际可达/需要预见的区间；
   - 同时检查位置、切向和曲率误差。
4. 把 `max_reference_fit_error` 改成真正比较“OCP 参考”与原 spline，不再比较 warm start 与它自己。

#### 2B. 同时满足 `omega` 和 `alpha` 可达性的速度参考

参考 profile 必须显式满足：

```text
abs(v*kappa) <= omega_max * margin_omega
abs(a*kappa + v^2*kappa_prime) <= alpha_max * margin_alpha
abs(a) <= a_max
```

建议在 horizon 曲率样本上做前向/后向 speed pass，让弯前有足够制动距离，而不是只在当前 stage 根据 `abs(kappa)` 局部夹速。

`0.3*v_cruise` 下限不应继续作为无条件参考下限。anti-creep 应惩罚“在可行 profile 下无原因停滞”，不应惩罚“为满足 alpha 约束而必须减速”。

#### 2C. 消除 codegen/运行时常量分裂

两种方案二选一，不得继续静默不一致：

1. 把 cost normalization 和 curvature-speed 所需的 motion limits 改为运行时参数，并更新 NP 契约；或
2. 每套 motion-limit profile 使用独立生成求解器，启动时严格验证 metadata，不匹配则拒绝运行。

从可维护性和 P2P/fixed-path 共用来看，优先第 1 种。

### Stage 3：加入航向/曲率前馈，重新整理转向代价语义

**状态：`TO_IMPLEMENT`。**

在参考几何和可达速度修正后，再增加：

1. 周期性 yaw tracking cost，优先用 `1-cos(yaw-phi_ref)` 或等价平滑形式，避免 `+-pi` 不连续。
2. `omega_ref=v*kappa` tracking cost，让车在 contour error 出现前就有建立正确角速度的收益。
3. 可选 `alpha_ref=d(v*kappa)/dt` 前馈，但必须使用与 speed profile 同一套 `kappa/kappa_prime/a/v`。

同时把当前含混语义拆开：

- `w_omega_reg`：角速度幅值正则；
- `w_omega_track`：对 `omega_ref` 的跟踪；
- `w_alpha_reg`：角加速度幅值正则；
- 若存在 `alpha_ref`，再独立定义 tracking 权重。

不得直接把旧 `w_omega/w_alpha` 从 0.1 调成 0 就宣布修复。那只是减少阻尼，没有建立可验证的转向参考。

### Stage 4：修复投影连续性和终点曲率一致性

**状态：`TO_IMPLEMENT`。**

#### 4A. Progress projector

投影候选应至少同时考虑：

- 上一路段索引/局部弧长窗口；
- 按 `v_max*dt`、定位不确定性和延迟给出的最大前跳；
- 车体 yaw 与路段切向的一致性；
- 连通路段优先；
- 小范围回退或显式 re-acquire 状态机。

全局重定位只能在局部投影失败后进入显式 recovery，不能在每拍普通 tracking 中默认发生。必须诊断 `delta_s`、segment index、heading mismatch 和 re-acquire reason。

#### 4B. Terminal

1. 保留 goal reached 的欧式位置判定。
2. slowdown/capture/clamp 进入要同时确认 tail progress/remaining arc length，防止空间靠近终点但实际还在早期路段。
3. `omega` 夹限必须与尾段 `v*kappa` 一致：若角速度必须更小，就应在 OCP 内同步降低可行速度，不得只在出口截断。
4. 终点大曲率 fixture 必须既不误触发 `TERMINAL_SPIN_FAIL`，也不因隐藏 omega clamp 偏离。

### Stage 5：B0 基线通过后，再做 slosh 对齐和正式验证

**状态：`TO_VALIDATE`。**

顺序不得颠倒：

1. B0 + 零延迟理想 plant；
2. B0 + 线/角分通道延迟 plant；
3. B0 低速实物 N=1 safety run；
4. B0 固定路径 N=3；
5. slosh solver 中 `w_slosh=0` 的机器人链对齐；
6. matched slosh pair；
7. 最后才能对 `w_slosh`、hard constraint 或 risk governor 作方法学结论。

## 7. 必须建立的自动回归门

### 7.1 单元/符号测试

| 编号 | 必须保证的性质 |
|---|---|
| UT-REF-01 | 任意朝向直线首尾 `kappa=0` |
| UT-REF-02 | OCP reference fit 误差直接对真 spline 计算，差几何必须被 gate 抓住 |
| UT-PROJ-01 | 自交/平行段不会无界前跳，单周期 `delta_s` 受约束 |
| UT-SAFE-01 | 合法持续圆弧不触发 spin fail |
| UT-SAFE-02 | 高 omega + 低 v + 低 progress 持续超时必须 fail closed |
| UT-COST-01 | 同一路径点上，正确 yaw/omega 的 cost 必须低于错误 yaw/omega |
| UT-COST-02 | 车仍在中心线上但前方有弯时，最优转向方向必须与 `kappa` 符号一致 |
| UT-FEAS-01 | 生成的 speed profile 在离散容差内满足 omega/alpha/a 限制 |
| UT-CFG-01 | runtime motion limits 与 cost/solver metadata 不一致时不得静默启动 |
| UT-MODE-01 | B0/slosh 共享参数前缀、维度和生成 metadata 同步 |

### 7.2 闭环场景测试

每个场景都要同时保存 solver command、post-terminal command、post-safety command 和 published command，不得只看最后 `/cmd_vel`。

| 场景 | 关键判据 |
|---|---|
| 直线 | 不甩舵，无假曲率减速，无进度跳变 |
| 定曲率 90° 弯 | 弯前角速度建立，不误触发 spin fail，不外切超走廊 |
| 高 `kappa_prime` S 弯 | 参考 alpha 可达，换向不滞后，无 creep |
| 纯延迟 plant | compensation 开启后 turn-onset/减速相位改善，关闭时能稳定复现旧问题 |
| 自交/回头弯 | 投影 segment 连续，无不可恢复前跳 |
| 终点弯 | 终点夹限与 `v*kappa` 一致，能跟踪并正常停车 |

### 7.3 生成求解器门

每次 model/cost 改动至少执行：

1. `generate_spmpc_acados.py --check --model b0`；
2. `--check --model slosh`；
3. 若共享代价受影响，再检查两个 direct-omega model；
4. 重生成后验证 `N/NX/NU/NP/NH`；
5. C++ wrapper 编译和参数布局 static assertions；
6. 对 generated metadata/config hash 做启动契约测试；
7. B0 和 slosh 的共享 robot dynamics/cost 符号测试。

### 7.4 实物发布门

建议最低标准，后续冻结实验时可收紧但不得临时放宽：

- B0 同一冻结路径 N=3 全部 `GOAL_REACHED`；
- 无 `TRACKING_SPIN_FAIL / TERMINAL_SPIN_FAIL / TRACKING_UNSAFE_PROJECTION`；
- solver p95 小于控制周期；
- 无未审计的 solver-to-published command 变化；
- projection p95/max、yaw p95/max 不劣于已冻结的 clean B0 baseline；
- delay compensation 实际 applied，不能只是 configured；
- 使用的 path/config/generated solver/binary 都有 SHA 或等价身份。

## 8. 历史证据与当前判断边界

### 8.1 已有证据

1. `docs/实物实验注意事项/实物实验前的仿真/20260609_alpha_state_B0主线复现记录.md:276-313`：同路径上 alpha-state B0 失败，RouteB direct-omega 到点，不能归因于环境或路径发布器。
2. `docs/实物实验注意事项/实物实验前的仿真/20260608_continuous_mpcc弯处creep修复记录.md:13-49,279-350`：alpha-state 在高曲率段会出现降速/creep，单纯放宽 alpha 不能解释全部问题。
3. 2026-07-05 实物 B0 gate：fixed delay compensation 下干净到点，delay off + 保守角向权限失败，放开角向权限后到点但误差更大。这支持“延迟 + 角向可达性”是主因之一。

### 8.2 不能过度外推的结论

- B0 不是所有路径都失败；较平滑 S 路径的实物 N=3 曾稳定到点。
- 问题主要随 `kappa_prime`、延迟、路径拓扑、终点位置和安全门持续时间触发。
- 静态代码审查能确认因果机制，但无具体 bag 时不能断言某一次失败是哪个 gate 最先触发。必须根据 status 和 cycle audit 分流。

运行时快速分流：

| 现象/状态 | 首先查看 |
|---|---|
| 入弯晚，但仍 `*_ACADOS_OK` | x0 omega、u0 alpha、cmd omega、delay applied、`v*kappa` |
| `TRACKING_SPIN_FAIL` | `SAFE-01`，同时检查 v/progress 是否仍正常 |
| `TERMINAL_SPIN_FAIL` | `SAFE-01 + TERM-01` |
| `TRACKING_UNSAFE_PROJECTION` | 延迟/转向滞后是否先发生，再查投影跳段 |
| progress 突然大跳但 projection distance 小 | `REF-02` |
| 弯前主动降到 creep | `FEAS-01`、anti-creep 与转向代价的交互 |
| P2P 急弯比 fixed-path 更容易失败 | 先查 `CFG-01` 的 `0.75 vs 1.2` 不一致 |
